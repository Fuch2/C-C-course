## Цели обучения

- Объяснить инвариант: Каждый раз выбираем лучший оставшийся элемент и закрываем одну позицию.
- Обосновать время: Θ(n²) сравнений на всех входах, O(n) обменов.
- Оценить память и компромиссы: Меньше записей, чем у пузырьковой, но нет адаптации к почти отсортированным данным и нет стабильности.

## Теория и инвариант

На каждом шаге ищем минимум неотсортированного суффикса и переносим его в текущую позицию. Перед шагом i префикс [0,i) содержит i наименьших элементов в правильном порядке. Поиск минимума требует полного просмотра остатка, даже если вход уже отсортирован.

В отличие от пузырьковой, число обменов ограничено n−1 значимыми перестановками, но сравнений всё равно квадратично. Дальний обмен может переставить равные ключи относительно друг друга: обычная версия нестабильна. Например 2a,2b,1 превращается в 1,2b,2a. Это не ошибка сортировки чисел, но нарушает контракт стабильного упорядочивания записей.

<Concept title="Ментальная модель">

Каждый раз выбираем лучший оставшийся элемент и закрываем одну позицию.

</Concept>

## Пошаговый разбор

[3,2,1] → [1,2,3]; первый обмен дал нужный порядок, но обычный алгоритм всё равно проверит оставшийся суффикс.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static void sort(int *a,int n){
    for(int i=0;i<n;++i){
        int smallest=i;
        for(int j=i+1;j<n;++j) if(a[j]<a[smallest]) smallest=j;
        int temp=a[i];a[i]=a[smallest];a[smallest]=temp;
    }
}
int main(void) {
int a[]={4,1,3,2};int n=4;sort(a,n);for(int i=0;i<n;++i) printf("%s%d", i?" ":"",a[i]); puts("");
return 0;
}
```

Ожидаемый вывод:

```text
1 2 3 4
```

## Почему реализация корректна

На [3,1,2] сначала просматриваем весь массив и выбираем позицию минимума 1. После одного обмена получаем [1,3,2]. Затем ищем минимум оставшегося суффикса и получаем [1,2,3]. Поиск минимума каждый раз продолжается до конца: уже отсортированный вход не сокращает число сравнений.

Префикс перед позицией i уже содержит i минимальных значений на окончательных местах. Обмен может переносить элементы через равные ключи: на записях 2A, 2B, 1 перестановка первого и последнего даёт 1, 2B, 2A. Поэтому обычная selection sort нестабильна. Её небольшой объём обменов бывает полезен при дорогой записи, но квадратичный поиск остаётся.

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Поиск минимума читает последовательно; дальний обмен затрагивает две позиции.

Меньше записей, чем у пузырьковой, но нет адаптации к почти отсортированным данным и нет стабильности.

Практическое применение: Малые наборы, где обмен дорогого объекта важнее числа сравнений.

<CommonMistake title="Типичная ошибка">

Мало обменов не означает мало сравнений.

</CommonMistake>
