## Идея

Как отсортировать карточки с числами, если можно смотреть на все сразу? Найти самую маленькую и положить её первой. Из оставшихся снова найти самую маленькую и положить второй. И так до конца. Это **сортировка выбором** (selection sort): на каждом шаге из неотсортированной части **выбирается** минимум и ставится на своё место.

В массиве «положить первой» — значит обменять минимум с элементом, который стоит в начале неотсортированной части.

```c
#include <stdio.h>

static void print(const int *values, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
}

int main(void) {
    int values[] = {29, 10, 14, 37, 13};
    int n = 5;
    for (int i = 0; i < n - 1; i++) {
        int min_index = i;
        for (int j = i + 1; j < n; j++) {
            if (values[j] < values[min_index]) {
                min_index = j;
            }
        }
        int tmp = values[i];
        values[i] = values[min_index];
        values[min_index] = tmp;
        printf("шаг %d (минимум %d): ", i + 1, values[i]);
        print(values, n);
    }
    return 0;
}
```

Вывод:

```text
шаг 1 (минимум 10): 10 29 14 37 13
шаг 2 (минимум 13): 10 13 14 37 29
шаг 3 (минимум 14): 10 13 14 37 29
шаг 4 (минимум 29): 10 13 14 29 37
```

На шаге 3 минимум уже стоял на месте — обмен элемента с самим собой ничего не меняет.

**Инвариант:** перед шагом `i` первые `i` элементов — это `i` наименьших элементов массива, отсортированные. Шаг находит наименьший из оставшихся — он не меньше любого из первых `i` — и ставит его на позицию `i`. После `n − 1` шагов на месте все элементы, кроме последнего, а он — наибольший — уже стоит в конце.

Сравните с пузырьком: там готовым становится **хвост** из наибольших элементов, здесь — **начало** из наименьших.

## Сколько это стоит

Поиск минимума среди `n − i` элементов — `n − i − 1` сравнений. Всего `(n − 1) + (n − 2) + … + 1 = n(n − 1) / 2` сравнений — **на любом входе**: даже отсортированный массив сортировка выбором проверяет целиком, раннего выхода у неё нет.

Зато обменов — не больше `n − 1`, по одному на шаг. У пузырька обменов столько же, сколько инверсий, — до `n² / 2`.

| Свойство                 | Пузырёк                    | Выбор               |
| ------------------------ | -------------------------- | ------------------- |
| сравнений                | до `n(n − 1)/2`            | всегда `n(n − 1)/2` |
| обменов                  | число инверсий             | не больше `n − 1`   |
| на отсортированном входе | `O(n)` с ранней остановкой | `O(n²)`             |
| устойчивость             | да                         | нет                 |

Малое число записей — главное достоинство сортировки выбором. Оно важно там, где запись дорогая: например, во флеш-памяти и EEPROM, у которых ограничено число циклов перезаписи, или когда «элемент» — большая структура, которую дорого копировать.

## Почему выбор неустойчив

Обмен переносит элемент **далеко** — через головы других. Если среди перепрыгнутых есть равный ему, их порядок нарушится:

```c
#include <stdio.h>

typedef struct {
    int key;
    char label;
} Item;

int main(void) {
    Item items[] = {{2, 'a'}, {2, 'b'}, {1, 'c'}};
    int n = 3;
    for (int i = 0; i < n - 1; i++) {
        int m = i;
        for (int j = i + 1; j < n; j++) {
            if (items[j].key < items[m].key) {
                m = j;
            }
        }
        Item tmp = items[i];
        items[i] = items[m];
        items[m] = tmp;
    }
    for (int i = 0; i < n; i++) {
        printf("%d%c ", items[i].key, items[i].label);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1c 2b 2a
```

На первом шаге `1c` меняется местами с `2a`, и `2a` улетает в конец — за `2b`. Во входе `a` было раньше `b`, в результате — позже. Сделать выбор устойчивым можно, если вместо обмена **сдвигать** элементы, но тогда записей станет `O(n²)` и пропадёт главное достоинство.

## Частичная сортировка: k наименьших

Сортировку выбором можно остановить в любой момент: после `k` шагов первые `k` элементов — это `k` наименьших, уже по порядку. Если нужны только они («топ-10 результатов»), достаточно `k` шагов — `O(n · k)` вместо `O(n²)`:

```c
#include <stdio.h>

int main(void) {
    int scores[] = {71, 98, 45, 88, 93, 60, 99, 77};
    int n = 8, k = 3;
    for (int i = 0; i < k; i++) {
        int max_index = i;                              // ищем максимум — топ по убыванию
        for (int j = i + 1; j < n; j++) {
            if (scores[j] > scores[max_index]) {
                max_index = j;
            }
        }
        int tmp = scores[i];
        scores[i] = scores[max_index];
        scores[max_index] = tmp;
        printf("%d место: %d\n", i + 1, scores[i]);
    }
    return 0;
}
```

Вывод:

```text
1 место: 99
2 место: 98
3 место: 93
```

При `k = 3` и `n = 10⁶` это 3 миллиона сравнений, а полная сортировка даже быстрым алгоритмом — около 20 миллионов. Для большого `k` есть способы лучше — с кучей, о ней в одном из следующих уроков.

<Concept title="Сортировка выбором">

На шаге `i` находится минимум среди элементов `i…n − 1` и обменивается с элементом `i`. После `k` шагов первые `k` элементов — `k` наименьших, по порядку. Всегда `n(n − 1)/2` сравнений и не больше `n − 1` обменов; сортирует на месте, но неустойчиво. Полезна, когда запись дорогая, и как частичная сортировка для `k` наименьших.

</Concept>

## Частые ошибки

<CommonMistake title="Минимум с начала массива">

```c
for (int i = 0; i < n - 1; i++) {
    int min_index = 0;          // должно быть i
    ...
}
```

Минимум ищется среди **неотсортированной** части, начиная с `i`. Если начать с `0`, найдётся уже поставленный на место первый элемент, и обмен испортит отсортированное начало.

</CommonMistake>

<CommonMistake title="Обмен в каждом сравнении">

Если менять элементы каждый раз, когда найден меньший, а не один раз после поиска, алгоритм всё ещё сортирует, но делает до `n²/2` обменов — и теряет своё главное преимущество.

</CommonMistake>

<CommonMistake title="Сравнение по индексу вместо значения">

`if (j < min_index)` вместо `if (values[j] < values[min_index])` сравнивает номера позиций, а не элементы. Компилятор не возразит — оба выражения корректны. Трассировка на трёх элементах находит такую опечатку сразу.

</CommonMistake>

## Практика

1. **Минимумы по шагам** — трассировка сортировки выбором.
2. **Топ-k** — частичная сортировка.
3. **Найди ошибку: поиск минимума** — неверное начало поиска.
4. **Минимум обменов** — циклы перестановки.

## Итоги

- Сортировка выбором ставит на позицию `i` минимум из оставшихся элементов.
- Инвариант: первые `i` элементов — `i` наименьших, по порядку.
- Всегда `n(n − 1)/2` сравнений, не больше `n − 1` обменов, `O(1)` памяти.
- Неустойчива: обмен переносит элемент через равные ему.
- `k` шагов дают `k` наименьших элементов за `O(n · k)`.
