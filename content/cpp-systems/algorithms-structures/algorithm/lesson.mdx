## Цели обучения

- Объяснить инвариант: Контракт — пункт назначения, инвариант — утверждение, верное на каждой остановке.
- Обосновать время: Θ(n) сравнений с порогом; ввод тоже требует Θ(n).
- Оценить память и компромиссы: Хранение данных позволяет повторные запросы и отладку; потоковая обработка экономит память, но теряет исходные значения.

## Теория и инвариант

Алгоритм задаёт конечную последовательность однозначных действий для класса входов. Программа добавляет к нему ввод, представление данных и обработку ошибок. Начинайте с контракта: что считается корректным входом, какой результат требуется и что делать с пустым набором. «Найти плохое измерение» неоднозначно: первое, любое или все?

Для подсчёта превышений порога полезен инвариант: перед итерацией i счётчик равен числу превышений среди элементов [0,i). Инициализация делает утверждение истинным для пустого префикса, шаг сохраняет его, завершение при i=n распространяет на весь массив. Доказательство завершения отдельно: n-i уменьшается и не отрицательно. Правильный алгоритм может быть неправильно реализован из-за неверной границы или переполнения.

<Concept title="Ментальная модель">

Контракт — пункт назначения, инвариант — утверждение, верное на каждой остановке.

</Concept>

## Пошаговый разбор

Для [4,9,2,7] и порога 5 счётчик проходит 0 → 0 → 1 → 1 → 2. Равенство порогу не является превышением.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static int count_above(const int *a,int n,int limit){
    int count=0;
    for(int i=0;i<n;++i) if(a[i]>limit) ++count;
    return count;
}
int main(void) {
int a[]={4,9,2,7};printf("%d\n",count_above(a,4,5));
return 0;
}
```

Ожидаемый вывод:

```text
2
```

## Почему реализация корректна

Рассмотрим измерения 12, 18, 9, 21 и порог 15. До чтения элементов счётчик равен нулю. После 12 он остаётся нулём, после 18 становится единицей, после 9 не меняется, после 21 равен двум. Это не случайное совпадение: после обработки первых k элементов счётчик равен числу подходящих среди именно этих k элементов.

Начальное состояние соответствует k=0. Очередное сравнение либо добавляет ровно один подходящий элемент, либо не меняет ответ. После последней итерации обработан весь вход, поэтому локальный инвариант даёт глобальную корректность. Такой способ рассуждения полезнее проверки одного красивого примера. Отдельно уточняйте контракт: значение, равное порогу, в этой задаче не считается превышением.

## Сложность и память

| Что оцениваем | Гарантия                                                                            |
| ------------- | ----------------------------------------------------------------------------------- |
| Время         | Θ(n) сравнений с порогом; ввод тоже требует Θ(n).                                   |
| Память        | O(1) дополнительной памяти при потоковой обработке; сохранённый вход занимает O(n). |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Последовательное чтение массива использует соседние элементы одной cache line. Но для однократного подсчёта массив можно вообще не сохранять.

Хранение данных позволяет повторные запросы и отладку; потоковая обработка экономит память, но теряет исходные значения.

Практическое применение: Контроль перегрева по потоку показаний, подсчёт брака и нарушений порога.

<CommonMistake title="Типичная ошибка">

Тест с одним примером не доказывает контракт; отдельно проверяйте пустой вход, равенство порогу и все превышения.

</CommonMistake>

## Связь со STL C++

std::count_if выражает тот же проход через предикат. Алгоритм не создаёт копию диапазона.
