Этот модуль — о том, как решать задачи не просто правильно, а **быстро** и **надёжно**. Вы уже умеете писать программы на C; теперь научимся рассуждать о них: почему программа верна для любого ввода, сколько шагов она сделает на миллионе элементов и какую структуру данных выбрать, чтобы она уложилась в секунду.

## Что такое алгоритм

**Алгоритм** — точная последовательность шагов, которая для любых допустимых входных данных за конечное число шагов получает правильный результат. В этом определении три требования:

| Требование   | Что оно значит                                                |
| ------------ | ------------------------------------------------------------- |
| точность     | каждый шаг понятен однозначно, без «примерно» и «как-нибудь»  |
| конечность   | алгоритм останавливается на любом допустимом входе            |
| корректность | результат правильный для **каждого** входа, а не для примеров |

Программа на C — запись алгоритма для компьютера. Но один и тот же алгоритм можно записать на любом языке или словами, а одну задачу — решить разными алгоритмами.

## Сначала — условие задачи

Прежде чем писать алгоритм, нужно точно сформулировать, **что** он получает и **что** должен вернуть. Например:

- **Вход:** число `n` (от 1 до 1000) и `n` целых чисел.
- **Выход:** наибольшее из них.

Обратите внимание на «от 1»: при `n = 0` максимума нет, и условие должно сказать, что делать в этом случае. Половина ошибок в алгоритмах — это забытые граничные случаи условия: пустой ввод, один элемент, все элементы одинаковые, все отрицательные.

## Алгоритм поиска максимума

Словами: «запомни первое число как лучшее; затем просмотри остальные и, если очередное больше лучшего, запомни его».

```c
#include <stdio.h>

int main(void) {
    int n;
    scanf("%d", &n);
    int best;
    scanf("%d", &best);                  // первое число — пока лучшее
    for (int i = 1; i < n; i++) {
        int value;
        scanf("%d", &value);
        if (value > best) {
            best = value;
        }
    }
    printf("%d\n", best);
    return 0;
}
```

Ввод:

```text
5
3 8 -2 8 5
```

Вывод:

```text
8
```

Программа читает числа по одному и не хранит их в массиве: для максимума достаточно помнить одно лучшее значение.

## Трассировка

Чтобы понять, как работает алгоритм, выполните его вручную и запишите значения переменных после каждого шага. Такая таблица называется **трассировкой**:

| Шаг     | `value` | `best` |
| ------- | ------- | ------ |
| начало  | —       | 3      |
| `i = 1` | 8       | 8      |
| `i = 2` | −2      | 8      |
| `i = 3` | 8       | 8      |
| `i = 4` | 5       | 8      |

Трассировка — главный инструмент этого модуля. Если алгоритм непонятен, возьмите маленький вход и проследите его шаг за шагом.

## Почему алгоритм верен: инвариант цикла

Трассировка проверяет один вход. Чтобы убедиться, что алгоритм верен для **всех** входов, используют **инвариант цикла** — утверждение, которое истинно перед каждой итерацией.

Для поиска максимума инвариант такой: _перед итерацией с номером `i` переменная `best` равна наибольшему из первых `i` чисел._

Доказательство состоит из трёх шагов:

1. **Начало.** Перед первой итерацией `i = 1`, а `best` — первое число. Наибольшее из одного числа — оно само. Верно.
2. **Сохранение.** Пусть перед итерацией `best` — максимум первых `i` чисел. Итерация сравнивает его с `(i + 1)`-м числом и оставляет большее. Значит, после неё `best` — максимум первых `i + 1` чисел.
3. **Завершение.** Цикл заканчивается при `i = n`. По инварианту `best` — максимум всех `n` чисел. Это и требовалось.

Это рассуждение похоже на математическую индукцию. Оно не требует перебирать входы и работает для любого `n` от 1 до 1000.

## Почему алгоритм останавливается

Цикл `for` от 1 до `n` очевидно конечен. Но бывают циклы, где это неочевидно. Классический пример — **алгоритм Евклида** для наибольшего общего делителя (НОД): пока `b` не ноль, заменить пару `(a, b)` на `(b, a % b)`.

```c
#include <stdio.h>

int main(void) {
    int a = 48, b = 18;
    while (b != 0) {
        printf("a = %d, b = %d\n", a, b);
        int rest = a % b;
        a = b;
        b = rest;
    }
    printf("НОД = %d\n", a);
    return 0;
}
```

Вывод:

```text
a = 48, b = 18
a = 18, b = 12
a = 12, b = 6
НОД = 6
```

Алгоритм останавливается, потому что остаток `a % b` всегда меньше `b`: значение `b` — неотрицательное целое и на каждом шаге строго уменьшается, а бесконечно уменьшаться неотрицательное целое не может. Такую величину называют **вариантом цикла**. Если для цикла не удаётся назвать вариант, стоит проверить, не может ли он зациклиться.

Верен алгоритм благодаря инварианту: НОД пары `(a, b)` равен НОД пары `(b, a % b)`, потому что общие делители у этих пар одинаковые. Когда `b` становится нулём, НОД `(a, 0)` равен `a`.

## Одна задача — разные алгоритмы

НОД можно найти и «в лоб»: перебирать делители от меньшего числа вниз, пока не найдётся общий.

```c
#include <stdio.h>

static int gcd_brute(int a, int b, int *steps) {
    int d = a < b ? a : b;
    *steps = 0;
    while (a % d != 0 || b % d != 0) {
        d--;
        (*steps)++;
    }
    return d;
}

static int gcd_euclid(int a, int b, int *steps) {
    *steps = 0;
    while (b != 0) {
        int rest = a % b;
        a = b;
        b = rest;
        (*steps)++;
    }
    return a;
}

int main(void) {
    int s1, s2;
    int g1 = gcd_brute(1000000, 999999, &s1);
    int g2 = gcd_euclid(1000000, 999999, &s2);
    printf("перебор: НОД %d, шагов %d\n", g1, s1);
    printf("Евклид:  НОД %d, шагов %d\n", g2, s2);
    return 0;
}
```

Вывод:

```text
перебор: НОД 1, шагов 999998
Евклид:  НОД 1, шагов 2
```

Оба алгоритма корректны, но первый делает почти миллион шагов, а второй — два. Перебор к тому же требует, чтобы оба числа были положительными: при `b = 0` он делит на ноль. Сравнивать алгоритмы по числу шагов мы научимся в следующих уроках.

<Concept title="Три вопроса к любому алгоритму">

1. **Верен ли он?** — инвариант цикла и проверка граничных случаев.
2. **Остановится ли он?** — вариант цикла: величина, которая строго уменьшается.
3. **Насколько он быстр?** — сколько шагов он делает в зависимости от размера входа.

</Concept>

## Частые ошибки

<CommonMistake title="Начальное значение «из головы»">

```c
int best = 0;
for (int i = 0; i < n; i++) {
    if (values[i] > best) best = values[i];
}
```

Для чисел `-5 -3 -9` программа напечатает `0`, которого во входе нет. Инвариант «`best` — максимум просмотренных чисел» нарушен уже в начале: ни одного числа не просмотрено, а `best` равен 0. Начинайте с первого элемента — или с `INT_MIN` из `<limits.h>`, если пустой ввод обрабатывается отдельно.

</CommonMistake>

<CommonMistake title="Проверка на примерах вместо рассуждения">

Программа, которая выдаёт верные ответы на три примера из условия, может ошибаться на пустом вводе, одном элементе или повторах. Перед отправкой решения переберите граничные случаи и проверьте инвариант на каждом.

</CommonMistake>

<CommonMistake title="Цикл без варианта">

```c
while (x != 1) {
    x = x % 2 == 0 ? x / 2 : 3 * x + 1;
}
```

Никто не доказал, что этот цикл останавливается для всех `x` (это знаменитая гипотеза Коллатца), а при `x = 0` он точно зацикливается: `0 / 2 == 0`. Если не можете назвать величину, которая уменьшается, — добавьте ограничение на число шагов.

</CommonMistake>

## Практика

1. **Максимум и его позиция** — разминка на инвариант.
2. **НОД и число шагов** — алгоритм Евклида с подсчётом.
3. **Найди ошибку: минимум** — неверное начальное значение.
4. **Второй максимум** — инвариант из двух переменных.

## Итоги

- Алгоритм — точная и конечная последовательность шагов, верная для **каждого** допустимого входа.
- Начинайте с условия: вход, выход и граничные случаи.
- Трассировка проверяет алгоритм на одном входе; инвариант цикла доказывает его для всех.
- Инвариант доказывают в три шага: начало, сохранение, завершение.
- Остановку доказывает вариант цикла — неотрицательная величина, которая строго уменьшается.
- У одной задачи бывают алгоритмы, различающиеся по скорости в сотни тысяч раз.
