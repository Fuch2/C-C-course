## Линейное время

Алгоритм работает за **O(n)**, если число операций пропорционально размеру входа: каждый элемент обрабатывается константное число раз. Сумма, минимум, максимум, подсчёт элементов с условием — всё это один проход, `O(n)`.

Для многих задач `O(n)` — лучшее, на что можно надеяться: чтобы ответить на вопрос о данных, их нужно хотя бы прочитать, а чтение `n` чисел — уже `n` операций. Такую оценку называют **нижней границей**: быстрее, чем за `O(n)`, сумму `n` произвольных чисел не посчитать.

Этот урок — о трёх приёмах, которые превращают «очевидные» решения за `O(n²)` в решения за `O(n)`.

## Приём 1. Префиксные суммы

Задача: дан массив и много запросов «сумма элементов с `l` по `r`». Если на каждый запрос складывать элементы циклом, это `O(n)` на запрос, а на `q` запросов — `O(n · q)`. При `n = q = 10⁵` — 10¹⁰ операций.

Решение — один раз посчитать **префиксные суммы**: `prefix[i]` — сумма первых `i` элементов. Тогда сумма с `l` по `r` (нумерация с 1) — это `prefix[r] − prefix[l − 1]`:

```text
индекс:     1   2   3   4   5
values:     3   1   4   1   5
prefix: 0   3   4   8   9  14
```

Сумма со 2-го по 4-й элемент: `prefix[4] − prefix[1] = 9 − 3 = 6` (и правда, `1 + 4 + 1 = 6`).

```c
#include <stdio.h>

int main(void) {
    int values[] = {3, 1, 4, 1, 5};
    int n = 5;
    long long prefix[6];
    prefix[0] = 0;
    for (int i = 1; i <= n; i++) {
        prefix[i] = prefix[i - 1] + values[i - 1];
    }
    int queries[][2] = {{2, 4}, {1, 5}, {3, 3}};
    for (int k = 0; k < 3; k++) {
        int l = queries[k][0], r = queries[k][1];
        printf("сумма [%d, %d] = %lld\n", l, r, prefix[r] - prefix[l - 1]);
    }
    return 0;
}
```

Вывод:

```text
сумма [2, 4] = 6
сумма [1, 5] = 14
сумма [3, 3] = 4
```

Подготовка — `O(n)`, каждый запрос — `O(1)`, итого `O(n + q)`. Нулевой элемент `prefix[0] = 0` избавляет от особого случая `l = 1`.

## Приём 2. Два указателя

Задача: в **отсортированном** массиве найти два элемента с суммой `target`. Перебор всех пар — `O(n²)`. Но отсортированность позволяет действовать умнее.

Поставим один указатель на начало, другой на конец. Если сумма меньше `target`, её нужно увеличить — сдвигаем левый указатель вправо. Если больше — сдвигаем правый влево. Если равна — пара найдена.

```c
#include <stdio.h>

int main(void) {
    int values[] = {1, 3, 4, 6, 8, 11};
    int n = 6, target = 14;
    int left = 0, right = n - 1;
    while (left < right) {
        int sum = values[left] + values[right];
        printf("[%d] + [%d] = %d\n", left, right, sum);
        if (sum == target) {
            printf("нашли: %d + %d\n", values[left], values[right]);
            break;
        }
        if (sum < target) {
            left++;
        } else {
            right--;
        }
    }
    return 0;
}
```

Вывод:

```text
[0] + [5] = 12
[1] + [5] = 14
нашли: 3 + 11
```

Почему мы не пропустим ответ? Инвариант: **все пары, где один из элементов левее `left` или правее `right`, уже исключены**. Если `values[left] + values[right] < target`, то `values[left]` с любым элементом не больше `values[right]` тоже даст сумму меньше `target` — значит, `left` не участвует ни в одной подходящей паре, и его можно отбросить. Аналогично для `right`.

Каждый шаг сдвигает один из указателей, а встретиться они могут не позже чем через `n − 1` шагов. Итого `O(n)` вместо `O(n²)`.

## Приём 3. Скользящее окно

Задача: найти наибольшую сумму `k` подряд идущих элементов. Наивно — для каждого начала сложить `k` элементов: `O(n · k)`. Но соседние окна отличаются всего двумя элементами: при сдвиге окна на один вправо в него входит новый элемент, а выходит самый левый.

```c
#include <stdio.h>

int main(void) {
    int values[] = {2, -1, 3, 5, -2, 4, 1};
    int n = 7, k = 3;
    long long window = 0;
    for (int i = 0; i < k; i++) {
        window += values[i];
    }
    long long best = window;
    int best_start = 0;
    for (int i = k; i < n; i++) {
        window += values[i] - values[i - k];   // вошёл values[i], вышел values[i - k]
        if (window > best) {
            best = window;
            best_start = i - k + 1;
        }
    }
    printf("лучшее окно с индекса %d, сумма %lld\n", best_start, best);
    return 0;
}
```

Вывод:

```text
лучшее окно с индекса 1, сумма 7
```

Трассировка по окнам:

| Начало окна | Элементы | Сумма | `best` | `best_start` |
| ----------- | -------- | ----- | ------ | ------------ |
| 0           | `2 −1 3` | 4     | 4      | 0            |
| 1           | `−1 3 5` | 7     | 7      | 1            |
| 2           | `3 5 −2` | 6     | 7      | 1            |
| 3           | `5 −2 4` | 7     | 7      | 1            |
| 4           | `−2 4 1` | 3     | 7      | 1            |

Окно с индекса 3 тоже даёт 7, но `best` обновляется только при **строгом** улучшении, поэтому запоминается первое из лучших окон. Каждый сдвиг — два обращения к массиву, а не `k`: весь алгоритм работает за `O(n)` при любом `k`.

## Скрытый квадрат

Линейный на вид код иногда скрывает квадратичную работу:

| Код                               | Почему он `O(n²)`                           |
| --------------------------------- | ------------------------------------------- |
| `for (i = 0; i < strlen(s); i++)` | `strlen` проходит строку на каждой итерации |
| `strcat(result, piece)` в цикле   | `strcat` каждый раз ищет конец строки       |
| вставка в начало массива в цикле  | каждая вставка сдвигает все элементы        |

Исправление всегда одно: не повторять работу, которую можно сделать один раз, — вычислить длину заранее, помнить, где конец строки, добавлять в конец.

<Concept title="Сделать работу один раз">

Все три приёма урока убирают повторную работу. Префиксные суммы считают каждую частичную сумму один раз. Два указателя не возвращаются назад: каждый элемент отбрасывается один раз. Скользящее окно не пересчитывает общую часть соседних окон. Если алгоритм за `O(n²)` много раз делает похожие вычисления, ищите способ переиспользовать результат.

</Concept>

## Частые ошибки

<CommonMistake title="Сдвиг на единицу в префиксных суммах">

С `prefix[0] = 0` сумма `[l, r]` (с 1) — `prefix[r] − prefix[l − 1]`. Частая ошибка — `prefix[r] − prefix[l]`: она теряет элемент `l`. Проверяйте формулу на отрезке из одного элемента: `[3, 3]` должен дать `values[3]`.

</CommonMistake>

<CommonMistake title="Два указателя на несортированном массиве">

Рассуждение «если сумма велика, двигаем правый указатель» опирается на порядок. На массиве `3 1 2` с целью 3 указатели проверят `3 + 2 = 5` и `3 + 1 = 4`, обе суммы больше 3, и остановятся — хотя `1 + 2 = 3`. Сначала сортировка — потом два указателя.

</CommonMistake>

<CommonMistake title="Последнее окно">

Цикл сдвига окна должен дойти до `i = n − 1`: условие `i < n`, а не `i < n − 1`. Иначе последнее окно не проверяется — и ошибка видна, только если лучшее окно стоит в конце.

</CommonMistake>

## Практика

1. **Суммы на отрезках** — префиксные суммы.
2. **Пара с суммой** — два указателя в отсортированном массиве.
3. **Найди ошибку: лучшее окно** — пропущенное последнее окно.
4. **Длинный отрезок** — окно переменной длины.

## Итоги

- `O(n)` — каждый элемент обрабатывается константное число раз; для задач, где нужно прочитать весь вход, это нижняя граница.
- Префиксные суммы: подготовка `O(n)`, сумма любого отрезка — `O(1)`.
- Два указателя в отсортированном массиве находят пару за `O(n)` вместо `O(n²)`.
- Скользящее окно обновляет сумму за `O(1)` при сдвиге: вошёл один элемент, вышел другой.
- `strlen` в условии цикла, `strcat` в цикле и вставка в начало массива превращают линейный код в квадратичный.
