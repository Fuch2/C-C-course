## Теория и инвариант

Линейный проход касается каждого элемента ограниченное число раз. Для суммы произвольных измерений пропуск элемента может изменить ответ, поэтому без дополнительных сведений требуется прочитать все значения. Оптимизация констант не убирает эту информационную необходимость.

Можно объединить сумму, минимум и число превышений в один проход, сократив повторное чтение. Но слишком много независимой работы в одной функции ухудшает ясность и может мешать векторизации. Формулируйте инвариант каждого накопителя. Для пустого набора сумма определена как ноль, а минимум требует отдельного статуса, поскольку элемента нет.

## Пошаговый разбор

Сумма [3,-2,5] проходит 0 → 3 → 1 → 6; пустой массив оставляет ноль.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>


int main(void) {
int a[]={3,-2,5};long long sum=0;for(int i=0;i<3;++i)sum+=a[i];printf("%lld\n",sum);
return 0;
}
```

Ожидаемый вывод:

```text
6
```

## Почему реализация корректна

При суммировании 7, −2, 5 аккумулятор принимает значения 0, 7, 5, 10. После k шагов он равен сумме префикса длины k. Отрицательные значения ничего не меняют в доказательстве; пустой префикс естественно имеет сумму ноль.

Дополнительная память аккумулятора O(1). Если вход уже лежит в массиве, его O(n) памяти не исчезает: разделяйте память входа и рабочую память алгоритма. Потоковая версия могла бы читать и складывать значения сразу, не сохраняя весь массив. Тип суммы выбирают по произведению максимального количества элементов на максимальную величину одного, а не по типу отдельного измерения.
