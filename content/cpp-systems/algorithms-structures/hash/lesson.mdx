## Поиск по любому ключу за O(1)

В уроке об `O(1)` прямая адресация отвечала на вопрос «встречалось ли число x?» одним обращением к массиву — но только для небольших чисел: таблица занимает столько ячеек, сколько возможных значений. Для чисел до миллиарда, а тем более для строк, так не получится.

**Хеш-таблица** (hash table) сохраняет идею прямой адресации, но сжимает огромное множество ключей в небольшой массив. **Хеш-функция** превращает ключ в номер ячейки — **корзины** (bucket), — и ключ хранится в этой корзине. В среднем поиск, вставка и удаление работают за `O(1)` — для чисел любого размера, строк и любых других ключей.

## Хеш-функция

Хеш-функция должна:

- быть **детерминированной** — один и тот же ключ всегда даёт одно и то же число;
- работать **быстро** — за время, пропорциональное длине ключа;
- **равномерно разбрасывать** ключи по корзинам — похожие ключи должны попадать в разные корзины.

Для строк часто используют **FNV-1a**: начать с фиксированного числа и для каждого байта сначала сделать XOR, затем умножить на большое простое число. Вычисления ведутся в беззнаковом типе: переполнение беззнаковых чисел в C определено — это арифметика по модулю `2³²`.

```c
#include <stdint.h>
#include <stdio.h>

static uint32_t fnv1a(const char *s) {
    uint32_t h = 2166136261u;
    for (; *s != '\0'; s++) {
        h ^= (unsigned char)*s;
        h *= 16777619u;
    }
    return h;
}

int main(void) {
    const char *words[] = {"cat", "cot", "act", "dog", "god"};
    for (int i = 0; i < 5; i++) {
        uint32_t h = fnv1a(words[i]);
        printf("%-3s %10u корзина %u из 8\n", words[i], h, h % 8);
    }
    return 0;
}
```

Вывод:

```text
cat  108289031 корзина 7 из 8
cot 4203602185 корзина 1 из 8
act  759842187 корзина 3 из 8
dog 3865623817 корзина 1 из 8
god 1209769725 корзина 5 из 8
```

Слова из одних и тех же букв получают совершенно разные хеши — функция учитывает порядок символов. Сумма кодов букв дала бы всем анаграммам одинаковый хеш, и они попадали бы в одну корзину.

## Коллизии неизбежны

Ключей бесконечно много, а корзин — конечное число, поэтому разные ключи неизбежно будут попадать в одну корзину. Это **коллизия**. В примере `cot` и `dog` попали в одну корзину — 1, хотя у них нет ничего общего. Коллизии случаются гораздо раньше, чем кажется: по «парадоксу дней рождения» уже 23 ключа в 365 корзинах дают коллизию с вероятностью больше 50 %.

Хеш-таблица должна уметь хранить несколько ключей в одной корзине. Два основных способа — цепочки и открытая адресация.

## Цепочки

В каждой корзине хранится **односвязный список** ключей, попавших в неё. Поиск: вычислить корзину и пройти её список. Вставка: если ключа нет, добавить узел в начало списка.

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

enum { BUCKETS = 8 };

typedef struct Entry {
    char *key;
    int value;
    struct Entry *next;
} Entry;

static uint32_t fnv1a(const char *s) {
    uint32_t h = 2166136261u;
    for (; *s != '\0'; s++) {
        h ^= (unsigned char)*s;
        h *= 16777619u;
    }
    return h;
}

static Entry *find(Entry *table[], const char *key) {
    for (Entry *e = table[fnv1a(key) % BUCKETS]; e != NULL; e = e->next) {
        if (strcmp(e->key, key) == 0) {
            return e;
        }
    }
    return NULL;
}

static void put(Entry *table[], const char *key, int value) {
    Entry *e = find(table, key);
    if (e != NULL) {
        e->value = value;                       // ключ уже есть — обновить
        return;
    }
    e = malloc(sizeof *e);
    char *copy = malloc(strlen(key) + 1);
    if (e == NULL || copy == NULL) {
        exit(1);
    }
    strcpy(copy, key);
    uint32_t b = fnv1a(key) % BUCKETS;
    e->key = copy;
    e->value = value;
    e->next = table[b];                         // в начало цепочки
    table[b] = e;
}

int main(void) {
    Entry *table[BUCKETS] = {NULL};
    put(table, "cat", 3);
    put(table, "dog", 5);
    put(table, "god", 7);
    put(table, "cat", 4);
    const char *queries[] = {"cat", "dog", "god", "act"};
    for (int i = 0; i < 4; i++) {
        Entry *e = find(table, queries[i]);
        printf("%s: %d\n", queries[i], e != NULL ? e->value : -1);
    }
    for (int b = 0; b < BUCKETS; b++) {
        while (table[b] != NULL) {
            Entry *next = table[b]->next;
            free(table[b]->key);
            free(table[b]);
            table[b] = next;
        }
    }
    return 0;
}
```

Вывод:

```text
cat: 4
dog: 5
god: 7
act: -1
```

Таблица хранит **копию** ключа: если бы она хранила указатель на чужую строку, изменение или освобождение этой строки сломало бы таблицу.

## Коэффициент заполнения и рост

Отношение числа ключей `n` к числу корзин `m` называют **коэффициентом заполнения** `α = n / m`. При хорошей хеш-функции средняя длина цепочки — `α`, и поиск стоит `O(1 + α)`. Пока `α` ограничено константой, операции работают за `O(1)` в среднем.

Поэтому таблица **растёт**: когда `α` превышает порог (обычно 0,75–1), число корзин удваивается и все ключи **перераспределяются** — ведь `hash % m` изменилось. Перераспределение стоит `O(n)`, но, как у динамического массива, происходит редко: вставка остаётся амортизированно `O(1)`.

## Открытая адресация

Второй способ — хранить ключи прямо в массиве, без списков. Если корзина занята, ключ кладут в **следующую** свободную: `(h + 1) % m`, `(h + 2) % m`, … Это **линейное пробирование**. Поиск идёт тем же маршрутом, пока не найдёт ключ или пустую ячейку.

```c
#include <stdio.h>

enum { M = 8, EMPTY = -1 };

int main(void) {
    int table[M];
    for (int i = 0; i < M; i++) {
        table[i] = EMPTY;
    }
    int keys[] = {10, 18, 26, 3, 11};           // остатки по модулю 8: 2, 2, 2, 3, 3
    for (int k = 0; k < 5; k++) {
        int i = keys[k] % M;
        while (table[i] != EMPTY) {
            i = (i + 1) % M;                    // следующая ячейка
        }
        table[i] = keys[k];
    }
    for (int i = 0; i < M; i++) {
        printf("%d ", table[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
-1 -1 10 18 26 3 11 -1
```

`10`, `18` и `26` хотели в ячейку 2 и выстроились подряд. Затем `3` хотело в ячейку 3 — занято, ушло в 5; `11` — тоже в 3, ушло в 6. Занятые подряд ячейки образуют **кластер**, и он растёт сам собой: каждая коллизия удлиняет его. Поэтому открытую адресацию держат заполненной не больше чем на 50–70 %.

У открытой адресации есть тонкость с удалением: если просто очистить ячейку, поиск ключа, который лежит дальше по маршруту, остановится на этой пустоте и ключ «пропадёт». Удалённую ячейку помечают специальным значением — **надгробием** (tombstone): поиск через него проходит, а вставка может его занять.

Зато открытая адресация не выделяет память на каждый ключ и обходит память подряд — на практике она часто быстрее цепочек.

## Худший случай

Все гарантии хеш-таблицы — **средние**. Если все ключи попадут в одну корзину, таблица превратится в список, и операции станут `O(n)`. Случайно с хорошей функцией это почти невозможно, но злоумышленник, знающий хеш-функцию, может специально подобрать такие ключи и «завалить» сервер — это атака **hash flooding**. Защита — хеш-функция со случайным секретным начальным значением.

В C++ хеш-таблица — `std::unordered_map` (модуль «Основы C++»):

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> count;
    for (const char *word : {"cat", "dog", "cat", "cat", "dog", "owl"}) {
        ++count[word];
    }
    std::cout << count["cat"] << ' ' << count["dog"] << ' ' << count["owl"] << '\n';
    return 0;
}
```

Вывод:

```text
3 2 1
```

<Concept title="Хеш-таблица">

Хеш-функция превращает ключ в номер корзины, и ключ хранится в своей корзине. Коллизии разрешают цепочками или открытой адресацией. При ограниченном коэффициенте заполнения поиск, вставка и удаление работают за `O(1)` в среднем; таблица растёт с перераспределением ключей, амортизированно `O(1)`. Худший случай — `O(n)`, если ключи попали в одну корзину.

</Concept>

## Частые ошибки

<CommonMistake title="Знаковый хеш">

```c
int h = 0;
for (; *s; s++) h = h * 31 + *s;     // переполнение int — неопределённое поведение
return h % BUCKETS;                  // и отрицательный номер корзины
```

На длинных строках `h` переполняется, а `%` от отрицательного числа отрицателен — обращение `table[-3]`. Считайте хеш в `uint32_t` или `uint64_t`.

</CommonMistake>

<CommonMistake title="Ключ без копии">

Если таблица хранит указатель на буфер, в который читаются слова, после следующего `scanf` все ключи «изменятся». Таблица должна владеть копией ключа и освобождать её при удалении.

</CommonMistake>

<CommonMistake title="Удаление очисткой при открытой адресации">

Очищенная ячейка обрывает маршрут поиска, и ключи за ней становятся ненаходимыми. Нужна отметка-надгробие.

</CommonMistake>

## Практика

1. **Частоты слов** — таблица с цепочками.
2. **Множество с открытой адресацией** — пробирование и надгробия.
3. **Найди ошибку: хеш строки** — знаковое переполнение.
4. **Пары с суммой для больших чисел** — таблица вместо массива встреч.

## Итоги

- Хеш-таблица хранит ключ в корзине с номером `hash(key) % m`; операции — `O(1)` в среднем.
- Хорошая хеш-функция детерминирована, быстра и равномерно разбрасывает ключи; считайте её в беззнаковом типе.
- Коллизии неизбежны: цепочки хранят списки в корзинах, открытая адресация ищет следующую свободную ячейку.
- Коэффициент заполнения `n / m` ограничивают, увеличивая таблицу с перераспределением ключей.
- При открытой адресации удалённые ячейки помечают надгробиями.
- Худший случай — `O(n)`; против подобранных ключей помогает хеш со случайным начальным значением.
