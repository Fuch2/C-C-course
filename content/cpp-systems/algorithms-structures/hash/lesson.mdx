## Цели обучения

- Объяснить инвариант: Хеш указывает начало района поиска, а ключ подтверждает конкретный адрес.

- Оценить память и компромиссы: Быстрый поиск по равенству против отсутствия порядка и зависимости от качества хеша.

## Теория и инвариант

Хеш-функция выбирает начальную позицию, но совпадение хеша не доказывает равенство ключей. При открытой адресации коллизии разрешаются поиском следующего слота. В реализации линейное пробирование ограничено capacity шагами, чтобы полный массив не создал бесконечный цикл. Отрицательный остаток C нормализуется перед использованием как индекс.

Удаление оставляет tombstone, а не EMPTY: за удалённым слотом могут лежать ключи той же цепочки. Вставка запоминает первый tombstone, но продолжает искать существующий ключ, чтобы обновление не создало дубликат. Высокий load factor и tombstones удлиняют цепочки. Учебная версия фиксирована на 17 слотах; производственная растущая таблица периодически делает rehash.

## Пошаговый разбор

0 и 17 попадают в один стартовый слот. После удаления 0 поиск 17 должен пройти через tombstone, а не остановиться.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

enum { CAPACITY=17, EMPTY=0, FULL=1, DELETED=2 };
typedef struct { int key,value,state; } Slot;
typedef struct { Slot slots[CAPACITY]; } Table;
static int hash(int key){return (key%CAPACITY+CAPACITY)%CAPACITY;}
static int find(const Table *t,int key){
    for(int step=0;step<CAPACITY;++step){
        int i=(hash(key)+step)%CAPACITY;
        if(t->slots[i].state==EMPTY)return -1;
        if(t->slots[i].state==FULL && t->slots[i].key==key)return i;
    }
    return -1;
}
static int set(Table *t,int key,int value){
    int candidate=-1;
    for(int step=0;step<CAPACITY;++step){
        int i=(hash(key)+step)%CAPACITY;Slot *s=&t->slots[i];
        if(s->state==FULL && s->key==key){s->value=value;return 1;}
        if(s->state!=FULL && candidate<0)candidate=i;
        if(s->state==EMPTY)break;
    }
    if(candidate<0)return 0;
    t->slots[candidate]=(Slot){key,value,FULL};return 1;
}
static int remove_key(Table *t,int key){
    int i=find(t,key);if(i<0)return 0;t->slots[i].state=DELETED;return 1;
}
int main(void) {
Table t={0};set(&t,0,10);set(&t,17,20);remove_key(&t,0);int i=find(&t,17);if(i<0)return 1;printf("%d\n",t.slots[i].value);
return 0;
}
```

Ожидаемый вывод:

```text
20
```

## Почему реализация корректна

Ключи 0 и 17 при вместимости 17 имеют один начальный слот. После вставки второй ключ занимает следующий свободный. Если при удалении 0 сделать слот EMPTY, поиск 17 остановится слишком рано. DELETED означает «элемента нет, но цепочка поиска продолжается».

При вставке запоминаем первый DELETED, продолжая искать существующий ключ до EMPTY или полного обхода. Иначе обновление может создать вторую запись одного ключа. Ограничение числа проб вместимостью гарантирует завершение даже в полностью заполненной таблице. Фиксированная учебная таблица не делает rehash: в реальной растущей реализации нужно учитывать load factor и цену переноса всех ключей.

## Сложность и память

| Что оцениваем | Гарантия                                                                           |
| ------------- | ---------------------------------------------------------------------------------- |
| Время         | Ожидаемо O(1) при хороших хешах и ограниченной загрузке; худший O(n), rehash O(n). |
| Память        | O(capacity), включая свободные и удалённые слоты.                                  |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Линейное пробирование читает соседние слоты, но кластеры повышают число чтений.

Быстрый поиск по равенству против отсутствия порядка и зависимости от качества хеша.

Практическое применение: Счётчики событий по идентификатору датчика и кеш результатов.

<CommonMistake title="Типичная ошибка">

Замена удалённого слота на EMPTY может сделать существующий ключ недоступным.

</CommonMistake>

## Связь со STL C++

std::unordered_map обещает средние оценки; не полагайтесь на порядок обхода и стабильность итераторов при rehash. Его внутреннее устройство не обязано быть открытой адресацией.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <unordered_map>
int main(){
std::unordered_map<int,int> counts;counts[17]=20;counts.erase(0);auto it=counts.find(17);if(it==counts.end())return 1;std::cout<<it->second<<"\n";
return 0;
}
```

Вывод:

```text
20
```
