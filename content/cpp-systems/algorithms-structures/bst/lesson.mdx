## Теория и инвариант

BST добавляет инвариант: все ключи левого поддерева меньше ключа узла, правого — больше. Дубликаты в нашей версии не добавляются. Поиск сравнивает ключ и выбирает только одну ветвь. Inorder-обход посещает левое поддерево, узел, правое и выдаёт отсортированные ключи.

Скорость определяется высотой. Вставка отсортированных ключей в обычное BST строит цепочку, где поиск O(n). Поэтому обещать O(log n) без балансировки нельзя. При удалении узла с двумя детьми необходимо сохранить порядок, например через следующий по величине ключ; учебное упражнение сначала закрепляет вставку, поиск и освобождение. Балансировка — отдельный следующий шаг, а не скрытая возможность приведённого кода.

## Пошаговый разбор

Вставка 4,2,6 даёт высоту 2; вставка 2,4,6 даёт цепочку высоты 3. Одинаковый набор не гарантирует одинаковую форму.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct Node { int key; struct Node *left,*right; } Node;
static int insert(Node **root,int key){
    while(*root){
        if(key==(*root)->key)return 1;
        root=key<(*root)->key?&(*root)->left:&(*root)->right;
    }
    *root=malloc(sizeof **root);if(!*root)return 0;
    **root=(Node){key,NULL,NULL};return 1;
}
static int contains(const Node *root,int key){
    while(root){if(root->key==key)return 1;root=key<root->key?root->left:root->right;}return 0;
}
static void inorder(const Node *root,int *first){
    if(!root)return;inorder(root->left,first);
    printf("%s%d",*first?"":" ",root->key);*first=0;inorder(root->right,first);
}
static void destroy(Node *root){if(root){destroy(root->left);destroy(root->right);free(root);}}
int main(void) {
Node *root=NULL;if(!insert(&root,4)||!insert(&root,2)||!insert(&root,6)){destroy(root);return 1;}int first=1;inorder(root,&first);puts("");destroy(root);
return 0;
}
```

Ожидаемый вывод:

```text
2 4 6
```

## Почему реализация корректна

Вставка 4,2,6 создаёт корень 4 с детьми 2 и 6. При поиске 5 сначала выбираем правую ветвь, затем левую от 6 и встречаем NULL: ключ отсутствует. Это исключение целого поддерева опирается на инвариант порядка, а не на форму дерева. Повторная вставка 2 в нашем множестве ничего не добавляет.

Inorder обходит левое поддерево, печатает корень, затем правое: инвариант гарантирует сортировку. Вставки 1,2,3,4 превращают дерево в цепочку. Время операции определяется высотой h, которая может достигать n; небольшие тесты не доказывают логарифмическую гарантию. Для production-нагрузок со строгими требованиями нужны балансировка либо подходящий библиотечный контейнер.

## Связь со STL C++

std::set и std::map обеспечивают логарифмические операции; стандарт не требует конкретно красно-чёрного дерева. Они сильнее по гарантиям, чем наша несбалансированная версия.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <set>
int main(){
std::set<int> a{4,2,6,2};bool first=true;for(int x:a){std::cout<<(first?"":" ")<<x;first=false;}std::cout<<"\n";
return 0;
}
```

Вывод:

```text
2 4 6
```
