## Двоичный поиск в виде дерева

Отсортированный массив ищет за `O(log n)`, но вставка в него стоит `O(n)` — нужно сдвигать элементы. Связный список вставляет за `O(1)`, но ищет за `O(n)`. **Дерево двоичного поиска** (binary search tree, BST) соединяет преимущества: и поиск, и вставка, и удаление — за `O(h)`, где `h` — высота дерева. Если дерево сбалансировано, это `O(log n)`.

Дерево поиска — бинарное дерево с **упорядоченными ключами**: для каждого узла все ключи в его **левом поддереве** меньше ключа узла, а все ключи в **правом** — больше.

```text
           8
         /   \
        3     10
       / \      \
      1   6      14
         / \     /
        4   7   13
```

Именно это дерево в прошлом уроке дало при центральном обходе отсортированную последовательность: `1 3 4 6 7 8 10 13 14`. Это свойство любого дерева поиска: центральный обход выдаёт ключи по возрастанию.

## Поиск

Сравниваем ключ с корнем. Равен — нашли. Меньше — искомый ключ может быть только в левом поддереве, больше — только в правом. Каждое сравнение отбрасывает целое поддерево, как двоичный поиск отбрасывает половину массива.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    struct Node *left;
    struct Node *right;
} Node;

static bool contains(const Node *t, int key) {
    while (t != NULL) {
        if (key == t->key) {
            return true;
        }
        t = key < t->key ? t->left : t->right;
    }
    return false;
}

static Node *insert(Node *t, int key) {
    if (t == NULL) {                              // нашли место — новый лист
        Node *node = malloc(sizeof *node);
        if (node == NULL) {
            exit(1);
        }
        node->key = key;
        node->left = node->right = NULL;
        return node;
    }
    if (key < t->key) {
        t->left = insert(t->left, key);
    } else if (key > t->key) {
        t->right = insert(t->right, key);
    }                                             // равный ключ не вставляем
    return t;
}

static void inorder(const Node *t) {
    if (t == NULL) {
        return;
    }
    inorder(t->left);
    printf("%d ", t->key);
    inorder(t->right);
}

static void destroy(Node *t) {
    if (t == NULL) {
        return;
    }
    destroy(t->left);
    destroy(t->right);
    free(t);
}

int main(void) {
    int keys[] = {8, 3, 10, 1, 6, 14, 4, 7, 13, 6};
    Node *root = NULL;
    for (int i = 0; i < 10; i++) {
        root = insert(root, keys[i]);
    }
    inorder(root);
    printf("\n%d %d\n", contains(root, 7), contains(root, 5));
    destroy(root);
    return 0;
}
```

Вывод:

```text
1 3 4 6 7 8 10 13 14
1 0
```

Вставка идёт тем же путём, что поиск, и новый ключ становится **листом** там, где поиск упёрся в `NULL`. Функция возвращает корень поддерева: `t->left = insert(t->left, key)` подвешивает новый лист к родителю, а `root = insert(root, key)` обрабатывает и пустое дерево. Повторный ключ `6` не вставлен — дерево хранит множество. Если повторы нужны, договариваются отправлять равные ключи, например, вправо или хранить в узле счётчик.

## Минимум, максимум и соседи

Наименьший ключ — в самом левом узле: идём влево, пока можно. Наибольший — в самом правом. А «пол» — наибольший ключ, не превышающий `x`, — находится одним спуском: если ключ узла не больше `x`, он кандидат, и лучший кандидат может найтись правее; иначе идём влево.

```c
#include <stdio.h>

typedef struct Node {
    int key;
    struct Node *left, *right;
} Node;

static bool floor_key(const Node *t, int x, int *out) {
    bool found = false;
    while (t != NULL) {
        if (t->key <= x) {
            *out = t->key;                 // кандидат; ищем больший правее
            found = true;
            t = t->right;
        } else {
            t = t->left;
        }
    }
    return found;
}

int main(void) {
    Node n4 = {4, NULL, NULL}, n7 = {7, NULL, NULL}, n13 = {13, NULL, NULL};
    Node n1 = {1, NULL, NULL}, n6 = {6, &n4, &n7}, n14 = {14, &n13, NULL};
    Node n3 = {3, &n1, &n6}, n10 = {10, NULL, &n14};
    Node root = {8, &n3, &n10};
    int queries[] = {5, 8, 12, 0, 20};
    for (int i = 0; i < 5; i++) {
        int answer;
        if (floor_key(&root, queries[i], &answer)) {
            printf("пол(%d) = %d\n", queries[i], answer);
        } else {
            printf("пол(%d) нет\n", queries[i]);
        }
    }
    return 0;
}
```

Вывод:

```text
пол(5) = 4
пол(8) = 8
пол(12) = 10
пол(0) нет
пол(20) = 14
```

Отсортированный массив отвечает на такие вопросы двоичным поиском, хеш-таблица — не умеет вовсе: она не хранит порядок ключей. Это главная причина выбирать дерево вместо хеш-таблицы.

## Удаление

Удаление — самая сложная операция. Три случая:

1. **У узла нет детей** — просто удалить его.
2. **Один ребёнок** — подвесить этого ребёнка на место узла.
3. **Два ребёнка** — найти **преемника**: наименьший ключ правого поддерева (самый левый его узел). Он больше всех ключей слева и меньше всех остальных справа — значит, может встать на место удаляемого. Скопировать ключ преемника в узел и удалить преемника из правого поддерева; у преемника нет левого ребёнка, поэтому это случай 1 или 2.

```c
static Node *erase(Node *t, int key) {
    if (t == NULL) {
        return NULL;                                  // ключа нет
    }
    if (key < t->key) {
        t->left = erase(t->left, key);
    } else if (key > t->key) {
        t->right = erase(t->right, key);
    } else if (t->left == NULL || t->right == NULL) { // случаи 1 и 2
        Node *child = t->left != NULL ? t->left : t->right;
        free(t);
        return child;
    } else {                                          // случай 3
        Node *succ = t->right;
        while (succ->left != NULL) {
            succ = succ->left;
        }
        t->key = succ->key;
        t->right = erase(t->right, succ->key);        // удалить преемника справа
    }
    return t;
}
```

## Высота решает всё

Все операции спускаются по одному пути от корня — `O(h)`. Но высота зависит от **порядка вставки**. Ключи в случайном порядке дают дерево высотой около `2–3 · log₂ n`. А отсортированные ключи превращают дерево в «палку»: каждый новый ключ больше всех и уходит вправо.

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int key;
    struct Node *left, *right;
} Node;

static Node *insert(Node *t, int key) {
    if (t == NULL) {
        Node *node = malloc(sizeof *node);
        if (node == NULL) {
            exit(1);
        }
        node->key = key;
        node->left = node->right = NULL;
        return node;
    }
    if (key < t->key) {
        t->left = insert(t->left, key);
    } else if (key > t->key) {
        t->right = insert(t->right, key);
    }
    return t;
}

static int height(const Node *t) {
    if (t == NULL) {
        return -1;
    }
    int l = height(t->left), r = height(t->right);
    return 1 + (l > r ? l : r);
}

static void destroy(Node *t) {
    if (t != NULL) {
        destroy(t->left);
        destroy(t->right);
        free(t);
    }
}

int main(void) {
    enum { N = 1000 };
    Node *sorted = NULL, *mixed = NULL;
    for (int i = 0; i < N; i++) {
        sorted = insert(sorted, i);
        mixed = insert(mixed, (i * 7919) % N);    // те же ключи, перемешанные
    }
    printf("по порядку: высота %d\n", height(sorted));
    printf("вперемешку: высота %d\n", height(mixed));
    destroy(sorted);
    destroy(mixed);
    return 0;
}
```

Вывод:

```text
по порядку: высота 999
вперемешку: высота 25
```

Тысяча ключей: высота 999 — поиск как в списке — против 25. Поэтому на практике используют **самобалансирующиеся** деревья — AVL-деревья и красно-чёрные деревья. После каждой вставки и удаления они перестраивают несколько узлов поворотами и гарантируют высоту `O(log n)` на любом порядке ключей. Их устройство выходит за рамки урока; важно знать, что они есть и что `std::map` и `std::set` в C++ — именно такие деревья, с гарантией `O(log n)` на операцию.

<Concept title="Дерево двоичного поиска">

В каждом узле ключи левого поддерева меньше, правого — больше. Поиск, вставка и удаление спускаются по одному пути — `O(h)`. Центральный обход выдаёт ключи по возрастанию, а пол, потолок, минимум и максимум находятся одним спуском. Высота зависит от порядка вставки: от `log n` до `n`; балансирующие деревья гарантируют `O(log n)`.

</Concept>

## Частые ошибки

<CommonMistake title="Проверка только детей">

Условие «левый ребёнок меньше узла, правый — больше» **не** делает дерево деревом поиска. В дереве `8 → левый 3 → правый 9` каждый узел меньше или больше своего ребёнка как надо, но `9` лежит в левом поддереве `8`. Свойство относится ко **всему** поддереву.

</CommonMistake>

<CommonMistake title="Потерянный результат вставки">

`insert(root, key);` без присваивания `root = ...` работает, пока дерево не пусто, но первый ключ теряется: функция создаёт узел и возвращает его в никуда. Рекурсивные функции, которые возвращают новый корень поддерева, требуют присваивания на каждом уровне.

</CommonMistake>

<CommonMistake title="Преемник не из того поддерева">

При удалении узла с двумя детьми преемника нужно удалять из **правого** поддерева, где он лежит. Если вызвать удаление в левом поддереве, ключ преемника останется в дереве дважды.

</CommonMistake>

## Практика

1. **Вставка и поиск** — множество на дереве поиска.
2. **Пол и потолок** — ближайшие ключи.
3. **Найди ошибку: удаление** — преемник удаляется не оттуда.
4. **Проверка дерева поиска** — свойство всего поддерева.

## Итоги

- В дереве поиска ключи левого поддерева меньше узла, правого — больше; центральный обход выдаёт их по возрастанию.
- Поиск, вставка и удаление идут по одному пути — `O(h)`.
- Вставка создаёт новый лист; функция возвращает корень поддерева.
- Удаление узла с двумя детьми заменяет его ключ преемником из правого поддерева.
- Дерево умеет то, чего не умеет хеш-таблица: минимум, максимум, пол, потолок, обход по порядку.
- Высота зависит от порядка вставки; балансирующие деревья (`std::map`) гарантируют `O(log n)`.
