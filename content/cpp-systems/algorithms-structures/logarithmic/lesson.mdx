## Сколько раз можно делить пополам

Возьмите число 1000 и делите его пополам (нацело), пока не останется 1: `1000 → 500 → 250 → 125 → 62 → 31 → 15 → 7 → 3 → 1`. Девять делений. А для миллиона — девятнадцать, для миллиарда — двадцать девять.

Число делений пополам, за которое `n` превращается в 1, — это **двоичный логарифм** `log₂ n`, округлённый вниз. По определению `log₂ n` — степень, в которую нужно возвести 2, чтобы получить `n`: `log₂ 1024 = 10`, потому что `2¹⁰ = 1024`.

| `n`           | `log₂ n` (округлённо) |
| ------------- | --------------------- |
| 1 000         | 10                    |
| 1 000 000     | 20                    |
| 1 000 000 000 | 30                    |
| 10¹⁸          | 60                    |

Логарифм растёт невероятно медленно: при увеличении `n` в тысячу раз он прибавляет всего 10. Алгоритм, который на каждом шаге **отбрасывает половину** оставшихся данных, работает за **O(log n)** — для миллиарда элементов ему хватает тридцати шагов.

## Цикл, который делит пополам

Узнать логарифмический цикл легко: его переменная не увеличивается на единицу, а делится или умножается на константу.

```c
#include <stdio.h>

int main(void) {
    int sizes[] = {1, 2, 10, 1000, 1000000, 1000000000};
    for (int k = 0; k < 6; k++) {
        int steps = 0;
        for (int i = sizes[k]; i > 1; i /= 2) {
            steps++;
        }
        printf("%10d: %2d делений\n", sizes[k], steps);
    }
    return 0;
}
```

Вывод:

```text
         1:  0 делений
         2:  1 делений
        10:  3 делений
      1000:  9 делений
   1000000: 19 делений
1000000000: 29 делений
```

Тот же счёт получится, если умножать: `for (i = 1; i < n; i *= 2)` делает `⌈log₂ n⌉` шагов. Основание не обязательно 2 — цикл с `i /= 10` тоже логарифмический, он считает **десятичные цифры** числа. В O-нотации основание не пишут: все логарифмы отличаются в константу раз.

## Цифры числа

Число цифр в записи числа — тоже логарифм: у числа `n` в десятичной записи `⌊log₁₀ n⌋ + 1` цифр, в двоичной — `⌊log₂ n⌋ + 1`. Поэтому любой алгоритм, который перебирает цифры числа, работает за `O(log n)`:

```c
#include <stdio.h>

int main(void) {
    unsigned long long n = 9876543210ULL;
    int digits = 0, sum = 0;
    for (unsigned long long x = n; x > 0; x /= 10) {
        sum += (int)(x % 10);
        digits++;
    }
    printf("цифр %d, сумма цифр %d\n", digits, sum);
    return 0;
}
```

Вывод:

```text
цифр 10, сумма цифр 45
```

Число до 10¹⁰ — а цикл всего десять шагов. Именно поэтому, кстати, сложение двух чисел «столбиком» работает за `O(log n)`: длина записи числа — его логарифм.

## Быстрое возведение в степень

Посчитаем `aᵇ`. Прямой способ — умножить `a` само на себя `b` раз — делает `b` умножений. При `b = 10¹⁸` это невозможно.

Быстрый способ использует два наблюдения:

- если `b` чётно, то `aᵇ = (a²)^(b/2)`;
- если `b` нечётно, то `aᵇ = a · aᵇ⁻¹`.

Каждые один-два шага показатель уменьшается вдвое, значит, умножений `O(log b)`. В коде удобно идти по битам `b`: на каждом шаге основание возводится в квадрат, а если младший бит показателя равен 1, текущее основание домножается к результату.

Результат быстро становится огромным, поэтому степень обычно считают **по модулю** — остаток от деления на `m`. Остаток произведения можно брать после каждого умножения: `(x · y) % m = ((x % m) · (y % m)) % m`.

```c
#include <stdio.h>

static long long power_mod(long long base, long long exp, long long mod) {
    long long result = 1 % mod;
    base %= mod;
    int multiplications = 0;
    while (exp > 0) {
        if (exp % 2 == 1) {
            result = result * base % mod;
            multiplications++;
        }
        base = base * base % mod;
        multiplications++;
        exp /= 2;
    }
    printf("умножений: %d\n", multiplications);
    return result;
}

int main(void) {
    printf("%lld\n", power_mod(2, 10, 1000000007));
    printf("%lld\n", power_mod(3, 1000000000000000000LL, 1000000007));
    return 0;
}
```

Вывод:

```text
умножений: 6
1024
умножений: 84
246336683
```

Для показателя 10¹⁸ — 84 умножения вместо 10¹⁸. Трассировка для `2¹⁰` (`10 = 1010₂`):

| `exp` | бит | `result` | `base` после шага |
| ----- | --- | -------- | ----------------- |
| 10    | 0   | 1        | 4                 |
| 5     | 1   | 4        | 16                |
| 2     | 0   | 4        | 256               |
| 1     | 1   | 1024     | 65536             |

Результат собирается из степеней `2⁸ · 2² = 2¹⁰` — ровно тех, что соответствуют единицам в двоичной записи 10.

Почему модуль до 10⁹: произведение двух остатков меньше 10¹⁸ и помещается в `long long`. При модуле около 10¹⁸ произведение переполнилось бы.

## Логарифм в других алгоритмах

Вы уже видели логарифмический алгоритм: алгоритм Евклида каждые два шага уменьшает меньшее число как минимум вдвое, поэтому делает `O(log min(a, b))` шагов. Дальше в модуле логарифм появится много раз:

- двоичный поиск отбрасывает половину отсортированного массива — `O(log n)`;
- сортировка слиянием делит массив пополам `log n` раз — `O(n log n)`;
- сбалансированное дерево и куча высотой `log n` — `O(log n)` на операцию.

<Concept title="Отбросить половину">

Алгоритм работает за `O(log n)`, если за константную работу он уменьшает задачу в константу раз — чаще всего вдвое. Тогда до задачи размера 1 он дойдёт за `log₂ n` шагов. Для миллиарда это 30 шагов: логарифмический алгоритм практически не замечает роста входа.

</Concept>

## Частые ошибки

<CommonMistake title="Умножение, которое не растёт">

```c
for (int i = 0; i < n; i *= 2) { ... }
```

Ноль, умноженный на два, — ноль: цикл бесконечен. Логарифмический цикл с умножением начинается с 1.

</CommonMistake>

<CommonMistake title="Логарифм через double">

`(int)(log(1000) / log(10))` может дать 2 вместо 3: `log(1000) / log(10)` вычисляется приближённо и бывает равно 2,9999999999999996. Для целых чисел считайте цифры циклом или сравнивайте со степенями — это точно и так же быстро.

</CommonMistake>

<CommonMistake title="Переполнение в быстрой степени">

Без `base %= mod` в начале основание до 10¹⁸ возводится в квадрат и переполняет `long long`. Без `1 % mod` функция вернёт 1 при `mod = 1`, хотя любое число по модулю 1 равно 0.

</CommonMistake>

## Итоги

- `log₂ n` — сколько раз `n` можно поделить пополам до 1; для миллиарда это 30.
- Алгоритм, который каждый шаг уменьшает задачу в константу раз, работает за `O(log n)`.
- Цикл с `i /= 2` или `i *= 2` логарифмический; основание логарифма в O не важно.
- Число цифр числа — его логарифм; перебор цифр — `O(log n)`.
- Быстрое возведение в степень делает `O(log b)` умножений; остаток берут после каждого умножения.
- Логарифмы для целых чисел считайте целочисленно, а не через `double`.
