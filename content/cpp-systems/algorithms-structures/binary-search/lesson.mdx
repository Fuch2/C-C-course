## Цели обучения

- Объяснить инвариант: Граница между «ещё мало» и «уже достаточно», а не угадывание случайного совпадения.
- Обосновать время: O(log n) сравнений; сортировка исходных данных при необходимости стоит отдельно.
- Оценить память и компромиссы: Отсортированный массив удобен для чтений; вставки требуют сдвигов O(n).

## Теория и инвариант

Двоичный поиск использует отсортированный диапазон. В варианте lower_bound ищется первая позиция, где элемент не меньше target. Поддерживаем полуинтервал [left,right): слева уже известны меньшие элементы, справа — подходящие или конец. middle=left+(right-left)/2 не складывает две потенциально большие границы.

Если a[middle]&lt;target, исключаем middle и всё слева. Иначе сохраняем middle среди кандидатов, сдвигая right. В каждом шаге интервал строго сокращается, включая один элемент. При выходе left может равняться n; перед проверкой равенства ключу необходимо проверить границу. Дубликаты не ломают алгоритм: правая граница продолжает двигаться к первому совпадению.

<Concept title="Ментальная модель">

Граница между «ещё мало» и «уже достаточно», а не угадывание случайного совпадения.

</Concept>

## Пошаговый разбор

В [1,3,3,7], target=3: [0,4) → [0,2) → [0,1) → [1,1). Первая позиция равна 1.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static int lower(const int *a,int n,int target){
    int left=0,right=n;
    while(left<right){
        int middle=left+(right-left)/2;
        if(a[middle]<target) left=middle+1; else right=middle;
    }
    return left;
}
int main(void) {
int a[]={1,3,3,7};printf("%d\n",lower(a,4,3));
return 0;
}
```

Ожидаемый вывод:

```text
1
```

## Почему реализация корректна

Пусть a=[1,3,3,7], цель 3, границы [0,4). Середина 2 содержит 3: оставляем левую половину вместе с возможной границей, устанавливая right=2. Середина 1 тоже содержит 3: right=1. Середина 0 содержит 1: left=1. Границы совпали на первом элементе, который не меньше цели.

Это ещё не доказательство наличия цели: для запроса 2 нижняя граница тоже равна 1, но a[1] равно 3. После цикла нужны left&lt;n и проверка равенства. Полуинтервал позволяет представить пустой вход [0,0), не вычисляя n−1. Середина left+(right−left)/2 избегает сложения двух больших индексов. Несортированный вход нарушает основание для отбрасывания половины.

## Cache locality и компромиссы

На больших массивах скачки ухудшают локальность, хотя сравнений намного меньше.

Отсортированный массив удобен для чтений; вставки требуют сдвигов O(n).

Практическое применение: Поиск временной отметки в отсортированном журнале.

## Связь со STL C++

std::lower_bound возвращает точку вставки; для ответа «найдено» проверьте end и равенство.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <algorithm>
#include <vector>
int main(){
std::vector<int> a{1,3,3,7};auto it=std::lower_bound(a.begin(),a.end(),3);std::cout<<(it-a.begin())<<"\n";
return 0;
}
```

Вывод:

```text
1
```
