## Угадай число

Загадано число от 1 до 100. На каждую попытку отвечают «больше», «меньше» или «угадал». Лучшая стратегия — называть середину оставшегося диапазона: 50, затем 25 или 75, и так далее. Каждый ответ отбрасывает **половину** вариантов, поэтому хватит семи попыток: `2⁷ = 128 ≥ 100`.

Так же можно искать в **отсортированном** массиве: сравнить искомое с элементом посередине и, в зависимости от ответа, продолжить в левой или правой половине. Это **двоичный поиск** (binary search). Для миллиона элементов ему нужно 20 сравнений, для миллиарда — 30. Линейному поиску понадобился бы миллион и миллиард.

Цена — данные должны быть отсортированы. Без порядка сравнение с серединой ничего не говорит о том, в какой половине искать.

## Классический вариант

Будем хранить границы `lo` и `hi` — отрезок `[lo, hi]`, где ещё может находиться искомое:

```c
#include <stdio.h>

static int binary_search(const int *values, int n, int target) {
    int lo = 0, hi = n - 1;
    while (lo <= hi) {
        int mid = lo + (hi - lo) / 2;
        printf("  lo=%d hi=%d mid=%d values[mid]=%d\n", lo, hi, mid, values[mid]);
        if (values[mid] == target) {
            return mid;
        }
        if (values[mid] < target) {
            lo = mid + 1;            // искомое правее mid
        } else {
            hi = mid - 1;            // искомое левее mid
        }
    }
    return -1;
}

int main(void) {
    int values[] = {2, 5, 8, 12, 16, 23, 38, 56, 72, 91};
    printf("ищем 23:\n");
    printf("индекс %d\n", binary_search(values, 10, 23));
    printf("ищем 7:\n");
    printf("индекс %d\n", binary_search(values, 10, 7));
    return 0;
}
```

Вывод:

```text
ищем 23:
  lo=0 hi=9 mid=4 values[mid]=16
  lo=5 hi=9 mid=7 values[mid]=56
  lo=5 hi=6 mid=5 values[mid]=23
индекс 5
ищем 7:
  lo=0 hi=9 mid=4 values[mid]=16
  lo=0 hi=3 mid=1 values[mid]=5
  lo=2 hi=3 mid=2 values[mid]=8
индекс -1
```

Поиск семёрки закончился, когда отрезок стал пустым: после третьего шага `lo = 2`, `hi = 1`, и цикл `lo <= hi` больше не выполняется.

**Инвариант:** если `target` есть в массиве, он находится на отрезке `[lo, hi]`. В начале это весь массив. Если `values[mid] < target`, то и все элементы левее `mid` меньше `target` (массив отсортирован) — их можно отбросить: `lo = mid + 1`. Симметрично для `hi`. Когда отрезок пуст (`lo > hi`), искомого нет.

**Остановка:** длина отрезка `hi − lo + 1` на каждой итерации уменьшается как минимум вдвое, поэтому итераций не больше `⌊log₂ n⌋ + 1`.

## Середина без переполнения

Почему `lo + (hi - lo) / 2`, а не `(lo + hi) / 2`? Если `lo` и `hi` близки к `INT_MAX`, их сумма переполнится — а это неопределённое поведение. Разность `hi − lo` всегда помещается в тип, и `lo + (hi − lo) / 2` даёт ту же середину. Эта ошибка годами жила в стандартной библиотеке Java и была найдена только тогда, когда массивы выросли до миллиарда элементов.

## Нижняя граница

Часто нужен не «какой-нибудь индекс с таким значением», а **первая позиция, где элемент не меньше `x`**. Её называют **нижней границей** (lower bound). Она отвечает сразу на несколько вопросов:

- есть ли `x` в массиве — да, если по этой позиции стоит `x`;
- где первое вхождение `x` при повторах;
- куда вставить `x`, чтобы не нарушить порядок;
- сколько элементов меньше `x` — сама позиция.

Её удобно писать на **полуинтервале** `[lo, hi)`: `lo` входит, `hi` — нет.

```c
#include <stdio.h>

static int lower_bound(const int *values, int n, int x) {
    int lo = 0, hi = n;                       // ответ лежит в [lo, hi]
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (values[mid] < x) {
            lo = mid + 1;                     // mid точно не ответ
        } else {
            hi = mid;                         // mid может быть ответом
        }
    }
    return lo;
}

static int upper_bound(const int *values, int n, int x) {
    int lo = 0, hi = n;
    while (lo < hi) {
        int mid = lo + (hi - lo) / 2;
        if (values[mid] <= x) {               // единственное отличие
            lo = mid + 1;
        } else {
            hi = mid;
        }
    }
    return lo;
}

int main(void) {
    int values[] = {1, 3, 3, 3, 7, 9};
    int n = 6;
    for (int x = 2; x <= 4; x++) {
        int lo = lower_bound(values, n, x), hi = upper_bound(values, n, x);
        printf("x=%d: lower %d, upper %d, вхождений %d\n", x, lo, hi, hi - lo);
    }
    printf("x=10: lower %d\n", lower_bound(values, n, 10));
    return 0;
}
```

Вывод:

```text
x=2: lower 1, upper 1, вхождений 0
x=3: lower 1, upper 4, вхождений 3
x=4: lower 4, upper 4, вхождений 0
x=10: lower 6
```

**Верхняя граница** (upper bound) — первая позиция, где элемент **больше** `x`. Разность `upper − lower` — число вхождений `x`. Если все элементы меньше `x`, ответ — `n`, позиция за концом массива: туда `x` и нужно вставить. Поэтому перед обращением `values[lo]` проверяйте `lo < n`.

Обратите внимание, что в этом варианте `hi = mid`, а не `mid − 1`: элемент `mid` может оказаться ответом, и выбрасывать его нельзя. Цикл всё равно остановится: `mid < hi` всегда, поэтому отрезок строго уменьшается.

## Поиск по ответу

Двоичный поиск работает не только с массивами. Ему нужно одно: **монотонное условие** — такое, что для маленьких значений оно ложно, а начиная с какого-то — истинно. Тогда точку перехода можно найти делением пополам.

Пример — целая часть квадратного корня: наибольшее `r`, для которого `r² ≤ n`. Условие «`r² > n`» монотонно: ложно до ответа и истинно после.

```c
#include <stdio.h>

static long long isqrt(long long n) {
    long long lo = 0, hi = 1000000001LL;          // (10⁹ + 1)² > 10¹⁸
    while (lo < hi) {                             // первое r с r * r > n
        long long mid = lo + (hi - lo) / 2;
        if (mid * mid > n) {
            hi = mid;
        } else {
            lo = mid + 1;
        }
    }
    return lo - 1;
}

int main(void) {
    long long tests[] = {0, 1, 15, 16, 17, 1000000000000000000LL};
    for (int i = 0; i < 6; i++) {
        printf("isqrt(%lld) = %lld\n", tests[i], isqrt(tests[i]));
    }
    return 0;
}
```

Вывод:

```text
isqrt(0) = 0
isqrt(1) = 1
isqrt(15) = 3
isqrt(16) = 4
isqrt(17) = 4
isqrt(1000000000000000000) = 1000000000
```

Около 30 итераций — и без вещественной арифметики, у которой `sqrt` для больших чисел может ошибиться на единицу. Этот приём называют **двоичным поиском по ответу**: перебирается не индекс, а само значение ответа.

## В стандартной библиотеке

В C есть функция `bsearch` из `<stdlib.h>`. Она устроена как `qsort`: принимает функцию сравнения и возвращает указатель на найденный элемент или `NULL`. Но при повторах она возвращает **какое-нибудь** вхождение, а нижней границы в библиотеке C нет — её пишут сами.

В C++ (модуль «Основы C++») есть `std::lower_bound`, `std::upper_bound` и `std::binary_search`:

```cpp
#include <algorithm>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values{1, 3, 3, 3, 7, 9};
    auto first = std::lower_bound(values.begin(), values.end(), 3);
    auto last = std::upper_bound(values.begin(), values.end(), 3);
    std::cout << first - values.begin() << ' ' << last - first << '\n';
    std::cout << std::boolalpha << std::binary_search(values.begin(), values.end(), 5) << '\n';
    return 0;
}
```

Вывод:

```text
1 3
false
```

<Concept title="Двоичный поиск">

На отсортированных данных сравнение с серединой отбрасывает половину вариантов: `O(log n)` сравнений. Главное в реализации — инвариант границ: что гарантированно лежит левее `lo`, что — правее `hi`, и может ли сам `mid` быть ответом. Нижняя граница — первая позиция с элементом `≥ x`; через неё выражаются поиск, первое вхождение, число вхождений и место вставки.

</Concept>

## Частые ошибки

<CommonMistake title="Бесконечный цикл: lo = mid">

```c
while (lo < hi) {
    int mid = lo + (hi - lo) / 2;
    if (values[mid] < x) lo = mid;      // должно быть mid + 1
    else hi = mid;
}
```

При `hi = lo + 1` середина равна `lo`, и `lo = mid` ничего не меняет — цикл вечен. Каждая ветка должна строго уменьшать отрезок.

</CommonMistake>

<CommonMistake title="Поиск в неотсортированном массиве">

Двоичный поиск в `5 1 4 2 3` может не найти `1`: первое сравнение с `4` отправит поиск влево, в `5 1`, а дальше всё зависит от удачи. Компилятор не предупредит — проверяйте, что данные отсортированы тем же порядком, которым вы ищете.

</CommonMistake>

<CommonMistake title="Чтение values[n]">

Нижняя граница может вернуть `n`. Код `if (values[lower_bound(...)] == x)` в этом случае читает элемент за концом массива. Сначала `pos < n`, затем сравнение.

</CommonMistake>

## Практика

1. **Есть ли число** — классический двоичный поиск.
2. **Числа в диапазоне** — нижняя и верхняя границы.
3. **Найди ошибку: потерянный кандидат** — граница, выбросившая ответ.
4. **Benchmark: сравнения поиска** — линейный против двоичного.
5. **Деление на отрезки** — двоичный поиск по ответу.

## Итоги

- Двоичный поиск работает только на отсортированных данных и делает `O(log n)` сравнений.
- Инвариант: искомое (если оно есть) лежит между границами; каждая итерация строго сужает отрезок.
- Середина — `lo + (hi − lo) / 2`, без переполнения.
- Нижняя граница — первая позиция с элементом `≥ x`, верхняя — `> x`; их разность — число вхождений.
- Результат может быть равен `n` — проверяйте границу до обращения к элементу.
- Двоичный поиск по ответу находит точку перехода любого монотонного условия.
