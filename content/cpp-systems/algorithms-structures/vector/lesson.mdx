## Цели обучения

- Объяснить инвариант: Ряд мест с запасом: занято size, построено capacity; при расширении весь ряд может переехать.
- Обосновать время: Индекс O(1), push амортизированно O(1), отдельный рост O(n), erase O(n).
- Оценить память и компромиссы: Запас памяти уменьшает частоту аллокаций, но не обеспечивает стабильность адресов.

## Теория и инвариант

Динамический массив хранит элементы подряд, но различает логическую длину size и выделенную вместимость capacity. Допустимы обращения только в [0,size), даже если allocator выделил больше. При заполнении вместимость увеличивают геометрически. realloc может перенести блок, поэтому результат сначала сохраняют во временный указатель. При отказе прежний владелец и данные остаются действительными.

Одно расширение копирует O(n) элементов, однако удвоения дают суммарно менее 2n переносов за n последовательных добавлений, если считать логическое копирование старых элементов при каждом росте. Удаление в середине сдвигает суффикс. Любые указатели на элементы после успешного realloc нужно получать заново. Умножение вместимости на sizeof элемента проверяют до вызова allocator.

## Пошаговый разбор

Добавления 10,20,30 дают состояния size/capacity: 1/1 → 2/2 → 3/4. Удаление позиции 1 сдвигает 30 влево.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct { int *data; size_t size,capacity; } Vector;
static int push(Vector *v,int value){
    if(v->size==v->capacity){
        if(v->capacity>SIZE_MAX/2)return 0;
        size_t capacity=v->capacity?v->capacity*2:1;
        if(capacity>SIZE_MAX/sizeof *v->data)return 0;
        int *next=realloc(v->data,capacity*sizeof *next);
        if(!next)return 0;
        v->data=next;v->capacity=capacity;
    }
    v->data[v->size++]=value;return 1;
}
static int erase(Vector *v,size_t position){
    if(position>=v->size)return 0;
    for(size_t i=position+1;i<v->size;++i)v->data[i-1]=v->data[i];
    --v->size;return 1;
}
static void destroy(Vector *v){free(v->data);*v=(Vector){0};}
int main(void) {
Vector v={0};if(!push(&v,10)||!push(&v,20)||!push(&v,30)){destroy(&v);return 1;}erase(&v,1);printf("%zu %zu %d\n",v.size,v.capacity,v.data[1]);destroy(&v);
return 0;
}
```

Ожидаемый вывод:

```text
2 4 30
```

## Почему реализация корректна

После P 10 состояние size=1, capacity=1. P 20 увеличивает вместимость до 2. P 30 увеличивает её до 4, оставляя один запасной слот. Удаление индекса 0 сдвигает 20 и 30 влево и уменьшает size до 2; capacity остаётся 4. Старое содержимое за size не является логическим элементом и не должно читаться через интерфейс.

При realloc сначала сохраняйте результат во временный указатель. Неудача оставляет старый блок действительным; прямое присваивание v->data=realloc(...) потеряет единственную ссылку на него. Успех может переместить блок и обесценить прежние указатели на элементы. Рост 1,2,4,8 даёт геометрическую сумму копирований; отдельная вставка дорога, последовательность вставок — линейна по общей работе.

## Связь со STL C++

std::vector управляет ресурсом автоматически. reserve меняет capacity, resize меняет size. Стандарт не фиксирует коэффициент роста.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <vector>
int main(){
std::vector<int> a; a.reserve(8);a.push_back(10);a.push_back(20);a.erase(a.begin());std::cout<<a.size()<<" "<<a.at(0)<<"\n";
return 0;
}
```

Вывод:

```text
1 20
```

## Benchmark-задача

Ввод n (0…10000). Сравните n добавлений при двух политиках: вместимость каждый раз size+1 и геометрический рост 0→1→2→4… Считайте логически переносимые прежние элементы при каждом росте, предполагая полный перенос. Новое значение не учитывается. Выведите два счётчика. Реальный realloc иногда расширяет блок на месте; здесь проверяется явно заданная модель, а не число физических копирований allocator.

Выберите «Benchmark: цена роста вместимости» среди заданий во вкладке «Практика». Сравните отсортированный, обратный, пустой и обычный вход там, где они применимы. Счётчик отвечает на вопрос об объёме работы; секунды зависят от машины и сборки.

Для отдельного эксперимента со временем подготовьте одинаковые входы до начала замера. Используйте clock() вокруг исследуемой операции, проверяйте результат на (clock_t)-1 и делите разницу на CLOCKS_PER_SEC с преобразованием к double. Выведите контрольную сумму результата, чтобы компилятор не мог просто удалить неиспользуемую работу. Короткую операцию повторяйте в пределах timeout: нулевой отсчёт может означать недостаточное разрешение часов.

Сделайте прогрев и несколько замеров с переменой порядка вариантов. Сравните медианы и разброс, запишите компилятор и режим сборки. Диагностику ASan/UBSan проверяйте отдельно: её накладные расходы искажают сравнение обычных реализаций. Поле времени всего запуска в интерфейсе не заменяет время операции. Никакое фиксированное ускорение не требуется для зачёта.
