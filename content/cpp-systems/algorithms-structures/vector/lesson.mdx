## Массив, который растёт

С этого урока начинается раздел о **структурах данных** — способах хранить данные так, чтобы нужные операции были быстрыми. Первая структура вам знакома: в модуле «Память и указатели» вы писали **динамический массив** — блок в куче, который увеличивается через `realloc`, когда место кончается.

```c
typedef struct {
    int *data;
    size_t size;        // сколько элементов хранится
    size_t capacity;    // на сколько элементов выделена память
} Vector;
```

Здесь нас интересует не реализация, а **стоимость операций** — и главный вопрос: как именно увеличивать ёмкость.

## Сколько стоит рост

При росте `realloc` выделяет новый блок и **копирует** в него все `size` элементов (иногда блок удаётся расширить на месте, но рассчитывать на это нельзя). Посчитаем копирования при `n` добавлениях для разных правил роста:

```c
#include <stdio.h>

static long long copies_for(int n, int strategy) {
    long long copies = 0;
    long long size = 0, capacity = 0;
    for (int i = 0; i < n; i++) {
        if (size == capacity) {
            copies += size;                                     // перенос в новый блок
            capacity = strategy == 0 ? capacity + 1             // по одному
                     : strategy == 1 ? capacity + 100           // по сто
                     : (capacity == 0 ? 1 : capacity * 2);      // удвоение
        }
        size++;
    }
    return copies;
}

int main(void) {
    const char *names[] = {"+1  ", "+100", "x2  "};
    for (int s = 0; s < 3; s++) {
        printf("%s:", names[s]);
        for (int n = 1000; n <= 1000000; n *= 10) {
            printf(" %13lld", copies_for(n, s));
        }
        printf("\n");
    }
    return 0;
}
```

Вывод:

```text
+1  :        499500      49995000    4999950000  499999500000
+100:          4500        495000      49950000    4999500000
x2  :          1023         16383        131071       1048575
```

Рост «по одному» копирует `0 + 1 + 2 + … + (n − 1) ≈ n²/2` элементов: миллион добавлений — полтриллиона копирований. Рост «по сто» лучше в сто раз, но всё равно квадратичен: `n² / 200`. А при **удвоении** копирований меньше `n` — для миллиона элементов чуть больше миллиона.

## Амортизированная стоимость

Почему при удвоении так мало? Перед последним ростом скопировано `n/2` элементов, перед предыдущим — `n/4`, и так далее:

```text
n/2 + n/4 + n/8 + … + 1 < n
```

Отдельное добавление иногда дорогое — когда массив растёт, копируется всё. Но такие добавления редки: после роста до ёмкости `2c` следующие `c` добавлений дешёвые. Если разделить общую стоимость на число операций, на каждую придётся меньше одного копирования. Это называют **амортизированной** стоимостью: добавление в конец работает за **амортизированное O(1)**.

Амортизированная оценка — это гарантия для **последовательности** операций: `n` добавлений всегда стоят `O(n)`. Она не обещает, что каждое отдельное добавление быстрое, — в системах, где важна задержка каждой операции (например, обработка звука), это бывает существенно.

Важно, что ёмкость растёт **в константу раз**, а не на константу. Любое прибавление фиксированного числа — сто, тысяча — даёт `O(n²)` на `n` добавлений, только с меньшей константой.

## Коэффициент роста

Множитель не обязан быть равен 2. Чем он больше, тем реже рост и меньше копирований, но тем больше памяти простаивает: сразу после роста в 2 раза половина блока пустая.

| Множитель | Копирований на элемент (в пределе) | Запас памяти сразу после роста |
| --------- | ---------------------------------- | ------------------------------ |
| 1,5       | около 2                            | 33 %                           |
| 2         | около 1                            | 50 %                           |
| 3         | около 0,5                          | 67 %                           |

Стандарт C++ не фиксирует множитель для `std::vector`: libstdc++ (GCC) удваивает ёмкость, Microsoft STL увеличивает в 1,5 раза. Важна только гарантия — амортизированное `O(1)` на добавление.

## Стоимость остальных операций

| Операция                   | Стоимость                                    |
| -------------------------- | -------------------------------------------- |
| чтение и запись по индексу | `O(1)`                                       |
| добавление в конец         | амортизированное `O(1)`                      |
| удаление из конца          | `O(1)`                                       |
| вставка в позицию `i`      | `O(n − i)` — сдвиг хвоста                    |
| удаление из позиции `i`    | `O(n − i)`                                   |
| поиск значения             | `O(n)`; `O(log n)`, если массив отсортирован |

Вставка и удаление в середине требуют сдвига всех элементов правее — `memmove`. Если такие операции частые, нужна другая структура: в следующем уроке — связный список.

## Уменьшение ёмкости

Если из массива удалили почти всё, память можно вернуть системе. Наивное правило «уменьшать вдвое, когда заполнен наполовину» опасно: у самой границы чередование добавлений и удалений будет то увеличивать, то уменьшать массив, и **каждая** операция станет копированием всех элементов. Правильно уменьшать вдвое, когда массив заполнен на **четверть**: после уменьшения он заполнен наполовину, и до следующего изменения ёмкости нужно не меньше `c/4` операций.

## Указатели внутрь массива

У роста есть опасное следствие: после `realloc` данные могут переехать, и **все указатели на элементы становятся висячими**.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t capacity = 2, size = 2;
    int *data = malloc(capacity * sizeof *data);
    if (data == NULL) {
        return 1;
    }
    data[0] = 10;
    data[1] = 20;
    int *first = &data[0];               // указатель на элемент

    capacity *= 2;                       // массив растёт
    int *grown = realloc(data, capacity * sizeof *data);
    if (grown == NULL) {
        free(data);
        return 1;
    }
    data = grown;
    data[size++] = 30;

    printf("%d\n", *first);              // Ошибка памяти: блок мог переехать
    free(data);
    return 0;
}
```

AddressSanitizer сообщает `heap-use-after-free`: старый блок освобождён, а `first` по-прежнему указывает в него. Без санитайзера программа может «случайно» работать — пока `realloc` расширяет блок на месте. Храните **индексы**, а не указатели на элементы растущего массива. В C++ это правило называют инвалидацией итераторов: `push_back` может сделать недействительными все указатели и ссылки на элементы `std::vector`.

<Concept title="Амортизированное O(1)">

Динамический массив, ёмкость которого растёт в константу раз, выполняет `n` добавлений за `O(n)` копирований: редкие дорогие росты «оплачиваются» многими дешёвыми добавлениями. Рост на фиксированное число элементов даёт `O(n²)`. Уменьшать ёмкость стоит при заполнении на четверть, а указатели на элементы после роста становятся недействительными.

</Concept>

## Частые ошибки

<CommonMistake title="Рост на константу">

`capacity += 16` выглядит экономно, но `n` добавлений стоят `O(n² / 16)` копирований. Растите в константу раз: `capacity *= 2`.

</CommonMistake>

<CommonMistake title="Указатель на элемент через рост">

Указатель или ссылка на элемент, полученные до добавления, после роста указывают в освобождённую память. Запоминайте индекс и обращайтесь `data[index]` после каждой операции, которая может вызвать рост.

</CommonMistake>

<CommonMistake title="Уменьшение на половине">

Уменьшение вдвое при заполнении наполовину сразу оставляет массив полным, и следующее же добавление снова его увеличивает. Порог уменьшения должен быть ниже порога роста: четверть.

</CommonMistake>

## Итоги

- Динамический массив даёт `O(1)` доступ по индексу и амортизированное `O(1)` добавление в конец.
- Рост в константу раз копирует меньше `2n` элементов на `n` добавлений; рост на константу — `O(n²)`.
- Амортизированная стоимость — средняя по последовательности операций; отдельная операция может быть дорогой.
- Вставка и удаление в середине — `O(n)` из-за сдвига.
- Уменьшайте ёмкость вдвое при заполнении на четверть.
- После роста указатели на элементы недействительны — храните индексы.
