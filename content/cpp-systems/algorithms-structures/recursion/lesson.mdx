## Функция, которая вызывает себя

**Рекурсия** — приём, при котором функция решает задачу, вызывая саму себя для задачи поменьше. Следующие два урока — сортировка слиянием и быстрая сортировка — построены на рекурсии, поэтому разберёмся в ней сейчас.

Классический пример — факториал: `n! = 1 · 2 · … · n`. Заметим, что `n! = n · (n − 1)!`. Если мы умеем считать факториал меньшего числа, то умеем и для `n`:

```c
#include <stdio.h>

static long long factorial(int n) {
    if (n == 0) {
        return 1;                        // базовый случай
    }
    return n * factorial(n - 1);         // рекурсивный шаг
}

int main(void) {
    for (int n = 0; n <= 5; n++) {
        printf("%d! = %lld\n", n, factorial(n));
    }
    printf("20! = %lld\n", factorial(20));
    return 0;
}
```

Вывод:

```text
0! = 1
1! = 1
2! = 2
3! = 6
4! = 24
5! = 120
20! = 2432902008176640000
```

У любой правильной рекурсии две части:

1. **Базовый случай** — задача настолько маленькая, что ответ известен без рекурсии: `0! = 1`.
2. **Рекурсивный шаг** — задача сводится к **меньшей** задаче того же вида: `n!` через `(n − 1)!`.

Если базового случая нет или шаг не приближает к нему, функция вызывает себя бесконечно.

## Что происходит при вызове

Каждый вызов функции получает свой **кадр стека** — место для параметров и локальных переменных (вы видели его в модуле о памяти). У вызова `factorial(3)` свой `n = 3`, у вложенного `factorial(2)` — свой `n = 2`, и они не мешают друг другу. Проследим вызовы, печатая отступ по глубине:

```c
#include <stdio.h>

static int factorial(int n, int depth) {
    printf("%*sfactorial(%d)\n", depth * 2, "", n);
    int result = n == 0 ? 1 : n * factorial(n - 1, depth + 1);
    printf("%*s= %d\n", depth * 2, "", result);
    return result;
}

int main(void) {
    factorial(3, 0);
    return 0;
}
```

Вывод:

```text
factorial(3)
  factorial(2)
    factorial(1)
      factorial(0)
      = 1
    = 1
  = 2
= 6
```

Сначала вызовы «спускаются» до базового случая, затем результаты «поднимаются» обратно: каждый вызов дожидается ответа вложенного и только потом заканчивает свою работу. В самой глубокой точке в стеке одновременно лежат четыре кадра.

## Как рассуждать о рекурсии

Пытаться мысленно проследить все вызовы — путь к путанице. Рассуждайте как в доказательстве по индукции:

1. Базовый случай верен.
2. **Предположите**, что рекурсивный вызов для меньшей задачи возвращает правильный ответ.
3. Проверьте, что из этого ответа функция правильно строит ответ для текущей задачи.

Например, сумма цифр: сумма цифр числа `n` — это последняя цифра `n % 10` плюс сумма цифр числа без неё, `n / 10`. Базовый случай — число из одной цифры.

```c
#include <stdio.h>

static int digit_sum(long long n) {
    if (n < 10) {
        return (int)n;
    }
    return (int)(n % 10) + digit_sum(n / 10);
}

static void print_binary(unsigned n) {
    if (n >= 2) {
        print_binary(n / 2);       // сначала старшие разряды
    }
    putchar('0' + (int)(n % 2));   // затем младший
}

int main(void) {
    printf("%d\n", digit_sum(9876543210LL));
    print_binary(37);
    printf("\n");
    return 0;
}
```

Вывод:

```text
45
100101
```

`print_binary` показывает силу рекурсии: цифры числа получаются от младшей к старшей, а печатать их нужно наоборот. Рекурсивный вызов **до** печати решает это без массива: младшая цифра печатается после того, как напечатаны все старшие.

## Глубина рекурсии

Каждый вложенный вызов занимает место в стеке, а размер стека ограничен — обычно несколько мегабайт. Рекурсия глубиной в миллион вызовов его переполнит, и программа аварийно завершится (AddressSanitizer сообщает `stack-overflow`).

| Рекурсия            | Глубина    | Безопасна при n = 10⁶ |
| ------------------- | ---------- | --------------------- |
| `factorial(n - 1)`  | `n`        | нет                   |
| `digit_sum(n / 10)` | число цифр | да                    |
| деление пополам     | `log₂ n`   | да                    |

Рекурсия с уменьшением на единицу — по сути цикл, и её лучше так и писать. Рекурсия, которая делит задачу пополам, имеет глубину `log₂ n` — 20 для миллиона — и безопасна.

## Дерево вызовов и повторные вычисления

Числа Фибоначчи определены рекурсивно: `F(n) = F(n − 1) + F(n − 2)`. Прямая запись этой формулы делает **два** рекурсивных вызова, и они многократно пересчитывают одно и то же:

```c
#include <stdio.h>

static long long calls = 0;

static long long fib(int n) {
    calls++;
    return n < 2 ? n : fib(n - 1) + fib(n - 2);
}

static long long memo[91];

static long long fib_memo(int n) {
    if (n < 2) {
        return n;
    }
    if (memo[n] == 0) {
        memo[n] = fib_memo(n - 1) + fib_memo(n - 2);   // считаем один раз
    }
    return memo[n];
}

int main(void) {
    long long f30 = fib(30);         // сначала вычисляем, потом читаем calls
    printf("fib(30) = %lld, вызовов: %lld\n", f30, calls);
    printf("fib(90) = %lld\n", fib_memo(90));
    return 0;
}
```

Вывод:

```text
fib(30) = 832040, вызовов: 2692537
fib(90) = 2880067194370816120
```

Для `F(30)` — почти 2,7 миллиона вызовов: дерево вызовов ветвится надвое, и число вызовов растёт как `F(n)`, то есть экспоненциально. `F(90)` таким способом не дождаться. **Мемоизация** — запоминание уже вычисленных ответов в таблице — превращает экспоненту в `O(n)`: каждое `F(k)` вычисляется один раз.

## Разделяй и властвуй

Самая полезная форма рекурсии — **разделяй и властвуй**: разбить задачу на половины, решить каждую рекурсивно и объединить ответы. Например, сумма массива:

```c
#include <stdio.h>

static long long sum(const int *values, int lo, int hi) {   // полуинтервал [lo, hi)
    if (hi - lo == 0) {
        return 0;
    }
    if (hi - lo == 1) {
        return values[lo];
    }
    int mid = lo + (hi - lo) / 2;
    return sum(values, lo, mid) + sum(values, mid, hi);
}

int main(void) {
    int values[] = {3, 1, 4, 1, 5, 9, 2, 6};
    printf("%lld\n", sum(values, 0, 8));
    return 0;
}
```

Вывод:

```text
31
```

Для суммы это ничего не даёт — цикл проще. Но если объединение половин умнее простого сложения, получаются быстрые алгоритмы: сортировка слиянием сортирует половины рекурсивно и сливает их за `O(n)`, что даёт `O(n log n)`. Глубина такой рекурсии — `log₂ n`, а на каждом уровне вместе обрабатываются все `n` элементов.

<Concept title="Рекурсия">

Функция сводит задачу к меньшей задаче того же вида и вызывает для неё себя. Нужны базовый случай и шаг, который строго приближает к нему. Корректность доказывается индукцией: предположите, что вызов для меньшей задачи верен. Каждый вызов занимает кадр стека; глубина `n` опасна, глубина `log n` — нет. Повторные вычисления в дереве вызовов убирает мемоизация.

</Concept>

## Частые ошибки

<CommonMistake title="Базовый случай не покрывает все входы">

```c
long long factorial(int n) {
    if (n == 1) return 1;
    return n * factorial(n - 1);
}
```

`factorial(0)` вызовет `factorial(-1)`, затем `factorial(-2)` — и так до переполнения стека. Проверяйте базовый случай на самых маленьких допустимых входах: 0, пустой массив, пустая строка.

</CommonMistake>

<CommonMistake title="Шаг, который не уменьшает задачу">

`sum(values, lo, hi)` с делением `mid = lo + (hi - lo) / 2` и базой только `hi - lo == 0` зациклится на отрезке длины 1: `mid == lo`, и вызов `sum(values, mid, hi)` получает тот же отрезок. Каждый рекурсивный вызов должен получать **строго меньшую** задачу.

</CommonMistake>

<CommonMistake title="Экспоненциальная рекурсия">

Два рекурсивных вызова на задачи размера `n − 1` и `n − 2` без мемоизации — `O(φⁿ)` вызовов. Если в дереве вызовов повторяются одинаковые подзадачи, запоминайте их ответы.

</CommonMistake>

## Практика

1. **Двоичная запись** — рекурсивная печать разрядов.
2. **Ханойские башни** — классическая рекурсия с `2ⁿ − 1` ходами.
3. **Найди ошибку: рекурсивная сумма** — базовый случай без пустого массива.
4. **Подмножества с суммой** — перебор с возвратом.

## Итоги

- Рекурсивная функция вызывает себя для меньшей задачи; нужны базовый случай и уменьшающий шаг.
- Корректность доказывается индукцией: считайте, что меньший вызов работает правильно.
- Каждый вызов — отдельный кадр стека; глубина рекурсии ограничена размером стека.
- Рекурсия с шагом `n − 1` — замаскированный цикл; деление пополам даёт безопасную глубину `log n`.
- Повторные подзадачи убирает мемоизация.
- «Разделяй и властвуй»: разбить, решить части рекурсивно, объединить — основа быстрых сортировок.
