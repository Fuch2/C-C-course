## Откуда берётся квадрат

Алгоритм работает за **O(n²)**, если для каждого из `n` элементов он делает работу, пропорциональную `n`. Обычно это два вложенных цикла по данным — например, перебор **всех пар** элементов. Пар `i < j` ровно `n(n − 1) / 2`: для 10 элементов — 45, для тысячи — почти полмиллиона, для миллиона — полтриллиона.

Квадратичный алгоритм — не приговор. При `n` до нескольких тысяч он работает мгновенно, его легко написать и проверить. Проблема в росте: удвоение входа увеличивает работу **в четыре раза**, и при `n = 10⁵` она уже занимает секунды, а при `10⁶` — часы.

## Пример: все пары

Сколько в массиве пар, стоящих «не по порядку» — когда большее число стоит раньше меньшего? Такие пары называют **инверсиями**. Их число показывает, насколько массив далёк от отсортированного: у отсортированного 0 инверсий, у отсортированного в обратном порядке — `n(n − 1) / 2`.

```c
#include <stdio.h>

int main(void) {
    int values[] = {3, 1, 4, 1, 5, 9, 2, 6};
    int n = 8;
    int inversions = 0;
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (values[i] > values[j]) {
                inversions++;
            }
        }
    }
    printf("инверсий: %d\n", inversions);
    return 0;
}
```

Вывод:

```text
инверсий: 8
```

Решение очевидно верное — оно буквально перебирает определение. Это хорошая отправная точка: сначала напишите простое квадратичное решение, проверьте на нём быстрое и только потом отказывайтесь от простого. В уроке о сортировке слиянием мы посчитаем инверсии за `O(n log n)`.

## От квадрата к линии: запомнить лучшее

Задача: известны цены акции по дням. Купить можно один раз, продать — один раз и позже покупки. Какую наибольшую прибыль можно получить?

Прямое решение перебирает все пары «день покупки `i` < день продажи `j`» — `O(n²)`. Но для фиксированного дня продажи лучший день покупки — тот, где цена **минимальна среди предыдущих дней**. Этот минимум можно поддерживать на ходу:

```c
#include <stdio.h>

int main(void) {
    int prices[] = {7, 1, 5, 3, 6, 4};
    int n = 6;

    int slow = 0;                                  // O(n²): все пары
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            if (prices[j] - prices[i] > slow) {
                slow = prices[j] - prices[i];
            }
        }
    }

    int fast = 0, min_price = prices[0];           // O(n): один проход
    for (int j = 1; j < n; j++) {
        if (prices[j] - min_price > fast) {
            fast = prices[j] - min_price;
        }
        if (prices[j] < min_price) {
            min_price = prices[j];
        }
    }
    printf("%d %d\n", slow, fast);
    return 0;
}
```

Вывод:

```text
5 5
```

Инвариант быстрого решения: перед днём `j` переменная `min_price` — наименьшая цена среди дней `0…j − 1`, а `fast` — лучшая прибыль среди сделок с продажей до дня `j`. Внутренний цикл исчез, потому что ответ на его вопрос («какая покупка лучше всего для продажи в день `j`?») уже известен.

## От квадрата к линии: таблица

В уроке о подсчёте операций пары с суммой `target` искались перебором. Если значения небольшие, есть способ быстрее: идём по массиву и для каждого элемента `x` спрашиваем, **сколько раньше встретилось** число `target − x`. Счётчики встреч хранятся в массиве по значениям — та же прямая адресация, что в уроке об `O(1)`:

```c
#include <stdio.h>

int main(void) {
    int values[] = {1, 9, 3, 7, 5, 5, 4};
    int n = 7, target = 10;
    int count[11] = {0};                // значения от 0 до 10
    int pairs = 0;
    for (int i = 0; i < n; i++) {
        int need = target - values[i];
        if (need >= 0 && need <= 10) {
            pairs += count[need];       // пары с уже просмотренными элементами
        }
        count[values[i]]++;
    }
    printf("пар: %d\n", pairs);
    return 0;
}
```

Вывод:

```text
пар: 3
```

Пары: `1 + 9`, `3 + 7`, `5 + 5`. Элемент сначала ищет себе пару среди **предыдущих**, и только потом записывается в таблицу — поэтому он не сложится сам с собой, а каждая пара посчитается один раз.

## Скрытый квадрат: удаление со сдвигом

Удалить из массива все нули, сохранив порядок остальных. Прямое решение: найти ноль и сдвинуть влево всё, что правее. Каждый сдвиг — `O(n)`, а нулей может быть `O(n)` — итого `O(n²)`.

Быстрое решение — **два индекса**: `read` идёт по всем элементам, `write` показывает, куда записать следующий сохраняемый:

```c
#include <stdio.h>

int main(void) {
    int values[] = {0, 3, 0, 0, 7, 1, 0, 5};
    int n = 8;
    int write = 0;
    for (int read = 0; read < n; read++) {
        if (values[read] != 0) {
            values[write] = values[read];
            write++;
        }
    }
    n = write;
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
3 7 1 5
```

Каждый элемент читается один раз и записывается не больше одного раза — `O(n)`, без дополнительной памяти. `write` никогда не обгоняет `read`, поэтому запись не портит ещё не прочитанные элементы.

## Сколько это — n²

| `n`   | `n²` | примерно (10⁸ операций в секунду) |
| ----- | ---- | --------------------------------- |
| 1 000 | 10⁶  | 0,01 с                            |
| 10⁴   | 10⁸  | 1 с                               |
| 10⁵   | 10¹⁰ | 100 с                             |
| 10⁶   | 10¹² | 3 часа                            |

Три вложенных цикла — `O(n³)` — допустимы только до нескольких сотен элементов.

<Concept title="Где прячется лишний цикл">

Квадратичный алгоритм часто отвечает на один и тот же вопрос много раз: «какой минимум был раньше?», «встречалось ли такое число?», «куда сдвинуть элемент?». Если ответ можно **запомнить** — в переменной, таблице или втором индексе, — внутренний цикл исчезает. Начинайте с простого решения за `O(n²)`, а затем ищите, что в нём повторяется.

</Concept>

## Частые ошибки

<CommonMistake title="Пропуск элемента после удаления">

```c
for (int i = 0; i < n; i++) {
    if (values[i] == 0) {
        for (int k = i; k < n - 1; k++) values[k] = values[k + 1];
        n--;
    }
}
```

После сдвига на место `i` встал следующий элемент, но цикл делает `i++` и его не проверяет. Два нуля подряд — и второй остаётся. Используйте схему с `read` и `write`.

</CommonMistake>

<CommonMistake title="Пара из одного элемента">

Если сначала записать элемент в таблицу, а потом искать `target − x`, то при `x = target / 2` элемент найдёт сам себя. Порядок «сначала спросить, потом записать» гарантирует, что пары составляются только с предыдущими элементами.

</CommonMistake>

<CommonMistake title="Квадрат там, где n большое">

Если в условии `n ≤ 2·10⁵`, решение за `O(n²)` не уложится в лимит, сколько бы его ни оптимизировали. Оценивайте сложность до того, как писать код.

</CommonMistake>

## Практика

1. **Инверсии** — перебор всех пар.
2. **Лучшая сделка** — от `O(n²)` к `O(n)`.
3. **Найди ошибку: удаление значений** — пропуск элемента после сдвига.
4. **Пары с суммой за O(n)** — таблица встреч.

## Итоги

- `O(n²)` — работа, пропорциональная `n`, для каждого из `n` элементов; обычно это перебор пар.
- Квадратичные решения хороши до `n` порядка 10⁴ и как эталон для проверки быстрых.
- Внутренний цикл исчезает, если его ответ можно запомнить: минимум на префиксе, таблица встреч, второй индекс.
- Удаление со сдвигом в цикле — скрытый `O(n²)`; схема `read`/`write` удаляет за `O(n)`.
- При поиске пар через таблицу сначала ищите пару, потом записывайте элемент.
