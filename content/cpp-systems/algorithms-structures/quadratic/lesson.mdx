## Теория и инвариант

Перебор всех неупорядоченных пар использует индексы i&lt;j. Число пар равно n(n−1)/2: первый элемент образует n−1 пар, следующий n−2 и так далее. Половина в формуле не меняет квадратичный порядок. При удвоении большого входа работа примерно учетверяется.

Квадратичный алгоритм не всегда плох: для десятка точек он прост, легко проверяется и может победить сложную структуру с затратной подготовкой. Однако лимит n должен быть явным. Если задача допускает сортировку, хеширование или скользящее окно, можно уменьшить число проверок, заплатив памятью, подготовкой или более сложным доказательством.

## Пошаговый разбор

Для четырёх элементов пары: (0,1),(0,2),(0,3),(1,2),(1,3),(2,3) — всего 6.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>


int main(void) {
int pairs=0;for(int i=0;i<4;++i)for(int j=i+1;j<4;++j)++pairs;printf("%d\n",pairs);
return 0;
}
```

Ожидаемый вывод:

```text
6
```

## Почему реализация корректна

Для четырёх измерений нужны пары индексов (0,1), (0,2), (0,3), (1,2), (1,3), (2,3). Начало внутреннего цикла с i+1 исключает сравнение элемента с собой и повтор пары в обратном порядке. Число сравнений равно 3+2+1=6, в общем случае n(n−1)/2.

Деление на два не делает рост линейным. При n=1000 число пар равно 499500; при n=2000 — 1999000. На малом наборе это полезный простой эталон для проверки более сложного решения. Если вместо счётчика сохранять все подходящие пары, дополнительная память в худшем случае тоже станет квадратичной.

## Сложность и память

| Что оцениваем | Гарантия                                    |
| ------------- | ------------------------------------------- |
| Время         | Θ(n²) проверок пар.                         |
| Память        | O(1) сверх входа, если пары не сохраняются. |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».
