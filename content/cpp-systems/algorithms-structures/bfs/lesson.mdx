## Кратчайший путь по числу шагов

Сколько пересадок нужно, чтобы доехать от одной станции метро до другой? Через сколько рукопожатий вы знакомы с незнакомцем? За сколько ходов конь дойдёт до клетки? Во всех этих задачах граф **невзвешенный** — каждое ребро стоит одинаково, — и нужен путь с наименьшим числом рёбер.

**Поиск в ширину** (breadth-first search, BFS) решает эту задачу. Он обходит граф **слоями**: сначала стартовая вершина (расстояние 0), затем все её соседи (расстояние 1), затем их ещё не посещённые соседи (расстояние 2) — как круги по воде от брошенного камня. Вы уже видели этот алгоритм в уроке о бинарных деревьях — обход по уровням. В графе добавляется одна забота: вершина может быть достижима несколькими путями, и посещать её нужно один раз.

## Алгоритм

1. Расстояние до старта — 0, до остальных — «неизвестно» (`-1`). Старт кладём в очередь.
2. Пока очередь не пуста: достаём вершину `u` и перебираем её соседей. Каждый сосед `v` с неизвестным расстоянием получает `dist[v] = dist[u] + 1` и встаёт в очередь.

Отметка «расстояние известно» ставится **в момент добавления** в очередь, а не извлечения: тогда вершина попадает в очередь ровно один раз.

```c
#include <stdio.h>

enum { V = 7, E = 7 };

int main(void) {
    int edges[E][2] = {{1, 2}, {1, 3}, {2, 4}, {3, 4}, {4, 5}, {5, 6}, {3, 6}};
    // сжатые списки смежности, как в прошлом уроке
    int start[V + 2] = {0}, fill[V + 1], adj[2 * E];
    for (int i = 0; i < E; i++) {
        start[edges[i][0] + 1]++;
        start[edges[i][1] + 1]++;
    }
    for (int v = 1; v <= V + 1; v++) {
        start[v] += start[v - 1];
    }
    for (int v = 1; v <= V; v++) {
        fill[v] = start[v];
    }
    for (int i = 0; i < E; i++) {
        adj[fill[edges[i][0]]++] = edges[i][1];
        adj[fill[edges[i][1]]++] = edges[i][0];
    }

    int dist[V + 1], queue[V], head = 0, tail = 0;
    for (int v = 1; v <= V; v++) {
        dist[v] = -1;
    }
    dist[1] = 0;
    queue[tail++] = 1;
    while (head < tail) {
        int u = queue[head++];
        for (int k = start[u]; k < start[u + 1]; k++) {
            int v = adj[k];
            if (dist[v] == -1) {                  // ещё не открыта
                dist[v] = dist[u] + 1;
                queue[tail++] = v;
            }
        }
    }
    for (int v = 1; v <= V; v++) {
        printf("до %d: %d\n", v, dist[v]);
    }
    return 0;
}
```

Вывод:

```text
до 1: 0
до 2: 1
до 3: 1
до 4: 2
до 5: 3
до 6: 2
до 7: -1
```

Вершина 7 не связана ни с чем — её расстояние осталось `-1`. До вершины 5 два пути длины 3 (`1 → 2 → 4 → 5` и `1 → 3 → 6 → 5`), и BFS нашёл расстояние, не перебирая пути.

## Почему расстояния кратчайшие

Инвариант очереди: в каждый момент в ней лежат вершины с расстоянием `d`, за которыми — вершины с расстоянием `d + 1`, и больше ничего. Вершины извлекаются в порядке неубывания расстояния. Поэтому, когда вершина `v` открывается впервые из вершины `u`, у `u` наименьшее расстояние среди всех соседей `v`, которые ещё будут извлечены, — более короткого пути к `v` не существует.

Каждая вершина добавляется в очередь один раз, а каждое ребро просматривается дважды (с обоих концов) — время **`O(V + E)`**, память — `O(V)` под очередь и расстояния.

## Восстановление пути

Чтобы узнать не только длину, но и сам путь, запоминают, **откуда** открыта каждая вершина: `parent[v] = u`. Путь восстанавливается с конца — от цели по родителям к старту, — и затем разворачивается.

```c
#include <stdio.h>

int main(void) {
    // граф-сетка 3 × 3: вершина r * 3 + c, ходы по четырём направлениям
    const char *grid[3] = {"..#", ".#.", "..."};
    int dist[9], parent[9], queue[9], head = 0, tail = 0;
    for (int i = 0; i < 9; i++) {
        dist[i] = -1;
    }
    dist[0] = 0;
    parent[0] = -1;
    queue[tail++] = 0;
    int dr[] = {-1, 1, 0, 0}, dc[] = {0, 0, -1, 1};
    while (head < tail) {
        int u = queue[head++];
        int r = u / 3, c = u % 3;
        for (int d = 0; d < 4; d++) {
            int nr = r + dr[d], nc = c + dc[d];
            if (nr < 0 || nr >= 3 || nc < 0 || nc >= 3 || grid[nr][nc] == '#') {
                continue;
            }
            int v = nr * 3 + nc;
            if (dist[v] == -1) {
                dist[v] = dist[u] + 1;
                parent[v] = u;
                queue[tail++] = v;
            }
        }
    }
    int target = 2 * 3 + 2, path[9], length = 0;   // правый нижний угол
    for (int v = target; v != -1; v = parent[v]) {
        path[length++] = v;
    }
    printf("шагов: %d\n", dist[target]);
    for (int i = length - 1; i >= 0; i--) {
        printf("(%d,%d) ", path[i] / 3, path[i] % 3);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
шагов: 4
(0,0) (1,0) (2,0) (2,1) (2,2)
```

Этот пример показывает ещё одну важную вещь: граф не обязан храниться явно. Клетки лабиринта — вершины, соседние свободные клетки — рёбра, и соседей можно вычислять на ходу. Так BFS ищет пути в играх, в головоломках и в роботах-пылесосах.

## Компоненты связности

Если граф несвязный, один запуск BFS обойдёт только **компоненту** стартовой вершины. Чтобы найти все компоненты, запускают BFS из каждой ещё не посещённой вершины — каждый запуск открывает новую компоненту. Суммарно это всё равно `O(V + E)`: каждая вершина и каждое ребро обрабатываются один раз.

## Несколько стартов

Если источников несколько — например, расстояние до ближайшей аптеки от каждого дома, — не нужно запускать BFS из каждой аптеки. Достаточно положить **все** источники в очередь с расстоянием 0 и запустить один BFS. Это **многоисточниковый** поиск в ширину, тоже `O(V + E)`.

<Concept title="Поиск в ширину">

BFS обходит граф слоями с помощью очереди и находит кратчайшие по числу рёбер расстояния от старта до всех достижимых вершин за `O(V + E)`. Вершина отмечается в момент добавления в очередь, поэтому попадает в неё один раз. Массив родителей восстанавливает путь. Повторные запуски из непосещённых вершин находят компоненты связности, а общий запуск из нескольких источников — расстояния до ближайшего из них.

</Concept>

## Частые ошибки

<CommonMistake title="Отметка при извлечении">

Если отмечать вершину посещённой только при извлечении из очереди, она успеет попасть в очередь несколько раз — от каждого соседа, обработанного раньше. Очередь разрастается до `O(E)` элементов и может выйти за выделенный массив на `V` ячеек.

</CommonMistake>

<CommonMistake title="BFS для взвешенного графа">

Если у рёбер разная длина, путь с наименьшим числом рёбер не обязательно самый короткий. Для взвешенных графов нужен алгоритм Дейкстры — тот же BFS, только с очередью с приоритетом вместо обычной.

</CommonMistake>

<CommonMistake title="Выход за край сетки">

При поиске в лабиринте проверяйте границы **до** обращения к клетке: `nr >= 0 && nr < rows && …` — и только потом `grid[nr][nc]`.

</CommonMistake>

## Практика

Граф задаётся так: первая строка — `V` и `E`, дальше `E` строк `u v` (вершины с 1, граф неориентированный).

1. **Расстояния** — BFS от вершины 1.
2. **Лабиринт** — BFS по клеткам.
3. **Найди ошибку: переполненная очередь** — отметка при извлечении.
4. **Наименьший кратчайший путь** — BFS от цели и жадный выбор.

## Итоги

- BFS обходит граф слоями с очередью и находит кратчайшие расстояния в невзвешенном графе.
- Вершину отмечают при добавлении в очередь — тогда она обрабатывается один раз, и время `O(V + E)`.
- Массив родителей восстанавливает кратчайший путь.
- Граф можно не хранить: соседей клетки лабиринта вычисляют на ходу.
- Повторные запуски находят компоненты связности, общий запуск — расстояния до ближайшего из нескольких источников.
- Для взвешенных графов BFS не подходит — нужен алгоритм Дейкстры.
