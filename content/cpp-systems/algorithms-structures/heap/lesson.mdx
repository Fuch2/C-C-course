## Очередь с приоритетом

Обычная очередь выдаёт элементы в порядке поступления. Но в больнице первым принимают не того, кто раньше пришёл, а того, кому хуже. Планировщик операционной системы запускает самый важный процесс, навигатор раскрывает ближайшую из ещё не обработанных точек. Нужна **очередь с приоритетом** (priority queue): из неё всегда извлекается элемент с **наименьшим** (или наибольшим) ключом.

| Операция  | Что делает                        |
| --------- | --------------------------------- |
| `push(x)` | добавить элемент                  |
| `top()`   | посмотреть на минимальный элемент |
| `pop()`   | извлечь минимальный элемент       |

Можно держать элементы в отсортированном массиве — тогда `pop` дешёвый, а `push` стоит `O(n)`. Можно в неотсортированном — тогда наоборот. **Двоичная куча** (binary heap) даёт `O(log n)` на обе операции и `O(1)` на `top`.

## Двоичная куча

Куча — полное бинарное дерево (все уровни заполнены, последний — слева направо) со **свойством кучи**: ключ каждого узла не больше ключей его детей. Такая куча называется **min-кучей**: наименьший элемент всегда в корне. В max-куче всё наоборот.

Полное дерево хранится в массиве без указателей (вы видели это в уроке о бинарных деревьях): дети узла `i` — в ячейках `2i + 1` и `2i + 2`, родитель — в `(i − 1) / 2`.

```text
массив: [1, 3, 2, 7, 4, 5, 9]

            1
          /   \
         3     2
        / \   / \
       7   4 5   9
```

Свойство кучи слабее упорядоченности: `3` и `2` — братья, и между ними порядок не важен; `7` больше `5`, но стоит левее. Требуется только одно — каждый родитель не больше своих детей. Этого хватает, чтобы минимум был в корне, и это свойство дёшево восстанавливать.

## Вставка: просеивание вверх

Новый элемент кладут в конец массива — на первое свободное место последнего уровня; дерево остаётся полным. Свойство кучи может нарушиться только между новым элементом и его родителем. Если родитель больше — меняем их местами и повторяем для нового положения. Это **просеивание вверх** (sift up): элемент «всплывает», пока не встретит родителя не больше себя или не станет корнем.

## Извлечение: просеивание вниз

Минимум — в корне. Чтобы его убрать, на место корня ставят **последний** элемент массива и уменьшают размер. Новый корень, скорее всего, слишком велик. Сравниваем его с **меньшим** из детей; если ребёнок меньше — меняем местами и продолжаем ниже. Это **просеивание вниз** (sift down). Выбирать нужно именно меньшего ребёнка: тогда он станет родителем другого ребёнка и будет не больше его.

```c
#include <stdio.h>

enum { CAPACITY = 100 };

typedef struct {
    int data[CAPACITY];
    int size;
} Heap;

static void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

static bool heap_push(Heap *h, int x) {
    if (h->size == CAPACITY) {
        return false;
    }
    int i = h->size++;
    h->data[i] = x;
    while (i > 0 && h->data[(i - 1) / 2] > h->data[i]) {      // родитель больше — всплываем
        swap(&h->data[(i - 1) / 2], &h->data[i]);
        i = (i - 1) / 2;
    }
    return true;
}

static bool heap_pop(Heap *h, int *out) {
    if (h->size == 0) {
        return false;
    }
    *out = h->data[0];
    h->data[0] = h->data[--h->size];                           // последний — в корень
    int i = 0;
    for (;;) {
        int smallest = i, l = 2 * i + 1, r = 2 * i + 2;
        if (l < h->size && h->data[l] < h->data[smallest]) smallest = l;
        if (r < h->size && h->data[r] < h->data[smallest]) smallest = r;
        if (smallest == i) {
            break;                                             // оба ребёнка не меньше
        }
        swap(&h->data[i], &h->data[smallest]);
        i = smallest;
    }
    return true;
}

int main(void) {
    Heap h = {.size = 0};
    int input[] = {5, 9, 2, 7, 1, 8, 3};
    for (int i = 0; i < 7; i++) {
        heap_push(&h, input[i]);
    }
    printf("массив кучи: ");
    for (int i = 0; i < h.size; i++) {
        printf("%d ", h.data[i]);
    }
    printf("\nпо приоритету: ");
    int x;
    while (heap_pop(&h, &x)) {
        printf("%d ", x);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
массив кучи: 1 2 3 9 7 8 5
по приоритету: 1 2 3 5 7 8 9
```

Массив кучи не отсортирован, но извлечения выдают элементы по возрастанию. Каждая операция проходит один путь от листа до корня или обратно — не длиннее высоты полного дерева, `⌊log₂ n⌋`. Для миллиона элементов — 20 обменов.

## Построение кучи за O(n)

Если все элементы известны заранее, кучу можно построить быстрее, чем `n` вставками по `O(log n)`. Просеиваем вниз все узлы, у которых есть дети, — от последнего такого узла `n / 2 − 1` к корню. Листья (половина узлов) уже являются кучами из одного элемента. Большинство узлов находятся внизу и просеиваются на одну-две ступени; суммарная работа оказывается `O(n)`.

## Сортировка кучей

Куча даёт ещё одну сортировку за `O(n log n)`. Построим **max-кучу** из массива за `O(n)`. Наибольший элемент в корне — обменяем его с последним элементом, уменьшим размер кучи и просеем новый корень вниз. Теперь наибольший стоит в конце массива, на своём месте. Повторим для оставшейся части.

```c
#include <stdio.h>

static void sift_down(int *a, int n, int i) {          // max-куча из a[0…n − 1]
    for (;;) {
        int largest = i, l = 2 * i + 1, r = 2 * i + 2;
        if (l < n && a[l] > a[largest]) largest = l;
        if (r < n && a[r] > a[largest]) largest = r;
        if (largest == i) {
            return;
        }
        int t = a[i];
        a[i] = a[largest];
        a[largest] = t;
        i = largest;
    }
}

int main(void) {
    int a[] = {4, 10, 3, 5, 1, 8, 2};
    int n = 7;
    for (int i = n / 2 - 1; i >= 0; i--) {             // построение кучи
        sift_down(a, n, i);
    }
    for (int end = n - 1; end > 0; end--) {
        int t = a[0];                                  // максимум — в конец
        a[0] = a[end];
        a[end] = t;
        sift_down(a, end, 0);
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1 2 3 4 5 8 10
```

Сортировка кучей работает **на месте** и гарантирует `O(n log n)` на любом входе — у неё нет квадратичного худшего случая, как у быстрой сортировки. Поэтому `std::sort` в C++ переключается на неё, если рекурсия быстрой сортировки стала слишком глубокой. Сортировка кучей неустойчива, и на практике обычно медленнее быстрой: она прыгает по массиву и плохо использует кэш.

## Где нужны кучи

- **k наименьших из потока.** Max-куча размера `k` хранит `k` лучших кандидатов; новый элемент вытесняет корень, если он меньше. `O(n log k)` времени и `O(k)` памяти.
- **Слияние `k` отсортированных списков.** В min-куче лежат текущие головы списков; извлекаем минимум и кладём следующий элемент того же списка.
- **Кратчайшие пути** (алгоритм Дейкстры) и планирование событий по времени.
- **Медиана потока** — две кучи: max-куча для меньшей половины и min-куча для большей.

В C++ куча — `std::priority_queue`; по умолчанию это **max**-куча:

```cpp
#include <functional>
#include <iostream>
#include <queue>
#include <vector>

int main() {
    std::priority_queue<int> max_heap;
    std::priority_queue<int, std::vector<int>, std::greater<int>> min_heap;
    for (int x : {5, 9, 2, 7, 1}) {
        max_heap.push(x);
        min_heap.push(x);
    }
    std::cout << max_heap.top() << ' ' << min_heap.top() << '\n';
    return 0;
}
```

Вывод:

```text
9 1
```

<Concept title="Двоичная куча">

Полное бинарное дерево в массиве, где каждый родитель не больше детей. Минимум — в корне, `O(1)`. Вставка просеивает новый элемент вверх, извлечение ставит последний элемент в корень и просеивает вниз через меньшего ребёнка — `O(log n)`. Кучу из готового массива строят за `O(n)`. На куче построены очереди с приоритетом, сортировка кучей и поиск `k` лучших элементов.

</Concept>

## Частые ошибки

<CommonMistake title="Просеивание вниз через одного ребёнка">

Если сравнивать узел только с левым ребёнком или менять его с первым же меньшим ребёнком, а не с наименьшим, свойство кучи нарушится: больший из детей станет родителем меньшего, и следующий `pop` вернёт не минимум.

</CommonMistake>

<CommonMistake title="Проверка существования детей">

Правый ребёнок `2i + 2` существует, только если `2i + 2 < size`. Без проверки просеивание читает ячейки за концом кучи — устаревшие значения или память за массивом.

</CommonMistake>

<CommonMistake title="Ожидать отсортированный массив">

Куча упорядочена только вдоль путей от корня к листьям. Печать массива кучи по порядку не выдаёт отсортированную последовательность — для этого нужно извлекать элементы.

</CommonMistake>

## Практика

1. **Очередь с приоритетом** — min-куча на массиве.
2. **Сортировка кучей** — max-куча на месте.
3. **Найди ошибку: просеивание вниз** — неверный выбор ребёнка.
4. **Медиана потока на двух кучах** — `O(log n)` на число.

## Итоги

- Очередь с приоритетом выдаёт наименьший (или наибольший) элемент; двоичная куча реализует её за `O(log n)` на операцию.
- Свойство кучи: родитель не больше детей; полное дерево хранится в массиве, дети узла `i` — `2i + 1` и `2i + 2`.
- Вставка — просеивание вверх, извлечение — последний элемент в корень и просеивание вниз через меньшего ребёнка.
- Построение кучи из массива — `O(n)`; сортировка кучей — `O(n log n)` на месте, неустойчива.
- Кучи применяют для `k` лучших элементов, слияния списков, кратчайших путей и медианы потока.
