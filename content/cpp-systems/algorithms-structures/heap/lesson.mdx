## Цели обучения

- Объяснить инвариант: Наверху всегда лучший кандидат, но полный порядок остальных нам не нужен.
- Обосновать время: Минимум O(1), вставка/извлечение O(log n).
- Оценить память и компромиссы: Дешёвый лучший элемент, но поиск произвольного ключа O(n); порядок равных приоритетов не гарантирован.

## Теория и инвариант

Бинарная min-heap — почти полное дерево, где родитель не больше детей. В массиве дети i находятся на 2i+1 и 2i+2, родитель при i>0 — (i−1)/2. Порядок между соседними ветвями не определён: массив кучи не отсортирован.

При вставке значение поднимается, пока не восстановлен порядок с родителем. При извлечении минимум заменяется последним элементом, который опускается по меньшему ребёнку. Проверяйте наличие второго ребёнка до чтения. Построение кучи снизу вверх за O(n) отличается от n последовательных вставок с верхней оценкой O(n log n). В данной задаче используются именно вставки, а не линейный heapify.

## Пошаговый разбор

После вставки 5,2,7 корень 2. Извлечение 2 ставит 7 наверх, затем опускает под 5: следующий минимум 5.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct { int data[128]; int size; } Heap;
static int push(Heap *h,int value){
    if(h->size==128)return 0;
    int i=h->size++;
    while(i>0){int parent=(i-1)/2;if(h->data[parent]<=value)break;h->data[i]=h->data[parent];i=parent;}
    h->data[i]=value;return 1;
}
static int pop(Heap *h,int *out){
    if(!h->size)return 0;*out=h->data[0];int last=h->data[--h->size];
    if(!h->size)return 1;
    int i=0;
    while(2*i+1<h->size){
        int child=2*i+1;
        if(child+1<h->size && h->data[child+1]<h->data[child])++child;
        if(last<=h->data[child])break;
        h->data[i]=h->data[child];i=child;
    }
    h->data[i]=last;return 1;
}
int main(void) {
Heap h={0};push(&h,5);push(&h,2);push(&h,7);int x;while(pop(&h,&x))printf("%d%s",x,h.size?" ":"\n");
return 0;
}
```

Ожидаемый вывод:

```text
2 5 7
```

## Почему реализация корректна

Из массива кучи [2,5,7] извлечение сохраняет 2 и переносит последний элемент 7 в корень. Сравнение с меньшим существующим ребёнком 5 даёт [5,7]. Если детей два, выбор большего нарушил бы инвариант относительно меньшего. Если ребёнок один, чтение правого индекса недопустимо.

При вставке достаточно чинить путь от нового листа к корню: все остальные связи остались прежними. При извлечении — путь от корня вниз. Длина пути ограничена высотой почти полного дерева, то есть O(log n). Плотное хранение устраняет отдельные аллокации узлов, но последовательные извлечения не равны простому чтению отсортированного массива.

## Cache locality и компромиссы

Нет указателей и отдельных аллокаций, но путь к листу перескакивает между индексами.

Дешёвый лучший элемент, но поиск произвольного ключа O(n); порядок равных приоритетов не гарантирован.

Практическое применение: Планировщик ближайших событий и объединение нескольких отсортированных потоков.

## Связь со STL C++

std::priority_queue по умолчанию выдаёт максимум. Для минимума нужен std::greater; top читает, pop удаляет.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <functional>
int main(){
std::priority_queue<int,std::vector<int>,std::greater<int>> q;q.push(5);q.push(2);q.push(7);std::cout<<q.top()<<"\n";
return 0;
}
```

Вывод:

```text
2
```
