## Цели обучения

- Объяснить инвариант: Круговая дорожка с ограниченным числом мест; логический порядок не совпадает с порядком индексов.
- Обосновать время: O(1) без выделений на каждую операцию.
- Оценить память и компромиссы: Предсказуемая память против необходимости явно обрабатывать полный буфер.

## Теория и инвариант

Кольцевой буфер переиспользует фиксированный массив. Индекс головы двигается по модулю capacity, а позиция добавления вычисляется как (head+size)%capacity. Отдельный size различает пустой и полный буфер, даже если физические позиции головы и хвоста совпадают. Вместимость должна быть положительной.

Заранее выберите политику переполнения: отказ, перезапись старейшего или блокировка. В задаче — отказ без изменения данных. Маска index &amp; (capacity−1) заменяет modulo только для степени двойки. Данная реализация однопоточная; два индекса без атомиков не создают безопасную очередь между потоками. Для producer/consumer нужны отдельные гарантии порядка памяти.

<Concept title="Ментальная модель">

Круговая дорожка с ограниченным числом мест; логический порядок не совпадает с порядком индексов.

</Concept>

## Пошаговый разбор

При capacity=3 после P 1,P 2,P 3,O,P 4 массив содержит [4,2,3], но очередь читается 2,3,4.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct { int data[32]; size_t head,size,capacity; } Ring;
static int push(Ring *r,int value){
    if(r->size==r->capacity)return 0;
    r->data[(r->head+r->size)%r->capacity]=value;++r->size;return 1;
}
static int pop(Ring *r,int *out){
    if(!r->size)return 0;
    *out=r->data[r->head];r->head=(r->head+1)%r->capacity;--r->size;return 1;
}
int main(void) {
Ring r={.capacity=3};push(&r,1);push(&r,2);push(&r,3);int x;pop(&r,&x);push(&r,4);while(pop(&r,&x))printf("%d%s",x,r.size?" ":"\n");
return 0;
}
```

Ожидаемый вывод:

```text
2 3 4
```

## Почему реализация корректна

При capacity=3, head=0, size=0 вставки A,B,C занимают индексы 0,1,2. После извлечения A head=1, size=2. Новое D записывается в (head+size)%capacity=0. Физический массив содержит D,B,C, логическая очередь — B,C,D. Поэтому печать массива слева направо не равна обходу очереди.

Хранение size позволяет отличать пустоту от заполнения без потери одной ячейки: одинаковые индексы головы и следующей вставки возможны в обоих состояниях. Полный буфер в нашей задаче отказывает во вставке, а не перезаписывает старые данные. Capacity должна быть положительной до операции %. Несколько потоков потребовали бы отдельного протокола синхронизации.

## Сложность и память

| Что оцениваем | Гарантия                               |
| ------------- | -------------------------------------- |
| Время         | O(1) без выделений на каждую операцию. |
| Память        | O(capacity), расход заранее ограничен. |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Практическое задание

Ввод capacity (1…32), q (0…128), затем команды P x и O. Успешное добавление молчит, отказ в полном буфере выводит ПОЛНО и сохраняет прежние данные. O выводит старейшее значение или ПУСТО. x — int −1000…1000. Не используйте аллокации на операцию.
