## Очередь, которая не уползает

В прошлом уроке очередь на массиве с индексами `head` и `tail` «ползла» вправо: удалённые элементы освобождали место слева, но им никто не пользовался. **Кольцевой буфер** (ring buffer, circular buffer) решает это просто: когда индекс доходит до конца массива, он **заворачивается** в начало. Массив мысленно замкнут в кольцо.

```text
ёмкость 6, в буфере 4 элемента, начало — ячейка 4:

индекс:  0   1   2   3   4   5
data:   [c] [d] [ ] [ ] [a] [b]
                         ↑ head
порядок: a b c d
```

Следующий за ячейкой 5 — ячейка 0. Позиция `i`-го элемента очереди — `(head + i) % capacity`.

## Реализация со счётчиком

Храним массив, индекс начала `head` и число элементов `size`. Конец очереди — `(head + size) % capacity`.

```c
#include <stdio.h>

enum { CAPACITY = 4 };

typedef struct {
    int data[CAPACITY];
    int head;
    int size;
} Ring;

static bool push(Ring *r, int x) {
    if (r->size == CAPACITY) {
        return false;                                   // полон
    }
    r->data[(r->head + r->size) % CAPACITY] = x;
    r->size++;
    return true;
}

static bool pop(Ring *r, int *out) {
    if (r->size == 0) {
        return false;                                   // пуст
    }
    *out = r->data[r->head];
    r->head = (r->head + 1) % CAPACITY;
    r->size--;
    return true;
}

int main(void) {
    Ring r = {.head = 0, .size = 0};
    int x;
    for (int i = 1; i <= 5; i++) {
        printf("push %d: %s\n", i, push(&r, i) ? "ok" : "полон");
    }
    pop(&r, &x);
    printf("pop: %d\n", x);
    pop(&r, &x);
    printf("pop: %d\n", x);
    push(&r, 6);
    push(&r, 7);                                        // 6 и 7 легли в ячейки 0 и 1
    while (pop(&r, &x)) {
        printf("%d ", x);
    }
    printf("\nhead = %d\n", r.head);
    return 0;
}
```

Вывод:

```text
push 1: ok
push 2: ok
push 3: ok
push 4: ok
push 5: полон
pop: 1
pop: 2
3 4 6 7
head = 2
```

Все операции — `O(1)`, память фиксирована и выделяется один раз. После того как элементы `6` и `7` легли в начало массива, порядок очереди всё равно правильный: `3 4 6 7`.

## Полон или пуст?

Иногда кольцевой буфер хранят без счётчика — двумя индексами: `head` (откуда читать) и `tail` (куда писать). Тогда возникает ловушка: и в пустом, и в полном буфере `head == tail`. Есть два решения:

1. Хранить счётчик `size`, как выше.
2. Никогда не заполнять буфер до конца: считать его полным, когда `(tail + 1) % capacity == head`. Одна ячейка всегда пустует, и буфер ёмкости `N` хранит не больше `N − 1` элементов.

Второй способ любят там, где читатель и писатель работают одновременно (например, обработчик прерывания пишет, а основная программа читает): писатель меняет только `tail`, читатель — только `head`, и общий счётчик не нужен.

## Ёмкость — степень двойки

Остаток от деления — относительно медленная операция. Если ёмкость — степень двойки, `% capacity` можно заменить битовой маской: `i & (capacity − 1)`. Для `capacity = 8` маска `0b111` оставляет три младших бита — ровно остаток от деления на 8. Поэтому ёмкости буферов в драйверах и сетевых картах почти всегда 256, 1024, 4096.

```c
#include <stdio.h>

int main(void) {
    unsigned capacity = 8;
    for (unsigned i = 5; i < 12; i++) {
        printf("%u: %u %u\n", i, i % capacity, i & (capacity - 1));
    }
    return 0;
}
```

Вывод:

```text
5: 5 5
6: 6 6
7: 7 7
8: 0 0
9: 1 1
10: 2 2
11: 3 3
```

## Режим перезаписи: последние N событий

Часто нужно хранить не всё, а только **последние** `N` значений: последние 100 строк журнала, показания датчика за последнюю минуту, историю команд. Кольцевой буфер для этого идеален: если он полон, новое значение просто **затирает самое старое**.

```c
#include <stdio.h>

enum { N = 3 };

int main(void) {
    int last[N];
    int head = 0, size = 0;
    for (int reading = 1; reading <= 7; reading++) {
        if (size < N) {
            last[(head + size) % N] = reading;
            size++;
        } else {
            last[head] = reading;            // затираем самое старое
            head = (head + 1) % N;
        }
    }
    for (int i = 0; i < size; i++) {
        printf("%d ", last[(head + i) % N]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
5 6 7
```

Сколько бы значений ни пришло, память остаётся `O(N)`, а каждое новое значение обрабатывается за `O(1)`.

<Concept title="Кольцевой буфер">

Массив фиксированной ёмкости, индексы которого заворачиваются по модулю: позиция `i`-го элемента — `(head + i) % capacity`. Очередь без сдвигов и без выделения памяти: все операции `O(1)`. Пустой и полный буфер различают счётчиком или пустой ячейкой. В режиме перезаписи хранит последние `N` значений потока.

</Concept>

## Частые ошибки

<CommonMistake title="Заворот на единицу позже">

```c
tail++;
if (tail > CAPACITY) tail = 0;   // при tail == CAPACITY — запись за конец массива
```

Допустимые индексы — `0…CAPACITY − 1`. Заворачивать нужно при `tail == CAPACITY`, а надёжнее всего — всегда писать `tail = (tail + 1) % CAPACITY`.

</CommonMistake>

<CommonMistake title="head == tail без счётчика">

Если хранить только два индекса и заполнять буфер целиком, полный буфер выглядит как пустой — после заполнения все данные «исчезнут». Нужен счётчик или пустая ячейка.

</CommonMistake>

<CommonMistake title="Маска при ёмкости не степени двойки">

`i & (capacity − 1)` даёт остаток только для ёмкостей 2, 4, 8, … Для ёмкости 6 маска `0b101` превращает индекс 2 в 0 — буфер портит свои же данные.

</CommonMistake>

## Итоги

- Кольцевой буфер — очередь на массиве, индексы которой заворачиваются по модулю ёмкости.
- Все операции `O(1)`, память выделяется один раз.
- Пустой и полный буфер различают счётчиком `size` или пустой ячейкой.
- Для ёмкости-степени двойки `% capacity` заменяется маской `& (capacity − 1)`.
- В режиме перезаписи буфер хранит последние `N` значений потока.
