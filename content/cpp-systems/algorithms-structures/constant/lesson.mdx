## Теория и инвариант

Постоянная сложность означает, что число действий не растёт с выбранным размером задачи. Доступ к a[index] вычисляет адрес из базы, индекса и размера элемента без прохода через предшествующие элементы. Индекс всё равно должен находиться в допустимом диапазоне.

Важно определить, что включено в измерение. Один запрос в уже готовый массив O(1), но чтение n чисел с stdin O(n). Если база адресует не оперативную память, а сеть или диск, абстракция стоимости меняется. Даже в RAM попадание в кеш и обращение к основной памяти имеют разную задержку; O(1) не означает одинаковую длительность каждого вызова.

## Пошаговый разбор

В [10,20,30,40] индекс 2 адресует 30. Индекс 4 уже равен длине и должен быть отвергнут до чтения.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>


int main(void) {
int a[]={10,20,30};printf("%d\n",a[2]);
return 0;
}
```

Ожидаемый вывод:

```text
30
```

## Почему реализация корректна

Чтение a[i] в обычной модели массива использует базовый адрес, размер элемента и индекс. Число этих действий не растёт вместе с длиной массива. Однако корректная операция включает проверку 0≤i&lt;n. В C выражение с отрицательным индексом не становится безопасным от того, что арифметика адреса занимает постоянное время.

Сравните доступ к a[500] и поиск значения 500: первая задача уже знает позицию, вторая должна её обнаружить. Если нужно сначала найти i, сложность поиска входит в стоимость полного запроса. Промах кеша может сильно изменить задержку отдельного чтения, сохранив O(1) в рассматриваемой модели.

| Время         | Запрос индекса O(1); полная программа с загрузкой n значений O(n). |
| Память        | Массив O(n), дополнительная память запроса O(1).                   |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Случайные индексы чаще попадают в разные линии кеша, чем последовательные, хотя обе операции индексирования O(1).

Массив обеспечивает быстрый доступ, но вставка в середину требует сдвигов.
