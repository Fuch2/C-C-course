## Связи между объектами

Деревья описывают иерархию: у каждого узла один родитель. Но многие связи устроены сложнее. Между городами — дороги, и из одного города в другой можно попасть разными путями. В социальной сети у человека много друзей, и друзья дружат между собой. Цели в Makefile зависят от других целей, страницы в интернете ссылаются друг на друга. Всё это **графы**.

**Граф** — набор **вершин** (vertices) и **рёбер** (edges); ребро соединяет две вершины. Обозначения: `V` — число вершин, `E` — число рёбер.

| Понятие                | Значение                                                  |
| ---------------------- | --------------------------------------------------------- |
| неориентированный граф | ребро `u — v` можно пройти в обе стороны (дружба, дорога) |
| ориентированный граф   | ребро `u → v` идёт в одну сторону (ссылка, зависимость)   |
| взвешенный граф        | у ребра есть число — длина, цена, время                   |
| степень вершины        | число рёбер, выходящих из неё                             |
| путь                   | последовательность вершин, соседние соединены рёбрами     |
| цикл                   | путь, который возвращается в начальную вершину            |
| связный граф           | из любой вершины есть путь в любую другую                 |

Дерево — частный случай графа: связный граф без циклов. Списки, деревья, сетки и карты — всё это графы с разной формой.

```text
неориентированный граф, V = 5, E = 5:

   1 ─── 2
   │   ╱ │
   │  ╱  │
   3     4 ─── 5
```

## Матрица смежности

Простейшее представление — таблица `V × V`: `adj[u][v] = 1`, если есть ребро между `u` и `v`. Для неориентированного графа таблица симметрична.

```c
#include <stdio.h>

int main(void) {
    enum { V = 5 };
    int edges[][2] = {{1, 2}, {1, 3}, {2, 3}, {2, 4}, {4, 5}};
    int adj[V + 1][V + 1] = {{0}};                  // вершины с 1, строка 0 не используется
    for (int i = 0; i < 5; i++) {
        int u = edges[i][0], v = edges[i][1];
        adj[u][v] = 1;
        adj[v][u] = 1;                              // неориентированный — в обе стороны
    }
    for (int u = 1; u <= V; u++) {
        int degree = 0;
        for (int v = 1; v <= V; v++) {
            printf("%d ", adj[u][v]);
            degree += adj[u][v];
        }
        printf("  степень %d\n", degree);
    }
    printf("ребро 3-4? %s\n", adj[3][4] ? "да" : "нет");
    return 0;
}
```

Вывод:

```text
0 1 1 0 0   степень 2
1 0 1 1 0   степень 3
1 1 0 0 0   степень 2
0 1 0 0 1   степень 2
0 0 0 1 0   степень 1
ребро 3-4? нет
```

Проверка «есть ли ребро» — `O(1)`. Но таблица занимает `V²` ячеек: для графа дорог России с миллионом перекрёстков это триллион ячеек, хотя дорог всего несколько миллионов. Перебор соседей вершины тоже стоит `O(V)`, даже если соседей двое. Матрица хороша для **плотных** графов, где рёбер порядка `V²`, и для небольших `V`.

Сумма степеней `2 + 3 + 2 + 2 + 1 = 10` — ровно вдвое больше числа рёбер: каждое ребро добавляет единицу к степени обоих концов. Это **лемма о рукопожатиях**, удобная проверка правильности построения.

## Списки смежности

Большинство реальных графов **разреженные**: рёбер намного меньше `V²`. Для них хранят у каждой вершины **список соседей**. Память — `O(V + E)`, перебор соседей вершины — пропорционально её степени.

В C списки смежности удобно строить без отдельного `malloc` на каждое ребро — в виде **сжатого представления** (CSR, compressed sparse row). Идея из урока о префиксных суммах:

1. Посчитать степень каждой вершины.
2. Префиксными суммами вычислить, где в общем массиве начинается список каждой вершины: `start[v]`.
3. Разложить соседей по своим местам.

```c
#include <stdio.h>

enum { V = 5, E = 5 };

int main(void) {
    int edges[E][2] = {{1, 2}, {1, 3}, {2, 3}, {2, 4}, {4, 5}};
    int start[V + 2] = {0};
    for (int i = 0; i < E; i++) {                   // 1. степени
        start[edges[i][0] + 1]++;
        start[edges[i][1] + 1]++;
    }
    for (int v = 1; v <= V + 1; v++) {              // 2. начала списков
        start[v] += start[v - 1];
    }
    int neighbours[2 * E];
    int fill[V + 1];
    for (int v = 1; v <= V; v++) {
        fill[v] = start[v];
    }
    for (int i = 0; i < E; i++) {                   // 3. раскладка
        int u = edges[i][0], v = edges[i][1];
        neighbours[fill[u]++] = v;
        neighbours[fill[v]++] = u;
    }
    for (int v = 1; v <= V; v++) {
        printf("%d:", v);
        for (int k = start[v]; k < start[v + 1]; k++) {
            printf(" %d", neighbours[k]);
        }
        printf("\n");
    }
    return 0;
}
```

Вывод:

```text
1: 2 3
2: 1 3 4
3: 1 2
4: 2 5
5: 4
```

Соседи вершины `v` лежат подряд: `neighbours[start[v] … start[v + 1] − 1]`. Весь граф — два массива, а обход соседей — простой цикл по памяти подряд, что хорошо для кэша. Неориентированное ребро записано дважды — у обоих концов, поэтому массив соседей длины `2E`.

## Сравнение представлений

| Операция              | Матрица | Списки смежности                                    |
| --------------------- | ------- | --------------------------------------------------- |
| память                | `O(V²)` | `O(V + E)`                                          |
| есть ли ребро `u — v` | `O(1)`  | `O(deg u)`; `O(log deg u)` в отсортированном списке |
| перебор соседей `u`   | `O(V)`  | `O(deg u)`                                          |
| обход всего графа     | `O(V²)` | `O(V + E)`                                          |

Для алгоритмов обхода — поиска в ширину и в глубину из следующих уроков — нужен именно перебор соседей, поэтому их почти всегда пишут на списках смежности.

## Ввод графа

В задачах граф обычно задают так: первая строка — `V` и `E`, дальше `E` строк с парами вершин `u v`. Вершины нумеруются **с 1** — частый источник ошибок: массив на `V` элементов имеет индексы `0…V − 1`, и вершина `V` в него не помещается. Либо выделяйте `V + 1` ячейку, либо вычитайте единицу при чтении.

<Concept title="Граф">

Вершины и рёбра; рёбра бывают направленными и взвешенными. Матрица смежности занимает `O(V²)` и проверяет ребро за `O(1)`; списки смежности занимают `O(V + E)` и перебирают соседей за степень вершины. Для разреженных графов и алгоритмов обхода выбирают списки; в C их удобно хранить сжато: массив начал и общий массив соседей.

</Concept>

## Частые ошибки

<CommonMistake title="Вершины с единицы в массиве с нуля">

`int degree[V]` и `degree[v]++` для `v = V` — запись за границей массива. AddressSanitizer сообщит `buffer-overflow`. Выделяйте `V + 1` элемент или храните `v − 1`.

</CommonMistake>

<CommonMistake title="Неориентированное ребро в одну сторону">

Для неориентированного графа ребро нужно записать у **обоих** концов. Если записать только `u → v`, из `v` в `u` пройти будет нельзя, и обход найдёт не все вершины.

</CommonMistake>

<CommonMistake title="Матрица для большого разреженного графа">

`int adj[100000][100000]` — 40 ГБ памяти. При `V` больше нескольких тысяч используйте списки смежности.

</CommonMistake>

## Практика

Граф задаётся так: первая строка — `V` и `E`, дальше `E` строк `u v` (вершины с 1).

1. **Степени вершин** — подсчёт и лемма о рукопожатиях.
2. **Списки смежности** — сжатое представление.
3. **Найди ошибку: нумерация с единицы** — выход за массив.
4. **Общие соседи** — слияние отсортированных списков.

## Итоги

- Граф — вершины и рёбра; рёбра бывают ориентированными и взвешенными.
- Матрица смежности: `O(V²)` памяти, ребро проверяется за `O(1)`; подходит для плотных и маленьких графов.
- Списки смежности: `O(V + E)` памяти, соседи перебираются за степень вершины; основа алгоритмов обхода.
- Сжатое представление строится подсчётом степеней и префиксными суммами.
- Сумма степеней неориентированного графа равна `2E`.
- Вершины во вводе часто нумеруются с 1 — выделяйте `V + 1` ячейку.
