## Почему не секунды

Самый очевидный способ сравнить два алгоритма — засечь время. Но время зависит от процессора, компилятора, флагов оптимизации и того, чем ещё занят компьютер. Программа, которая на ноутбуке работает 2 секунды, на сервере проверки может работать 0,5 или 5.

Поэтому алгоритмы сравнивают по **числу элементарных операций** в зависимости от **размера входа**. Элементарной считают операцию, которая занимает примерно постоянное время: сравнение, присваивание, арифметику, обращение к элементу массива по индексу. Точное время каждой операции не важно — важно, как растёт их количество.

## Размер входа

Размер входа обозначают `n`. Что это такое, зависит от задачи:

| Задача                           | Размер входа `n`       |
| -------------------------------- | ---------------------- |
| сумма массива, поиск, сортировка | число элементов        |
| сложение длинных чисел           | число цифр             |
| поиск подстроки                  | длины текста и образца |
| обход дорог между городами       | число городов и дорог  |

Иногда размеров два: например, текст длины `n` и образец длины `m`. Тогда число операций зависит от обоих.

## Подсчёт операций в цикле

Посчитаем операции в сумме массива. Тело цикла выполняется `n` раз, в нём сложение и обращение к элементу; ещё `n + 1` раз проверяется условие `i < n`. Итого около `3n + 2` операций. Точная константа зависит от того, что считать операцией, — а вот то, что число операций **пропорционально `n`**, не зависит ни от чего.

Чтобы не гадать, операции можно посчитать прямо в программе — завести счётчик и увеличивать его там, где выполняется интересующая нас операция:

```c
#include <stdio.h>

static long long comparisons = 0;

static int find(const int *values, int n, int target) {
    for (int i = 0; i < n; i++) {
        comparisons++;
        if (values[i] == target) {
            return i;
        }
    }
    return -1;
}

int main(void) {
    int values[] = {4, 8, 15, 16, 23, 42};
    int targets[] = {4, 23, 42, 7};
    for (int k = 0; k < 4; k++) {
        comparisons = 0;
        int index = find(values, 6, targets[k]);
        printf("ищем %2d: индекс %2d, сравнений %lld\n", targets[k], index, comparisons);
    }
    return 0;
}
```

Вывод:

```text
ищем  4: индекс  0, сравнений 1
ищем 23: индекс  4, сравнений 5
ищем 42: индекс  5, сравнений 6
ищем  7: индекс -1, сравнений 6
```

Такой счётчик — честная метрика: он не зависит от компьютера, и его можно проверить тестом. Мы будем пользоваться им весь модуль.

## Лучший, худший и средний случай

Пример выше показывает, что даже при одном и том же `n` число операций бывает разным:

- **лучший случай** — искомое стоит первым: 1 сравнение;
- **худший случай** — искомое последнее или его нет: `n` сравнений;
- **средний случай** — если искомое с равной вероятностью стоит на любом месте, в среднем около `n / 2` сравнений.

Чаще всего оценивают **худший случай**. Он даёт гарантию: «программа никогда не сделает больше стольких-то операций». Лучший случай почти бесполезен — на удачном входе быстр любой алгоритм. Средний случай важен на практике, но требует знать, какие входы встречаются чаще.

## Вложенные циклы

Когда один цикл вложен в другой, количество операций перемножается. Посчитаем, сколько раз выполнится тело в трёх типичных вариантах:

```c
#include <stdio.h>

int main(void) {
    int n = 6;
    long long all = 0, pairs = 0, halving = 0;
    for (int i = 0; i < n; i++) {
        for (int j = 0; j < n; j++) {
            all++;                       // все упорядоченные пары
        }
    }
    for (int i = 0; i < n; i++) {
        for (int j = i + 1; j < n; j++) {
            pairs++;                     // пары i < j
        }
    }
    for (int i = n; i > 0; i /= 2) {
        halving++;                       // деление пополам
    }
    printf("n * n = %lld\n", all);
    printf("i < j = %lld\n", pairs);
    printf("пополам = %lld\n", halving);
    return 0;
}
```

Вывод:

```text
n * n = 36
i < j = 15
пополам = 3
```

- Два полных цикла по `n` дают `n · n = n²` итераций.
- Пары `i < j`: при `i = 0` внутренний цикл делает `n − 1` итераций, при `i = 1` — `n − 2`, и так до нуля. Сумма `(n − 1) + (n − 2) + … + 1 + 0 = n(n − 1) / 2`. Для `n = 6` это 15. Вдвое меньше, чем `n²`, но всё равно растёт как квадрат.
- Цикл, который делит `i` пополам, делает столько итераций, сколько цифр в двоичной записи `n`: `6 → 3 → 1 → 0`. Это примерно `log₂ n`.

## Как растут функции

Вот число операций для разных `n`, если алгоритм делает `log₂ n`, `n`, `n log₂ n`, `n²` или `2ⁿ` шагов:

| `n`   | `log₂ n` | `n`   | `n log₂ n` | `n²` | `2ⁿ`         |
| ----- | -------- | ----- | ---------- | ---- | ------------ |
| 10    | 3        | 10    | 33         | 100  | 1 024        |
| 100   | 7        | 100   | 664        | 10⁴  | ≈ 1,3 · 10³⁰ |
| 1 000 | 10       | 1 000 | ≈ 10⁴      | 10⁶  | —            |
| 10⁶   | 20       | 10⁶   | ≈ 2 · 10⁷  | 10¹² | —            |

Современный процессор выполняет порядка **10⁸–10⁹ простых операций в секунду**. Отсюда практическое правило для задач с лимитом в одну секунду:

| `n` до | подходящий алгоритм             |
| ------ | ------------------------------- |
| 20     | `2ⁿ` — перебор всех подмножеств |
| 5 000  | `n²`                            |
| 10⁶    | `n log n`                       |
| 10⁸    | `n`                             |
| больше | `log n` или формула             |

При `n = 10⁶` алгоритм `n²` сделает 10¹² операций — это десятки минут. Никакая оптимизация кода не спасёт неудачный алгоритм; спасает только другой алгоритм.

## Частые ошибки

<CommonMistake title="Мерить время одного запуска">

Одно измерение показывает, как быстро работала конкретная программа на конкретном компьютере. На маленьких входах `n²` может оказаться быстрее `n log n` из-за накладных расходов. Сравнивайте рост: удвойте `n` и посмотрите, во сколько раз выросло число операций.

</CommonMistake>

<CommonMistake title="Не замечать скрытый цикл">

```c
for (size_t i = 0; i < strlen(text); i++) {
    // ...
}
```

`strlen` сама проходит всю строку, а вызывается в условии на **каждой** итерации. Цикл, который выглядит линейным, делает `n²` операций. Вычислите длину один раз до цикла.

</CommonMistake>

<CommonMistake title="Переполнение счётчика">

Число операций растёт быстро: `n²` при `n = 10⁵` — уже 10¹⁰, больше `INT_MAX`. Считайте операции в `long long`.

</CommonMistake>

## Практика

1. **Сколько итераций** — формулы для трёх видов циклов.
2. **Счётчик сравнений** — лучший и худший случай поиска.
3. **Найди ошибку: пары с суммой** — неверные границы вложенного цикла.
4. **Уложится ли в секунду** — оценка числа операций без переполнения.

## Итоги

- Алгоритмы сравнивают по числу операций в зависимости от размера входа `n`, а не по секундам.
- Счётчик операций в программе — воспроизводимая метрика.
- Оценивают обычно худший случай: он даёт гарантию.
- Два вложенных цикла по `n` — `n²` итераций, пары `i < j` — `n(n − 1) / 2`, деление пополам — около `log₂ n`.
- Около 10⁸ простых операций в секунду: по ограничению на `n` можно понять, какой алгоритм нужен.
