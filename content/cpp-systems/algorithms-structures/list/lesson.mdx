## Цели обучения

- Объяснить инвариант: Цепочка вагонов: каждый знает только следующий, а head — точка входа.
- Обосновать время: Вставка в голову O(1), поиск и удаление всех совпадений O(n).
- Оценить память и компромиссы: Стабильность адресов живых узлов и дешёвые локальные перестановки против дорогого обхода и отсутствия индексации.

## Теория и инвариант

Узел хранит значение и ссылку next. Вставка после известного узла меняет несколько ссылок, но поиск нужного места остаётся линейным. Поэтому фраза «вставка в список O(1)» неполна без условия о готовом указателе. Если задача просит удалить по значению, сначала нужно найти совпадения.

Указатель на указатель позволяет единообразно менять head или next предыдущего узла. При удалении сохраняем следующий адрес до free и не читаем освобождённый узел. Если удалили текущий узел, ссылку на следующее место проверяем снова: рядом могут стоять несколько совпадений. Владелец списка отвечает за освобождение всех узлов, включая частично построенный список при отказе malloc.

## Пошаговый разбор

3 → 3 → 5 → NULL, удаление 3 сначала меняет head на вторую 3, затем на 5. Нельзя пропускать второй совпавший узел.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct Node { int value; struct Node *next; } Node;
static int prepend(Node **head,int value){
    Node *node=malloc(sizeof *node);if(!node)return 0;
    *node=(Node){value,*head};*head=node;return 1;
}
static void remove_value(Node **head,int target){
    /* link указывает на поле, которое владеет ссылкой на текущий узел. */
    Node **link=head;
    while(*link){
        if((*link)->value==target){Node *old=*link;*link=old->next;free(old);}
        else link=&(*link)->next;
    }
}
static void destroy(Node **head){
    while(*head){Node *old=*head;*head=old->next;free(old);}
}
int main(void) {
Node *head=NULL;if(!prepend(&head,5)||!prepend(&head,3)||!prepend(&head,3)){destroy(&head);return 1;}remove_value(&head,3);printf("%d\n",head->value);destroy(&head);
return 0;
}
```

Ожидаемый вывод:

```text
5
```

## Почему реализация корректна

Для цепочки 3→3→5→3 и удаления 3 нельзя просто запомнить предшественника: первого предшественника нет, а совпадения идут подряд. Указатель на ссылку сначала обозначает head. Если текущий узел удаляется, переписываем эту ссылку на next и освобождаем узел; сам указатель на ссылку остаётся на месте и проверяет нового соседа.

Если значение сохраняется, переносим указатель на поле next текущего узла. Так одинаково обрабатываются голова и середина. Перед free нужно сохранить или присвоить next, после free читать поле уже нельзя. При обходе очистки применяется то же правило. Поиск занимает O(n), хотя само исключение известного узла после найденной ссылки требует O(1) действий.

## Cache locality и компромиссы

Узлы могут лежать далеко друг от друга; pointer chasing мешает предвыборке следующего адреса.

Стабильность адресов живых узлов и дешёвые локальные перестановки против дорогого обхода и отсутствия индексации.

Практическое применение: Связывание объектов, которые уже имеют устойчивые адреса; свободные списки.

<CommonMistake title="Типичная ошибка">

Операция O(1) изменения ссылок не включает поиск позиции.

</CommonMistake>

## Связь со STL C++

std::forward_list предоставляет insert_after и erase_after; это подчёркивает необходимость знать предшествующий узел.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <forward_list>
int main(){
std::forward_list<int> a{3,3,5};a.remove(3);for(int x:a)std::cout<<x;std::cout<<"\n";
return 0;
}
```

Вывод:

```text
5
```
