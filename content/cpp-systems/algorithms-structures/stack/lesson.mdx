## Последним пришёл — первым ушёл

**Стек** (stack) — набор элементов, в котором добавлять и удалять можно только с одного конца — **вершины**. Как стопка тарелок: новую кладут сверху, и берут тоже сверху. Порядок такой называют **LIFO** — last in, first out, «последним пришёл — первым ушёл».

У стека три основные операции, все за `O(1)`:

| Операция  | Что делает                            |
| --------- | ------------------------------------- |
| `push(x)` | положить `x` на вершину               |
| `pop()`   | снять элемент с вершины и вернуть его |
| `top()`   | посмотреть на вершину, не снимая      |

Стек — **абстрактный тип данных**: он определяется операциями, а не устройством. Реализовать его можно на массиве или на списке.

## Стек на массиве

Массив и индекс вершины — всё, что нужно. Элементы лежат в `data[0…size − 1]`, вершина — `data[size − 1]`:

```c
#include <stdio.h>

enum { CAPACITY = 100 };

typedef struct {
    int data[CAPACITY];
    int size;
} Stack;

static bool push(Stack *s, int x) {
    if (s->size == CAPACITY) {
        return false;                    // переполнение
    }
    s->data[s->size++] = x;
    return true;
}

static bool pop(Stack *s, int *out) {
    if (s->size == 0) {
        return false;                    // стек пуст
    }
    *out = s->data[--s->size];
    return true;
}

int main(void) {
    Stack s = {.size = 0};
    for (int i = 1; i <= 4; i++) {
        push(&s, i * 10);
    }
    int x;
    while (pop(&s, &x)) {
        printf("%d ", x);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
40 30 20 10
```

Элементы выходят в обратном порядке. Обе граничные ситуации — **переполнение** (push в полный стек) и **опустошение** (pop из пустого) — нужно обрабатывать явно: функции возвращают `false`, а значение передают через указатель. Если ёмкость заранее неизвестна, стек строят на динамическом массиве: `push` в конец — амортизированное `O(1)`. На односвязном списке стек тоже естественен: вершина — голова.

## Проверка скобок

Классическая задача для стека — проверить, правильно ли расставлены скобки: `([]{})` — правильно, `([)]` — нет. Идея: открывающую скобку кладём на стек; закрывающая должна соответствовать **последней** не закрытой открывающей — то есть вершине стека.

```c
#include <stdio.h>

static bool balanced(const char *text) {
    char stack[100];
    int size = 0;
    for (const char *p = text; *p != '\0'; p++) {
        char c = *p;
        if (c == '(' || c == '[' || c == '{') {
            if (size == 100) {
                return false;
            }
            stack[size++] = c;
        } else if (c == ')' || c == ']' || c == '}') {
            char open = c == ')' ? '(' : c == ']' ? '[' : '{';
            if (size == 0 || stack[size - 1] != open) {
                return false;            // нет пары или пара не того вида
            }
            size--;
        }
    }
    return size == 0;                    // все открытые закрыты
}

int main(void) {
    const char *tests[] = {"([]{})", "([)]", "((", "())", "a[b(c)d]e"};
    for (int i = 0; i < 5; i++) {
        printf("%-10s %s\n", tests[i], balanced(tests[i]) ? "да" : "нет");
    }
    return 0;
}
```

Вывод:

```text
([]{})     да
([)]       нет
((         нет
())        нет
a[b(c)d]e  да
```

Три способа ошибиться — три проверки: закрывающая скобка при пустом стеке, закрывающая скобка не того вида и незакрытые скобки в конце. Без стека, одним счётчиком, можно проверить только скобки одного вида.

## Стек вызовов

Вы уже пользовались стеком, даже не замечая: **стек вызовов** функций. При вызове функции её кадр кладётся на вершину, при возврате — снимается. Вернуться можно только в последнюю вызвавшую функцию — LIFO. Поэтому любую рекурсию можно переписать циклом с явным стеком: в стек кладётся то, что иначе хранилось бы в кадрах вызовов. Так делают, когда глубина рекурсии может превысить размер стека вызовов.

## Вычисление выражений

Компьютеру неудобно вычислять `3 + 4 * 2` — мешают приоритеты и скобки. Удобнее **обратная польская запись** (постфиксная): операция пишется после операндов, `3 4 2 * +`. Скобки не нужны, а вычисляется она одним проходом со стеком: число кладём на стек, операция снимает два верхних числа и кладёт результат.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    char expr[] = "3 4 2 * + 10 2 / -";
    long long stack[50];
    int size = 0;
    for (char *token = strtok(expr, " "); token != NULL; token = strtok(NULL, " ")) {
        if (strlen(token) == 1 && strchr("+-*/", token[0]) != NULL) {
            long long b = stack[--size];         // правый операнд — на вершине
            long long a = stack[--size];
            long long r = token[0] == '+' ? a + b
                        : token[0] == '-' ? a - b
                        : token[0] == '*' ? a * b
                                          : a / b;
            stack[size++] = r;
        } else {
            stack[size++] = strtoll(token, NULL, 10);
        }
    }
    printf("%lld\n", stack[0]);
    return 0;
}
```

Вывод:

```text
6
```

`3 4 2 * +` — это `3 + 4·2 = 11`, `10 2 /` — `5`, и итог `11 − 5 = 6`. Порядок снятия важен: правый операнд лежит на вершине, поэтому для `10 2 /` сначала снимается `2`. Эта программа доверяет входу; в практике нужно проверять, что для операции хватает операндов. Компиляторы и калькуляторы переводят обычную запись в постфиксную тоже стеком — алгоритмом «сортировочной станции» Дейкстры.

## Монотонный стек

Задача: для каждого дня найти, через сколько дней будет теплее. Перебор «для каждого дня смотреть вперёд» — `O(n²)`. Стек решает её за `O(n)`: в нём лежат индексы дней, для которых тёплый день ещё не найден, причём температуры в стеке **убывают** от дна к вершине. Новый день «закрывает» все дни на вершине, которые холоднее его.

```c
#include <stdio.h>

int main(void) {
    int t[] = {73, 74, 75, 71, 69, 72, 76, 73};
    int n = 8;
    int answer[8] = {0};
    int stack[8], size = 0;                 // индексы дней без ответа
    for (int i = 0; i < n; i++) {
        while (size > 0 && t[stack[size - 1]] < t[i]) {
            int day = stack[--size];
            answer[day] = i - day;
        }
        stack[size++] = i;
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", answer[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1 1 4 2 1 1 0 0
```

Хотя внутри цикла `for` есть цикл `while`, алгоритм линейный: каждый индекс кладётся в стек один раз и снимается не больше одного раза — всего не больше `2n` операций со стеком. Это та же амортизация, что у динамического массива.

<Concept title="Стек">

Структура LIFO: `push`, `pop` и `top` работают с вершиной за `O(1)`. Реализуется массивом с индексом вершины или списком с головой-вершиной. Стек нужен, когда последнее начатое должно закончиться первым: вложенные скобки, вызовы функций, вычисление выражений, возврат при обходе. Пустой и переполненный стек — граничные случаи, которые всегда проверяются.

</Concept>

## Частые ошибки

<CommonMistake title="pop из пустого стека">

`stack[--size]` при `size == 0` читает `stack[-1]`, а `size` становится отрицательным, и следующие операции портят память. Перед `pop` и `top` проверяйте `size > 0`.

</CommonMistake>

<CommonMistake title="Переполнение массива стека">

`stack[size++] = x` без проверки `size < CAPACITY` пишет за конец массива. Для входа произвольной длины используйте динамический массив или проверяйте ёмкость.

</CommonMistake>

<CommonMistake title="Порядок операндов">

В постфиксной записи `a b -` вершина стека — `b`. Если снять `a` первым, `10 2 -` вычислится как `−8`.

</CommonMistake>

## Практика

1. **Обратный порядок** — стек на массиве.
2. **Скобки** — проверка с позицией ошибки.
3. **Найди ошибку: калькулятор** — снятие из пустого стека.
4. **Ближайший больший справа** — монотонный стек.

## Итоги

- Стек — LIFO: добавление и удаление только на вершине, `O(1)`.
- На массиве вершина — `data[size − 1]`; на списке — голова.
- Переполнение и опустошение проверяются явно.
- Стек проверяет вложенность скобок, вычисляет постфиксные выражения и заменяет рекурсию.
- Монотонный стек находит ближайший больший элемент для всех позиций за `O(n)`.
