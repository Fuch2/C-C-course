## Теория и инвариант

Стек задаёт дисциплину LIFO: последним добавлен — первым извлечён. Это абстрактный интерфейс, а не обязательно системный стек вызовов. Его можно реализовать массивом или списком. В массиве size указывает на первое свободное место; top читает data[size−1] только при непустом стеке.

Фиксированная вместимость полезна в ограниченной среде: операции не вызывают allocator и имеют предсказуемую стоимость. За это платим возможностью переполнения. Динамическая версия переносит проблему в отказ выделения и амортизированную оценку. pop возвращает статус отдельно от значения: ноль и отрицательные числа могут быть корректными данными.

</Concept>

## Пошаговый разбор

P 4, P 9, T, O, O дают наблюдения 9,9,4. Следующий O сообщает ПУСТО.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct { int data[128]; size_t size; } Stack;
static int push(Stack *stack,int value){
    if(stack->size==128)return 0;stack->data[stack->size++]=value;return 1;
}
static int pop(Stack *stack,int *out){
    if(!stack->size)return 0;*out=stack->data[--stack->size];return 1;
}
static int top(const Stack *stack,int *out){
    if(!stack->size)return 0;*out=stack->data[stack->size-1];return 1;
}
int main(void) {
Stack stack={0};push(&stack,4);push(&stack,9);int x;pop(&stack,&x);printf("%d\n",x);
return 0;
}
```

Ожидаемый вывод:

```text
9
```

## Почему реализация корректна

Для команд P 4, P 9, T, O, O вершина сначала 4, затем 9. T читает 9, не меняя size; O уменьшает size и возвращает бывший верхний элемент. Следующее O возвращает 4, ещё одно сообщает пустоту. Проверка size==0 должна предшествовать уменьшению беззнакового счётчика или вычислению индекса size−1.

Массивный стек не обязан очищать освободившуюся ячейку: границу живых элементов определяет size. Это допустимо для int, но для владеющих ресурсов потребовалось бы освобождение. Проверка переполнения предшествует записи. Для ограниченного стека операции имеют гарантированное O(1); для растущего массива push становится амортизированным O(1).

## Сложность и память

| Что оцениваем | Гарантия                                                       |
| ------------- | -------------------------------------------------------------- |
| Время         | O(1) на push/pop/top в фиксированном массиве.                  |
| Память        | O(capacity); в реализации capacity=128 задаёт конечный ресурс. |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Верхушка расположена рядом с недавно использованными элементами и обычно остаётся горячей.

Предсказуемость и простота против доступа только к верхушке.

Практическое применение: Проверка скобок, отмена команд, явная замена рекурсии.

<CommonMistake title="Типичная ошибка">

Вычитание 1 из нулевого size_t даёт огромное значение; сначала проверяется пустота.

</CommonMistake>

## Связь со STL C++

std::stack — адаптер; top читает, pop удаляет и не возвращает значение. Проверяйте empty до обеих операций.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <stack>
int main(){
std::stack<int> s;s.push(4);s.push(9);std::cout<<s.top()<<"\n";s.pop();
return 0;
}
```

Вывод:

```text
9
```
