## Идея: разбиение

Сортировка слиянием делит массив пополам «вслепую», а всю работу делает при слиянии. **Быстрая сортировка** (quicksort) поступает наоборот: работу она делает при **разбиении**, а объединять ничего не нужно.

Выберем элемент — **опорный** (pivot). Переставим массив так, чтобы все элементы меньше опорного оказались левее него, а остальные — правее. После этого опорный элемент стоит **на своём окончательном месте**: левее — только меньшие, правее — только не меньшие. Осталось отдельно отсортировать левую и правую части — рекурсивно.

## Разбиение Ломуто

Простейший способ разбиения — схема Ломуто. Опорный — последний элемент. Индекс `store` отмечает границу «меньших»: всё левее `store` меньше опорного. Проходим по массиву; встретив элемент меньше опорного, ставим его на место `store` и сдвигаем границу.

```c
#include <stdio.h>

static void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

static int partition(int *values, int lo, int hi) {     // [lo, hi], опорный — values[hi]
    int pivot = values[hi];
    int store = lo;
    for (int i = lo; i < hi; i++) {
        if (values[i] < pivot) {
            swap(&values[i], &values[store]);
            store++;
        }
    }
    swap(&values[store], &values[hi]);                  // опорный — на границу
    return store;
}

int main(void) {
    int values[] = {7, 2, 1, 8, 6, 3, 5, 4};
    int p = partition(values, 0, 7);
    for (int i = 0; i < 8; i++) {
        printf("%d ", values[i]);
    }
    printf("\nопорный %d на позиции %d\n", values[p], p);
    return 0;
}
```

Вывод:

```text
2 1 3 4 6 7 5 8
опорный 4 на позиции 3
```

Слева от `4` — `2 1 3` (меньшие), справа — `6 7 5 8` (большие). Сами части не отсортированы, но `4` уже на месте: в отсортированном массиве перед ним как раз три элемента.

**Инвариант цикла:** элементы `values[lo…store − 1]` меньше опорного, элементы `values[store…i − 1]` — не меньше. После цикла остаётся поставить опорный между двумя группами.

## Сортировка

```c
#include <stdio.h>

static void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

static int partition(int *values, int lo, int hi) {
    int pivot = values[hi];
    int store = lo;
    for (int i = lo; i < hi; i++) {
        if (values[i] < pivot) {
            swap(&values[i], &values[store++]);
        }
    }
    swap(&values[store], &values[hi]);
    return store;
}

static void quick_sort(int *values, int lo, int hi) {   // [lo, hi]
    if (lo >= hi) {
        return;
    }
    int p = partition(values, lo, hi);
    quick_sort(values, lo, p - 1);                      // опорный не входит
    quick_sort(values, p + 1, hi);
}

int main(void) {
    int values[] = {7, 2, 1, 8, 6, 3, 5, 4};
    quick_sort(values, 0, 7);
    for (int i = 0; i < 8; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1 2 3 4 5 6 7 8
```

Опорный элемент в рекурсивные вызовы **не входит** — именно это гарантирует, что каждая часть строго меньше исходного отрезка, даже если опорный оказался крайним.

## Хороший и плохой опорный

Если опорный каждый раз делит отрезок примерно пополам, получается то же дерево, что у сортировки слиянием: `log₂ n` уровней по `O(n)` — `O(n log n)`. Но если опорный оказывается **наибольшим** или **наименьшим**, одна часть пустая, а другая короче всего на единицу. Уровней становится `n`, и сортировка вырождается в `O(n²)`.

С опорным «последний элемент» так происходит на **уже отсортированном** массиве — самом частом входе на практике:

```c
#include <stdio.h>
#include <stdlib.h>

static long long comparisons;

static void swap(int *a, int *b) {
    int t = *a;
    *a = *b;
    *b = t;
}

static void quick_sort(int *values, int lo, int hi, int middle_pivot) {
    if (lo >= hi) {
        return;
    }
    if (middle_pivot) {
        swap(&values[lo + (hi - lo) / 2], &values[hi]);   // опорный — средний элемент
    }
    int pivot = values[hi], store = lo;
    for (int i = lo; i < hi; i++) {
        comparisons++;
        if (values[i] < pivot) {
            swap(&values[i], &values[store++]);
        }
    }
    swap(&values[store], &values[hi]);
    quick_sort(values, lo, store - 1, middle_pivot);
    quick_sort(values, store + 1, hi, middle_pivot);
}

int main(void) {
    enum { N = 2000 };
    static int a[N];
    for (int pivot_kind = 0; pivot_kind < 2; pivot_kind++) {
        for (int i = 0; i < N; i++) {
            a[i] = i;                                      // уже отсортирован
        }
        comparisons = 0;
        quick_sort(a, 0, N - 1, pivot_kind);
        printf("%s: %lld сравнений\n", pivot_kind ? "средний" : "последний", comparisons);
    }
    return 0;
}
```

Вывод:

```text
последний: 1999000 сравнений
средний: 17964 сравнений
```

Почти два миллиона сравнений — ровно `n(n − 1)/2` — против восемнадцати тысяч — меньше, чем `n log₂ n ≈ 22 000`. На отсортированном массиве средний элемент — идеальный опорный.

Способы выбрать опорный:

| Способ                                    | Плюс                                      | Минус                                    |
| ----------------------------------------- | ----------------------------------------- | ---------------------------------------- |
| первый или последний                      | просто                                    | `O(n²)` на отсортированных данных        |
| средний                                   | хорош на отсортированных данных           | есть специально подобранные плохие входы |
| медиана трёх (первый, средний, последний) | редко ошибается сильно                    | тоже уязвим к подобранным входам         |
| случайный                                 | плохой случай маловероятен на любом входе | нужен генератор случайных чисел          |

В среднем быстрая сортировка делает около `1,39 n log₂ n` сравнений и обычно быстрее сортировки слиянием: она работает **на месте**, без буфера, и её внутренний цикл очень прост.

## Глубина рекурсии и равные элементы

Даже при хорошем опорном стоит позаботиться о худшем случае: глубина рекурсии `n` переполнит стек. Приём — рекурсивно сортировать **меньшую** часть, а большую обрабатывать в цикле. Тогда каждый рекурсивный вызов получает не больше половины отрезка, и глубина не превышает `log₂ n`.

Вторая ловушка — **много равных элементов**. Разбиение Ломуто отправляет все равные опорному элементы в одну часть, и на массиве из одинаковых чисел сортировка снова становится квадратичной. Решение — **трёхчастное разбиение**: меньшие, равные и большие; равные сразу оказываются на месте и в рекурсию не идут.

## Свойства

- Средний случай `O(n log n)`, худший — `O(n²)`.
- Сортирует **на месте**: дополнительная память — только стек рекурсии, `O(log n)` при правильной реализации.
- **Неустойчива**: обмены переносят элементы через равные им.
- Функция `qsort` из `<stdlib.h>` названа в честь быстрой сортировки, но стандарт не требует конкретного алгоритма; `std::sort` в C++ — гибрид быстрой сортировки, сортировки кучей и вставками, который гарантирует `O(n log n)`.

<Concept title="Быстрая сортировка">

Разбиение ставит опорный элемент на окончательное место: левее — меньшие, правее — не меньшие; затем части сортируются рекурсивно без опорного. Хороший опорный делит отрезок примерно пополам — `O(n log n)`; крайний — даёт `O(n²)`. Работает на месте и на практике обычно быстрее всех, но неустойчива и требует аккуратного выбора опорного.

</Concept>

## Частые ошибки

<CommonMistake title="Опорный в рекурсивном вызове">

```c
int p = partition(values, lo, hi);
quick_sort(values, lo, p);          // должно быть p − 1
quick_sort(values, p + 1, hi);
```

Если опорный — наибольший элемент, `p == hi`, и первый вызов получает тот же отрезок `[lo, hi]`. Рекурсия бесконечна, программа падает с переполнением стека.

</CommonMistake>

<CommonMistake title="Крайний опорный на отсортированных данных">

Опорный «последний элемент» на отсортированном или почти отсортированном массиве даёт `O(n²)` и глубину рекурсии `n`. Берите средний элемент, медиану трёх или случайный.

</CommonMistake>

<CommonMistake title="Сравнение <= в разбиении">

С условием `values[i] <= pivot` равные опорному уходят влево, и массив из одинаковых элементов разбивается на части `n − 1` и `0` на каждом шаге — квадратичное время. Для данных с повторами нужно трёхчастное разбиение.

</CommonMistake>

## Итоги

- Разбиение ставит опорный на окончательное место и делит отрезок на меньшие и не меньшие элементы.
- Части сортируются рекурсивно, опорный в них не входит.
- Хороший опорный — `O(n log n)`, крайний — `O(n²)`; последний элемент как опорный плох на отсортированных данных.
- Сортирует на месте и неустойчива; рекурсия в меньшую часть ограничивает глубину `log n`.
- Много равных элементов требуют трёхчастного разбиения.
