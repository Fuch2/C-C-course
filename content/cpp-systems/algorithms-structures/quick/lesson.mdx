## Цели обучения

- Объяснить инвариант: Раскладываем карточки по трём коробкам, а затем разбираем только две крайние.
- Обосновать время: В среднем O(n log n) при подходящей модели входов; худший O(n²).
- Оценить память и компромиссы: Малая дополнительная память против отсутствия стабильности и риска плохих разбиений.

## Теория и инвариант

Выбираем опорное значение и делим диапазон на элементы меньше, равные и больше него. В трёхчастной схеме поддерживаются области [left,lt), [lt,i), [i,gt), [gt,right). Третья область ещё не исследована. После обмена с правой границей новый a[i] ещё неизвестен, поэтому i не увеличивается.

Равные опорному элементы исключаются из будущей работы, что важно на данных с множеством дубликатов. Выбор среднего индекса не гарантирует сбалансированные значения: возможен квадратичный худший случай. В реализации рекурсивно обрабатывается меньшая часть, большая — циклом. Это ограничивает глубину стека O(log n), даже когда суммарная работа плоха.

</Concept>

## Пошаговый разбор

Для [3,1,3,2,3] при pivot=3 средняя область собирает три тройки, рекурсия нужна только для [1,2].

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static void swap(int *a,int *b){int temp=*a;*a=*b;*b=temp;}
static void quick(int *a,int left,int right){
    /* Три области: меньше опорного, равно, больше. Интервал [left,right). */
    while(right-left>1){
        int pivot=a[left+(right-left)/2],lt=left,i=left,gt=right;
        while(i<gt){
            if(a[i]<pivot)swap(&a[lt++],&a[i++]);
            else if(a[i]>pivot)swap(&a[i],&a[--gt]);
            else ++i;
        }
        /* Рекурсия только в меньшую часть ограничивает глубину стека. */
        if(lt-left<right-gt){quick(a,left,lt);left=gt;}
        else {quick(a,gt,right);right=lt;}
    }
}
int main(void) {
int a[]={4,1,3,2};int n=4;quick(a,0,n);for(int i=0;i<n;++i) printf("%s%d", i?" ":"",a[i]); puts("");
return 0;
}
```

Ожидаемый вывод:

```text
1 2 3 4
```

## Почему реализация корректна

Трёхчастное разбиение поддерживает четыре области: меньше pivot, равно pivot, ещё не исследовано, больше pivot. Если текущий элемент больше pivot, меняем его с концом неизвестной области и уменьшаем её правую границу. Индекс текущего элемента не увеличиваем: на это место приехало ещё не исследованное значение.

На [2,1,2,3,2] весь центральный блок двоек исключается из дальнейшей рекурсии. Значение pivot нужно сохранить отдельно от изменяемого массива. Рекурсивный вызов только для меньшей части ограничивает глубину стека, но не исправляет плохое распределение работы: худшее время остаётся O(n²). Средний элемент по позиции не обязан быть медианой по значению.

## Cache locality и компромиссы

Разбиение работает внутри массива, но обмены и ветвления влияют на фактическую скорость.

Малая дополнительная память против отсутствия стабильности и риска плохих разбиений.

Практическое применение: Сортировка массивов в памяти, изучение partition.

<CommonMistake title="Типичная ошибка">

После обмена a[i] с ещё не изученным правым элементом нельзя без проверки увеличивать i.

</CommonMistake>

## Связь со STL C++

std::sort имеет гарантию O(n log n) сравнений; наивный quicksort с квадратичным худшим случаем не является полным аналогом этой гарантии.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <algorithm>
#include <vector>
int main(){
std::vector<int> a{4,1,3,2};std::sort(a.begin(),a.end());for(std::size_t i=0;i<a.size();++i)std::cout<<(i?" ":"")<<a[i];std::cout<<"\n";
return 0;
}
```

Вывод:

```text
1 2 3 4
```
