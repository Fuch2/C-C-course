## Теория и инвариант

Очередь задаёт FIFO: первым добавлен — первым обслужен. Связная реализация с head и tail добавляет в конец и удаляет из начала без прохода по остальным узлам. Если хранить только head и искать конец при каждом добавлении, enqueue станет O(n).

Удаление последнего узла должно обнулить tail, иначе следующее добавление запишет по освобождённому адресу. Для очереди задач порядок — часть корректности, а не вопрос удобства. Время выделения отдельного узла не обязано быть константным в строгом реальном времени, даже если алгоритмическое число изменений ссылок постоянно. Для такого сценария рассмотрите кольцевой буфер или пул.

## Пошаговый разбор

P 4, P 9, O, P 2, O, O → 4,9,2. После полного опустошения очередью можно пользоваться снова.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

typedef struct Node { int value; struct Node *next; } Node;
typedef struct { Node *head,*tail; } Queue;
static int push(Queue *q,int value){
    Node *node=malloc(sizeof *node);if(!node)return 0;
    *node=(Node){value,NULL};
    if(q->tail)q->tail->next=node;else q->head=node;
    q->tail=node;return 1;
}
static int pop(Queue *q,int *out){
    if(!q->head)return 0;
    Node *old=q->head;*out=old->value;q->head=old->next;
    if(!q->head)q->tail=NULL;
    free(old);return 1;
}
static void destroy(Queue *q){int value;while(pop(q,&value)){} }
int main(void) {
Queue queue={0};if(!push(&queue,4)||!push(&queue,9)){destroy(&queue);return 1;}int x;pop(&queue,&x);printf("%d\n",x);destroy(&queue);
return 0;
}
```

Ожидаемый вывод:

```text
4
```

## Почему реализация корректна

После добавления 4 и 9 head указывает на 4, tail на 9. Извлечение сохраняет значение головы, переносит head на следующий узел и освобождает старый. После извлечения 9 список пуст: tail тоже нужно обнулить. Иначе следующая вставка попробует связать новый узел через уже освобождённый хвост.

FIFO описывает порядок, а не способ хранения. Связная очередь избегает сдвигов, но платит malloc и метаданными узлов. Массивная очередь со сдвигом всего содержимого делает извлечение линейным; кольцевое представление следующего урока устраняет этот сдвиг. В STL адаптер queue обычно использует deque, поэтому нельзя приписывать ему устройство нашего списка.

## Cache locality и компромиссы

Разрозненные узлы проигрывают плотному буферу в локальности и добавляют обращения к allocator.

Рост по потребности против аллокации на каждое добавление.

Практическое применение: Очередь фоновых задач и фронт BFS.

<CommonMistake title="Типичная ошибка">

Нельзя путать очередь с priority_queue: та выбирает по приоритету, а не по времени поступления.

</CommonMistake>

## Связь со STL C++

std::queue обычно использует deque, а не связный список. FIFO-интерфейс совпадает, физическая память может отличаться.

Запускаемый вариант C++20:

```cpp
#include <iostream>
#include <queue>
int main(){
std::queue<int> q;q.push(4);q.push(9);std::cout<<q.front()<<"\n";q.pop();
return 0;
}
```

Вывод:

```text
4
```
