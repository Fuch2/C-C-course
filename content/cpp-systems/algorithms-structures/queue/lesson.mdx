## Первым пришёл — первым ушёл

**Очередь** (queue) устроена как очередь в магазине: новые элементы встают в **конец**, а уходят из **начала**. Порядок — **FIFO**: first in, first out, «первым пришёл — первым ушёл». Стек разворачивает последовательность, очередь сохраняет её порядок.

| Операция     | Что делает                              |
| ------------ | --------------------------------------- |
| `enqueue(x)` | добавить `x` в конец                    |
| `dequeue()`  | удалить элемент из начала и вернуть его |
| `front()`    | посмотреть на первый элемент, не удаляя |

Все три операции должны работать за `O(1)`. Посмотрим, как этого добиться.

## Почему не просто массив

Самая простая идея — массив, где начало очереди — `data[0]`. Добавление в конец дешёвое, но удаление из начала сдвигает все элементы — `O(n)`. Если вместо сдвига хранить индекс начала `head` и просто увеличивать его, удаление станет `O(1)`, но очередь будет «ползти» по массиву вправо: место слева от `head` больше не используется, и массив кончится, хотя элементов в очереди мало. Решение этой проблемы — кольцевой буфер — тема следующего урока. А сейчас — очередь на списке.

## Очередь на односвязном списке

В односвязном списке с указателями на голову и хвост добавление в конец и удаление из начала — обе `O(1)`. Это ровно то, что нужно очереди:

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *next;
} Node;

typedef struct {
    Node *head;     // отсюда уходят
    Node *tail;     // сюда приходят
    int size;
} Queue;

static void enqueue(Queue *q, int value) {
    Node *node = malloc(sizeof *node);
    if (node == NULL) {
        exit(1);
    }
    node->value = value;
    node->next = NULL;
    if (q->tail == NULL) {
        q->head = node;
    } else {
        q->tail->next = node;
    }
    q->tail = node;
    q->size++;
}

static bool dequeue(Queue *q, int *out) {
    if (q->head == NULL) {
        return false;
    }
    Node *node = q->head;
    *out = node->value;
    q->head = node->next;
    if (q->head == NULL) {
        q->tail = NULL;              // очередь опустела — хвоста тоже нет
    }
    free(node);
    q->size--;
    return true;
}

int main(void) {
    Queue q = {NULL, NULL, 0};
    enqueue(&q, 1);
    enqueue(&q, 2);
    enqueue(&q, 3);
    int x;
    dequeue(&q, &x);
    printf("ушёл %d, осталось %d\n", x, q.size);
    enqueue(&q, 4);
    while (dequeue(&q, &x)) {
        printf("%d ", x);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
ушёл 1, осталось 2
2 3 4
```

Самая коварная строка — сброс `tail` при опустошении. Если её забыть, `tail` будет указывать на освобождённый узел, и следующий `enqueue` запишет в него `tail->next = node`.

## Очередь на двух стеках

Красивый приём: очередь можно собрать из двух стеков. В стек `in` элементы кладутся при добавлении. При удалении элементы берутся из стека `out`; если он пуст, в него перекладывается **всё** содержимое `in` — и порядок при этом разворачивается, так что на вершине `out` оказывается самый старый элемент.

```c
#include <stdio.h>

static int in[100], out[100];
static int in_size = 0, out_size = 0;
static int moves = 0;

static void enqueue(int x) {
    in[in_size++] = x;
}

static int dequeue(void) {
    if (out_size == 0) {
        while (in_size > 0) {               // переложить всё, разворачивая
            out[out_size++] = in[--in_size];
            moves++;
        }
    }
    return out[--out_size];
}

int main(void) {
    enqueue(1);
    enqueue(2);
    enqueue(3);
    printf("%d ", dequeue());
    enqueue(4);
    printf("%d ", dequeue());
    printf("%d ", dequeue());
    printf("%d\n", dequeue());
    printf("перекладываний: %d\n", moves);
    return 0;
}
```

Вывод:

```text
1 2 3 4
перекладываний: 4
```

Отдельное удаление может стоить `O(n)` — когда перекладывается весь стек. Но каждый элемент перекладывается **ровно один раз** за всё время жизни в очереди: из `in` в `out`, и обратно уже никогда. Поэтому `n` операций стоят `O(n)`, и удаление работает за амортизированное `O(1)`. Этот приём полезен в языках и системах, где стек есть, а очереди нет, — и как упражнение в амортизированном анализе.

## Где нужны очереди

Очередь появляется всюду, где что-то нужно обработать **в порядке поступления**:

- задания на печать, запросы к серверу, сообщения между программами;
- буферы ввода-вывода: клавиатура, сеть и диск отдают данные в том порядке, в каком они пришли;
- планировщик процессов в операционной системе;
- **поиск в ширину** в графах — в одном из последних уроков модуля.

Пример — моделирование планировщика с **квантом времени** (round-robin): процессы стоят в очереди; первый получает процессор на `q` единиц времени; если не закончил — встаёт в конец очереди.

```c
#include <stdio.h>

int main(void) {
    int need[] = {5, 2, 4};                // сколько времени нужно процессам A, B, C
    int queue[64], head = 0, tail = 0;
    for (int i = 0; i < 3; i++) {
        queue[tail++] = i;
    }
    int quantum = 2, time = 0;
    while (head < tail) {
        int p = queue[head++];
        int run = need[p] < quantum ? need[p] : quantum;
        time += run;
        need[p] -= run;
        if (need[p] > 0) {
            queue[tail++] = p;             // не успел — в конец очереди
        } else {
            printf("%c закончил в момент %d\n", 'A' + p, time);
        }
    }
    return 0;
}
```

Вывод:

```text
B закончил в момент 4
C закончил в момент 10
A закончил в момент 11
```

Здесь очередь «ползёт» по массиву — `head` и `tail` только растут. Для короткой модели это допустимо (массив с запасом), но для бесконечного потока нужен кольцевой буфер.

<Concept title="Очередь">

Структура FIFO: добавление в конец, удаление из начала, обе операции `O(1)`. Реализуется списком с головой и хвостом, кольцевым буфером или двумя стеками (амортизированное `O(1)`). Очередь сохраняет порядок поступления и нужна везде, где данные обрабатываются по мере прихода: буферы, планировщики, обход в ширину.

</Concept>

## Частые ошибки

<CommonMistake title="Хвост после опустошения">

Если удалить последний элемент и не обнулить `tail`, он укажет на освобождённый узел. Следующий `enqueue` выполнит `tail->next = node` — запись в освобождённую память, и новый узел не попадёт в очередь.

</CommonMistake>

<CommonMistake title="Удаление из начала массива сдвигом">

`memmove(data, data + 1, ...)` при каждом `dequeue` делает очередь `O(n)` на операцию. Для очереди на массиве нужен кольцевой буфер.

</CommonMistake>

<CommonMistake title="Перекладывание при непустом out">

В очереди на двух стеках элементы перекладываются, только когда `out` **пуст**. Если перекладывать при каждом удалении, новые элементы окажутся над старыми, и порядок FIFO нарушится.

</CommonMistake>

## Итоги

- Очередь — FIFO: элементы уходят в порядке поступления.
- На списке с головой и хвостом обе операции — `O(1)`; при опустошении хвост обнуляется.
- Удаление из начала массива сдвигом — `O(n)`; правильная очередь на массиве — кольцевой буфер.
- Две стопки дают очередь с амортизированным `O(1)`: каждый элемент перекладывается один раз.
- Очереди лежат в основе буферов, планировщиков и поиска в ширину.
