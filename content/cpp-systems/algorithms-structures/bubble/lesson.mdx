## Цели обучения

- Объяснить инвариант: Крупные элементы всплывают вправо по одному соседнему обмену.
- Обосновать время: Лучший Θ(n) с флагом; средний и худший Θ(n²).
- Оценить память и компромиссы: Простота и стабильность против большого количества обменов.

## Теория и инвариант

Соседние элементы сравниваются и меняются местами, если идут в неправильном порядке. После полного прохода максимум активного префикса оказывается справа. Следующий проход можно завершить раньше, не затрагивая уже зафиксированный суффикс. Флаг changed позволяет остановиться, если обменов не было.

Для стабильности равные элементы не меняют местами: условие строгое >. Это важно для записей с одинаковой температурой и разными временными отметками. Пузырьковая сортировка полезна для изучения инварианта, но число мелких обменов обычно делает её плохим выбором для больших наборов. Проверяйте n=0 до вычислений с беззнаковым n−1.

</Concept>

## Пошаговый разбор

[3,1,2] → [1,3,2] → [1,2,3]; максимум 3 закреплён. Следующий проход не делает обменов.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static void sort(int *a,int n){
    for(int end=n;end>1;--end){
        int changed=0;
        for(int j=1;j<end;++j) if(a[j-1]>a[j]){
            int temp=a[j-1];a[j-1]=a[j];a[j]=temp;changed=1;
        }
        if(!changed) break;
    }
}
int main(void) {
int a[]={4,1,3,2};int n=4;sort(a,n);for(int i=0;i<n;++i) printf("%s%d", i?" ":"",a[i]); puts("");
return 0;
}
```

Ожидаемый вывод:

```text
1 2 3 4
```

## Почему реализация корректна

Для [3,1,2] первое сравнение меняет 3 и 1, второе — 3 и 2; после прохода максимум 3 закреплён в конце. Следующий проход рассматривает только [1,2] и не делает обменов. Флаг changed позволяет завершить работу, потому что все соседние пары уже упорядочены.

Инвариант внешнего цикла: суффикс за текущей границей содержит самые большие значения на окончательных местах. Сравнение строго через > сохраняет взаимный порядок равных ключей. Если использовать >=, лишние обмены потеряют стабильность и испортят ранний выход на одинаковых данных. Даже с флагом обратный порядок остаётся квадратичным.
