## Зачем сортировать

**Сортировка** — расположение элементов по порядку: чисел по возрастанию, слов по алфавиту, записей по дате. Отсортированные данные удобнее не только людям. В прошлом уроке двоичный поиск искал в миллиарде элементов за 30 сравнений — но только в отсортированном массиве. После сортировки одинаковые элементы стоят рядом, и повторы находятся одним проходом; медиана — это просто средний элемент.

Следующие уроки разбирают пять алгоритмов сортировки — от простых квадратичных до быстрых `O(n log n)`. Простые стоит знать не только ради истории: на них видны идеи, которые есть во всех сортировках, а на коротких массивах они работают быстрее сложных.

Массив **отсортирован по неубыванию**, если каждый элемент не больше следующего. Это легко проверить одним проходом:

```c
#include <stdio.h>

static bool is_sorted(const int *values, int n) {
    for (int i = 0; i + 1 < n; i++) {
        if (values[i] > values[i + 1]) {
            return false;
        }
    }
    return true;
}

int main(void) {
    int a[] = {1, 2, 2, 5}, b[] = {1, 3, 2};
    printf("%d %d\n", is_sorted(a, 4), is_sorted(b, 3));
    return 0;
}
```

Вывод:

```text
1 0
```

Условие `i + 1 < n` вместо `i < n − 1` верно и для пустого массива — и не ломается, если `n` беззнаковое.

## Идея пузырька

Пройдём по массиву и сравним каждую пару **соседей**. Если они стоят не по порядку — поменяем местами. После такого прохода наибольший элемент окажется в конце: на каждом сравнении он «всплывает» на одну позицию, как пузырёк. Повторим проход для оставшихся элементов — на предпоследнем месте окажется второй по величине. И так далее.

```c
#include <stdio.h>

static void print(const int *values, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
}

int main(void) {
    int values[] = {5, 1, 4, 2, 8};
    int n = 5;
    for (int pass = 0; pass < n - 1; pass++) {
        for (int j = 0; j < n - 1 - pass; j++) {
            if (values[j] > values[j + 1]) {
                int tmp = values[j];
                values[j] = values[j + 1];
                values[j + 1] = tmp;
            }
        }
        printf("проход %d: ", pass + 1);
        print(values, n);
    }
    return 0;
}
```

Вывод:

```text
проход 1: 1 4 2 5 8
проход 2: 1 2 4 5 8
проход 3: 1 2 4 5 8
проход 4: 1 2 4 5 8
```

Внутренний цикл с каждым проходом короче на единицу: `j < n − 1 − pass`. Последние `pass` элементов уже на своих местах, сравнивать их не нужно.

**Инвариант:** после `k` проходов последние `k` элементов массива — это `k` наибольших элементов, и стоят они в правильном порядке. Через `n − 1` проходов на месте все элементы, кроме первого, — а значит, и он.

## Ранняя остановка

В примере массив был отсортирован уже после второго прохода, а программа сделала ещё два впустую. Если за проход не случилось ни одного обмена, все соседи стоят по порядку — массив отсортирован, и можно остановиться:

```c
#include <stdio.h>

static int bubble_sort(int *values, int n) {
    int passes = 0;
    for (int pass = 0; pass < n - 1; pass++) {
        bool swapped = false;
        for (int j = 0; j < n - 1 - pass; j++) {
            if (values[j] > values[j + 1]) {
                int tmp = values[j];
                values[j] = values[j + 1];
                values[j + 1] = tmp;
                swapped = true;
            }
        }
        passes++;
        if (!swapped) {
            break;
        }
    }
    return passes;
}

int main(void) {
    int a[] = {5, 1, 4, 2, 8};
    int sorted[] = {1, 2, 3, 4, 5};
    int reversed[] = {5, 4, 3, 2, 1};
    printf("%d %d %d\n", bubble_sort(a, 5), bubble_sort(sorted, 5), bubble_sort(reversed, 5));
    return 0;
}
```

Вывод:

```text
3 1 4
```

Третий проход первого массива — проверочный: обменов не было, значит, готово. Отсортированный массив проверяется за один проход — `O(n)`. Массив в обратном порядке требует всех `n − 1` проходов.

## Сколько это стоит

| Вход               | Сравнений         | Обменов        |
| ------------------ | ----------------- | -------------- |
| уже отсортирован   | `n − 1`           | 0              |
| в обратном порядке | `n(n − 1) / 2`    | `n(n − 1) / 2` |
| в общем случае     | до `n(n − 1) / 2` | число инверсий |

Каждый обмен соседей исправляет ровно **одну инверсию** — пару, стоящую не по порядку (урок о квадратичной сложности). Поэтому число обменов пузырька точно равно числу инверсий массива, а в среднем это около `n² / 4`. Пузырьковая сортировка — `O(n²)` в худшем и среднем случае, `O(n)` в лучшем, и `O(1)` дополнительной памяти: она сортирует **на месте**.

## Устойчивость

Пусть сортируются не числа, а записи — например, заказы по сумме. Сортировка называется **устойчивой**, если записи с равными ключами сохраняют исходный взаимный порядок. Это важно, когда сортируют в несколько приёмов: отсортировав заказы сначала по дате, а затем устойчиво по сумме, получим заказы с одинаковой суммой — по дате.

Пузырёк устойчив, потому что меняет соседей только при **строгом** неравенстве: равные элементы никогда не обгоняют друг друга.

```c
#include <stdio.h>

typedef struct {
    int amount;
    char label;
} Order;

int main(void) {
    Order orders[] = {{300, 'a'}, {100, 'b'}, {300, 'c'}, {100, 'd'}, {200, 'e'}};
    int n = 5;
    for (int pass = 0; pass < n - 1; pass++) {
        for (int j = 0; j < n - 1 - pass; j++) {
            if (orders[j].amount > orders[j + 1].amount) {     // строго больше
                Order tmp = orders[j];
                orders[j] = orders[j + 1];
                orders[j + 1] = tmp;
            }
        }
    }
    for (int i = 0; i < n; i++) {
        printf("%d%c ", orders[i].amount, orders[i].label);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
100b 100d 200e 300a 300c
```

`b` раньше `d`, `a` раньше `c` — как во входе. С условием `>=` равные элементы менялись бы местами, и сортировка перестала бы быть устойчивой. Структуры можно присваивать целиком (`Order tmp = orders[j]`) — это копирует все поля.

## Порядок по своему правилу

Чтобы сортировать по убыванию или по нескольким полям, вынесите сравнение в функцию: «должен ли `a` стоять после `b`?». Сортировка останется той же, изменится только условие обмена.

```c
#include <stdio.h>

// Должно ли x стоять после y: по убыванию последней цифры, при равенстве — по возрастанию числа.
static bool after(int x, int y) {
    if (x % 10 != y % 10) {
        return x % 10 < y % 10;
    }
    return x > y;
}

int main(void) {
    int values[] = {21, 39, 13, 49, 9, 11};
    int n = 6;
    for (int pass = 0; pass < n - 1; pass++) {
        for (int j = 0; j < n - 1 - pass; j++) {
            if (after(values[j], values[j + 1])) {
                int tmp = values[j];
                values[j] = values[j + 1];
                values[j + 1] = tmp;
            }
        }
    }
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
9 39 49 13 11 21
```

Так же устроены функции сравнения для `qsort`, которые вы видели в модуле о памяти.

<Concept title="Пузырьковая сортировка">

Проходы по массиву с обменом соседей, стоящих не по порядку. После `k` проходов `k` наибольших элементов стоят в конце на своих местах. `O(n²)` сравнений в худшем случае, `O(n)` с ранней остановкой на отсортированном массиве; число обменов равно числу инверсий; сортирует на месте и устойчиво. На практике применяется редко, но идеи — обмен соседей, инвариант «хвост готов», ранняя остановка — встречаются везде.

</Concept>

## Частые ошибки

<CommonMistake title="Выход за массив при сравнении соседей">

```c
for (int j = 0; j < n - pass; j++) {
    if (values[j] > values[j + 1]) ...   // при j = n − 1 читается values[n]
}
```

Пара `(j, j + 1)` существует, пока `j + 1 < n`. Граница внутреннего цикла — `n − 1 − pass`.

</CommonMistake>

<CommonMistake title="Нестрогое сравнение">

Условие `values[j] >= values[j + 1]` сортирует правильно, но делает лишние обмены равных элементов и ломает устойчивость. Для записей это меняет результат.

</CommonMistake>

<CommonMistake title="Флаг вне прохода">

Флаг `swapped` нужно сбрасывать в `false` **в начале каждого прохода**. Если объявить его один раз до внешнего цикла, после первого же обмена ранняя остановка никогда не сработает.

</CommonMistake>

## Практика

1. **Проходы пузырька** — состояние массива после каждого прохода.
2. **Число обменов** — обмены равны инверсиям.
3. **Найди ошибку: сравнение соседей** — выход за границу массива.
4. **Турнирная таблица** — сортировка записей по нескольким ключам.

## Итоги

- Пузырёк сравнивает соседей и меняет их, если они стоят не по порядку; после `k` проходов `k` наибольших элементов на месте.
- Ранняя остановка: проход без обменов означает, что массив отсортирован.
- `O(n²)` в худшем и среднем случае, `O(n)` в лучшем, `O(1)` памяти.
- Каждый обмен соседей исправляет одну инверсию.
- Устойчивая сортировка сохраняет порядок равных элементов; пузырёк устойчив при строгом сравнении.
- Порядок по своему правилу — функция «должен ли `a` стоять после `b`».
