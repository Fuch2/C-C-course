## Задача поиска

**Поиск** — одна из самых частых задач в программировании: найти в наборе данных элемент с нужным значением или свойством. Есть ли пользователь с таким именем? Где в тексте первая точка? Встречалось ли это число раньше?

Если про данные ничего не известно — они не отсортированы и не разложены в специальную структуру, — остаётся один способ: просмотреть элементы по очереди. Это **линейный поиск**.

## Функция поиска

Оформим поиск функцией, которая возвращает индекс первого вхождения или `-1`, если элемента нет:

```c
#include <stdio.h>

static int find(const int *values, int n, int target) {
    for (int i = 0; i < n; i++) {
        if (values[i] == target) {
            return i;                // нашли — дальше смотреть не нужно
        }
    }
    return -1;                       // просмотрели всё — элемента нет
}

int main(void) {
    int values[] = {4, 8, 15, 16, 23, 42, 15};
    printf("%d %d %d\n", find(values, 7, 15), find(values, 7, 42), find(values, 7, 5));
    return 0;
}
```

Вывод:

```text
2 5 -1
```

Несколько деталей, которые стоит запомнить:

- `const int *` обещает, что функция не изменит массив;
- `return` внутри цикла сразу заканчивает поиск — это **ранний выход**;
- `-1` — значение, которое не может быть индексом, поэтому им удобно обозначать «не найдено»;
- `return -1` стоит **после** цикла: только просмотрев все элементы, можно утверждать, что элемента нет.

Инвариант цикла: перед итерацией `i` среди `values[0…i − 1]` нет `target`. Поэтому, если цикл закончился, `target` нет нигде, а найденное вхождение — первое.

## Варианты поиска

Тот же цикл решает много похожих задач — меняются только условие и направление.

```c
#include <stdio.h>

static int find_last(const int *values, int n, int target) {
    for (int i = n - 1; i >= 0; i--) {         // идём с конца
        if (values[i] == target) {
            return i;
        }
    }
    return -1;
}

static int count(const int *values, int n, int target) {
    int result = 0;
    for (int i = 0; i < n; i++) {
        if (values[i] == target) {
            result++;                          // не выходим — считаем все
        }
    }
    return result;
}

static int find_first_negative(const int *values, int n) {
    for (int i = 0; i < n; i++) {
        if (values[i] < 0) {                   // поиск по условию
            return i;
        }
    }
    return -1;
}

int main(void) {
    int values[] = {3, 7, -2, 7, 0, -5, 7};
    printf("последняя 7: %d\n", find_last(values, 7, 7));
    printf("семёрок: %d\n", count(values, 7, 7));
    printf("первое отрицательное: %d\n", find_first_negative(values, 7));
    return 0;
}
```

Вывод:

```text
последняя 7: 6
семёрок: 3
первое отрицательное: 2
```

Стандартные функции `strchr` (символ в строке) и `memchr` (байт в блоке памяти) — тоже линейный поиск.

## Поиск записи по ключу

Чаще ищут не число, а **запись** — структуру, у которой одно из полей служит ключом:

```c
#include <stdio.h>
#include <string.h>

typedef struct {
    const char *name;
    int score;
} Student;

static const Student *find_student(const Student *students, int n, const char *name) {
    for (int i = 0; i < n; i++) {
        if (strcmp(students[i].name, name) == 0) {
            return &students[i];
        }
    }
    return NULL;
}

int main(void) {
    Student group[] = {{"Аня", 91}, {"Борис", 78}, {"Вера", 85}};
    const Student *s = find_student(group, 3, "Вера");
    if (s != NULL) {
        printf("%s: %d\n", s->name, s->score);
    }
    if (find_student(group, 3, "Глеб") == NULL) {
        printf("Глеб не найден\n");
    }
    return 0;
}
```

Вывод:

```text
Вера: 85
Глеб не найден
```

Функция возвращает указатель на найденную запись, а «не найдено» обозначает `NULL`. Строки сравниваются `strcmp`, а не `==`: оператор `==` сравнил бы адреса, а не содержимое.

## Сложность

| Случай                  | Сравнений     |
| ----------------------- | ------------- |
| элемент первый          | 1             |
| элемент на позиции `k`  | `k + 1`       |
| элемента нет            | `n`           |
| в среднем, если он есть | около `n / 2` |

Худший случай — `O(n)`. Для одного запроса к неотсортированным данным лучше не бывает: любой элемент, который мы не посмотрели, может оказаться искомым. Но если запросов много, выгоднее один раз отсортировать данные (`O(n log n)`), а потом искать двоичным поиском за `O(log n)` — об этом следующий урок.

## Поиск с барьером

В обычном цикле на каждой итерации **две** проверки: `i < n` и `values[i] == target`. Классический приём убирает первую: в конец массива записывают сам искомый элемент — **барьер** (sentinel). Тогда цикл гарантированно остановится, и проверять границу не нужно:

```c
#include <stdio.h>

static int find_sentinel(int *values, int n, int target) {
    int last = values[n - 1];
    values[n - 1] = target;              // барьер
    int i = 0;
    while (values[i] != target) {
        i++;
    }
    values[n - 1] = last;                // вернуть массив как был
    if (i < n - 1 || last == target) {
        return i;
    }
    return -1;
}

int main(void) {
    int values[] = {5, 1, 9, 3};
    printf("%d %d %d\n", find_sentinel(values, 4, 9), find_sentinel(values, 4, 3),
           find_sentinel(values, 4, 7));
    return 0;
}
```

Вывод:

```text
2 3 -1
```

После цикла нужно понять, нашли ли мы настоящий элемент или барьер. Если `i < n − 1` — настоящий. Если `i == n − 1`, цикл дошёл до барьера, и ответ зависит от того, что стояло там **до** подмены. Сложность прежняя — `O(n)`, выигрыш — в константе. Современные компиляторы часто оптимизируют обычный цикл не хуже, так что приём важнее как пример рассуждения об инвариантах, чем как ускорение.

<Concept title="Линейный поиск">

Просмотр элементов по очереди до первого подходящего. Работает на любых данных, не требует подготовки и дополнительной памяти, но в худшем случае просматривает все `n` элементов. Инвариант: среди уже просмотренных элементов искомого нет — поэтому найденное вхождение первое, а «не найдено» можно сказать только после конца цикла.

</Concept>

## Частые ошибки

<CommonMistake title="«Не найдено» внутри цикла">

```c
for (int i = 0; i < n; i++) {
    if (values[i] == target) return i;
    else return -1;          // ошибка: решение по первому элементу
}
```

Функция смотрит только на первый элемент. Вывод «элемента нет» можно сделать только после того, как просмотрены все.

</CommonMistake>

<CommonMistake title="Сравнение строк через ==">

`students[i].name == name` сравнивает адреса. Две одинаковые строки в разных местах памяти окажутся «разными». Используйте `strcmp(a, b) == 0`.

</CommonMistake>

<CommonMistake title="Выход за границу при поиске с конца">

Цикл `for (size_t i = n - 1; i >= 0; i--)` бесконечен: беззнаковый `i` всегда `>= 0`, а после нуля он становится огромным числом. Для обратного цикла используйте `int` или условие `i-- > 0`.

</CommonMistake>

## Практика

1. **Первое и последнее вхождение** — два варианта поиска.
2. **Поиск по имени** — записи и `strcmp`.
3. **Найди ошибку: поиск с барьером** — проверка после цикла.
4. **Перемещение в начало** — ускорение частых запросов.

## Итоги

- Линейный поиск просматривает элементы по очереди; ранний выход — при первом совпадении.
- «Не найдено» — только после окончания цикла.
- Меняя условие и направление, получаем поиск последнего, подсчёт и поиск по условию.
- Записи ищут по ключу; строки сравнивают `strcmp`.
- Худший случай — `O(n)`; для одного запроса к неупорядоченным данным это оптимально.
- Барьер убирает проверку границы, но требует аккуратной проверки после цикла.
