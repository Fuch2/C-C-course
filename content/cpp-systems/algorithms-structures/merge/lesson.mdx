## Слияние двух отсортированных массивов

Начнём с задачи попроще. Есть две **уже отсортированные** стопки карточек; нужно сложить их в одну отсортированную. Достаточно смотреть на верхние карточки двух стопок и каждый раз забирать меньшую. Это **слияние** (merge), и работает оно за один проход — `O(n + m)`:

```c
#include <stdio.h>

int main(void) {
    int a[] = {1, 4, 7, 9}, b[] = {2, 3, 7, 10, 12};
    int n = 4, m = 5;
    int result[9];
    int i = 0, j = 0, k = 0;
    while (i < n && j < m) {
        if (a[i] <= b[j]) {
            result[k++] = a[i++];
        } else {
            result[k++] = b[j++];
        }
    }
    while (i < n) {
        result[k++] = a[i++];          // остаток первого массива
    }
    while (j < m) {
        result[k++] = b[j++];          // остаток второго
    }
    for (int t = 0; t < k; t++) {
        printf("%d ", result[t]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1 2 3 4 7 7 9 10 12
```

Когда один массив кончился, остаток другого просто дописывается: он отсортирован и не меньше всего, что уже в результате. Про эти два «хвостовых» цикла легко забыть — и потерять элементы.

**Инвариант:** `result[0…k − 1]` — это `k` наименьших элементов обоих массивов, отсортированные; `a[i]` и `b[j]` — наименьшие из ещё не взятых.

## Сортировка слиянием

Теперь — рекурсия. Чтобы отсортировать массив:

1. Если в нём меньше двух элементов, он уже отсортирован (базовый случай).
2. Разделить его пополам.
3. Рекурсивно отсортировать каждую половину.
4. Слить две отсортированные половины.

```c
#include <stdio.h>
#include <stdlib.h>

static void merge_sort(int *values, int *tmp, int lo, int hi) {     // [lo, hi)
    if (hi - lo < 2) {
        return;
    }
    int mid = lo + (hi - lo) / 2;
    merge_sort(values, tmp, lo, mid);
    merge_sort(values, tmp, mid, hi);
    int i = lo, j = mid, k = lo;
    while (i < mid && j < hi) {
        tmp[k++] = values[i] <= values[j] ? values[i++] : values[j++];
    }
    while (i < mid) {
        tmp[k++] = values[i++];
    }
    while (j < hi) {
        tmp[k++] = values[j++];
    }
    for (k = lo; k < hi; k++) {
        values[k] = tmp[k];
    }
}

int main(void) {
    int values[] = {38, 27, 43, 3, 9, 82, 10};
    int n = 7;
    int *tmp = malloc((size_t)n * sizeof *tmp);
    if (tmp == NULL) {
        return 1;
    }
    merge_sort(values, tmp, 0, n);
    free(tmp);
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
3 9 10 27 38 43 82
```

Вспомогательный массив `tmp` выделяется **один раз** и передаётся во все вызовы: слияние пишет результат в `tmp`, а затем копирует его обратно. Выделять буфер в каждом вызове было бы медленно.

Дерево вызовов для `38 27 43 3 9 82 10`:

```text
             [38 27 43 3 9 82 10]
          [38 27 43]        [3 9 82 10]
        [38]  [27 43]      [3 9]   [82 10]
             [27] [43]    [3] [9]  [82] [10]
слияния снизу вверх:
             [27 43]       [3 9]    [10 82]
        [27 38 43]          [3 9 10 82]
             [3 9 10 27 38 43 82]
```

## Почему O(n log n)

Посмотрите на дерево по уровням. На каждом уровне массив разбит на куски, и **все слияния уровня вместе** обрабатывают каждый элемент один раз — `O(n)` работы на уровень. Уровней столько, сколько раз можно поделить `n` пополам, — `log₂ n`. Итого `O(n log n)`.

| `n`   | `n²` (вставки, худший случай) | `n log₂ n` (слияние) |
| ----- | ----------------------------- | -------------------- |
| 1 000 | 10⁶                           | ≈ 10⁴                |
| 10⁶   | 10¹²                          | ≈ 2 · 10⁷            |

Миллион элементов: часы против долей секунды. И это гарантия для **любого** входа — у сортировки слиянием нет плохих случаев, она всегда делит ровно пополам.

## Свойства

- **Устойчива**, если при равенстве брать элемент из левой половины: условие `values[i] <= values[j]`. С `<` равные элементы правой половины обгоняли бы левые.
- Требует **`O(n)` дополнительной памяти** под буфер — это её главный недостаток по сравнению с сортировками на месте.
- Читает и пишет данные **последовательно**. Поэтому слиянием сортируют данные, которые не помещаются в память: куски сортируют по отдельности, записывают в файлы и сливают. Связные списки тоже удобно сортировать слиянием: там буфер не нужен.
- Рекурсия глубиной `log₂ n` — безопасна: для миллиона элементов это 20 кадров.

В стандартной библиотеке C++ (модуль «Основы C++») устойчивую сортировку даёт `std::stable_sort` — обычно это сортировка слиянием:

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::pair<int, std::string>> orders{{300, "a"}, {100, "b"}, {300, "c"}, {100, "d"}};
    std::stable_sort(orders.begin(), orders.end(),
                     [](const auto &x, const auto &y) { return x.first < y.first; });
    for (const auto &[amount, label] : orders) {
        std::cout << amount << label << ' ';
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
100b 100d 300a 300c
```

<Concept title="Сортировка слиянием">

Разделить массив пополам, рекурсивно отсортировать половины и слить их за линейное время. Глубина рекурсии `log₂ n`, на каждом уровне `O(n)` работы — `O(n log n)` на любом входе. Устойчива при слиянии с `<=`, требует `O(n)` дополнительной памяти, обращается к данным последовательно — подходит для списков и данных на диске.

</Concept>

## Частые ошибки

<CommonMistake title="Забытый хвост">

После основного цикла слияния в одной из половин остаются элементы. Без циклов `while (i < mid)` и `while (j < hi)` они не попадут в буфер, а при копировании обратно на их место запишется мусор из `tmp`.

</CommonMistake>

<CommonMistake title="Деление, которое не уменьшает задачу">

С отрезками `[lo, mid]` и `[mid + 1, hi]` (включительно) и базовым случаем `lo == hi` всё работает. Но если смешать стили — полуинтервал `[lo, hi)` и вызов `merge_sort(lo, mid + 1)` — на отрезке из двух элементов половина совпадёт с целым, и рекурсия станет бесконечной. Выберите одно соглашение о границах и придерживайтесь его.

</CommonMistake>

<CommonMistake title="Буфер в каждом вызове">

`malloc` внутри рекурсивной функции выполняется `O(n)` раз и заметно замедляет сортировку; забытый `free` при этом даёт утечку на каждом вызове. Выделите буфер один раз снаружи.

</CommonMistake>

## Итоги

- Слияние двух отсортированных массивов — один проход, `O(n + m)`; не забудьте хвосты.
- Сортировка слиянием: половины сортируются рекурсивно и сливаются.
- `log₂ n` уровней по `O(n)` — `O(n log n)` на любом входе.
- Устойчива при `<=`; требует `O(n)` памяти под буфер, выделенный один раз.
- Последовательный доступ делает слияние основой внешней сортировки и сортировки списков.
