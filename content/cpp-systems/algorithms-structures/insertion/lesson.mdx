## Идея

Так сортируют карты в руке: берут очередную карту и вставляют её на своё место среди уже упорядоченных — сдвигая те, что больше, вправо. **Сортировка вставками** (insertion sort) делает то же с массивом: левая часть всегда отсортирована, а очередной элемент вставляется в неё.

```c
#include <stdio.h>

static void print(const int *values, int n) {
    for (int i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
}

int main(void) {
    int values[] = {12, 11, 13, 5, 6};
    int n = 5;
    for (int i = 1; i < n; i++) {
        int key = values[i];                   // элемент, который вставляем
        int j = i - 1;
        while (j >= 0 && values[j] > key) {
            values[j + 1] = values[j];         // сдвиг вправо
            j--;
        }
        values[j + 1] = key;                   // вставка на освободившееся место
        printf("вставили %2d: ", key);
        print(values, n);
    }
    return 0;
}
```

Вывод:

```text
вставили 11: 11 12 13 5 6
вставили 13: 11 12 13 5 6
вставили  5: 5 11 12 13 6
вставили  6: 5 6 11 12 13
```

Обратите внимание: элементы не **обмениваются**, а **сдвигаются**. `key` сохранён в переменной, поэтому его ячейку можно затереть сдвигом, а потом записать `key` один раз — туда, где сдвиги остановились. Обмен потребовал бы трёх присваиваний на шаг, сдвиг — одного.

**Инвариант:** перед шагом `i` элементы `values[0…i − 1]` — это исходные первые `i` элементов, отсортированные. В отличие от выбора, они **не обязательно наименьшие**: `5` пришло на шаге 3 и встало в самое начало.

## Порядок условий в цикле

Условие `j >= 0 && values[j] > key` проверяется слева направо, и **порядок важен**. Когда ключ меньше всех элементов, `j` уменьшается до `−1`; первое условие становится ложным, и благодаря сокращённому вычислению `&&` второе — `values[-1]` — уже не вычисляется. Если поменять условия местами, программа прочитает элемент перед началом массива. AddressSanitizer сообщит об этом как о `buffer-underflow` — переполнении в обратную сторону.

## Адаптивность

Сколько работы делает сортировка вставками, зависит от данных:

- на **отсортированном** массиве цикл `while` на каждом шаге сразу останавливается — `n − 1` сравнение, ни одного сдвига, `O(n)`;
- на массиве **в обратном порядке** каждый элемент сдвигается в самое начало — `n(n − 1)/2` сдвигов, `O(n²)`;
- в общем случае сдвигов ровно столько, сколько **инверсий**: каждый сдвиг ставит `key` перед одним большим элементом и исправляет одну инверсию.

Сортировку, которая работает тем быстрее, чем ближе данные к отсортированным, называют **адаптивной**. Почти отсортированный массив — частый случай на практике: журнал, где записи приходят почти по времени, таблица, в которую добавили несколько строк.

```c
#include <stdio.h>

static long long shifts;

static void insertion_sort(int *values, int n) {
    for (int i = 1; i < n; i++) {
        int key = values[i];
        int j = i - 1;
        while (j >= 0 && values[j] > key) {
            values[j + 1] = values[j];
            shifts++;
            j--;
        }
        values[j + 1] = key;
    }
}

int main(void) {
    enum { N = 1000 };
    static int sorted[N], nearly[N], reversed[N];
    for (int i = 0; i < N; i++) {
        sorted[i] = i;
        nearly[i] = i;
        reversed[i] = N - i;
    }
    for (int i = 0; i + 1 < N; i += 100) {    // 10 соседних обменов
        int t = nearly[i];
        nearly[i] = nearly[i + 1];
        nearly[i + 1] = t;
    }
    shifts = 0; insertion_sort(sorted, N);   printf("отсортированный: %lld\n", shifts);
    shifts = 0; insertion_sort(nearly, N);   printf("почти:           %lld\n", shifts);
    shifts = 0; insertion_sort(reversed, N); printf("обратный:        %lld\n", shifts);
    return 0;
}
```

Вывод:

```text
отсортированный: 0
почти:           10
обратный:        499500
```

## Устойчивость и сортировка «на лету»

Сортировка вставками **устойчива**: элемент сдвигается только мимо строго больших (`values[j] > key`), поэтому равные элементы сохраняют порядок.

Кроме того, ей не нужно знать все данные заранее: она обрабатывает элементы по одному, слева направо. Такие алгоритмы называют **онлайновыми**. Если числа приходят по одному — например, с датчика, — после каждого числа массив уже отсортирован.

## Где она используется

Асимптотически сортировка вставками проигрывает быстрым алгоритмам, но на **коротких** массивах она быстрее их: маленькая константа, нет рекурсии, последовательный доступ к памяти. Поэтому библиотечные сортировки — `std::sort` в C++, Timsort в Python и Java — сортируют короткие участки (обычно до 16–32 элементов) вставками.

| Свойство                     | Вставки          |
| ---------------------------- | ---------------- |
| худший и средний случай      | `O(n²)`          |
| лучший случай (отсортирован) | `O(n)`           |
| сдвигов                      | число инверсий   |
| память                       | `O(1)`, на месте |
| устойчивость                 | да               |
| онлайновая                   | да               |

<Concept title="Сортировка вставками">

Левая часть массива всегда отсортирована; очередной элемент сохраняется, большие элементы сдвигаются вправо, и он вставляется в освободившееся место. Число сдвигов равно числу инверсий, поэтому на почти отсортированных данных сортировка близка к линейной. Устойчива, онлайнова, работает на месте и быстрее всех на коротких массивах.

</Concept>

## Частые ошибки

<CommonMistake title="Условия в неверном порядке">

```c
while (values[j] > key && j >= 0) { ... }   // values[-1] при j = −1
```

`&&` вычисляет условия слева направо и останавливается на первом ложном. Проверка границы должна стоять первой — тогда обращение к массиву происходит только с допустимым индексом.

</CommonMistake>

<CommonMistake title="Потерянный ключ">

Если не сохранить `values[i]` в `key` до сдвигов, первый же сдвиг `values[i] = values[i − 1]` затрёт его. Сохраните элемент, освободите место, запишите обратно.

</CommonMistake>

<CommonMistake title="Вставка на j вместо j + 1">

После цикла `j` указывает на элемент, который **не больше** `key` (или равен `−1`). Ключ встаёт правее него — на `j + 1`.

</CommonMistake>

## Итоги

- Сортировка вставками вставляет очередной элемент в отсортированную левую часть, сдвигая большие вправо.
- Сдвиг дешевле обмена: ключ сохраняется и записывается один раз.
- Проверка `j >= 0` стоит в условии первой.
- Сдвигов столько, сколько инверсий: `O(n)` на отсортированном, `O(n²)` на обратном массиве.
- Устойчива, онлайнова, на месте; используется внутри библиотечных сортировок для коротких участков.
