- Оценить память и компромиссы: Хороша для малых и почти отсортированных данных; плохо масштабируется на обратном порядке.

## Теория и инвариант

Перед шагом i префикс [0,i) отсортирован. Сохраняем a[i] во временную переменную, сдвигаем большие элементы вправо и вставляем значение в освободившееся место. Сохранение необходимо: первый сдвиг может затереть исходное значение. Условие j>0 проверяется раньше доступа a[j−1].

Число сдвигов равно числу инверсий — пар, стоящих в неправильном порядке. Поэтому почти отсортированный массив обрабатывается значительно быстрее обратного. Строгое сравнение > сохраняет порядок равных ключей. Эта сортировка часто полезна для маленьких блоков внутри более сложного алгоритма, но её адаптивность не отменяет квадратичный худший случай.

## Пошаговый разбор

[2,5,3] сохраняем 3, сдвигаем 5: [2,5,5], затем пишем 3: [2,3,5].

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

static void sort(int *a,int n){
    for(int i=1;i<n;++i){
        int value=a[i],j=i;
        while(j>0 && a[j-1]>value){a[j]=a[j-1];--j;}
        a[j]=value;
    }
}
int main(void) {
int a[]={4,1,3,2};int n=4;sort(a,n);for(int i=0;i<n;++i) printf("%s%d", i?" ":"",a[i]); puts("");
return 0;
}
```

Ожидаемый вывод:

```text
1 2 3 4
```

## Почему реализация корректна

Перед вставкой очередного key префикс уже отсортирован. Для [3,1,2] сохраняем 1 во временной переменной, сдвигаем 3 вправо и помещаем 1 в освободившуюся позицию. Затем сохраняем 2, сдвигаем 3, останавливаемся на 1 и вставляем 2. Временная переменная нужна, иначе первый сдвиг уничтожит вставляемое значение.

Условие j>0 проверяется до обращения к a[j−1]. Строгое > не переносит ключ через равные элементы, сохраняя стабильность. В benchmark различайте сравнение ключей, сдвиг и финальную запись key: это три разных события. Отсортированный вход требует линейного числа проверок, обратный — суммы длин растущих префиксов.

## Cache locality и компромиссы

Сдвиги идут по соседним адресам, что удобно для кеша на небольших массивах.

Хороша для малых и почти отсортированных данных; плохо масштабируется на обратном порядке.

Практическое применение: Досортировка небольшой очереди событий.

<CommonMistake title="Типичная ошибка">

Обратный порядок из n элементов содержит n(n−1)/2 инверсий; случайный вход не заменяет этот тест.

</CommonMistake>

## Связь со STL C++

Стандарт не требует insertion sort внутри std::sort, хотя реализации могут применять её для малых частей.

## Benchmark-задача

Ввод n (0…256) и n int −1000…1000. Выполните insertion sort. Считайте каждое вычисление a[j−1]>value (включая последнее ложное, но не проверку j>0) и каждый сдвиг a[j]=a[j−1]. Запись сохранённого value не является сдвигом. Выведите сравнения и сдвиги.

Выберите «Benchmark: сравнения и сдвиги вставок» среди заданий во вкладке «Практика». Сравните отсортированный, обратный, пустой и обычный вход там, где они применимы. Счётчик отвечает на вопрос об объёме работы; секунды зависят от машины и сборки.

Для отдельного эксперимента со временем подготовьте одинаковые входы до начала замера. Используйте clock() вокруг исследуемой операции, проверяйте результат на (clock_t)-1 и делите разницу на CLOCKS_PER_SEC с преобразованием к double. Выведите контрольную сумму результата, чтобы компилятор не мог просто удалить неиспользуемую работу. Короткую операцию повторяйте в пределах timeout: нулевой отсчёт может означать недостаточное разрешение часов.

Сделайте прогрев и несколько замеров с переменой порядка вариантов. Сравните медианы и разброс, запишите компилятор и режим сборки. Диагностику ASan/UBSan проверяйте отдельно: её накладные расходы искажают сравнение обычных реализаций. Поле времени всего запуска в интерфейсе не заменяет время операции. Никакое фиксированное ускорение не требуется для зачёта.
