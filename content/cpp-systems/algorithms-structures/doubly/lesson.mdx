## Ссылки в обе стороны

У односвязного списка две слабости: по нему нельзя идти назад, и чтобы удалить узел, нужно знать **предыдущий** — а его приходится искать от головы. **Двусвязный список** (doubly linked list) хранит в каждом узле два указателя: на следующий и на предыдущий.

```c
typedef struct Node {
    int value;
    struct Node *prev;
    struct Node *next;
} Node;
```

```text
NULL ← [3] ⇄ [7] ⇄ [1] → NULL
```

Теперь узел можно удалить за `O(1)`, зная только его самого: соседи доступны через `prev` и `next`.

## Фиктивный узел

Код двусвязного списка полон особых случаев: пустой список, удаление головы, удаление хвоста, единственный узел — и в каждом свои `NULL`-проверки. Их все убирает **фиктивный узел** (sentinel, «страж»): служебный узел без данных, замкнутый в кольцо со всеми остальными. Его `next` — первый узел, `prev` — последний. Пустой список — это страж, указывающий сам на себя.

```text
пустой:      ┌→ [страж] ─┐
             └───────────┘

три узла:  [страж] ⇄ [3] ⇄ [7] ⇄ [1] ⇄ (снова страж)
```

У каждого настоящего узла теперь **всегда** есть оба соседа — может быть, страж. Поэтому вставка и удаление записываются без единого `if`:

```c
#include <stdio.h>
#include <stdlib.h>

typedef struct Node {
    int value;
    struct Node *prev;
    struct Node *next;
} Node;

static void list_init(Node *sentinel) {
    sentinel->prev = sentinel;
    sentinel->next = sentinel;
}

static Node *insert_after(Node *where, int value) {
    Node *node = malloc(sizeof *node);
    if (node == NULL) {
        exit(1);
    }
    node->value = value;
    node->prev = where;
    node->next = where->next;
    where->next->prev = node;        // сначала старый сосед справа
    where->next = node;              // затем сам where
    return node;
}

static void unlink_node(Node *node) {
    node->prev->next = node->next;
    node->next->prev = node->prev;
    free(node);
}

static void print(const Node *sentinel) {
    for (const Node *p = sentinel->next; p != sentinel; p = p->next) {
        printf("%d ", p->value);
    }
    printf("| ");
    for (const Node *p = sentinel->prev; p != sentinel; p = p->prev) {
        printf("%d ", p->value);
    }
    printf("\n");
}

int main(void) {
    Node list;
    list_init(&list);
    insert_after(list.prev, 10);             // в конец
    Node *b = insert_after(list.prev, 20);   // в конец
    insert_after(list.prev, 30);             // в конец
    insert_after(&list, 5);                  // в начало
    print(&list);
    unlink_node(b);                          // удалить 20 за O(1)
    print(&list);
    while (list.next != &list) {
        unlink_node(list.next);
    }
    print(&list);
    return 0;
}
```

Вывод:

```text
5 10 20 30 | 30 20 10 5
5 10 30 | 30 10 5
|
```

Добавление в начало — `insert_after(&list, x)`, в конец — `insert_after(list.prev, x)`: одна функция для обоих концов. Обход заканчивается, когда мы вернулись к стражу, а не на `NULL`. Сам страж — обычная переменная `list` на стеке; освобождать его не нужно.

## Порядок присваиваний

При вставке важна последовательность. Новый узел сначала получает обоих соседей, затем сосед справа (`where->next`) указывает назад на новый узел, и только потом `where->next` переключается на новый узел. Если поменять две последние строки местами, `where->next->prev = node` изменит уже **сам новый узел** — его `prev` станет указывать на себя, а у старого соседа ссылка назад останется неверной. Обход вперёд при этом работает, и ошибку видно только при обходе назад.

Правило: перед тем как перезаписать указатель, убедитесь, что всё, до чего через него можно добраться, уже сохранено или больше не нужно. Полезно нарисовать узлы и стрелки на бумаге и вычёркивать каждую изменённую стрелку.

## Стоимость

| Операция                              | Стоимость |
| ------------------------------------- | --------- |
| вставка до или после известного узла  | `O(1)`    |
| удаление известного узла              | `O(1)`    |
| добавление и удаление на обоих концах | `O(1)`    |
| обход вперёд и назад                  | `O(n)`    |
| доступ к `k`-му элементу              | `O(k)`    |
| поиск значения                        | `O(n)`    |

Цена — второй указатель в каждом узле: на 64-битной системе ещё 8 байт к значению и указателю `next`.

## Где он нужен

Двусвязный список хорош там, где на узлы есть **внешние ссылки** и узлы нужно быстро удалять или переставлять:

- **LRU-кэш** (least recently used): элементы хранятся в порядке последнего обращения. Обращение переносит элемент в начало, а при переполнении удаляется последний. Таблица «ключ → узел» находит узел за `O(1)`, а двусвязный список переносит и удаляет его за `O(1)`.
- **Текстовый редактор**: курсор — узел списка строк или символов, вставка и удаление у курсора — `O(1)`.
- **История браузера** «назад/вперёд», списки задач в ядрах операционных систем.

В стандартной библиотеке C++ двусвязный список — `std::list`:

```cpp
#include <iostream>
#include <list>

int main() {
    std::list<int> values{10, 20, 30};
    values.push_front(5);
    auto it = values.begin();
    ++it;
    ++it;                          // указывает на 20
    values.erase(it);              // O(1): остальные итераторы остаются верными
    for (int v : values) {
        std::cout << v << ' ';
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
5 10 30
```

<Concept title="Двусвязный список">

Каждый узел знает предыдущий и следующий, поэтому вставка и удаление известного узла — `O(1)`, а обходить можно в обе стороны. Фиктивный узел, замкнутый в кольцо, убирает все особые случаи: у каждого настоящего узла всегда есть оба соседа. Порядок присваиваний при вставке и удалении важен — следите, чтобы нужные указатели не были перезаписаны раньше времени.

</Concept>

## Частые ошибки

<CommonMistake title="Обновлена только одна ссылка">

При удалении нужно поправить **две** ссылки: `prev->next` и `next->prev`. Если забыть вторую, обход вперёд работает, а обход назад заходит в освобождённый узел — AddressSanitizer сообщит `heap-use-after-free`.

</CommonMistake>

<CommonMistake title="Удаление стража">

`unlink_node(list.next)` в пустом списке удалит сам страж — он указывает на себя — и вызовет `free` для переменной на стеке. Перед удалением с конца проверяйте, что список не пуст: `list.next != &list`.

</CommonMistake>

<CommonMistake title="Обход до NULL в кольце">

В списке со стражем нет `NULL`: цикл `while (p != NULL)` бесконечен. Условие окончания — возвращение к стражу.

</CommonMistake>

## Практика

1. **Вперёд и назад** — обход в обе стороны.
2. **Дек** — операции на обоих концах.
3. **Найди ошибку: удаление узла** — забытая обратная ссылка.
4. **LRU-кэш** — таблица и двусвязный список.

## Итоги

- Узел двусвязного списка хранит `prev` и `next`; удалить или вставить рядом с известным узлом — `O(1)`.
- Фиктивный узел, замкнутый в кольцо, убирает проверки на `NULL` и особые случаи концов.
- При вставке и удалении обновляются ссылки обоих соседей, в правильном порядке.
- Двусвязный список полезен, когда на узлы есть внешние ссылки: LRU-кэш, редакторы, планировщики.
- Цена — дополнительный указатель на каждый элемент.
