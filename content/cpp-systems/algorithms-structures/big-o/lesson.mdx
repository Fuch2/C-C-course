## Зачем отбрасывать константы

В прошлом уроке сумма массива сделала около `3n + 2` операций. А если считать операции иначе — например, не учитывать проверку условия, — получится `2n`. Обе записи верны, и обе говорят одно и то же: **число операций растёт пропорционально `n`**. Удвоили вход — удвоилась работа.

Для сравнения алгоритмов важна именно скорость роста. Сравните алгоритм A, который делает `100n` операций, и алгоритм B, который делает `n²`:

| `n`   | A: `100n` | B: `n²`   |
| ----- | --------- | --------- |
| 10    | 1 000     | 100       |
| 100   | 10 000    | 10 000    |
| 1 000 | 100 000   | 1 000 000 |
| 10⁶   | 10⁸       | 10¹²      |

На маленьких входах B быстрее, при `n = 100` они равны, а дальше A выигрывает всё сильнее — при миллионе элементов в 10 000 раз. Какой бы большой ни была константа у A, для достаточно больших `n` квадрат её обгонит. Поэтому константы и младшие слагаемые отбрасывают и говорят: A работает за **O(n)**, B — за **O(n²)**.

## Определение O

Запись `f(n) = O(g(n))` читается «f есть O большое от g» и означает: начиная с некоторого `n`, функция `f` не больше `g`, умноженной на константу.

Формально: существуют числа `c > 0` и `n₀`, такие что `f(n) ≤ c · g(n)` для всех `n ≥ n₀`.

Пример: `3n + 2 = O(n)`, потому что `3n + 2 ≤ 4n` при `n ≥ 2` — подходят `c = 4` и `n₀ = 2`.

O — это **верхняя граница**: «растёт не быстрее, чем». Формально `3n + 2` есть и `O(n²)`, но такая оценка бесполезна — так же как сказать «до магазина не больше ста километров». Мы всегда ищем самую точную границу.

Рядом с O используют ещё две записи:

| Запись | Смысл                   | Аналогия |
| ------ | ----------------------- | -------- |
| `O(g)` | растёт не быстрее `g`   | `≤`      |
| `Ω(g)` | растёт не медленнее `g` | `≥`      |
| `Θ(g)` | растёт так же, как `g`  | `=`      |

Линейный поиск работает за `O(n)` и `Ω(1)`: в худшем случае `n` сравнений, в лучшем — одно. Сумма массива — за `Θ(n)`: она всегда просматривает все элементы. В повседневной речи программисты говорят «O(n)», имея в виду точную оценку, и мы будем поступать так же.

## Правила упрощения

Оценку обычно получают не по определению, а по четырём правилам.

**1. Константы отбрасываются.** `O(5n) = O(n)`, `O(n² / 2) = O(n²)`, `O(1000) = O(1)`.

**2. Остаётся старшее слагаемое.** `O(n² + 3n + 7) = O(n²)`: при больших `n` слагаемое `3n` ничтожно по сравнению с `n²`.

**3. Последовательные части складываются — побеждает большая.** Два цикла подряд по `n` дают `O(n) + O(n) = O(n)`, а цикл по `n` и затем двойной цикл — `O(n) + O(n²) = O(n²)`.

**4. Вложенные части перемножаются.** Цикл по `n`, внутри которого цикл по `m`, — `O(n · m)`.

Основание логарифма не указывают: `log₂ n` и `log₁₀ n` отличаются в постоянное число раз (`log₂ n ≈ 3,32 · log₁₀ n`), а константы отбрасываются.

## Оценка кода по правилам

```c
#include <stdio.h>

int main(void) {
    int n = 16;
    long long a = 0, b = 0, c = 0;

    for (int i = 0; i < n; i++) a++;              // O(n)
    for (int i = 0; i < n; i++) a++;              // O(n), вместе O(n)

    for (int i = 0; i < n; i++)                   // O(n) раз
        for (int j = 1; j < n; j *= 2) b++;       //   по O(log n)

    for (int i = 0; i < n; i++)                   // O(n) раз
        for (int j = 0; j < 100; j++) c++;        //   по 100 — константа

    printf("a = %lld, b = %lld, c = %lld\n", a, b, c);
    return 0;
}
```

Вывод:

```text
a = 32, b = 64, c = 1600
```

- `a`: два цикла подряд — `2n`, то есть `O(n)`.
- `b`: внешний цикл `n` раз, внутренний — пока `j` удваивается от 1 до `n`, это `log₂ 16 = 4` раза. Итого `n log n` = 64, **O(n log n)**.
- `c`: внутренний цикл делает 100 итераций **независимо от `n`**. Это константа, поэтому `100n = O(n)`, хотя число операций самое большое.

Последний пример важен: O-оценка говорит о **росте**, а не о числе операций при конкретном `n`.

## Иерархия роста

Самые частые оценки от медленного роста к быстрому:

| Оценка       | Название         | Пример                               |
| ------------ | ---------------- | ------------------------------------ |
| `O(1)`       | константная      | элемент массива по индексу           |
| `O(log n)`   | логарифмическая  | двоичный поиск                       |
| `O(n)`       | линейная         | сумма массива, линейный поиск        |
| `O(n log n)` | «эн лог эн»      | хорошие сортировки                   |
| `O(n²)`      | квадратичная     | все пары элементов                   |
| `O(n³)`      | кубическая       | все тройки, наивное умножение матриц |
| `O(2ⁿ)`      | экспоненциальная | все подмножества                     |

Каждая следующая строка растёт быстрее предыдущей так сильно, что никакая константа не спасает. Следующие уроки разбирают первые пять классов по отдельности.

## Тест удвоения

Как определить сложность по наблюдениям? Удвойте `n` и посмотрите, во сколько раз выросло число операций. Для `O(n)` — в 2 раза, для `O(n²)` — в 4, для `O(n³)` — в 8, для `O(log n)` — прибавится одна операция, для `O(n log n)` — чуть больше чем в 2 раза.

```c
#include <stdio.h>

static long long linear(int n) {
    long long ops = 0;
    for (int i = 0; i < n; i++) ops++;
    return ops;
}

static long long quadratic(int n) {
    long long ops = 0;
    for (int i = 0; i < n; i++)
        for (int j = 0; j < n; j++) ops++;
    return ops;
}

static long long logarithmic(int n) {
    long long ops = 0;
    for (int i = n; i > 0; i /= 2) ops++;
    return ops;
}

int main(void) {
    for (int n = 1000; n <= 8000; n *= 2) {
        printf("n = %4d: log %2lld, n %4lld, n^2 %8lld\n",
               n, logarithmic(n), linear(n), quadratic(n));
    }
    return 0;
}
```

Вывод:

```text
n = 1000: log 10, n 1000, n^2  1000000
n = 2000: log 11, n 2000, n^2  4000000
n = 4000: log 12, n 4000, n^2 16000000
n = 8000: log 13, n 8000, n^2 64000000
```

Тот же тест работает и со временем: если удвоение входа увеличивает время работы примерно в 4 раза, алгоритм, скорее всего, квадратичный.

## Сложность по памяти

Так же оценивают и **дополнительную память** — сколько её нужно сверх самого входа. Сумма массива использует пару переменных — `O(1)` памяти. Программа, которая копирует вход в новый массив, — `O(n)`. Часто приходится выбирать: потратить память, чтобы сэкономить время, или наоборот.

<Concept title="О-оценка">

`f(n) = O(g(n))`, если `f(n) ≤ c · g(n)` для всех достаточно больших `n`. Оценку получают по правилам: константы отбрасываются, остаётся старшее слагаемое, последовательные части складываются, вложенные — перемножаются. O описывает скорость роста, а не число операций при конкретном `n`.

</Concept>

## Частые ошибки

<CommonMistake title="Константа в цикле — не n">

```c
for (int i = 0; i < n; i++)
    for (int j = 0; j < 26; j++)   // по буквам алфавита
        ...
```

Это `O(26n) = O(n)`, а не `O(n²)`. Квадрат появляется, только если **оба** цикла зависят от размера входа.

</CommonMistake>

<CommonMistake title="Сложение вместо умножения">

Цикл по `n` и **внутри** него цикл по `m` — это `O(n · m)`. Цикл по `n`, а **после** него цикл по `m` — `O(n + m)`. Смотрите на вложенность, а не на число циклов.

</CommonMistake>

<CommonMistake title="«O(n²) всегда медленнее O(n)»">

O-оценка ничего не говорит о маленьких входах. Алгоритм `n²` с маленькой константой на 20 элементах может обогнать `1000n`. Поэтому стандартные библиотеки сортируют короткие массивы простой квадратичной сортировкой вставками.

</CommonMistake>

## Практика

1. **Порядок роста** — упорядочить классы сложности.
2. **Когда константа перестаёт помогать** — найти точку, где квадрат обгоняет `n log n`.
3. **Найди ошибку: удвоение до n** — переполнение счётчика цикла.
4. **Сумма делителей** — от `O(n²)` к `O(n)` перестановкой суммирования.

## Итоги

- O-оценка описывает скорость роста: константы и младшие слагаемые отбрасываются.
- `f = O(g)` — растёт не быстрее; `Ω` — не медленнее; `Θ` — так же.
- Последовательные части: побеждает большая; вложенные: перемножаются.
- Основание логарифма в O не важно.
- Иерархия: `1 < log n < n < n log n < n² < n³ < 2ⁿ`.
- Тест удвоения: рост в 2 раза — линейная сложность, в 4 — квадратичная.
- Так же оценивают дополнительную память.
