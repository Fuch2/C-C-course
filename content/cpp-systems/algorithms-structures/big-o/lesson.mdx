## Цели обучения

- Объяснить инвариант: Big O — потолок роста при больших входах, а не обещание конкретного времени.
- Обосновать время: 3n²+7n+12 = Θ(n²), следовательно O(n²).
- Оценить память и компромиссы: Асимптотика отсекает неподходящие решения на больших n; benchmark помогает выбрать среди оставшихся на нужных размерах.

## Теория и инвариант

Запись f(n)=O(g(n)) означает существование констант C и n₀, таких что f(n)≤C·g(n) при n≥n₀. Это верхняя асимптотическая граница, а не точное число действий. Для точной по порядку границы используют Θ, для нижней — Ω. Линейная функция одновременно принадлежит O(n) и O(n²), но более тесная граница полезнее.

В 3n²+7n+12 доминирует квадратный член при достаточно большом n. Константы отбрасывают для изучения роста, однако на конкретных размерах они важны. Пишите, для какого случая дана граница: worst-case O(n), expected O(1) и amortized O(1) не взаимозаменяемы. Амортизированная оценка относится к последовательности операций, а ожидаемая — к вероятностной модели.

</Concept>

## Пошаговый разбор

При n=10 функция 3n²+7n+12 равна 382, при n=20 — 1352. Удвоение входа приближает отношение к 4, но не даёт ровно 4 на каждом n.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>


int main(void) {
long long n=20;printf("%lld\n",3*n*n+7*n+12);
return 0;
}
```

Ожидаемый вывод:

```text
1352
```

## Почему реализация корректна

Если стоимость равна 3n²+7n+12, то при n≥1 имеем 7n≤7n² и 12≤12n². Следовательно, стоимость не больше 22n²: найдены конкретные константа и порог для O(n²). Одновременно стоимость не меньше 3n², поэтому здесь допустима более точная характеристика Θ(n²).

Из O(n²) не следует, что программа всегда делает ровно n² шагов; более быстрый алгоритм тоже удовлетворяет такой верхней границе. Для инженерного решения нужна достаточно тесная оценка и указание случая. Уменьшение константы существенно на практических размерах, но не отменяет старшую степень. При вычислении точного полинома в C выберите широкий тип до умножения, а не только для конечной переменной.

## Cache locality и компромиссы

Big O не описывает расположение данных. Одинаковая граница не означает одинаковую долю cache misses.

Асимптотика отсекает неподходящие решения на больших n; benchmark помогает выбрать среди оставшихся на нужных размерах.

Практическое применение: Планирование ограничений API и анализ, почему увеличение входа в 10 раз даёт рост задержки примерно в 100 раз.

<CommonMistake title="Типичная ошибка">

Нельзя называть O(n²) точным числом операций или автоматически считать Big O только худшим случаем.

</CommonMistake>

## Связь со STL C++

Документация std::sort обещает O(n log n) сравнений, но не фиксирует конкретную реализацию и постоянный множитель.
