## Цели обучения

- Объяснить инвариант: Идём по одной тропе до конца, сохраняя развилки, к которым надо вернуться.
- Обосновать время: O(V+E) для полного обхода списков.
- Оценить память и компромиссы: Удобен для структуры зависимостей и postorder, но не гарантирует кратчайший путь.

## Теория и инвариант

DFS сначала углубляется в одного непосещённого соседа, затем возвращается к отложенным ветвям. Отложенные действия хранятся в рекурсивных кадрах или явном стеке. Вершина помечается до перехода к соседям, иначе цикл графа вызовет бесконечный обход.

Для подсчёта компонент неориентированного графа запускайте DFS из каждой ещё непосещённой вершины и увеличивайте счётчик один раз на запуск. Порядок посещения зависит от порядка соседей, но число компонент — нет. Рекурсивная глубина может быть V на цепочке; наш учебный предел 32 делает это контролируемым. На большом графе переход к итеративному стеку должен сохранять нужную семантику входа/выхода, если задача использует postorder.

## Пошаговый разбор

Рёбра 0–1 и 2–3 при пяти вершинах дают три запуска: компоненты &#123;0,1&#125;, &#123;2,3&#125;, &#123;4&#125;.

## Реализация и запускаемый пример на C17

Пример не требует stdin. Сначала предскажите результат; затем выполните код и измените данные. Функции демонстрируют алгоритм, а практика ниже требует самостоятельного ввода и обработки граничных состояний.

```c
#include <stdio.h>
#include <stdlib.h>
#include <stdint.h>
#include <string.h>
#include <limits.h>

enum { MAX_VERTICES=32, MAX_ARCS=256 };
typedef struct { int to,next; } Edge;
typedef struct { int head[MAX_VERTICES],count; Edge edges[MAX_ARCS]; } Graph;
static void init(Graph *g){for(int i=0;i<MAX_VERTICES;++i)g->head[i]=-1;g->count=0;}
static int connect(Graph *g,int from,int to){
    if(g->count==MAX_ARCS)return 0;
    g->edges[g->count]=(Edge){to,g->head[from]};g->head[from]=g->count++;return 1;
}
static int read_graph(Graph *g,int *vertices){
    int m;if(scanf("%d%d",vertices,&m)!=2 || *vertices<1 || *vertices>32 || m<0 || m>128)return 0;
    init(g);
    for(int i=0;i<m;++i){int a,b;if(scanf("%d%d",&a,&b)!=2 || a<0 || b<0 || a>=*vertices || b>=*vertices)return 0;
        if(!connect(g,a,b) || !connect(g,b,a))return 0;
    }return 1;
}
static void visit(const Graph *g,int v,int *seen){
    seen[v]=1;
    for(int e=g->head[v];e!=-1;e=g->edges[e].next){int to=g->edges[e].to;if(!seen[to])visit(g,to,seen);}
}
static int components(const Graph *g,int n){
    int seen[MAX_VERTICES]={0},count=0;
    for(int i=0;i<n;++i)if(!seen[i]){++count;visit(g,i,seen);}
    return count;
}
int main(void) {
Graph g;init(&g);connect(&g,0,1);connect(&g,1,0);connect(&g,2,3);connect(&g,3,2);printf("%d\n",components(&g,5));
return 0;
}
```

Ожидаемый вывод:

```text
3
```

## Почему реализация корректна

Вершина помечается до рекурсивных вызовов соседей. Тогда обратное ребро в неориентированном графе встречает уже посещённую вершину и не создаёт бесконечную рекурсию. Для двух компонент 0—1 и 2—3 внешний цикл запускает обход из 0, пропускает 1, затем запускает из 2 и пропускает 3: ответ равен двум.

Один DFS из вершины 0 не решает задачу числа компонент, если граф несвязен. В отличие от BFS, глубина стека DFS может достигать V даже на простом пути. Учебный предел 32 позволяет рекурсию; на больших данных нужен явный стек и контроль памяти. Результат здесь относится к неориентированным компонентам, а не к сильной связности ориентированного графа.

## Сложность и память

| Что оцениваем | Гарантия                                  |
| ------------- | ----------------------------------------- |
| Время         | O(V+E) для полного обхода списков.        |
| Память        | O(V) visited и O(V) стек в худшем случае. |

Размеры в учебном коде ограничены ради безопасного запуска. При анализе представляйте масштабируемый вариант той же структуры; фиксированный тестовый предел не превращает любой алгоритм в полезное «O(1)».

## Cache locality и компромиссы

Глубокий путь может переходить по разным участкам графа; предвыборка менее предсказуема, чем линейный массив.

Удобен для структуры зависимостей и postorder, но не гарантирует кратчайший путь.

Практическое применение: Компоненты связности, анализ зависимостей и основа топологического обхода ориентированных графов.

<CommonMistake title="Типичная ошибка">

Для ориентированного графа такой счётчик запусков не является алгоритмом сильных компонент.

</CommonMistake>

## Связь со STL C++

std::vector может быть явным стеком через push_back/pop_back. Стандартного DFS для произвольного графа нет.
