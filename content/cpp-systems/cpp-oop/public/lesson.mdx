## Интерфейс — обещание клиентам

Код, который пользуется классом, называют его **клиентом**. Клиент видит только открытую часть — интерфейс — и строится вокруг неё. Поэтому интерфейс — это обещание: если завтра поменять закрытые поля, клиенты не заметят, а если поменять открытый метод, придётся исправлять каждого клиента. В большом проекте их может быть сотни.

Отсюда главная задача при проектировании класса — решить, **что** открыть. Хороший интерфейс:

- описывает **операции** предметной области, а не поля;
- **минимален** — в нём нет методов «на всякий случай»;
- **полон** — клиенту не приходится обходить его, чтобы сделать нужное;
- не позволяет нарушить инвариант ни одной последовательностью вызовов.

## Операции, а не поля

Самый частый способ испортить класс — снабдить каждое закрытое поле парой «получить/установить»:

```cpp
#include <print>

class Account {
public:
    long long balance() const {
        return balance_;
    }

    void set_balance(long long value) {
        balance_ = value;
    }

private:
    long long balance_ = 0;
};

int main() {
    Account acc;
    acc.set_balance(acc.balance() + 100);     // вклад
    acc.set_balance(acc.balance() - 500);     // снятие без проверки
    std::println("{}", acc.balance());
    return 0;
}
```

Вывод:

```text
-400
```

Поле формально закрыто, но `set_balance` позволяет записать любое значение — защиты нет. Хуже того, правила работы со счётом расползлись по клиентам: каждый сам считает новый баланс и сам решает, проверять ли остаток. Интерфейс должен говорить на языке задачи:

```cpp
#include <print>

class Account {
public:
    long long balance() const {
        return balance_;
    }

    void deposit(long long amount) {
        if (amount > 0) {
            balance_ += amount;
        }
    }

    bool withdraw(long long amount) {
        if (amount <= 0 || amount > balance_) {
            return false;
        }
        balance_ -= amount;
        return true;
    }

private:
    long long balance_ = 0;
};

int main() {
    Account acc;
    acc.deposit(100);
    bool ok = acc.withdraw(500);
    std::println("{} {}", ok, acc.balance());
    return 0;
}
```

Вывод:

```text
false 100
```

Теперь правило «нельзя уйти в минус» записано один раз, в `withdraw`, и клиент не может его обойти. Этот принцип называют **«говори, а не спрашивай»** (tell, don't ask): клиент не спрашивает объект о состоянии, чтобы самому принять решение, а говорит, что нужно сделать, — решение принимает объект, который знает свои правила.

## Не отдавайте ссылку на внутренности

Метод может вернуть ссылку на закрытое поле. Если ссылка **неконстантная**, закрытость поля исчезает:

```cpp
#include <algorithm>
#include <print>
#include <vector>

class SortedList {
public:
    void insert(int value) {
        auto pos = std::ranges::upper_bound(items_, value);
        items_.insert(pos, value);
    }

    const std::vector<int> &items() const {
        return items_;
    }

    int min() const {
        return items_.front();
    }

private:
    std::vector<int> items_;   // инвариант: по возрастанию
};

int main() {
    SortedList list;
    for (int x : {5, 1, 4}) {
        list.insert(x);
    }
    for (int x : list.items()) {
        std::print("{} ", x);
    }
    std::println("| min {}", list.min());
    return 0;
}
```

Вывод:

```text
1 4 5 | min 1
```

`insert` ставит элемент на своё место (`std::ranges::upper_bound` двоичным поиском находит позицию), поэтому `min()` — просто первый элемент. Метод `items()` возвращает **константную** ссылку: клиент может читать и перебирать список без копирования, но не может изменить. Будь там `std::vector<int> &items()`, клиент мог бы написать `list.items().push_back(0)` — и `min()` начал бы лгать.

| Что вернуть                         | Когда                                                        |
| ----------------------------------- | ------------------------------------------------------------ |
| значение (`int`, `double`, `Point`) | маленькие типы и вычисляемые результаты                      |
| `const T &`                         | большое поле, которое клиенту нужно прочитать                |
| `T &`                               | почти никогда: только если любое изменение не нарушит правил |

Есть и тонкость: константная ссылка на поле живёт, пока жив объект. `const auto &v = make_list().items();` — ссылка на часть временного объекта, который сразу уничтожается.

## Статические члены

Иногда данные принадлежат не отдельному объекту, а **классу целиком**: общий счётчик созданных объектов, константа для всех экземпляров. Такие члены объявляют со словом `static`:

```cpp
#include <print>
#include <string>
#include <utility>

class Order {
public:
    explicit Order(std::string item) : number_(++last_number_), item_(std::move(item)) {}

    void print() const {
        std::println("заказ №{}: {}", number_, item_);
    }

    static int created() {
        return last_number_;
    }

    static constexpr int max_items = 50;

private:
    inline static int last_number_ = 0;
    int number_;
    std::string item_;
};

int main() {
    Order a("книга"), b("лампа");
    Order c("кружка");
    b.print();
    c.print();
    std::println("создано {}, лимит {}", Order::created(), Order::max_items);
    return 0;
}
```

Вывод:

```text
заказ №2: лампа
заказ №3: кружка
создано 3, лимит 50
```

- `inline static int last_number_ = 0;` — одна переменная на весь класс, общая для всех заказов. Слово `inline` (C++17) позволяет задать начальное значение прямо в классе.
- `static constexpr int max_items = 50;` — константа класса, известная при компиляции.
- `static int created()` — функция класса: у неё нет получателя, она видит только статические члены. Вызывают её через имя класса — `Order::created()`.

Статические изменяемые данные — это глобальные переменные под другим именем: ими пользуются осторожно, потому что их меняет любой объект класса из любого места программы.

<Concept title="Открытый интерфейс">

Интерфейс класса — обещание клиентам: его меняют редко и осторожно. Хороший интерфейс состоит из операций предметной области («вложить», «снять»), а не из пар «получить/установить», минимален и полон и не позволяет нарушить инвариант. Большие поля отдают по константной ссылке, неконстантную ссылку на внутренности не отдают. Данные и функции, общие для всего класса, объявляют `static`.

</Concept>

## Частые ошибки

<CommonMistake title="Сеттер для каждого поля">

`set_balance`, `set_size`, `set_items` превращают класс в структуру с лишними словами: защита формальная, правила живут у клиентов. Спросите себя, какую **операцию** выполняет клиент, и откройте её.

</CommonMistake>

<CommonMistake title="Неконстантная ссылка на поле">

`std::vector<int> &items()` разрешает клиенту делать с внутренним вектором что угодно. Для чтения — `const std::vector<int> &items() const`.

</CommonMistake>

<CommonMistake title="Метод «на будущее»">

Каждый открытый метод придётся поддерживать, пока у него есть клиенты. Не открывайте то, что сегодня никому не нужно: добавить метод легко, убрать — трудно.

</CommonMistake>

<CommonMistake title="Ссылка на часть временного объекта">

`const auto &v = make_list().items();` — временный список уничтожается в конце строки, и ссылка висит. Сохраните сам объект: `auto list = make_list();`.

</CommonMistake>

## Практика

1. **Склад** — операции вместо доступа к внутреннему словарю.
2. **Отсортированный список** — интерфейс, который хранит порядок.
3. **Найди ошибку: открытые внутренности** — ссылка на закрытый вектор.
4. **Талоны** — статические счётчики по видам услуг.

## Итоги

- Интерфейс — обещание клиентам; закрытое можно менять свободно, открытое — нет.
- Открывайте операции предметной области, а не поля; «говори, а не спрашивай».
- Маленькие значения возвращают копией, большие поля — константной ссылкой; неконстантная ссылка разрушает инкапсуляцию.
- `static` — члены класса, а не объекта: общие данные (`inline static`), константы (`static constexpr`) и функции, вызываемые через `Класс::имя`.
