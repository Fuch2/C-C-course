## От данных к типу с поведением

В C структура — это только данные. Всё, что с ними делают, живёт отдельно, в функциях, которые получают указатель на структуру:

```c
struct Rect {
    double width;
    double height;
};

double rect_area(const struct Rect *r) {
    return r->width * r->height;
}
```

Связь между `Rect` и `rect_area` существует только в голове программиста и в приставке `rect_` в имени. Функцию легко потерять в большом проекте, перепутать с функцией для другой структуры, вызвать с чужим указателем.

C++ позволяет объявить функцию **внутри** структуры. Такая функция называется **методом** (или функцией-членом): она принадлежит типу, вызывается через точку и сама видит поля объекта. С этого шага начинается объектно-ориентированное программирование — данные и операции над ними описываются вместе, как одно понятие.

## Методы

```cpp
#include <print>

struct Rect {
    double width;
    double height;

    double area() const {
        return width * height;
    }

    double perimeter() const {
        return 2 * (width + height);
    }

    void scale(double factor) {
        width *= factor;
        height *= factor;
    }
};

int main() {
    Rect r{3, 4};
    std::println("площадь {}, периметр {}", r.area(), r.perimeter());
    r.scale(2);
    std::println("после scale: {} x {}, площадь {}", r.width, r.height, r.area());
    return 0;
}
```

Вывод:

```text
площадь 12, периметр 14
после scale: 6 x 8, площадь 48
```

Внутри метода имена `width` и `height` означают поля **того объекта, для которого метод вызван**: в `r.area()` — поля `r`. Передавать указатель не нужно, компилятор делает это сам (как именно — в уроке о `this`). Объект, у которого вызывают метод, называют **получателем** вызова.

## `const` после скобок

Слово `const` после списка параметров — обещание: метод **не меняет** объект. `area` и `perimeter` только читают поля, поэтому помечены `const`; `scale` меняет — и `const` у него нет. Компилятор следит за обещанием в обе стороны:

```cpp
#include <print>

struct Counter {
    int value = 0;

    int get() const {
        return value;
    }

    void increment() {
        value++;
    }
};

void show(const Counter &c) {
    std::println("значение {}", c.get());
    c.increment();                 // Ошибка компиляции: increment не const, а c — const
}

int main() {
    Counter c;
    show(c);
    return 0;
}
```

Через `const Counter &` можно вызывать только `const`-методы. Поэтому правило простое: **каждый метод, который не меняет объект, помечайте `const`**. Иначе его нельзя будет вызвать у константы или через константную ссылку — а именно так объекты обычно и передают в функции. Попытка изменить поле внутри `const`-метода — тоже ошибка компиляции.

## Значения полей по умолчанию

У поля можно задать начальное значение прямо в объявлении — как `value = 0` в `Counter` выше. Тогда объект, созданный без явной инициализации, не содержит мусора:

```cpp
#include <print>
#include <string>

struct Settings {
    std::string language = "ru";
    int font_size = 14;
    bool dark_theme = false;
};

int main() {
    Settings a;
    Settings b{"en", 16};
    Settings c{.font_size = 20, .dark_theme = true};
    std::println("{} {} {}", a.language, a.font_size, a.dark_theme);
    std::println("{} {} {}", b.language, b.font_size, b.dark_theme);
    std::println("{} {} {}", c.language, c.font_size, c.dark_theme);
    return 0;
}
```

Вывод:

```text
ru 14 false
en 16 false
ru 20 true
```

`Settings b{"en", 16}` задаёт поля по порядку, остальные получают значения по умолчанию. Запись `{.font_size = 20, .dark_theme = true}` — **именованная инициализация** (C++20): поля называются явно, пропущенные берутся по умолчанию. Она знакома по C99, но в C++ есть ограничение — поля нужно перечислять **в порядке объявления**.

Без значения по умолчанию поле числового типа в `Settings a;` содержало бы мусор, как локальная переменная в C. Задавайте значения по умолчанию всем полям, у которых есть разумное «пустое» состояние.

## Метод, определённый вне структуры

Если метод длинный или структура объявлена в заголовке, внутри оставляют только **объявление**, а тело пишут отдельно — с именем структуры и оператором `::`:

```cpp
#include <cmath>
#include <print>

struct Point {
    double x = 0;
    double y = 0;

    double distance_to(Point other) const;
    Point moved(double dx, double dy) const;
};

double Point::distance_to(Point other) const {
    return std::hypot(x - other.x, y - other.y);
}

Point Point::moved(double dx, double dy) const {
    return {x + dx, y + dy};
}

int main() {
    Point a{0, 0};
    Point b = a.moved(3, 4);
    std::println("({}, {}) {}", b.x, b.y, a.distance_to(b));
    return 0;
}
```

Вывод:

```text
(3, 4) 5
```

`Point::` говорит компилятору: это метод `distance_to` структуры `Point`, а не отдельная функция. Слово `const` повторяется и в объявлении, и в определении — это часть типа метода. Так устроены настоящие проекты: объявление структуры — в файле `point.h`, определения методов — в `point.cpp`.

Обратите внимание на `moved`: он не меняет точку, а **возвращает новую**. Такие методы удобны тем, что исходный объект остаётся нетронутым, и их можно вызывать у констант.

## Структуры в контейнерах

Структура с методами — обычный тип: её кладут в `std::vector`, передают по константной ссылке, возвращают из функций.

```cpp
#include <print>
#include <vector>

struct Item {
    double price;
    int quantity;

    double cost() const {
        return price * quantity;
    }
};

double total(const std::vector<Item> &items) {
    double sum = 0;
    for (const Item &item : items) {
        sum += item.cost();
    }
    return sum;
}

int main() {
    std::vector<Item> cart = {{89.9, 2}, {54.5, 1}, {650, 1}};
    std::println("{:.2f}", total(cart));
    return 0;
}
```

Вывод:

```text
884.30
```

`item.cost()` вызывается через константную ссылку — и это возможно только потому, что `cost` помечен `const`.

## Чего структуре не хватает

Все поля структуры открыты: любой код может написать `r.width = -5;`, и прямоугольник с отрицательной шириной будет считать отрицательную площадь. Структура не может **защитить** свои данные. Для «мешка с данными» — точки, настроек, записи из файла — это нормально и даже удобно. Но как только у данных появляются правила (ширина не отрицательна, баланс меняется только операциями), нужен тип, который сам следит за правилами. Это класс — тема следующего урока.

<Concept title="Структура с методами">

В C++ структура может содержать методы — функции, которые вызываются через точку и работают с полями получателя без явного указателя. Методы, не меняющие объект, помечают `const` после скобок: только их можно вызывать у констант и через `const &`. Полям задают значения по умолчанию; именованная инициализация `{.поле = …}` перечисляет поля в порядке объявления. Длинные методы определяют вне структуры: `Тип::метод(…) const { … }`.

</Concept>

## Частые ошибки

<CommonMistake title="Забытый const у читающего метода">

`double area() { … }` без `const` работает, пока объект не константный. Первая же функция с параметром `const Rect &` не сможет вызвать `area`, и придётся исправлять тип и все его методы. Ставьте `const` сразу.

</CommonMistake>

<CommonMistake title="Параметр с именем поля">

`void deposit(long long balance) { balance += balance; }` — внутри метода имя `balance` означает **параметр**, а не поле: метод удваивает свою копию аргумента, а поле не меняется. Компилятор не предупредит. Называйте параметры иначе, чем поля (`amount`), или обращайтесь к полю явно — `this->balance` (об этом в уроке о `this`).

</CommonMistake>

<CommonMistake title="Точка с запятой после структуры">

`struct Rect { … }` без `;` в конце — ошибка компиляции, сообщение о которой указывает на следующую строку. Эта ловушка пришла из C.

</CommonMistake>

<CommonMistake title="Поля без значений по умолчанию">

`struct Counter { int value; };` и затем `Counter c; c.value++;` — увеличение мусора. Пишите `int value = 0;`.

</CommonMistake>

## Практика

1. **Прямоугольники** — методы `area`, `perimeter`, `is_square`.
2. **Маршрут** — точка с методами `distance_to` и `moved`.
3. **Найди ошибку: вклад, который не зачисляется** — параметр с именем поля.
4. **Расписание** — время суток с методами и форматированным выводом.

## Итоги

- Метод — функция внутри структуры; вызывается через точку и видит поля получателя.
- `const` после скобок обещает не менять объект; только такие методы доступны у констант и через `const &`.
- Значения полей по умолчанию избавляют от мусора; `{.поле = …}` — именованная инициализация в порядке объявления.
- Метод можно объявить в структуре, а определить снаружи: `double Point::distance_to(Point other) const { … }`.
- Поля структуры открыты всем, поэтому она не может защитить правила своих данных — для этого нужен класс.
