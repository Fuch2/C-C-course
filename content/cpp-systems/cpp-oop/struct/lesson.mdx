## Задача и модель

В C++ struct объявляет полноценный пользовательский тип: у него бывают методы, конструкторы и правила доступа. По умолчанию его члены открыты. Для измерения, координаты или результата расчёта это удобный тип значения: смысл имеет совокупность полей, а копирование создаёт самостоятельный объект. Метод вызывается для конкретного объекта и может читать его поля без повторной передачи каждого аргумента.

## Как это работает в C++

Сначала отделите данные измерения от устройства, которое их получает. Measurement можно свободно копировать и хранить в vector. Sensor позднее будет иметь поведение и собственное время жизни. Суффикс const у метода обещает не менять обычные поля через этот вызов. Инициализаторы полей защищают от неопределённых начальных значений, но не проверяют физическую корректность данных. Не добавляйте наследование только потому, что два объекта содержат одинаковое поле value.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Point { int x{}; int y{}; int sum() const { return x + y; } };
int main() { const Point p{3, 8}; auto copy = p; copy.x = 1; std::cout << p.sum() << ' ' << copy.sum() << '\n'; }
```

Ожидаемый вывод:

```text
11 9
```

## Разбор и эксперимент

Добавьте третье поле единиц. Объясните, почему одинаковые численные value не гарантируют сопоставимости измерений. Проверьте независимость копий после изменения одного поля. Стоимость копирования определяется полями: для двух int она постоянна, для vector внутри структуры могла бы стать линейной.

<CommonMistake title="Ошибка, которую нужно заметить">

Не считайте struct урезанной версией class. Отличаются значения доступа по умолчанию; возможности методов одинаковы. Не возвращайте ссылку на локальное измерение.
