## Задача и модель

private ограничивает доступ к члену самим классом и его друзьями. Внешний код и производные классы не получают прямого доступа к закрытому полю. Это правило компиляции, а не шифрование памяти. Его задача — направить изменения через операции, сохраняющие контракт. Часто именно отказ операции показывает качество инкапсуляции: после ошибки старое значение должно сохраниться.

## Как это работает в C++

В примере try_set проверяет диапазон до присваивания. Клиент видит результат bool и может повторить запрос. Порядок «проверить, затем изменить» проще, чем откатывать уже испорченное состояние. Не предоставляйте пару getter/setter автоматически каждому полю: setter должен иметь предметный смысл. Для чтения небольшого int достаточно копии; ссылка добавила бы ненужные вопросы времени жизни.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Level { int value_{5}; public: bool try_set(int x) { if (x < 0 || x > 10) return false; value_ = x; return true; } int value() const { return value_; } };
int main() { Level x; std::cout << x.try_set(11) << ' ' << x.value() << '\n'; }
```

Ожидаемый вывод:

```text
0 5
```

## Разбор и эксперимент

Проверьте последовательность: корректная запись, ошибочная запись, чтение. Она обнаруживает повреждение состояния, которое незаметно при единственном вызове. Отдельно проверьте обе включённые границы. Контроль доступа не добавляет отдельной проверки прав во время каждого вызова.

<CommonMistake title="Ошибка, которую нужно заметить">

Если setter сначала присваивает, а затем сообщает об ошибке, он нарушает обещание сохранения состояния. private такой логический дефект не обнаружит.

</CommonMistake>

## Практика

Реализуйте Level с начальным private value\_=0. try_set(int) принимает только [0,100], возвращает bool и при отказе не меняет состояние. value() const читает значение. solve(a,b) последовательно пытается записать a и b, затем возвращает value(). Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
