## Один из нескольких типов

Виртуальные функции хороши, когда набор наследников **открыт**: завтра кто-то добавит новый датчик, и цикл обработки его примет. Но часто набор вариантов известен заранее и не меняется: команда робота — «шаг», «поворот» или «сказать»; ячейка таблицы — число или текст; соединение — отключено, подключается или подключено. Для таких случаев в C++17 появился **`std::variant`** — тип-сумма, который в каждый момент хранит значение ровно одного из перечисленных типов.

```cpp
#include <print>
#include <string>
#include <variant>

int main() {
    std::variant<int, std::string> v = 42;
    std::println("{} {}", v.index(), std::get<int>(v));

    v = std::string("сорок два");
    std::println("{} {}", v.index(), std::get<std::string>(v));

    if (const int *p = std::get_if<int>(&v)) {
        std::println("число {}", *p);
    } else {
        std::println("сейчас не int");
    }
    std::println("{}", std::holds_alternative<std::string>(v));
    return 0;
}
```

Вывод:

```text
0 42
1 сорок два
сейчас не int
true
```

`variant` помнит, какая **альтернатива** в нём сейчас лежит (`index()` — её номер). Достать значение можно тремя способами:

| Способ                         | Если альтернатива не та                    |
| ------------------------------ | ------------------------------------------ |
| `std::get<T>(v)`               | бросает `std::bad_variant_access`          |
| `std::get_if<T>(&v)`           | возвращает `nullptr`                       |
| `std::holds_alternative<T>(v)` | просто отвечает `false`, ничего не достаёт |

Значение хранится **внутри** объекта `variant`, без кучи и без указателей: размер `variant` — размер самой большой альтернативы плюс место для номера. Копирование `variant` копирует значение целиком, поэтому срезки здесь не бывает.

## std::visit: обработчик для каждого случая

Проверять альтернативы цепочкой `if` неудобно и опасно: легко забыть случай. **`std::visit`** вызывает функцию, подходящую текущей альтернативе. Удобнее всего собрать такую функцию из нескольких лямбд маленьким шаблоном `overloaded`:

```cpp
#include <print>
#include <variant>
#include <vector>

struct Circle {
    double r;
};

struct Rect {
    double w, h;
};

using Shape = std::variant<Circle, Rect>;

template <class... Ts>
struct overloaded : Ts... {
    using Ts::operator()...;
};

double area(const Shape &shape) {
    return std::visit(overloaded{
                          [](const Circle &c) { return 3.14 * c.r * c.r; },
                          [](const Rect &r) { return r.w * r.h; },
                      },
                      shape);
}

int main() {
    const std::vector<Shape> shapes{Circle{1}, Rect{2, 3}, Circle{2}};
    double total = 0;
    for (const Shape &s : shapes) {
        total += area(s);
    }
    std::println("{:.2f}", total);
    return 0;
}
```

Вывод:

```text
21.70
```

`overloaded` наследует операторы вызова всех переданных лямбд, и обычная перегрузка выбирает нужный. Главное свойство: если в `overloaded` **нет** обработчика для какой-то альтернативы, программа **не скомпилируется**. Добавили в `Shape` треугольник — компилятор покажет каждое место, где его забыли обработать.

<Tip title="overloaded в C++17 и C++20">

В C++17 к `overloaded` нужно было дописывать правило вывода `template <class... Ts> overloaded(Ts...) -> overloaded<Ts...>;`. Начиная с C++20 агрегаты выводят параметры шаблона сами, и хватает трёх строк. В C++26 у `variant` появится и метод `v.visit(...)`.

</Tip>

## Виртуальные функции или variant

Оба способа выражают «один из нескольких видов», но расширяются в разные стороны:

|                    | Виртуальные функции                             | `std::variant` + `std::visit`              |
| ------------------ | ----------------------------------------------- | ------------------------------------------ |
| Новый **тип**      | легко: новый наследник, старый код не меняется  | трудно: правка `using` и всех обработчиков |
| Новая **операция** | трудно: новый виртуальный метод во всех классах | легко: ещё одна функция с `visit`          |
| Хранение           | в куче, через `unique_ptr<База>`                | по значению, в самом объекте               |
| Копирование        | нужна `clone()`                                 | обычное копирование                        |
| Забытый случай     | ошибка, если метод чисто виртуальный            | ошибка компиляции в `visit`                |
| Типы связаны       | общей базой                                     | никак: альтернативы — любые типы           |

Правило выбора простое. Если виды будут добавлять другие люди (плагины, новые датчики) — иерархия с интерфейсом. Если набор видов закрыт и над ним часто появляются новые операции (разбор, печать, сохранение) — `variant`. Команды, токены разборщика, сообщения протокола, состояния конечного автомата — типичные случаи для `variant`.

## Конечный автомат

Состояние объекта, у которого в разных режимах разные данные, удобно хранить как `variant`: данные подключения существуют, только пока соединение установлено, и случайно прочитать их в другом состоянии нельзя.

```cpp
#include <print>
#include <string>
#include <variant>

struct Idle {};
struct Running {
    int seconds;
};
struct Finished {
    std::string result;
};

using State = std::variant<Idle, Running, Finished>;

template <class... Ts>
struct overloaded : Ts... {
    using Ts::operator()...;
};

std::string describe(const State &state) {
    return std::visit(overloaded{
                          [](const Idle &) { return std::string("ожидает"); },
                          [](const Running &r) { return "работает " + std::to_string(r.seconds) + " с"; },
                          [](const Finished &f) { return "готово: " + f.result; },
                      },
                      state);
}

int main() {
    State job;
    std::println("{}", describe(job));
    job = Running{5};
    std::println("{}", describe(job));
    job = Finished{"ок"};
    std::println("{}", describe(job));
    return 0;
}
```

Вывод:

```text
ожидает
работает 5 с
готово: ок
```

`State job;` создаёт значение **первой** альтернативы — поэтому её делают «пустым» начальным состоянием. Если у первой альтернативы нет конструктора по умолчанию, первой ставят `std::monostate` — специальный пустой тип.

<Concept title="std::variant и std::visit">

`std::variant<A, B, C>` хранит значение ровно одного из типов — по значению, без кучи. `index()` и `holds_alternative<T>` говорят, что внутри; `get<T>` достаёт значение или бросает `std::bad_variant_access`; `get_if<T>` возвращает указатель или `nullptr`. `std::visit` с набором лямбд (`overloaded`) обрабатывает каждую альтернативу, и пропущенный случай — ошибка компиляции. `variant` удобен для закрытого набора видов и открытого набора операций; виртуальные функции — наоборот.

</Concept>

## Частые ошибки

<CommonMistake title="std::get без проверки">

`std::get<int>(v)` для `v`, в котором строка, бросает исключение. Если альтернатива может быть любой, используйте `visit` или `get_if`.

</CommonMistake>

<CommonMistake title="Проверка по номеру альтернативы">

`if (v.index() == 0)` ломается, как только кто-то поменяет порядок типов в `variant`. Проверяйте по типу: `holds_alternative<T>`, `get_if<T>`.

</CommonMistake>

<CommonMistake title="variant вместо иерархии там, где типы будут добавлять">

Если новые виды появляются часто и их пишут разные люди, каждый новый тип потребует правки всех `visit`. Это случай для интерфейса и виртуальных функций.

</CommonMistake>

## Практика

1. **Команды робота** — `variant` команд и `visit`, меняющий состояние.
2. **Токены** — разбор слов на целые, дробные и строки.
3. **Найди ошибку: номер вместо типа** — проверка альтернативы по индексу.
4. **Соединение** — конечный автомат и `visit` по двум `variant` сразу.

## Итоги

- `std::variant` хранит значение одного из перечисленных типов по значению, без кучи и без общей базы.
- Значение достают через `get` (исключение при ошибке), `get_if` (указатель) или обрабатывают все случаи через `std::visit`.
- Набор лямбд в `overloaded` делает `visit` проверяемым: пропущенная альтернатива — ошибка компиляции.
- Виртуальные функции упрощают добавление типов, `variant` — добавление операций.
- Состояния конечного автомата, команды и токены — типичные места для `variant`.
