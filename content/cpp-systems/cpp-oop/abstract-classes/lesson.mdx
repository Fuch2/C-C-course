## Задача и модель

Абстрактный класс нельзя создать как самостоятельный полный объект, но он существует как базовая часть конкретного наследника. Поэтому у него могут быть поля, конструктор и обычные методы. Это полезно, когда всем реализациям нужен одинаковый идентификатор с едиными правилами. Ссылка на абстрактный тип допустима и образует границу между алгоритмом и устройством.

## Как это работает в C++

Общее состояние оправдано лишь при действительно одинаковой семантике. Если конкретные источники идентифицируются совершенно по-разному, лучше оставить абстрактный метод id(), а хранение поручить реализации. Не раздувайте базовый класс логированием, очередями и фильтрами. В примере идентификатор создаётся конструктором базы, а чтение значения обязано предоставить устройство. Конструктор базы не пытается читать ещё не готовый датчик.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Source { int id_; public: explicit Source(int id) : id_(id) {} int id() const { return id_; } virtual int read() const = 0; virtual ~Source() = default; };
class TestSource : public Source { public: TestSource() : Source(3) {} int read() const override { return 8; } };
int main() { TestSource s; std::cout << s.id() << ' ' << s.read() << '\n'; }
```

Ожидаемый вывод:

```text
3 8
```

## Разбор и эксперимент

Напишите вспомогательную функцию, принимающую const Source&amp;, и передайте TestSource. Объясните, почему ссылка допустима, а локальная переменная Source — нет. Проверьте, что общий id не дублируется в наследнике и инициализируется только конструктором базы.

## Практика

Абстрактный Source хранит private int id\_, создаётся explicit Source(int), имеет id() const, pure virtual read() const и virtual destructor. Sample(int id,int value) наследует его и возвращает своё value в read. solve(a,b) через const Source&amp; возвращает id()+read(). Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
