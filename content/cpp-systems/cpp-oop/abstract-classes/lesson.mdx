## Договор плюс общая часть

В прошлом уроке абстрактный класс был чистым договором: только чисто виртуальные функции. Но часто у всех наследников есть и **общее состояние**, и **общее поведение**. У всех персонажей игры есть имя и здоровье, все они одинаково получают урон и выбывают при нуле здоровья — а различаются только защитой и атакой. Абстрактный класс может содержать всё это сразу:

- поля, общие для всех наследников (закрытые, как обычно);
- реализованные методы, общие для всех;
- чисто виртуальные функции — то, что наследник обязан определить сам.

```cpp
#include <print>
#include <string>
#include <utility>

class Character {
public:
    virtual ~Character() = default;

    void take_hit(int damage) {
        int real = damage - defense();
        if (real < 0) {
            real = 0;
        }
        hp_ = real >= hp_ ? 0 : hp_ - real;
    }

    bool alive() const {
        return hp_ > 0;
    }

    void status() const {
        std::println("{}: {} hp{}", name_, hp_, alive() ? "" : " (выбыл)");
    }

protected:
    Character(std::string name, int hp) : name_(std::move(name)), hp_(hp) {}

private:
    virtual int defense() const = 0;

    std::string name_;
    int hp_;
};

class Warrior : public Character {
public:
    explicit Warrior(std::string name) : Character(std::move(name), 120) {}

private:
    int defense() const override {
        return 8;
    }
};

class Mage : public Character {
public:
    explicit Mage(std::string name) : Character(std::move(name), 70) {}

private:
    int defense() const override {
        return 2;
    }
};

int main() {
    Warrior w("Боромир");
    Mage m("Гэндальф");
    for (Character *c : {static_cast<Character *>(&w), static_cast<Character *>(&m)}) {
        c->take_hit(30);
        c->take_hit(50);
        c->status();
    }
    return 0;
}
```

Вывод:

```text
Боромир: 56 hp
Гэндальф: 0 hp (выбыл)
```

Правило получения урона — вычесть защиту, не опуститься ниже нуля — записано один раз в базе. Наследники отвечают только за то, что у них действительно разное. Это та же схема, что NVI из урока об `override`: открытый невиртуальный `take_hit` задаёт алгоритм, закрытая чисто виртуальная `defense` — шаг, который определяет наследник.

## Защищённый конструктор

Конструктор `Character` защищённый. Объект абстрактного класса и так нельзя создать, но `protected` сообщает читателю замысел: этот конструктор существует только для наследников. Через него наследник обязан передать имя и здоровье — забыть про общее состояние нельзя.

## Что класть в базу, а что — в наследника

| Вопрос                                        | Ответ «да» → где это место                     |
| --------------------------------------------- | ---------------------------------------------- |
| Есть у всех наследников и одинаково устроено? | поле или метод базы                            |
| Есть у всех, но устроено по-разному?          | чисто виртуальная функция                      |
| Есть у большинства, а у некоторых иначе?      | виртуальная функция с реализацией по умолчанию |
| Есть только у одного наследника?              | только в наследнике                            |

Третья строка — компромисс: реализация по умолчанию удобна, но наследник может забыть, что её стоит переопределить. Если «по умолчанию» на самом деле неверно для половины наследников, лучше `= 0`.

## Абстрактный класс или интерфейс

Абстрактный класс с полями и реализацией экономит код наследникам, но и связывает их: каждый наследник получает поля базы, её инвариант, её конструктор. Чистый интерфейс (только `= 0`) ничего не навязывает, и класс может реализовать несколько интерфейсов. Часто их сочетают: интерфейс — договор для клиентов, абстрактный класс — удобная общая реализация для части наследников.

```cpp
#include <print>
#include <string>
#include <utility>

class Payable {
public:
    virtual ~Payable() = default;
    virtual long long amount() const = 0;
};

class Bill : public Payable {
public:
    long long amount() const final {
        return base() + base() * vat_percent() / 100;
    }

protected:
    explicit Bill(long long base) : base_(base) {}

    long long base() const {
        return base_;
    }

private:
    virtual long long vat_percent() const = 0;
    long long base_;
};

class Food : public Bill {
public:
    explicit Food(long long base) : Bill(base) {}

private:
    long long vat_percent() const override {
        return 10;
    }
};

class Gadget : public Bill {
public:
    explicit Gadget(long long base) : Bill(base) {}

private:
    long long vat_percent() const override {
        return 20;
    }
};

class Fine : public Payable {
public:
    explicit Fine(long long sum) : sum_(sum) {}

    long long amount() const override {
        return sum_;
    }

private:
    long long sum_;
};

int main() {
    Food bread(5000);
    Gadget phone(3000000);
    Fine parking(300000);
    long long total = 0;
    for (const Payable *p : {static_cast<const Payable *>(&bread), static_cast<const Payable *>(&phone),
                             static_cast<const Payable *>(&parking)}) {
        total += p->amount();
    }
    std::println("{}", total);
    return 0;
}
```

Вывод:

```text
3905500
```

Клиенты видят интерфейс `Payable`. `Bill` — абстрактный класс для счетов с НДС: общее поле, общая формула, а ставка — у наследника. `Fine` реализует интерфейс напрямую: НДС к штрафу не относится, и базовая часть счёта ему не нужна.

<Tip title="Наследуемые конструкторы сохраняют доступ">

Запись `using Bill::Bill;` наследует конструкторы **вместе с их уровнем доступа**: защищённый конструктор базы останется защищённым и в наследнике, и `Food bread(5000);` не скомпилируется. Поэтому здесь у наследников свои открытые конструкторы, которые передают аргумент базе.

</Tip>

<Concept title="Абстрактный класс">

Абстрактный класс может хранить общее состояние (закрытые поля), реализовывать общее поведение и требовать от наследников чисто виртуальные шаги. Его конструктор делают защищённым: он нужен только наследникам. В базу выносят то, что общее и одинаковое, чисто виртуальными делают то, что общее, но разное. Абстрактный класс экономит код, но связывает наследников; чистый интерфейс ничего не навязывает — их часто сочетают.

</Concept>

## Частые ошибки

<CommonMistake title="Реализация по умолчанию, неверная для части наследников">

`virtual int defense() const { return 0; }` — наследник, забывший переопределить, окажется беззащитным без единого предупреждения. Если разумного значения по умолчанию нет — `= 0`.

</CommonMistake>

<CommonMistake title="Метод наследника с неверной сигнатурой">

`int defense()` без `const` не реализует `defense() const`, и наследник остаётся абстрактным: ошибка появится при создании объекта. Пишите `override` — компилятор укажет на метод.

</CommonMistake>

<CommonMistake title="Всё в базу «на будущее»">

Поле, нужное только одному наследнику, но положенное в базу, получат все. База разрастается и навязывает наследникам лишнее. Кладите в базу только общее.

</CommonMistake>

## Практика

1. **Транспорт** — общая формула времени и разные тарифы.
2. **Персонажи** — общее здоровье и разная защита.
3. **Найди ошибку: класс остался абстрактным** — неверная сигнатура переопределения.
4. **Банковские продукты** — общий месячный цикл и разные начисления.

## Итоги

- Абстрактный класс может содержать поля, реализованные методы и чисто виртуальные функции.
- Общее и одинаковое — в базе, общее, но разное — чисто виртуальными функциями, особенное — только в наследнике.
- Конструктор абстрактного класса делают защищённым.
- Реализация по умолчанию уместна, только если она верна почти для всех наследников.
- Абстрактный класс экономит код, но связывает наследников; интерфейс ничего не навязывает; их сочетают.
