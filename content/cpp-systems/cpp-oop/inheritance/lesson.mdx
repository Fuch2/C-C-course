## Задача и модель

Производный объект содержит базовый подобъект и собственные поля. Конструктор производного класса сначала создаёт базовую часть, затем свои поля. Деструктор выполняет обратный путь. Это позволяет расширять контракт, но одновременно связывает представление и правила времени жизни двух типов. Наследование не делает методы виртуальными автоматически.

## Как это работает в C++

Пример наследует идентификатор и добавляет номер канала. База предоставляет чтение id, оставляя поле закрытым. Производный конструктор явно вызывает конструктор базы, потому что база требует аргумент. При отсутствии такого вызова компилятор попытался бы создать базу без аргументов. Проверяйте смысл связи: каждый Channel является идентифицируемым объектом, однако не всякая пара похожих полей требует иерархии.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Identified { int id_; public: explicit Identified(int id) : id_(id) {} int id() const { return id_; } };
class Channel : public Identified { int port_; public: Channel(int id,int port) : Identified(id), port_(port) {} int port() const { return port_; } };
int main() { Channel c{4,7}; std::cout << c.id() << ' ' << c.port() << '\n'; }
```

Ожидаемый вывод:

```text
4 7
```

## Разбор и эксперимент

Добавьте в базу и наследника сообщения конструктора и деструктора, выпишите ожидаемый порядок до запуска в sandbox. Не удаляйте объект через базовый указатель, пока контракт удаления не изучен. Обычный локальный Channel уничтожается как полный конкретный объект.

<CommonMistake title="Ошибка, которую нужно заметить">

Не дублируйте поле базы в наследнике с тем же именем: это два разных состояния. Не пытайтесь присваиванием в теле конструктора заменить правильное создание базовой части.

</CommonMistake>
