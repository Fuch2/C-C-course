## Общее у разных классов

В программе учёта персонала есть сотрудники и руководители. У обоих — имя и оклад, оба умеют представиться. Но у руководителя есть ещё команда и надбавка за каждого подчинённого. Можно написать два независимых класса и продублировать общую часть — а потом исправлять каждую ошибку дважды. **Наследование** позволяет описать общее один раз в **базовом** классе, а в **производном** — только то, что добавляется:

```cpp
#include <print>
#include <string>
#include <utility>

class Employee {
public:
    Employee(std::string name, int salary) : name_(std::move(name)), salary_(salary) {}

    const std::string &name() const {
        return name_;
    }

    int salary() const {
        return salary_;
    }

    void introduce() const {
        std::println("Я {}, оклад {}", name_, salary_);
    }

private:
    std::string name_;
    int salary_;
};

class Manager : public Employee {
public:
    Manager(std::string name, int salary, int team) : Employee(std::move(name), salary), team_(team) {}

    int total_pay() const {
        return salary() + 5000 * team_;
    }

private:
    int team_;
};

int main() {
    Employee e("Ада", 120000);
    Manager m("Алан", 150000, 4);
    e.introduce();
    m.introduce();
    std::println("{} получает {}", m.name(), m.total_pay());
    return 0;
}
```

Вывод:

```text
Я Ада, оклад 120000
Я Алан, оклад 150000
Алан получает 170000
```

Запись `class Manager : public Employee` означает: «руководитель — это сотрудник, у которого есть ещё кое-что». У `Manager` есть всё, что открыто у `Employee`, — `name`, `salary`, `introduce` — и сверх того свой `total_pay`. Слово `public` перед именем базового класса — вид наследования; о нём следующий урок, пока считайте его обязательной частью записи.

## Базовая часть внутри объекта

Объект производного класса **содержит** объект базового класса — так называемый базовый подобъект — и дописывает к нему свои поля. В памяти `Manager` выглядит как `Employee` (имя и оклад), за которым идёт `team_`.

Закрытые поля базового класса остаются закрытыми и для наследника: `Manager` не может обратиться к `salary_` напрямую и пользуется открытым методом `salary()`. Это правильно: базовый класс охраняет свой инвариант, и наследник не должен уметь его нарушить.

## Конструкторы и деструкторы

Базовая часть создаётся **первой** — раньше полей наследника и его тела конструктора. Аргументы для неё передают в списке инициализации, вызывая конструктор базового класса по имени: `: Employee(std::move(name), salary)`. Если этого не сделать, компилятор попытается вызвать конструктор базового класса без аргументов — а у `Employee` его нет, и это ошибка компиляции.

Уничтожение — в обратном порядке: сначала тело деструктора наследника, потом его поля, потом базовая часть.

```cpp
#include <print>

class Base {
public:
    Base() {
        std::println("+ база");
    }
    ~Base() {
        std::println("- база");
    }
};

class Member {
public:
    Member() {
        std::println("+ поле");
    }
    ~Member() {
        std::println("- поле");
    }
};

class Derived : public Base {
public:
    Derived() {
        std::println("+ наследник");
    }
    ~Derived() {
        std::println("- наследник");
    }

private:
    Member member_;
};

int main() {
    Derived d;
    std::println("работа");
    return 0;
}
```

Вывод:

```text
+ база
+ поле
+ наследник
работа
- наследник
- поле
- база
```

Логика та же, что у композиции: дом строят с фундамента, а разбирают с крыши. Наследник может опираться на базовую часть в конструкторе и деструкторе — она уже (ещё) существует.

## Наследование конструкторов

Если наследник не добавляет полей, требующих инициализации, писать конструктор, который лишь передаёт аргументы базе, скучно. Запись `using Base::Base;` **наследует** конструкторы базового класса:

```cpp
#include <print>
#include <string>
#include <utility>

class Message {
public:
    explicit Message(std::string text) : text_(std::move(text)) {}

    const std::string &text() const {
        return text_;
    }

private:
    std::string text_;
};

class Warning : public Message {
public:
    using Message::Message;

    void show() const {
        std::println("ВНИМАНИЕ: {}", text());
    }
};

int main() {
    Warning w("заканчивается место на диске");
    w.show();
    return 0;
}
```

Вывод:

```text
ВНИМАНИЕ: заканчивается место на диске
```

## Метод с тем же именем

Наследник может объявить метод с тем же именем, что и в базе. Тогда при вызове **через объект наследника** будет вызван его метод — он **скрывает** базовый. Базовую версию можно вызвать явно, через имя класса:

```cpp
#include <print>
#include <string>
#include <utility>

class Employee {
public:
    explicit Employee(std::string name) : name_(std::move(name)) {}

    void introduce() const {
        std::println("Я {}", name_);
    }

private:
    std::string name_;
};

class Intern : public Employee {
public:
    using Employee::Employee;

    void introduce() const {
        Employee::introduce();
        std::println("  (стажёр)");
    }
};

int main() {
    Intern i("Грейс");
    i.introduce();
    return 0;
}
```

Вывод:

```text
Я Грейс
  (стажёр)
```

`Employee::introduce()` внутри метода наследника вызывает базовую версию — так наследник **дополняет** поведение, а не повторяет его. Но будьте внимательны: какая версия вызовется, здесь решает **тип в коде**, а не настоящий объект. Через ссылку `const Employee &` на стажёра вызовется базовый `introduce`. Как сделать, чтобы вызывалась версия настоящего объекта, — тема урока о `virtual`.

## Когда наследование уместно

Наследование выражает отношение **«является»**: руководитель _является_ сотрудником, предупреждение _является_ сообщением. Проверка простая: можно ли сказать о производном объекте всё, что верно о базовом? Если нет — наследование неуместно, даже если оно экономит пару строк. Квадрат как наследник прямоугольника, стек как наследник вектора, машина как наследник двигателя — классические ошибки: машина не _является_ двигателем, она его _содержит_ (композиция).

<Concept title="Наследование">

`class D : public B` — производный класс содержит базовую часть `B` и добавляет свои поля и методы; открытые члены `B` доступны через объект `D`, закрытые — нет даже наследнику. Базовая часть создаётся первой (её конструктор вызывают в списке инициализации) и уничтожается последней. `using B::B;` наследует конструкторы. Метод наследника с тем же именем скрывает базовый; `B::метод()` вызывает базовую версию. Наследование выражает отношение «является».

</Concept>

## Частые ошибки

<CommonMistake title="Поле, дублирующее поле базы">

Наследник объявляет своё поле `name_`, «чтобы было где хранить имя», и заполняет его, а база продолжает пользоваться своим `name_`. В объекте теперь два имени, и методы базы видят не то. Передавайте данные в конструктор базы.

</CommonMistake>

<CommonMistake title="Забытый вызов конструктора базы">

Без `: Base(…)` в списке инициализации компилятор вызывает конструктор базы без аргументов. Если его нет — ошибка компиляции, а если есть — база молча получает значения по умолчанию.

</CommonMistake>

<CommonMistake title="Наследование ради повторного использования кода">

`class Stack : public std::vector<int>` даёт стеку `insert` в середину, `operator[]` и всё остальное, что ломает идею стека. Если отношения «является» нет, используйте композицию.

</CommonMistake>

## Практика

1. **Сотрудники** — базовый класс и наследник с надбавкой.
2. **Устройства** — общая часть и разные наследники.
3. **Найди ошибку: два имени** — наследник дублирует поле базы.
4. **Сберегательный счёт** — наследник дополняет поведение базы.

## Итоги

- Наследование описывает общее в базовом классе, а в производном — только добавленное: `class D : public B`.
- Объект наследника содержит базовую часть; закрытые члены базы недоступны и наследнику.
- Базовая часть создаётся первой и уничтожается последней; её конструктор вызывают в списке инициализации, `using B::B;` наследует конструкторы.
- Метод с тем же именем скрывает базовый; `B::метод()` вызывает базовую версию. Выбор версии здесь определяет тип в коде.
- Наследование уместно только для отношения «является»; для «содержит» — композиция.
