## Объект, у которого отрезали часть

Объект наследника — это базовая часть плюс поля наследника. Если скопировать его **в объект базового типа**, копируется только базовая часть: в переменной типа `Animal` просто нет места для полей кошки и нет «кошачьей» таблицы виртуальных функций. Такую потерю называют **срезкой** (object slicing).

```cpp
#include <print>
#include <string>
#include <utility>

class Animal {
public:
    explicit Animal(std::string name) : name_(std::move(name)) {}
    virtual ~Animal() = default;

    virtual std::string sound() const {
        return "...";
    }

    const std::string &name() const {
        return name_;
    }

private:
    std::string name_;
};

class Cat : public Animal {
public:
    using Animal::Animal;

    std::string sound() const override {
        return "мяу";
    }
};

void by_value(Animal a) {
    std::println("по значению: {} говорит {}", a.name(), a.sound());
}

void by_ref(const Animal &a) {
    std::println("по ссылке: {} говорит {}", a.name(), a.sound());
}

int main() {
    Cat murka("Мурка");
    by_value(murka);
    by_ref(murka);
    return 0;
}
```

Вывод:

```text
по значению: Мурка говорит ...
по ссылке: Мурка говорит мяу
```

`by_value` получила копию базовой части: имя сохранилось (оно в базе), а поведение кошки исчезло. Компилятор не предупреждает — копирование наследника в базу законно, это обычное преобразование «вверх».

## Где прячется срезка

Срезка возникает везде, где полиморфный объект копируется в переменную базового типа:

| Код                                            | Что происходит                          |
| ---------------------------------------------- | --------------------------------------- |
| `void f(Animal a)`                             | параметр — копия базовой части          |
| `Animal a = cat;`                              | переменная — копия базовой части        |
| `std::vector<Animal> zoo; zoo.push_back(cat);` | вектор хранит базовые части             |
| `catch (std::exception e)`                     | исключение-наследник обрезается до базы |
| `Animal f() { Cat c; return c; }`              | возвращается копия базовой части        |

Последняя строка таблицы особенно коварна для исключений: `catch (std::exception e)` теряет текст сообщения наследника, если тот хранит его сам, а `e.what()` возвращает базовую версию. Исключения ловят по **константной ссылке**: `catch (const std::exception &e)`.

## Частичное присваивание

Ещё одна форма срезки — присваивание через ссылки на базу. Оно копирует только базовую часть, а производная часть приёмника остаётся старой:

```cpp
#include <print>
#include <string>
#include <utility>

class Account {
public:
    explicit Account(std::string owner) : owner_(std::move(owner)) {}
    virtual ~Account() = default;
    const std::string &owner() const {
        return owner_;
    }

private:
    std::string owner_;
};

class Savings : public Account {
public:
    Savings(std::string owner, int rate) : Account(std::move(owner)), rate_(rate) {}
    int rate() const {
        return rate_;
    }

private:
    int rate_;
};

int main() {
    Savings a("Ада", 5), b("Алан", 12);
    Account &ra = a;
    const Account &rb = b;
    ra = rb;                                     // копируется только базовая часть
    std::println("{} {}", a.owner(), a.rate());
    return 0;
}
```

Вывод:

```text
Алан 5
```

Получился «гибрид»: владелец от одного счёта, ставка от другого. Такого объекта никто не создавал, и его инвариант может быть нарушен.

## Как защититься

1. **Передавайте полиморфные объекты по ссылке или указателю**, храните — через `std::unique_ptr<База>`.
2. **Запретите копирование полиморфной базы.** C++ Core Guidelines (C.67) советуют подавлять открытое копирование в базовых классах иерархий: тогда срезка становится ошибкой компиляции.

```cpp
#include <print>

class Shape {
public:
    Shape() = default;
    virtual ~Shape() = default;
    Shape(const Shape &) = delete;
    Shape &operator=(const Shape &) = delete;

    virtual double area() const = 0;
};

class Square final : public Shape {
public:
    explicit Square(double s) : s_(s) {}
    double area() const override {
        return s_ * s_;
    }

private:
    double s_;
};

void report(const Shape &s) {
    std::println("{}", s.area());
}

int main() {
    Square sq(3);
    report(sq);
    return 0;
}
```

Вывод:

```text
9
```

Теперь `void f(Shape s)` или `Shape copy = sq;` не скомпилируются: копирование базы удалено. А передача по ссылке работает как прежде.

## Как же тогда копировать?

Если полиморфный объект всё-таки нужно скопировать целиком, не зная его настоящего типа, используют виртуальную функцию **`clone()`**: каждый класс умеет создать свою копию.

```cpp
#include <memory>
#include <print>
#include <vector>

class Shape {
public:
    Shape() = default;
    virtual ~Shape() = default;
    Shape(const Shape &) = delete;
    Shape &operator=(const Shape &) = delete;

    virtual double area() const = 0;
    virtual std::unique_ptr<Shape> clone() const = 0;
};

class Square final : public Shape {
public:
    explicit Square(double s) : s_(s) {}

    double area() const override {
        return s_ * s_;
    }

    std::unique_ptr<Shape> clone() const override {
        return std::make_unique<Square>(s_);
    }

private:
    double s_;
};

int main() {
    std::vector<std::unique_ptr<Shape>> original;
    original.push_back(std::make_unique<Square>(2));
    original.push_back(std::make_unique<Square>(5));
    std::vector<std::unique_ptr<Shape>> copy;
    for (const auto &s : original) {
        copy.push_back(s->clone());
    }
    std::println("{} {} {}", copy.size(), copy[0]->area(), copy[1]->area());
    return 0;
}
```

Вывод:

```text
2 4 25
```

`clone()` — виртуальная, поэтому вызывается версия настоящего объекта, и копия получается полной. Это шаблон «Прототип».

<Concept title="Срезка">

Срезка — копирование наследника в объект базового типа, при котором теряются поля и поведение наследника: передача и возврат по значению, `std::vector<База>`, `catch` по значению, присваивание через ссылки на базу (частичное присваивание). Защита: полиморфные объекты передают по ссылке и хранят через `std::unique_ptr`, а копирование полиморфной базы удаляют (`= delete`). Полная копия неизвестного наследника — виртуальная функция `clone()`.

</Concept>

## Частые ошибки

<CommonMistake title="Параметр базового типа по значению">

`void feed(Animal a)` обрезает любое животное до базы. Принимайте `const Animal &`.

</CommonMistake>

<CommonMistake title="catch по значению">

`catch (std::exception e)` обрезает исключение и копирует его. Всегда `catch (const std::exception &e)`.

</CommonMistake>

<CommonMistake title="Вектор базового типа">

`std::vector<Animal>` для разных животных хранит только базовые части. Нужен `std::vector<std::unique_ptr<Animal>>`.

</CommonMistake>

## Практика

1. **Клонирование** — копия вектора разнотипных фигур через `clone()`.
2. **Ошибки по ссылке** — иерархия исключений и `catch` по константной ссылке.
3. **Найди ошибку: потерянный голос** — передача по значению.
4. **Шаблоны документов** — прототипы и создание копий по имени.

## Итоги

- Срезка: копия наследника в объект базового типа теряет поля и поведение наследника; компилятор молчит.
- Она возникает при передаче и возврате по значению, в `std::vector<База>`, в `catch` по значению и при присваивании через ссылки на базу.
- Полиморфные объекты передают по ссылке, хранят в `std::unique_ptr<База>`, исключения ловят по `const &`.
- Копирование полиморфной базы удаляют (`= delete`) — срезка становится ошибкой компиляции.
- Полную копию неизвестного наследника даёт виртуальная `clone()`.
