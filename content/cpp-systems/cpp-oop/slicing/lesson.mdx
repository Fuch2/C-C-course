## Задача и модель

При копировании производного объекта в отдельное значение базового типа сохраняется только базовая часть. Это object slicing. Новый объект действительно является базой: дополнительное состояние потеряно, виртуальные вызовы используют его базовую реализацию. Это не ошибка виртуальной таблицы и не повод применять cast.

## Как это работает в C++

Такая копия возникает незаметно в параметре Base value, при push_back в vector&lt;Base> или возврате Base по значению. Передавайте полиморфные объекты по ссылке, а владение — через указатель с корректным деструктором. Если требуется независимая полиморфная копия, нужен явный контракт clone; в этом модуле процессор не копируется. Абстрактная база предотвращает часть срезок на этапе компиляции, поскольку отдельное значение базы создать нельзя.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Base { virtual int read() const { return 1; } virtual ~Base() = default; };
struct Derived : Base { int read() const override { return 9; } };
int main() { Derived d; Base copy=d; const Base& ref=d; std::cout << copy.read() << ' ' << ref.read() << '\n'; }
```

Ожидаемый вывод:

```text
1 9
```

## Разбор и эксперимент

Замените локальную срезку передачей Base по значению в функцию и предскажите ту же потерю поведения. Затем используйте const Base&amp;. Срезка сама по себе может быть определённым копированием; дефект в том, что вызывающий код ожидал сохранения производного состояния.

## Практика

Base возвращает 1 из virtual read() const, имеет virtual destructor. Derived(int) возвращает своё число. Исправьте consumer так, чтобы int consumer(const Base&amp;) сохранял полиморфизм. solve(a,b) создаёт Derived&#123;a&#125; и возвращает consumer(d)+b. Передача базы по значению запрещена контрактом.
