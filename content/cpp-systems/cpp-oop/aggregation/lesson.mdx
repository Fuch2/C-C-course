## Задача и модель

При агрегации объект использует независимо живущую часть и не уничтожает её. В C++ это договорённость о владении, а не отдельное ключевое слово. Ссылка подходит для обязательной зависимости; указатель — если отсутствие допустимо и явно обработано. Тип ссылки не продлевает произвольно время жизни внешнего объекта.

## Как это работает в C++

В примере View заимствует источник и видит последующие изменения. Это принципиально отличается от копии состояния. Владелец должен существовать дольше всех обращений View. Поэтому источник объявлен первым, наблюдатель вторым, а разрушение происходит наоборот. Копирование объекта со ссылочным полем сохраняет ссылку на тот же источник. Не выбирайте shared_ptr автоматически: совместное владение — иной контракт, который нужен далеко не каждой зависимости.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Source { int value{2}; };
class View { const Source& source_; public: explicit View(const Source& s) : source_(s) {} int read() const { return source_.value; } };
int main() { Source s; View v{s}; s.value=9; std::cout << v.read() << '\n'; }
```

Ожидаемый вывод:

```text
9
```

## Разбор и эксперимент

Предскажите результат, если в View вместо const Source&amp; хранить Source. Внешнее изменение перестанет быть видно. Затем рассмотрите перемещение владельца Source в контейнере: ссылка может стать висячей при перераспределении памяти. Стабильность адреса входит в обязательства владельца.

## Практика

Создайте Source с public int value и View с private const Source&amp;. View(const Source&amp;) сохраняет ссылку, read() const возвращает актуальное value. solve(a,b) создаёт Source&#123;a&#125;, затем View, меняет источник на b и возвращает view.read(). Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
