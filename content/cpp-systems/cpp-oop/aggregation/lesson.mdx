## Пользоваться, но не владеть

При композиции целое владеет частями: двигатель создаётся и уничтожается вместе с машиной. Но часто объекту нужен другой объект, которым он **не владеет**. Сервисы программы пишут в один общий журнал; читатель берёт книгу из библиотеки, но книга принадлежит библиотеке; табло показывает температуру с термометра, который существует и без табло.

Такое отношение называют **агрегацией** или **использованием**: объект хранит ссылку или указатель на чужой объект и пользуется им, но не создаёт и не уничтожает его.

| Отношение  | Хранится как                          | Кто уничтожает часть |
| ---------- | ------------------------------------- | -------------------- |
| композиция | поле-объект: `Engine engine_;`        | целое, автоматически |
| агрегация  | ссылка или указатель: `Logger &log_;` | кто-то другой        |

## Общий журнал

```cpp
#include <print>
#include <string>
#include <utility>
#include <vector>

class Logger {
public:
    void write(const std::string &message) {
        lines_.push_back(message);
    }

    void dump() const {
        for (std::size_t i = 0; i < lines_.size(); i++) {
            std::println("{}. {}", i + 1, lines_[i]);
        }
    }

private:
    std::vector<std::string> lines_;
};

class Account {
public:
    Account(std::string owner, Logger &log) : owner_(std::move(owner)), log_(log) {}

    void deposit(int amount) {
        balance_ += amount;
        log_.write(owner_ + ": +" + std::to_string(amount));
    }

private:
    std::string owner_;
    Logger &log_;
    int balance_ = 0;
};

int main() {
    Logger log;
    Account a("Ада", log);
    Account b("Алан", log);
    a.deposit(100);
    b.deposit(50);
    a.deposit(20);
    log.dump();
    return 0;
}
```

Вывод:

```text
1. Ада: +100
2. Алан: +50
3. Ада: +20
```

Оба счёта пишут в **один** журнал: поле `Logger &log_` — ссылка на объект из `main`. Журнал создан раньше счетов и живёт дольше них, поэтому ссылка всё время действительна. Если бы каждый счёт хранил `Logger` полем, у каждого был бы свой отдельный журнал — композиция здесь означала бы совсем другое.

## Зависимость — через конструктор

`Account` получает журнал **снаружи**, в конструкторе, а не создаёт его сам и не обращается к глобальной переменной. Такой приём называют **внедрением зависимости** (dependency injection). Он делает зависимость видимой в сигнатуре и позволяет подставить другой объект: в тестах — журнал, который ничего не печатает или проверяет записи; в программе — журнал, пишущий в файл. Позже, в уроках об интерфейсах, вы увидите, как подставлять объекты разных классов.

## Ссылка или указатель

Невладеющую связь хранят ссылкой или указателем:

| Поле                 | Когда                                                |
| -------------------- | ---------------------------------------------------- |
| `Logger &log_`       | связь обязательна и не меняется за всю жизнь объекта |
| `Logger *log_`       | связь может отсутствовать (`nullptr`) или меняться   |
| `const Logger *log_` | то же, но объект только читается                     |

У поля-ссылки есть особенность: её нельзя «перенаправить», поэтому объект с таким полем нельзя присвоить (`a = b` не скомпилируется). Если присваивание нужно — используют указатель.

```cpp
#include <print>

class Thermometer {
public:
    void set(double t) {
        value_ = t;
    }

    double value() const {
        return value_;
    }

private:
    double value_ = 20;
};

class Display {
public:
    void connect(const Thermometer *source) {
        source_ = source;
    }

    void show() const {
        if (source_ == nullptr) {
            std::println("нет датчика");
            return;
        }
        std::println("{:.1f} °C", source_->value());
    }

private:
    const Thermometer *source_ = nullptr;
};

int main() {
    Thermometer kitchen, street;
    street.set(-7.5);
    Display display;
    display.show();
    display.connect(&kitchen);
    display.show();
    display.connect(&street);
    display.show();
    return 0;
}
```

Вывод:

```text
нет датчика
20.0 °C
-7.5 °C
```

Табло может быть ни к чему не подключено, а потом переключиться на другой термометр — поэтому указатель. Указатель на константу подчёркивает: табло только читает показания.

## Главный риск — время жизни

Агрегация опирается на обещание: **используемый объект живёт дольше использующего**. Компилятор это обещание не проверяет. Если оно нарушено, ссылка «повисает»:

```cpp
#include <print>
#include <string>

class Label {
public:
    explicit Label(const std::string &text) : text_(text) {}

    void print() const {
        std::println("[{}]", text_);
    }

private:
    const std::string &text_;
};

Label make_label() {
    std::string text = "длинная надпись для этикетки товара";
    return Label(text);              // ссылка на локальную строку
}

int main() {
    Label label = make_label();
    label.print();                   // Ошибка памяти
    return 0;
}
```

`Label` хранит ссылку на строку, которая уничтожена при выходе из `make_label`. AddressSanitizer сообщает о чтении освобождённой памяти. Строку здесь нужно было хранить **значением** — `std::string text_;`: надпись — часть этикетки, это композиция, а не использование.

Правила, которые спасают от висячих связей:

1. Если объект — часть целого и нужен только ему, храните его **полем** (композиция).
2. Ссылку или указатель храните, только если ясно, кто владелец и что он живёт дольше: например, объект создан раньше в той же функции или принадлежит долгоживущему владельцу.
3. Не храните ссылки на элементы `std::vector`, который ещё будет расти: при перевыделении памяти они повиснут.

<Concept title="Агрегация">

Агрегация — объект пользуется чужим объектом, не владея им: хранит ссылку (связь обязательна и постоянна) или указатель (может отсутствовать или меняться), но не создаёт и не уничтожает его. Зависимость передают в конструкторе — внедрение зависимости. Используемый объект обязан жить дольше использующего; компилятор этого не проверяет. Если объект — часть целого, нужна композиция.

</Concept>

## Частые ошибки

<CommonMistake title="Ссылка на временный или локальный объект">

`Label(std::string("текст"))` или ссылка на локальную переменную функции — объект исчезает, а ссылка остаётся. Если время жизни не гарантировано, храните копию.

</CommonMistake>

<CommonMistake title="Указатели на элементы растущего вектора">

`readers.push_back(Reader(&books[0]))`, а потом `books.push_back(…)` — вектор книг переехал, и указатель висит. Сначала заполните контейнер, потом раздавайте указатели — или храните индексы.

</CommonMistake>

<CommonMistake title="Глобальный объект вместо зависимости">

Класс, который сам обращается к глобальному журналу, нельзя проверить с другим журналом, а его зависимость не видна в объявлении. Передавайте зависимость в конструкторе.

</CommonMistake>

<CommonMistake title="delete чужого объекта">

Невладеющий указатель нельзя освобождать: объектом владеет кто-то другой, и он сделает это сам. Двойное освобождение — неопределённое поведение.

</CommonMistake>

## Практика

1. **Журнал операций** — несколько объектов пишут в один журнал.
2. **Табло** — подключение и переключение источника данных.
3. **Найди ошибку: висячая надпись** — ссылка на уничтоженную строку.
4. **Наблюдатели** — датчик оповещает подписчиков, не владея ими.

## Итоги

- Агрегация — использование чужого объекта без владения: поле-ссылка или поле-указатель.
- Ссылка — для обязательной постоянной связи (объект с ней не присваивается); указатель — для необязательной или меняющейся.
- Зависимость передают в конструкторе — так её видно и можно подменить.
- Используемый объект обязан жить дольше использующего: компилятор это не проверяет, нарушение даёт висячие ссылки.
- Если объект — часть целого, нужна композиция: поле-значение.
