## Закрыть расширение

Наследование — сильный инструмент, но не каждый класс для него предназначен. Класс, от которого наследуют, должен быть **спроектирован** под это: понятный договор для наследников, виртуальный деструктор, продуманные защищённые операции. Если класс так не проектировали, наследник легко нарушит его инвариант или будет зависеть от деталей, которые завтра изменятся.

Слово `final` позволяет сказать это явно и проверяемо:

- `class Money final { … };` — от класса **нельзя наследовать**;
- `void f() const final;` — виртуальную функцию **нельзя переопределять дальше** в наследниках этого класса.

## Финальный класс

```cpp
#include <print>

class Money final {
public:
    explicit Money(long long kopecks) : kopecks_(kopecks) {}

    long long kopecks() const {
        return kopecks_;
    }

private:
    long long kopecks_;
};

class Bonus : public Money {         // Ошибка компиляции: cannot derive from 'final' base 'Money'
public:
    using Money::Money;
};

int main() {
    Bonus b(100);
    std::println("{}", b.kopecks());
    return 0;
}
```

`Money` — тип-значение: его копируют, сравнивают, складывают. Наследник мог бы добавить поля, которые потерялись бы при копировании в `Money` (срезка), или поменять смысл операций. `final` закрывает эту возможность, и ошибка становится видна сразу, а не после жалобы пользователя.

Многие типы стандартной библиотеки не помечены `final` по историческим причинам, но и не предназначены для наследования: `std::string`, `std::vector`, `std::map` не имеют виртуального деструктора. Для своих типов-значений `final` — хорошая привычка.

## Финальное переопределение

Иногда класс в середине иерархии реализует виртуальную функцию так, что дальше её менять нельзя: например, проверяет безопасность или считает что-то, на что опирается инвариант.

```cpp
#include <print>
#include <string>

class Payment {
public:
    virtual ~Payment() = default;
    virtual bool authorize(long long amount) const = 0;
    virtual std::string name() const = 0;
};

class CardPayment : public Payment {
public:
    bool authorize(long long amount) const final {
        return amount > 0 && amount <= limit();
    }

protected:
    virtual long long limit() const {
        return 100000;
    }
};

class GoldCard : public CardPayment {
public:
    std::string name() const override {
        return "золотая карта";
    }

protected:
    long long limit() const override {
        return 1000000;
    }
};

int main() {
    GoldCard card;
    const Payment &p = card;
    std::println("{}: {} {}", p.name(), p.authorize(500000), p.authorize(-1));
    return 0;
}
```

Вывод:

```text
золотая карта: true false
```

`CardPayment::authorize` помечен `final`: правило «сумма положительна и не превышает лимит» не может переписать ни один наследник карты. Наследникам оставлена ровно одна точка расширения — `limit()`. Попытка переопределить `authorize` в `GoldCard` даст ошибку `overriding final function`.

Обратите внимание: `final` у функции подразумевает `override` — такая функция обязана переопределять виртуальную функцию базы, иначе тоже ошибка компиляции.

## `final` помогает оптимизатору

Если класс финальный, компилятор знает, что у объекта этого типа нет наследников. Вызов виртуальной функции через объект, ссылку или указатель **на финальный класс** можно выполнить напрямую, без таблицы виртуальных функций, и даже встроить. Это называют **девиртуализацией**. Выигрыш обычно небольшой, но бесплатный: `final` пишут ради ясности проекта, а скорость получают в подарок.

## Когда ставить `final`

| Ситуация                                                         | Решение                           |
| ---------------------------------------------------------------- | --------------------------------- |
| тип-значение: деньги, координаты, дата                           | `final` на класс                  |
| конкретный «лист» иерархии, у которого не планируются наследники | `final` на класс                  |
| функция, задающая обязательное правило для всех наследников      | `final` на функцию                |
| базовый класс, спроектированный для расширения                   | без `final`, с понятным договором |

Часть сообщества предлагает ставить `final` на все классы по умолчанию и снимать его, когда наследование действительно понадобится и класс будет к нему подготовлен. Снять `final` — безопасное изменение: ничей код не сломается. А вот добавить `final` к классу, от которого уже наследуют, — несовместимое изменение.

<Concept title="final">

`class X final` запрещает наследовать от класса, `f() final` — переопределять виртуальную функцию дальше. Это способ закрепить замысел: класс не спроектирован для расширения или правило не должно меняться. `final` у функции подразумевает `override`. Финальные классы позволяют компилятору вызывать виртуальные функции напрямую (девиртуализация). Снять `final` позже безопасно, добавить — нет.

</Concept>

## Частые ошибки

<CommonMistake title="Наследование от типа-значения">

`class Discounted : public Money` с новым полем: при передаче в функцию, принимающую `Money` по значению, поле теряется. Объявляйте типы-значения `final`.

</CommonMistake>

<CommonMistake title="final вместо override">

`final` у функции, которая ничего не переопределяет, — ошибка компиляции, так же как `override`. Пишите `final` только там, где переопределение действительно последнее.

</CommonMistake>

<CommonMistake title="final на базе, предназначенной для расширения">

Если класс задуман как точка расширения (интерфейс плагина, базовый обработчик), `final` делает его бесполезным. Закрывайте только то, что не проектировали под наследование.

</CommonMistake>

## Практика

1. **Финальные значения** — тип-значение, закрытый от наследования.
2. **Правило авторизации** — финальная функция и одна точка расширения.
3. **Найди ошибку: правило обойдено** — наследник переопределил обязательную проверку.
4. **Тарифы** — иерархия с финальными листьями.

## Итоги

- `class X final` — от класса нельзя наследовать; `f() final` — функцию нельзя переопределять дальше.
- Наследование нужно проектировать; `final` закрепляет, что класс или правило для расширения не предназначены.
- Типы-значения и «листья» иерархии делают финальными; обязательные правила — финальными функциями.
- `final` у функции подразумевает `override`.
- Компилятор может девиртуализировать вызовы через финальные классы.
- Снять `final` безопасно, добавить к уже расширяемому классу — нет.
