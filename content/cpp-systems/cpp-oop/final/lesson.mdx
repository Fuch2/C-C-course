## Задача и модель

final у класса запрещает наследование от него. final у виртуального метода запрещает дальнейшее переопределение этого метода, но не обязательно наследование от всего класса. Так фиксируют поведение законченного адаптера или критическую часть контракта. final не делает поля неизменяемыми и не заменяет const.

## Как это работает в C++

В примере Fixed — конечная реализация интерфейса. Клиент по-прежнему работает через базовую ссылку. Для компилятора final иногда помогает убрать косвенный вызов, но гарантии ускорения нет: решение зависит от видимости кода и оптимизации. Главная причина использования — архитектурное ограничение. Не закрывайте каждую точку расширения автоматически: новый тип датчика должен добавляться через интерфейс Sensor, даже если конкретные TemperatureSensor и PressureSensor закончены.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Base { virtual int read() const = 0; virtual ~Base() = default; };
struct Fixed final : Base { int read() const override { return 12; } };
int main() { Fixed f; const Base& b=f; std::cout << b.read() << '\n'; }
```

Ожидаемый вывод:

```text
12
```

## Разбор и эксперимент

Рассмотрите класс-наследник от класса с final методом. Дополнительные новые методы допустимы, переопределение закрытого метода — нет. Сравните это с final на самом классе. Не обещайте ускорение из одного ключевого слова без измерений сборки с оптимизацией.

Не объясняйте final как «объект больше нельзя менять». Это запрет наследования или переопределения; методы могут продолжать менять собственное состояние.

## Практика

Создайте Base с virtual int read() const = 0 и виртуальным деструктором. Fixed final : public Base хранит значение из explicit Fixed(int) и возвращает его в read() const override. solve(a,b) создаёт два Fixed и возвращает разность read через две const Base&amp;. Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
