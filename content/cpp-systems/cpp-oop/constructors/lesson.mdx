## Задача и модель

Конструктор задаёт начальное состояние объекта и не имеет возвращаемого типа. Список инициализации создаёт поля непосредственно: это особенно важно для const полей, ссылок и объектов без конструктора по умолчанию. Поля инициализируются в порядке объявления в классе, независимо от порядка записей в списке. explicit предотвращает нежелательное неявное преобразование аргумента в объект.

## Как это работает в C++

В теле конструктора поля уже существуют, поэтому присваивание там может означать лишнюю работу. Базовые подобъекты создаются раньше полей, тело выполняется последним. Если конструктор выбрасывает исключение, полного объекта не существует, а уже созданные члены разрушаются автоматически. Для учебного измерения некорректную границу можно либо отвергнуть исключением, либо явно нормализовать; контракт обязан назвать выбранную политику.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Gain { const int factor_; public: explicit Gain(int factor) : factor_(factor) {} int apply(int x) const { return factor_ * x; } };
int main() { Gain g{3}; std::cout << g.apply(4) << '\n'; }
```

Ожидаемый вывод:

```text
12
```

## Разбор и эксперимент

Добавьте второй const член и объясните, почему присваивание в теле конструктора не подходит. Затем рассмотрите explicit: прямая инициализация Gain&#123;3&#125; разрешена, автоматическое превращение числа в Gain при передаче функции запрещено. Такой барьер помогает не спутать значение с настройкой.
