## Объект сразу готов к работе

В прошлом уроке у классов были значения полей по умолчанию: громкость 50, лифт на первом этаже. Но у многих объектов нет разумного «пустого» состояния. Какой дробью сделать дробь по умолчанию? Каким должен быть счёт без владельца? Если создать объект «пустым», а настроить потом, между этими моментами он существует в недопустимом состоянии — и кто-нибудь успеет им воспользоваться.

**Конструктор** — особый метод, который вызывается при создании объекта и получает всё, что нужно для допустимого начального состояния. Его имя совпадает с именем класса, а возвращаемого типа у него нет:

```cpp
#include <numeric>
#include <print>
#include <stdexcept>

class Fraction {
public:
    Fraction(int numerator, int denominator) {
        if (denominator == 0) {
            throw std::invalid_argument("знаменатель равен нулю");
        }
        if (denominator < 0) {
            numerator = -numerator;
            denominator = -denominator;
        }
        int g = std::gcd(numerator, denominator);
        num_ = numerator / g;
        den_ = denominator / g;
    }

    int numerator() const {
        return num_;
    }

    int denominator() const {
        return den_;
    }

private:
    int num_;
    int den_;
};

int main() {
    Fraction a(6, -8);
    std::println("{}/{}", a.numerator(), a.denominator());
    try {
        Fraction bad(1, 0);
    } catch (const std::invalid_argument &e) {
        std::println("ошибка: {}", e.what());
    }
    return 0;
}
```

Вывод:

```text
-3/4
ошибка: знаменатель равен нулю
```

Инвариант дроби — «знаменатель положительный, дробь несократима» — устанавливается в конструкторе, и других способов создать `Fraction` нет. Если аргументы недопустимы, конструктор бросает исключение, и объект **не создаётся вовсе**: не существует дроби, которую можно было бы использовать по ошибке. `std::gcd` из `<numeric>` (C++17) — наибольший общий делитель.

## Список инициализации

У конструктора есть специальное место для начальных значений полей — **список инициализации** после двоеточия:

```cpp
#include <print>
#include <string>
#include <utility>

class Book {
public:
    Book(std::string title, int pages)
        : title_(std::move(title)), pages_(pages > 0 ? pages : 1) {}

    void print() const {
        std::println("«{}», {} стр.", title_, pages_);
    }

private:
    std::string title_;
    int pages_;
};

int main() {
    Book b("Язык программирования C", 288);
    b.print();
    Book empty("Черновик", 0);
    empty.print();
    return 0;
}
```

Вывод:

```text
«Язык программирования C», 288 стр.
«Черновик», 1 стр.
```

Разница с присваиванием в теле конструктора принципиальная. К моменту, когда выполняется тело, все поля **уже созданы**: присваивание в теле — это создание поля значением по умолчанию, а потом замена. Список инициализации создаёт поле сразу нужным значением. Для `int` разница незаметна, но:

- поле-константу (`const int id_`) и поле-ссылку можно только **инициализировать** — присвоить им нельзя;
- поле типа без конструктора по умолчанию нельзя создать «пустым»;
- для строк и контейнеров лишнее создание и замена — лишняя работа.

Поэтому правило: **поля инициализируют в списке**, а тело конструктора оставляют для проверок и вычислений. `std::move(title)` передаёт строку в поле без копирования — подробно о перемещении в модуле «Время жизни объектов».

## Порядок инициализации

Поля инициализируются **в порядке объявления в классе**, а не в порядке записи в списке:

```cpp
#include <print>

class Stats {
public:
    Stats(int total, int count) : count_(count), average_(static_cast<double>(total) / count_) {}

    double average() const {
        return average_;
    }

private:
    int count_;            // объявлено первым — инициализируется первым
    double average_;
};

int main() {
    Stats s(10, 4);
    std::println("{}", s.average());
    return 0;
}
```

Вывод:

```text
2.5
```

Здесь всё правильно: `count_` объявлено раньше `average_`, поэтому к моменту вычисления среднего оно уже готово. Поменяйте поля местами в объявлении — и `average_` будет вычислено из ещё **не инициализированного** `count_`, то есть из мусора. GCC и Clang предупреждают об этом при `-Wall`: `field 'count_' will be initialized after field 'average_'` (`-Wreorder`). Записывайте список в порядке объявления полей — тогда то, что вы читаете, совпадает с тем, что происходит.

## Конструктор по умолчанию и `= default`

Конструктор без параметров называется **конструктором по умолчанию**. Пока в классе нет ни одного конструктора, компилятор создаёт его сам. Но как только вы объявили любой свой конструктор, автоматический исчезает: `Fraction f;` для дроби выше — ошибка компиляции. Это правильно: у дроби нет разумного значения «по умолчанию».

Если конструктор по умолчанию нужен, его возвращают явно:

```cpp
#include <print>

class Point {
public:
    Point() = default;
    Point(int x, int y) : x_(x), y_(y) {}

    void print() const {
        std::println("({}, {})", x_, y_);
    }

private:
    int x_ = 0;
    int y_ = 0;
};

int main() {
    Point origin;
    Point p(3, 4);
    Point q{5, 6};
    origin.print();
    p.print();
    q.print();
    return 0;
}
```

Вывод:

```text
(0, 0)
(3, 4)
(5, 6)
```

`= default` просит компилятор создать обычную версию: поля получают значения по умолчанию из объявления. Объект можно создать круглыми скобками `p(3, 4)` или фигурными `q{5, 6}` — во втором случае компилятор запретит сужающие преобразования вроде `Point q{1.5, 2}`.

## Делегирование и `explicit`

Конструкторов может быть несколько — это обычная перегрузка. Один конструктор может **делегировать** работу другому, указав его в списке инициализации:

```cpp
#include <print>

class Duration {
public:
    explicit Duration(int minutes) : minutes_(minutes < 0 ? 0 : minutes) {}
    Duration(int hours, int minutes) : Duration(hours * 60 + minutes) {}

    void print() const {
        std::println("{} ч {} мин", minutes_ / 60, minutes_ % 60);
    }

private:
    int minutes_;
};

void show(Duration d) {
    d.print();
}

int main() {
    Duration a(90);
    Duration b(2, 15);
    show(a);
    show(b);
    show(Duration(45));
    return 0;
}
```

Вывод:

```text
1 ч 30 мин
2 ч 15 мин
0 ч 45 мин
```

Проверка отрицательных значений написана один раз — в конструкторе от минут, а конструктор от часов и минут просто к нему обращается.

Слово `explicit` запрещает **неявное** преобразование. Без него конструктор с одним параметром разрешил бы написать `show(45)` — и компилятор молча превратил бы число в `Duration`. Сорок пять чего — минут, секунд, часов? `explicit` требует написать `Duration(45)`, и намерение видно в коде. Правило современного C++: **конструктор с одним параметром помечают `explicit`**, если только неявное преобразование не очевидно и не задумано специально.

## Конструктор, который не бросает: фабричная функция

Исключение в конструкторе — стандартный способ отказаться создавать объект. Но иногда неверные данные — обычное дело (например, ввод пользователя), и удобнее получить `std::expected`, а не ловить исключения. Тогда конструктор делают закрытым, а создание поручают статической функции класса, которая проверяет данные:

```cpp
#include <expected>
#include <print>
#include <string>

class Percent {
public:
    static std::expected<Percent, std::string> make(int value) {
        if (value < 0 || value > 100) {
            return std::unexpected("процент вне 0–100: " + std::to_string(value));
        }
        return Percent(value);
    }

    int value() const {
        return value_;
    }

private:
    explicit Percent(int value) : value_(value) {}
    int value_;
};

int main() {
    for (int v : {42, 150}) {
        auto p = Percent::make(v);
        if (p) {
            std::println("{}%", p->value());
        } else {
            std::println("ошибка: {}", p.error());
        }
    }
    return 0;
}
```

Вывод:

```text
42%
ошибка: процент вне 0–100: 150
```

`static` означает, что функция принадлежит классу, а не объекту: её вызывают через имя класса — `Percent::make(…)`. Будучи частью класса, она может вызвать закрытый конструктор, а код снаружи — нет. Такие функции называют **именованными конструкторами** или фабриками.

<Concept title="Конструкторы">

Конструктор вызывается при создании объекта и устанавливает инвариант; при недопустимых аргументах он бросает исключение, и объект не создаётся. Поля инициализируют в списке `: поле_(значение)` — в порядке их объявления. Любой свой конструктор отменяет автоматический конструктор по умолчанию; вернуть его можно через `= default`. Конструкторы перегружают и делегируют друг другу; конструктор с одним параметром помечают `explicit`. Создание с проверкой без исключений даёт статическая фабрика, возвращающая `std::expected`.

</Concept>

## Частые ошибки

<CommonMistake title="Присваивание в теле вместо списка инициализации">

`Book(std::string t) { title_ = t; }` сначала создаёт пустую строку, потом копирует. А для полей-констант и ссылок такой код вообще не скомпилируется. Используйте список инициализации.

</CommonMistake>

<CommonMistake title="Порядок в списке не совпадает с объявлением">

Поле, которое инициализируется через другое поле, должно быть объявлено **после** него. Не игнорируйте предупреждение `-Wreorder`: оно указывает на чтение неинициализированного значения.

</CommonMistake>

<CommonMistake title="Конструктор с одним параметром без explicit">

`Duration(int minutes)` без `explicit` позволяет передать число туда, где ждут `Duration`, — и ошибка «перепутали минуты с часами» станет незаметной. Ставьте `explicit`.

</CommonMistake>

<CommonMistake title="Создать «пустой» объект и настроить потом">

`Fraction f; f.set(1, 2);` — между этими строками объект недопустим. Если у типа нет естественного значения по умолчанию, не давайте ему конструктора по умолчанию: пусть объект создаётся сразу готовым.

</CommonMistake>

## Практика

1. **Дроби** — конструктор с проверкой и сокращением.
2. **Длительности** — перегрузка и делегирование конструкторов.
3. **Найди ошибку: порядок инициализации** — поле вычисляется из ещё не созданного поля.
4. **Цвет из строки** — статическая фабрика с `std::expected`.

## Итоги

- Конструктор — метод с именем класса и без возвращаемого типа; он делает объект допустимым с первой строки его жизни.
- Недопустимые аргументы — исключение из конструктора: объект не создаётся.
- Поля инициализируют в списке `: поле_(значение)`; порядок инициализации — порядок объявления полей.
- Свой конструктор отменяет конструктор по умолчанию; `= default` возвращает его.
- Конструкторы перегружают и делегируют; конструктор с одним параметром — `explicit`.
- Статическая фабрика с закрытым конструктором возвращает `std::expected` — создание с проверкой без исключений.
