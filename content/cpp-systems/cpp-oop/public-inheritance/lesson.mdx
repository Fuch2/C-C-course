## Задача и модель

public наследование позволяет клиенту неявно преобразовать указатель или ссылку на производный объект к доступной однозначной базе. Это обещание подстановки: функция, принимающая базу, должна корректно работать и с наследником. При этом private члены базы не становятся доступными наследнику. Для class отсутствие public после двоеточия означает private наследование.

## Как это работает в C++

Вызов функции inspect(const Device&amp;) не создаёт копию Device: ссылка обозначает базовый подобъект исходного объекта. Так сохраняется полная сущность и её время жизни. Но если метод пока невиртуальный, выбор реализации определяется статическим типом выражения. Публичная доступность преобразования и динамический выбор метода — разные вопросы. Обещайте клиенту только то, что выполняется для каждого конкретного устройства.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Device { int id{6}; };
struct Probe : public Device { int channel{3}; };
int inspect(const Device& d) { return d.id; }
int main() { Probe p; std::cout << inspect(p) << '\n'; }
```

Ожидаемый вывод:

```text
6
```

## Разбор и эксперимент

Сравните public и private наследование на вызове inspect из main. Внутреннее устройство наследника остаётся похожим, но доступность преобразования для клиента меняется. Это проверяется компилятором и не является измеряемой ценой операции во время выполнения.
