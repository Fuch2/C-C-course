## Через ссылку на базу вызывается база

В уроке о наследовании наследник объявлял метод с тем же именем, и при вызове через объект наследника работала его версия. Но через ссылку на базу вызывалась **базовая** версия — даже если ссылка указывала на наследника:

```cpp
#include <print>

class Shape {
public:
    double area() const {
        return 0;
    }
};

class Square : public Shape {
public:
    explicit Square(double side) : side_(side) {}

    double area() const {
        return side_ * side_;
    }

private:
    double side_;
};

void report(const Shape &s) {
    std::println("площадь {}", s.area());
}

int main() {
    Square sq(3);
    std::println("напрямую {}", sq.area());
    report(sq);
    return 0;
}
```

Вывод:

```text
напрямую 9
площадь 0
```

Компилятор выбирает функцию по **статическому типу** — типу, записанному в коде: в `report` это `const Shape &`, значит, `Shape::area`. Какой объект окажется за ссылкой во время работы программы, при таком выборе не учитывается. Функция `report`, написанная для любых фигур, бесполезна: она не может узнать площадь.

## `virtual`

Слово `virtual` перед методом базы меняет правило: метод выбирается по **динамическому типу** — типу настоящего объекта, на который указывает ссылка или указатель:

```cpp
#include <numbers>
#include <print>

class Shape {
public:
    virtual double area() const {
        return 0;
    }

    virtual const char *name() const {
        return "фигура";
    }
};

class Square : public Shape {
public:
    explicit Square(double side) : side_(side) {}

    double area() const override {
        return side_ * side_;
    }

    const char *name() const override {
        return "квадрат";
    }

private:
    double side_;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override {
        return std::numbers::pi * r_ * r_;
    }

    const char *name() const override {
        return "круг";
    }

private:
    double r_;
};

void report(const Shape &s) {
    std::println("{}: {:.2f}", s.name(), s.area());
}

int main() {
    Square sq(3);
    Circle c(1);
    report(sq);
    report(c);
    return 0;
}
```

Вывод:

```text
квадрат: 9.00
круг: 3.14
```

Теперь одна и та же строка `s.area()` в `report` вызывает разные функции в зависимости от того, какую фигуру ей передали. Это и есть **полиморфизм** — «много форм»: один интерфейс, разное поведение. Функция `report` написана один раз и будет работать с треугольниками, эллипсами и любыми фигурами, которые появятся позже, — без единой правки.

Наследник **переопределяет** (override) виртуальную функцию, объявляя метод с той же сигнатурой. Слово `override` после скобок необязательно, но очень полезно — следующий урок ему посвящён. Его стоит писать всегда.

## Когда работает выбор по объекту

Виртуальный выбор происходит только при вызове **через ссылку или указатель** на базу. Если скопировать наследника в объект базы, копируется лишь базовая часть — это «срезка», о ней отдельный урок — и вызывается базовая версия:

```cpp
#include <print>

class Animal {
public:
    virtual const char *sound() const {
        return "...";
    }
};

class Cat : public Animal {
public:
    const char *sound() const override {
        return "мяу";
    }
};

int main() {
    Cat cat;
    const Animal &ref = cat;
    const Animal *ptr = &cat;
    Animal copy = cat;
    std::println("{} {} {}", ref.sound(), ptr->sound(), copy.sound());
    return 0;
}
```

Вывод:

```text
мяу мяу ...
```

`copy` — объект типа `Animal`, а не кошка: никакой «кошачьей» части в нём нет. Поэтому полиморфные объекты передают по ссылке или указателю.

## Набор разных объектов

Полиморфизм особенно полезен, когда разные объекты обрабатываются одним циклом. Указатели на базу можно сложить в один вектор:

```cpp
#include <print>
#include <vector>

class Employee {
public:
    virtual long long pay() const {
        return 50000;
    }
};

class Engineer : public Employee {
public:
    long long pay() const override {
        return 180000;
    }
};

class Intern : public Employee {
public:
    long long pay() const override {
        return 40000;
    }
};

int main() {
    Engineer e1, e2;
    Intern i1;
    Employee clerk;
    std::vector<const Employee *> staff = {&e1, &i1, &clerk, &e2};
    long long total = 0;
    for (const Employee *person : staff) {
        total += person->pay();
    }
    std::println("фонд оплаты: {}", total);
    return 0;
}
```

Вывод:

```text
фонд оплаты: 450000
```

Цикл не знает и не должен знать, кто есть кто: каждый объект сам отвечает за свою зарплату. Здесь объекты живут в `main`, а вектор лишь указывает на них (агрегация). Как хранить в контейнере полиморфные объекты, которыми он **владеет**, — тема урока о виртуальном деструкторе.

## Как это устроено и сколько стоит

Компиляторы реализуют виртуальные функции через **таблицу виртуальных функций**: у каждого класса с виртуальными методами есть таблица адресов его версий, а в каждом объекте — скрытый указатель на таблицу своего класса. Вызов `s.area()` превращается в «возьми таблицу объекта, найди в ней адрес `area`, перейди по нему». Стандарт не требует именно такой реализации, но так делают все распространённые компиляторы.

Цена: объект становится больше на указатель (8 байт), вызов — на один косвенный переход, и компилятор реже может встроить функцию. Для большинства программ это незаметно; в самых горячих циклах иногда выбирают другие инструменты (`std::variant` и шаблоны — темы уроков в конце модуля).

## Виртуальные вызовы в конструкторе и деструкторе

Пока работает конструктор базы, наследник ещё не создан, а пока работает деструктор базы — уже уничтожен. Поэтому виртуальный вызов из конструктора или деструктора базы вызывает **версию базы**, а не наследника:

```cpp
#include <print>

class Base {
public:
    Base() {
        std::println("в конструкторе базы: {}", kind());
    }

    virtual const char *kind() const {
        return "база";
    }
};

class Derived : public Base {
public:
    const char *kind() const override {
        return "наследник";
    }
};

int main() {
    Derived d;
    std::println("после создания: {}", d.kind());
    return 0;
}
```

Вывод:

```text
в конструкторе базы: база
после создания: наследник
```

Это защита, а не ошибка языка: версия наследника могла бы обратиться к его ещё не созданным полям. Вывод для практики: не рассчитывайте в конструкторе базы на поведение наследника.

<Concept title="Виртуальные функции">

Метод, объявленный `virtual` в базе, выбирается по динамическому типу — настоящему объекту за ссылкой или указателем. Наследник переопределяет его методом с той же сигнатурой (помечайте `override`). Это полиморфизм: одна функция для базы работает с любыми наследниками, каждый из которых ведёт себя по-своему. Выбор по объекту работает только через ссылку или указатель; копия базы — срезка. Реализация — таблица виртуальных функций: указатель в объекте и косвенный вызов. В конструкторе и деструкторе базы вызываются версии базы.

</Concept>

## Частые ошибки

<CommonMistake title="Забытое virtual в базе">

Наследник объявил `area()`, но в базе нет `virtual` — через ссылку на базу вызывается базовая версия. Компилятор не предупредит. Слово `override` у наследника превращает эту ошибку в ошибку компиляции.

</CommonMistake>

<CommonMistake title="Сигнатура не совпадает">

`double area()` без `const` в наследнике — **другая** функция, она не переопределяет `double area() const` базы, а скрывает её. Вызов через базу опять придёт в базовую версию. Снова спасает `override`.

</CommonMistake>

<CommonMistake title="Полиморфный объект по значению">

`void report(Shape s)` получает копию базовой части, и виртуальный вызов выберет базовую версию. Принимайте `const Shape &`.

</CommonMistake>

<CommonMistake title="Поведение наследника в конструкторе базы">

Виртуальный вызов в конструкторе базы не дойдёт до наследника. Если базе нужно что-то от наследника при создании, передайте это аргументом конструктора.

</CommonMistake>

## Практика

1. **Фигуры** — одна функция для любых фигур.
2. **Оплата труда** — фонд оплаты одним циклом по разным сотрудникам.
3. **Найди ошибку: всегда базовая версия** — забытое `virtual`.
4. **Скидки** — цепочка разных правил, применяемых одним циклом.

## Итоги

- Без `virtual` метод выбирается по статическому типу (типу в коде), с `virtual` — по динамическому (настоящему объекту).
- Наследник переопределяет виртуальный метод методом с той же сигнатурой; помечайте его `override`.
- Полиморфизм работает через ссылку или указатель; копия наследника в объект базы теряет производную часть.
- Реализация — таблица виртуальных функций: +указатель в объекте и косвенный вызов.
- В конструкторе и деструкторе базы вызываются версии базы.
