## Задача и модель

Виртуальная функция позволяет вызвать реализацию фактического объекта через базовую ссылку или указатель. Статический тип определяет доступный интерфейс; динамический тип участвует в выборе реализации. Это нужно, когда клиент обрабатывает разные источники одинаковым алгоритмом. Типичная реализация использует таблицу виртуальных функций, но стандарт не требует конкретного расположения таблиц в памяти.

## Как это работает в C++

Сначала выполните прямой вызов, затем тот же вызов через const Base&amp;. В примере база возвращает единицу, реальный Fast — девятку. Квалифицированный вызов b.Base::read() явно выбирает базовую реализацию. Во время конструктора или деструктора виртуальные вызовы не направляются в ещё не созданную или уже разрушенную производную часть. Не используйте такой вызов для обязательной настройки наследника. Виртуальность не заменяет проверку состояния и обработку ошибок.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Base { virtual int read() const { return 1; } virtual ~Base() = default; };
struct Fast : Base { int read() const override { return 9; } };
int main() { Fast f; const Base& b=f; std::cout << b.read() << ' ' << b.Base::read() << '\n'; }
```

Ожидаемый вывод:

```text
9 1
```

## Разбор и эксперимент

Уберите virtual у базового read, сохранив только одноимённый метод без override у наследника, и предскажите результат базовой ссылки. Затем верните virtual. Виртуальный вызов обычно требует косвенного перехода; точную цену следует измерять на реальном горячем пути.

<CommonMistake title="Ошибка, которую нужно заметить">

Одноимённая невиртуальная функция в наследнике скрывает имя, но не обеспечивает динамическую диспетчеризацию через базу.

</CommonMistake>
