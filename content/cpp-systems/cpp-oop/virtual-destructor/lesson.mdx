## Объекты, которыми владеет база

До сих пор полиморфные объекты жили в `main` или в векторах конкретных типов, а функции и векторы лишь указывали на них. Это неудобно: чтобы сложить в один список фигуры разных видов, приходилось заводить по вектору на вид и следить, чтобы указатели не испортились. Хочется одного контейнера, который **владеет** объектами разных классов и сам их уничтожает.

Объекты разных размеров нельзя положить в `std::vector<Shape>` — абстрактный класс по значению не бывает, а конкретные объекты обрезались бы до базы. Владеть ими приходится через указатели на объекты в куче. Ручные `new` и `delete` из урока о деструкторе здесь не нужны: стандартная библиотека даёт **умный указатель** `std::unique_ptr<T>` из `<memory>` — он владеет объектом и сам удаляет его в своём деструкторе.

```cpp
#include <memory>
#include <numbers>
#include <print>
#include <vector>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override {
        return std::numbers::pi * r_ * r_;
    }

private:
    double r_;
};

class Rect : public Shape {
public:
    Rect(double w, double h) : w_(w), h_(h) {}

    double area() const override {
        return w_ * h_;
    }

private:
    double w_;
    double h_;
};

int main() {
    std::vector<std::unique_ptr<Shape>> shapes;
    shapes.push_back(std::make_unique<Circle>(1));
    shapes.push_back(std::make_unique<Rect>(2, 3));
    shapes.push_back(std::make_unique<Circle>(0.5));
    double total = 0;
    for (const auto &s : shapes) {
        total += s->area();
    }
    std::println("фигур {}, площадь {:.2f}", shapes.size(), total);
    return 0;
}
```

Вывод:

```text
фигур 3, площадь 9.93
```

`std::make_unique<Circle>(1)` создаёт круг в куче и возвращает `std::unique_ptr<Circle>`, который неявно превращается в `std::unique_ptr<Shape>`. Вектор владеет всеми фигурами: при его уничтожении каждый `unique_ptr` удалит свой объект. Ни одного `delete` в программе нет. Подробно `unique_ptr`, передача владения и `std::move` — в модуле «Время жизни объектов»; здесь достаточно схемы «вектор умных указателей на базу».

## Удаление через указатель на базу

`unique_ptr<Shape>` удаляет объект как `Shape` — вызывая деструктор **через указатель на базу**. Если деструктор базы **не виртуальный**, вызов выбирается по статическому типу: работает только деструктор `Shape`, а деструктор настоящего класса не вызывается. Его поля не уничтожаются, и, кроме того, освобождение памяти размером базы для объекта размером наследника — неопределённое поведение.

```cpp
#include <memory>
#include <print>
#include <string>

class Base {
public:
    ~Base() {                                  // не виртуальный
        std::println("~Base");
    }

    virtual void hello() const {
        std::println("база");
    }
};

class Derived : public Base {
public:
    ~Derived() {
        std::println("~Derived");
    }

    void hello() const override {
        std::println("наследник: {}", log_.size());
    }

private:
    std::string log_ = std::string(100, '*');
};

int main() {
    std::unique_ptr<Base> p = std::make_unique<Derived>();
    p->hello();
    return 0;                                  // Ошибка памяти
}
```

AddressSanitizer сообщает `new-delete-type-mismatch`: объект создавался как `Derived`, а удаляется как `Base`. Без санитайзера программа «работает», но `~Derived` не вызывается, и строка `log_` никогда не освобождается — утечка, а в общем случае — неопределённое поведение. Clang даже предупреждает при компиляции: `delete called on non-final 'Base' that has virtual functions but non-virtual destructor`.

## Правило

Исправление — одно слово: `virtual ~Base()`. Тогда удаление через базу вызывает деструктор настоящего объекта, а он, как всегда, после себя вызывает деструктор базы:

```cpp
#include <memory>
#include <print>

class Base {
public:
    virtual ~Base() {
        std::println("~Base");
    }
};

class Derived : public Base {
public:
    ~Derived() override {
        std::println("~Derived");
    }
};

int main() {
    std::unique_ptr<Base> p = std::make_unique<Derived>();
    std::println("работа");
    return 0;
}
```

Вывод:

```text
работа
~Derived
~Base
```

Правило из C++ Core Guidelines: **деструктор базового класса либо открытый и виртуальный, либо защищённый и невиртуальный**. Первый вариант — для классов, через указатель на которые объекты удаляют (почти любая полиморфная база). Второй — для баз, через которые удалять запрещено: защищённый деструктор делает `delete` через базу ошибкой компиляции.

На практике: если в классе есть хотя бы одна виртуальная функция, пишите `virtual ~Класс() = default;`. Цена — ноль: указатель на таблицу виртуальных функций у такого класса уже есть.

## Когда вызывается деструктор каждого объекта

С вектором умных указателей время жизни объектов становится обычным и предсказуемым. Удалили элемент — объект уничтожился сразу:

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

class Task {
public:
    explicit Task(std::string name) : name_(std::move(name)) {}
    virtual ~Task() {
        std::println("удалена {}", name_);
    }

private:
    std::string name_;
};

class Urgent : public Task {
public:
    using Task::Task;
};

int main() {
    std::vector<std::unique_ptr<Task>> tasks;
    tasks.push_back(std::make_unique<Task>("почта"));
    tasks.push_back(std::make_unique<Urgent>("сервер"));
    tasks.push_back(std::make_unique<Task>("отчёт"));
    tasks.erase(tasks.begin() + 1);
    std::println("осталось {}", tasks.size());
    return 0;
}
```

Вывод:

```text
удалена сервер
осталось 2
удалена почта
удалена отчёт
```

`erase` уничтожил `unique_ptr`, а тот — свою задачу. Остальные задачи удалились при уничтожении вектора, в порядке элементов.

<Concept title="Виртуальный деструктор">

Полиморфными объектами разных классов владеют через `std::unique_ptr<База>` (создаются `std::make_unique<Наследник>(…)`), например в `std::vector<std::unique_ptr<База>>`. Умный указатель удаляет объект через указатель на базу, поэтому деструктор базы обязан быть виртуальным: иначе деструктор наследника не вызовется — неопределённое поведение, ASan сообщает `new-delete-type-mismatch`. Правило: деструктор базы либо `public virtual`, либо `protected` невиртуальный. Класс с виртуальными функциями получает `virtual ~Класс() = default;`.

</Concept>

## Частые ошибки

<CommonMistake title="Полиморфная база без виртуального деструктора">

Удаление наследника через `unique_ptr<База>` или `delete` указателя на базу не вызывает деструктор наследника. Добавьте `virtual ~База() = default;`.

</CommonMistake>

<CommonMistake title="std::vector<База> вместо вектора указателей">

`std::vector<Shape>` не компилируется для абстрактной базы, а для неабстрактной обрезает наследников до базы. Полиморфные объекты хранят через `std::unique_ptr<База>`.

</CommonMistake>

<CommonMistake title="Ручной new без delete">

`shapes.push_back(new Circle(1))` в векторе сырых указателей — утечка: вектор уничтожит указатели, но не объекты. Используйте `std::make_unique` и вектор `unique_ptr`.

</CommonMistake>

## Практика

1. **Зоопарк** — вектор `unique_ptr` на абстрактную базу.
2. **Порядок уничтожения** — деструкторы наследника и базы при удалении через базу.
3. **Найди ошибку: невиртуальный деструктор** — утечка поля наследника.
4. **Редактор фигур** — добавление, удаление и обход владеющего контейнера.

## Итоги

- Владеющий контейнер разнотипных объектов — `std::vector<std::unique_ptr<База>>`, объекты создаёт `std::make_unique<Наследник>(…)`.
- `unique_ptr` удаляет объект через указатель на базу; без виртуального деструктора базы деструктор наследника не вызывается — неопределённое поведение.
- Деструктор базы: `public virtual` или `protected` невиртуальный.
- В классе с виртуальными функциями пишите `virtual ~Класс() = default;`.
- Удаление элемента вектора `unique_ptr` сразу уничтожает объект; остальные уничтожаются вместе с вектором.
