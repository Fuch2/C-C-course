## Задача и модель

Если объект удаляют через указатель на базу обычным delete, базовый деструктор должен быть виртуальным. Иначе удаление производного объекта через такую базу имеет неопределённое поведение. unique_ptr&lt;Base> по умолчанию тоже использует delete через Base\*, поэтому умный указатель не исправляет ошибочный интерфейс базы.

## Как это работает в C++

Для общедоступного полиморфного владения используйте public virtual ~Base() = default. Альтернатива для интерфейса, через который удаление запрещено, — protected невиртуальный деструктор; она не подходит нашему vector&lt;unique_ptr&lt;Sensor>>. В примере счётчик фиксирует разрушение конкретного объекта. При разрушении сначала выполняется тело деструктора наследника, затем разрушаются его члены и база. Проверять только отсутствие утечки недостаточно: тип обязан иметь корректный контракт удаления.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Base { virtual ~Base() = default; };
struct Probe : Base { int& count; explicit Probe(int& c) : count(c) {} ~Probe() override { ++count; } };
int main() { int count=0; { std::unique_ptr<Base> p=std::make_unique<Probe>(count); } std::cout << count << '\n'; }
```

Ожидаемый вывод:

```text
1
```

## Разбор и эксперимент

Проверьте ровно одно разрушение каждого производного объекта, включая случай исключения после добавления первого датчика. Внешний счётчик должен жить дольше всей коллекции. ASan помогает обнаруживать ошибки памяти, но доказательство виртуального контракта даёт также проверка типа.

## Практика

Base имеет виртуальный деструктор. Probe(int&amp; count,int delta) хранит ссылку и delta, в ~Probe() override прибавляет delta к count. solve(a,b) создаёт count=0, во вложенной области два unique_ptr&lt;Base> на Probe(count,a) и Probe(count,b), после области возвращает count.
