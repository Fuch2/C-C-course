## Третий уровень доступа

Вы знаете два уровня доступа: `public` — всем, `private` — только самому классу. Наследование добавляет вопрос: что база открывает **своим наследникам**, но не остальному миру? Для этого есть `protected`:

| Кто обращается       | `public` | `protected` | `private` |
| -------------------- | -------- | ----------- | --------- |
| методы самого класса | да       | да          | да        |
| методы наследников   | да       | да          | нет       |
| любой другой код     | да       | нет         | нет       |

`protected` — это интерфейс для **расширения**: то, чем наследники пользуются, чтобы построить своё поведение, но что не нужно обычным клиентам.

## Защищённые вспомогательные методы

```cpp
#include <print>
#include <string>
#include <utility>

class Report {
public:
    explicit Report(std::string title) : title_(std::move(title)) {}

protected:
    void header() const {
        std::println("=== {} ===", title_);
    }

    void line(const std::string &label, long long value) const {
        std::println("{:<12}{:>10}", label, value);
    }

private:
    std::string title_;
};

class SalesReport : public Report {
public:
    SalesReport(long long revenue, int orders) : Report("Продажи"), revenue_(revenue), orders_(orders) {}

    void print() const {
        header();
        line("выручка", revenue_);
        line("заказов", orders_);
    }

private:
    long long revenue_;
    int orders_;
};

int main() {
    SalesReport report(1250000, 37);
    report.print();
    return 0;
}
```

Вывод:

```text
=== Продажи ===
выручка        1250000
заказов             37
```

`header` и `line` — общие инструменты оформления: все отчёты печатаются одинаково, а код форматирования написан один раз. Клиенту отчёта они не нужны — он вызывает `print()`, — поэтому они защищённые. Попытка вызвать `report.line(…)` из `main` — ошибка компиляции.

## Защищённый конструктор

Если конструктор базы защищённый, создать объект базы **напрямую нельзя**, а наследники — могут: их конструкторы вызывают конструктор базы.

```cpp
#include <print>

class Quantity {
public:
    double value() const {
        return value_;
    }

protected:
    explicit Quantity(double value) : value_(value) {}

private:
    double value_;
};

class Meters : public Quantity {
public:
    explicit Meters(double v) : Quantity(v) {}
};

class Kilograms : public Quantity {
public:
    explicit Kilograms(double v) : Quantity(v) {}
};

int main() {
    Meters height(1.8);
    Kilograms weight(72.5);
    std::println("{} м, {} кг", height.value(), weight.value());
    return 0;
}
```

Вывод:

```text
1.8 м, 72.5 кг
```

«Величина без единиц» бессмысленна, поэтому `Quantity q(5);` не компилируется — пользоваться можно только метрами и килограммами. Это часто встречающийся приём для базовых классов, которые существуют только ради наследников.

## Защищённые данные — плохая идея

Соблазн сделать поля `protected`, «чтобы наследникам было удобно», велик. Но вспомните, ради чего поля закрывают: класс охраняет инвариант. Защищённое поле может изменить **любой** наследник, написанный кем угодно и когда угодно, — и инвариант базы теперь зависит от аккуратности всех будущих авторов:

```cpp
#include <print>

class Range {
public:
    Range(int low, int high) : low_(low), high_(high < low ? low : high) {}

    int length() const {
        return high_ - low_;
    }

protected:
    int low_;
    int high_;      // инвариант базы: low_ <= high_
};

class Window : public Range {
public:
    using Range::Range;

    void shrink_right(int d) {
        high_ -= d;               // наследник не проверил инвариант
    }
};

int main() {
    Window w(0, 10);
    w.shrink_right(15);
    std::println("{}", w.length());
    return 0;
}
```

Вывод:

```text
-5
```

Длина диапазона стала отрицательной — база этого никогда не допустила бы, но её поля менял наследник. Правильная схема: **данные закрыты, а наследникам открыты защищённые операции**, которые сами проверяют правило:

```cpp
#include <print>

class Range {
public:
    Range(int low, int high) {
        set_bounds(low, high);
    }

    int length() const {
        return high_ - low_;
    }

    int high() const {
        return high_;
    }

protected:
    void set_bounds(int low, int high) {
        low_ = low;
        high_ = high < low ? low : high;
    }

    int low() const {
        return low_;
    }

private:
    int low_ = 0;
    int high_ = 0;
};

class Window : public Range {
public:
    using Range::Range;

    void shrink_right(int d) {
        set_bounds(low(), high() - d);
    }
};

int main() {
    Window w(0, 10);
    w.shrink_right(15);
    std::println("{}", w.length());
    return 0;
}
```

Вывод:

```text
0
```

Теперь наследник может сделать с диапазоном всё, что ему нужно, но только через операцию, которая охраняет инвариант. Руководства по C++ (в том числе C++ Core Guidelines) формулируют это прямо: избегайте защищённых данных.

<Concept title="protected">

`protected` открывает члены наследникам, но не остальному коду. Это интерфейс для расширения: защищённые вспомогательные методы, защищённый конструктор базового класса, который нельзя создать напрямую. Данные базы держат закрытыми, а наследникам дают защищённые операции, сохраняющие инвариант: защищённое поле может испортить любой будущий наследник.

</Concept>

## Частые ошибки

<CommonMistake title="Защищённые поля «для удобства»">

Наследник получает возможность нарушить инвариант базы, и база больше не отвечает за свои данные. Закрывайте поля, открывайте наследникам операции.

</CommonMistake>

<CommonMistake title="protected вместо public для нужного клиентам">

Если метод нужен клиентам, но спрятан в `protected`, его начнут «доставать» через лишних наследников. Уровень доступа выбирают по тому, кто пользуется методом.

</CommonMistake>

<CommonMistake title="Ожидание, что protected открыт для любых объектов базы">

Метод наследника может обращаться к защищённым членам **своего** объекта и объектов своего типа, но не к защищённым членам произвольного объекта базы: `void f(Range &other) { other.low_; }` внутри `Window` — ошибка.

</CommonMistake>

## Практика

1. **Отчёты** — защищённые методы оформления.
2. **Величины** — защищённый конструктор базы.
3. **Найди ошибку: наследник ломает инвариант** — защищённые поля.
4. **Журнал с уровнями** — база с защищённой записью и открытые методы наследника.

## Итоги

- `protected` — доступ для наследников, но не для остального кода.
- Защищённые методы — инструменты для расширения; защищённый конструктор запрещает создавать базу напрямую.
- Данные базы держите закрытыми; наследникам открывайте операции, сохраняющие инвариант.
- Наследник видит защищённые члены своих объектов, но не произвольных объектов базы.
