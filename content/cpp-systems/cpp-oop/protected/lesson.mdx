## Задача и модель

protected разрешает доступ классу и его наследникам, сохраняя запрет для обычного клиента. Это полезно для небольших вспомогательных операций расширения. Наследование здесь показано минимально: Derived : public Base создаёт объект, содержащий базовую часть. Полноценный контракт наследования будет разобран далее. Закрытые данные лучше менять через protected метод, который проверяет правила.

## Как это работает в C++

Защищённое поле связывает каждого наследника с представлением базы: замена единиц или формата ломает все такие классы. Поэтому пример оставляет offset\_ private, а наследнику даёт готовый пересчёт. Правило доступа тоньше «наследник видит всё»: через произвольный Base&amp; производный класс не может просто читать protected член другого объекта. Используйте protected для собственного механизма расширения, а public — для клиента.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Offset { int offset_{2}; protected: int adjust(int x) const { return x + offset_; } };
class Probe : public Offset { public: int read() const { return adjust(5); } };
int main() { Probe p; std::cout << p.read() << '\n'; }
```

Ожидаемый вывод:

```text
7
```

## Разбор и эксперимент

Замените protected helper на private и предскажите место ошибки компиляции. Затем попробуйте public: код соберётся, но клиент получит лишнюю операцию. Не выбирайте уровень доступа по тому, что быстрее устраняет сообщение компилятора; сначала определите, кому нужна эта возможность.

Не объявляйте все поля protected «на будущее». Наследник тоже может нарушить инвариант; лучше передать ему операцию, а не голые данные.
