## Правило, которое нельзя нарушить

У многих данных есть правила. Температура в кельвинах не бывает отрицательной. Громкость плеера — от 0 до 100. Баланс счёта меняется только вкладами и снятиями, а не прямой записью. Такое правило, которое верно для объекта **всегда**, называют **инвариантом**.

Структура из прошлого урока не может защитить инвариант: её поля открыты, и любой код может написать `player.volume = 250;`. Проверку пришлось бы повторять везде, где используется объект, — и однажды её обязательно забудут.

Класс решает это иначе: данные **закрыты**, а менять их можно только через методы, которые проверяют правило. Тогда инвариант достаточно обеспечить в одном месте — внутри класса.

## `class`, `public` и `private`

```cpp
#include <print>

class Player {
public:
    int volume() const {
        return volume_;
    }

    void set_volume(int value) {
        if (value < 0) {
            value = 0;
        }
        if (value > 100) {
            value = 100;
        }
        volume_ = value;
    }

    void louder() {
        set_volume(volume_ + 10);
    }

private:
    int volume_ = 50;
};

int main() {
    Player p;
    p.set_volume(95);
    p.louder();
    std::println("{}", p.volume());
    p.set_volume(-20);
    std::println("{}", p.volume());
    return 0;
}
```

Вывод:

```text
100
0
```

Метки доступа делят класс на части:

- **`public:`** — открытый **интерфейс**: то, что могут использовать все;
- **`private:`** — закрытое **представление**: доступно только методам самого класса.

Код снаружи класса может вызвать `p.set_volume(95)`, но не может написать `p.volume_ = 250` — это ошибка компиляции. Единственный способ изменить громкость проходит через проверку, поэтому громкость **всегда** от 0 до 100: и после `louder`, и после любых будущих методов, если они пользуются `set_volume`.

Подчёркивание в конце имени `volume_` — распространённое соглашение для закрытых полей: оно отличает поле от метода `volume()` и от параметров. Его используют, например, руководства Google и многих крупных проектов.

## Закрытое поле — ошибка компиляции

```cpp
#include <print>

class Player {
public:
    int volume() const {
        return volume_;
    }

private:
    int volume_ = 50;
};

int main() {
    Player p;
    p.volume_ = 250;          // Ошибка компиляции: 'int Player::volume_' is private
    std::println("{}", p.volume());
    return 0;
}
```

Защита работает при компиляции и ничего не стоит во время выполнения: в готовой программе класс с закрытыми полями такой же быстрый, как структура.

## `struct` и `class` — почти одно и то же

В C++ разница между `struct` и `class` одна: доступ по умолчанию. В `struct` всё открыто, пока не написано `private:`, в `class` всё закрыто, пока не написано `public:`. Всё остальное — методы, наследование, конструкторы — у них одинаковое.

Поэтому выбор — вопрос смысла, а не возможностей. Принятое соглашение:

| Тип                                                 | Ключевое слово |
| --------------------------------------------------- | -------------- |
| набор связанных данных без правил: точка, настройки | `struct`       |
| данные с инвариантом, который нужно защищать        | `class`        |

Если у полей есть правила, которые нельзя нарушить, — нужен `class`. Если любое сочетание значений полей допустимо, хватит `struct`.

## Инвариант с несколькими полями

Самые интересные инварианты связывают несколько полей. Например, у диапазона `[low, high]` нижняя граница не больше верхней:

```cpp
#include <print>

class Range {
public:
    int low() const {
        return low_;
    }

    int high() const {
        return high_;
    }

    int length() const {
        return high_ - low_;
    }

    void set(int a, int b) {
        if (a > b) {
            int t = a;
            a = b;
            b = t;
        }
        low_ = a;
        high_ = b;
    }

    bool contains(int x) const {
        return low_ <= x && x <= high_;
    }

private:
    int low_ = 0;
    int high_ = 0;
};

int main() {
    Range r;
    r.set(10, 3);
    std::println("[{}, {}] длина {}", r.low(), r.high(), r.length());
    std::println("{} {}", r.contains(5), r.contains(11));
    return 0;
}
```

Вывод:

```text
[3, 10] длина 7
true false
```

Отдельные методы `set_low` и `set_high` здесь были бы ловушкой: между двумя вызовами объект мог бы оказаться в состоянии `low > high`. Метод `set` меняет обе границы **сразу**, поэтому инвариант не нарушается ни на мгновение. Благодаря инварианту `length()` никогда не бывает отрицательной, и ни одному методу не нужно это проверять.

<Important title="Инвариант держат все методы">

Каждый метод, который меняет закрытые поля, обязан оставить объект в допустимом состоянии. Если хоть один метод нарушает правило, гарантии исчезают для всех.

</Important>

## Что делать с неверным значением

`Player::set_volume` молча приводит громкость к границам, `Range::set` переставляет границы местами. Это не единственные варианты. Метод, получивший недопустимое значение, может:

1. **исправить** его, если исправление очевидно (громкость 120 → 100);
2. **отказаться** и сообщить об этом: вернуть `false` или `std::expected` с описанием ошибки;
3. **бросить исключение**, если вызов с таким значением — ошибка программы.

```cpp
#include <print>

class Kelvin {
public:
    double value() const {
        return value_;
    }

    bool set(double kelvin) {
        if (kelvin < 0) {
            return false;               // абсолютного нуля ниже нет — отказ
        }
        value_ = kelvin;
        return true;
    }

private:
    double value_ = 273.15;
};

int main() {
    Kelvin t;
    bool ok = t.set(-5);
    std::println("{} {}", ok, t.value());
    ok = t.set(300);
    std::println("{} {}", ok, t.value());
    return 0;
}
```

Вывод:

```text
false 273.15
true 300
```

Главное — при отказе объект **не меняется**: прежнее допустимое значение сохраняется. Молча записать «лишь бы что-то» нельзя ни в одном из вариантов.

<Concept title="Класс и инвариант">

Инвариант — правило, верное для объекта всегда. Класс защищает его: поля в секции `private:` недоступны снаружи, а открытые методы в секции `public:` меняют их только с проверкой. `struct` и `class` различаются лишь доступом по умолчанию; `class` выбирают, когда у данных есть правила. Каждый изменяющий метод обязан сохранить инвариант: исправить значение, отказаться или сообщить об ошибке, не оставляя объект в недопустимом состоянии.

</Concept>

## Частые ошибки

<CommonMistake title="Сеттер для каждого поля">

`void set_low(int)` и `void set_high(int)` по отдельности позволяют на время нарушить правило `low ≤ high` — или нарушить его навсегда, если второй вызов забыт. Делайте методы, которые меняют связанные поля вместе.

</CommonMistake>

<CommonMistake title="Метод, который нарушает инвариант «изнутри»">

`void louder() { volume_ += 10; }` — метод класса имеет доступ к полю и может обойти проверку. Изменяйте поля через методы, которые проверяют правило, или повторяйте проверку.

</CommonMistake>

<CommonMistake title="Изменение при отказе">

`bool set(double k) { value_ = k; return k >= 0; }` сообщает об ошибке, но объект уже испорчен. Сначала проверка, потом изменение.

</CommonMistake>

<CommonMistake title="Открытые поля «на всякий случай»">

Поле, открытое ради удобства одного места, может менять весь проект. Начинайте с закрытых полей и открывайте только то, что действительно нужно.

</CommonMistake>

## Практика

1. **Громкость** — класс с ограничением значения.
2. **Счётчик посещений** — отказ при недопустимой операции.
3. **Найди ошибку: метод в обход правила** — инвариант нарушается изнутри класса.
4. **Окно на экране** — инвариант с несколькими полями.

## Итоги

- Инвариант — правило, которое верно для объекта всегда.
- `private:` закрывает поля от кода снаружи класса, `public:` открывает методы; защита работает при компиляции и бесплатна во время выполнения.
- `struct` и `class` различаются только доступом по умолчанию; `class` — для данных с правилами.
- Связанные поля меняют одним методом, чтобы правило не нарушалось даже на время.
- На недопустимое значение метод реагирует исправлением, отказом или ошибкой, но не оставляет объект испорченным.
