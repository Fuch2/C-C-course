## Операторы для своих типов

`std::string` складывается через `+`, сравнивается через `==` и `<`, индексируется через `[]`. Это не особая привилегия стандартной библиотеки: в C++ операторы — это функции с особыми именами, и их можно определить для любого своего типа. Запись `a + b` компилятор превращает в вызов `operator+(a, b)` или `a.operator+(b)`.

Цель перегрузки — чтобы свой тип выглядел в коде так же естественно, как встроенный. `price + tax` читается лучше, чем `price.add(tax)`, а `v1 == v2` — лучше, чем `equal(v1, v2)`. Но правило одно и строгое: **оператор должен означать то, что от него ожидают**. `+` складывает, `==` сравнивает на равенство, и ничего больше.

## Арифметика: `+=` и `+`

```cpp
#include <print>

class Money {
public:
    explicit Money(long long kopecks) : kopecks_(kopecks) {}

    Money &operator+=(Money other) {
        kopecks_ += other.kopecks_;
        return *this;
    }

    long long kopecks() const {
        return kopecks_;
    }

private:
    long long kopecks_;
};

Money operator+(Money a, Money b) {
    a += b;
    return a;
}

Money operator*(Money a, int k) {
    return Money(a.kopecks() * k);
}

int main() {
    Money price(19990);
    Money total = price * 3 + Money(500);
    total += Money(1);
    std::println("{}.{:02}", total.kopecks() / 100, total.kopecks() % 100);
    return 0;
}
```

Вывод:

```text
604.71
```

Принятая схема: составное присваивание `+=` — **метод**, который меняет объект и возвращает ссылку на него (как `return *this` в уроке о `this`). Обычный `+` — **свободная функция**, которая получает копии, применяет `+=` и возвращает новый объект. Логика сложения записана один раз — в `+=`.

Почему `+` — не метод? Метод вызывается у левого операнда, и для выражения `2 * price` (число слева) метод `Money::operator*` не подошёл бы. Свободная функция работает с любым порядком операндов, если определить нужные варианты.

## Сравнение: `==` и `<=>`

До C++20 для полноценного сравнения нужно было написать шесть операторов: `==`, `!=`, `<`, `<=`, `>`, `>=`. Теперь достаточно двух, а часто — двух строк с `= default`:

```cpp
#include <algorithm>
#include <print>
#include <vector>

struct Version {
    int major;
    int minor;
    int patch;

    auto operator<=>(const Version &) const = default;
};

int main() {
    Version a{1, 2, 3}, b{1, 10, 0};
    std::println("{} {} {}", a < b, a == b, a >= b);
    std::vector<Version> list = {{2, 0, 0}, {1, 10, 0}, {1, 2, 3}};
    std::ranges::sort(list);
    for (const Version &v : list) {
        std::print("{}.{}.{} ", v.major, v.minor, v.patch);
    }
    std::println();
    return 0;
}
```

Вывод:

```text
true false false
1.2.3 1.10.0 2.0.0
```

`operator<=>` — **трёхстороннее сравнение**, его называют «космическим кораблём» за форму. Выражение `a <=> b` отвечает сразу на вопрос «меньше, равно или больше». Объявленный `= default`, он сравнивает поля по порядку объявления — как слова в словаре: сначала `major`, при равенстве `minor`, потом `patch`. Из одного `<=>` компилятор выводит `<`, `<=`, `>`, `>=`, а `= default` для него заодно даёт и `==` с `!=`. После этого тип можно сортировать, класть в `std::set` и ключом в `std::map`.

Обратите внимание: `1.2.3 < 1.10.0`, хотя строка `"1.2.3"` больше строки `"1.10.0"`. Сравнение версий как чисел — именно то, что нужно, и получили мы его даром.

## Своё сравнение

`= default` сравнивает поля «как есть». Если равенство объектов означает что-то другое, сравнение пишут сами. Дроби `1/2` и `2/4` равны, хотя поля у них разные:

```cpp
#include <compare>
#include <print>

class Fraction {
public:
    Fraction(int numerator, int denominator) : num_(numerator), den_(denominator) {}

    friend bool operator==(Fraction a, Fraction b) {
        return 1LL * a.num_ * b.den_ == 1LL * b.num_ * a.den_;
    }

    friend std::strong_ordering operator<=>(Fraction a, Fraction b) {
        return 1LL * a.num_ * b.den_ <=> 1LL * b.num_ * a.den_;
    }

private:
    int num_;
    int den_;          // инвариант: знаменатель положителен
};

int main() {
    std::println("{} {}", Fraction(1, 2) == Fraction(2, 4), Fraction(1, 3) < Fraction(1, 2));
    std::println("{}", Fraction(3, 4) != Fraction(3, 5));
    return 0;
}
```

Вывод:

```text
true true
true
```

Дроби сравниваются перекрёстным умножением: `a/b < c/d` тогда и только тогда, когда `a·d < c·b` (при положительных знаменателях). Умножение в `long long` защищает от переполнения. `<=>` для двух целых чисел возвращает `std::strong_ordering` — тип результата из `<compare>`; его и возвращает наш оператор.

Операторы объявлены `friend` прямо внутри класса — так их называют **скрытыми друзьями**. Это рекомендуемый способ для симметричных операторов: функция видит закрытые поля, работает с любым порядком операндов, а компилятор находит её только для дробей, не засоряя общий список кандидатов. `!=` компилятор выводит из `==` сам.

## Индексация: `operator[]`

`operator[]` даёт доступ к элементам по индексу. C++23 разрешил ему принимать **несколько** аргументов — теперь матрица индексируется естественно, `m[i, j]`:

```cpp
#include <print>
#include <vector>

class Matrix {
public:
    Matrix(int rows, int cols) : cols_(cols), cells_(static_cast<std::size_t>(rows * cols)) {}

    int &operator[](int row, int col) {
        return cells_[static_cast<std::size_t>(row * cols_ + col)];
    }

    int operator[](int row, int col) const {
        return cells_[static_cast<std::size_t>(row * cols_ + col)];
    }

private:
    int cols_;
    std::vector<int> cells_;
};

int main() {
    Matrix m(3, 3);
    for (int i = 0; i < 3; i++) {
        m[i, i] = 1;
    }
    m[0, 2] = 7;
    const Matrix &view = m;
    std::println("{} {} {}", view[0, 0], view[0, 2], view[2, 0]);
    return 0;
}
```

Вывод:

```text
1 7 0
```

До C++23 приходилось писать `m(i, j)` или `m[i][j]` с промежуточным объектом-строкой. Две версии оператора — для изменения и для чтения через константу — знакомая по уроку о `this` перегрузка по `const`.

## Что не перегружать

| Оператор                               | Совет                                                            |
| -------------------------------------- | ---------------------------------------------------------------- | ------ | -------------------------------------------------------------------- |
| `+ - * /`, `+= -=`                     | для чисел и «числоподобных» типов: деньги, векторы, дроби, время |
| `== <=>`                               | почти для любого типа-значения; часто `= default`                |
| `[]`                                   | для контейнеров и таблиц                                         |
| `<<` для потока                        | для печати — об этом следующий урок                              |
| `&&`, `                                |                                                                  | `, `,` | не перегружайте: теряется сокращённое вычисление и порядок операндов |
| `+` для «добавить в список» и подобные | не надо: метод `add` с понятным именем лучше загадочного символа |

<Concept title="Перегрузка операторов">

Оператор — функция с именем `operator@`; `a + b` вызывает `operator+(a, b)`. Составное присваивание (`+=`) делают методом, возвращающим `*this`, а `+` — свободной функцией через `+=`. C++20 выводит все сравнения из `operator<=>` и `operator==`; `= default` сравнивает поля по порядку объявления. Симметричные операторы объявляют скрытыми друзьями. C++23 разрешает `operator[]` с несколькими индексами. Оператор должен означать то, что от него ожидают.

</Concept>

## Частые ошибки

<CommonMistake title="+= без возврата ссылки">

`void operator+=(Money)` работает для `a += b`, но ломает цепочки вроде `(a += b) += c` и расходится с поведением встроенных типов. Возвращайте `Money &` и `*this`.

</CommonMistake>

<CommonMistake title="= default там, где поля не определяют равенство">

У дроби `= default` объявит `1/2` и `2/4` разными. Сравнение по умолчанию годится, только если два объекта равны тогда и только тогда, когда равны все поля.

</CommonMistake>

<CommonMistake title="Переполнение в сравнении">

`a.num_ * b.den_` в `int` переполняется на больших дробях, и сравнение даёт случайный ответ. Перемножайте в `long long`.

</CommonMistake>

<CommonMistake title="Оператор с неожиданным смыслом">

`list + item` для добавления, `matrix ^ 2` для возведения в степень (у `^` к тому же низкий приоритет) — читатель не угадает смысл. Если операция не арифметическая — дайте ей имя.

</CommonMistake>

## Практика

1. **Векторы на плоскости** — `+`, `-`, умножение на число и `==`.
2. **Время дня** — сравнение через `<=>` и сортировка.
3. **Найди ошибку: равные дроби** — сравнение по умолчанию.
4. **Матрицы** — `operator[]` с двумя индексами и умножение матриц.

## Итоги

- Операторы — функции с именами `operator+`, `operator==` и т. д.; их определяют для своих типов, сохраняя привычный смысл.
- `+=` — метод, возвращающий `*this`; `+` — свободная функция через `+=`.
- C++20: `operator<=>` и `operator==` дают все шесть сравнений; `= default` сравнивает поля по порядку объявления.
- Своё сравнение пишут, когда равенство не сводится к равенству полей; симметричные операторы — скрытые друзья.
- C++23: `operator[]` принимает несколько индексов — `m[i, j]`.
- Не перегружайте `&&`, `||`, `,` и не давайте операторам неожиданного смысла.
