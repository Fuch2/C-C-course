## Задача и модель

В C++ нет отдельного ключевого слова interface. Интерфейс обычно выражают абстрактным классом с небольшим набором чисто виртуальных операций и подходящим деструктором. Он описывает не только сигнатуру, но и смысл: единицы, допустимые аргументы, состояние после вызова, возможные ошибки. Два метода с одинаковыми типами ещё не означают одинаковый контракт.

## Как это работает в C++

Отделите чтение от настройки. Источник, который умеет только читать, не должен притворяться настраиваемым и выбрасывать исключение из обязательного configure. Для тестирования алгоритма реализуйте TestSource с заранее известными показаниями. Это настоящий объект с тем же контрактом, а не подмена выполнения интерфейса пользователю. Производственная реализация в проекте обрабатывает детерминированные сырые данные; подключение реального оборудования осталось бы задачей отдельного адаптера.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Reader { virtual int read() const = 0; virtual ~Reader() = default; };
struct TestReader : Reader { int read() const override { return 6; } };
int collect(const Reader& r) { return r.read()+r.read(); }
int main() { TestReader r; std::cout << collect(r) << '\n'; }
```

Ожидаемый вывод:

```text
12
```

## Практика

Создайте Reader с pure virtual int read() const и виртуальным деструктором. ConstantReader(int) реализует его. int difference(const Reader&amp; left,const Reader&amp; right) возвращает left.read()-right.read(). solve(a,b) передаёт два ConstantReader в difference. Функция difference не должна зависеть от ConstantReader. Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
