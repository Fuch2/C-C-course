## База, которой нечего сказать

В уроке о `virtual` у класса `Shape` была функция `area()`, возвращавшая 0. Это неправда: у «просто фигуры» нет площади, ноль — заглушка, чтобы программа скомпилировалась. Заглушка опасна: наследник, забывший переопределить `area`, будет тихо возвращать 0, а объект «просто фигура» можно создать, хотя он ничего не означает.

C++ позволяет сказать честно: «у базы реализации нет, каждый наследник обязан дать свою». Это **чисто виртуальная функция** — виртуальная функция с `= 0` вместо тела:

```cpp
#include <numbers>
#include <print>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
    virtual const char *name() const = 0;
};

class Circle : public Shape {
public:
    explicit Circle(double r) : r_(r) {}

    double area() const override {
        return std::numbers::pi * r_ * r_;
    }

    const char *name() const override {
        return "круг";
    }

private:
    double r_;
};

void report(const Shape &s) {
    std::println("{}: {:.2f}", s.name(), s.area());
}

int main() {
    Circle c(2);
    report(c);
    return 0;
}
```

Вывод:

```text
круг: 12.57
```

Класс, в котором есть хотя бы одна чисто виртуальная функция, называется **абстрактным**. Объект абстрактного класса создать нельзя — только объекты наследников, в которых все чисто виртуальные функции реализованы. Ссылки и указатели на абстрактный класс при этом создавать можно и нужно: именно через них работает `report`.

## Компилятор не даст создать неполный объект

```cpp
#include <print>

class Shape {
public:
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

class Square : public Shape {
public:
    explicit Square(double side) : side_(side) {}
    // area() не реализована

private:
    double side_;
};

int main() {
    Square sq(3);            // Ошибка компиляции: Square — абстрактный класс
    std::println("{}", sq.area());
    return 0;
}
```

GCC сообщает `cannot declare variable 'sq' to be of abstract type 'Square'` и перечисляет, какие функции не реализованы. Наследник, не реализовавший все чисто виртуальные функции, сам остаётся абстрактным. Ошибка «забыл переопределить» превращается из тихого нуля в ошибку компиляции — в этом главная польза `= 0`.

## Обязательный договор

Чисто виртуальные функции превращают базовый класс в **договор**: «каждый, кто называет себя фигурой, обязан уметь вычислить площадь и назвать себя». Код, работающий с базой, может полагаться на это без проверок:

```cpp
#include <print>
#include <vector>

class Tax {
public:
    virtual ~Tax() = default;
    virtual long long amount(long long income) const = 0;
};

class Flat : public Tax {
public:
    long long amount(long long income) const override {
        return income * 13 / 100;
    }
};

class Progressive : public Tax {
public:
    long long amount(long long income) const override {
        const long long border = 2400000;
        return income <= border ? income * 13 / 100
                                : border * 13 / 100 + (income - border) * 15 / 100;
    }
};

int main() {
    Flat flat;
    Progressive progressive;
    std::vector<const Tax *> rules = {&flat, &progressive};
    for (long long income : {1000000LL, 5000000LL}) {
        for (const Tax *t : rules) {
            std::print("{} ", t->amount(income));
        }
        std::println();
    }
    return 0;
}
```

Вывод:

```text
130000 130000
650000 702000
```

У базового класса `Tax` нет ни полей, ни реализаций — только договор. Класс, состоящий из одних чисто виртуальных функций и виртуального деструктора, — это **интерфейс**; им посвящён отдельный урок.

## Чисто виртуальная функция с телом

Необычная, но законная возможность: у чисто виртуальной функции может быть **определение**. Наследник всё равно обязан её переопределить, но может вызвать базовую версию явно — как общую часть поведения:

```cpp
#include <print>

class Logger {
public:
    virtual ~Logger() = default;
    virtual void log(const char *text) const = 0;
};

void Logger::log(const char *text) const {
    std::print("[журнал] {}", text);
}

class ConsoleLogger : public Logger {
public:
    void log(const char *text) const override {
        Logger::log(text);
        std::println(" (консоль)");
    }
};

int main() {
    ConsoleLogger c;
    const Logger &l = c;
    l.log("старт");
    return 0;
}
```

Вывод:

```text
[журнал] старт (консоль)
```

Тело пишут вне класса. Приём встречается редко: обычно общую часть удобнее вынести в обычный защищённый метод базы.

## Не вызывайте чисто виртуальные функции из конструктора

Вы помните: в конструкторе базы наследник ещё не создан, и виртуальный вызов уходит в версию базы. А у чисто виртуальной функции версии базы обычно нет. GCC в этом случае выдаёт предупреждение и ошибку компоновки (`undefined reference`), Clang — предупреждение, а программа аварийно завершается с сообщением `pure virtual method called`. Если базе при создании нужно что-то от наследника, наследник передаёт это **аргументом конструктора**.

<Concept title="Чисто виртуальные функции">

`virtual T f() = 0;` — чисто виртуальная функция: у базы нет реализации, наследник обязан дать свою. Класс с хотя бы одной такой функцией абстрактный: его объект создать нельзя, а ссылки и указатели на него — можно. Наследник, не реализовавший все чисто виртуальные функции, сам абстрактен. Так базовый класс становится обязательным договором. У чисто виртуальной функции может быть тело, вызываемое как `Base::f()`. Из конструктора и деструктора базы чисто виртуальные функции не вызывают.

</Concept>

## Частые ошибки

<CommonMistake title="Заглушка вместо = 0">

`virtual double area() const { return 0; }` — наследник, забывший переопределение, молча вернёт 0. Если у базы нет осмысленной реализации, делайте функцию чисто виртуальной: забытое переопределение станет ошибкой компиляции.

</CommonMistake>

<CommonMistake title="Сигнатура не совпала — класс остался абстрактным">

`double area()` без `const` в наследнике не реализует `area() const`, и `Square` остаётся абстрактным. Ошибка покажется в месте создания объекта, далеко от причины. С `override` компилятор укажет прямо на метод.

</CommonMistake>

<CommonMistake title="Абстрактный класс по значению">

`void report(Shape s)` и `std::vector<Shape>` не компилируются: объектов абстрактного класса не бывает. Используйте ссылки и указатели.

</CommonMistake>

<CommonMistake title="Чисто виртуальный вызов из конструктора">

Конструктор базы вызывает `describe()`, объявленную `= 0`. Наследник ещё не создан — вызов попадает в несуществующую реализацию. Передайте нужное аргументом конструктора.

</CommonMistake>

## Итоги

- `= 0` после объявления виртуальной функции делает её чисто виртуальной: реализации в базе нет, наследник обязан её дать.
- Класс с чисто виртуальной функцией абстрактный: его объект создать нельзя, ссылки и указатели — можно.
- Наследник, не реализовавший все чисто виртуальные функции, тоже абстрактный; забытое переопределение — ошибка компиляции.
- Абстрактный класс задаёт договор, на который код может полагаться без проверок.
- Из конструктора и деструктора базы чисто виртуальные функции не вызывают.
