## Задача и модель

Запись virtual int read() const = 0 объявляет обязательную операцию без реализации по умолчанию в интерфейсе. Класс, у которого остаётся чисто виртуальный финальный переопределитель, абстрактен. Производный класс становится конкретным, когда реализует все обязательные операции. Ноль здесь — часть синтаксиса, а не возвращаемое значение.

## Как это работает в C++

У чисто виртуальной функции может быть отдельное определение, но это не отменяет абстрактность соответствующего класса. Чисто виртуальному деструктору определение необходимо: он всё равно участвует в уничтожении. Для нашего интерфейса проще обычный virtual ~Sensor() = default. Не вызывайте чисто виртуальные функции виртуально из конструктора или деструктора базы. Интерфейс должен требовать только то, что способен обеспечить каждый датчик.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Source { virtual int read() const = 0; virtual ~Source() = default; };
struct Constant : Source { int read() const override { return 14; } };
int main() { Constant c; const Source& s=c; std::cout << s.read() << '\n'; }
```

Ожидаемый вывод:

```text
14
```

## Разбор и эксперимент

Удалите реализацию read у Constant и объясните, почему его нельзя создать. Ошибка появляется до выполнения. Затем добавьте другой конкретный Source и передайте его тому же клиенту без изменения клиента. Это практический смысл обязательной операции интерфейса.

Не возвращайте фиктивный ноль в базе, если реального значения по умолчанию нет. Такая заглушка скрывает забытое переопределение.

## Практика

Определите Source с чисто виртуальным int read() const и виртуальным деструктором. Constant(int) сохраняет число, реализует read. Функция int twice(const Source&amp;) вызывает read ровно два раза и суммирует результаты. solve(a,b) возвращает twice(Constant&#123;a&#125;)+b. Аргументы a,b — целые −1000…1000. Не добавляйте main: его создаёт система.
