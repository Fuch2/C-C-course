## Ошибка, которую легко пропустить

Виртуальная функция переопределяется методом **с точно такой же сигнатурой**: то же имя, те же типы параметров, тот же `const`. Отличие в одной мелочи — и метод наследника становится **новой** функцией, которая ничего не переопределяет. Программа собирается, а через ссылку на базу вызывается базовая версия. Ошибкой это не считается — GCC и Clang с `-Wall` лишь выдают предупреждение `-Woverloaded-virtual`: базовая `area() const` оказалась скрыта.

```cpp
#include <print>

class Shape {
public:
    virtual double area() const {
        return 0;
    }
};

class Square : public Shape {
public:
    explicit Square(double side) : side_(side) {}

    double area() { // Предупреждение: забыт const — это другая функция
        return side_ * side_;
    }

private:
    double side_;
};

int main() {
    Square sq(3);
    const Shape &s = sq;
    std::println("{}", s.area());
    return 0;
}
```

Вывод:

```text
0
```

Такие ошибки появляются не только по невнимательности. Кто-то меняет сигнатуру в базе — добавляет параметр или `const`, — и все наследники в проекте перестают её переопределять. Сборка проходит; предупреждение появится, только если включён `-Wall`, и легко потеряется среди десятков других.

## `override`

Слово `override` после списка параметров говорит компилятору: «этот метод **должен** переопределять виртуальную функцию базы». Если это не так, — ошибка компиляции:

```cpp
#include <print>

class Shape {
public:
    virtual double area() const {
        return 0;
    }
};

class Square : public Shape {
public:
    explicit Square(double side) : side_(side) {}

    double area() override {       // Ошибка компиляции: marked 'override', but does not override
        return side_ * side_;
    }

private:
    double side_;
};

int main() {
    Square sq(3);
    const Shape &s = sq;
    std::println("{}", s.area());
    return 0;
}
```

GCC сообщает `'double Square::area()' marked 'override', but does not override` и заодно предупреждает, что базовая `area() const` оказалась скрыта. Clang формулирует иначе, но суть та же. Та же проверка срабатывает, если в базе забыли `virtual`, ошиблись в имени (`aera`) или типе параметра.

Правило современного C++ (и C++ Core Guidelines): **каждое переопределение помечайте `override`**, а слово `virtual` пишите только в базе, где функция объявляется впервые. В наследнике `virtual` ничего не добавляет — функция и так виртуальная, — а `override` добавляет проверку.

## Аргументы по умолчанию — ловушка

У виртуальной функции может быть аргумент по умолчанию. Но значение по умолчанию подставляется **при компиляции**, по статическому типу, а тело выбирается **при выполнении**, по объекту. В результате вызов может собрать тело наследника с аргументом базы:

```cpp
#include <print>
#include <string>

class Greeter {
public:
    virtual void greet(const std::string &who = "мир") const {
        std::println("Привет, {}!", who);
    }
};

class Friendly : public Greeter {
public:
    void greet(const std::string &who = "друг") const override {
        std::println("Здравствуй, {}!", who);
    }
};

int main() {
    Friendly f;
    const Greeter &g = f;
    f.greet();
    g.greet();
    return 0;
}
```

Вывод:

```text
Здравствуй, друг!
Здравствуй, мир!
```

Второй вызов выполнил тело `Friendly`, но с аргументом по умолчанию из `Greeter`. Такой код читается одним образом, а работает другим. Правило: **не задавайте аргументов по умолчанию у виртуальных функций** (или задавайте их только в базе и никогда не меняйте в наследниках).

## Перегрузки и сокрытие

Если в базе несколько перегрузок виртуальной функции, а наследник переопределил одну, остальные **скрываются** при вызове через объект наследника: имя в наследнике закрывает все одноимённые функции базы.

```cpp
#include <print>
#include <string>

class Printer {
public:
    virtual void print(int x) const {
        std::println("число {}", x);
    }

    virtual void print(const std::string &s) const {
        std::println("строка {}", s);
    }
};

class Fancy : public Printer {
public:
    using Printer::print;          // без этой строки print(std::string) недоступен у Fancy

    void print(int x) const override {
        std::println("<<{}>>", x);
    }
};

int main() {
    Fancy f;
    f.print(42);
    f.print(std::string("текст"));
    return 0;
}
```

Вывод:

```text
<<42>>
строка текст
```

Без `using Printer::print;` вызов `f.print(std::string("текст"))` не скомпилируется: компилятор видит в `Fancy` только `print(int)` и пытается превратить строку в число. `using` возвращает в область видимости наследника все перегрузки базы, а переопределённая заменяет свою.

## Открытый невиртуальный, закрытый виртуальный

Сильный приём проектирования иерархий — **NVI** (non-virtual interface, «невиртуальный интерфейс»): открытый метод базы невиртуальный и задаёт **порядок** действий, а изменяемые шаги — закрытые виртуальные функции, которые переопределяют наследники.

```cpp
#include <print>
#include <string>
#include <vector>

class Exporter {
public:
    void run(const std::vector<std::string> &rows) const {
        header();
        for (const std::string &row : rows) {
            line(row);
        }
        std::println("--- строк: {}", rows.size());
    }

private:
    virtual void header() const = 0;
    virtual void line(const std::string &row) const = 0;
};

class Csv : public Exporter {
    void header() const override {
        std::println("name");
    }

    void line(const std::string &row) const override {
        std::println("{}", row);
    }
};

class Markdown : public Exporter {
    void header() const override {
        std::println("| name |\n|---|");
    }

    void line(const std::string &row) const override {
        std::println("| {} |", row);
    }
};

int main() {
    std::vector<std::string> rows = {"Ада", "Алан"};
    Csv().run(rows);
    Markdown().run(rows);
    return 0;
}
```

Вывод:

```text
name
Ада
Алан
--- строк: 2
| name |
|---|
| Ада |
| Алан |
--- строк: 2
```

База контролирует общий алгоритм и подсчёт строк, наследники — только формат. Переопределить **закрытую** виртуальную функцию наследнику можно — нельзя лишь вызвать её снаружи. Запись `= 0` означает «реализации в базе нет, наследник обязан её дать» — это чисто виртуальная функция, тема урока через один.

<Concept title="override">

`override` после параметров требует, чтобы метод переопределял виртуальную функцию базы; несовпадение сигнатуры, забытое `virtual` или опечатка в имени становятся ошибками компиляции. `virtual` пишут в базе, `override` — во всех переопределениях. Аргументы по умолчанию у виртуальных функций берутся по статическому типу — их избегают. Переопределение одной перегрузки скрывает остальные; `using Base::имя;` возвращает их. NVI: открытый невиртуальный метод задаёт порядок, закрытые виртуальные — изменяемые шаги.

</Concept>

## Частые ошибки

<CommonMistake title="Переопределение без override">

Метод с чуть другой сигнатурой становится новой функцией — без `override` это лишь предупреждение, которое легко пропустить. С `override` компилятор поймает это сразу — и при сегодняшней ошибке, и при будущем изменении базы.

</CommonMistake>

<CommonMistake title="Разные значения по умолчанию в базе и наследнике">

Значение по умолчанию выбирается по типу в коде, тело — по объекту. Получается смесь. Не задавайте значений по умолчанию у виртуальных функций.

</CommonMistake>

<CommonMistake title="Переопределена одна перегрузка из нескольких">

Остальные перегрузки базы скрываются при вызове через объект наследника. Добавьте `using Base::имя;`.

</CommonMistake>

## Итоги

- Переопределение требует точного совпадения сигнатуры, включая `const`; иначе получается новая функция.
- `override` превращает несовпадение в ошибку компиляции; `virtual` — только в базе, `override` — во всех наследниках.
- Аргументы по умолчанию у виртуальных функций берутся по статическому типу — не используйте их.
- Переопределение одной перегрузки скрывает остальные; `using Base::имя;` возвращает их.
- NVI: открытый невиртуальный метод задаёт алгоритм, закрытые виртуальные функции — шаги для наследников.
