## Задача и модель

override сообщает компилятору, что метод обязан переопределять виртуальную функцию базы. Несовпадающий параметр или потерянный const превращается в ошибку компиляции вместо незаметного нового метода. Ключевое слово не вводит отдельный механизм вызова: корректное переопределение и без него остаётся виртуальным. Его ценность — проверяемое намерение автора.

## Как это работает в C++

Сравнивайте имя, параметры, const и ссылочные квалификаторы. Возвращаемый тип обычно должен совпадать; специальное исключение существует для ковариантных указателей и ссылок на классы. Здесь используем одинаковый int, чтобы сосредоточиться на контракте. Отсутствующий const особенно опасен: метод read() и метод read() const различны. Не исправляйте ошибку простым удалением override: проверьте расхождение интерфейсов.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Base { virtual int read() const { return 2; } virtual ~Base() = default; };
struct Probe : Base { int read() const override { return 7; } };
int main() { const Probe p; const Base& b=p; std::cout << b.read() << '\n'; }
```

Ожидаемый вывод:

```text
7
```

## Разбор и эксперимент

Измените один параметр int на long и заранее определите, какой метод перестал переопределять базу. Проверьте также потерю const. Это compile-time ошибки намерения, поэтому успешные тесты значений не заменяют override. Не пытайтесь запускать исходник, который не скомпилировался.
