## Задача и модель

Наследование подходит для подстановки разных реализаций общего поведения. Композиция подходит для сборки объекта из частей и независимой замены алгоритмов. В системе телеметрии TemperatureSensor является Sensor, а TelemetryProcessor содержит фильтр и владеет датчиками. Процессор не является датчиком, даже если у обоих есть метод обработки.

## Как это работает в C++

Если сочетать наследованием тип датчика, фильтр и формат отчёта, количество классов растёт по числу комбинаций. Отдельный фильтр позволяет менять допуск независимо от устройства. Стоимость композиции зависит от представления: поле по значению дёшево, динамический интерфейс добавляет косвенность. Итоговый проект использует полиморфизм там, где нужен новый вид датчика, и обычный объект там, где достаточно диапазона. Перед реализацией назовите владельца каждой части, затем проверьте его уничтожение и отсутствие срезки.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

struct Offset { int value; int apply(int x) const { return x+value; } };
struct Limit { int high; int apply(int x) const { return x>high ? high : x; } };
class Pipeline { Offset offset_{2}; Limit limit_{10}; public: int run(int x) const { return limit_.apply(offset_.apply(x)); } };
int main() { Pipeline p; std::cout << p.run(4) << ' ' << p.run(20) << '\n'; }
```

Ожидаемый вывод:

```text
6 10
```

## Практика

Создайте Offset с int delta и apply(int) const = x+delta; Limit с int high и apply(int) const = min(x,high). Pipeline владеет обоими по значению, создаётся Pipeline(int delta,int high), run(int) const сначала применяет Offset, затем Limit. solve(a,b) возвращает Pipeline&#123;b,100&#125;.run(a). ## Этап проекта

Реализуйте систему обработки датчиков C++20 в одном файле. Интерфейс и готовый консольный адаптер находятся в стартовом коде; заполните тела методов, сохраняя сигнатуры. Measurement — значение с int sensorId и int value. Sensor — абстрактный интерфейс Measurement read(int raw) const с публичным виртуальным деструктором. TemperatureSensor(id, offset) возвращает &#123;id, raw+offset&#125;; PressureSensor(id, scale) — &#123;id, raw\*scale&#125;. Оба конечных класса объявите final. Все поля реализации закрыты.

Filter(low, high) принимает Measurement, когда low &lt;= value &lt;= high. При low>high конструктор бросает std::invalid_argument. TelemetryProcessor(Filter) владеет фильтром по значению и датчиками через vector&lt;unique_ptr&lt;Sensor>>. add(unique_ptr&lt;Sensor>) передаёт владение и отклоняет nullptr через std::invalid_argument без изменения коллекции. Копирование процессора запрещено. process(const vector&lt;int>&amp; raw) const сначала проверяет соответствие числа входов числу датчиков, иначе бросает std::invalid_argument до любого read. Затем вызывает каждый read ровно один раз, применяет фильтр к преобразованному значению и возвращает vector&lt;Measurement> в порядке добавления датчиков. Повторный process независим от предыдущего, источники не удаляются. Алгоритм работает с любым наследником Sensor, без switch, dynamic_cast и знания конкретных классов. Исключения read распространяются вызывающему коду; предыдущие вызовы не откатываются, частичный результат наружу не возвращается.

Протокол адаптера: n low high, затем n строк type id calibration raw. type=T или P; n=0…100; id=1…1000 (повторы допустимы); calibration=−10…10; raw=−1000…1000; −10000 &lt;= low &lt;= high &lt;= 10000. Вход корректен. Для каждого принятого измерения выведите id и преобразованное value через пробел на отдельной строке; в конце «Принято k». Порядок и повторные идентификаторы сохраняются. Пустой набор печатает только «Принято 0». Не суммируйте температуры с давлениями: здесь целые нормализованные коды тестового протокола, не физические величины в общих единицах. В реальном адаптере понадобятся отдельные единицы и диапазоны.

Сдайте заполненный стартовый файл. Публичные и скрытые тесты проверяют протокол. Отдельный test:oop-project проверяет архитектуру эталона, включая сторонний Sensor, время жизни, повторные вызовы и ошибки. Проверка произвольной архитектуры ученика по одному stdout невозможна: на ревью дополнительно проверьте private, override, final, владение и отсутствие срезки.
