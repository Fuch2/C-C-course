## Задача и модель

В нестатическом методе this указывает на объект, для которого вызван метод. Запись this->value\_ явно выбирает его поле. Она помогает различить поле и параметр с одинаковыми именами. Выражение \*this обозначает сам объект; возврат Type&amp; позволяет цепочку вызовов без создания копий.

## Как это работает в C++

В const методе через this нельзя изменять обычные поля. Статические методы не имеют this, поскольку не привязаны к экземпляру. Возвращаемая ссылка живёт столько, сколько исходный объект: цепочка корректна для существующего объекта, но сохранять ссылку на временный результат опасно. API с цепочками имеет смысл для последовательной настройки; это не обязательная форма каждого setter.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>

class Setting { int value{}; public: Setting& set(int value) { this->value = value; return *this; } int get() const { return value; } };
int main() { Setting s; auto& same = s.set(2).set(8); std::cout << (&same == &s) << ' ' << s.get() << '\n'; }
```

Ожидаемый вывод:

```text
1 8
```

## Разбор и эксперимент

Сравните возвращение Setting&amp;, Setting и void. Первый вариант поддерживает цепочку на исходном объекте, второй создаёт копию, третий запрещает цепочку. Определите, должен ли ваш интерфейс позволять настройку временного объекта и последующее сохранение ссылки на него.
