## Откуда метод знает свой объект

В C функция, работающая со структурой, получает указатель на неё явно: `rect_area(&r)`. Метод в C++ вызывается как `r.area()`, без аргумента, — но откуда он знает, чьи поля читать? Компилятор передаёт указатель на получателя **скрыто**. Внутри метода этот указатель доступен под именем `this`:

```cpp
#include <print>

class Counter {
public:
    void increment() {
        this->value_++;          // то же, что value_++
    }

    int value() const {
        return value_;
    }

    const Counter *address() const {
        return this;
    }

private:
    int value_ = 0;
};

int main() {
    Counter a, b;
    a.increment();
    a.increment();
    b.increment();
    std::println("{} {}", a.value(), b.value());
    std::println("{} {}", a.address() == &a, b.address() == &a);
    return 0;
}
```

Вывод:

```text
2 1
true false
```

В вызове `a.increment()` указатель `this` равен `&a`, в `b.increment()` — `&b`. Запись `value_` внутри метода — это сокращение для `this->value_`. Обычно `this->` не пишут, но иногда оно нужно: чтобы отличить поле от параметра с тем же именем, вернуть сам объект или сравнить его с другим.

## Тип `this` и `const`

В обычном методе класса `Counter` указатель `this` имеет тип `Counter *`. В `const`-методе — `const Counter *`: через него поля можно только читать. Именно так компилятор проверяет обещание `const` — и именно поэтому `address()` выше возвращает `const Counter *`, а не `Counter *`.

## Возврат `*this`: цепочки вызовов

Метод может вернуть **ссылку на свой объект** — `*this`. Тогда вызовы можно соединять в цепочку:

```cpp
#include <print>
#include <string>

class Html {
public:
    Html &open(const std::string &tag) {
        text_ += "<" + tag + ">";
        return *this;
    }

    Html &text(const std::string &content) {
        text_ += content;
        return *this;
    }

    Html &close(const std::string &tag) {
        text_ += "</" + tag + ">";
        return *this;
    }

    const std::string &str() const {
        return text_;
    }

private:
    std::string text_;
};

int main() {
    Html page;
    page.open("p").text("Привет, ").open("b").text("мир").close("b").close("p");
    std::println("{}", page.str());
    return 0;
}
```

Вывод:

```text
<p>Привет, <b>мир</b></p>
```

Каждый метод возвращает `Html &` — ссылку на тот же `page`, и следующий метод вызывается для него. Так устроены, например, `std::cout << a << b`: оператор `<<` возвращает ссылку на поток. Возвращать нужно именно **ссылку**: метод, возвращающий `Html` по значению, отдал бы копию, и вся цепочка после первого звена работала бы с временными копиями, а `page` получил бы только первую часть.

## Сравнение с самим собой

`this` позволяет понять, не передан ли объекту он сам. Это важно для операций над двумя объектами одного типа:

```cpp
#include <print>

class Account {
public:
    explicit Account(long long balance) : balance_(balance) {}

    bool transfer(Account &to, long long amount) {
        if (this == &to || amount <= 0 || amount > balance_) {
            return false;
        }
        balance_ -= amount;
        to.balance_ += amount;
        return true;
    }

    long long balance() const {
        return balance_;
    }

private:
    long long balance_;
};

int main() {
    Account a(100), b(50);
    std::println("{}", a.transfer(b, 30));
    std::println("{}", a.transfer(a, 10));
    std::println("{} {}", a.balance(), b.balance());
    return 0;
}
```

Вывод:

```text
true
false
70 80
```

Перевод самому себе отклоняется явно. Без проверки он здесь случайно ничего бы не испортил, но в чуть более сложной операции — с комиссией, журналом или освобождением памяти — обращение к одному объекту под двумя именами порождает трудные ошибки. В модуле «Время жизни объектов» вы встретите ту же проверку в операторе присваивания.

## Две версии метода: для константы и для изменения

Часто нужен доступ к элементу и на чтение, и на запись: `grid.at(1, 2) = 7` и чтение через `const Grid &`. Классическое решение — **перегрузка по `const`**: две версии метода, одна возвращает `int &`, другая — `const int &` для константного объекта.

```cpp
#include <print>
#include <vector>

class Grid {
public:
    Grid(int rows, int cols) : cols_(cols), cells_(rows * cols) {}

    int &at(int r, int c) {
        return cells_[r * cols_ + c];
    }

    const int &at(int r, int c) const {
        return cells_[r * cols_ + c];
    }

private:
    int cols_;
    std::vector<int> cells_;
};

int row_sum(const Grid &g, int r, int cols) {
    int s = 0;
    for (int c = 0; c < cols; c++) {
        s += g.at(r, c);             // выбирается const-версия
    }
    return s;
}

int main() {
    Grid g(2, 3);
    g.at(1, 0) = 1;                  // выбирается неконстантная версия
    g.at(1, 2) = 7;
    std::println("{}", row_sum(g, 1, 3));
    return 0;
}
```

Вывод:

```text
8
```

Компилятор выбирает версию по константности получателя. Неудобство очевидно: два одинаковых тела. Если логика сложнее одной строки, дублирование становится источником ошибок.

## C++23: явный параметр объекта

C++23 добавил возможность сделать скрытый параметр **явным** — так называемый deducing this. Первый параметр метода пишется со словом `this`, и его тип выводится из получателя:

```cpp
#include <print>
#include <vector>

class Grid {
public:
    Grid(int rows, int cols) : cols_(cols), cells_(rows * cols) {}

    auto &at(this auto &self, int r, int c) {
        return self.cells_[r * self.cols_ + c];
    }

private:
    int cols_;
    std::vector<int> cells_;
};

int main() {
    Grid g(2, 3);
    g.at(1, 2) = 7;
    const Grid &view = g;
    std::println("{}", view.at(1, 2));
    return 0;
}
```

Вывод:

```text
7
```

`this auto &self` означает: «получатель — это `self`, а его тип пусть выведет компилятор». Для `g` тип — `Grid &`, и метод возвращает `int &`. Для `view` — `const Grid &`, и метод возвращает `const int &`, а запись `view.at(1, 2) = 5` не скомпилируется. Одно тело заменило две перегрузки. Внутри такого метода нет `this` и нет неявного доступа к полям: всё пишется через `self.`.

Тот же приём позволяет лямбде вызвать саму себя — раньше для рекурсивных лямбд приходилось хитрить:

```cpp
#include <print>

int main() {
    auto factorial = [](this auto self, int n) -> long long {
        return n <= 1 ? 1 : n * self(n - 1);
    };
    std::println("{}", factorial(10));
    return 0;
}
```

Вывод:

```text
3628800
```

Deducing this поддерживают GCC 14 и Clang 18 и новее. В существующем коде вы гораздо чаще встретите перегрузку по `const` — её нужно уметь читать, — но в новом коде C++23 явный параметр объекта избавляет от дублирования.

<Concept title="this">

`this` — скрытый параметр метода, указатель на получателя: в обычном методе `T *`, в `const`-методе — `const T *`. `value_` внутри метода означает `this->value_`. `return *this;` из метода, возвращающего `T &`, позволяет строить цепочки вызовов. Сравнение `this == &other` выявляет операцию объекта с самим собой. Перегрузка по `const` даёт разные версии метода для изменяемого и константного получателя; C++23 заменяет её одним методом с явным параметром объекта `this auto &self`.

</Concept>

## Частые ошибки

<CommonMistake title="Цепочка, возвращающая копию">

`Html open(…) { …; return *this; }` — без `&` метод возвращает копию. В цепочке `page.open("p").text("x")` второй вызов изменит временную копию, а `page` останется с одним тегом.

</CommonMistake>

<CommonMistake title="Операция объекта с самим собой">

`a.transfer(a, 10)`, `a.merge(a)`, присваивание `a = a` — проверяйте `this == &other`, если операция читает один объект и меняет другой.

</CommonMistake>

<CommonMistake title="this в статической функции">

Статическая функция класса не имеет получателя — в ней нет `this`, и обращение к обычным полям — ошибка компиляции.

</CommonMistake>

<CommonMistake title="Две перегрузки разошлись">

Константная и неконстантная версии `at` написаны отдельно, и проверку индекса добавили только в одну. Держите тела одинаковыми — или используйте явный параметр объекта.

</CommonMistake>

## Практика

1. **Строка по шагам** — цепочка методов, возвращающих `*this`.
2. **Поле для игры** — один метод доступа через `this auto &self`.
3. **Найди ошибку: цепочка из копий** — метод возвращает объект по значению.
4. **Переводы между счетами** — проверка `this == &other`.

## Итоги

- `this` — указатель на получателя; поле `x_` внутри метода — это `this->x_`.
- В `const`-методе `this` указывает на константу — так компилятор проверяет обещание.
- `return *this;` из метода, возвращающего ссылку, позволяет строить цепочки вызовов.
- `this == &other` выявляет операцию объекта с самим собой.
- Перегрузка по `const` даёт разные версии для изменяемого и константного получателя; C++23 (`this auto &self`) заменяет их одним методом.
