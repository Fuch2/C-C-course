## Два компилятора одного языка

C — это стандарт, документ с правилами языка. Компиляторов, которые его реализуют, несколько. Два главных в мире Linux и macOS:

- **GCC** (GNU Compiler Collection) — с 1987 года, основной компилятор Linux; команды `gcc` и `g++`;
- **Clang** — компилятор проекта LLVM, основной в macOS и FreeBSD, популярен благодаря понятным сообщениям; команды `clang` и `clang++`.

Флаги у них почти одинаковые, поэтому всё в этом уроке работает в обоих. Курс проверяет решения обоими: код, который собирается без предупреждений в GCC **и** Clang, скорее всего, написан по стандарту, а не «под компилятор».

<Warning title="gcc на macOS — это Clang">

На Mac команда `gcc` по умолчанию вызывает Clang: `gcc --version` печатает `Apple clang version …`. Настоящий GCC ставят отдельно (например, через Homebrew), и он называется `gcc-14` или похоже.

</Warning>

## Анатомия команды

Флаги реальной команды сборки делятся на группы по стадиям, которые они настраивают:

```text
gcc -std=c17 -Wall -Wextra -Wpedantic -g -O0 -Iinclude -DDEBUG main.c util.c -o app -lm
```

| Группа         | Флаги                      | Стадия           |
| -------------- | -------------------------- | ---------------- |
| язык           | `-std=c17`                 | компиляция       |
| предупреждения | `-Wall -Wextra -Wpedantic` | компиляция       |
| отладка        | `-g`                       | компиляция       |
| оптимизация    | `-O0`, `-O2`               | компиляция       |
| препроцессор   | `-Iinclude`, `-DDEBUG`     | препроцессор     |
| результат      | `-o app`                   | последняя стадия |
| библиотеки     | `-lm`, `-L/opt/lib`        | линковка         |

Порядок большинства флагов не важен, но есть исключение — библиотеки `-l` должны стоять **после** файлов, которые их используют (подробнее в уроке о линковке). Если флаг повторяется с разными значениями, например `-O1 -O2`, действует последний.

## Стандарт языка: -std

Флаг `-std` выбирает версию языка: `c99`, `c11`, `c17`, `c23`. Без него GCC использует `gnu17` — C17 **с расширениями GNU**. Расширения удобны, но код с ними может не собраться другим компилятором. Флаг `-Wpedantic` предупреждает о каждом выходе за стандарт:

```c
#include <stdio.h>

int main(void) {
    int mask = 0b1010;          // Предупреждение: двоичная запись — расширение до C23
    printf("%d\n", mask);
    return 0;
}
```

Вывод:

```text
10
```

Программа работает, но с `-std=c17 -Wpedantic` компилятор предупредит: двоичные литералы вошли в стандарт только в C23. Курс собирает все примеры именно так — `-std=c17 -Wall -Wextra -Wpedantic`.

## Предупреждения: -Wall и -Wextra

Предупреждение — это код, который язык разрешает, но который почти наверняка ошибочен. По умолчанию компилятор молчит о большинстве таких мест. Флаги включают наборы проверок:

| Флаг           | Что включает                                                                                     |
| -------------- | ------------------------------------------------------------------------------------------------ |
| `-Wall`        | основной набор: `=` в условии, неверный формат `printf`, неиспользуемые переменные, нет `return` |
| `-Wextra`      | дополнительные: сравнение знаковых и беззнаковых, неиспользуемые параметры                       |
| `-Wpedantic`   | всё, что выходит за выбранный стандарт                                                           |
| `-Wconversion` | неявные преобразования с потерей значения (`double` → `int`)                                     |
| `-Wshadow`     | переменная скрывает другую с тем же именем                                                       |
| `-Werror`      | превращает все предупреждения в ошибки                                                           |
| `-Wno-имя`     | отключает одно предупреждение, например `-Wno-unused-parameter`                                  |

Несмотря на название, `-Wall` включает **не все** предупреждения. Вот две классические ошибки, которые они ловят. Первая — присваивание вместо сравнения:

```c
#include <stdio.h>

int main(void) {
    int count = 3;
    if (count = 0) {            // Предупреждение: присваивание вместо ==
        printf("пусто\n");
    } else {
        printf("count = %d\n", count);
    }
    return 0;
}
```

Вывод:

```text
count = 0
```

Условие присвоило `count` ноль, а значение выражения — `0`, то есть «ложь». GCC с `-Wall` пишет: `suggest parentheses around assignment used as truth value`. Если присваивание в условии действительно нужно, его берут в дополнительные скобки: `if ((c = getchar()) != EOF)`.

Вторая — сравнение знакового и беззнакового числа:

```c
#include <stdio.h>

int main(void) {
    int position = -1;
    unsigned int size = 3;
    if (position < size) {      // Предупреждение: -1 станет огромным беззнаковым числом
        printf("внутри\n");
    } else {
        printf("снаружи\n");
    }
    return 0;
}
```

Вывод:

```text
снаружи
```

Перед сравнением `-1` преобразуется в `unsigned int` и становится числом 4 294 967 295. Флаг `-Wextra` сообщает: `comparison of integer expressions of different signedness`. Такие ошибки часто прячутся в сравнениях с `strlen` и `sizeof` — они возвращают беззнаковый `size_t`.

<Tip title="Привычка">

Собирайте **каждую** программу с `-Wall -Wextra` и доводите сборку до нуля предупреждений. В командных проектах добавляют `-Werror`, чтобы предупреждение нельзя было проигнорировать.

</Tip>

## Оптимизация: -O

| Флаг  | Назначение                                                                     |
| ----- | ------------------------------------------------------------------------------ |
| `-O0` | без оптимизаций (по умолчанию): код точно следует исходнику, быстро собирается |
| `-Og` | оптимизации, не мешающие отладке                                               |
| `-O2` | основной уровень для выпуска программы                                         |
| `-O3` | агрессивнее: развёртывание циклов, векторизация; код больше                    |
| `-Os` | минимальный размер                                                             |

Оптимизатор меняет **как** программа вычисляет результат, но не **что** она выводит: удаляет ненужные переменные, выносит вычисления из циклов, подставляет тела маленьких функций. Это гарантировано только для корректных программ: код с неопределённым поведением (выход за массив, переполнение `int`) при `-O2` может вести себя иначе, чем при `-O0`. Если программа «ломается от оптимизации» — почти всегда ошибка в ней, а не в компиляторе.

## Отладочная информация: -g

Флаг `-g` добавляет в файл таблицы соответствия машинного кода строкам исходника и именам переменных. Поведение программы не меняется, растёт только размер файла. Без `-g` отладчик покажет лишь адреса и ассемблер. Типичные наборы:

```text
$ gcc -std=c17 -Wall -Wextra -g -O0 main.c -o app      # отладочная сборка
$ gcc -std=c17 -Wall -Wextra -O2 -DNDEBUG main.c -o app  # сборка для выпуска
```

`-DNDEBUG` отключает проверки `assert` в выпускаемой версии.

## Одна ошибка — два сообщения

Компиляторы находят одни и те же ошибки, но формулируют их по-разному. Пропущенная `;` после `printf("hi")`:

```text
GCC:
main.c:4:16: error: expected ';' before 'return'
    4 |     printf("hi")
      |                ^
      |                ;

Clang:
main.c:4:17: error: expected ';' after expression
    4 |     printf("hi")
      |                 ^
      |                 ;
1 error generated.
```

Формат одинаковый — `файл:строка:столбец: вид: текст`, — а формулировка и даже столбец различаются. Если сообщение одного компилятора непонятно, полезно собрать тот же код другим.

<Concept title="Предупреждение — бесплатный тест">

Каждое предупреждение — проверка, которую компилятор провёл за вас без единого запуска программы. Отключать его ради «чистого вывода» — всё равно что удалять упавший тест. Исправляйте код; отключайте конкретное предупреждение (`-Wno-…`) только когда точно понимаете, почему оно ложное.

</Concept>

## Частые ошибки

<CommonMistake title="Считать, что -Wall включает всё">

`-Wall` — лишь основной набор. Сравнение знакового с беззнаковым ловит `-Wextra`, потерю точности — `-Wconversion`. Минимум для учебных и рабочих проектов — `-Wall -Wextra`.

</CommonMistake>

<CommonMistake title="Отлаживать сборку -O2 без -g">

Отладчик покажет «оптимизированные» значения или вовсе не найдёт переменных. Для отладки собирайте с `-g -O0` (или `-Og`).

</CommonMistake>

<CommonMistake title="Проверять только одним компилятором">

Код с расширениями GNU (`typeof`, вложенные функции, `0b` до C23) соберётся в GCC и может не собраться в другом компиляторе. Задавайте `-std=c17 -Wpedantic`.

</CommonMistake>

Соберите на своём компьютере пример со сравнением `position < size` командами `gcc main.c` и `gcc -Wall -Wextra main.c`. Первая промолчит. Затем добавьте `-Werror` — сборка остановится.

</TryIt>

## Практика

1. **Разбор флагов** — разложить команду сборки по группам.
2. **Какие предупреждения включены** — смоделировать работу `-Wall`, `-Wextra`, `-Wno-…` и `-Werror`.
3. **Найди ошибку: сравнение со знаком** — исправить ошибку, о которой предупреждает `-Wextra`.
4. **Найди ошибку: = вместо ==** — исправить ошибку, о которой предупреждает `-Wall`.

## Итоги

- GCC и Clang реализуют один стандарт и понимают почти одинаковые флаги; на macOS `gcc` — это Clang.
- `-std=c17` выбирает стандарт, `-Wpedantic` сообщает о расширениях; без `-std` GCC использует `gnu17`.
- `-Wall -Wextra` — обязательный минимум предупреждений; `-Werror` превращает их в ошибки, `-Wno-имя` отключает одно.
- `-O0`/`-Og` — для отладки, `-O2` — для выпуска; оптимизация не меняет вывод корректной программы.
- `-g` добавляет отладочную информацию, не меняя поведения; `-I`, `-D` — флаги препроцессора, `-L`, `-l` — линковщика.
