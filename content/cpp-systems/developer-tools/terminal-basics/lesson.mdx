## Зачем программисту терминал

До сих пор вы запускали программы кнопкой в браузере. Настоящая разработка на C и C++ почти целиком проходит в **терминале** — текстовом окне, где команды набираются с клавиатуры. Компилятор, линковщик, Make, CMake, отладчик, Git — все они в первую очередь консольные программы. Среды разработки (VS Code, CLion) лишь вызывают их за вас и показывают результат.

Терминал стоит освоить, потому что:

- команду можно повторить, записать в скрипт и передать коллеге — в отличие от последовательности щелчков мышью;
- сообщения инструментов видны полностью, без «упрощений» среды разработки;
- на серверах и встраиваемых устройствах графического интерфейса часто нет вовсе.

Терминал — это окно, а в нём работает **оболочка** (shell): программа, которая читает команду, находит нужную программу и запускает её. В Linux и macOS это обычно `bash` или `zsh`, в Windows — PowerShell или Linux-окружение WSL. Команды этого урока — для `bash`/`zsh`; в WSL и Git Bash на Windows они работают так же.

## Приглашение и первая команда

Оболочка показывает **приглашение** и ждёт ввода:

```text
student@laptop:~/projects$ pwd
/home/student/projects
```

Слева — имя пользователя, компьютера и текущий каталог (`~` — домашний каталог). Всё после `$` набираете вы. Команда `pwd` (print working directory) печатает **текущий каталог** — место в файловой системе, относительно которого работают остальные команды.

## Пути

Файлы в Linux и macOS образуют одно дерево с корнем `/`. Путь к файлу — список каталогов через `/`:

| Запись                 | Значение                                        |
| ---------------------- | ----------------------------------------------- |
| `/home/student/main.c` | **абсолютный** путь — от корня                  |
| `src/main.c`           | **относительный** путь — от текущего каталога   |
| `.`                    | текущий каталог                                 |
| `..`                   | родительский каталог                            |
| `~`                    | домашний каталог пользователя (`/home/student`) |

Если текущий каталог — `/home/student/projects/calc`, то `../notes.txt` — это `/home/student/projects/notes.txt`, а `./build` — `/home/student/projects/calc/build`.

## Навигация и файлы

```text
$ cd ~/projects          # перейти в каталог
$ ls                     # список файлов
calc  notes.txt
$ ls -l calc             # подробный список: права, размер, дата
-rw-r--r-- 1 student student  412 Oct 13 10:02 main.c
-rw-r--r-- 1 student student  138 Oct 13 10:02 Makefile
$ mkdir -p calc/build    # создать каталог (-p — вместе с недостающими родителями)
$ cd calc
$ cat main.c             # показать содержимое файла
$ cp main.c backup.c     # копировать
$ mv backup.c old.c      # переименовать или переместить
$ rm old.c               # удалить файл
```

| Команда                | Что делает                                                           |
| ---------------------- | -------------------------------------------------------------------- |
| `pwd`                  | показать текущий каталог                                             |
| `cd путь`              | перейти в каталог; `cd` без аргумента — домой; `cd -` — в предыдущий |
| `ls`, `ls -l`, `ls -a` | список файлов; подробно; включая скрытые (имена с точкой)            |
| `mkdir`, `mkdir -p`    | создать каталог                                                      |
| `cat`, `less`          | показать файл целиком; постранично (выход — `q`)                     |
| `cp`, `mv`             | копировать; переместить или переименовать                            |
| `rm`, `rm -r`          | удалить файл; каталог со всем содержимым                             |

<Warning title="rm не спрашивает и не кладёт в корзину">

Удалённый через `rm` файл нельзя восстановить штатными средствами. Особенно осторожно с `rm -r` и шаблонами: `rm -r *` в неверном каталоге уничтожит всё. Перед удалением проверяйте `pwd` и `ls`.

</Warning>

Две привычки сильно ускоряют работу: клавиша **Tab** дополняет имена файлов и команд, а стрелка **↑** возвращает предыдущие команды. Справку по команде показывают `man ls` или `ls --help`.

## Запуск своей программы

```text
$ gcc -std=c17 -Wall -Wextra main.c -o calc
$ ./calc
```

Почему `./calc`, а не просто `calc`? Оболочка ищет программы только в каталогах из переменной `PATH` (`/usr/bin`, `/bin` и др.), а текущий каталог туда из соображений безопасности не входит. Запись `./calc` — явный путь: «программа `calc` в текущем каталоге».

## Код завершения

Каждая программа, завершаясь, сообщает оболочке **код завершения** — число, которое возвращает `main`. `0` означает успех, всё остальное — ошибку. Оболочка хранит код последней команды в переменной `$?`:

```c
#include <stdio.h>

int main(void) {
    int value;
    if (scanf("%d", &value) != 1) {
        fprintf(stderr, "ожидалось число\n");
        return 2;                 // Код завершения: ошибка ввода
    }
    printf("%d\n", value * value);
    return 0;
}
```

```text
$ echo 7 | ./square ; echo "код: $?"
49
код: 0
$ echo abc | ./square ; echo "код: $?"
ожидалось число
код: 2
```

Коды завершения связывают команды в цепочки:

- `команда1 && команда2` — вторая выполняется, только если первая **успешна**: `gcc main.c -o app && ./app`;
- `команда1 || команда2` — вторая выполняется, только если первая **не удалась**: `./tests || echo "тесты упали"`;
- `команда1 ; команда2` — выполнить обе подряд независимо от результата.

## Потоки и перенаправления

У каждой программы три стандартных потока: **stdin** (ввод, номер 0), **stdout** (вывод, 1) и **stderr** (ошибки, 2). По умолчанию все три подключены к терминалу, но оболочка умеет их перенаправлять:

| Запись    | Что происходит                                                 |
| --------- | -------------------------------------------------------------- |
| `< file`  | stdin читается из файла                                        |
| `> file`  | stdout записывается в файл (файл перезаписывается)             |
| `>> file` | stdout дописывается в конец файла                              |
| `2> file` | stderr записывается в файл                                     |
| `2>&1`    | stderr направляется туда же, куда stdout                       |
| `a \| b`  | stdout программы `a` становится stdin программы `b` (конвейер) |

Именно так проверяют решения задач: программа запускается с тестом на входе, а её вывод сравнивается с эталоном:

```text
$ ./calc < tests/input1.txt > out.txt
$ diff out.txt tests/expected1.txt && echo "тест пройден"
тест пройден
```

Разделение stdout и stderr важно: сообщения об ошибках, напечатанные через `fprintf(stderr, …)`, не попадают в файл с результатом и не портят сравнение. Поэтому отладочный вывод всегда направляйте в stderr:

```c
#include <stdio.h>

int main(void) {
    int sum = 0;
    for (int i = 1; i <= 3; i++) {
        sum += i;
        fprintf(stderr, "отладка: i=%d sum=%d\n", i, sum);   // не попадёт в результат
    }
    printf("%d\n", sum);
    return 0;
}
```

Вывод:

```text
6
```

В блоке «Вывод» только stdout; отладочные строки идут в stderr и при запуске `./sum > result.txt` остаются на экране.

<Concept title="Программы как детали конструктора">

Unix-инструменты делают по одной вещи, читают stdin и пишут stdout. Перенаправления и конвейеры соединяют их: `grep error build.log | wc -l` считает строки с ошибками, `./gen | ./solve | ./check` проверяет решение. Пишите свои программы так же — ввод из stdin, результат в stdout, ошибки в stderr, код завершения по смыслу — и они встроятся в любой такой конвейер.

</Concept>

## Частые ошибки

<CommonMistake title="Запуск без ./">

`calc` вместо `./calc` даёт `command not found`: текущий каталог не входит в `PATH`.

</CommonMistake>

<CommonMistake title="> вместо <">

`./calc > input.txt` не читает файл, а **перезаписывает** его выводом программы. Ввод — `<`, вывод — `>`.

</CommonMistake>

<CommonMistake title="Пробелы в путях">

`cd My Projects` передаёт команде два аргумента. Берите путь в кавычки: `cd "My Projects"` — а лучше не используйте пробелы в именах файлов проекта.

</CommonMistake>

## Практика

Задачи этого модуля моделируют работу инструментов — так вы разберётесь, что они делают внутри.

1. **Как wc** — подсчёт строк, слов и байтов из stdin.
2. **Переход по каталогам** — что напечатает `pwd` после серии `cd`.
3. **Перенаправления** — куда пойдут потоки команды.
4. **Цепочки && и ||** — какие команды выполнятся.

## Итоги

- Терминал — окно, оболочка — программа, которая читает и запускает команды; инструменты C и C++ работают в ней.
- Абсолютный путь начинается с `/`, относительный — от текущего каталога; `.` — текущий, `..` — родительский, `~` — домашний.
- Основные команды: `pwd`, `cd`, `ls`, `mkdir`, `cat`, `cp`, `mv`, `rm` (осторожно — без корзины).
- Свою программу запускают как `./имя`; код завершения доступен в `$?`, `&&` и `||` выполняют следующую команду по успеху или неудаче.
- `<`, `>`, `>>`, `2>`, `|` перенаправляют потоки; результат — в stdout, ошибки и отладка — в stderr.
