## Зачем отладчик, если есть printf

Отладочная печать хороша, пока вы знаете, **что** печатать. Когда программа падает неизвестно где или переменная портится неизвестно когда, приходится добавлять `printf`, пересобирать, запускать — и повторять десятки раз.

**Отладчик** позволяет остановить работающую программу в любом месте и рассмотреть её изнутри: значения переменных, цепочку вызовов, память — не меняя кода. GDB (GNU Debugger) — стандартный отладчик Linux; на macOS его роль играет LLDB из следующего урока. Среды разработки (VS Code, CLion) показывают те же возможности кнопками — внутри у них GDB или LLDB.

## Подготовка: сборка с -g

Отладчику нужна отладочная информация — связь машинного кода со строками и переменными. Собирайте с `-g`, а оптимизацию отключайте, чтобы код шёл строго по исходнику:

```text
$ gcc -std=c23 -Wall -Wextra -g -O0 main.c -o app
$ gdb ./app
(gdb)
```

`(gdb)` — приглашение отладчика: программа загружена, но ещё не запущена. Выход — `quit` (или `q`), справка — `help команда`.

## Программа для отладки

Эта программа должна печатать сумму чисел, но печатает что-то странное:

```c
#include <stdio.h>

int sum(const int *values, int count) {
    int total = 0;
    for (int i = 0; i < count; i++) {
        total += values[i];
    }
    return total;
}

int main(void) {
    int data[4] = {3, 1, 4, 1};
    int result = sum(data, 4);
    printf("сумма: %d\n", result);
    return 0;
}
```

Вывод:

```text
сумма: 9
```

Здесь всё правильно — сначала посмотрим, как отладчик показывает работающую программу, а ошибки найдём ниже.

## Точки останова и шаги

```text
(gdb) break sum
Breakpoint 1 at 0x1171: file main.c, line 4.
(gdb) run
Starting program: /home/u/app

Breakpoint 1, sum (values=0x7fffffffe3d0, count=4) at main.c:4
4	    int total = 0;
(gdb) next
5	    for (int i = 0; i < count; i++) {
(gdb) next
6	        total += values[i];
(gdb) print i
$1 = 0
(gdb) print values[i]
$2 = 3
(gdb) print values[0]@4
$3 = {3, 1, 4, 1}
(gdb) continue
Continuing.
сумма: 9
[Inferior 1 (process 4242) exited normally]
```

**Точка останова** (breakpoint) — место, где программа остановится. GDB печатает строку, которая будет выполнена **следующей** (ещё не выполнена). Основные команды:

| Команда             | Сокращение | Что делает                                                  |
| ------------------- | ---------- | ----------------------------------------------------------- |
| `break sum`         | `b sum`    | остановиться при входе в функцию                            |
| `break main.c:6`    | `b 6`      | остановиться на строке                                      |
| `break 6 if i == 3` |            | остановиться, только если условие истинно                   |
| `run`               | `r`        | запустить; `run < input.txt` — с вводом из файла            |
| `next`              | `n`        | выполнить строку, **не заходя** в вызываемые функции        |
| `step`              | `s`        | выполнить строку, **заходя** в вызываемую функцию           |
| `finish`            |            | доработать текущую функцию до возврата и показать результат |
| `continue`          | `c`        | продолжить до следующей точки останова                      |
| `info breakpoints`  | `i b`      | список точек останова и сколько раз сработала каждая        |
| `delete 1`          | `d 1`      | удалить точку останова 1                                    |

Нажатие Enter на пустой строке повторяет последнюю команду — удобно для серии `next`.

## Смотрим на данные

| Команда          | Что показывает                                                  |
| ---------------- | --------------------------------------------------------------- |
| `print x`, `p x` | значение выражения на языке C: `p a + b`, `p *ptr`, `p s->name` |
| `p arr[0]@5`     | пять элементов начиная с `arr[0]`                               |
| `p/x n`, `p/t n` | в шестнадцатеричном, двоичном виде                              |
| `display total`  | печатать `total` после каждого шага                             |
| `info locals`    | все локальные переменные текущей функции                        |
| `info args`      | аргументы текущей функции                                       |
| `set var x = 5`  | изменить значение прямо во время работы                         |

`print` вычисляет любое выражение C — даже вызов функции вашей программы: `p sum(data, 2)`.

## Стек вызовов: где мы и как сюда попали

Команда `backtrace` (`bt`) печатает цепочку вызовов — по одному **кадру** на функцию, от текущей к `main`:

```text
(gdb) bt
#0  sum (values=0x7fffffffe3d0, count=4) at main.c:6
#1  0x00005555555551d2 in main () at main.c:13
(gdb) frame 1
#1  0x00005555555551d2 in main () at main.c:13
13	    int result = sum(data, 4);
(gdb) print data
$4 = {3, 1, 4, 1}
```

`frame N` (или `up`/`down`) переключает «взгляд» на другой кадр, чтобы посмотреть его переменные. Это тот самый стек вызовов из модуля о памяти — отладчик показывает его вживую.

## Отладка падения

Теперь программа с ошибкой: она ищет длину самого длинного слова, но падает.

```c
#include <stdio.h>
#include <string.h>

int longest(const char *words[], int count) {
    int best = 0;
    for (int i = 0; i <= count; i++) {          // Ошибка памяти: <= выходит за массив
        int length = (int)strlen(words[i]);
        if (length > best) {
            best = length;
        }
    }
    return best;
}

int main(void) {
    const char *words[3] = {"gdb", "debugger", "stack"};
    printf("%d\n", longest(words, 3));
    return 0;
}
```

В отладчике падение выглядит так:

```text
(gdb) run
Program received signal SIGSEGV, Segmentation fault.
__strlen_avx2 () at ../sysdeps/x86_64/multiarch/strlen-avx2.S:76
(gdb) bt
#0  __strlen_avx2 () at ../sysdeps/x86_64/multiarch/strlen-avx2.S:76
#1  0x0000555555555190 in longest (words=0x7fffffffe3b0, count=3) at main.c:7
#2  0x00005555555551f4 in main () at main.c:17
(gdb) frame 1
#1  0x0000555555555190 in longest (words=0x7fffffffe3b0, count=3) at main.c:7
7	        int length = (int)strlen(words[i]);
(gdb) print i
$1 = 3
```

Кадр `#0` — внутри библиотеки C (путь `../sysdeps/…` — не ваш код), но `strlen` не виновата: ей передали плохой указатель. Первый кадр **вашего** кода — `#1`, строка 7, и `i = 3` при массиве из трёх элементов сразу выдаёт ошибку: условие `i <= count`. Правило: **ищите в backtrace первый кадр своего кода**.

## Точка наблюдения

Если переменная получает неверное значение, но неясно где, поставьте **точку наблюдения** (watchpoint): GDB остановится в момент, когда значение изменится.

```text
(gdb) break 5
(gdb) run
(gdb) watch total
Hardware watchpoint 2: total
(gdb) continue

Hardware watchpoint 2: total

Old value = 0
New value = 3
sum (values=0x7fffffffe3d0, count=4) at main.c:5
5	    for (int i = 0; i < count; i++) {
```

GDB показывает старое и новое значение и строку, **следующую** за изменившей. Точка наблюдения особенно полезна, когда переменную портит запись за границу соседнего массива — такую ошибку не найти чтением кода, где переменная упоминается.

<Concept title="Гипотеза → остановка → проверка">

Отладчик не ищет ошибку сам. Он отвечает на вопросы: «чему здесь равна переменная?», «кто вызвал эту функцию?», «когда изменилось значение?». Сформулируйте гипотезу, остановитесь там, где её можно проверить, и посмотрите. Опровергнутая гипотеза сужает поиск не хуже подтверждённой.

</Concept>

## Частые ошибки

<CommonMistake title="Отладка без -g">

Без `-g` GDB пишет `No symbol table is loaded` и показывает только адреса. Пересоберите с `-g -O0`.

</CommonMistake>

<CommonMistake title="Ждать результата строки, на которой стоит остановка">

Строка, которую показывает GDB, **ещё не выполнена**. Чтобы увидеть результат присваивания, выполните `next` и только потом `print`.

</CommonMistake>

<CommonMistake title="Искать ошибку в библиотечной функции">

Падение в `strlen`, `memcpy` или `printf` почти всегда означает, что им передали плохие аргументы. Поднимайтесь по `bt` до первого кадра своего кода.

</CommonMistake>

## Практика

1. **Читаем backtrace** — найти первый кадр своего кода и построить цепочку вызовов.
2. **Точка наблюдения** — смоделировать срабатывания `watch`.
3. **Сеанс отладчика** — смоделировать точки останова, `continue` и `next`.
4. **Найди ошибку: падение** — исправить программу, которую разбирают через backtrace.

## Итоги

- Для отладки собирайте с `-g -O0` и запускайте `gdb ./app`; `run < файл` передаёт ввод.
- `break` ставит точку останова на функцию, строку или по условию; `next` шагает через вызовы, `step` заходит в них, `finish` возвращается, `continue` идёт дальше.
- `print` вычисляет выражения C, `info locals` показывает локальные переменные, `display` печатает выражение после каждого шага.
- `bt` показывает стек вызовов; при падении ищите первый кадр своего кода и смотрите его переменные через `frame`.
- `watch` останавливает программу, когда меняется значение, — так находят, кто портит переменную.
