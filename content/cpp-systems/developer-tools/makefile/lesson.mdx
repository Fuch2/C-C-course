## Зачем нужен Make

В прошлом уроке проект собирался четырьмя командами `gcc`. Представьте сто файлов: набирать команды вручную долго, а пересобирать всё после каждой правки — ещё дольше. Нужен инструмент, который:

- помнит, **как** собирается каждый файл;
- знает, **от чего** он зависит;
- пересобирает **только устаревшее**.

Это Make — программа 1976 года, которая до сих пор собирает ядро Linux, Git и тысячи других проектов. Описание сборки она читает из файла `Makefile` в текущем каталоге.

## Правило

Makefile состоит из **правил**:

```text
цель: зависимости
	команда
	команда
```

- **цель** — файл, который правило создаёт;
- **зависимости** — файлы, нужные для его создания;
- **команды** (рецепт) — как его создать. Каждая строка рецепта начинается с символа **табуляции**, а не пробелов.

Минимальный Makefile для проекта из прошлого урока:

```text
calc: main.o lexer.o parser.o
	gcc main.o lexer.o parser.o -o calc

main.o: main.c lexer.h parser.h
	gcc -std=c17 -Wall -Wextra -c main.c

lexer.o: lexer.c lexer.h
	gcc -std=c17 -Wall -Wextra -c lexer.c

parser.o: parser.c parser.h lexer.h
	gcc -std=c17 -Wall -Wextra -c parser.c
```

```text
$ make
gcc -std=c17 -Wall -Wextra -c main.c
gcc -std=c17 -Wall -Wextra -c lexer.c
gcc -std=c17 -Wall -Wextra -c parser.c
gcc main.o lexer.o parser.o -o calc
$ make
make: 'calc' is up to date.
$ touch parser.c          # «изменили» parser.c
$ make
gcc -std=c17 -Wall -Wextra -c parser.c
gcc main.o lexer.o parser.o -o calc
```

Make печатает каждую команду перед выполнением. После правки `parser.c` пересобран только `parser.o` и программа — ровно то, что нужно.

## Как Make решает, что пересобрать

Make строит граф: цель → её зависимости → их зависимости. Затем обходит его **в глубину**, начиная с цели из командной строки (без аргументов — с **первой** цели файла):

1. сначала обновить каждую зависимость, у которой есть своё правило;
2. затем выполнить рецепт цели, если цели **нет** или она **старше** хотя бы одной зависимости.

«Старше» определяется по времени изменения файлов (`ls -l` показывает его). Make не смотрит на содержимое: `touch parser.c` меняет только время — и этого достаточно для пересборки. Если команда завершилась с ошибкой (код ≠ 0), Make останавливается — `&&` между шагами не нужен.

Обратите внимание на заголовки в зависимостях: `main.o: main.c lexer.h parser.h`. Если их не указать, правка `lexer.h` не пересоберёт `main.o`, и программа соберётся из несогласованных частей — одна из самых коварных ошибок сборки.

## Переменные и автоматические переменные

Повторяющиеся части выносят в переменные. Принято использовать имена, которые понимают встроенные правила Make:

| Переменная | Смысл               | Пример                      |
| ---------- | ------------------- | --------------------------- |
| `CC`       | компилятор C        | `gcc`                       |
| `CFLAGS`   | флаги компиляции    | `-std=c17 -Wall -Wextra -g` |
| `CPPFLAGS` | флаги препроцессора | `-Iinclude -DDEBUG`         |
| `LDFLAGS`  | флаги линковки      | `-L/opt/lib`                |
| `LDLIBS`   | библиотеки          | `-lm`                       |

Значение подставляется записью `$(ИМЯ)`. А **автоматические переменные** Make вычисляет для каждого правила сам:

| Запись | Значение                                    |
| ------ | ------------------------------------------- |
| `$@`   | цель правила                                |
| `$<`   | первая зависимость                          |
| `$^`   | все зависимости через пробел (без повторов) |

**Шаблонное правило** `%.o: %.c` описывает сразу все объектные файлы: `%` совпадает с любой частью имени, и для `lexer.o` зависимостью станет `lexer.c`. Вместе это даёт короткий Makefile, который не придётся менять при добавлении файлов:

```text
CC = gcc
CFLAGS = -std=c17 -Wall -Wextra -g
CPPFLAGS = -Iinclude
LDLIBS = -lm

SRC = $(wildcard src/*.c)
OBJ = $(SRC:src/%.c=build/%.o)

build/calc: $(OBJ)
	$(CC) $(LDFLAGS) $^ -o $@ $(LDLIBS)

build/%.o: src/%.c
	@mkdir -p build
	$(CC) $(CPPFLAGS) $(CFLAGS) -MMD -MP -c $< -o $@

-include $(OBJ:.o=.d)

.PHONY: clean
clean:
	rm -rf build
```

Разберём новое:

- `$(wildcard src/*.c)` — список всех `.c` в `src/`; `$(SRC:src/%.c=build/%.o)` заменяет в каждом имени `src/….c` на `build/….o`.
- Для `build/lexer.o` рецепт раскроется в `gcc -Iinclude -std=c17 -Wall -Wextra -g -MMD -MP -c src/lexer.c -o build/lexer.o`.
- `@` в начале строки рецепта скрывает саму команду из вывода.
- `-MMD -MP` — флаги, знакомые по уроку о препроцессоре: при компиляции gcc попутно пишет файл `build/lexer.d` с правилом зависимостей от заголовков. `-include` подключает эти файлы (минус — «не ругаться, если их ещё нет»). Теперь зависимости от заголовков поддерживаются **автоматически**.

## Фиктивные цели

Цель `clean` не создаёт файл с именем `clean` — это просто именованная команда. Строка `.PHONY: clean` сообщает Make, что `clean` — **фиктивная** цель: её рецепт выполняется всегда. Без неё случайно созданный файл `clean` сделает цель «актуальной», и `make clean` перестанет работать. Так же объявляют `all`, `test`, `install`.

## Полезные ключи

| Команда           | Что делает                                    |
| ----------------- | --------------------------------------------- |
| `make`            | собрать первую цель                           |
| `make clean`      | собрать (выполнить) цель `clean`              |
| `make -n`         | показать команды, ничего не выполняя          |
| `make -j8`        | выполнять до 8 независимых команд параллельно |
| `make -B`         | пересобрать всё, игнорируя время файлов       |
| `make CFLAGS=-O2` | переопределить переменную из командной строки |

`-j` безопасен только при **полных** зависимостях: если правило забыло зависимость, параллельная сборка может начать линковку раньше, чем готов объектный файл.

<Concept title="Make — это граф, а не скрипт">

Makefile не выполняется сверху вниз, как скрипт. Это описание графа «что из чего получается». Make сам решает, в каком порядке и что выполнять, — поэтому правила можно писать в любом порядке, а пропущенная зависимость — это не опечатка, а неверный граф.

</Concept>

## Частые ошибки

<CommonMistake title="Пробелы вместо табуляции">

`Makefile:2: *** missing separator.  Stop.` — строка рецепта начинается с пробелов. Нужна табуляция; редакторы обычно умеют показывать её и не заменять пробелами в Makefile.

</CommonMistake>

<CommonMistake title="Забытые заголовки">

`main.o: main.c` без `calc.h` — после правки структуры в `calc.h` файл `main.o` не пересоберётся и будет работать со старой раскладкой полей. Используйте `-MMD -MP` и `-include`.

</CommonMistake>

<CommonMistake title="clean без .PHONY">

Если в каталоге окажется файл `clean`, команда `make clean` ответит `'clean' is up to date` и ничего не удалит.

</CommonMistake>

</TryIt>

## Итоги

- Makefile состоит из правил `цель: зависимости` и рецептов; строки рецепта начинаются с табуляции.
- Make обходит граф в глубину и выполняет рецепт, если цели нет или она старше любой зависимости; без аргументов собирается первая цель.
- Переменные `CC`, `CFLAGS`, `CPPFLAGS`, `LDLIBS` и автоматические `$@`, `$<`, `$^` делают правила короткими; `%.o: %.c` описывает все объектные файлы сразу.
- Зависимости от заголовков генерирует компилятор: `-MMD -MP` и `-include`.
- Цели вроде `clean` объявляют `.PHONY`; `make -n` показывает команды, `-j` распараллеливает сборку.
