## Указатель «в никуда»

Иногда указателю нечего хранить: переменная, на которую он должен указывать, ещё не выбрана, поиск ничего не нашёл, память не выделилась. Для таких случаев в C есть специальное значение — **нулевой указатель** `NULL`. Это «адрес», который гарантированно не указывает ни на какой объект. Его можно хранить, сравнивать и возвращать из функций, но **нельзя разыменовывать**.

## `NULL` как начальное значение

Указатель без инициализации содержит мусор, и по нему ничего нельзя понять. Указатель, равный `NULL`, честно говорит: «я ни на что не указываю».

```c
#include <stdio.h>

int main(void) {
    int scores[5] = {70, 92, 85, 92, 60};
    int *first_excellent = NULL;
    for (int i = 0; i < 5; i++) {
        if (scores[i] >= 90) {
            first_excellent = &scores[i];
            break;
        }
    }
    if (first_excellent != NULL) {
        printf("первый отличник набрал %d\n", *first_excellent);
    } else {
        printf("отличников нет\n");
    }
    return 0;
}
```

Вывод:

```text
первый отличник набрал 92
```

`NULL` здесь играет ту же роль, что `-1` для индекса в уроке о возвращаемых значениях: «ничего не найдено». Но у указателя есть преимущество: значение `NULL` не может совпасть с адресом настоящего элемента.

`NULL` определён в нескольких стандартных заголовках, в том числе `<stdio.h>`, `<stdlib.h>` и `<stddef.h>`.

## Проверка перед разыменованием

Главное правило: **если указатель может быть `NULL`, проверьте его перед `*p`**. Разыменование нулевого указателя — неопределённое поведение; в Linux и других системах программа обычно сразу аварийно завершается с ошибкой «Segmentation fault» (нарушение доступа к памяти):

```c
#include <stdio.h>

int main(void) {
    int *p = NULL;
    printf("до\n");
    fflush(stdout);
    printf("%d\n", *p);   // Ошибка выполнения: разыменование NULL
    return 0;
}
```

Запустите пример: строка «до» напечатается, а затем программа аварийно завершится. `fflush(stdout)` заставляет вывести накопленный текст немедленно — иначе он мог бы пропасть вместе с упавшей программой.

Проверку записывают по-разному — все варианты эквивалентны:

| Проверка «не NULL» | Проверка «NULL» |
| ------------------ | --------------- |
| `p != NULL`        | `p == NULL`     |
| `p`                | `!p`            |

Короткая форма `if (p)` работает, потому что `NULL` в условии считается ложью. Она часто встречается в реальном коде; полная форма `p != NULL` нагляднее для начинающих.

## Функции, возвращающие `NULL`

Многие функции стандартной библиотеки возвращают `NULL`, чтобы сообщить «не получилось» или «не найдено»:

| Функция                | Возвращает `NULL`, если…                     |
| ---------------------- | -------------------------------------------- |
| `strchr(s, c)`         | символа нет в строке                         |
| `strstr(s, sub)`       | подстроки нет                                |
| `fgets(buf, n, stdin)` | ввод закончился                              |
| `malloc(size)`         | не удалось выделить память (модуль «Память») |
| `fopen(name, mode)`    | файл не открылся (модуль «Углублённый C»)    |

Результат каждой такой функции нужно проверять. Пропущенная проверка — одна из самых частых причин аварий программ на C.

## Своя функция, возвращающая указатель

Функция может вернуть указатель на найденный элемент массива или `NULL`:

```c
#include <stdio.h>

int *find(int a[], int n, int target) {
    for (int i = 0; i < n; i++) {
        if (a[i] == target) {
            return &a[i];
        }
    }
    return NULL;
}

int main(void) {
    int stock[4] = {5, 0, 12, 3};
    int *item = find(stock, 4, 12);
    if (item != NULL) {
        *item -= 1;           // продали одну штуку
    }
    printf("%d %d %d %d\n", stock[0], stock[1], stock[2], stock[3]);
    printf("%d\n", find(stock, 4, 99) == NULL);
    return 0;
}
```

Вывод:

```text
5 0 11 3
1
```

Здесь возвращать адрес безопасно: он указывает на элемент массива `stock`, который принадлежит `main` и продолжает существовать после возврата из `find`. Опасно было бы вернуть адрес **локальной** переменной самой функции.

## `NULL`, `0` и `'\0'` — не путайте

| Запись | Что это           | Где используется     |
| ------ | ----------------- | -------------------- |
| `NULL` | нулевой указатель | значения указателей  |
| `0`    | целое число ноль  | арифметика, счётчики |
| `'\0'` | символ с кодом 0  | конец строки         |

Технически все три связаны с нулём, но означают разное. Пишите то, что соответствует смыслу: `p = NULL`, `count = 0`, `s[i] == '\0'`. Так код легче читать.

## Частые ошибки

<CommonMistake title="Разыменование без проверки">

`printf("%c", *strchr(s, 'x'));` — если символа нет, `strchr` вернёт `NULL`, и программа упадёт. Сохраните результат и проверьте.

</CommonMistake>

<CommonMistake title="Неинициализированный вместо NULL">

`int *p;` — мусор, проверка `p != NULL` ничего не скажет. Инициализируйте `int *p = NULL;`, если адреса пока нет.

</CommonMistake>

<CommonMistake title="Проверка после использования">

`int v = *p; if (p == NULL) return;` — проверка опоздала: авария уже произошла. Проверяйте **до** разыменования.

</CommonMistake>

## Практика

1. **Первое отрицательное** — функция возвращает указатель или `NULL`.
2. **Позиция символа** — результат `strchr`.
3. **Безопасный доступ** — `NULL` для индекса вне массива.

## Итоги

- `NULL` — нулевой указатель, который ни на что не указывает; его можно хранить и сравнивать, но нельзя разыменовывать.
- Инициализируйте указатели `NULL`, если адреса ещё нет.
- Проверяйте `p != NULL` перед `*p`; разыменование `NULL` обычно аварийно завершает программу.
- Функции поиска и выделения ресурсов сообщают о неудаче, возвращая `NULL`.
- `NULL`, `0` и `'\0'` используйте по смыслу: указатель, число, конец строки.
