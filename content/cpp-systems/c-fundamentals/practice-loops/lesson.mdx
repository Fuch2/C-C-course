## Практикум: циклы

Циклы — сердце большинства программ. В этом практикуме шесть задач, в которых нужно самостоятельно придумать, **что** повторять и **когда** остановиться. Перед задачами — два приёма, которые помогают писать циклы без ошибок.

## Приём 1: что верно перед каждой итерацией

Опытные программисты, разбираясь в цикле, задают вопрос: «Какое утверждение верно перед каждой итерацией?» Такое утверждение называют **инвариантом цикла**. Например, для суммы:

```c
long long sum = 0;
for (int i = 0; i < n; i++) {
    // Инвариант: sum — сумма первых i чисел.
    scanf("%d", &x);
    sum += x;
}
// После цикла i == n, значит sum — сумма всех n чисел.
```

Инвариант помогает проверить три вещи:

1. **Начало.** Верен ли он до первой итерации? Сумма первых 0 чисел — 0, и `sum` начинается с 0. Верно.
2. **Шаг.** Если он верен перед итерацией, останется ли верным после? Прибавили очередное число и увеличили `i` — да.
3. **Конец.** Что он даёт после выхода? При `i == n` — ровно ответ задачи.

Если не удаётся сформулировать инвариант, скорее всего, вы ещё не до конца понимаете свой цикл.

## Приём 2: проверить 0, 1 и много итераций

Большинство ошибок в циклах проявляется на крайних случаях:

- **ноль итераций** — пустой ввод, `n = 0`, число 0: не делим ли на ноль, правильно ли инициализирован ответ?
- **одна итерация** — правильна ли граница (`<` или `<=`)?
- **много итераций** — нет ли переполнения?

## Разбор: алгоритм Евклида

Наибольший общий делитель (НОД) двух чисел — самое большое число, на которое делятся оба. Перебирать все возможные делители долго. Евклид больше двух тысяч лет назад заметил: **НОД(a, b) = НОД(b, a mod b)**, а НОД(a, 0) = a. Числа быстро уменьшаются, и через несколько шагов второе становится нулём.

```c
#include <stdio.h>

int main(void) {
    long long a, b;
    scanf("%lld %lld", &a, &b);
    while (b != 0) {
        long long r = a % b;
        a = b;
        b = r;
        printf("%lld %lld\n", a, b);
    }
    printf("НОД = %lld\n", a);
    return 0;
}
```

Ввод:

```text
1071 462
```

Вывод:

```text
462 147
147 21
21 0
НОД = 21
```

Инвариант: НОД пары `(a, b)` не меняется от итерации к итерации. В конце пара `(21, 0)`, и её НОД очевиден — 21. Алгоритм делает не больше примерно 90 итераций даже для чисел около 10¹⁸: остатки убывают не медленнее, чем числа Фибоначчи.

## Задачи

1. **НОД и НОК** — алгоритм Евклида.
2. **Палиндром** — число, которое читается одинаково в обе стороны.
3. **Двоичная запись** — перевод в систему счисления по основанию 2.
4. **Второй максимум** — две «лучшие» переменные вместо одной.
5. **Самая длинная серия** — подряд идущие одинаковые числа.
6. **Совершенные числа** — сумма собственных делителей.
