## У каждого числа есть предел

В математике целые числа бесконечны. В компьютере каждое число хранится в ячейке фиксированного размера, поэтому у каждого целого типа есть минимальное и максимальное значение. Пока ваши числа маленькие, это незаметно. Но стоит посчитать население Земли в секундах жизни или перемножить два миллиарда — и `int` перестаёт справляться. Эта ошибка называется **переполнением**, и она стоила реальным проектам миллионы долларов. В этом уроке вы узнаете, какие целые типы есть в C и как выбрать подходящий.

## Биты и байты за одну минуту

Память компьютера состоит из **битов** — ячеек, хранящих 0 или 1. Восемь битов образуют **байт**. В `n` битах можно записать 2ⁿ разных комбинаций:

| Битов | Комбинаций      | Диапазон со знаком                 |
| ----- | --------------- | ---------------------------------- |
| 8     | 256             | от −128 до 127                     |
| 16    | 65 536          | от −32 768 до 32 767               |
| 32    | ≈ 4,3 миллиарда | от −2 147 483 648 до 2 147 483 647 |
| 64    | ≈ 1,8 · 10¹⁹    | от ≈ −9,2 · 10¹⁸ до ≈ 9,2 · 10¹⁸   |

Половина комбинаций отдаётся отрицательным числам, половина — нулю и положительным, поэтому положительная граница на единицу меньше модуля отрицательной.

## Тип `int`

`int` — основной целый тип. Стандарт C гарантирует ему минимум 16 бит, но на всех современных компьютерах (и на сервере проверки курса) он занимает **32 бита**: от −2 147 483 648 до 2 147 483 647, то есть примерно ±2,1 миллиарда.

Точные границы хранятся в константах `INT_MIN` и `INT_MAX` из заголовка `<limits.h>`:

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    printf("%d\n", INT_MIN);
    printf("%d\n", INT_MAX);
    return 0;
}
```

Вывод:

```text
-2147483648
2147483647
```

## Переполнение

Что будет, если результат вычисления не помещается в `int`? Например, перемножить два числа по 100 000 — результат 10¹⁰ больше 2,1 миллиарда:

```c
#include <stdio.h>

int main(void) {
    int a, b;
    scanf("%d %d", &a, &b);
    int product = a * b;          // переполнение при больших a и b
    printf("%d\n", product);
    return 0;
}
```

Ввод:

```text
100000 100000
```

Скорее всего, программа напечатает `1410065408` — совершенно неверное число без всякого предупреждения. Но гарантий нет даже этого: для знаковых типов переполнение в C — **неопределённое поведение** (undefined behavior, UB). Стандарт не говорит, что произойдёт: программа может выдать мусор, упасть или повести себя по-разному при разных настройках компилятора.

<Warning title="Переполнение не сообщает о себе">

Компилятор не может предупредить о переполнении, если числа приходят из ввода. Программа молча посчитает неправильно. Защита одна — заранее оценить, насколько большими могут быть значения, и выбрать тип с запасом.

</Warning>

## Тип `long long`

Для больших чисел есть `long long` — гарантированно не меньше 64 бит, диапазон примерно ±9,2 · 10¹⁸. Этого хватает почти для всего: количества миллисекунд за всю историю человечества, денежных сумм в копейках, произведения двух чисел до миллиарда.

У `long long` свой спецификатор — `%lld` (две буквы l):

```c
#include <stdio.h>

int main(void) {
    long long a, b;
    scanf("%lld %lld", &a, &b);
    long long product = a * b;
    printf("%lld\n", product);
    return 0;
}
```

Ввод:

```text
100000 100000
```

Вывод:

```text
10000000000
```

## Главная ловушка: тип выражения

Даже если результат записывается в `long long`, вычисление может переполниться **раньше** присваивания:

```c
int a = 100000, b = 100000;
long long product = a * b;   // ошибка: a * b считается в int
```

Тип выражения определяется типами операндов, а не переменной, в которую попадёт результат. `a` и `b` — `int`, значит, `a * b` вычисляется в `int` и переполняется, а в `long long` записывается уже испорченное значение.

Исправление — привести хотя бы один операнд к `long long` **до** умножения:

```c
#include <stdio.h>

int main(void) {
    int a = 100000, b = 100000;
    long long product = (long long)a * b;
    printf("%lld\n", product);
    return 0;
}
```

Вывод:

```text
10000000000
```

Запись `(long long)a` называется **приведением типа**: значение `a` преобразуется в `long long`. Когда один операнд `long long`, второй тоже автоматически расширяется, и умножение выполняется в 64 битах.

То же касается констант. `1000000 * 1000000` переполняет `int`, потому что обе константы — `int`. Суффикс `LL` делает константу `long long`: `1000000LL * 1000000` вычисляется верно.

<Concept title="Правило">

Тип результата выражения определяется типами операндов. Если результат может не поместиться в `int`, расширяйте тип до начала вычисления: `(long long)a * b` или `a * 1LL * b`.

</Concept>

## Остальные целые типы

| Тип         | Обычный размер | Спецификатор | Когда использовать                        |
| ----------- | -------------- | ------------ | ----------------------------------------- |
| `char`      | 8 бит          | `%c` / `%d`  | символы (урок «Символы»)                  |
| `short`     | 16 бит         | `%hd`        | экономия памяти в больших массивах        |
| `int`       | 32 бита        | `%d`         | по умолчанию                              |
| `long`      | 32 или 64 бита | `%ld`        | лучше избегать: размер зависит от системы |
| `long long` | 64 бита        | `%lld`       | большие числа                             |

`long` — неудобный тип: в Linux он 64-битный, а в Windows 32-битный. Программа, правильная на одной системе, переполнится на другой. Поэтому в курсе мы пользуемся `int` и `long long`, а когда важен точный размер — типами из `<stdint.h>` вроде `int32_t` и `int64_t`, о которых расскажем в уроке «signed и unsigned».

## Как выбрать тип

1. Оцените максимальное значение по ограничениям задачи. Не только входных данных, но и **всех промежуточных результатов**.
2. Если всё укладывается в ±2 · 10⁹ — используйте `int`.
3. Если могут быть больше — `long long`, и не забудьте `%lld` в `printf` и `scanf`.

Пример оценки: если `a, b ≤ 10⁹`, то `a + b ≤ 2 · 10⁹` — едва помещается в `int`. А `a * b ≤ 10¹⁸` — только `long long`.

## Частые ошибки

<CommonMistake title="%d для long long">

`printf("%d", big)` при `long long big` — несоответствие формата. Компилятор предупредит, а напечатано будет неверное число. Для `long long` — `%lld`.

</CommonMistake>

<CommonMistake title="Переполнение до присваивания">

`long long r = a * b;` при `int a, b` всё равно переполняется. Приведите тип до умножения: `(long long)a * b`.

</CommonMistake>

<CommonMistake title="Проверка суммы только на входных данных">

Каждое число по отдельности помещается в `int`, но их сумма или произведение — нет. Оценивайте промежуточные результаты.

</CommonMistake>

## Практика

1. **Большое произведение** — числа до миллиарда.
2. **Секунды за годы** — константы и переполнение.
3. **Сумма от 1 до n** — формула Гаусса для больших n.
4. **На границе int** — сумма двух чисел, близких к пределу.

## Итоги

- Каждый целый тип имеет фиксированный размер и диапазон. `int` — 32 бита, примерно ±2,1 · 10⁹; `long long` — 64 бита, примерно ±9,2 · 10¹⁸.
- Границы типов — в `<limits.h>`: `INT_MAX`, `INT_MIN`, `LLONG_MAX`.
- Переполнение знакового типа — неопределённое поведение; программа молча считает неправильно.
- Тип выражения определяется операндами: приводите к `long long` до операции — `(long long)a * b`, суффикс `LL` у констант.
- Для `long long` в `printf` и `scanf` используется `%lld`.
