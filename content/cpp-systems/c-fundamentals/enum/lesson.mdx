## Числа, которые ничего не говорят

Программа управляет станком. Состояние станка хранится в переменной `int state`: 0 — простаивает, 1 — работает, 2 — авария. Код выглядит так:

```c
if (state == 2) {
    alarm();
}
state = 1;
```

Что такое `2`? Что такое `1`? Чтобы понять, придётся искать комментарий или документацию. Такие числа называют **магическими**. Ещё хуже то, что ничто не мешает записать `state = 7` — значение, которое ничего не означает.

**Перечисление** (`enum`) даёт числам имена. Вместо `state == 2` пишут `state == FAULT`, и код объясняет себя сам.

## Объявление перечисления

```c
#include <stdio.h>

enum color { RED, GREEN, BLUE };

int main(void) {
    enum color c = GREEN;
    printf("%d %d %d\n", RED, GREEN, BLUE);
    printf("c = %d\n", c);
    c = BLUE;
    if (c == BLUE) {
        printf("синий\n");
    }
    return 0;
}
```

Вывод:

```text
0 1 2
c = 1
синий
```

Разберём:

- `enum color { RED, GREEN, BLUE };` объявляет тип `enum color` и три **константы перечисления**. Как и у структур, слово `enum` — часть имени типа, а после `}` нужна точка с запятой.
- Константы получают значения по порядку, начиная с нуля: `RED` = 0, `GREEN` = 1, `BLUE` = 2.
- Константы — это обычные целые числа типа `int`. Их печатают через `%d`, сравнивают через `==`, используют в арифметике.
- Имена констант принято писать заглавными буквами, как и другие константы.

## Явные значения

Любой константе можно задать значение. Следующие за ней продолжают счёт от него:

```c
#include <stdio.h>

enum month { JAN = 1, FEB, MAR, APR, MAY, JUN, JUL, AUG, SEP, OCT, NOV, DEC };

enum http_status {
    HTTP_OK = 200,
    HTTP_CREATED,                // 201
    HTTP_NOT_FOUND = 404,
    HTTP_SERVER_ERROR = 500
};

int main(void) {
    printf("%d %d %d\n", JAN, MAR, DEC);
    printf("%d %d %d\n", HTTP_CREATED, HTTP_NOT_FOUND, HTTP_SERVER_ERROR);
    return 0;
}
```

Вывод:

```text
1 3 12
201 404 500
```

Месяцы удобно нумеровать с единицы, как в календаре. Коды HTTP заданы стандартом, поэтому их значения перечислены явно. Если значения не важны (цвета, состояния), их не указывают вовсе — компилятор пронумерует сам.

Все константы перечислений живут в одной области имён с переменными и функциями. Поэтому одно имя нельзя использовать в двух перечислениях, а к именам часто добавляют общий префикс: `HTTP_OK`, `HTTP_NOT_FOUND`.

## Перечисление и `switch`

Перечисления и `switch` созданы друг для друга: каждой константе — свой `case`. Вот функция, превращающая значение в название:

```c
#include <stdio.h>

enum light { LIGHT_RED, LIGHT_YELLOW, LIGHT_GREEN };

const char *light_name(enum light l) {
    switch (l) {
        case LIGHT_RED:
            return "красный";
        case LIGHT_YELLOW:
            return "жёлтый";
        case LIGHT_GREEN:
            return "зелёный";
    }
    return "неизвестно";
}

enum light next_light(enum light l) {
    switch (l) {
        case LIGHT_RED:
            return LIGHT_GREEN;
        case LIGHT_GREEN:
            return LIGHT_YELLOW;
        case LIGHT_YELLOW:
            return LIGHT_RED;
    }
    return LIGHT_RED;
}

int main(void) {
    enum light l = LIGHT_RED;
    for (int step = 0; step < 4; step++) {
        printf("%s\n", light_name(l));
        l = next_light(l);
    }
    return 0;
}
```

Вывод:

```text
красный
зелёный
жёлтый
красный
```

`return` сразу выходит из функции, поэтому `break` после него не нужен. Строка `return "неизвестно";` после `switch` срабатывает, только если в переменной оказалось значение вне перечисления — об этом ниже.

У такого `switch` есть важное преимущество: компилятор проверяет, что перечислены **все** константы. Если добавить новый цвет и забыть его обработать, GCC с флагом `-Wall` предупредит:

```c
#include <stdio.h>

enum light { LIGHT_RED, LIGHT_YELLOW, LIGHT_GREEN, LIGHT_BLINKING };

const char *light_name(enum light l) {
    switch (l) {     // Предупреждение: enumeration value ‘LIGHT_BLINKING’ not handled in switch
        case LIGHT_RED:
            return "красный";
        case LIGHT_YELLOW:
            return "жёлтый";
        case LIGHT_GREEN:
            return "зелёный";
    }
    return "неизвестно";
}

int main(void) {
    printf("%s\n", light_name(LIGHT_BLINKING));
    return 0;
}
```

Вывод:

```text
неизвестно
```

Программа собралась, но предупреждение указывает на забытый случай. Поэтому в `switch` по перечислению часто **не пишут** `default`: с ним компилятор посчитает, что все случаи обработаны, и промолчит.

## Таблица названий и счётчик констант

Когда значения идут подряд с нуля, их удобно использовать как индексы массива. Добавьте в конец перечисления ещё одну константу — она будет равна количеству остальных:

```c
#include <stdio.h>

enum weekday { MON, TUE, WED, THU, FRI, SAT, SUN, DAY_COUNT };

const char *day_names[DAY_COUNT] = {"Пн", "Вт", "Ср", "Чт", "Пт", "Сб", "Вс"};

int is_weekend(enum weekday d) {
    return d == SAT || d == SUN;
}

int main(void) {
    for (int d = MON; d < DAY_COUNT; d++) {
        printf("%s%s ", day_names[d], is_weekend(d) ? "*" : "");
    }
    printf("\n");
    enum weekday today = FRI;
    enum weekday after = (today + 3) % DAY_COUNT;
    printf("Через 3 дня после %s: %s\n", day_names[today], day_names[after]);
    return 0;
}
```

Вывод:

```text
Пн Вт Ср Чт Пт Сб* Вс*
Через 3 дня после Пт: Пн
```

- `DAY_COUNT` равна 7 — числу дней. Если добавить день в середину перечисления, размер массива и граница цикла изменятся сами.
- Константы перечисления — настоящие константы времени компиляции, поэтому `DAY_COUNT` можно использовать как размер массива.
- `(today + 3) % DAY_COUNT` — арифметика по кругу: после воскресенья снова понедельник. Результат — `int`, и его можно присвоить переменной типа `enum weekday`.

## Перечисление — это просто `int`

В C переменная типа перечисления хранит обычное целое число. Компилятор **не проверяет**, что в ней лежит одно из перечисленных значений:

```c
#include <stdio.h>

enum color { RED, GREEN, BLUE };

int main(void) {
    enum color c = 42;     // компилируется без предупреждений
    printf("%d\n", c);
    return 0;
}
```

Вывод:

```text
42
```

Поэтому значения, пришедшие снаружи — из ввода, файла, сети, — проверяют перед использованием. Перечисление с константой-счётчиком делает это удобным:

```c
#include <stdio.h>

enum level { LEVEL_LOW, LEVEL_MEDIUM, LEVEL_HIGH, LEVEL_COUNT };

const char *level_names[LEVEL_COUNT] = {"low", "medium", "high"};

int main(void) {
    int code;
    while (scanf("%d", &code) == 1) {
        if (code < 0 || code >= LEVEL_COUNT) {
            printf("%d: неверный код\n", code);
            continue;
        }
        enum level l = code;
        printf("%d: %s\n", code, level_names[l]);
    }
    return 0;
}
```

Ввод:

```text
2 0 5 -1 1
```

Вывод:

```text
2: high
0: low
5: неверный код
-1: неверный код
1: medium
```

Без проверки `level_names[5]` прочитал бы память за пределами массива.

## Конечный автомат

Перечисления часто описывают **состояния** системы, которая переходит из одного состояния в другое по событиям. Такую модель называют конечным автоматом. Пример — турникет в метро: он заперт, пока не опустят жетон, а после прохода снова запирается.

<MemoryDiagram title="Переходы турникета">

| Состояние  | Событие `c` (жетон) | Событие `p` (проход) |
| ---------- | ------------------- | -------------------- |
| `LOCKED`   | → `UNLOCKED`        | остаётся `LOCKED`    |
| `UNLOCKED` | остаётся `UNLOCKED` | → `LOCKED`           |

</MemoryDiagram>

```c
#include <stdio.h>

enum turnstile { LOCKED, UNLOCKED };

enum turnstile step(enum turnstile state, char event) {
    if (state == LOCKED && event == 'c') {
        return UNLOCKED;
    }
    if (state == UNLOCKED && event == 'p') {
        return LOCKED;
    }
    return state;
}

int main(void) {
    char events[64];
    scanf("%63s", events);
    enum turnstile state = LOCKED;
    int passed = 0;
    for (int i = 0; events[i] != '\0'; i++) {
        if (state == UNLOCKED && events[i] == 'p') {
            passed++;
        }
        state = step(state, events[i]);
    }
    printf("Прошло: %d, турникет %s\n", passed, state == LOCKED ? "заперт" : "открыт");
    return 0;
}
```

Ввод:

```text
cpppccpc
```

Вывод:

```text
Прошло: 2, турникет открыт
```

Вся логика переходов собрана в одной функции `step`: по текущему состоянию и событию она возвращает новое состояние. Так устроены разборщики текста, сетевые протоколы, игровые персонажи и контроллеры устройств.

## `enum` или `#define`?

Константы можно задать и через `#define`, но у перечисления есть преимущества:

- константы объединены в тип, и по объявлению `enum light l` видно, какие значения ожидаются;
- компилятор проверяет полноту `switch`;
- значения нумеруются автоматически;
- константы видны отладчику по именам.

Поэтому для набора связанных значений — состояний, видов, кодов — используйте `enum`. `#define` остаётся для отдельных констант и для случаев, когда нужен не `int`.

## Частые ошибки

<CommonMistake title="Одно имя в двух перечислениях">

`enum color { RED, GREEN }; enum light { RED, YELLOW };` — ошибка компиляции: `RED` уже объявлен. Константы перечислений общие для всего файла — используйте префиксы.

</CommonMistake>

<CommonMistake title="Ожидание нумерации с единицы">

Без явных значений первая константа равна 0. Если значения важны (коды из протокола, номера месяцев), задайте их явно.

</CommonMistake>

<CommonMistake title="Значение из ввода без проверки">

`enum level l = code;` компилируется при любом `code`. Прежде чем использовать значение как индекс массива названий, проверьте диапазон.

</CommonMistake>

<CommonMistake title="Печать через %s">

`printf("%s", RED)` — ошибка: `RED` — число, а не строка. Названия нужно хранить отдельно — в массиве строк или в функции со `switch`.

</CommonMistake>

## Итоги

- `enum имя { A, B, C };` задаёт тип и именованные целые константы; по умолчанию они равны 0, 1, 2, …
- Константе можно задать значение явно; следующие продолжают счёт от него.
- `switch` по перечислению без `default` позволяет компилятору найти необработанные значения.
- Константа-счётчик в конце (`DAY_COUNT`) задаёт размер массива названий и границу циклов.
- Перечисление в C — это `int`: значения из ввода проверяйте перед использованием.
- Перечисления удобно применять для состояний конечного автомата.
