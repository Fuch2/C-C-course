## Короткие имена для типов

После уроков о структурах и перечислениях в коде появилось много длинных имён: `struct point`, `const struct student *`, `enum weekday`. Слово `struct` или `enum` приходится повторять в каждом объявлении, параметре и возвращаемом типе.

Ключевое слово `typedef` даёт существующему типу **новое имя** — синоним. Это не новый тип, а лишь другое название уже существующего. Но правильно выбранное имя делает код короче и понятнее: `Money price` говорит больше, чем `long long price`.

## Синоним для простого типа

Запись `typedef` выглядит как объявление переменной, перед которым стоит `typedef`. Там, где было бы имя переменной, оказывается имя нового типа:

```c
#include <stdio.h>

typedef long long Money;     // сумма в копейках

Money add_tax(Money amount, int percent) {
    return amount + amount * percent / 100;
}

int main(void) {
    Money price = 199900;
    Money total = add_tax(price, 20);
    printf("%lld.%02lld\n", total / 100, total % 100);
    return 0;
}
```

Вывод:

```text
2398.80
```

`Money` — то же самое, что `long long`: его так же печатают через `%lld`, с ним работает та же арифметика. Зато по объявлению `Money add_tax(Money amount, int percent)` сразу понятно, что функция работает с деньгами, а процент — обычное число.

Есть и практическая польза: если позже суммы понадобится хранить в другом типе, достаточно изменить одну строку с `typedef`.

## `typedef` и структуры

Главное применение `typedef` — короткие имена для структур. Есть три способа записи:

```c
#include <stdio.h>

// 1. Синоним для уже объявленной структуры.
struct point {
    int x;
    int y;
};
typedef struct point Point;

// 2. Объявление и синоним одновременно.
typedef struct size {
    int width;
    int height;
} Size;

// 3. Структура без тега — у неё есть только синоним.
typedef struct {
    Point position;
    Size size;
} Window;

int main(void) {
    Window w = {.position = {10, 20}, .size = {640, 480}};
    struct point p = w.position;     // struct point и Point — один тип
    Point q = p;
    Size s = w.size;
    printf("(%d, %d) %dx%d\n", q.x, q.y, s.width, s.height);
    return 0;
}
```

Вывод:

```text
(10, 20) 640x480
```

- Способ 1 добавляет имя `Point` к существующему `struct point`. Пользоваться можно обоими.
- Способ 2 делает то же самое одной конструкцией: между `struct` и `{` — тег `size`, после `}` — синоним `Size`.
- Способ 3 обходится без тега. Тип можно называть только `Window`. Этот вариант самый короткий и встречается чаще всего.

В этом курсе синонимы типов будем писать с заглавной буквы — так их легко отличить от переменных. В реальных проектах встречаются и другие соглашения: `point_t`, `Point`, `point`. Важно одно — придерживаться выбранного стиля во всём проекте.

## `typedef` и перечисления

С перечислениями всё так же:

```c
#include <stdio.h>

typedef enum { SUIT_HEARTS, SUIT_DIAMONDS, SUIT_CLUBS, SUIT_SPADES } Suit;

typedef struct {
    int rank;      // 2..14, где 11 — валет, 14 — туз
    Suit suit;
} Card;

int is_red(Card c) {
    return c.suit == SUIT_HEARTS || c.suit == SUIT_DIAMONDS;
}

int main(void) {
    Card hand[3] = {{14, SUIT_SPADES}, {10, SUIT_HEARTS}, {7, SUIT_DIAMONDS}};
    int red = 0;
    for (int i = 0; i < 3; i++) {
        red += is_red(hand[i]);
    }
    printf("Красных карт: %d\n", red);
    return 0;
}
```

Вывод:

```text
Красных карт: 2
```

Сравните заголовок `int is_red(Card c)` с `int is_red(struct card c)` — с синонимами код читается почти как описание предметной области.

## Синонимы из стандартной библиотеки

Вы уже пользовались синонимами, созданными через `typedef`: `size_t` — тип результата `sizeof` и `strlen`, `ptrdiff_t` — тип разности указателей. Их объявляют заголовочные файлы стандартной библиотеки.

Ещё одна важная группа синонимов — **целые типы фиксированного размера** из `<stdint.h>`. Размер `int` или `long` зависит от платформы, а `int32_t` всегда занимает ровно 32 бита, `uint8_t` — ровно 8 бит без знака:

```c
#include <stdio.h>
#include <stdint.h>
#include <inttypes.h>

int main(void) {
    int64_t population = 8100000000;
    uint8_t brightness = 255;
    brightness++;                 // переход через максимум
    printf("%" PRId64 "\n", population);
    printf("%d %zu\n", brightness, sizeof(int32_t));
    return 0;
}
```

Вывод:

```text
8100000000
0 4
```

- `int64_t` гарантированно вмещает 8.1 миллиарда — для `int` это слишком много.
- `uint8_t` хранит значения от 0 до 255, после 255 идёт 0 — как и у любого беззнакового типа.
- Для печати `int64_t` в `<inttypes.h>` есть макрос `PRId64`: он превращается в правильный спецификатор для платформы (`"ld"` или `"lld"`). Запись `"%" PRId64 "\n"` — это склейка трёх строковых литералов в одну.

Такие типы используют, когда важен точный размер: в файловых форматах, сетевых протоколах, при работе с оборудованием.

## Структура, которая ссылается на себя

Полем структуры может быть указатель на структуру того же типа. Так связывают записи в цепочки — это основа **связных списков**, которые подробно разбираются в следующих модулях.

```c
#include <stdio.h>

typedef struct node {
    int value;
    struct node *next;     // здесь синоним Node ещё не объявлен
} Node;

int main(void) {
    Node third = {30, NULL};
    Node second = {20, &third};
    Node first = {10, &second};
    int sum = 0;
    for (const Node *p = &first; p != NULL; p = p->next) {
        printf("%d ", p->value);
        sum += p->value;
    }
    printf("\nСумма: %d\n", sum);
    return 0;
}
```

Вывод:

```text
10 20 30
Сумма: 60
```

Внутри фигурных скобок синоним `Node` ещё не существует — он появится только после `}`. Поэтому поле объявлено через тег: `struct node *next`. По этой причине самоссылающимся структурам тег нужен обязательно.

Цикл `for (p = &first; p != NULL; p = p->next)` идёт по цепочке: каждый узел знает, где лежит следующий, а `NULL` в поле `next` означает конец. В отличие от массива, узлы не обязаны лежать в памяти подряд.

## Синоним — не новый тип

`typedef` не создаёт новый тип, поэтому компилятор не отличает синонимы друг от друга:

```c
#include <stdio.h>

typedef double Celsius;
typedef double Fahrenheit;

Fahrenheit to_fahrenheit(Celsius c) {
    return c * 9 / 5 + 32;
}

int main(void) {
    Fahrenheit hot = 100;
    printf("%.1f\n", to_fahrenheit(hot));   // ошибка смысла, но компилятор молчит
    return 0;
}
```

Вывод:

```text
212.0
```

Функция ждёт градусы Цельсия, а получила Фаренгейта — и компилятор не возразил: оба синонима означают `double`. Имена служат документацией для людей, но не проверкой. Если типы действительно нужно различать, оборачивают значение в структуру: `typedef struct { double value; } Celsius;` — разные структуры компилятор уже не перепутает.

Ещё одно правило хорошего стиля: **не прячьте указатели в `typedef`**. Запись `typedef Node *NodePtr;` скрывает звёздочку, и по объявлению `NodePtr p` уже не видно, что это указатель, который может быть `NULL` и который нельзя копировать как значение. Исключения — только для типов, с которыми работают исключительно через функции библиотеки, как `FILE *` из следующих модулей.

## Частые ошибки

<CommonMistake title="Забытое слово typedef">

`struct { int x; int y; } Point;` без `typedef` — это объявление **переменной** `Point` безымянного структурного типа. Следующая строка `Point p;` уже не скомпилируется.

</CommonMistake>

<CommonMistake title="Синоним внутри своего же объявления">

```c
typedef struct {
    int value;
    Node *next;    // ошибка: Node ещё не объявлен
} Node;
```

Для ссылки на себя нужен тег: `typedef struct node { …; struct node *next; } Node;`.

</CommonMistake>

<CommonMistake title="Тег вместо синонима">

Если структура объявлена без тега (`typedef struct { … } Window;`), записи `struct Window` не существует — есть только `Window`.

</CommonMistake>

<CommonMistake title="Ожидание проверки типов от синонимов">

`typedef int UserId; typedef int ProductId;` — компилятор не помешает передать `ProductId` туда, где ждут `UserId`. Синонимы — документация, а не защита.

</CommonMistake>

## Итоги

- `typedef тип Имя;` создаёт синоним существующего типа; синоним и исходный тип полностью взаимозаменяемы.
- Для структур и перечислений `typedef` убирает необходимость писать `struct`/`enum`; структура без тега доступна только по синониму.
- `size_t`, `ptrdiff_t`, `int32_t`, `uint8_t`, `int64_t` — синонимы из стандартной библиотеки; типы `<stdint.h>` имеют гарантированный размер.
- Самоссылающейся структуре нужен тег: внутри объявления синоним ещё не существует.
- Синонимы не различаются компилятором; для настоящих разных типов используют обёртки-структуры.
- Не прячьте указатели за `typedef`.
