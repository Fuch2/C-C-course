## Что вы уже знаете и что будет дальше

В модуле «Старт» вы написали первые программы и научились читать сообщения компилятора. Теперь начинается систематическое изучение языка C. Модуль разбит на шесть разделов, и после каждого идёт практикум — урок, целиком состоящий из задач:

1. Первые программы: вывод, переменные, арифметика, ввод, типы данных.
2. Ветвления: сравнения, логические операции, `if`, `switch`.
3. Циклы: `while`, `for`, вложенные циклы.
4. Функции.
5. Массивы и строки.
6. Указатели и структуры.

В этом уроке разберёмся, из каких «кирпичиков» складывается текст программы: инструкции, блоки, комментарии, имена. Это скучная на первый взгляд тема, но от неё зависит, сможете ли вы через месяц прочитать собственный код.

## Инструкции

**Инструкция** (statement) — одно законченное действие: объявить переменную, напечатать текст, вычислить значение, вернуть результат. Большинство инструкций заканчивается точкой с запятой:

```c
#include <stdio.h>

int main(void) {
    int apples = 5;                 // инструкция: создать переменную
    apples = apples + 2;            // инструкция: изменить её
    printf("%d\n", apples);         // инструкция: напечатать
    return 0;                       // инструкция: завершить main
}
```

Вывод:

```text
7
```

Точка с запятой для компилятора — то же, что точка в конце предложения для читателя. Без неё компилятор не понимает, где кончается одно действие и начинается следующее. При этом перевод строки для компилятора ничего не значит: две инструкции можно написать в одной строке, а одну — растянуть на несколько.

```c
#include <stdio.h>

int main(void) {
    int a = 1; int b = 2;
    printf("%d\n",
           a + b);
    return 0;
}
```

Вывод:

```text
3
```

Программа корректна, но первую строку внутри `main` читать неудобно. Общепринятое правило: **одна инструкция — одна строка**. Длинные вызовы допустимо переносить, выравнивая продолжение.

## Блоки и отступы

Фигурные скобки `{` и `}` объединяют несколько инструкций в **блок**. Тело функции `main` — это блок. Позже вы увидите блоки внутри `if` и циклов, и блоки внутри блоков.

Компилятору безразлично, сколько пробелов стоит в начале строки. Людям — нет. Сравните два варианта одной и той же программы:

```c
#include <stdio.h>
int main(void){printf("Пример\n");
printf("без отступов\n");return 0;}
```

Вывод:

```text
Пример
без отступов
```

```c
#include <stdio.h>

int main(void) {
    printf("Пример\n");
    printf("с отступами\n");
    return 0;
}
```

Вывод:

```text
Пример
с отступами
```

Обе программы работают, но вторую понять намного проще. В этом курсе принят стиль:

- отступ внутри каждого блока — **4 пробела**;
- открывающая `{` на той же строке, что и заголовок;
- закрывающая `}` на отдельной строке, на уровне начала заголовка;
- пустые строки разделяют логические части программы.

<Tip title="Отступы — это не украшение">

Отступы показывают структуру программы. Когда появятся вложенные условия и циклы, неправильные отступы будут прямо вводить вас в заблуждение: код будет выглядеть так, будто инструкция находится внутри блока, хотя на самом деле она снаружи.

</Tip>

## Комментарии

**Комментарий** — текст для людей, который компилятор полностью игнорирует. В C два вида комментариев:

```c
#include <stdio.h>

int main(void) {
    // Однострочный: от двух косых черт до конца строки.
    printf("Раз\n");

    /* Многострочный: всё между косой чертой со звёздочкой
       и звёздочкой с косой чертой, даже если строк несколько. */
    printf("Два\n");

    // printf("Три\n");   — эта строка «закомментирована» и не выполнится
    return 0;
}
```

Вывод:

```text
Раз
Два
```

Последний пример показывает частое применение комментариев: временно «выключить» строку кода, не удаляя её. В отладке это очень удобно.

Хороший комментарий объясняет **зачем**, а не **что**. Код `count = count + 1;` и так говорит, что `count` увеличивается на единицу. Комментарий `// учитываем заголовок таблицы` объясняет причину — это полезно.

<Warning title="Многострочные комментарии не вкладываются">

Комментарий `/* ... */` заканчивается на **первом** встреченном `*/`. Если внутри есть ещё один `/* ... */`, внешний комментарий оборвётся раньше, чем вы ожидаете, и компилятор увидит обрывок текста как код.

</Warning>

## Имена: правила и соглашения

Переменным, функциям и другим сущностям программист даёт **имена** (идентификаторы). Правила языка:

- имя состоит из латинских букв, цифр и знака подчёркивания `_`;
- имя не может начинаться с цифры: `total2` можно, `2total` — нельзя;
- регистр важен: `count`, `Count` и `COUNT` — три разных имени;
- нельзя использовать **ключевые слова** языка — слова, у которых в C уже есть смысл.

Ключевых слов в C немного. Вот те, что встретятся в курсе первыми:

| Ключевые слова                            | Для чего              |
| ----------------------------------------- | --------------------- |
| `int`, `char`, `double`, `void`           | Типы данных           |
| `if`, `else`, `switch`, `case`            | Ветвления             |
| `while`, `do`, `for`, `break`, `continue` | Циклы                 |
| `return`                                  | Возврат из функции    |
| `const`, `struct`, `enum`, `typedef`      | Константы и свои типы |

Кроме правил есть **соглашения** — договорённости, которых придерживаются программисты. В C принято писать имена переменных и функций строчными буквами, разделяя слова подчёркиванием: `total_price`, `max_speed`, `read_input`. Такой стиль называют snake_case.

| Имя           | Допустимо? | Хорошее?                               |
| ------------- | ---------- | -------------------------------------- |
| `total_price` | да         | да: понятно, что хранится              |
| `x`           | да         | только для коротких формул и счётчиков |
| `tp`          | да         | нет: через неделю не вспомните смысл   |
| `2nd_value`   | нет        | начинается с цифры                     |
| `return`      | нет        | ключевое слово                         |
| `цена`        | нет        | в стандарте C имена только латиницей   |

## Порядок выполнения

Внутри блока инструкции выполняются строго сверху вниз, одна за другой. Это кажется очевидным, но из этого следует важная вещь: инструкция видит результат всех инструкций **выше** неё и ничего не знает о тех, что ниже.

```c
#include <stdio.h>

int main(void) {
    int score = 10;
    printf("%d\n", score);
    score = 25;
    printf("%d\n", score);
    return 0;
}
```

Вывод:

```text
10
25
```

Первый `printf` выполняется, когда в `score` ещё лежит 10. То, что ниже значение изменится, на него никак не влияет. В следующих разделах появятся конструкции, которые меняют этот порядок, — условия и циклы, — но внутри любого блока правило «сверху вниз» сохраняется.

## Частые ошибки

<CommonMistake title="Точка с запятой после закрывающей скобки функции или перед открывающей">

`int main(void); {` — ошибка. После заголовка функции сразу идёт блок. Точка с запятой ставится после инструкций, а не после заголовков и не после `}` функции.

</CommonMistake>

<CommonMistake title="Кириллица в именах и «умные» кавычки">

Русские буквы допустимы внутри строк в кавычках, но не в именах. Если вы набирали код в текстовом редакторе, проверьте, не превратились ли прямые кавычки `"` в «ёлочки».

</CommonMistake>

<CommonMistake title="Комментарий, который врёт">

Код изменили, а комментарий — нет. Устаревший комментарий хуже его отсутствия: он уверенно сообщает неправду. Меняя код, перечитывайте комментарии рядом.

</CommonMistake>

## Практика

1. **Включите нужные строки** — работа с закомментированным кодом.
2. **Наведите порядок** — расставьте инструкции так, чтобы вывод совпал с образцом.
3. **Рамка** — напечатайте текст в рамке из символов.
4. **Расписание** — несколько строк с выравниванием табуляцией.

## Итоги

- Инструкция — одно действие; почти все инструкции заканчиваются точкой с запятой.
- Фигурные скобки объединяют инструкции в блок; отступ внутри блока — 4 пробела.
- Комментарии `//` и `/* */` игнорируются компилятором; ими поясняют «зачем» и временно отключают код.
- Имена: латинские буквы, цифры и `_`, не начинаются с цифры, регистр важен, ключевые слова запрещены. Принят стиль `snake_case`.
- Инструкции в блоке выполняются сверху вниз.
