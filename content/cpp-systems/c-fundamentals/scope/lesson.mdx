## Где «видна» переменная

В функциях из прошлых уроков были переменные с одинаковыми именами — `i` в `main` и `i` в функции, — и они не мешали друг другу. Почему? Каждая переменная в C имеет **область видимости** — часть программы, где к ней можно обратиться по имени, — и **время жизни** — период, когда она существует в памяти. Понимание этих двух свойств избавляет от целого класса загадочных ошибок.

## Локальные переменные и блоки

Переменная, объявленная внутри блока `{ ... }`, видна только в этом блоке — от точки объявления до закрывающей скобки. Такие переменные называют **локальными**.

```c
#include <stdio.h>

int main(void) {
    int total = 0;
    for (int i = 1; i <= 3; i++) {
        int square = i * i;      // видна только внутри тела цикла
        total += square;
    }
    // здесь нет ни i, ни square
    printf("%d\n", total);
    return 0;
}
```

Вывод:

```text
14
```

Попытка использовать `square` после цикла даст ошибку компиляции `'square' undeclared`. Это не неудобство, а помощь: переменная существует ровно там, где нужна, и её нельзя случайно использовать с устаревшим значением.

Правило хорошего стиля: **объявляйте переменную как можно ближе к месту использования** и в самом узком блоке, где она нужна.

## Параметры и локальные переменные функций

Параметры и переменные функции — локальные для неё. Две функции могут использовать одинаковые имена, и это разные переменные:

```c
#include <stdio.h>

int sum_to(int n) {
    int total = 0;
    for (int i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

int main(void) {
    int total = 100;
    int i = 7;
    printf("%d\n", sum_to(4));
    printf("%d %d\n", total, i);    // не изменились
    return 0;
}
```

Вывод:

```text
10
100 7
```

У каждого **вызова** функции свои локальные переменные: они создаются при входе в функцию и уничтожаются при выходе. Если функцию вызвать дважды, второй вызов начнёт с «чистого листа» — значения первого вызова не сохраняются.

## Затенение имён

Во вложенном блоке можно объявить переменную с тем же именем, что и во внешнем. Тогда внутреннее имя **затеняет** внешнее: внутри блока имя относится к новой переменной.

```c
#include <stdio.h>

int main(void) {
    int count = 5;
    {
        int count = 10;          // другая переменная!
        count++;
        printf("внутри: %d\n", count);
    }
    printf("снаружи: %d\n", count);
    return 0;
}
```

Вывод:

```text
внутри: 11
снаружи: 5
```

Так почти никогда не делают намеренно. Обычно затенение — ошибка: программист хотел изменить внешнюю переменную, но случайно написал `int` перед именем и создал новую. Флаг компилятора `-Wshadow` предупреждает о таких местах.

## Глобальные переменные

Переменная, объявленная **вне всех функций**, — **глобальная**: она видна во всех функциях ниже по файлу и существует всё время работы программы.

```c
#include <stdio.h>

int call_count = 0;     // глобальная переменная

void greet(void) {
    call_count++;
    printf("привет #%d\n", call_count);
}

int main(void) {
    greet();
    greet();
    printf("всего вызовов: %d\n", call_count);
    return 0;
}
```

Вывод:

```text
привет #1
привет #2
всего вызовов: 2
```

Глобальные переменные кажутся удобными, но создают проблемы:

- любая функция может изменить переменную, и, читая одну функцию, нельзя понять, откуда взялось значение;
- функцию с глобальным состоянием трудно тестировать: её результат зависит не только от аргументов;
- в больших программах легко случайно использовать одно имя для разных целей.

Правило: **передавайте данные через параметры и возвращаемые значения**. Глобальные переменные оставляйте для действительно общих для всей программы вещей — и то лучше в виде констант.

Есть важное отличие в инициализации: глобальные переменные, если им не задано значение, автоматически **обнуляются**. Локальные — нет, в них мусор.

## `static` у локальной переменной

Иногда функции нужно **помнить** что-то между вызовами, но не хочется заводить глобальную переменную. Для этого локальную переменную объявляют `static`:

```c
#include <stdio.h>

int next_ticket(void) {
    static int last = 0;    // инициализируется один раз
    last++;
    return last;
}

int main(void) {
    printf("%d\n", next_ticket());
    printf("%d\n", next_ticket());
    printf("%d\n", next_ticket());
    return 0;
}
```

Вывод:

```text
1
2
3
```

У `static`-переменной **область видимости** локальная (она видна только внутри функции), а **время жизни** — как у глобальной: она создаётся один раз при запуске программы и сохраняет значение между вызовами. Строка `static int last = 0;` выполняет инициализацию только однажды, а не при каждом вызове.

<MemoryDiagram title="Видимость и время жизни">

| Вид переменной     | Где видна                    | Сколько живёт              | Начальное значение    |
| ------------------ | ---------------------------- | -------------------------- | --------------------- |
| Локальная          | от объявления до конца блока | до выхода из блока         | мусор, если не задано |
| Параметр           | всё тело функции             | время вызова функции       | значение аргумента    |
| `static` локальная | внутри функции               | всё время работы программы | 0, если не задано     |
| Глобальная         | все функции ниже по файлу    | всё время работы программы | 0, если не задано     |

</MemoryDiagram>

## `static` у глобальной переменной

Слово `static` перед **глобальной** переменной означает другое: переменная видна только в своём файле. Это важно в программах из нескольких файлов, о которых пойдёт речь в модуле «Углублённый C». В однофайловой программе такая переменная ведёт себя как обычная глобальная, но сразу сообщает читателю: «это внутреннее состояние этого файла».

## Частые ошибки

<CommonMistake title="Случайное новое объявление">

`int total = 0; for (...) { int total = total + x; }` — внутри цикла создаётся новая переменная, внешняя не меняется. Уберите `int` внутри цикла.

</CommonMistake>

<CommonMistake title="Использование переменной вне её блока">

Переменная, объявленная в `if` или в теле цикла, после закрывающей скобки уже не существует. Если значение нужно после блока, объявите переменную до него.

</CommonMistake>

<CommonMistake title="Глобальная переменная вместо параметра">

Функция, читающая глобальную переменную, «скрывает» свою зависимость. Если ей нужно значение — передайте его параметром.

</CommonMistake>

## Практика

1. **Номерки** — функция со `static`-счётчиком.
2. **Нарастающий итог** — `static`-аккумулятор.
3. **Пропавшая сумма** — найдите затенение.
4. **Генератор случайных чисел** — общее состояние двух функций.

## Итоги

- Область видимости — где имя доступно; время жизни — когда переменная существует.
- Локальные переменные видны в своём блоке и уничтожаются при выходе из него; каждый вызов функции получает свои.
- Внутреннее объявление затеняет внешнее с тем же именем — обычно это ошибка.
- Глобальные переменные видны всем функциям и живут всю программу; используйте их как можно реже.
- `static`-локальная переменная видна только в функции, но сохраняет значение между вызовами и инициализируется один раз.
- Глобальные и `static`-переменные без инициализатора равны нулю, обычные локальные — нет.
