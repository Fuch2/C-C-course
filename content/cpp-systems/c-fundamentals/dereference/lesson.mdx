## Работа с данными через указатель

Вы уже знаете, что `*p` — значение по адресу из `p`. В этом уроке разберём разыменование подробнее: как указатели позволяют обращаться к одним данным под разными именами, как `const` защищает данные от изменения через указатель, почему важны скобки в `(*p)++` и почему нельзя хранить адрес переменной, которая уже исчезла.

## `*p` ведёт себя как переменная

Разыменованный указатель можно использовать везде, где допустима обычная переменная: в выражениях, слева от `=`, в составном присваивании, в `scanf`:

```c
#include <stdio.h>

int main(void) {
    int balance = 100;
    int *p = &balance;
    *p += 50;          // balance = 150
    *p = *p * 2;       // balance = 300
    (*p)--;            // balance = 299
    scanf("%d", p);    // p уже адрес — & не нужен
    printf("%d\n", balance);
    return 0;
}
```

Ввод:

```text
7
```

Вывод:

```text
7
```

Последний `scanf` записал введённое число прямо в `balance`: `p` — это и есть адрес, поэтому `&` не нужен. Напишите `&p` — и `scanf` получит адрес самого указателя, а это уже ошибка.

## Псевдонимы

Если два указателя (или указатель и имя переменной) ссылаются на одно место, они — **псевдонимы**: изменение через одно имя видно через другое.

```c
#include <stdio.h>

int main(void) {
    int value = 10;
    int *p = &value;
    int *q = &value;
    *p += 5;
    *q *= 2;
    printf("%d %d %d\n", value, *p, *q);
    return 0;
}
```

Вывод:

```text
30 30 30
```

Все три имени — `value`, `*p`, `*q` — обозначают одну ячейку памяти: (10 + 5) · 2 = 30. Псевдонимы — источник и силы, и ошибок: читая код с указателями, всегда спрашивайте себя, на что сейчас указывает каждый из них.

## Приоритет: `(*p)++` и `*p++`

Постфиксный `++` имеет **более высокий** приоритет, чем разыменование `*`. Поэтому:

- `(*p)++` — увеличить **значение** по адресу;
- `*p++` — прочитать значение, затем сдвинуть **сам указатель** на следующий элемент.

```c
#include <stdio.h>

int main(void) {
    int a[3] = {10, 20, 30};
    int *p = &a[0];
    (*p)++;                 // a[0] стал 11, p на месте
    printf("%d %d\n", a[0], *p);
    int first = *p++;       // прочитали 11, p теперь указывает на a[1]
    printf("%d %d\n", first, *p);
    return 0;
}
```

Вывод:

```text
11 11
11 20
```

Запись `*p++` — классическая идиома C для прохода по массиву, к ней вернёмся в уроке «Арифметика указателей». Пока правило простое: если хотите изменить значение — ставьте скобки `(*p)++`.

## `const` и указатели

`const` рядом с указателем может защищать две разные вещи — данные или сам указатель. Читайте объявление **справа налево**:

| Объявление           | Читается                                 | Можно `*p = …` | Можно `p = …` |
| -------------------- | ---------------------------------------- | -------------- | ------------- |
| `int *p`             | указатель на int                         | да             | да            |
| `const int *p`       | указатель на константный int             | **нет**        | да            |
| `int *const p`       | константный указатель на int             | да             | **нет**       |
| `const int *const p` | константный указатель на константный int | **нет**        | **нет**       |

Чаще всего встречается второй вариант — `const int *p`. Он означает: «через этот указатель данные только читают». Вы уже видели его в параметрах функций: `int max_of(const int a[], int n)`. Компилятор запретит запись:

```c
#include <stdio.h>

int main(void) {
    int limit = 10;
    const int *view = &limit;
    printf("%d\n", *view);
    *view = 20;     // Ошибка компиляции: assignment of read-only location
    return 0;
}
```

Обратите внимание: сама переменная `limit` не константа — её можно менять напрямую (`limit = 20;`). `const` запрещает менять её **через этот указатель**. Это обещание кода, который получил указатель, — «я только посмотрю».

## Указатель, который пережил свою переменную

Указатель хранит только адрес. Он не знает, существует ли ещё переменная по этому адресу. Если функция вернёт адрес своей локальной переменной, после возврата переменной уже нет, а указатель «висит»:

```c
int *broken(void) {
    int local = 42;
    return &local;       // ошибка: local исчезнет после return
}
```

Компилятор предупреждает: `function returns address of local variable`. Использование такого указателя — неопределённое поведение: программа может напечатать 42, мусор или упасть. Висячим указателям и способам их избежать посвящены уроки модуля «Память и указатели».

## Частые ошибки

<CommonMistake title="*p++ вместо (*p)++">

`*p++;` сдвигает указатель, а не увеличивает значение. Компилятор может предупредить, что результат разыменования не используется.

</CommonMistake>

<CommonMistake title="& перед указателем в scanf">

`scanf("%d", &p)` при `int *p` записывает число **в сам указатель**. Если `p` уже хранит адрес нужной переменной, пишите `scanf("%d", p)`.

</CommonMistake>

<CommonMistake title="Попытка изменить данные через const-указатель">

`const int *p` — указатель «только для чтения». Если функции нужно менять данные, параметр должен быть без `const`.

</CommonMistake>

<CommonMistake title="Возврат адреса локальной переменной">

Локальные переменные исчезают после выхода из функции. Возвращать нужно значение, а не адрес локальной переменной.

</CommonMistake>

## Практика

В задачах этого урока программа выполняет команды — как маленький интерпретатор. Команды читаются до конца ввода.

1. **Регистры** — указатель выбирает, какую переменную менять.
2. **Курсор** — указатель ходит по массиву.
3. **Только для чтения** — исправьте ошибку с `const`.

## Итоги

- `*p` можно использовать как обычную переменную: в выражениях, присваиваниях, `scanf(…, p)`.
- Несколько указателей на одно место — псевдонимы; изменение через один виден через все.
- `(*p)++` увеличивает значение, `*p++` сдвигает указатель.
- `const int *p` — данные только для чтения; `int *const p` — указатель нельзя перенаправить.
- Указатель не продлевает жизнь переменной: адрес локальной переменной нельзя использовать после выхода из функции.
