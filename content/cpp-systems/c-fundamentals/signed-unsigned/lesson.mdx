## Числа без знака

Некоторые величины в принципе не бывают отрицательными: количество байт в файле, номер пикселя, цвет от 0 до 255. Для них в C есть **беззнаковые** (unsigned) типы. Им не нужно тратить половину комбинаций битов на минус, поэтому положительный диапазон у них вдвое больше. Но вместе с этим приходят свои правила, и одно из них — источник самых коварных ошибок в C. Разберёмся.

## `unsigned int`

Слово `unsigned` перед типом делает его беззнаковым. Для печати используется `%u`:

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    unsigned int big = 4000000000u;
    printf("%u\n", big);
    printf("%u\n", UINT_MAX);
    return 0;
}
```

Вывод:

```text
4000000000
4294967295
```

32-битный `unsigned int` хранит значения от 0 до 4 294 967 295 (2³² − 1). Суффикс `u` у константы `4000000000u` говорит компилятору, что это беззнаковое число.

| Знаковый тип | Беззнаковый          | Спецификатор | Диапазон беззнакового |
| ------------ | -------------------- | ------------ | --------------------- |
| `int`        | `unsigned int`       | `%u`         | 0 … 4 294 967 295     |
| `long long`  | `unsigned long long` | `%llu`       | 0 … ≈ 1,8 · 10¹⁹      |
| `char`       | `unsigned char`      | `%d` / `%u`  | 0 … 255               |

## Переполнение беззнаковых — по кругу

В прошлом уроке вы узнали, что переполнение знакового `int` — неопределённое поведение. С беззнаковыми типами всё иначе: стандарт **гарантирует**, что вычисления выполняются по модулю 2ⁿ. Число, вышедшее за верхнюю границу, начинает отсчёт с нуля, а вычитание из нуля даёт максимальное значение — как на механическом счётчике пробега.

```c
#include <stdio.h>
#include <limits.h>

int main(void) {
    unsigned int max = UINT_MAX;
    unsigned int zero = 0;
    printf("%u\n", max + 1);
    printf("%u\n", zero - 1);
    printf("%u\n", 5u - 7u);
    return 0;
}
```

Вывод:

```text
0
4294967295
4294967294
```

`5u - 7u` — не −2, а 2³² − 2. Беззнаковые числа не умеют быть отрицательными, и результат «заворачивается» с другого конца.

Это поведение полезно, когда цикличность и нужна: хеш-функции, контрольные суммы, генераторы случайных чисел, работа с битами. И опасно, когда вы его не ждёте.

## Главная ловушка: смешивание знаковых и беззнаковых

Если в выражении встречаются `int` и `unsigned int`, знаковое значение **преобразуется в беззнаковое**. И −1 превращается в 4 294 967 295:

```c
#include <stdio.h>

int main(void) {
    int balance = -1;
    unsigned int limit = 10;
    printf("%d\n", balance < limit);      // Предупреждение: сравнение со знаком и без
    return 0;
}
```

Вывод:

```text
0
```

Сравнение `-1 < 10` должно быть истинным (1), но программа говорит, что ложно. Перед сравнением `balance` превратился в 4 294 967 295, а это больше 10. Компилятор предупреждает:

```text
warning: comparison of integer expressions of different signedness: 'int' and 'unsigned int' [-Wsign-compare]
```

Если видите такое предупреждение — это не формальность, а реальная ошибка в логике.

<Important title="Правило выбора">

Используйте `unsigned`, когда значение действительно не может быть отрицательным **и** не участвует в вычитании и сравнении со знаковыми числами: биты, маски, хеши, коды цветов. Для количеств, которые вычитаются и сравниваются (остаток на счёте, разница дат, индекс, который может уйти в минус), используйте обычный `int` или `long long`.

</Important>

## Приведение знакового к беззнаковому

Явное приведение `(unsigned int)x` для отрицательного `x` даёт `x + 2³²`. Это не ошибка, а точно определённое правило:

```c
#include <stdio.h>

int main(void) {
    int values[] = {-1, -2, -2147483647 - 1};
    printf("%u %u %u\n", (unsigned int)values[0], (unsigned int)values[1],
           (unsigned int)values[2]);
    return 0;
}
```

Вывод:

```text
4294967295 4294967294 2147483648
```

(Запись `int values[] = {...}` — массив, о нём будет отдельный урок. Здесь это просто три числа под одним именем.)

Внутри компьютера знаковые числа хранятся в так называемом **дополнительном коде**: биты −1 совпадают с битами 4 294 967 295. Приведение типа меняет не биты, а то, как они толкуются.

## Типы точного размера: `<stdint.h>`

Размер `int` и `long` формально зависит от системы. Когда точный размер важен — в файлах, сетевых протоколах, работе с устройствами, — используют типы из заголовка `<stdint.h>`:

| Тип        | Размер  | Диапазон         |
| ---------- | ------- | ---------------- |
| `int8_t`   | 8 бит   | −128 … 127       |
| `uint8_t`  | 8 бит   | 0 … 255          |
| `int16_t`  | 16 бит  | −32 768 … 32 767 |
| `uint16_t` | 16 бит  | 0 … 65 535       |
| `int32_t`  | 32 бита | ≈ ±2,1 · 10⁹     |
| `uint32_t` | 32 бита | 0 … ≈ 4,3 · 10⁹  |
| `int64_t`  | 64 бита | ≈ ±9,2 · 10¹⁸    |
| `uint64_t` | 64 бита | 0 … ≈ 1,8 · 10¹⁹ |

Буква `u` означает unsigned, число — количество бит, `_t` — соглашение для имён типов.

```c
#include <stdio.h>
#include <stdint.h>

int main(void) {
    uint8_t brightness = 250;
    brightness = brightness + 10;    // 260 не помещается в 8 бит
    printf("%d\n", brightness);
    return 0;
}
```

Вывод:

```text
4
```

260 по модулю 256 равно 4. При записи в `uint8_t` значение «обрезается» до младших 8 бит. Для печати маленьких типов подходит обычный `%d`: при передаче в `printf` они автоматически расширяются до `int`.

## Частые ошибки

<CommonMistake title="Ожидать отрицательный результат от беззнакового вычитания">

`unsigned a = 3, b = 5; a - b` — это 4 294 967 294, а не −2. Если разность может быть отрицательной, вычисляйте её в знаковом типе.

</CommonMistake>

<CommonMistake title="Игнорировать -Wsign-compare">

Сравнение `int` с `unsigned` молча превращает отрицательные числа в огромные положительные. Предупреждение компилятора — повод привести типы к одному.

</CommonMistake>

<CommonMistake title="%d для unsigned int">

`printf("%d", 4000000000u)` напечатает отрицательное число: `%d` толкует биты как знаковые. Для `unsigned int` — `%u`, для `unsigned long long` — `%llu`.

</CommonMistake>

## Практика

1. **Как увидит unsigned** — приведение отрицательного числа.
2. **Разность по кругу** — беззнаковое вычитание.
3. **Яркость пикселя** — `uint8_t` и переполнение по модулю 256.
4. **Шестнадцатибитный счётчик** — `uint16_t`.

## Итоги

- Беззнаковые типы хранят только неотрицательные значения: `unsigned int` — от 0 до 4 294 967 295, печать через `%u`.
- Беззнаковая арифметика выполняется по модулю 2ⁿ: `0u - 1` — максимальное значение. Это определённое поведение, в отличие от переполнения знаковых.
- При смешивании `int` и `unsigned` знаковое значение становится беззнаковым: −1 превращается в огромное число. Следите за предупреждением `-Wsign-compare`.
- `<stdint.h>` даёт типы точного размера: `int32_t`, `uint8_t`, `uint64_t` и другие.
- Для обычных количеств используйте знаковые типы; беззнаковые — для битов, хешей и данных фиксированного формата.
