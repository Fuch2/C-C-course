## Массивы нельзя присвоить

Структуру можно скопировать одной операцией `a = b`, а массив — нет: запись `dst = src` для массивов не компилируется. Копировать поэлементно в цикле можно, но в C для этого есть быстрые функции из `<string.h>`, которые работают с памятью **как с байтами**:

| Функция                 | Что делает                                               |
| ----------------------- | -------------------------------------------------------- |
| `memcpy(dst, src, n)`   | копирует `n` байтов; области **не должны перекрываться** |
| `memmove(dst, src, n)`  | копирует `n` байтов; области могут перекрываться         |
| `memset(dst, value, n)` | записывает байт `value` в `n` байтов подряд              |
| `memcmp(a, b, n)`       | сравнивает `n` байтов, возвращает `< 0`, `0` или `> 0`   |

Все они принимают `void *` — «адрес чего угодно» — и **число байтов**, а не элементов. О `void *` подробно поговорим в отдельном уроке; сейчас достаточно знать, что туда можно передать указатель любого типа.

## `memcpy`: копирование блока

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    int src[5] = {10, 20, 30, 40, 50};
    int dst[5] = {0};
    memcpy(dst, src, sizeof src);                    // весь массив: 20 байтов
    int part[2];
    memcpy(part, src + 3, 2 * sizeof src[0]);        // элементы src[3] и src[4]
    printf("%d %d %d\n", dst[0], dst[4], part[0] + part[1]);
    return 0;
}
```

Вывод:

```text
10 50 90
```

Третий аргумент — **байты**. Для части массива это «количество элементов × `sizeof` элемента». Начало копируемого участка задаётся арифметикой указателей: `src + 3` — адрес элемента `src[3]`.

## Как это устроено внутри

`memcpy` видит память как последовательность байтов. Простейшая реализация — цикл по `unsigned char *`:

```c
#include <stdio.h>

void *copy_bytes(void *dst, const void *src, size_t n) {
    unsigned char *d = dst;               // void * неявно превращается в unsigned char *
    const unsigned char *s = src;
    for (size_t i = 0; i < n; i++) {
        d[i] = s[i];
    }
    return dst;
}

int main(void) {
    double a[3] = {1.5, 2.5, 3.5};
    double b[3];
    copy_bytes(b, a, sizeof a);
    printf("%.1f %.1f %.1f\n", b[0], b[1], b[2]);
    return 0;
}
```

Вывод:

```text
1.5 2.5 3.5
```

Функции не нужно знать, что копируются `double`: байты переносятся один в один, и в `b` получаются те же числа. Настоящая `memcpy` копирует сразу по 8, 16 или 32 байта и поэтому значительно быстрее цикла, но смысл тот же.

## Перекрытие: `memcpy` против `memmove`

Нужно вставить число в середину массива — сдвинуть хвост на одну позицию вправо. Источник и приёмник **перекрываются**: `a + 2` и `a + 3` — участки одного массива. `memcpy` для этого использовать нельзя: копируя вперёд, она перезапишет байты, которые ещё не успела прочитать. Стандарт объявляет такой вызов неопределённым поведением, и AddressSanitizer его ловит:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    int a[6] = {1, 2, 3, 4, 5};
    memcpy(a + 3, a + 2, 3 * sizeof a[0]);       // Ошибка памяти: области перекрываются
    a[2] = 99;
    printf("%d %d %d\n", a[2], a[3], a[5]);
    return 0;
}
```

Отчёт санитайзера:

```text
ERROR: AddressSanitizer: memcpy-param-overlap: memory ranges [0x7ffffffca8cc,0x7ffffffca8d8) and [0x7ffffffca8c8, 0x7ffffffca8d4) overlap
    #0 0x5555555f7374 in __asan_memcpy
    #1 0x555555633115 in main /work/main.c:6:5
```

Диапазоны отличаются на 4 байта — на один `int`: приёмник начинается внутри источника.

`memmove` гарантирует правильный результат при любом перекрытии — она выбирает направление копирования (с конца, если приёмник правее источника):

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    int a[6] = {1, 2, 3, 4, 5};
    int n = 5;
    int pos = 2;
    memmove(a + pos + 1, a + pos, (n - pos) * sizeof a[0]);   // сдвиг хвоста вправо
    a[pos] = 99;
    n++;
    for (int i = 0; i < n; i++) {
        printf("%d ", a[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
1 2 99 3 4 5
```

Удаление элемента — сдвиг хвоста влево — тоже перекрытие и тоже `memmove`. Правило простое: **если источник и приёмник — части одного массива, используйте `memmove`**.

## `memset`: заполнение байтами

`memset` записывает **один и тот же байт** в каждую позицию. Поэтому она подходит для обнуления любых данных и для заполнения массивов `char`:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    int counts[4];
    memset(counts, 0, sizeof counts);          // все байты 0 — все числа 0
    char line[8];
    memset(line, '-', sizeof line - 1);
    line[7] = '\0';
    int ones[2];
    memset(ones, 1, sizeof ones);              // каждый БАЙТ равен 1!
    printf("%d %d %s %d\n", counts[0], counts[3], line, ones[0]);
    return 0;
}
```

Вывод:

```text
0 0 ------- 16843009
```

Последнее число — ловушка: `memset(ones, 1, ...)` записал единицу в **каждый байт**, и четыре байта `01 01 01 01` образовали число `0x01010101 = 16843009`. Для заполнения массива `int` ненулевым значением нужен обычный цикл.

## `memcmp`: сравнение байтов

`memcmp` сравнивает байты по порядку и возвращает разность первых несовпавших (как беззнаковых чисел), либо 0, если все `n` байтов равны:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    unsigned char a[4] = {1, 2, 3, 4};
    unsigned char b[4] = {1, 2, 9, 0};
    char code1[4] = {'A', 'B', 'C', 'D'};
    char code2[4] = {'A', 'B', 'C', 'D'};
    printf("%d\n", memcmp(a, b, 4) < 0);       // 3 < 9 во втором байте
    printf("%d\n", memcmp(a, b, 2) == 0);      // первые два байта равны
    printf("%d\n", memcmp(code1, code2, sizeof code1) == 0);
    return 0;
}
```

Вывод:

```text
1
1
1
```

В отличие от `strcmp`, `memcmp` не останавливается на нулевом байте — она сравнивает ровно `n` байтов. Это удобно для двоичных данных фиксированной длины. Но помните урок о байтах: для `double` и структур с промежутками выравнивания равенство байтов не совпадает с равенством значений, такие объекты сравнивают поле за полем.

<Concept title="Байтовые функции не знают типов">

`memcpy`, `memmove`, `memset` и `memcmp` работают с «сырыми» байтами. Они не знают, что копируют `int` или структуру, и не проверяют границы. Всю ответственность за правильный размер и отсутствие перекрытия несёт вызывающий код. Почти всегда размер записывается как `количество * sizeof элемента`.

</Concept>

## Частые ошибки

<CommonMistake title="Количество элементов вместо байтов">

`memcpy(dst, src, n)` для массива из `n` чисел `int` скопирует только `n` байтов — четверть данных. Правильно: `memcpy(dst, src, n * sizeof *src)`.

</CommonMistake>

<CommonMistake title="memcpy для перекрывающихся областей">

Сдвиг внутри одного массива через `memcpy` — неопределённое поведение: результат зависит от реализации и может меняться с версией библиотеки. Используйте `memmove`.

</CommonMistake>

<CommonMistake title="memset с ненулевым значением для int">

`memset(a, -1, sizeof a)` даёт `-1` во всех `int` (все биты — единицы), а `memset(a, 5, sizeof a)` — число `0x05050505`. Кроме нуля и `-1`, заполняйте массивы чисел циклом.

</CommonMistake>

<CommonMistake title="sizeof указателя вместо массива">

```c
void clear(int *a, size_t n) {
    memset(a, 0, sizeof a);       // обнулит только 8 байтов!
}
```

Внутри функции `a` — указатель. Размер передавайте параметром: `memset(a, 0, n * sizeof *a)`.

</CommonMistake>

## Практика

1. **Вставка в массив** — сдвиг хвоста вправо через `memmove`.
2. **Удаление отрезка** — сдвиг хвоста влево.
3. **Циклический сдвиг** — две `memcpy` через вспомогательный буфер.
4. **Своя memmove** — копирование с правильным направлением при перекрытии.

## Итоги

- `memcpy`, `memmove`, `memset`, `memcmp` из `<string.h>` работают с байтами; размер — всегда в байтах.
- `memcpy` требует, чтобы области не перекрывались; для сдвигов внутри одного массива нужна `memmove`.
- `memset` записывает один байт во все позиции: годится для обнуления и массивов `char`, но не для заполнения `int` числом 1.
- `memcmp` сравнивает ровно `n` байтов и не останавливается на нуле.
- Внутри эти функции — циклы по `unsigned char *`; они не знают типов и не проверяют границы.
