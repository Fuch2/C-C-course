## Зачем знать, где живут данные

В «Основах C» вы объявляли переменные и не задумывались, где они хранятся. Для коротких программ этого хватало. Но как только данные начинают передаваться между функциями, выделяться по запросу и жить дольше одного вызова, появляются вопросы:

- почему локальная переменная «забывает» значение между вызовами функции, а `static` — нет;
- почему адрес локального массива нельзя вернуть из функции;
- почему программа падает, если изменить строковый литерал;
- откуда берётся память под массив, размер которого известен только во время работы.

Ответ на все эти вопросы один: у каждого объекта в C есть **место** и **время жизни**. Этот модуль учит видеть их в любом коде. Начнём с общей карты.

## Четыре области памяти

Когда операционная система запускает программу, она выделяет ей участок памяти — **адресное пространство процесса**. Внутри него данные разложены по областям с разными правилами:

| Область                | Что там лежит                                                  | Когда появляется и исчезает                        |
| ---------------------- | -------------------------------------------------------------- | -------------------------------------------------- |
| **Код**                | машинные команды ваших функций                                 | весь запуск, только для чтения                     |
| **Статические данные** | глобальные переменные, переменные `static`, строковые литералы | создаются до `main`, исчезают после её завершения  |
| **Стек**               | локальные переменные и параметры функций                       | при входе в функцию — появляются, при выходе — нет |
| **Куча**               | блоки, выделенные `malloc`, `calloc`, `realloc`                | когда программа попросит — и до явного `free`      |

<MemoryDiagram title="Типичная карта памяти процесса (упрощённо)">

| Область            | Пример объекта                | Размер                            |
| ------------------ | ----------------------------- | --------------------------------- |
| Код                | инструкции `main`, `printf`   | известен после компиляции         |
| Статические данные | `int total;`, `"Привет"`      | известен после компиляции         |
| Куча ↓             | `malloc(n * sizeof(int))`     | растёт по запросам программы      |
| … свободно …       |                               |                                   |
| Стек ↑             | локальные `int i`, `double t` | растёт с каждым вложенным вызовом |

</MemoryDiagram>

Стрелки показывают типичное направление роста: куча и стек занимают свободное пространство с разных сторон. Точное расположение зависит от системы, компилятора и оптимизаций; стандарт C говорит не об «областях», а о **длительности хранения** объектов. Но карта помогает понять, почему правила именно такие.

## Смотрим на адреса из разных областей

Напечатаем адреса объектов, которые живут в разных местах:

```c
#include <stdio.h>
#include <stdlib.h>

int total = 100;                 // глобальная: статические данные

int main(void) {
    static int calls = 0;        // static внутри функции: тоже статические данные
    int local = 5;               // локальная: стек
    int *block = malloc(sizeof *block);   // блок в куче
    if (block == NULL) {
        return 1;
    }
    *block = 42;
    const char *text = "литерал";        // сам текст лежит в статических данных

    printf("глобальная  %p\n", (void *)&total);
    printf("static      %p\n", (void *)&calls);
    printf("литерал     %p\n", (void *)text);
    printf("куча        %p\n", (void *)block);
    printf("локальная   %p\n", (void *)&local);
    printf("%d %d %d %d\n", total, calls, local, *block);
    free(block);
    return 0;
}
```

Запустите пример несколько раз. Конкретные числа меняются от запуска к запуску — операционная система нарочно размещает программу по-разному. Но обычно видна закономерность: глобальная переменная, `static` и литерал лежат рядом друг с другом, адрес из кучи заметно отличается, а локальная переменная находится в совсем другом диапазоне — там, где стек.

Последняя строка всегда одинакова: `100 0 5 42`. Значения не зависят от того, где лежат объекты.

## Статические данные: живут всю программу

Глобальные переменные и переменные с `static` создаются **один раз**, до первого вызова `main`, и существуют до конца программы. У них есть ещё одно важное свойство: если вы не задали начальное значение, они **обнуляются**.

```c
#include <stdio.h>

int counter;              // без инициализатора — гарантированно 0
double ratio;             // 0.0
int table[5];             // все пять элементов — 0

int main(void) {
    printf("%d %.1f %d %d\n", counter, ratio, table[0], table[4]);
    return 0;
}
```

Вывод:

```text
0 0.0 0 0
```

Локальные переменные этого свойства **не имеют** — к этому вернёмся через минуту.

### `static` внутри функции

Слово `static` перед локальной переменной меняет её место хранения: переменная остаётся видна только внутри функции, но живёт всю программу и сохраняет значение между вызовами.

```c
#include <stdio.h>

void visit(void) {
    int fresh = 0;          // создаётся заново при каждом вызове
    static int kept = 0;    // создан один раз, до запуска main
    fresh++;
    kept++;
    printf("fresh=%d kept=%d\n", fresh, kept);
}

int main(void) {
    visit();
    visit();
    visit();
    return 0;
}
```

Вывод:

```text
fresh=1 kept=1
fresh=1 kept=2
fresh=1 kept=3
```

Инициализатор `static int kept = 0` выполняется **не при каждом вызове**, а один раз — при подготовке программы. Поэтому `kept` накапливает значение, а `fresh` каждый раз начинается с нуля.

<MemoryDiagram title="Третий вызов visit (адреса условные)">

| Область            | Объект  | Значение                       |
| ------------------ | ------- | ------------------------------ |
| Статические данные | `kept`  | 2 → 3 (пережил прошлые вызовы) |
| Стек: кадр `visit` | `fresh` | 0 → 1 (создан при этом вызове) |
| Стек: кадр `main`  | —       | ждёт возврата из `visit`       |

</MemoryDiagram>

## Стек: память на время вызова

Каждый вызов функции получает на стеке **кадр** — участок под её параметры и локальные переменные. При возврате кадр освобождается, и место переиспользует следующий вызов. Это очень быстро: выделение кадра — одна команда процессора.

Платой за скорость является то, что локальные переменные **не обнуляются**. В них лежит то, что осталось от предыдущих вызовов:

```c
int sum_to_three(void) {
    int sum;                       // значение не определено!
    for (int i = 1; i <= 3; i++) {
        sum += i;
    }
    return sum;
}
```

Такая функция может вернуть `6`, а может — любое другое число. Чтение неинициализированной локальной переменной — ошибка, и компилятор с `-Wall` часто предупреждает о ней. Исправление очевидно: `int sum = 0;`. В уроке о стеке разберём кадры подробно.

## Строковые литералы нельзя менять

Литерал `"hello"` — это массив символов в статических данных, причём обычно в области **только для чтения**. Указатель `char *s = "hello"` смотрит прямо на него:

```c
#include <stdio.h>

int main(void) {
    char *s = "hello";
    s[0] = 'H';               // Ошибка выполнения: запись в память только для чтения
    printf("%s\n", s);
    return 0;
}
```

Программа компилируется без предупреждений, но при запуске аварийно завершается: процессор не позволяет писать в защищённую область. Если строку нужно менять, создайте **свой массив** — литерал скопируется в него:

```c
#include <stdio.h>

int main(void) {
    char s[] = "hello";       // массив из 6 символов на стеке — копия литерала
    s[0] = 'H';
    const char *t = "world";  // const честно говорит: только для чтения
    printf("%s %s\n", s, t);
    return 0;
}
```

Вывод:

```text
Hello world
```

Хорошая привычка: указатель на литерал всегда объявляйте как `const char *`. Тогда случайная запись станет ошибкой компиляции, а не аварией.

## Куча: память по запросу

Стек мал (обычно несколько мегабайт) и живёт только во время вызова. Статические данные имеют размер, известный при компиляции. А если программа читает из файла миллион чисел, или функция должна создать массив и вернуть его? Для этого есть **куча**: программа просит блок нужного размера функцией `malloc` и сама решает, когда вернуть его функцией `free`. Куче посвящены несколько уроков модуля, начиная с урока «Куча: память по запросу».

## Три вида времени жизни

Стандарт C описывает не области, а **длительность хранения** — сколько живёт объект:

| Длительность                 | Объекты                              | Начало                  | Конец                   |
| ---------------------------- | ------------------------------------ | ----------------------- | ----------------------- |
| статическая (`static`)       | глобальные, `static`, литералы       | до запуска `main`       | после завершения `main` |
| автоматическая (`automatic`) | локальные переменные и параметры     | вход в блок `{`         | выход из блока `}`      |
| выделенная (`allocated`)     | блоки из `malloc`/`calloc`/`realloc` | вызов функции выделения | вызов `free`            |

Почти все ошибки памяти в C — это обращение к объекту **вне его времени жизни** или **за его границами**. Привыкайте для каждого указателя спрашивать: на объект какой длительности он указывает и жив ли этот объект сейчас?

<Concept title="Место и время">

У каждого объекта две характеристики: **где** он лежит (статические данные, стек, куча) и **сколько** живёт (всю программу, один вызов, до `free`). Указатель хранит только адрес — он не знает, жив ли объект. Следить за этим — работа программиста.

</Concept>

## Частые ошибки

<CommonMistake title="Ожидать, что локальная переменная сохранит значение">

```c
int next_id(void) {
    int id = 0;
    id++;
    return id;      // всегда 1
}
```

Локальная переменная создаётся заново при каждом вызове. Если значение должно сохраняться между вызовами, нужен `static int id = 0;`.

</CommonMistake>

<CommonMistake title="Читать неинициализированную локальную переменную">

`int count; count++;` — в `count` мусор. Глобальные и `static` переменные обнуляются автоматически, локальные — нет. Инициализируйте локальные переменные при объявлении.

</CommonMistake>

<CommonMistake title="Изменять строковый литерал">

`char *name = "anna"; name[0] = 'A';` — запись в память только для чтения, аварийное завершение. Используйте массив `char name[] = "anna";` или объявляйте указатель как `const char *`.

</CommonMistake>

## Практика

Все задачи модуля проверяются с включёнными AddressSanitizer и UndefinedBehaviorSanitizer: даже если вывод верный, обращение к памяти вне правил сделает тест непройденным.

1. **Статистика без глобального массива** — переменные `static` на уровне файла накапливают данные между вызовами.
2. **Скользящее среднее** — `static`-массив внутри функции помнит последние значения.
3. **Встречалось ли раньше** — статический массив обнуляется автоматически.

## Итоги

- Память процесса делится на код, статические данные, стек и кучу.
- Глобальные и `static` переменные живут всю программу и обнуляются, если нет инициализатора.
- `static` внутри функции сохраняет значение между вызовами; инициализатор выполняется один раз.
- Локальные переменные живут один вызов и не обнуляются — инициализируйте их сами.
- Строковые литералы лежат в памяти только для чтения: храните их через `const char *`.
- Каждый объект имеет статическую, автоматическую или выделенную длительность хранения; обращаться к нему можно только пока он жив.
