## Что происходит при вызове функции

Когда `main` вызывает функцию, процессору нужно где-то разместить её параметры и локальные переменные, а после возврата — продолжить `main` с того же места. Для этого служит **стек вызовов** — область памяти, устроенная как стопка тарелок: последний положенный элемент снимают первым.

При каждом вызове на вершину стека кладётся **кадр** (stack frame) функции. В нём:

- копии аргументов — параметры функции;
- локальные переменные;
- служебные данные: куда вернуться после завершения.

При возврате кадр снимается, и его место займёт кадр следующего вызова. Именно поэтому локальные переменные исчезают после возврата из функции.

## Следим за кадрами

Добавим в функции печать при входе и выходе:

```c
#include <stdio.h>

int square(int x) {
    printf("  вход в square(%d)\n", x);
    int result = x * x;
    printf("  выход из square: %d\n", result);
    return result;
}

int sum_of_squares(int a, int b) {
    printf("вход в sum_of_squares(%d, %d)\n", a, b);
    int total = square(a) + square(b);
    printf("выход из sum_of_squares: %d\n", total);
    return total;
}

int main(void) {
    int answer = sum_of_squares(3, 4);
    printf("main получил %d\n", answer);
    return 0;
}
```

Вывод:

```text
вход в sum_of_squares(3, 4)
  вход в square(3)
  выход из square: 9
  вход в square(4)
  выход из square: 16
выход из sum_of_squares: 25
main получил 25
```

Функции завершаются в порядке, обратном вызовам: `square` закончила раньше, чем `sum_of_squares`, а та — раньше `main`. В самый глубокий момент на стеке три кадра:

<MemoryDiagram title="Стек во время вызова square(3) (адреса условные, стек растёт вниз)">

| Кадр             | Содержимое                        | Состояние                   |
| ---------------- | --------------------------------- | --------------------------- |
| `main`           | `answer` — ещё не записан         | ждёт sum_of_squares         |
| `sum_of_squares` | `a = 3`, `b = 4`, `total` — пусто | ждёт square                 |
| `square`         | `x = 3`, `result = 9`             | вершина стека — выполняется |

</MemoryDiagram>

После возврата из `square(3)` её кадр снимается, и `square(4)` получает **то же самое место** на стеке. Поэтому значения локальных переменных не переживают вызов: следующий вызов перезапишет их.

## Параметры — это копии в новом кадре

Каждый кадр хранит **свои** параметры. Изменение параметра меняет копию в кадре функции, но не переменную вызывающего кода:

```c
#include <stdio.h>

void reset(int value) {
    value = 0;                 // меняется копия в кадре reset
    printf("в reset: %d\n", value);
}

void reset_by_address(int *value) {
    *value = 0;                // запись по адресу из кадра main
}

int main(void) {
    int balance = 500;
    reset(balance);
    printf("%d\n", balance);
    reset_by_address(&balance);
    printf("%d\n", balance);
    return 0;
}
```

Вывод:

```text
в reset: 0
500
0
```

Указатель тоже копируется — но копия адреса указывает на тот же объект в кадре `main`. Вы уже видели это в уроке «Указатели и функции»; теперь понятно, почему так: функция видит чужой кадр только через адрес.

## Рекурсия: стопка одинаковых кадров

Рекурсивная функция вызывает саму себя, и каждый вызов получает **отдельный кадр со своим `n`**. Добавим отступ по глубине, чтобы увидеть стопку:

```c
#include <stdio.h>

int factorial(int n, int depth) {
    printf("%*sfactorial(%d)\n", depth * 2, "", n);
    int result = n <= 1 ? 1 : n * factorial(n - 1, depth + 1);
    printf("%*s= %d\n", depth * 2, "", result);
    return result;
}

int main(void) {
    factorial(3, 0);
    return 0;
}
```

Вывод:

```text
factorial(3)
  factorial(2)
    factorial(1)
    = 1
  = 2
= 6
```

Запись `%*s` с аргументами `depth * 2, ""` печатает пустую строку шириной `depth * 2` — то есть нужное число пробелов.

Пока `factorial(1)` не вернёт значение, кадры `factorial(3)` и `factorial(2)` лежат на стеке и ждут. У каждого свой `n`: у нижнего 3, у среднего 2, у верхнего 1.

<MemoryDiagram title="Стек в момент вызова factorial(1)">

| Кадр        | `n` | Ждёт                            |
| ----------- | --- | ------------------------------- |
| `main`      | —   | factorial(3)                    |
| `factorial` | 3   | результата factorial(2)         |
| `factorial` | 2   | результата factorial(1)         |
| `factorial` | 1   | ничего — вершина, сейчас вернёт |

</MemoryDiagram>

## Стек не бесконечен

Под стек основного потока обычно отводится несколько мегабайтов (в Linux — 8 МБ по умолчанию). Каждый кадр занимает десятки или сотни байтов, поэтому глубина рекурсии ограничена. Если базовый случай никогда не наступает, стек переполняется:

```c
#include <stdio.h>

int countdown(int n) {
    if (n == 0) {
        return 0;
    }
    return 1 + countdown(n - 1);
}

int main(void) {
    int n = -1;                         // базовый случай n == 0 не наступит
    printf("%d\n", countdown(n));       // Ошибка выполнения: переполнение стека
    return 0;
}
```

Программа аварийно завершится с ошибкой сегментации (`Segmentation fault`, сигнал 11): очередной кадр не помещается в отведённую память. AddressSanitizer в таком случае сообщает `stack-overflow` и показывает повторяющиеся строки `countdown` в трассировке вызовов.

Переполнить стек можно и без рекурсии — одним большим локальным массивом:

```c
void process(void) {
    double samples[2000000];     // 16 МБ на стеке — больше, чем весь стек
    samples[0] = 1.0;
}
```

Большие массивы размещают в статических данных (`static`) или в куче (`malloc`) — об этом следующий урок.

## Рекурсия или цикл

Рекурсия удобна для задач, которые естественно делятся на подзадачи: обход дерева, перебор вариантов, «разделяй и властвуй». Но если глубина рекурсии растёт **линейно с размером входа** — например, `sum(n) = n + sum(n - 1)` для `n` до миллиона, — программа упадёт на больших данных. Такую рекурсию переписывают циклом:

```c
#include <stdio.h>

long long sum_recursive(long long n) {     // глубина n — опасно при больших n
    return n == 0 ? 0 : n + sum_recursive(n - 1);
}

long long sum_loop(long long n) {          // один кадр при любом n
    long long total = 0;
    for (long long i = 1; i <= n; i++) {
        total += i;
    }
    return total;
}

int main(void) {
    printf("%lld %lld\n", sum_recursive(1000), sum_loop(1000));
    printf("%lld\n", sum_loop(10000000));
    return 0;
}
```

Вывод:

```text
500500 500500
50000005000000
```

Хорошее правило: рекурсия безопасна, когда глубина растёт как логарифм размера (бинарный поиск, сбалансированное дерево) или ограничена небольшим числом.

<Concept title="Стек — черновик функции">

Кадр — это черновик, который функция получает на время работы и отдаёт при возврате. Всё, что должно пережить функцию, нельзя оставлять в черновике: результат возвращают значением, пишут по адресу, полученному от вызывающего кода, или размещают в куче.

</Concept>

## Частые ошибки

<CommonMistake title="Рекурсия без достижимого базового случая">

`int f(int n) { if (n == 0) return 0; return f(n - 2); }` — для нечётного `n` значение перескочит через ноль, и рекурсия станет бесконечной. Проверяйте, что каждый вызов приближает аргумент к базовому случаю **при любых допустимых входных данных**.

</CommonMistake>

<CommonMistake title="Огромный локальный массив">

`int counts[10000000];` внутри функции — 40 МБ на стеке и аварийное завершение ещё до первой строки кода. Используйте `static` или `malloc`.

</CommonMistake>

<CommonMistake title="Линейная рекурсия на больших данных">

Рекурсивная сумма, обход списка или поиск по массиву с глубиной `n` работают на тестах из десяти элементов и падают на миллионе. Если глубина равна размеру входа — пишите цикл.

</CommonMistake>

## Практика

1. **Трассировка рекурсии** — напечатать стопку кадров вычисления суммы цифр.
2. **Ханойские башни** — классическая рекурсия с глубиной `n`.
3. **Сколько кадров** — посчитать вызовы и максимальную глубину рекурсивного Фибоначчи.
4. **Найди ошибку: переполнение стека** — переписать линейную рекурсию циклом.

## Итоги

- Каждый вызов функции получает на стеке кадр с параметрами и локальными переменными; при возврате кадр снимается.
- Функции завершаются в порядке, обратном вызовам; освободившееся место занимает следующий вызов.
- Параметры — копии в новом кадре; доступ к чужому кадру возможен только через адрес.
- Каждый рекурсивный вызов имеет собственный кадр; глубина рекурсии ограничена размером стека (обычно 8 МБ).
- Бесконечная рекурсия и большие локальные массивы переполняют стек; линейную по глубине рекурсию заменяют циклом.
