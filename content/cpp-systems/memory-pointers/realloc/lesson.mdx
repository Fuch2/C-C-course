## Когда размер неизвестен даже во время выделения

`malloc` требует знать размер заранее. Но иногда количество данных неизвестно до самого конца: программа читает числа, пока они не закончатся, или строку, пока не встретит перевод строки. Решение — начать с небольшого блока и **увеличивать** его по мере надобности. Для этого есть `realloc`:

```c
void *realloc(void *ptr, size_t new_size);
```

`realloc` возвращает блок размера `new_size`, в начале которого лежат старые данные (столько, сколько помещается в оба размера). При этом:

- если рядом со старым блоком есть свободное место, блок просто **расширяется** на месте, и адрес не меняется;
- иначе выделяется **новый** блок, данные копируются, старый освобождается — адрес меняется;
- если памяти нет, возвращается `NULL`, а **старый блок остаётся нетронутым** и по-прежнему принадлежит вам;
- `realloc(NULL, n)` работает как `malloc(n)`.

## Правильный шаблон вызова

Из-за последнего пункта нельзя писать `p = realloc(p, new_size)`: при отказе `p` станет `NULL`, а адрес старого блока будет потерян — утечка. Результат сначала сохраняют во временную переменную:

```c
int *bigger = realloc(data, new_capacity * sizeof *data);
if (bigger == NULL) {
    free(data);              // или продолжить работу со старым блоком
    return -1;
}
data = bigger;               // только теперь — старый адрес больше не нужен
```

Это правило стоит запомнить дословно: оно защищает и от утечки, и от разыменования `NULL`.

## Растущий массив: читаем, пока есть данные

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    size_t count = 0, capacity = 2;
    int *data = malloc(capacity * sizeof *data);
    if (data == NULL) {
        return 1;
    }
    int x;
    while (scanf("%d", &x) == 1) {
        if (count == capacity) {                     // место кончилось
            capacity *= 2;
            int *bigger = realloc(data, capacity * sizeof *data);
            if (bigger == NULL) {
                free(data);
                return 1;
            }
            data = bigger;
            printf("ёмкость -> %zu\n", capacity);
        }
        data[count++] = x;
    }
    long long sum = 0;
    for (size_t i = 0; i < count; i++) {
        sum += data[i];
    }
    printf("%zu чисел, сумма %lld\n", count, sum);
    free(data);
    return 0;
}
```

Ввод:

```text
5 8 13 21 34 55 89
```

Вывод:

```text
ёмкость -> 4
ёмкость -> 8
7 чисел, сумма 225
```

Две величины: **длина** `count` — сколько элементов занято, и **ёмкость** `capacity` — на сколько элементов хватит блока. Когда они сравниваются, блок увеличивается.

<MemoryDiagram title="Состояние перед чтением пятого числа">

| Переменная | Значение | Смысл                                   |
| ---------- | -------- | --------------------------------------- |
| `count`    | 4        | занято 4 элемента: 5, 8, 13, 21         |
| `capacity` | 4        | блок вмещает 4 — нужно увеличить        |
| `data`     | H0       | после `realloc` может стать другим (H1) |

</MemoryDiagram>

## Почему удваивать, а не прибавлять

Если увеличивать ёмкость на один элемент, каждый `realloc` может скопировать весь массив: для `n` чисел это `1 + 2 + … + n ≈ n²/2` копирований. Для миллиона чисел — полтриллиона операций.

При **удвоении** блок растёт редко: для миллиона элементов — около 20 раз. Суммарно копируется не больше `2n` элементов — в среднем O(1) на добавление. Это называется **амортизированной** сложностью, и так устроены динамические массивы во всех языках: `std::vector` в C++, `ArrayList` в Java, `list` в Python.

```c
#include <stdio.h>

int main(void) {
    long long by_one = 0, doubling = 0;
    long long n = 1000000;
    for (long long size = 1; size < n; size++) {
        by_one += size;                // рост на 1: копируется весь массив
    }
    for (long long cap = 1; cap < n; cap *= 2) {
        doubling += cap;               // удвоение: копирование только при росте
    }
    printf("%lld\n%lld\n", by_one, doubling);
    return 0;
}
```

Вывод:

```text
499999500000
1048575
```

Пятьсот миллиардов против миллиона — разница в полмиллиона раз.

## Строка произвольной длины

Тот же приём для текста: читаем по символу и растим буфер, не забывая про место под `'\0'`:

```c
#include <stdio.h>
#include <stdlib.h>

// Читает строку до '\n' или конца ввода. Возвращает блок, который нужно освободить, или NULL.
char *read_line(void) {
    size_t length = 0, capacity = 8;
    char *line = malloc(capacity);
    if (line == NULL) {
        return NULL;
    }
    int c;
    while ((c = getchar()) != EOF && c != '\n') {
        if (length + 1 == capacity) {               // + 1 — место под '\0'
            capacity *= 2;
            char *bigger = realloc(line, capacity);
            if (bigger == NULL) {
                free(line);
                return NULL;
            }
            line = bigger;
        }
        line[length++] = (char)c;
    }
    line[length] = '\0';
    return line;
}

int main(void) {
    char *line = read_line();
    if (line == NULL) {
        return 1;
    }
    printf("[%s]\n", line);
    free(line);
    return 0;
}
```

Ввод:

```text
строка, длина которой заранее неизвестна
```

Вывод:

```text
[строка, длина которой заранее неизвестна]
```

Функция `getline` из POSIX делает то же самое; в стандартном C её нет, поэтому такие функции пишут сами.

## Уменьшение блока

`realloc` умеет и уменьшать блок — например, «подогнать» ёмкость под длину после чтения, чтобы не держать лишнюю память. Уменьшение почти всегда выполняется на месте, но адрес всё равно может измениться, поэтому шаблон тот же. Вызов `realloc(p, 0)` не используйте: его поведение зависит от реализации, а в C23 оно объявлено неопределённым. Чтобы освободить блок, есть `free`.

## Указатели в старый блок становятся висячими

Самая коварная ловушка `realloc`: если блок переехал, **все** указатели на его элементы теперь указывают в освобождённую память.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *a = malloc(2 * sizeof *a);
    if (a == NULL) {
        return 1;
    }
    a[0] = 10;
    a[1] = 20;
    int *second = &a[1];                      // адрес элемента старого блока
    int *bigger = realloc(a, 1000 * sizeof *a);
    if (bigger == NULL) {
        free(a);
        return 1;
    }
    a = bigger;
    printf("%d\n", *second);                  // Ошибка памяти: старый блок освобождён
    free(a);
    return 0;
}
```

AddressSanitizer сообщает:

```text
ERROR: AddressSanitizer: heap-use-after-free on address 0x602000000014
READ of size 4 at 0x602000000014 thread T0
    #0 0x555555633169 in main /work/main.c:18:20

freed by thread T0 here:
    #0 0x5555555f8576 in __interceptor_realloc
    #1 0x5555556330b4 in main /work/main.c:12:19
```

`second` указывает внутрь блока, который `realloc` освободил при переезде (строка 12), а чтение произошло в строке 18. Без санитайзера программа может напечатать 20 — пока память не занята чем-то другим. Правило: после `realloc` пересчитывайте все указатели от нового адреса или храните **индексы** вместо указателей.

<Concept title="realloc может переселить данные">

Думайте о `realloc` как о переезде: содержимое квартиры доставят по новому адресу, но все, кто записал старый адрес, придут в пустой дом. Поэтому указатели на элементы растущего массива живут только до следующего `realloc`, а надёжная «ссылка» на элемент — его индекс.

</Concept>

## Частые ошибки

<CommonMistake title="p = realloc(p, ...)">

При отказе `realloc` возвращает `NULL`, и старый адрес теряется — утечка, а следующая запись через `p` — разыменование `NULL`. Всегда через временную переменную.

</CommonMistake>

<CommonMistake title="Новый размер в элементах">

`realloc(data, capacity)` для массива `int` — размер в байтах, а не в элементах. Нужно `capacity * sizeof *data`.

</CommonMistake>

<CommonMistake title="Рост на один элемент">

`capacity++` перед каждым `realloc` превращает чтение `n` чисел в O(n²) копирований. Удваивайте ёмкость.

</CommonMistake>

<CommonMistake title="Указатель или ссылка на элемент после роста">

Сохранённый `&data[i]` после `realloc` может указывать в освобождённую память. Храните индекс `i` и обращайтесь `data[i]` через актуальный указатель.

</CommonMistake>

## Практика

1. **Чтение до конца ввода** — массив растёт удвоением.
2. **Строка любой длины** — посимвольное чтение в растущий буфер.
3. **Уникальные значения** — растущий массив только из новых элементов.
4. **Найди ошибку: указатель в старый блок** — указатель на максимум пережил `realloc`.

## Итоги

- `realloc(p, n)` возвращает блок размера `n` со старыми данными; блок может остаться на месте или переехать.
- При отказе `realloc` возвращает `NULL`, а старый блок остаётся вашим: результат сохраняют во временную переменную.
- `realloc(NULL, n)` эквивалентен `malloc(n)`; `realloc(p, 0)` не используйте.
- Растущий массив хранит длину и ёмкость; ёмкость удваивают — это даёт O(1) на добавление в среднем.
- После `realloc` все указатели на элементы старого блока могут стать висячими — используйте индексы.
