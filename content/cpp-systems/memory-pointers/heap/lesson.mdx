## Две задачи, которые стек не решает

Представьте программу, которая читает количество измерений `n`, а затем сами измерения. Сколько места выделить под массив?

- Объявить `int data[1000]` — а если измерений будет миллион? А если всего три — зачем занимать тысячу?
- Объявить `int data[n]` после чтения `n` — это **массив переменной длины** (VLA). Он живёт на стеке: при `n` порядка миллиона программа упадёт с переполнением стека, а проверить заранее, хватит ли места, невозможно. Кроме того, в стандарте C11 и новее поддержка VLA необязательна.

Вторая задача: функция должна **создать** массив и вернуть его вызывающему коду. Локальный массив исчезнет вместе с кадром функции, `static`-массив один на все вызовы и фиксированного размера.

Обе задачи решает **куча** (heap) — область памяти, из которой программа берёт блоки нужного размера во время работы и сама решает, когда их вернуть.

## `malloc` и `free`

Две функции из `<stdlib.h>`:

- `void *malloc(size_t size)` — выделяет блок из `size` **байтов** и возвращает адрес его начала. Если памяти нет — возвращает `NULL`.
- `void free(void *ptr)` — возвращает блок, полученный от `malloc`, обратно системе.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n;
    scanf("%d", &n);
    int *data = malloc(n * sizeof *data);     // n элементов по sizeof(int) байтов
    if (data == NULL) {
        printf("недостаточно памяти\n");
        return 1;
    }
    for (int i = 0; i < n; i++) {
        scanf("%d", &data[i]);
    }
    for (int i = n - 1; i >= 0; i--) {
        printf("%d ", data[i]);
    }
    printf("\n");
    free(data);                                // блок больше не нужен
    return 0;
}
```

Ввод:

```text
4
10 20 30 40
```

Вывод:

```text
40 30 20 10
```

Разберём по строкам:

1. `malloc(n * sizeof *data)` — размер в байтах. `sizeof *data` — размер того, на что указывает `data`, то есть `int`. Если позже поменять тип на `double`, выражение останется верным само.
2. `malloc` возвращает `void *` — «адрес без типа». В C он неявно превращается в `int *`, приведение `(int *)` писать не нужно.
3. Проверка `data == NULL` обязательна: выделение может не удаться, а разыменование `NULL` — аварийное завершение.
4. С блоком работают как с обычным массивом: `data[i]`.
5. `free(data)` — блок возвращён. После этого `data` больше нельзя использовать.

<MemoryDiagram title="После malloc при n = 4 (адреса условные)">

| Область         | Объект         | Значение                  |
| --------------- | -------------- | ------------------------- |
| Стек: кадр main | `int n`        | 4                         |
| Стек: кадр main | `int *data`    | 5000 — адрес блока в куче |
| Куча: 5000–5015 | блок 16 байтов | 10, 20, 30, 40            |

Указатель `data` — обычная локальная переменная на стеке. Он лишь хранит адрес блока в куче. Сам блок не имеет имени: добраться до него можно только через указатель.

## Блок переживает функцию

Блок в куче живёт до вызова `free` — независимо от того, какая функция его выделила. Поэтому функция может создать массив и отдать его наружу:

```c
#include <stdio.h>
#include <stdlib.h>

// Возвращает массив квадратов 1², 2², …, n². Освободить его должен вызывающий код.
int *make_squares(int n) {
    int *squares = malloc(n * sizeof *squares);
    if (squares == NULL) {
        return NULL;
    }
    for (int i = 0; i < n; i++) {
        squares[i] = (i + 1) * (i + 1);
    }
    return squares;           // кадр исчезнет, блок в куче — нет
}

int main(void) {
    int *sq = make_squares(5);
    if (sq == NULL) {
        return 1;
    }
    for (int i = 0; i < 5; i++) {
        printf("%d ", sq[i]);
    }
    printf("\n");
    free(sq);
    return 0;
}
```

Вывод:

```text
1 4 9 16 25
```

При возврате из `make_squares` её кадр снимается вместе с переменной `squares`, но **значение** указателя — адрес блока — возвращено в `main`. Блок по-прежнему существует, и теперь за него отвечает `main`.

<Concept title="Владелец блока">

У каждого блока из кучи должен быть **владелец** — часть программы, которая обязана вызвать `free`. Комментарий «освободить должен вызывающий код» — это договор о передаче владения. В C компилятор не следит за владением: если договор нарушен, блок либо не освободят (утечка), либо освободят дважды (авария).

</Concept>

## Стек или куча

| Свойство              | Стек                                       | Куча                                         |
| --------------------- | ------------------------------------------ | -------------------------------------------- |
| Размер                | несколько МБ на поток                      | почти вся свободная память                   |
| Когда известен размер | при компиляции (кроме VLA)                 | во время работы                              |
| Время жизни           | до выхода из блока `{ }`                   | до вызова `free`                             |
| Кто освобождает       | автоматически                              | программист                                  |
| Скорость выделения    | мгновенно                                  | вызов функции, поиск свободного места        |
| Типичные ошибки       | переполнение, адрес исчезнувшей переменной | утечки, двойное освобождение, use-after-free |

Правило выбора простое: **по умолчанию — локальные переменные**. Куча нужна, когда размер известен только во время работы и может быть большим, или когда данные должны пережить функцию, которая их создала.

## Один блок — много значений

Двумерная таблица `rows × cols` тоже помещается в один блок: элемент строки `r` и столбца `c` лежит по индексу `r * cols + c`.

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int rows = 2, cols = 3;
    int *table = malloc(rows * cols * sizeof *table);
    if (table == NULL) {
        return 1;
    }
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            table[r * cols + c] = (r + 1) * 10 + c;
        }
    }
    for (int r = 0; r < rows; r++) {
        for (int c = 0; c < cols; c++) {
            printf("%d ", table[r * cols + c]);
        }
        printf("\n");
    }
    free(table);
    return 0;
}
```

Вывод:

```text
10 11 12
20 21 22
```

Строки таблицы лежат в блоке друг за другом — ровно так же устроен обычный двумерный массив `int t[2][3]`. Один `malloc` — один `free`, и данные расположены компактно.

## Частые ошибки

<CommonMistake title="Размер в элементах вместо байтов">

`int *a = malloc(n);` выделяет `n` **байтов** — места хватит на `n / 4` чисел. Запись `a[n - 1]` выйдет за границу блока. Правильно: `malloc(n * sizeof *a)`.

</CommonMistake>

<CommonMistake title="Нет проверки на NULL">

`int *a = malloc(...); a[0] = 1;` — если память не выделилась, запись по `NULL` аварийно завершит программу. Проверяйте результат каждого `malloc`.

</CommonMistake>

<CommonMistake title="free для памяти не из кучи">

```c
int x = 5;
int *p = &x;
free(p);        // x живёт на стеке — free для неё запрещён
```

`free` принимает только адреса, полученные от `malloc`, `calloc` или `realloc` (или `NULL`). Любой другой адрес — неопределённое поведение, обычно аварийное завершение с сообщением `free(): invalid pointer`.

</CommonMistake>

<CommonMistake title="Забыть free">

Каждый `malloc` должен иметь ровно один парный `free`. Без него блок остаётся занятым до конца программы — это **утечка памяти**. В короткой программе её не видно, а сервер, работающий неделями, из-за утечек в итоге исчерпает память. Утечкам посвящён отдельный урок.

</CommonMistake>

## Практика

Проверка запускает программы с AddressSanitizer: забытый `free` или выход за границы блока сделают тест непройденным, даже если вывод верный.

1. **Обратный порядок** — массив размера, известного только во время работы.
2. **Функция создаёт диапазон** — блок переживает функцию, освобождает вызывающий код.
3. **Слияние в новый массив** — функция возвращает новый блок с результатом.
4. **Транспонирование таблицы** — двумерные данные в одном блоке.

## Итоги

- Куча — память, которую программа запрашивает во время работы и сама возвращает.
- `malloc(байты)` возвращает адрес блока или `NULL`; размер массива — `n * sizeof *p`.
- Результат `malloc` всегда проверяют на `NULL`.
- Блок живёт до `free`, поэтому функция может создать его и вернуть вызывающему коду.
- У каждого блока есть владелец, который обязан вызвать `free` ровно один раз; `free` принимает только адреса из кучи.
- По умолчанию используйте локальные переменные; кучу — для больших данных заранее неизвестного размера и данных, переживающих функцию.
