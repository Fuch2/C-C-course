## Договор `malloc`

В уроке о куче вы выделяли массивы. Теперь разберём `malloc` подробно — со всеми условиями, которые обычно и становятся причиной ошибок.

```c
void *malloc(size_t size);
```

Функция обещает:

1. вернуть адрес блока **не меньше** `size` байтов, выровненного так, что в нём можно хранить данные любого типа;
2. содержимое блока **не инициализировано** — там лежит что угодно;
3. если выделить не удалось — вернуть `NULL`.

Взамен программа обязуется не выходить за `size` байтов и вызвать `free` ровно один раз. Нарушение любого пункта — неопределённое поведение.

## Каноническая запись

```c
double *samples = malloc(count * sizeof *samples);
```

- Размер считается от **того, на что указывает переменная** (`sizeof *samples`), а не от названия типа. Если тип `samples` поменяют на `float *`, выражение останется верным.
- Результат не приводят: `void *` превращается в `double *` неявно. Приведение `(double *)malloc(...)` в C не нужно и может скрыть ошибку — забытый `#include <stdlib.h>`.
- Сразу после вызова — проверка на `NULL`.

## Содержимое не инициализировано

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;
    int *counts = malloc(n * sizeof *counts);
    if (counts == NULL) {
        return 1;
    }
    for (int i = 0; i < n; i++) {
        counts[i] = 0;              // без этого цикла в counts — мусор
    }
    counts[2] += 3;
    counts[4] += 1;
    for (int i = 0; i < n; i++) {
        printf("%d ", counts[i]);
    }
    printf("\n");
    free(counts);
    return 0;
}
```

Вывод:

```text
0 0 3 0 1
```

Без цикла обнуления программа на маленьких тестах часто печатает правильный ответ: свежая память от операционной системы обычно заполнена нулями. Но блок, освобождённый и выделенный повторно, содержит старые данные — и ошибка проявится в самый неудобный момент. AddressSanitizer такие ошибки не ловит; их находит Valgrind (урок «Valgrind») или функция `calloc`, которая сама обнуляет блок (следующий урок).

## Переполнение при вычислении размера

`count * sizeof *p` — умножение беззнаковых чисел `size_t`. При переполнении результат **не ошибка**, а остаток по модулю 2⁶⁴: огромное произведение превращается в маленькое число.

```c
#include <stdint.h>
#include <stdio.h>

int main(void) {
    size_t count = SIZE_MAX / 4 + 2;      // «очень много» элементов
    size_t bytes = count * sizeof(int);   // переполнение: результат по модулю 2^64
    printf("%zu\n", bytes);
    return 0;
}
```

Вывод:

```text
4
```

Если `count` пришло из файла или от пользователя, `malloc(bytes)` успешно выделит **4 байта**, а программа будет считать, что у неё огромный массив, и запишет данные далеко за его границу. Так устроены настоящие уязвимости. Проверка делается **до** умножения:

```c
#include <stdint.h>
#include <stdio.h>
#include <stdlib.h>

// Выделяет массив из count элементов int или возвращает NULL.
int *alloc_ints(size_t count) {
    if (count == 0 || count > SIZE_MAX / sizeof(int)) {
        return NULL;                          // произведение не помещается в size_t
    }
    return malloc(count * sizeof(int));
}

int main(void) {
    int *small = alloc_ints(10);
    int *huge = alloc_ints(SIZE_MAX / 2);
    printf("%s %s\n", small ? "выделено" : "NULL", huge ? "выделено" : "NULL");
    free(small);
    free(huge);
    return 0;
}
```

Вывод:

```text
выделено NULL
```

Условие `count > SIZE_MAX / size` эквивалентно «произведение больше `SIZE_MAX`», но не переполняется само. Функция `calloc` выполняет такую проверку внутри — ещё одна причина её использовать.

## Отказ выделения — обычная ветка программы

`malloc` возвращает `NULL`, если память закончилась, превышен лимит процесса или запрошен невозможный размер. Хорошая функция не завершает программу внезапно, а сообщает об ошибке вызывающему коду — и не оставляет за собой утечек:

```c
#include <stdio.h>
#include <stdlib.h>

struct Buffers {
    double *input;
    double *output;
};

// Возвращает 0 при успехе. При ошибке ничего не выделено.
int buffers_init(struct Buffers *b, size_t n) {
    b->input = malloc(n * sizeof *b->input);
    if (b->input == NULL) {
        return -1;
    }
    b->output = malloc(n * sizeof *b->output);
    if (b->output == NULL) {
        free(b->input);             // первый блок уже получен — вернуть его
        b->input = NULL;
        return -1;
    }
    return 0;
}

int main(void) {
    struct Buffers b;
    if (buffers_init(&b, 4) != 0) {
        printf("нет памяти\n");
        return 1;
    }
    b.input[0] = 2.5;
    b.output[0] = b.input[0] * 2;
    printf("%.1f\n", b.output[0]);
    free(b.input);
    free(b.output);
    return 0;
}
```

Вывод:

```text
5.0
```

Правило: на каждой ветке ошибки освободите всё, что уже успели получить. Чем больше ресурсов, тем удобнее приём «единой точки выхода» с `goto cleanup` — он разбирается в модуле «Углублённый C».

## Структура в куче

Одиночную структуру выделяют так же — `sizeof *node`. Все поля нужно задать явно:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Task {
    char title[32];
    int priority;
    int done;
};

struct Task *task_create(const char *title, int priority) {
    struct Task *t = malloc(sizeof *t);
    if (t == NULL) {
        return NULL;
    }
    snprintf(t->title, sizeof t->title, "%s", title);
    t->priority = priority;
    t->done = 0;                     // каждое поле — явно
    return t;
}

int main(void) {
    struct Task *t = task_create("Проверить отчёт", 2);
    if (t == NULL) {
        return 1;
    }
    t->done = 1;
    printf("%s [%d] %s\n", t->title, t->priority, t->done ? "готово" : "в работе");
    free(t);
    return 0;
}
```

Вывод:

```text
Проверить отчёт [2] готово
```

Функция-«конструктор», возвращающая указатель на новую структуру, — основной приём построения объектов в C. Парная функция-«деструктор» освобождает всё, чем объект владеет; к ним вернёмся в уроке о `free`.

## Строка нужной длины

Для строки нужно `strlen(s) + 1` байт: последний — под `'\0'`. Забытая единица — одна из самых частых ошибок выхода за границу.

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

char *join_path(const char *dir, const char *file) {
    size_t len = strlen(dir) + 1 + strlen(file);     // dir + '/' + file
    char *path = malloc(len + 1);                    // + '\0'
    if (path == NULL) {
        return NULL;
    }
    snprintf(path, len + 1, "%s/%s", dir, file);
    return path;
}

int main(void) {
    char *p = join_path("/var/log", "app.txt");
    if (p == NULL) {
        return 1;
    }
    printf("%s (%zu символов)\n", p, strlen(p));
    free(p);
    return 0;
}
```

Вывод:

```text
/var/log/app.txt (16 символов)
```

`sizeof(char)` по определению равен 1, поэтому для строк умножение на `sizeof` обычно опускают.

<Concept title="malloc выдаёт площадку, а не объект">

`malloc` знает только количество байтов. Она не знает, что вы будете хранить `int` или структуру, не задаёт значений и не помнит, сколько элементов вы собирались положить. Правильный размер, заполнение до чтения и учёт длины — ответственность вашего кода.

</Concept>

## Частые ошибки

<CommonMistake title="malloc(n) для n элементов">

`int *a = malloc(n);` — `n` байтов, а не `n` чисел. Запись `a[n - 1]` выходит далеко за границу. Всегда `n * sizeof *a`.

</CommonMistake>

<CommonMistake title="strlen(s) байтов под копию строки">

`char *copy = malloc(strlen(s)); strcpy(copy, s);` — `strcpy` запишет `'\0'` на один байт за концом блока. AddressSanitizer сообщит `heap-buffer-overflow`. Нужно `strlen(s) + 1`.

</CommonMistake>

<CommonMistake title="Размер от неизвестного количества без проверки">

`malloc(count * sizeof *p)` с `count` из входных данных без проверки — путь к переполнению размера. Проверяйте `count > SIZE_MAX / sizeof *p` или используйте `calloc`.

</CommonMistake>

<CommonMistake title="malloc(0)">

Результат `malloc(0)` зависит от реализации: `NULL` или уникальный указатель, через который нельзя ничего читать. Код, проверяющий `NULL`, может принять пустой массив за ошибку. Пустой массив удобнее представлять как `NULL` и длину 0.

</CommonMistake>

## Практика

1. **Копия строки** — свой аналог `strdup`.
2. **Повтор строки** — точный расчёт длины результата.
3. **Проверка размера перед malloc** — обнаружить переполнение произведения.
4. **Задачи в куче** — структуры, созданные функцией-конструктором.

## Итоги

- `malloc(size)` возвращает неинициализированный блок не меньше `size` байтов, выровненный для любого типа, или `NULL`.
- Каноническая запись: `p = malloc(n * sizeof *p);` без приведения, сразу — проверка `NULL`.
- Перед чтением каждый элемент блока нужно записать; ASan чтение мусора не замечает.
- Произведение `n * size` может переполниться: проверяйте `n > SIZE_MAX / size` до умножения.
- При отказе освобождайте всё, что уже выделено, и сообщайте об ошибке вызывающему коду.
- Строке нужно `strlen + 1` байт; пустой массив лучше представлять как `NULL` с длиной 0, а не `malloc(0)`.
