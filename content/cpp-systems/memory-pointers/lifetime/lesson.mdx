## Область видимости и время жизни — не одно и то же

Две похожие, но разные характеристики переменной:

- **Область видимости** (scope) — участок исходного кода, где к объекту можно обратиться **по имени**. Это понятие времени компиляции.
- **Время жизни** (lifetime) — промежуток выполнения программы, когда объект **существует** в памяти. Это понятие времени выполнения.

Чаще всего они совпадают, но не всегда:

| Объект                    | Область видимости          | Время жизни            |
| ------------------------- | -------------------------- | ---------------------- |
| локальная `int x;`        | от объявления до `}`       | от входа в блок до `}` |
| `static int x;` в функции | только внутри функции      | вся программа          |
| глобальная `int x;`       | весь файл после объявления | вся программа          |
| блок из `malloc`          | имени нет вообще           | от `malloc` до `free`  |

`static`-переменная невидима снаружи функции, но существует всегда. Блок из кучи не имеет имени, но существует, пока его не освободят. Указатель позволяет обратиться к объекту **вне** его области видимости — и именно поэтому указатель может пережить объект.

## Блок кода ограничивает жизнь

Локальная переменная, объявленная внутри `{ }`, перестаёт существовать на закрывающей скобке. Если её адрес сохранён в указателе снаружи, указатель становится **висячим**:

```c
#include <stdio.h>

int main(void) {
    int *p = NULL;
    {
        int temperature = 21;
        p = &temperature;
        printf("%d\n", *p);       // корректно: temperature жива
    }
    printf("%d\n", *p);           // Ошибка памяти: temperature уже не существует
    return 0;
}
```

Без инструментов такая программа часто печатает `21` дважды — байты на стеке ещё не перезаписаны. Это худший вид ошибки: она «работает» в тестах и ломается, когда рядом появляется новый код. AddressSanitizer ловит её сразу:

```text
ERROR: AddressSanitizer: stack-use-after-scope on address 0x7ffffffca960
READ of size 4 at 0x7ffffffca960 thread T0
    #0 0x5555556330a7 in main /work/main.c:10:20

  This frame has 1 object(s):
    [32, 36) 'temperature' (line 6) <== Memory access at offset 32 is inside this variable
```

Отчёт называет вид ошибки (`stack-use-after-scope` — обращение к стековой переменной после выхода из её блока), размер чтения (4 байта — `int`), строку исходника (10) и даже имя переменной, которой принадлежала память, — `temperature`, объявленная в строке 6. Подробно читать такие отчёты будем в уроке «AddressSanitizer».

<MemoryDiagram title="Что происходит на строке 10">

| Объект              | Где живёт   | Состояние                                |
| ------------------- | ----------- | ---------------------------------------- |
| `p`                 | кадр `main` | жив, хранит адрес бывшей `temperature`   |
| `temperature`       | кадр `main` | время жизни закончилось на `}`           |
| байты по адресу `p` | стек        | могут содержать 21, а могут — что угодно |

</MemoryDiagram>

Тот же эффект возникает в цикле: переменная, объявленная в теле цикла, создаётся заново на каждой итерации и исчезает в её конце.

## Адрес локальной переменной нельзя вернуть

Самая известная ошибка этого вида:

```c
int *make_counter(void) {
    int counter = 0;
    return &counter;          // counter умрёт при возврате
}
```

GCC предупреждает: `function returns address of local variable [-Wreturn-local-addr]` — и даже подменяет возвращаемое значение на `NULL`, чтобы ошибка проявилась сразу. Предупреждения такого рода всегда означают настоящую ошибку.

## Четыре правильных способа вернуть данные

### 1. Вернуть значение

Если результат небольшой, его проще всего вернуть **значением** — копией. Это работает и для структур:

```c
#include <stdio.h>

struct Point {
    double x;
    double y;
};

struct Point midpoint(struct Point a, struct Point b) {
    struct Point m = {(a.x + b.x) / 2, (a.y + b.y) / 2};
    return m;                 // возвращается копия, а не адрес
}

int main(void) {
    struct Point a = {0, 0}, b = {4, 2};
    struct Point m = midpoint(a, b);
    printf("%.1f %.1f\n", m.x, m.y);
    return 0;
}
```

Вывод:

```text
2.0 1.0
```

Локальная `m` исчезла, но её значение скопировано в `m` из `main`. Структура из нескольких полей копируется дёшево; не бойтесь возвращать её значением.

### 2. Записать в память вызывающего кода

Вызывающий код создаёт буфер и передаёт его адрес. Функция только заполняет его — время жизни буфера определяет вызывающий:

```c
#include <stdio.h>

// Записывает в out строку вида "12:05". out должен вмещать не меньше 16 символов.
void format_clock(int minutes, char out[16]) {
    snprintf(out, 16, "%02d:%02d", minutes / 60, minutes % 60);
}

int main(void) {
    char text[16];
    format_clock(725, text);
    printf("%s\n", text);
    return 0;
}
```

Вывод:

```text
12:05
```

Так устроены `scanf`, `fgets`, `snprintf` и большинство функций стандартной библиотеки. Это самый надёжный способ: память живёт ровно столько, сколько нужно вызывающему коду.

### 3. Статический буфер

Можно вернуть адрес `static`-объекта — он живёт всю программу:

```c
#include <stdio.h>

const char *weekday(int day) {
    static char buffer[16];
    const char *names[] = {"пн", "вт", "ср", "чт", "пт", "сб", "вс"};
    snprintf(buffer, sizeof buffer, "день %s", names[day]);
    return buffer;
}

int main(void) {
    const char *a = weekday(0);
    const char *b = weekday(4);
    printf("%s / %s\n", a, b);     // оба указателя — на один буфер!
    return 0;
}
```

Вывод:

```text
день пт / день пт
```

Ловушка: буфер **один на все вызовы**. Второй вызов перезаписал результат первого, и `a` теперь показывает пятницу. Так ведут себя некоторые старые функции стандартной библиотеки (`asctime`, `strtok`). Используйте этот способ редко и только с результатом, который сразу печатают или копируют.

### 4. Выделить в куче

Если размер результата заранее неизвестен, функция выделяет блок и передаёт владение вызывающему коду. Этот способ вы видели в прошлом уроке; цена — обязанность вызвать `free`.

| Способ            | Когда подходит                 | Чем рискуем                  |
| ----------------- | ------------------------------ | ---------------------------- |
| вернуть значение  | небольшой результат, структура | ничем                        |
| буфер вызывающего | размер известен вызывающему    | слишком маленький буфер      |
| `static`-буфер    | редкие простые случаи          | перезапись следующим вызовом |
| блок из кучи      | размер известен только функции | утечка, если забыть `free`   |

<Concept title="Кто переживёт кого">

Указатель безопасен, только пока объект, на который он указывает, жив. Перед тем как сохранить адрес, сравните два времени жизни: **указатель не должен жить дольше объекта**. Указатель на локальную переменную нельзя сохранять в `static`, возвращать из функции или класть в структуру, которая переживёт вызов.

</Concept>

## Частые ошибки

<CommonMistake title="Указатель на переменную из тела цикла">

```c
int *last = NULL;
for (int i = 0; i < n; i++) {
    int value = read_value();
    last = &value;            // value умирает в конце итерации
}
printf("%d", *last);           // обращение к мёртвому объекту
```

Сохраняйте значение, а не адрес: `int last = value;`.

</CommonMistake>

<CommonMistake title="Возврат адреса локального массива">

`char *greeting(void) { char s[] = "hi"; return s; }` — массив `s` живёт в кадре функции. Верните строковый литерал (`return "hi";` — он статический), заполните буфер вызывающего или выделите память в куче.

</CommonMistake>

<CommonMistake title="Два результата из одного статического буфера">

`printf("%s %s", name(1), name(2))` с функцией, возвращающей `static`-буфер, напечатает одно и то же дважды. Копируйте первый результат (`strcpy` в свой массив) перед повторным вызовом.

</CommonMistake>

## Практика

1. **Найди ошибку: адрес из завершившегося блока** — указатель пережил переменную цикла.
2. **Буфер вызывающего** — форматирование длительности в массив, созданный вызывающим кодом.
3. **Результат-структура** — вернуть несколько величин одной структурой.
4. **Найди ошибку: общий статический буфер** — второй вызов портит первый результат.

## Итоги

- Область видимости — где виден объект по имени; время жизни — когда он существует. Указатель позволяет обращаться к объекту вне области видимости.
- Локальная переменная умирает на `}` своего блока; указатель на неё становится висячим, а обращение — неопределённым поведением.
- Висячий указатель часто «работает» без инструментов; AddressSanitizer сообщает `stack-use-after-scope`.
- Адрес локальной переменной нельзя возвращать из функции.
- Данные из функции возвращают значением, через буфер вызывающего, через `static`-буфер (осторожно) или в куче.
- Указатель не должен жить дольше объекта, на который указывает.
