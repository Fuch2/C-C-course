## `const` — обещание в сигнатуре

В «Основах C» вы видели четыре сочетания `const` и указателя и правило чтения справа налево. В этом уроке посмотрим, зачем `const` нужен на практике: он превращает сигнатуру функции в **договор** о том, что функция будет делать с переданной памятью.

Прочитайте объявления двух стандартных функций:

```c
size_t strlen(const char *s);
char *strcpy(char *dst, const char *src);
```

Даже без документации ясно: `strlen` только читает строку `s`; `strcpy` читает `src` и **пишет** в `dst`. Если у параметра-указателя нет `const`, функция оставляет за собой право изменить данные — и вызывающий код должен быть к этому готов.

## Компилятор следит за обещанием

```c
#include <stdio.h>

double average(const double *values, int n) {
    double sum = 0;
    for (int i = 0; i < n; i++) {
        sum += values[i];
    }
    values[0] = 0;           // Ошибка компиляции: assignment of read-only location
    return sum / n;
}

int main(void) {
    double t[3] = {1.0, 2.0, 3.0};
    printf("%.1f\n", average(t, 3));
    return 0;
}
```

Компилятор не даст нарушить обещание даже случайно. Без строки с записью программа печатает `2.0`.

Обратите внимание: массив `t` в `main` не константный. Передача `double *` туда, где ожидается `const double *`, разрешена **неявно** — добавить ограничение всегда безопасно. Обратное преобразование — убрать `const` — неявно запрещено.

## Большая структура: `const`-указатель вместо копии

Структура, переданная по значению, копируется целиком. Для больших структур это лишняя работа, поэтому их передают указателем. `const` сохраняет главное достоинство передачи по значению — гарантию, что исходные данные не изменятся:

```c
#include <stdio.h>

struct Report {
    char title[32];
    int values[100];
    int count;
};

int report_max(const struct Report *r) {        // копируются 8 байтов, а не 436
    int best = r->values[0];
    for (int i = 1; i < r->count; i++) {
        if (r->values[i] > best) {
            best = r->values[i];
        }
    }
    return best;
}

void report_add(struct Report *r, int value) {  // без const: функция изменяет отчёт
    r->values[r->count++] = value;
}

int main(void) {
    struct Report daily = {"Температура", {0}, 0};
    report_add(&daily, 17);
    report_add(&daily, 23);
    report_add(&daily, 19);
    printf("%s: %d значения, максимум %d\n", daily.title, daily.count, report_max(&daily));
    printf("%zu\n", sizeof daily);
    return 0;
}
```

Вывод:

```text
Температура: 3 значения, максимум 23
436
```

По сигнатурам видно, какая функция только читает отчёт, а какая его меняет. Это соглашение используют все хорошие библиотеки на C.

## Функция возвращает указатель внутрь входных данных

Функция поиска часто возвращает указатель на найденное место. Если вход — `const char *`, то и результат должен быть `const char *`: он указывает в ту же неизменяемую память.

```c
#include <stdio.h>

const char *find_char(const char *s, char c) {
    while (*s != '\0') {
        if (*s == c) {
            return s;
        }
        s++;            // двигается копия указателя — это разрешено
    }
    return NULL;
}

int main(void) {
    const char *path = "/home/user/notes.txt";
    const char *dot = find_char(path, '.');
    if (dot != NULL) {
        printf("расширение: %s, позиция %td\n", dot + 1, dot - path);
    }
    return 0;
}
```

Вывод:

```text
расширение: txt, позиция 16
```

Строка `s++` не нарушает `const`: `const char *s` запрещает менять **символы**, а сам указатель — обычная локальная переменная, его можно двигать.

Стандартная `strchr` объявлена как `char *strchr(const char *s, int c)` — она возвращает неконстантный указатель на константные данные. Это историческая уступка (в C нет перегрузки функций), и ею легко нечаянно открыть запись в строковый литерал. В своём коде так не делайте.

## Таблицы констант

Таблицу названий, которая никогда не меняется, объявляют с двумя `const`:

```c
#include <stdio.h>

static const char *const LEVEL_NAMES[] = {"debug", "info", "warning", "error"};

const char *level_name(int level) {
    if (level < 0 || level >= (int)(sizeof LEVEL_NAMES / sizeof LEVEL_NAMES[0])) {
        return "unknown";
    }
    return LEVEL_NAMES[level];
}

int main(void) {
    printf("%s %s %s\n", level_name(0), level_name(3), level_name(7));
    return 0;
}
```

Вывод:

```text
debug error unknown
```

Читаем справа налево: `LEVEL_NAMES` — массив **константных** указателей (`*const`) на **константные** символы (`const char`). Нельзя ни заменить строку в таблице, ни изменить буквы. Такая таблица целиком может лежать в памяти только для чтения.

## Снимать `const` нельзя

Приведением можно «снять» `const`: `(char *)s`. Компилятор поверит. Но если исходный объект действительно константный — литерал или переменная `const`, — запись через полученный указатель является неопределённым поведением:

```c
const int limit = 10;
int *p = (int *)&limit;      // компилятор молчит из-за приведения
*p = 20;                     // неопределённое поведение
```

Программа может упасть (если `limit` лежит в памяти только для чтения), а может продолжить работу, где-то используя старое значение 10, — компилятор вправе подставить константу прямо в код. Приведение, убирающее `const`, почти всегда означает ошибку в проектировании.

## Почему `char **` не превращается в `const char **`

`char *` неявно превращается в `const char *`, а вот `char **` в `const char **` — нет. Кажется странным, но это защищает от дыры:

```c
const char *secret = "только чтение";
char *p;
const char **pp = &p;        // если бы это было разрешено…
*pp = secret;                // …p стал бы указывать на литерал
p[0] = 'X';                  // …и запись в литерал прошла бы без приведений
```

Поэтому функции, принимающие массив строк только для чтения, объявляют параметр как `const char *const *words` или просто работают с `const char **`, а массив изначально объявляют как `const char *words[]`.

<Concept title="const — для читателя кода">

`const` ничего не ускоряет и не защищает от злонамеренного кода — его можно снять приведением. Его настоящая ценность — в документации, которую проверяет компилятор: глядя на сигнатуру, вы знаете, какие данные функция может изменить. Ставьте `const` у каждого параметра-указателя, через который функция только читает.

</Concept>

## Частые ошибки

<CommonMistake title="Указатель на литерал без const">

```c
char *messages[] = {"ok", "fail"};
messages[0][0] = 'O';          // авария: литерал только для чтения
```

Компилятор C не предупредит: тип литерала исторически `char[]`. Объявляйте `const char *messages[]` — тогда запись станет ошибкой компиляции.

</CommonMistake>

<CommonMistake title="Забытый const у входного параметра">

`int sum(int *a, int n)` нельзя вызвать для `const int data[]` без приведения, а читатель не знает, изменит ли функция массив. Если функция только читает — `const int *a`.

</CommonMistake>

<CommonMistake title="Путаница между const T * и T *const">

`const int *p` — нельзя менять данные, можно двигать указатель. `int *const p` — нельзя двигать указатель, можно менять данные. В параметрах почти всегда нужен первый вариант: второй ничего не обещает вызывающему коду, ведь указатель и так передаётся копией.

</CommonMistake>

## Практика

1. **Подсчёт без изменения** — функции, только читающие строку.
2. **Последнее вхождение** — функция возвращает `const char *` внутрь входных данных.
3. **Лучшая запись** — структуры передаются через `const`-указатели.
4. **Найди ошибку: изменение литерала** — таблица строк, которую пытаются изменить.

## Итоги

- `const` у параметра-указателя — проверяемое компилятором обещание не изменять данные через этот указатель.
- `T *` неявно превращается в `const T *`; обратное преобразование требует приведения и почти всегда ошибочно.
- Большие структуры передают через `const struct T *` — без копирования и без права на изменение.
- Функция, ищущая внутри `const`-данных, возвращает `const`-указатель.
- Таблицы констант объявляют как `static const char *const NAMES[]`.
- Запись в объект, изначально объявленный `const` (или литерал), — неопределённое поведение, даже если `const` снят приведением.
