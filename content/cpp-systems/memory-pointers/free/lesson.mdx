## Договор `free`

```c
void free(void *ptr);
```

`free` возвращает блок, полученный от `malloc`, `calloc` или `realloc`, обратно распределителю памяти. Правила короткие, но нарушить их легко:

1. Передавать можно только адрес **начала** блока из кучи — или `NULL` (тогда `free` ничего не делает).
2. Каждый блок освобождается **ровно один раз**.
3. После `free` блок больше не принадлежит программе: читать и писать по старому адресу нельзя.

`free` не меняет сам указатель и не стирает данные. После вызова переменная хранит прежний адрес, но он уже **висячий**:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int *p = malloc(sizeof *p);
    if (p == NULL) {
        return 1;
    }
    *p = 42;
    int *alias = p;           // второй указатель на тот же блок
    printf("%d\n", *alias);   // 42: alias и p указывают на один блок
    free(p);
    p = NULL;                 // обнулили p, но alias всё ещё хранит старый адрес
    if (p == NULL) {
        printf("p обнулён\n");
    }
    // *alias здесь — обращение к освобождённой памяти
    return 0;
}
```

Вывод:

```text
42
p обнулён
```

Приём `free(p); p = NULL;` полезен: повторный `free(p)` станет безопасным, а случайное `*p` — немедленной аварией вместо тихой порчи данных. Но он защищает **только эту переменную**. Все копии адреса (`alias`) по-прежнему висячие — поэтому главное средство не обнуление, а ясное правило, кто владеет блоком.

## Владелец и заимствование

**Владелец** блока — код, который обязан его освободить. Остальные могут временно **заимствовать** блок: читать и даже менять данные, но не освобождать и не хранить адрес дольше, чем живёт владелец.

В C владение не выражается в типах, поэтому его описывают именами и комментариями:

```c
// Возвращает новую строку. Освобождает вызывающий код.
char *format_name(const char *first, const char *last);

// Не забирает владение: s только читается во время вызова.
size_t count_vowels(const char *s);

// Забирает владение: после вызова list_append отвечает за освобождение item.
int list_append(struct List *list, char *item);
```

Принятое соглашение: функции с именами `create`, `new`, `copy`, `dup` возвращают владение; функции `destroy`, `free`, `release` его принимают и освобождают. Каждой функции «создать» соответствует функция «уничтожить».

## Вложенные блоки: освобождать изнутри наружу

Если структура владеет другими блоками, сначала освобождают внутренние, потом внешний — иначе адреса внутренних блоков будут потеряны вместе с освобождённой структурой:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Playlist {
    char *name;
    char **songs;            // массив указателей на строки
    int count;
};

char *copy_text(const char *s) {
    char *c = malloc(strlen(s) + 1);
    if (c != NULL) {
        strcpy(c, s);
    }
    return c;
}

void playlist_destroy(struct Playlist *p) {
    if (p == NULL) {
        return;              // как free: NULL допустим
    }
    for (int i = 0; i < p->count; i++) {
        free(p->songs[i]);   // 1. строки
    }
    free(p->songs);          // 2. массив указателей
    free(p->name);           // 3. имя
    free(p);                 // 4. сама структура — последней
}

int main(void) {
    struct Playlist *p = calloc(1, sizeof *p);
    if (p == NULL) {
        return 1;
    }
    p->name = copy_text("Дорога");
    p->songs = calloc(2, sizeof *p->songs);
    if (p->name == NULL || p->songs == NULL) {
        playlist_destroy(p);
        return 1;
    }
    p->songs[0] = copy_text("Intro");
    p->count = 1;
    p->songs[1] = copy_text("Finale");
    p->count = 2;
    printf("%s: %s, %s\n", p->name, p->songs[0], p->songs[1]);
    playlist_destroy(p);
    return 0;
}
```

Вывод:

```text
Дорога: Intro, Finale
```

Обратите внимание: структура выделена через `calloc`, поэтому до заполнения все указатели — `NULL`, а `count` — 0. Благодаря этому `playlist_destroy` безопасна в **любой** момент — даже если создание прервалось на середине.

## Цепочка блоков: сохраните «следующий» до `free`

Связанные структуры — каждый узел указывает на следующий — освобождают в цикле. Ловушка: после `free(node)` читать `node->next` уже нельзя:

```c
#include <stdio.h>
#include <stdlib.h>

struct Node {
    int value;
    struct Node *next;
};

int main(void) {
    struct Node *head = NULL;
    for (int i = 1; i <= 3; i++) {               // добавляем в начало: 3 → 2 → 1
        struct Node *node = malloc(sizeof *node);
        if (node == NULL) {
            break;
        }
        node->value = i;
        node->next = head;
        head = node;
    }
    for (struct Node *n = head; n != NULL; n = n->next) {
        printf("%d ", n->value);
    }
    printf("\n");
    struct Node *current = head;
    while (current != NULL) {
        struct Node *next = current->next;       // запомнить до free
        free(current);
        current = next;
    }
    return 0;
}
```

Вывод:

```text
3 2 1
```

Цикл `for (n = head; n; n = n->next) free(n);` выглядит короче, но читает `n->next` из уже освобождённого узла — это use-after-free. Связанные списки подробно разбираются в модуле об алгоритмах.

## Чего `free` не делает

- **Не обнуляет указатель** — это делаете вы.
- **Не стирает данные** — секреты (пароли, ключи) перед освобождением затирают отдельно.
- **Не обязательно возвращает память системе** — распределитель часто оставляет блок себе для следующих `malloc`. Поэтому размер процесса после `free` может не уменьшиться.
- **Не освобождает вложенные блоки** — только тот, адрес которого получил.

При завершении процесса операционная система забирает всю его память. Но полагаться на это не стоит: серверы и демоны работают месяцами, библиотечный код не знает, когда завершится программа, а инструменты поиска утечек сообщат о каждом неосвобождённом блоке.

<Concept title="Один блок — один владелец — один free">

Перед каждым `malloc` задайте вопрос: кто вызовет `free` для этого блока и когда? Если ответ «непонятно» или «может быть, двое» — у программы ошибка проектирования, даже если сейчас она работает.

</Concept>

## Частые ошибки

<CommonMistake title="free для середины блока">

`char *buf = malloc(100); char *word = buf + 10; free(word);` — `free` принимает только адрес начала блока. AddressSanitizer сообщит `attempting free on address which was not malloc()-ed`.

</CommonMistake>

<CommonMistake title="Сначала внешний блок">

`free(p); free(p->name);` — второй вызов читает поле из освобождённой структуры. Порядок — изнутри наружу.

</CommonMistake>

<CommonMistake title="Освобождение заимствованного блока">

Функция, получившая указатель «посмотреть» (`const char *s`), не должна вызывать `free(s)`: владелец потом освободит блок ещё раз. Тип `const` — хорошая подсказка, что владение не передаётся.

</CommonMistake>

## Практика

1. **Матрица: создать и уничтожить** — парные функции для структуры с вложенными блоками.
2. **Цепочка узлов** — освобождение связанной структуры.
3. **Найди ошибку: free для части блока** — указатели внутрь одного буфера.
4. **Передача владения** — стек строк, где `pop` отдаёт строку вызывающему коду.

## Итоги

- `free` принимает адрес начала блока из кучи или `NULL`; каждый блок освобождается ровно один раз.
- После `free` все копии адреса висячие; `p = NULL` защищает только одну переменную.
- У каждого блока один владелец; функции `create`/`destroy` образуют пары, владение описывают в комментариях.
- Вложенные блоки освобождают изнутри наружу; `destroy`, принимающая `NULL` и частично заполненные структуры, упрощает обработку ошибок.
- В связанных структурах следующий узел запоминают до `free` текущего.
- `free` не обнуляет указатель, не стирает данные и не освобождает вложенные блоки.
