## Почему адрес имеет значение

Процессор читает память не по одному байту, а порциями — по 4, 8, 16 или 64 байта, начиная с адресов, кратных размеру порции. Если `int` лежит по адресу 1000, процессор забирает его за одно обращение. Если по адресу 1001 — значение пересекает границу порций, и процессору приходится делать два чтения и склеивать результат. Некоторые процессоры так не умеют вовсе и аварийно останавливают программу.

Поэтому у каждого типа есть **требование выравнивания** (alignment): адрес объекта должен быть кратен определённому числу. Для `int` на распространённых платформах — 4, для `double` и указателей — 8. Адрес, удовлетворяющий требованию, называется **выровненным**.

## Узнаём выравнивание: `alignof`

Оператор `alignof` (из `<stdalign.h>`, или ключевое слово `_Alignof`) возвращает требование выравнивания типа:

```c
#include <stdalign.h>
#include <stddef.h>
#include <stdio.h>

int main(void) {
    printf("char        %zu\n", alignof(char));
    printf("short       %zu\n", alignof(short));
    printf("int         %zu\n", alignof(int));
    printf("long long   %zu\n", alignof(long long));
    printf("double      %zu\n", alignof(double));
    printf("void *      %zu\n", alignof(void *));
    printf("max_align_t %zu\n", alignof(max_align_t));
    return 0;
}
```

Вывод:

```text
char        1
short       2
int         4
long long   8
double      8
void *      8
max_align_t 16
```

Выравнивание — всегда степень двойки и обычно совпадает с размером простого типа. `max_align_t` — тип с самым строгим выравниванием среди стандартных; его выравнивание (здесь 16) гарантирует `malloc`: любой блок из кучи подходит для хранения объекта любого типа.

Компилятор сам размещает переменные, массивы и поля структур по выровненным адресам. Проблемы появляются, когда вы **сами** вычисляете адрес и приводите его к указателю другого типа.

## Невыровненный доступ

Типичная ситуация — разбор двоичных данных: пакета из сети или содержимого файла. Данные пришли массивом байтов, а внутри — числа:

```c
#include <stdio.h>

int main(void) {
    unsigned char packet[8] = {0x01, 0x2a, 0x00, 0x00, 0x00, 0xff, 0x00, 0x00};
    int *value = (int *)(packet + 1);       // адрес packet + 1 не кратен 4
    printf("%d\n", *value);                 // Ошибка памяти: невыровненное чтение int
    return 0;
}
```

На x86 программа печатает `42`: этот процессор умеет читать невыровненные данные, хоть и медленнее. Но по правилам C это неопределённое поведение: компилятор может сгенерировать команды, которые требуют выравнивания (например, векторные), а на некоторых процессорах ARM, MIPS и SPARC такое чтение аварийно завершает программу. UBSan сообщает:

```text
main.c:6:20: runtime error: load of misaligned address 0x7ffffffcaae1 for type 'int', which requires 4 byte alignment
```

Здесь есть и вторая проблема: обращение к массиву `unsigned char` через указатель `int *` нарушает **правило строгого псевдонимирования** (strict aliasing) — объект можно читать только через указатель на его собственный тип, на совместимый тип или на символьный тип. Оптимизатор полагается на это правило.

## Правильный способ: `memcpy`

Чтобы прочитать число из произвольного места байтового буфера, его **копируют** в переменную нужного типа. `memcpy` работает с байтами и не требует выравнивания:

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    unsigned char packet[8] = {0x01, 0x2a, 0x00, 0x00, 0x00, 0xff, 0x00, 0x00};
    int value;
    memcpy(&value, packet + 1, sizeof value);    // копия 4 байтов в выровненную переменную
    printf("%d\n", value);
    return 0;
}
```

Вывод:

```text
42
```

Это не медленнее, чем кажется: для маленького известного размера компилятор заменяет вызов `memcpy` одной командой чтения, допустимой на данной платформе. Порядок байтов при этом остаётся машинным (здесь little-endian) — о переносимом разборе чисел поговорим в уроке «Endianness».

## Выравнивание адреса вверх

Распределители памяти, форматы файлов и сетевые протоколы часто требуют округлить размер или адрес **вверх** до кратного выравнивания. Для степени двойки `a` есть классическая формула:

```c
#include <stdio.h>

// Наименьшее число ≥ x, кратное a (a — степень двойки).
size_t align_up(size_t x, size_t a) {
    return (x + a - 1) & ~(a - 1);
}

int main(void) {
    size_t sizes[] = {0, 1, 7, 8, 9, 13, 16, 17};
    for (int i = 0; i < 8; i++) {
        printf("%zu -> %zu\n", sizes[i], align_up(sizes[i], 8));
    }
    return 0;
}
```

Вывод:

```text
0 -> 0
1 -> 8
7 -> 8
8 -> 8
9 -> 16
13 -> 16
16 -> 16
17 -> 24
```

Как это работает: `a − 1` для `a = 8` — это `0b111`, младшие три бита. Прибавление `a − 1` «перепрыгивает» к следующему кратному, если число не было кратным, а `& ~(a − 1)` обнуляет младшие биты — округляет вниз. Для произвольного `a` (не степени двойки) подходит медленная, но общая формула `(x + a − 1) / a * a`.

Проверка выровненности адреса — тот же приём: `((uintptr_t)p & (a − 1)) == 0`. Тип `uintptr_t` из `<stdint.h>` — целое, в которое помещается указатель.

## Задать выравнивание: `alignas`

Иногда выравнивание нужно сделать строже обычного — например, чтобы массив начинался с границы кэш-линии (64 байта) или подходил для векторных команд:

```c
#include <stdalign.h>
#include <stdint.h>
#include <stdio.h>

int main(void) {
    alignas(64) unsigned char line[64];          // начало кратно 64
    alignas(16) float vec[4] = {1, 2, 3, 4};
    printf("%d %d\n", (int)((uintptr_t)line % 64), (int)((uintptr_t)vec % 16));
    line[0] = 7;
    printf("%.1f %d\n", vec[0] + vec[3], line[0]);
    return 0;
}
```

Вывод:

```text
0 0
5.0 7
```

Для блоков из кучи с особым выравниванием в C11 есть `aligned_alloc(alignment, size)`, где `size` должен быть кратен `alignment`. Освобождаются такие блоки обычным `free`.

<Concept title="Выравнивание — свойство адреса">

Тип говорит, каким должен быть адрес объекта; компилятор и `malloc` соблюдают это автоматически. Нарушить правило можно только вручную — приведением указателя после арифметики над байтами. Правило простое: адрес внутри байтового буфера не превращают в `T *`; значение копируют через `memcpy`.

</Concept>

## Частые ошибки

<CommonMistake title="Приведение указателя внутрь буфера">

`uint32_t len = *(uint32_t *)(buffer + offset);` — невыровненный доступ и нарушение strict aliasing. Используйте `memcpy(&len, buffer + offset, sizeof len);`.

</CommonMistake>

<CommonMistake title="Формула с маской для не степени двойки">

`(x + a − 1) & ~(a − 1)` работает только для `a`, равного степени двойки. Для `a = 6` она даёт неверные результаты. Проверка: `a != 0 && (a & (a − 1)) == 0`.

</CommonMistake>

<CommonMistake title="«На x86 же работает»">

Невыровненный доступ на x86 не падает, поэтому ошибка годами живёт в коде и проявляется при переносе на ARM или после включения векторизации. UBSan находит её на любой платформе.

</CommonMistake>

## Практика

1. **Выравнивание вверх** — формула с маской и проверка степени двойки.
2. **Чтение чисел из пакета** — `memcpy` вместо приведения указателя.
3. **Найди ошибку: невыровненный заголовок** — указатель на структуру внутри байтового буфера.
4. **Простой распределитель** — выдача выровненных смещений из общего буфера.

## Итоги

- Каждый тип имеет требование выравнивания — степень двойки, которой должен быть кратен адрес объекта; узнать его можно через `alignof`.
- Компилятор и `malloc` выравнивают объекты автоматически; `malloc` гарантирует выравнивание `max_align_t`.
- Невыровненный доступ через приведённый указатель — неопределённое поведение (и нарушение strict aliasing); на x86 он работает, на других процессорах может упасть.
- Числа из байтового буфера читают через `memcpy` в переменную нужного типа.
- Выравнивание вверх для степени двойки: `(x + a − 1) & ~(a − 1)`; задать выравнивание объекта можно через `alignas`.
