## Одна функция для любых типов

Функция сортировки, написанная для `int`, не сможет отсортировать `double`, строки или структуры. Писать по копии для каждого типа — долго и опасно: ошибку придётся исправлять во всех копиях. В C эту задачу решают через `void *` — **указатель без типа**.

Вы уже пользовались им: `malloc` возвращает `void *`, а `memcpy` принимает `void *` и `const void *`. Теперь разберёмся, как писать такие функции самим и как пользоваться самой известной из них — `qsort`.

## Что можно и чего нельзя с `void *`

`void *` хранит адрес, но не знает, что по нему лежит. Поэтому:

- любой указатель на объект **неявно** превращается в `void *` и обратно — приведение не нужно;
- разыменовать `void *` нельзя: неизвестно, сколько байтов читать и как их понимать;
- арифметика `p + 1` для `void *` в стандартном C запрещена: неизвестен размер шага.

```c
#include <stdio.h>

int main(void) {
    int count = 7;
    double ratio = 0.5;
    void *any = &count;            // int * → void *: неявно
    int *back = any;               // void * → int *: неявно
    printf("%d\n", *back);
    any = &ratio;                  // теперь тот же указатель хранит адрес double
    printf("%.1f\n", *(double *)any);
    return 0;
}
```

Вывод:

```text
7
0.5
```

Чтобы прочитать данные, `void *` превращают обратно в указатель **правильного** типа. Ответственность за «правильный» лежит на программисте: компилятор уже не может проверить, что по адресу действительно `double`.

## Обобщённая функция: тип заменяется размером

Обобщённая функция получает адрес и **размер элемента в байтах**, а работает с байтами через `unsigned char *`. Например, обмен двух значений любого типа:

```c
#include <stdio.h>

void swap_any(void *a, void *b, size_t size) {
    unsigned char *x = a;
    unsigned char *y = b;
    for (size_t i = 0; i < size; i++) {       // обмен байт за байтом
        unsigned char tmp = x[i];
        x[i] = y[i];
        y[i] = tmp;
    }
}

struct Point {
    int x, y;
};

int main(void) {
    int a = 1, b = 2;
    double c = 1.5, d = -3.0;
    struct Point p = {1, 2}, q = {30, 40};
    swap_any(&a, &b, sizeof a);
    swap_any(&c, &d, sizeof c);
    swap_any(&p, &q, sizeof p);
    printf("%d %d | %.1f %.1f | %d %d\n", a, b, c, d, p.x, q.y);
    return 0;
}
```

Вывод:

```text
2 1 | -3.0 1.5 | 30 2
```

Чтобы перейти к `i`-му элементу массива неизвестного типа, адрес считают в байтах: `(unsigned char *)base + i * size`. Именно так устроены `qsort`, `bsearch` и любые обобщённые контейнеры в C.

## `qsort`: сортировка чего угодно

```c
void qsort(void *base, size_t count, size_t size,
           int (*compare)(const void *, const void *));
```

- `base` — начало массива, `count` — число элементов, `size` — размер одного элемента;
- `compare` — **функция сравнения**, которую вы пишете сами. `qsort` вызывает её, передавая адреса двух элементов. Она возвращает отрицательное число, если первый элемент должен идти раньше, положительное — если позже, и 0 — если они равны.

Последний параметр — указатель на функцию: в `qsort` передают просто имя функции сравнения. Подробно указатели на функции разбираются в модуле «Углублённый C»; здесь достаточно знать, что `qsort` сама будет вызывать вашу функцию.

```c
#include <stdio.h>
#include <stdlib.h>

int compare_ints(const void *pa, const void *pb) {
    int a = *(const int *)pa;          // адрес элемента → значение
    int b = *(const int *)pb;
    return (a > b) - (a < b);          // -1, 0 или 1 без риска переполнения
}

int main(void) {
    int values[] = {42, -7, 15, 0, -7, 100};
    size_t n = sizeof values / sizeof values[0];
    qsort(values, n, sizeof values[0], compare_ints);
    for (size_t i = 0; i < n; i++) {
        printf("%d ", values[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
-7 -7 0 15 42 100
```

Выражение `(a > b) - (a < b)` даёт 1, 0 или −1. Соблазнительное `return a - b;` работает на маленьких числах, но при `a = 2 000 000 000` и `b = -2 000 000 000` разность переполняет `int` — это неопределённое поведение, и сортировка выдаст мусор. Чтобы сортировать по убыванию, достаточно поменять аргументы местами: `(b > a) - (b < a)`.

## Сортировка структур по нескольким ключам

Функция сравнения получает адреса элементов — для массива структур это `const struct T *`:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct City {
    char name[16];
    int population;
};

// По убыванию населения, при равенстве — по алфавиту.
int by_population(const void *pa, const void *pb) {
    const struct City *a = pa;
    const struct City *b = pb;
    if (a->population != b->population) {
        return (b->population > a->population) - (b->population < a->population);
    }
    return strcmp(a->name, b->name);
}

int main(void) {
    struct City cities[] = {
        {"Tver", 410}, {"Kazan", 1300}, {"Omsk", 1100}, {"Perm", 1030}, {"Ufa", 1100},
    };
    size_t n = sizeof cities / sizeof cities[0];
    qsort(cities, n, sizeof cities[0], by_population);
    for (size_t i = 0; i < n; i++) {
        printf("%s %d\n", cities[i].name, cities[i].population);
    }
    return 0;
}
```

Вывод:

```text
Kazan 1300
Omsk 1100
Ufa 1100
Perm 1030
Tver 410
```

`qsort` переставляет структуры целиком, копируя по `sizeof cities[0]` байтов. `qsort` не гарантирует **устойчивости**: элементы с равными ключами могут поменяться местами. Если порядок важен, добавляйте в сравнение дополнительный ключ, как имя здесь.

## Массив строк: уровень косвенности

Самая частая ошибка с `qsort` — массив указателей на строки. Элемент массива — `const char *`, значит, `qsort` передаёт в сравнение **адрес элемента** — `const char *const *`:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int compare_strings(const void *pa, const void *pb) {
    const char *a = *(const char *const *)pa;     // адрес элемента → сам указатель
    const char *b = *(const char *const *)pb;
    return strcmp(a, b);
}

int main(void) {
    const char *words[] = {"pear", "apple", "fig", "kiwi"};
    qsort(words, 4, sizeof words[0], compare_strings);
    printf("%s %s %s %s\n", words[0], words[1], words[2], words[3]);
    return 0;
}
```

Вывод:

```text
apple fig kiwi pear
```

Если написать `strcmp(pa, pb)`, `strcmp` получит адреса элементов массива — байты указателей, а не буквы, — и порядок будет бессмысленным. Компилятор не предупредит: `void *` молча превращается во что угодно.

## `bsearch`: двоичный поиск

`bsearch` ищет элемент в **отсортированном** массиве с той же функцией сравнения. Первым аргументом передаётся адрес искомого значения:

```c
#include <stdio.h>
#include <stdlib.h>

int compare_ints(const void *pa, const void *pb) {
    int a = *(const int *)pa;
    int b = *(const int *)pb;
    return (a > b) - (a < b);
}

int main(void) {
    int sorted[] = {2, 3, 5, 7, 11, 13, 17};
    int key = 11;
    int *found = bsearch(&key, sorted, 7, sizeof sorted[0], compare_ints);
    if (found != NULL) {
        printf("нашли %d на позиции %td\n", *found, found - sorted);
    }
    key = 4;
    printf("%s\n", bsearch(&key, sorted, 7, sizeof sorted[0], compare_ints) ? "есть" : "нет");
    return 0;
}
```

Вывод:

```text
нашли 11 на позиции 4
нет
```

`bsearch` возвращает указатель на найденный элемент (или `NULL`) — позицию получают вычитанием адресов.

<Concept title="Цена обобщённости">

`void *` убирает проверку типов. Если передать в `qsort` неверный размер элемента или функцию сравнения не того типа, компилятор промолчит, а программа тихо испортит данные. Поэтому размер всегда пишите как `sizeof array[0]`, а первой строкой функции сравнения превращайте `void *` в указатель на **тип элемента массива**.

</Concept>

## Частые ошибки

<CommonMistake title="Сравнение вычитанием">

`return *(const int *)a - *(const int *)b;` — переполнение для чисел разных знаков, близких к пределам `int`. Используйте `(x > y) - (x < y)`.

</CommonMistake>

<CommonMistake title="Пропущенный уровень косвенности">

Для `const char *words[]` функция сравнения получает `const char *const *`. Приведение сразу к `const char *` даёт адрес элемента массива вместо адреса строки.

</CommonMistake>

<CommonMistake title="Разыменование void *">

`*p` для `void *p` не компилируется, а `p + 1` — расширение GCC, запрещённое стандартом (с `-Wpedantic` будет предупреждение). Приведите к нужному типу или к `unsigned char *` для работы с байтами.

</CommonMistake>

<CommonMistake title="bsearch по неотсортированному массиву">

`bsearch` полагается на порядок, заданный функцией сравнения. Если массив отсортирован иначе (или не отсортирован), результат бессмысленный. Сортируйте и ищите **одной и той же** функцией сравнения.

</CommonMistake>

## Практика

1. **Сортировка по убыванию** — безопасная функция сравнения для любых `int`.
2. **Таблица результатов** — `qsort` для структур по нескольким ключам.
3. **Обобщённый разворот** — своя функция для массивов любого типа.
4. **Словарь** — сортировка и `bsearch` для массива слов.

## Итоги

- `void *` хранит адрес без типа: любой указатель на объект превращается в него и обратно неявно; разыменовывать и сдвигать `void *` нельзя.
- Обобщённая функция получает адрес, количество и размер элемента и работает с байтами через `unsigned char *`.
- `qsort(base, count, size, compare)` сортирует массив любых элементов; `compare` получает адреса элементов и возвращает отрицательное, ноль или положительное.
- Безопасное сравнение целых — `(a > b) - (a < b)`, а не вычитание.
- Для массива строк `const char *[]` функция сравнения получает `const char *const *`.
- `bsearch` ищет в отсортированном массиве с той же функцией сравнения и возвращает указатель на элемент или `NULL`.
