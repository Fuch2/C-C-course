## Указатель, который пережил объект

**Висячий указатель** (dangling pointer) хранит адрес объекта, который уже не существует или стал другим объектом. Сам указатель выглядит нормально — это просто число, — и ничто в языке не мешает его разыменовать. Последствия разные: иногда программа печатает старое значение, иногда — мусор, иногда падает, а иногда тихо портит чужие данные.

В предыдущих уроках вы уже встречали все источники висячих указателей. Соберём их вместе:

| Источник                        | Когда объект перестаёт существовать | Урок              |
| ------------------------------- | ----------------------------------- | ----------------- |
| адрес локальной переменной      | выход из блока `{ }` или функции    | «Время жизни»     |
| указатель на блок из кучи       | `free`                              | «free и владение» |
| указатель на элемент массива    | `realloc`, переместивший блок       | «realloc»         |
| указатель на элемент контейнера | удаление или сдвиг элементов        | этот урок         |
| указатель на общий буфер        | следующая запись в тот же буфер     | этот урок         |

Общий корень один: **указатель живёт дольше, чем то, на что он указывает**.

## Висячий указатель, которого не видят инструменты

AddressSanitizer ловит обращения к освобождённой памяти и к стеку вышедшей из области видимости переменной. Но есть висячие указатели, которые он не может заметить — когда память по адресу **жива**, но содержит **уже другой объект**:

```c
#include <stdio.h>
#include <string.h>

struct Product {
    char name[16];
    int price;
};

int main(void) {
    struct Product items[4] = {{"чай", 120}, {"кофе", 300}, {"сок", 90}, {"вода", 40}};
    int count = 4;
    struct Product *cheapest = &items[3];          // «вода»
    // Удаляем «кофе» (индекс 1) со сдвигом хвоста влево
    memmove(&items[1], &items[2], (size_t)(count - 2) * sizeof items[0]);
    count--;
    printf("%s %d\n", cheapest->name, cheapest->price);
    return 0;
}
```

Вывод:

```text
вода 40
```

Выглядит правильно — но это случайность. После сдвига «вода» переехала в `items[2]`, а `cheapest` указывает на `items[3]` — ячейку **за концом** логического массива (`count` теперь 3). Там осталась старая копия, поэтому печатается правильное название. Удалите ещё один элемент или добавьте новый — и `cheapest` покажет совсем другой товар. Санитайзер молчит: `items[3]` — законная память массива.

Защиту от таких ошибок даёт не инструмент, а дисциплина: указатель на элемент контейнера действителен только до следующего изменения контейнера.

## Общий буфер

Ещё одна незаметная форма — указатель на буфер, который переиспользуется:

```c
#include <stdio.h>

struct Student {
    const char *name;        // указатель — НЕ копия строки
    int grade;
};

int main(void) {
    struct Student group[3];
    char buffer[32];
    const char *names[] = {"Аня", "Борис", "Вера"};
    for (int i = 0; i < 3; i++) {
        snprintf(buffer, sizeof buffer, "%s", names[i]);   // как будто прочитали из ввода
        group[i].name = buffer;                             // все указывают на buffer!
        group[i].grade = 3 + i;
    }
    for (int i = 0; i < 3; i++) {
        printf("%s %d\n", group[i].name, group[i].grade);
    }
    return 0;
}
```

Вывод:

```text
Вера 3
Вера 4
Вера 5
```

Все три структуры хранят **один и тот же** адрес — адрес `buffer`, — а в буфере осталось последнее имя. Ошибка классическая для кода, который читает строки в буфер (`fgets`, `scanf("%s")`) и сохраняет указатель. Решение — **копировать** строку в собственную память (массив в структуре или блок из кучи).

## Как не создавать висячие указатели

**1. Индексы вместо указателей.** Индекс в массиве не ломается при `realloc` и остаётся понятным при сдвигах (его легко скорректировать). Указатель на элемент — только для коротких участков кода, где контейнер не меняется.

**2. Копии вместо ссылок на временные данные.** Если данные лежат в буфере, который будет перезаписан, или в кадре функции, сохраняйте копию.

**3. Обнуление после освобождения.** `free(p); p = NULL;` превращает случайное использование в немедленную аварию вместо тихой порчи — но только для одной переменной.

**4. Время жизни указателя ≤ времени жизни объекта.** Указатель на локальную переменную нельзя хранить в глобальной, в куче или в структуре, переживающей функцию.

**5. Дескрипторы с поколением.** Когда объекты создаются и удаляются в произвольном порядке, вместо указателя хранят **дескриптор** — номер ячейки плюс счётчик поколения. При удалении объекта поколение ячейки увеличивается, и старый дескриптор перестаёт совпадать:

```c
#include <stdio.h>

struct Slot {
    int value;
    unsigned generation;
    int used;
};

struct Handle {
    int index;
    unsigned generation;
};

int main(void) {
    struct Slot slots[2] = {{0, 0, 0}, {0, 0, 0}};
    slots[0] = (struct Slot){42, 0, 1};
    struct Handle h = {0, slots[0].generation};       // «ссылка» на объект 42

    slots[0].used = 0;                                 // объект удалён…
    slots[0].generation++;                             // …поколение ячейки выросло
    slots[0] = (struct Slot){99, slots[0].generation, 1};   // ячейку занял другой объект

    int valid = slots[h.index].used && slots[h.index].generation == h.generation;
    printf("%s\n", valid ? "объект жив" : "дескриптор устарел");
    return 0;
}
```

Вывод:

```text
дескриптор устарел
```

Обычный указатель на `slots[0]` показал бы новый объект 99, как будто это прежний. Дескриптор обнаруживает подмену. Так устроены системы объектов в играх, файловые дескрипторы в ядрах ОС и многие базы данных.

<Concept title="Указатель — это обещание">

Сохраняя указатель, вы обещаете: «объект по этому адресу будет существовать и оставаться тем же объектом, пока я пользуюсь указателем». Каждое удаление, перемещение, переиспользование памяти может нарушить обещание. Перед сохранением адреса спросите, что может произойти с объектом, пока указатель жив.

</Concept>

## Частые ошибки

<CommonMistake title="Сохранить указатель на буфер ввода">

`entry.name = buffer;` внутри цикла чтения — все записи будут указывать на одну строку. Копируйте: `strcpy(entry.name, buffer)` в массив внутри структуры или копию в куче.

</CommonMistake>

<CommonMistake title="Указатель на элемент через изменение контейнера">

`struct Item *it = &items[i];` затем удаление, вставка или `realloc` — и `it` указывает не туда. Храните индекс и пересчитывайте адрес после изменения.

</CommonMistake>

<CommonMistake title="Обнулить одну копию из нескольких">

`free(p); p = NULL;` не помогает, если адрес лежит ещё в `q`, в структуре или в массиве. Сначала разберитесь, сколько указателей на блок существует и кто из них владелец.

</CommonMistake>

## Практика

1. **Найди ошибку: общий буфер** — структуры хранят указатель на перезаписываемый буфер.
2. **Найди ошибку: выбранный элемент после удаления** — указатель на элемент массива после сдвига.
3. **Найди ошибку: адрес из функции** — функция форматирования возвращает адрес локального массива.
4. **Дескрипторы с поколением** — хранилище объектов, где устаревшие ссылки распознаются.

## Итоги

- Висячий указатель указывает на объект, который больше не существует или стал другим объектом.
- Источники: выход из блока, `free`, `realloc`, удаление и сдвиг в контейнере, перезапись общего буфера.
- Санитайзеры ловят обращение к освобождённой памяти и вышедшему из области видимости стеку, но не замечают указатель на живую память с другим содержимым.
- Защита: индексы вместо указателей, копии вместо ссылок на временные данные, обнуление после `free`, указатель живёт не дольше объекта.
- Дескриптор с поколением распознаёт ссылку на удалённый объект даже после повторного использования ячейки.
