## Запись за границу буфера

**Переполнение буфера** (buffer overflow) — запись данных за пределы отведённого массива. Чаще всего это происходит со строками: программа копирует, склеивает или читает текст, длина которого больше, чем место под него. Лишние байты затирают то, что лежит в памяти дальше: соседние переменные, служебные данные кучи, адрес возврата функции.

Переполнение буфера — одна из самых известных уязвимостей в истории программирования. Червь Морриса в 1988 году распространялся через переполнение буфера в `gets`; с тех пор этот класс ошибок постоянно встречается в отчётах о безопасности. Если злоумышленник управляет содержимым строки, переполнение стекового буфера позволяет подменить адрес возврата и выполнить свой код.

## Переполнение на стеке

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    char city[8];
    const char *input = "Petropavlovsk";
    strcpy(city, input);              // Ошибка памяти: 14 байтов в массив из 8
    printf("%s\n", city);
    return 0;
}
```

`strcpy` не знает размер `city` — она копирует, пока не встретит `'\0'`. Строка `"Petropavlovsk"` занимает 14 байтов (13 букв и ноль), массив — 8. Шесть байтов уходят за границу.

```text
==28==ERROR: AddressSanitizer: stack-buffer-overflow on address 0x7ffffffca9e8
WRITE of size 14 at 0x7ffffffca9e8 thread T0
    #0 0x5555555e28e6 in strcpy
    #1 0x555555632faf in main /work/main.c:7:5

  This frame has 1 object(s):
    [32, 40) 'city' (line 5) <== Memory access at offset 40 overflows this variable
```

`stack-buffer-overflow` — выход за границу объекта на стеке. `WRITE of size 14` — сколько байтов пыталась записать `strcpy`. Последняя строка указывает переменную: `city` занимает смещения 32–40 в кадре, а запись дошла до 40 — сразу за её концом.

## Переполнение в куче: забытый ноль

Самая частая причина в реальном коде — ошибка на единицу при расчёте размера:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    const char *name = "report";
    char *file = malloc(strlen(name) + 4);       // забыли место под '\0'
    if (file == NULL) {
        return 1;
    }
    sprintf(file, "%s.txt", name);               // Ошибка памяти: 11 байтов в блок из 10
    printf("%s\n", file);
    free(file);
    return 0;
}
```

```text
==27==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x60200000001a
WRITE of size 11 at 0x60200000001a thread T0
    #0 0x5555555976ef in __interceptor_vsprintf
    #1 0x5555555986d3 in sprintf
    #2 0x555555632f24 in main /work/main.c:11:5

0x60200000001a is located 0 bytes to the right of 10-byte region [0x602000000010,0x60200000001a)
allocated by thread T0 here:
    #1 0x555555632eec in main /work/main.c:7:18
```

«0 bytes to the right of 10-byte region» — запись началась **сразу за концом** блока из 10 байтов. Это классический признак забытого `'\0'`: `"report.txt"` — 10 символов и ещё один байт на ноль.

## Опасные функции и их замены

Большинство переполнений строк дают несколько функций, которые не знают размер приёмника:

| Опасно             | Почему                                   | Безопасная замена                                   |
| ------------------ | ---------------------------------------- | --------------------------------------------------- |
| `gets(buf)`        | читает строку любой длины                | `fgets(buf, sizeof buf, stdin)`                     |
| `scanf("%s", buf)` | слово любой длины                        | `scanf("%31s", buf)` для `char buf[32]`             |
| `strcpy(dst, src)` | копирует до `'\0'`, не зная размер `dst` | проверка длины или `snprintf(dst, size, "%s", src)` |
| `strcat(dst, src)` | дописывает, не зная свободного места     | `snprintf` с позицией или проверка длины            |
| `sprintf(buf, …)`  | форматирует без ограничения              | `snprintf(buf, sizeof buf, …)`                      |

`gets` настолько опасна, что удалена из стандарта C11: проверить размер с ней невозможно в принципе.

## `snprintf`: ограничение и обнаружение обрезки

`snprintf(buf, size, format, …)` записывает **не больше** `size` байтов, включая завершающий ноль, и **всегда** завершает строку нулём (если `size > 0`). Её возвращаемое значение — сколько символов **понадобилось бы** без ограничения. Это позволяет узнать, поместился ли результат:

```c
#include <stdio.h>

int main(void) {
    char label[12];
    const char *names[] = {"temp", "humidity-sensor"};
    for (int i = 0; i < 2; i++) {
        int needed = snprintf(label, sizeof label, "%s-%d", names[i], i + 1);
        if (needed >= (int)sizeof label) {
            printf("обрезано: \"%s\" (нужно %d символов)\n", label, needed);
        } else {
            printf("готово: \"%s\"\n", label);
        }
    }
    return 0;
}
```

Вывод:

```text
готово: "temp-1"
обрезано: "humidity-se" (нужно 17 символов)
```

Обрезка лучше переполнения, но она тоже ошибка: имя файла или команда, обрезанная посередине, может сделать не то, что задумано. Проверяйте результат `snprintf`, когда обрезка важна.

## Ширина в `scanf`

`scanf("%s", buf)` читает слово любой длины. Ширина в спецификаторе ограничивает число символов — она должна быть **на единицу меньше** размера массива:

```c
#include <stdio.h>

int main(void) {
    char code[6];
    int read = scanf("%5s", code);      // максимум 5 символов + '\0'
    printf("%d \"%s\"\n", read, code);
    return 0;
}
```

Ввод:

```text
ABCDEFGHIJ
```

Вывод:

```text
1 "ABCDE"
```

Оставшиеся символы `FGHIJ` остаются во входном потоке и будут прочитаны следующим `scanf`. Если это нежелательно, остаток строки нужно пропустить.

## Склеивание строк с проверкой

Чтобы безопасно собрать строку из частей, ведите текущую длину и проверяйте остаток места:

```c
#include <stdio.h>
#include <string.h>

// Дописывает src в dst размера size. Возвращает 0 или -1, если не поместилось (dst не меняется).
int append(char *dst, size_t size, const char *src) {
    size_t used = strlen(dst);
    size_t extra = strlen(src);
    if (used + extra + 1 > size) {
        return -1;
    }
    memcpy(dst + used, src, extra + 1);    // + 1 — вместе с '\0'
    return 0;
}

int main(void) {
    char path[16] = "/home";
    printf("%d %s\n", append(path, sizeof path, "/user"), path);
    printf("%d %s\n", append(path, sizeof path, "/documents"), path);
    return 0;
}
```

Вывод:

```text
0 /home/user
-1 /home/user
```

Вторая часть не поместилась бы (`/home/user/documents` — 20 символов), поэтому строка не изменилась, а функция сообщила об ошибке.

<Concept title="Размер приёмника всегда известен вызывающему">

Функция, которая пишет в массив, должна получать его размер — параметром, как `fgets` и `snprintf`. Если сигнатура функции этого не позволяет (`strcpy`, `strcat`, `sprintf`, `gets`), ответственность за проверку целиком на вас. Перед каждой записью строки задавайте вопрос: сколько байтов я пишу — включая `'\0'` — и сколько у меня есть?

</Concept>

## Частые ошибки

<CommonMistake title="Ширина равна размеру массива">

`char s[8]; scanf("%8s", s);` — 8 символов и ноль — 9 байтов. Ширина должна быть `размер − 1`: `%7s`.

</CommonMistake>

<CommonMistake title="strlen вместо strlen + 1">

`malloc(strlen(s))` и `strcpy` — переполнение на один байт. Такие ошибки часто не видны без инструментов: лишний байт попадает в выравнивание блока.

</CommonMistake>

<CommonMistake title="sizeof указателя в snprintf">

```c
void label(char *out, int id) {
    snprintf(out, sizeof out, "item-%d", id);   // sizeof out — 8, размер указателя
}
```

Внутри функции `out` — указатель. Размер буфера передавайте параметром.

</CommonMistake>

## Практика

1. **Найди ошибку: копия имени** — `strcpy` в маленький массив.
2. **Найди ошибку: ширина scanf** — чтение слова без ограничения.
3. **Безопасная склейка** — функция `append` с отказом при нехватке места.
4. **Метки с обрезкой** — `snprintf` и проверка возвращаемого значения.

## Итоги

- Переполнение буфера — запись за пределы массива; на стеке оно может подменить адрес возврата и стать уязвимостью.
- ASan различает `stack-buffer-overflow` и `heap-buffer-overflow` и показывает объект и смещение записи.
- Частые причины: `strcpy`, `strcat`, `sprintf`, `gets` и `scanf("%s")` без ширины, забытый байт под `'\0'`.
- `snprintf` никогда не пишет больше `size` байтов, всегда завершает строку и возвращает требуемую длину — по ней обнаруживают обрезку.
- Ширина в `scanf` — размер массива минус один; размер буфера передают в функцию параметром.
