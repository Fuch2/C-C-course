## Что такое утечка

**Утечка памяти** — блок из кучи, который программе больше не нужен (или до которого она больше не может добраться), но который так и не освобождён. Сам по себе один забытый блок безвреден: при завершении процесса система заберёт всю его память. Проблема в том, что утечки обычно сидят в коде, который выполняется **много раз**:

- сервер обрабатывает запросы неделями, и каждый запрос теряет по килобайту;
- редактор при каждом открытии файла теряет копию его имени;
- игра теряет блок в каждом кадре — 60 раз в секунду.

Память процесса растёт, пока система не начнёт тормозить или не завершит программу принудительно. Найти такую ошибку по симптомам трудно: падение происходит через часы после того места, где блок был потерян.

## Как выглядит утечка

```c
#include <stdio.h>
#include <stdlib.h>

char *make_label(int id) {
    char *label = malloc(16);
    if (label == NULL) {
        return NULL;
    }
    snprintf(label, 16, "item-%d", id);
    return label;                      // владение передано вызывающему коду
}

int main(void) {
    for (int i = 0; i < 3; i++) {
        char *label = make_label(i);
        if (label == NULL) {
            return 1;
        }
        printf("%s\n", label);
    }                                  // Ошибка памяти: label не освобождён
    return 0;
}
```

Программа печатает три строки и завершается с кодом 0 — по выводу ошибку не увидеть. Но на каждой итерации `label` получает новый блок, а адрес предыдущего теряется. LeakSanitizer (часть AddressSanitizer) в конце работы проверяет, какие блоки остались неосвобождёнными и недостижимыми:

```text
==1==ERROR: LeakSanitizer: detected memory leaks

Direct leak of 32 byte(s) in 2 object(s) allocated from:
    #0 0x5555555f814e in __interceptor_malloc
    #1 0x555555632eb4 in make_label /work/main.c:5:19
    #2 0x555555632f43 in main /work/main.c:15:23

SUMMARY: AddressSanitizer: 32 byte(s) leaked in 2 allocation(s).
```

Как читать отчёт:

- **Direct leak** — на блок не указывает ни один указатель: он потерян напрямую.
- **32 byte(s) in 2 object(s)** — сколько потеряно. Почему два блока, а не три? Адрес последнего ещё мог оставаться в регистре процессора к моменту проверки, и LeakSanitizer не считает такой блок потерянным. Инструмент находит утечку, но не обязан сосчитать каждый блок.
- **Стек вызовов** читается сверху вниз, от самого глубокого вызова: `malloc` вызван в `make_label` (файл `main.c`, строка 5, столбец 19), а та — из `main` (строка 15). Это место, **где выделен** блок. Место, где блок **нужно было** освободить, отчёт не знает — его находите вы, отслеживая владельца.

Исправление: после `printf` добавить `free(label);` — ведь владение передано `main`.

<Important title="Утечка в проверке задач">

Задачи модуля проверяются с LeakSanitizer. При обнаружении утечки программа завершается с ошибкой, а буферизованный вывод может пропасть. Поэтому решение с утечкой не проходит тест, даже если ответ вычислен верно.

</Important>

## Прямые и косвенные утечки

Если потеряна структура, которая владела другими блоками, все вложенные блоки тоже недостижимы. LeakSanitizer различает их:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct User {
    char *name;
    int *scores;
};

struct User *user_create(const char *name) {
    struct User *u = malloc(sizeof *u);
    if (u == NULL) {
        return NULL;
    }
    u->name = malloc(strlen(name) + 1);
    u->scores = calloc(10, sizeof *u->scores);
    if (u->name != NULL) {
        strcpy(u->name, name);
    }
    return u;
}

int main(void) {
    const char *names[] = {"alice", "bob", "carol"};
    for (int i = 0; i < 3; i++) {
        struct User *u = user_create(names[i]);
        if (u == NULL) {
            return 1;
        }
        printf("%s\n", u->name);
    }                          // Ошибка памяти: структуры потеряны вместе со всем, чем владели
    return 0;
}
```

```text
Direct leak of 32 byte(s) in 2 object(s) allocated from:
    #1 0x555555632eb5 in user_create /work/main.c:11:22
    #2 0x5555556333c0 in main /work/main.c:26:26

Indirect leak of 80 byte(s) in 2 object(s) allocated from:
    #1 0x555555632fab in user_create /work/main.c:16:17
    #2 0x5555556333c0 in main /work/main.c:26:26

Indirect leak of 4 byte(s) in 1 object(s) allocated from:
    #1 0x555555632f0b in user_create /work/main.c:15:15
    #2 0x5555556333c0 in main /work/main.c:26:26
```

Строки 11, 15 и 16 — три выделения в `user_create`: структура, имя и массив оценок. **Indirect leak** — на блок указывает другой потерянный блок. Исправлять нужно прямую утечку: как только структура будет освобождена правильной функцией `destroy`, косвенные исчезнут вместе с ней.

## Пять типичных причин

**1. Забытый `free` при передаче владения.** Функция вернула новый блок, а вызывающий код не освободил его — как в первом примере. Помогает правило имён: `create`, `copy`, `make` возвращают владение.

**2. Перезапись указателя.**

```c
char *buffer = malloc(64);
/* … */
buffer = malloc(128);         // адрес первого блока потерян
```

Перед присваиванием нового адреса старый блок нужно освободить — или использовать `realloc`.

**3. Ранний выход.**

```c
int process(const char *path) {
    char *data = malloc(4096);
    if (data == NULL) {
        return -1;
    }
    if (!is_valid(path)) {
        return -1;            // утечка: data не освобождён
    }
    /* … */
    free(data);
    return 0;
}
```

Каждый `return` после выделения — повод спросить: что уже выделено и кто это освободит? В функциях с несколькими ресурсами помогает единая точка очистки (`goto cleanup`), которую вы изучите в модуле «Углублённый C».

**4. `p = realloc(p, n)`.** При отказе `realloc` возвращает `NULL`, и единственный адрес блока затирается.

**5. Освобождение только верхнего уровня.** `free(user)` без `free(user->name)` — косвенная утечка всего, чем владела структура.

## Как писать код без утечек

- Для каждого `malloc` сразу решите, кто вызовет `free`, и напишите этот `free` вместе с выделением.
- Пары функций `create`/`destroy` для каждой структуры, владеющей памятью; `destroy` освобождает всё вложенное.
- Один владелец у каждого блока; заимствующий код получает `const`-указатель и не освобождает.
- Запускайте программу с AddressSanitizer или Valgrind на тестах, включая ветки ошибок: утечки чаще всего прячутся именно там.

<Concept title="Утечка — это потерянный владелец">

Блок утекает, когда исчезает последний указатель, через который его можно освободить. Это происходит при перезаписи указателя, выходе из функции или освобождении структуры-владельца. Ищите момент, когда «последняя ниточка» к блоку обрывается.

</Concept>

## Частые ошибки

<CommonMistake title="«Программа всё равно завершается»">

Утечка в `main` перед `return` действительно безвредна, но код из `main` часто переезжает в функцию, которая вызывается в цикле. Освобождайте всё — инструменты проверки тоже требуют чистого завершения.

</CommonMistake>

<CommonMistake title="Освобождение в обычной ветке, но не в ветке ошибки">

Тесты обычно проходят по успешному пути, поэтому утечка в ветке ошибки живёт годами. Проверяйте программу на некорректных входных данных.

</CommonMistake>

<CommonMistake title="Утечка при замене значения">

`entry->name = copy_string(new_name);` — старое имя потеряно. Сначала `free(entry->name)`, затем присваивание (или сначала копия во временную переменную, если копирование может не удаться).

</CommonMistake>

## Практика

1. **Найди ошибку: утечка в обработчике** — ранний выход без освобождения.
2. **Найди ошибку: перезаписанный указатель** — новый блок на каждой итерации.
3. **Найди ошибку: косвенная утечка** — `destroy` освобождает только структуру.
4. **Последние k записей** — кольцевой журнал, который освобождает вытесненные строки.

## Итоги

- Утечка — неосвобождённый блок, до которого программа больше не может добраться; опасна в повторяющемся коде.
- LeakSanitizer сообщает в конце работы, сколько байтов потеряно и где они были выделены.
- Direct leak — блок потерян напрямую; indirect leak — блок принадлежал потерянному блоку; исправлять нужно прямую.
- Типичные причины: забытый `free` после передачи владения, перезапись указателя, ранний выход, `p = realloc(p, …)`, освобождение только внешней структуры.
- Защита — ясный владелец у каждого блока, пары `create`/`destroy` и проверка инструментами на всех ветках, включая ошибки.
