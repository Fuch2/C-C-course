## От приёма к структуре данных

В уроке о `realloc` растущий массив состоял из трёх отдельных переменных: указателя, длины и ёмкости. Это работает в одной функции, но как только массив нужно передать куда-то ещё, три переменные легко рассогласовать. Решение — собрать их в структуру и работать с ней только через набор функций. Получится **динамический массив** (вектор) — самая используемая структура данных в программировании.

```c
struct IntVec {
    int *data;          // блок в куче или NULL
    size_t length;      // сколько элементов занято
    size_t capacity;    // на сколько элементов рассчитан блок
};
```

## Инварианты

Функции вектора полагаются на условия, которые должны выполняться **всегда** между вызовами. Такие условия называют **инвариантами**:

1. `length ≤ capacity`;
2. `data == NULL` тогда и только тогда, когда `capacity == 0`;
3. элементы `data[0] … data[length − 1]` инициализированы, остальные — нет;
4. блок `data` принадлежит вектору: освобождает его только `vec_free`.

Каждая функция может временно нарушить инвариант внутри себя, но обязана восстановить его до возврата. Если код вне функций вектора меняет поля напрямую, инварианты легко сломать — поэтому с полями работают только функции вектора.

## Реализация

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct IntVec {
    int *data;
    size_t length;
    size_t capacity;
};

void vec_init(struct IntVec *v) {
    v->data = NULL;
    v->length = 0;
    v->capacity = 0;
}

// Гарантирует место хотя бы под min_capacity элементов. 0 — успех, -1 — нет памяти.
int vec_reserve(struct IntVec *v, size_t min_capacity) {
    if (min_capacity <= v->capacity) {
        return 0;
    }
    size_t capacity = v->capacity ? v->capacity : 4;
    while (capacity < min_capacity) {
        capacity *= 2;
    }
    int *bigger = realloc(v->data, capacity * sizeof *bigger);
    if (bigger == NULL) {
        return -1;                          // вектор не изменился — инварианты целы
    }
    v->data = bigger;
    v->capacity = capacity;
    return 0;
}

int vec_push(struct IntVec *v, int value) {
    if (vec_reserve(v, v->length + 1) != 0) {
        return -1;
    }
    v->data[v->length++] = value;
    return 0;
}

// Вставка перед позицией index (0 ≤ index ≤ length).
int vec_insert(struct IntVec *v, size_t index, int value) {
    if (index > v->length || vec_reserve(v, v->length + 1) != 0) {
        return -1;
    }
    memmove(v->data + index + 1, v->data + index, (v->length - index) * sizeof *v->data);
    v->data[index] = value;
    v->length++;
    return 0;
}

void vec_free(struct IntVec *v) {
    free(v->data);
    vec_init(v);                            // вектор снова пустой и пригоден к работе
}

int main(void) {
    struct IntVec v;
    vec_init(&v);
    for (int i = 1; i <= 5; i++) {
        if (vec_push(&v, i * 10) != 0) {
            vec_free(&v);
            return 1;
        }
    }
    vec_insert(&v, 0, 5);
    vec_insert(&v, 3, 25);
    for (size_t i = 0; i < v.length; i++) {
        printf("%d ", v.data[i]);
    }
    printf("\nlength=%zu capacity=%zu\n", v.length, v.capacity);
    vec_free(&v);
    return 0;
}
```

Вывод:

```text
5 10 20 25 30 40 50
length=7 capacity=8
```

Разберём решения:

- `vec_reserve` — единственное место, где вызывается `realloc`. Все функции, которым нужно место, обращаются к ней. Так шаблон с временной переменной написан ровно один раз.
- При ошибке выделения вектор **не меняется**: старый блок, длина и ёмкость те же. Вызывающий код может продолжить работу или освободить вектор.
- `vec_free` после `free` возвращает вектор в пустое состояние. Повторный `vec_free` безопасен, и вектор можно использовать снова.

## Безопасный доступ к элементу

Прямое `v.data[i]` не проверяет границы. Функция доступа может проверять индекс и сообщать об ошибке:

```c
#include <stdio.h>
#include <stddef.h>

struct IntVec {
    int *data;
    size_t length;
    size_t capacity;
};

// Записывает элемент в *out. 0 — успех, -1 — индекс вне [0, length).
int vec_get(const struct IntVec *v, size_t index, int *out) {
    if (index >= v->length) {
        return -1;
    }
    *out = v->data[index];
    return 0;
}

int main(void) {
    int storage[4] = {7, 8, 9, 0};
    struct IntVec v = {storage, 3, 4};      // для примера — массив на стеке
    int x;
    for (size_t i = 2; i <= 4; i++) {
        if (vec_get(&v, i, &x) == 0) {
            printf("[%zu] = %d\n", i, x);
        } else {
            printf("[%zu] вне границ\n", i);
        }
    }
    return 0;
}
```

Вывод:

```text
[2] = 9
[3] вне границ
[4] вне границ
```

Индекс 3 меньше ёмкости, но элемент там **не инициализирован** — граница вектора проходит по `length`, а не по `capacity`.

## Удаление и сжатие

Удаление из середины сдвигает хвост влево (`memmove`) — O(n). Удаление с конца — просто `length--`, O(1). Ёмкость при этом не уменьшается: память остаётся за вектором на случай новых элементов. Если вектор сильно сократился и больше расти не будет, его можно **сжать**:

```c
// Уменьшает блок до length элементов. Пустой вектор освобождает блок.
int vec_shrink(struct IntVec *v) {
    if (v->length == 0) {
        free(v->data);
        v->data = NULL;
        v->capacity = 0;
        return 0;
    }
    int *smaller = realloc(v->data, v->length * sizeof *smaller);
    if (smaller == NULL) {
        return -1;
    }
    v->data = smaller;
    v->capacity = v->length;
    return 0;
}
```

Пустой вектор сжимается через `free`, а не `realloc(p, 0)` — так соблюдается инвариант «`data == NULL` ⇔ `capacity == 0`».

## Сложность операций

| Операция                    | Время                | Комментарий                    |
| --------------------------- | -------------------- | ------------------------------ |
| доступ `data[i]`            | O(1)                 | адрес вычисляется сразу        |
| добавление в конец          | O(1) амортизированно | редкие `realloc` при удвоении  |
| удаление с конца            | O(1)                 | только `length--`              |
| вставка/удаление в середине | O(n)                 | сдвиг хвоста `memmove`         |
| поиск значения              | O(n)                 | или O(log n) в отсортированном |

Элементы лежат в памяти подряд, поэтому обход вектора очень быстрый: процессор загружает соседние элементы в кэш заранее. Именно поэтому вектор — выбор по умолчанию, даже когда теоретически подходит список.

## Копирование структуры — это не копирование массива

Присваивание `struct IntVec b = a;` копирует **поля**: указатель, длину и ёмкость. Блок данных не копируется — у одного блока становится два «владельца»:

```c
#include <stdio.h>
#include <stdlib.h>

struct IntVec {
    int *data;
    size_t length;
    size_t capacity;
};

int main(void) {
    struct IntVec a = {malloc(2 * sizeof(int)), 2, 2};
    if (a.data == NULL) {
        return 1;
    }
    a.data[0] = 1;
    a.data[1] = 2;
    struct IntVec b = a;              // скопирован указатель, а не числа
    b.data[0] = 100;                  // меняет и «a»
    printf("%d\n", a.data[0]);
    free(a.data);
    // free(b.data) здесь освободил бы тот же блок второй раз
    return 0;
}
```

Вывод:

```text
100
```

Чтобы получить независимую копию, нужна функция **глубокого** копирования: выделить новый блок и скопировать в него элементы. Это одна из главных причин, по которой в C++ появились конструкторы копирования — вы встретите их в модуле о времени жизни объектов.

<Concept title="Структура данных = представление + инварианты + функции">

Динамический массив — не просто три поля. Это договор: поля меняются только функциями, которые сохраняют инварианты. Пока договор соблюдается, любая функция может доверять тому, что `data[0 … length − 1]` существуют и инициализированы.

</Concept>

## Частые ошибки

<CommonMistake title="Проверка индекса по capacity">

`if (i < v->capacity) return v->data[i];` — элементы между `length` и `capacity` не инициализированы. Граница — `length`.

</CommonMistake>

<CommonMistake title="Указатель на элемент между вставками">

`int *first = &v.data[0]; vec_push(&v, 5);` — если `push` вызвала `realloc`, `first` висит. Указатели на элементы вектора действительны только до следующей операции, способной изменить ёмкость.

</CommonMistake>

<CommonMistake title="Поверхностная копия">

`struct IntVec copy = v;` создаёт второго владельца того же блока: изменения видны в обоих, а освобождение обоих — двойной `free`. Нужна функция глубокого копирования.

</CommonMistake>

## Практика

1. **Стек команд** — вектор как стек: `push`, `pop`, `top`.
2. **Фильтр на месте** — удаление элементов за один проход и сжатие ёмкости.
3. **Отсортированная вставка** — `vec_insert` со сдвигом хвоста.
4. **Найди ошибку: копия вектора** — поверхностная копия структуры.

## Итоги

- Динамический массив хранит указатель, длину и ёмкость в одной структуре и меняется только через свои функции.
- Инварианты: `length ≤ capacity`, `data == NULL` ⇔ `capacity == 0`, инициализированы только первые `length` элементов.
- Один `vec_reserve` с удвоением и шаблоном `realloc` обслуживает все операции роста; при ошибке вектор не меняется.
- Добавление в конец — амортизированно O(1), вставка и удаление в середине — O(n), доступ — O(1).
- Указатели на элементы живут до следующего роста; копирование структуры не копирует данные.
