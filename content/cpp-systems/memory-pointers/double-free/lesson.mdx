## Один блок — один `free`

**Двойное освобождение** (double free) — повторный вызов `free` для блока, который уже освобождён. Распределитель памяти хранит служебные данные о свободных блоках, часто прямо внутри них. Повторный `free` портит эти структуры: следующий `malloc` может выдать один и тот же блок двум разным частям программы или аварийно завершить её. Как и use-after-free, двойное освобождение используется в атаках на программы.

Простейший случай компилятор GCC видит сам:

```c
#include <stdlib.h>

int main(void) {
    int *p = malloc(4);
    free(p);
    free(p);        // Ошибка памяти: второй free того же блока
    return 0;
}
```

```text
warning: pointer 'p' used after 'free' [-Wuse-after-free]
```

Запущенная без инструментов, такая программа обычно падает с сообщением стандартной библиотеки `free(): double free detected in tcache 2` и сигналом `SIGABRT`. Но в реальном коде два `free` разнесены по разным функциям и файлам, и компилятор их не связывает.

## Настоящая причина — два владельца

Двойное освобождение почти никогда не бывает опечаткой. Оно возникает, когда **два участка кода считают себя владельцами** одного блока. Самый частый путь — копирование структуры, содержащей указатель:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Config {
    char *path;
    int retries;
};

int main(void) {
    struct Config original = {malloc(16), 3};
    if (original.path == NULL) {
        return 1;
    }
    strcpy(original.path, "/etc/app.conf");
    struct Config backup = original;      // копия указателя, а не строки
    backup.retries = 5;
    printf("%s %d %d\n", backup.path, original.retries, backup.retries);
    free(original.path);
    free(backup.path);                    // Ошибка памяти: тот же блок второй раз
    return 0;
}
```

Число `retries` скопировалось и живёт независимо, а `path` — нет: обе структуры указывают на одну строку. Каждая «освобождает своё», и строка освобождается дважды.


Структура отчёта знакома по прошлому уроку: где произошёл второй `free` (строка 20), где первый (строка 19) и где блок выделен (строка 11). Valgrind сообщает о том же как `Invalid free() / delete / delete[] / realloc()` с теми же тремя местами.

## Три способа исправить

Исправление начинается с решения: **кто владелец**?

**1. Глубокая копия.** Каждая структура получает собственную строку:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

struct Config {
    char *path;
    int retries;
};

int config_copy(struct Config *dst, const struct Config *src) {
    dst->path = malloc(strlen(src->path) + 1);
    if (dst->path == NULL) {
        return -1;
    }
    strcpy(dst->path, src->path);
    dst->retries = src->retries;
    return 0;
}

int main(void) {
    struct Config original = {malloc(16), 3};
    if (original.path == NULL) {
        return 1;
    }
    strcpy(original.path, "/etc/app.conf");
    struct Config backup;
    if (config_copy(&backup, &original) != 0) {
        free(original.path);
        return 1;
    }
    backup.path[5] = 'X';                     // меняется только копия
    printf("%s %s\n", original.path, backup.path);
    free(original.path);
    free(backup.path);                        // теперь это другой блок
    return 0;
}
```

Вывод:

```text
/etc/app.conf /etc/Xpp.conf
```

**2. Передача владения.** Если старая структура больше не нужна, владение «переезжает»: новая получает указатель, старая — `NULL`. Освобождает только новый владелец, а `free(NULL)` у старого безопасен:

```c
struct Config moved = original;
original.path = NULL;        // original больше ничем не владеет
```

**3. Заимствование.** Одна структура владеет, другая только смотрит — тогда её поле лучше объявить `const char *` и никогда не освобождать.

## Обнуление после `free`

Приём `free(p); p = NULL;` превращает случайный повторный `free(p)` в безопасный `free(NULL)`. Особенно полезен он для полей структур, которые освобождаются в разных местах:

```c
#include <stdio.h>
#include <stdlib.h>

struct Cache {
    int *items;
    size_t count;
};

void cache_clear(struct Cache *c) {
    free(c->items);
    c->items = NULL;          // повторный cache_clear не сломается
    c->count = 0;
}

int main(void) {
    struct Cache c = {malloc(8 * sizeof(int)), 8};
    if (c.items == NULL) {
        return 1;
    }
    cache_clear(&c);
    cache_clear(&c);          // например, ещё раз при завершении программы
    printf("%zu %s\n", c.count, c.items == NULL ? "пусто" : "занято");
    return 0;
}
```

Вывод:

```text
0 пусто
```

Но помните ограничение из урока о висячих указателях: обнуляется только одна переменная. Если копия адреса лежит где-то ещё — как `backup.path` выше, — обнуление `original.path` не поможет.

## Другие ошибочные вызовы `free`

Рядом с двойным освобождением стоят ещё две ошибки с тем же результатом — испорченной кучей:

| Ошибка                                                | Пример                     | Отчёт ASan                                             |
| ----------------------------------------------------- | -------------------------- | ------------------------------------------------------ |
| освобождение середины блока                           | `free(buf + 4)`            | `attempting free on address which was not malloc()-ed` |
| освобождение не кучи                                  | `free(&x)`, `free("text")` | то же                                                  |
| освобождение через неверный указатель после `realloc` | `free(old)` после переезда | `attempting double-free`                               |

<Concept title="Владение не копируется">

Скопировать указатель — не значит скопировать владение. Каждый раз, когда адрес блока появляется в новой переменной или структуре, решите: это **глубокая копия** (новый блок), **передача** (старый владелец отказывается) или **заимствование** (новый держатель ничего не освобождает).

</Concept>

## Частые ошибки

<CommonMistake title="Поверхностная копия структуры с указателями">

`struct T b = a;` и затем `destroy(&a); destroy(&b);` — двойное освобождение всех полей-указателей. Пишите функцию глубокого копирования или явно передавайте владение.

</CommonMistake>

<CommonMistake title="Освобождение и в функции, и в вызывающем коде">

Функция `process(char *data)` освобождает `data` внутри, а вызывающий код тоже вызывает `free(data)`. Договоритесь: функции, которые забирают владение, называются соответственно (`consume`, `take`) и документируются.

</CommonMistake>

<CommonMistake title="free старого указателя после realloc">

`int *bigger = realloc(old, n); … free(old);` — если блок переехал, `realloc` уже освободила `old`. После успешного `realloc` освобождают только новый указатель.

</CommonMistake>

## Практика

1. **Найди ошибку: копия записи** — поверхностная копия структуры со строкой.
2. **Найди ошибку: функция забирает владение** — блок освобождается и внутри функции, и снаружи.
3. **Найди ошибку: повторная очистка** — очистка вызывается дважды без обнуления полей.
4. **Передача владения** — переместить строки между двумя списками без копирования и без двойного `free`.

## Итоги

- Двойное освобождение портит служебные структуры распределителя памяти; glibc обычно аварийно завершает программу, ASan сообщает `attempting double-free`.
- Причина почти всегда — два владельца одного блока, чаще всего из-за поверхностной копии структуры.
- Исправления: глубокая копия, передача владения с обнулением старого указателя или заимствование без освобождения.
- `free(p); p = NULL;` делает повторную очистку безопасной, но защищает только одну переменную.
- `free` середины блока, не-кучи и старого указателя после `realloc` — того же рода ошибки.
