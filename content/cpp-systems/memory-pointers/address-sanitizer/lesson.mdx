## Инструмент, который вы уже видели

Во всех уроках модуля задачи проверялись с AddressSanitizer (ASan) и UndefinedBehaviorSanitizer (UBSan), а в тексте встречались их отчёты. Теперь соберём всё вместе: как включить санитайзеры в своём проекте, как они устроены, что умеют и чего не умеют, и как систематически читать отчёт.

## Как включить

Санитайзеры встроены в GCC и Clang. Достаточно добавить флаги при компиляции **и** компоновке:

```text
clang -std=c17 -g -O1 -fsanitize=address,undefined -fno-omit-frame-pointer main.c -o main
./main
```

| Флаг                      | Зачем                                                          |
| ------------------------- | -------------------------------------------------------------- |
| `-fsanitize=address`      | AddressSanitizer: границы, use-after-free, double free, утечки |
| `-fsanitize=undefined`    | UBSan: переполнения, сдвиги, выравнивание, индексы, `NULL`     |
| `-g`                      | отладочная информация — имена файлов и номера строк в отчётах  |
| `-fno-omit-frame-pointer` | точный стек вызовов                                            |
| `-O1`                     | разумная скорость; `-O0` тоже работает, но медленнее           |

Поведение настраивается переменными окружения:

```text
ASAN_OPTIONS=detect_leaks=1:halt_on_error=1 UBSAN_OPTIONS=halt_on_error=1:print_stacktrace=1 ./main
```

`detect_leaks=1` включает LeakSanitizer (в Linux он включён по умолчанию), `halt_on_error=1` останавливает программу на первой ошибке UBSan — так работает проверка задач в этом курсе. Без него UBSan печатает предупреждение и продолжает работу.

## Как это работает

**Теневая память.** На каждые 8 байтов памяти программы ASan хранит 1 байт состояния: все 8 байтов доступны, доступны первые `k`, или недоступны — и почему (красная зона кучи, освобождённый блок, стек вне области видимости и т. д.). Это и есть таблица «Shadow bytes» в конце отчёта.

**Инструментирование.** Компилятор вставляет перед каждым чтением и записью проверку теневого байта. Если доступ запрещён — вызывается функция отчёта.

**Красные зоны.** Вокруг каждого блока кучи, локального массива и глобальной переменной ASan оставляет «отравленные» байты. Выход за границу на несколько байтов попадает в красную зону и сразу обнаруживается.

**Карантин.** Освобождённые блоки не отдаются новым `malloc` сразу, а держатся в карантине (по умолчанию 256 МБ). Поэтому use-after-free обнаруживается даже спустя много новых выделений.

**Перехват функций.** `malloc`, `free`, `memcpy`, `strcpy`, `printf` и сотни других функций заменены версиями, которые проверяют аргументы — отсюда `memcpy-param-overlap` и ошибки внутри `strcpy`.

Цена: программа работает примерно в 2 раза медленнее и потребляет в 2–3 раза больше памяти. Поэтому санитайзеры включают в отладочных сборках и тестах, а не в итоговой программе.

## Что находит каждый санитайзер

| Ошибка                                         | Отчёт                                       | Инструмент        |
| ---------------------------------------------- | ------------------------------------------- | ----------------- |
| выход за блок кучи                             | `heap-buffer-overflow`                      | ASan              |
| выход за локальный массив                      | `stack-buffer-overflow`                     | ASan              |
| выход за глобальный массив                     | `global-buffer-overflow`                    | ASan              |
| обращение к освобождённому блоку               | `heap-use-after-free`                       | ASan              |
| переменная вне области видимости               | `stack-use-after-scope`                     | ASan              |
| двойное или неверное освобождение              | `attempting double-free`, `bad-free`        | ASan              |
| перекрытие в `memcpy`                          | `memcpy-param-overlap`                      | ASan              |
| утечка                                         | `LeakSanitizer: detected memory leaks`      | LSan (часть ASan) |
| переполнение знаковых, сдвиги, деление         | `runtime error: signed integer overflow`    | UBSan             |
| индекс за пределами массива известного размера | `index 12 out of bounds for type 'int[12]'` | UBSan             |
| невыровненный доступ                           | `misaligned address`                        | UBSan             |
| разыменование `NULL`                           | `member access within null pointer`         | UBSan             |

## Чего санитайзеры не видят

- **Чтение неинициализированной памяти.** ASan проверяет, можно ли обращаться к байту, а не записан ли он. Для этого есть Valgrind (следующий урок) и MemorySanitizer в Clang.
- **Выход за логическую границу** внутри выделенного блока — например, чтение за `length` вектора внутри его `capacity`.
- **Выход внутри структуры** — переполнение одного поля в соседнее поле той же структуры.
- **Код, который не выполнялся.** Санитайзер проверяет только реально выполненные пути. Ошибка в ветке обработки ошибок останется незамеченной, пока тест не пройдёт через эту ветку.
- **Логические ошибки** — висячий указатель на живой, но другой объект, неверная формула.

Поэтому санитайзеры — не замена пониманию, а сеть, которая ловит то, что ускользнуло от внимания.

## Как читать отчёт: четыре вопроса

Возьмём программу с ошибкой и её отчёт:

```c
#include <stdio.h>
#include <stdlib.h>

long long sum_values(const int *values, int n) {
    long long sum = 0;
    for (int i = 0; i <= n; i++) {        // Ошибка памяти: лишняя итерация
        sum += values[i];
    }
    return sum;
}

int main(void) {
    int n = 5;
    int *values = malloc(n * sizeof *values);
    if (values == NULL) {
        return 1;
    }
    for (int i = 0; i < n; i++) {
        values[i] = i * i;
    }
    printf("%lld\n", sum_values(values, n));
    free(values);
    return 0;
}
```

```text
==27==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x603000000054
READ of size 4 at 0x603000000054 thread T0
    #0 0x555555632f9d in sum_values /work/main.c:7:16
    #1 0x5555556331eb in main /work/main.c:21:22

0x603000000054 is located 0 bytes to the right of 20-byte region [0x603000000040,0x603000000054)
allocated by thread T0 here:
    #0 0x5555555f814e in __interceptor_malloc
    #1 0x555555633052 in main /work/main.c:14:19

SUMMARY: AddressSanitizer: heap-buffer-overflow /work/main.c:7:16 in sum_values
```

1. **Что случилось?** Первая строка: `heap-buffer-overflow` — выход за границу блока кучи.
2. **Какая операция?** `READ of size 4` — чтение 4 байтов, скорее всего `int`.
3. **Где в коде?** Стек под операцией: строка 7 функции `sum_values`, вызванной из `main` в строке 21. Читайте сверху вниз; верхняя строка вашего кода — место ошибки.
4. **Какой объект?** «0 bytes to the right of 20-byte region» — сразу за концом блока из 20 байтов (5 чисел `int`), выделенного в строке 14. Значит, прочитан элемент с индексом 5 в массиве из 5 элементов — классическая ошибка на единицу, и условие `i <= n` в строке 6 — её причина.

Только после ответов на все четыре вопроса открывайте код и ищите причину. Помните: строка, где произошло обращение, — не всегда строка с ошибкой. Неверный индекс мог быть вычислен в другой функции.

## Несколько ошибок

ASan останавливается на **первой** ошибке. Если ошибок несколько, исправляйте их по одной: исправили первую — перезапустили — получили следующую. Не пытайтесь «угадать» все сразу: первая ошибка может портить память и вызывать ложные симптомы дальше.

<Concept title="Санитайзер превращает «иногда» во «всегда»">

Ошибки памяти без инструментов проявляются случайно: зависят от расположения данных, компилятора, входа. Санитайзер делает каждое нарушение немедленным и точным — с местом, объектом и историей. Включайте его на всех тестах: ошибка, найденная санитайзером в тесте, не доберётся до пользователя.

</Concept>

## Частые ошибки

<CommonMistake title="Сборка без -g">

Без отладочной информации отчёт содержит только адреса (`main+0x1a4`) вместо файлов и строк. Добавляйте `-g` в отладочные сборки.

</CommonMistake>

<CommonMistake title="Флаг только при компиляции">

`-fsanitize=address` нужен и при компоновке: он подключает библиотеку времени выполнения санитайзера. В Makefile и CMake добавляйте его и в `CFLAGS`, и в `LDFLAGS`.

</CommonMistake>

<CommonMistake title="«Санитайзер молчит — значит, ошибок нет»">

Санитайзер проверяет только выполненный код и не видит неинициализированные данные. Чистый запуск на одном тесте — не доказательство. Нужны тесты на граничные случаи и ветки ошибок.

</CommonMistake>

## Практика

Каждая задача — программа с ошибкой. В большинстве из них ошибку находит ASan или UBSan; одна показывает, как ошибка на единицу выглядит, когда санитайзер молчит. Запустите её кнопкой «Проверить», прочитайте отчёт по четырём вопросам и исправьте причину.

1. **Найди ошибку: таблица продаж** — `heap-buffer-overflow` в прямоугольной таблице.
2. **Найди ошибку: формат времени** — буфер на один байт меньше нужного.
3. **Найди ошибку: день недели** — выход за глобальную таблицу.
4. **Найди ошибку: две ошибки в одной программе** — исправляйте по одной.

## Итоги

- ASan и UBSan включаются флагами `-fsanitize=address,undefined -g -fno-omit-frame-pointer` при компиляции и компоновке; поведение настраивается `ASAN_OPTIONS` и `UBSAN_OPTIONS`.
- ASan работает через теневую память, красные зоны, карантин и перехват функций; цена — примерно двукратное замедление и рост памяти.
- ASan находит выход за границы, use-after-free, double free, утечки; UBSan — переполнения, сдвиги, выравнивание, индексы и `NULL`.
- Санитайзеры не видят неинициализированные данные, логические границы, выход внутри структуры и невыполненный код.
- Отчёт читают по четырём вопросам: что случилось, какая операция, где в коде, какой объект; ошибки исправляют по одной.
