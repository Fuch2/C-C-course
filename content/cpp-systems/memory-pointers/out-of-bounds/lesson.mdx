## Индекс за пределами массива

В прошлом уроке за границу выходили функции работы со строками. Но чаще всего выход за границы происходит в обычном коде с индексами: цикл делает на одну итерацию больше, индекс приходит из входных данных без проверки, формула для двумерного массива ошибается на строку. C не проверяет индексы: `a[i]` — это просто «адрес `a` плюс `i` элементов», каким бы ни было `i`.

Чтение за границей не менее опасно, чем запись: программа получает мусор, а в худшем случае — чужие данные. Знаменитая уязвимость Heartbleed (2014) была именно чтением за границей буфера: сервер отправлял клиенту до 64 КБ своей памяти — вместе с паролями и ключами шифрования.

## Ошибка на единицу

```c
#include <stdio.h>

int days[12] = {31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};

int main(void) {
    int total = 0;
    for (int m = 0; m <= 12; m++) {       // Ошибка памяти: <= вместо <
        total += days[m];
    }
    printf("%d\n", total);
    return 0;
}
```

Без инструментов эта программа на проверочной машине печатает `365` — правильный ответ! За массивом в памяти случайно оказался ноль, и лишняя итерация ничего не добавила. Ошибка может годами жить в коде, пока рядом не появится другая глобальная переменная.

UndefinedBehaviorSanitizer знает размер массива из его типа и останавливает программу:

```text
main.c:8:18: runtime error: index 12 out of bounds for type 'int[12]'
    #0 0x555555632ef0 in main /work/main.c:8:18
```

Массив из `N` элементов имеет индексы `0 … N − 1`. Цикл по всем элементам — `i < N`, а не `i <= N`. Запомните форму `for (i = 0; i < N; i++)`: если вы пишете `<=`, это повод перепроверить границу.

## Обращение к соседнему элементу

Код, сравнивающий соседние элементы, легко выходит за массив на последней итерации:

```c
#include <stdio.h>
#include <stdlib.h>

int main(void) {
    int n = 5;
    int *temps = malloc(n * sizeof *temps);
    if (temps == NULL) {
        return 1;
    }
    for (int i = 0; i < n; i++) {
        temps[i] = 20 + i;
    }
    int rises = 0;
    for (int i = 0; i < n; i++) {
        if (temps[i + 1] > temps[i]) {     // Ошибка памяти: при i = n - 1 читается temps[n]
            rises++;
        }
    }
    printf("%d\n", rises);
    free(temps);
    return 0;
}
```

```text
==28==ERROR: AddressSanitizer: heap-buffer-overflow on address 0x603000000054
READ of size 4 at 0x603000000054 thread T0
    #0 0x55555563317c in main /work/main.c:15:13

0x603000000054 is located 0 bytes to the right of 20-byte region [0x603000000040,0x603000000054)
```

`READ of size 4` — это чтение, а не запись: санитайзер ловит оба. Если в теле цикла есть `a[i + 1]`, цикл должен идти до `i < n − 1` (или `i + 1 < n` — так запись безопаснее для беззнаковых `n`). Аналогично для `a[i − 1]` цикл начинается с `i = 1`.

## Индекс из входных данных

Любой индекс, пришедший извне — из ввода, файла, сети, другой функции, — нужно проверить, прежде чем использовать:

```c
#include <stdio.h>

static const char *const MONTHS[12] = {
    "январь", "февраль", "март", "апрель", "май", "июнь",
    "июль", "август", "сентябрь", "октябрь", "ноябрь", "декабрь",
};

const char *month_name(int number) {          // number — от 1 до 12
    if (number < 1 || number > 12) {
        return "неизвестный месяц";
    }
    return MONTHS[number - 1];
}

int main(void) {
    int queries[] = {1, 12, 0, 13, -5};
    for (int i = 0; i < 5; i++) {
        printf("%d: %s\n", queries[i], month_name(queries[i]));
    }
    return 0;
}
```

Вывод:

```text
1: январь
12: декабрь
0: неизвестный месяц
13: неизвестный месяц
-5: неизвестный месяц
```

Проверка нужна с **обеих** сторон: отрицательный индекс читает память перед массивом. Для беззнакового индекса (`size_t`) достаточно одной проверки `index < count`: отрицательное число, превращённое в `size_t`, становится огромным и тоже отсекается.

## Двумерные данные в одном блоке

Для таблицы в одном блоке ошибка в формуле индекса даёт выход за границу не сразу, а только на последних строках:

| Формула        | Для таблицы `rows × cols`       | Результат                            |
| -------------- | ------------------------------- | ------------------------------------ |
| `r * cols + c` | правильно                       | индексы от 0 до `rows · cols − 1`    |
| `r * rows + c` | ошибка, если `rows ≠ cols`      | при `rows > cols` выходит за блок    |
| `c * cols + r` | транспонирование вместо доступа | при `rows ≠ cols` путаница или выход |

На квадратных тестовых таблицах все три формулы «работают». Проверяйте код на прямоугольных данных — и с санитайзером.

## Как санитайзеры видят границы

- **AddressSanitizer** окружает каждый объект — блок кучи, локальный массив, глобальную переменную — «отравленными» байтами (красными зонами). Обращение к ним — ошибка `heap-buffer-overflow`, `stack-buffer-overflow` или `global-buffer-overflow`.
- **UBSan** проверяет индексы массивов, размер которых известен из типа (`int days[12]`), и сообщает `index 12 out of bounds`.

Ни один инструмент не поймает выход за **логическую** границу внутри выделенной памяти: если вектор с ёмкостью 8 содержит 5 элементов, чтение `data[6]` формально законно. Такие ошибки находят только проверки в коде — как `index < length` в функции `vec_get`.

<Concept title="Граница — это длина, а не размер блока">

У каждого массива есть допустимый диапазон индексов. Для массива `T a[N]` — `[0, N)`, для динамического массива — `[0, length)`, для подстроки — свой. Каждое обращение `a[i]` должно сопровождаться доказательством, что `i` в диапазоне: условием цикла, проверкой или инвариантом.

</Concept>

## Частые ошибки

<CommonMistake title="i <= n в цикле по массиву">

Последний индекс массива из `n` элементов — `n − 1`. Условие `i <= n` делает лишнюю итерацию с `a[n]`.

</CommonMistake>

<CommonMistake title="Проверка только сверху">

`if (index < count) return a[index];` для `int index` пропускает отрицательные значения. Проверяйте `index >= 0 && index < count` или используйте `size_t`.

</CommonMistake>

<CommonMistake title="Цикл до n при обращении к i + 1">

`for (i = 0; i < n; i++) if (a[i] > a[i + 1])` — последняя итерация читает `a[n]`. Нужно `i + 1 < n`.

</CommonMistake>

## Практика

1. **Найди ошибку: подъёмы температуры** — сравнение с соседним элементом.
2. **Найди ошибку: запросы к массиву** — индексы из ввода без проверки.
3. **Найди ошибку: префиксные суммы** — обращение к `prefix[i − 1]` при `i = 0`.
4. **Безопасная таблица** — обращения к прямоугольной таблице с проверкой каждой координаты.

## Итоги

- C не проверяет индексы: `a[i]` вычисляет адрес, каким бы ни было `i`; чтение за границей так же опасно, как запись.
- Без инструментов выход за границу часто даёт «правильный» результат — до первого изменения окружения.
- Допустимые индексы массива из `N` элементов — `[0, N)`; при обращении к `a[i + 1]` цикл идёт до `i + 1 < N`.
- Индексы из внешних данных проверяют с обеих сторон.
- ASan находит выход за любой объект (куча, стек, глобальные), UBSan — индекс за пределами типа массива; выход за логическую длину внутри блока находят только проверки в коде.
