## Необязательные параметры

Часто у параметра функции есть «обычное» значение, которое нужно почти всегда: разделитель — запятая, точность — два знака, символ рамки — звёздочка. В C пришлось бы либо передавать его при каждом вызове, либо писать несколько функций. В C++ параметру можно задать **значение по умолчанию**:

```cpp
#include <iostream>

void line(char symbol = '-', int length = 10) {
    for (int i = 0; i < length; i++) {
        std::cout << symbol;
    }
    std::cout << '\n';
}

int main() {
    line();              // line('-', 10)
    line('=');           // line('=', 10)
    line('*', 3);
    return 0;
}
```

Вывод:

```text
----------
==========
***
```

Если аргумент при вызове не указан, компилятор подставляет значение по умолчанию. Подстановка происходит **в месте вызова**, при компиляции: `line()` превращается в `line('-', 10)`.

## Правила

**Значения по умолчанию задаются справа налево.** Если у параметра есть значение по умолчанию, оно должно быть и у всех параметров правее. И аргументы при вызове опускаются только с конца: нельзя указать `length`, пропустив `symbol`.

```cpp
void ok(int a, int b = 2, int c = 3);     // правильно
void bad(int a = 1, int b, int c = 3);    // ошибка: у b нет значения, а у a есть
```

**Значение по умолчанию пишут один раз — в объявлении.** Если функция объявлена в заголовке, а определена в `.cpp`-файле, значение указывают в заголовке, где его видят все вызывающие. Повторить его в определении нельзя — это ошибка компиляции, даже если значения совпадают.

```cpp
#include <iostream>

int percent(int part, int whole = 100);         // объявление со значением по умолчанию

int main() {
    std::cout << percent(25) << ' ' << percent(1, 4) << '\n';
    return 0;
}

int percent(int part, int whole) {              // определение без значения
    return part * 100 / whole;
}
```

Вывод:

```text
25 25
```

## Значения по умолчанию или перегрузка

Значение по умолчанию — короткий способ написать несколько перегрузок с одинаковой логикой. `void line(char symbol = '-', int length = 10)` ведёт себя как три функции: `line()`, `line(char)`, `line(char, int)`.

Выбирайте так:

- **значения по умолчанию** — когда поведение одно и то же, а меняется только параметр;
- **перегрузка** — когда для разных типов или наборов параметров нужна разная логика.

Смешивать их нужно осторожно: перегрузка `line(char)` рядом с `line(char = '-', int = 10)` делает вызов `line('=')` неоднозначным.

## Полезные примеры

Типичная функция с параметром по умолчанию — склеивание строк с разделителем:

```cpp
#include <iostream>
#include <string>
#include <vector>

std::string join(const std::vector<std::string> &parts, const std::string &sep = ", ") {
    std::string result;
    for (std::size_t i = 0; i < parts.size(); i++) {
        if (i > 0) {
            result += sep;
        }
        result += parts[i];
    }
    return result;
}

int main() {
    std::vector<std::string> langs = {"C", "C++", "Rust"};
    std::cout << join(langs) << '\n';
    std::cout << join(langs, " / ") << '\n';
    std::cout << '[' << join({}) << "]\n";
    return 0;
}
```

Вывод:

```text
C, C++, Rust
C / C++ / Rust
[]
```

Значение по умолчанию может быть любым выражением, в том числе объектом: `const std::string &sep = ", "` создаёт временную строку при каждом вызове без второго аргумента. `join({})` передаёт пустой вектор, записанный фигурными скобками.

## Ловушка: непонятные вызовы

Значения по умолчанию у логических параметров быстро делают вызовы нечитаемыми:

```cpp
void save(const std::string &file, bool compress = false, bool overwrite = true);

save("a.txt", true);        // сжать? перезаписать? нужно смотреть объявление
save("b.txt", false, false);
```

По вызову `save("a.txt", true)` невозможно понять, что означает `true`. Лучше использовать перечисление с понятными именами — `enum class` из следующего урока — или отдельные функции.

<Concept title="Аргументы по умолчанию">

Параметру можно задать значение, которое компилятор подставит, если аргумент не указан. Значения задаются справа налево, аргументы опускаются только с конца. Значение пишут один раз — в объявлении функции, обычно в заголовке. Значения по умолчанию заменяют перегрузки с одинаковой логикой; для разной логики нужна перегрузка.

</Concept>

## Частые ошибки

<CommonMistake title="Значение и в объявлении, и в определении">

```cpp
int percent(int part, int whole = 100);
int percent(int part, int whole = 100) { … }   // ошибка: default argument given twice
```

Оставьте значение только в объявлении.

</CommonMistake>

<CommonMistake title="Пропуск аргумента в середине">

`line(, 5)` — не C++. Чтобы указать второй аргумент, нужно указать и первый: `line('-', 5)`. Если такие вызовы частые, поменяйте порядок параметров или сделайте перегрузку.

</CommonMistake>

<CommonMistake title="Значение по умолчанию и перегрузка с тем же числом аргументов">

`void f(int a, int b = 0)` и `void f(int a)` — вызов `f(1)` неоднозначен. Используйте что-то одно.

</CommonMistake>

## Практика

1. **Склеивание** — разделитель по умолчанию.
2. **Округление** — необязательная точность.
3. **Найди ошибку: полоса загрузки** — значение по умолчанию дважды.
4. **Рамка** — несколько параметров по умолчанию.

## Итоги

- Параметру можно задать значение по умолчанию; компилятор подставит его в месте вызова.
- Значения по умолчанию — справа налево; аргументы опускаются только с конца.
- Значение пишут один раз — в объявлении функции.
- Одинаковая логика с разными наборами аргументов — значения по умолчанию; разная логика — перегрузка.
- Несколько логических параметров по умолчанию делают вызовы нечитаемыми.
