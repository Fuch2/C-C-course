## Пара «указатель и длина»

В C функция, которая работает с массивом, получает два параметра: адрес первого элемента и количество — `int sum(const int *a, size_t n)`. Компилятор не знает, что они связаны. Перепутали длину, передали размер другого массива, забыли поправить его после изменения кода — и функция читает чужую память.

В C++ для массивов есть `std::array` и `std::vector`, но писать функцию отдельно для каждого контейнера неудобно, а принимать `const std::vector<int> &` — значит отказаться от массивов и `std::array`. Решение из C++20 — `std::span` из `<span>`: **представление непрерывной последовательности** элементов. Как и `std::string_view` для строк, это указатель и длина в одном объекте, без владения элементами.

## Одна функция для любых массивов

```cpp
#include <array>
#include <print>
#include <span>
#include <vector>

int sum(std::span<const int> values) {
    int total = 0;
    for (int x : values) {
        total += x;
    }
    return total;
}

int main() {
    int raw[] = {1, 2, 3, 4};
    std::array<int, 3> fixed = {10, 20, 30};
    std::vector<int> dynamic = {5, 6, 7, 8, 9};
    std::println("{} {} {}", sum(raw), sum(fixed), sum(dynamic));
    std::println("{}", sizeof(std::span<int>));
    return 0;
}
```

Вывод:

```text
10 60 35
16
```

`std::span` создаётся из массива C, `std::array` и `std::vector` — элементы не копируются, запоминаются только адрес и размер. Поэтому `std::span` передают **по значению**: сам объект — 16 байт. Размер всегда идёт вместе с адресом, и рассогласовать их нельзя.

`std::span<const int>` — представление «только для чтения»: изменить элементы через него нельзя. Это аналог `const int *` в C, и для функций, которые только читают, правильный выбор именно такой.

## Изменение элементов

Без `const` представление разрешает менять элементы — и меняются они в исходном контейнере:

```cpp
#include <print>
#include <span>
#include <vector>

void scale(std::span<int> values, int factor) {
    for (int &x : values) {
        x *= factor;
    }
}

int main() {
    std::vector<int> prices = {100, 250, 80};
    int counts[] = {1, 2, 3};
    scale(prices, 2);
    scale(counts, 10);
    std::println("{} {} {}", prices[0], prices[1], prices[2]);
    std::println("{} {} {}", counts[0], counts[1], counts[2]);
    return 0;
}
```

Вывод:

```text
200 500 160
10 20 30
```

Функция не знает, массив перед ней или вектор, — она работает с последовательностью элементов. А вот изменить **размер** через `std::span` нельзя: у представления нет `push_back`.

## Части последовательности

Срезы создаются за постоянное время и тоже ничего не копируют:

| Вызов               | Что возвращает                         |
| ------------------- | -------------------------------------- |
| `s.first(n)`        | первые `n` элементов                   |
| `s.last(n)`         | последние `n` элементов                |
| `s.subspan(pos, n)` | `n` элементов, начиная с позиции `pos` |
| `s.subspan(pos)`    | все элементы, начиная с позиции `pos`  |

```cpp
#include <print>
#include <span>
#include <vector>

int sum(std::span<const int> values) {
    int total = 0;
    for (int x : values) {
        total += x;
    }
    return total;
}

int main() {
    std::vector<int> data = {5, 6, 7, 8, 9};
    std::span<int> all = data;
    std::println("{} {} {}", sum(all.first(2)), sum(all.last(2)), sum(all.subspan(1, 3)));
    for (int &x : all.subspan(3)) {
        x = 0;
    }
    std::println("{} {} {} {} {}", data[0], data[1], data[2], data[3], data[4]);
    return 0;
}
```

Вывод:

```text
11 17 21
5 6 7 0 0
```

`subspan(3)` смотрит на последние два элемента вектора, и запись через него меняет сам вектор. Срезы удобны в алгоритмах «разделяй и властвуй»: функция сортировки слиянием может принимать `std::span` и вызывать себя для `first(n / 2)` и `subspan(n / 2)` — без пар индексов.

## Фиксированный размер

Если длина известна при компиляции, её можно записать в тип: `std::span<const int, 3>`. Такое представление создаётся только из последовательности ровно такой длины — `std::array<int, 3>` или `int[3]`, и размер проверяет компилятор. По умолчанию размер динамический, и он хранится в объекте.

```cpp
#include <array>
#include <print>
#include <span>

double length(std::span<const double, 3> v) {
    return v[0] * v[0] + v[1] * v[1] + v[2] * v[2];
}

int main() {
    std::array<double, 3> point = {1.0, 2.0, 2.0};
    std::println("{} {}", length(point), std::span(point).size_bytes());
    return 0;
}
```

Вывод:

```text
9 24
```

`size_bytes()` — размер просматриваемой памяти в байтах: три `double` по 8 байт.

## Границы не проверяются

`s[i]` у `std::span`, как у массива и у `operator[]` вектора, **не проверяет** индекс: выход за границу — неопределённое поведение. AddressSanitizer такую ошибку найдёт (`heap-buffer-overflow`), а в обычной сборке программа прочитает чужую память.

В стандартных библиотеках есть «усиленный» режим, который превращает такую ошибку в немедленную остановку программы. В libstdc++ (GCC) его включает макрос `-D_GLIBCXX_ASSERTIONS`, в libc++ (Clang) — `-D_LIBCPP_HARDENING_MODE=_LIBCPP_HARDENING_MODE_FAST`. Проверки почти не влияют на скорость, поэтому многие дистрибутивы Linux и крупные проекты собирают с ними даже выпускаемые программы. C++26 закрепляет такой режим в стандарте и добавляет `std::span` проверяющий метод `at()`.

## Представление не владеет

Как и `std::string_view`, `std::span` не продлевает жизнь элементам. Самая коварная ловушка — вектор, который вырос после того, как на него создали представление:

```cpp
#include <print>
#include <span>
#include <vector>

int main() {
    std::vector<int> values = {1, 2, 3};
    std::span<const int> view = values;
    for (int i = 0; i < 100; i++) {
        values.push_back(i);              // вектор переезжает в новую память
    }
    std::println("{}", view[0]);          // Ошибка памяти
    return 0;
}
```

При росте вектор выделяет новый блок, переносит элементы и освобождает старый — а `view` по-прежнему указывает на старый. AddressSanitizer сообщает `heap-use-after-free`. Та же история с `std::span` на временный вектор: `std::span<const int> s = make_vector();` висит сразу после этой строки.

Правило то же, что для `string_view`: `std::span` — для **параметров функций** и коротких локальных срезов, пока контейнер не меняет размер.

## span, ссылка на контейнер или string_view

| Параметр функции     | Когда использовать                                        |
| -------------------- | --------------------------------------------------------- |
| `std::span<const T>` | читать последовательность элементов любого происхождения  |
| `std::span<T>`       | менять элементы, не меняя их количество                   |
| `std::vector<T> &`   | менять размер: добавлять и удалять элементы               |
| `std::string_view`   | читать текст (у него есть `find`, `starts_with` и другие) |

<Concept title="std::span">

Невладеющее представление непрерывной последовательности: указатель и количество элементов. Создаётся из массива C, `std::array` и `std::vector` без копирования; `first`, `last` и `subspan` дают срезы. `std::span<const T>` — только чтение. Индекс не проверяется; представление «висит», если контейнер уничтожен или перевыделил память.

</Concept>

## Частые ошибки

<CommonMistake title="span без const для функции, которая только читает">

`int sum(std::span<int> v)` не примет `const std::vector<int>` и разрешает случайно изменить элементы. Для чтения — `std::span<const int>`.

</CommonMistake>

<CommonMistake title="span на вектор, который потом растёт">

`push_back`, `insert`, `resize` могут перевыделить память вектора, и все представления на него становятся недействительными. Создавайте `span` после того, как размер перестал меняться.

</CommonMistake>

<CommonMistake title="Параметр std::span<int, 5> вместо динамического">

Фиксированный размер в параметре запрещает передать вектор: его длина неизвестна при компиляции. Если функция должна работать с последовательностями любой длины, пишите `std::span<const int>`.

</CommonMistake>

## Итоги

- `std::span<T>` (C++20) — указатель и длина в одном объекте; создаётся из массива C, `std::array` и `std::vector` без копирования и передаётся по значению.
- `std::span<const T>` — только чтение, `std::span<T>` — можно менять элементы, но не их количество.
- `first`, `last`, `subspan` — срезы без копирования; `size_bytes` — размер в байтах; `std::span<T, N>` — размер в типе.
- `[]` не проверяет границы; усиленный режим библиотеки (`-D_GLIBCXX_ASSERTIONS`) и санитайзеры ловят выход за массив.
- Представление не владеет элементами: оно висит после уничтожения контейнера или перевыделения памяти вектора.
