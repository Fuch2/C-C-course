## Чем плохи перечисления C

Перечисление в C — набор именованных целых констант:

```c
enum Color { RED, GREEN, BLUE };
enum Fruit { APPLE, ORANGE };
```

У такого перечисления три проблемы. **Имена попадают в окружающую область видимости**: второе перечисление с именем `RED` (например, `enum Alert { RED, YELLOW }`) не скомпилируется, поэтому библиотеки пишут префиксы — `COLOR_RED`. **Значения неявно превращаются в `int`**: `int x = BLUE + 1;` компилируется. **Можно сравнивать несравнимое**: `RED == APPLE` истинно — оба равны 0.

## enum class

C++11 добавил **перечисления с областью видимости** — `enum class`:

```cpp
#include <iostream>

enum class Color { Red, Green, Blue };
enum class Alert { Red, Yellow };        // своё Red — конфликта нет

int main() {
    Color c = Color::Green;
    Alert a = Alert::Red;
    if (c == Color::Green) {
        std::cout << "зелёный\n";
    }
    std::cout << static_cast<int>(c) << ' ' << static_cast<int>(a) << '\n';
    return 0;
}
```

Вывод:

```text
зелёный
1 0
```

- Имена живут **внутри** перечисления: `Color::Red` и `Alert::Red` — разные, префиксы не нужны.
- **Нет неявного превращения в `int`**: `int x = c;` не компилируется. Если число действительно нужно, его получают явно — `static_cast<int>(c)`.
- **Нельзя сравнить разные перечисления**: `c == a` — ошибка компиляции. Компилятор ловит путаницу, которую C пропускал.

Значения нумеруются с нуля, как в C, но их можно задать явно: `enum class Code { Ok = 200, NotFound = 404 };`.

## Тип, на котором построено перечисление

По умолчанию `enum class` хранится как `int`. Если перечисление попадает в файл или пакет сети, удобнее задать размер явно:

```cpp
#include <cstdint>
#include <iostream>

enum class Status : std::uint8_t { Idle, Busy, Error = 255 };

int main() {
    Status s = Status::Error;
    std::cout << sizeof(Status) << ' ' << static_cast<int>(s) << '\n';
    return 0;
}
```

Вывод:

```text
1 255
```

## switch по перечислению

Перечисление и `switch` хорошо работают вместе — а компилятор помогает не забыть вариант. С флагом `-Wall` GCC и Clang предупреждают, если в `switch` по перечислению обработаны не все значения и нет `default`. Добавили в перечисление новое значение — компилятор покажет все места, которые нужно обновить.

```cpp
#include <iostream>
#include <string>

enum class Direction { North, East, South, West };

std::string name(Direction d) {
    switch (d) {
    case Direction::North:
        return "север";
    case Direction::East:
        return "восток";
    case Direction::South:
        return "юг";
    case Direction::West:
        return "запад";
    }
    return "?";
}

Direction turn_right(Direction d) {
    return static_cast<Direction>((static_cast<int>(d) + 1) % 4);
}

int main() {
    Direction d = Direction::West;
    for (int i = 0; i < 3; i++) {
        std::cout << name(d) << ' ';
        d = turn_right(d);
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
запад север восток
```

`return "?"` после `switch` нужен формально: в перечисление можно силой привести любое число, и функция должна что-то вернуть и в этом случае. Поворот по кругу использует то, что значения идут подряд с нуля, — превращение в число и обратно делается явно, и это хорошо: такие места сразу видны.

Перечисление печатается не само: у `std::cout` нет оператора `<<` для своих перечислений. Обычно пишут функцию вроде `name`, которая превращает значение в строку.

## Перечисление вместо bool

В прошлом уроке вызов `save("a.txt", true, false)` было невозможно прочитать. Перечисления делают такие вызовы понятными:

```cpp
#include <iostream>
#include <string>

enum class Compression { None, Zip };
enum class Mode { Append, Overwrite };

void save(const std::string &file, Compression c, Mode m) {
    std::cout << file << ": " << (c == Compression::Zip ? "сжать" : "без сжатия") << ", "
              << (m == Mode::Overwrite ? "перезаписать" : "дописать") << '\n';
}

int main() {
    save("log.txt", Compression::None, Mode::Append);
    save("backup.bin", Compression::Zip, Mode::Overwrite);
    return 0;
}
```

Вывод:

```text
log.txt: без сжатия, дописать
backup.bin: сжать, перезаписать
```

Теперь вызов объясняет сам себя, а перепутать порядок аргументов не получится: `save("x", Mode::Append, Compression::Zip)` не скомпилируется — типы разные.

## Конечные автоматы

Перечисление — естественный способ описать **состояние** программы: «ждёт», «работает», «ошибка». Программа, которая переходит между состояниями по входным символам, называется **конечным автоматом**. На автоматах построены разбор чисел и текстовых форматов, протоколы связи, управление устройствами. В практике этого урока вы напишете автомат, проверяющий запись числа.

<Concept title="enum class">

Перечисление с областью видимости: имена пишут как `Color::Red`, они не конфликтуют с другими. Значения не превращаются в `int` неявно и не сравниваются со значениями других перечислений — для числа нужен `static_cast`. Можно задать базовый тип: `enum class Status : std::uint8_t`. `switch` по перечислению с `-Wall` предупреждает о забытых вариантах. Перечисления делают вызовы понятнее логических флагов и описывают состояния автоматов.

</Concept>

## Частые ошибки

<CommonMistake title="Забытый break">

```cpp
switch (level) {
case Level::Info:
    text = "info";          // нет break — выполнение «проваливается» дальше
case Level::Warning:
    text = "warning";
    break;
}
```

Без `break` после первой ветки выполнится и следующая, и `Info` превратится в `"warning"`. С `-Wextra` компилятор предупреждает о проваливании. Возвращайте значение через `return` прямо из ветки или ставьте `break` в каждой.

</CommonMistake>

<CommonMistake title="Печать перечисления">

`std::cout << Color::Red;` не компилируется. Напишите функцию, превращающую значение в строку, или приведите к `int`, если нужно число.

</CommonMistake>

<CommonMistake title="Число из ввода прямо в перечисление">

`static_cast<Color>(user_number)` для числа 7 создаст значение, которого нет среди вариантов. Проверяйте диапазон перед приведением.

</CommonMistake>

## Практика

1. **Светофор** — переходы между значениями перечисления.
2. **Робот** — направление как перечисление.
3. **Найди ошибку: уровни журнала** — проваливание в `switch`.
4. **Автомат для чисел** — конечный автомат на `enum class`.

## Итоги

- Перечисления C загрязняют область видимости, превращаются в `int` и сравниваются друг с другом.
- `enum class` решает все три проблемы: `Color::Red`, нет неявных преобразований, разные перечисления несравнимы.
- Число из перечисления — `static_cast<int>(x)`; перечисление из числа — `static_cast<E>(n)` с проверкой.
- Базовый тип задают явно: `enum class E : std::uint8_t`.
- `switch` по перечислению с `-Wall` находит забытые варианты; не забывайте `break` или используйте `return`.
- Перечисления делают вызовы понятными и описывают состояния автоматов.
