## Второе имя для переменной

В C, чтобы функция изменила переменную вызывающего, передают указатель: `void inc(int *p) { (*p)++; }` и вызов `inc(&x)`. Указатель приходится разыменовывать, при вызове не забыть `&`, а внутри функции — помнить, что указатель может оказаться `NULL`.

В C++ для этого есть **ссылки**. Ссылка — это второе имя уже существующей переменной:

```cpp
#include <iostream>

int main() {
    int x = 10;
    int &r = x;              // r — другое имя для x
    r += 5;
    std::cout << x << ' ' << r << '\n';
    std::cout << (&r == &x) << '\n';
    return 0;
}
```

Вывод:

```text
15 15
1
```

`int &r = x` объявляет ссылку на `int`. Всё, что делается с `r`, делается с `x`: у них один и тот же адрес. В отличие от указателя, ссылка не хранит «отдельное значение» — её не нужно разыменовывать звёздочкой.

## Три правила ссылок

1. **Ссылка всегда инициализируется** при объявлении: `int &r;` без инициализатора не компилируется.
2. **Ссылку нельзя перенаправить.** `r = y;` не делает `r` ссылкой на `y` — это присваивание значения `y` переменной `x`.
3. **Нулевых ссылок не бывает.** Ссылка всегда связана с объектом.

```cpp
#include <iostream>

int main() {
    int x = 1, y = 2;
    int &r = x;
    r = y;                   // присвоить x значение y, а не перенаправить r
    y = 100;
    std::cout << x << ' ' << y << ' ' << r << '\n';
    return 0;
}
```

Вывод:

```text
2 100 2
```

Благодаря этим правилам ссылка проще указателя: проверять её на `NULL` не нужно, а случайно «перенаправить» не получится.

## Параметры-ссылки

Главное применение ссылок — параметры функций. Сравните обмен значений на C и на C++:

```cpp
#include <iostream>

void swap_values(int &a, int &b) {
    int tmp = a;
    a = b;
    b = tmp;
}

int main() {
    int x = 3, y = 7;
    swap_values(x, y);       // без &: ссылки создаются автоматически
    std::cout << x << ' ' << y << '\n';
    return 0;
}
```

Вывод:

```text
7 3
```

При вызове `swap_values(x, y)` параметр `a` становится вторым именем `x`, а `b` — вторым именем `y`. Функция меняет сами переменные вызывающего. В C это была бы `swap(&x, &y)` с разыменованиями внутри.

У такого удобства есть цена: по вызову `swap_values(x, y)` не видно, что функция меняет аргументы. Поэтому в C++ принято, что параметр-ссылка без `const` означает «функция изменит этот аргумент», и такие функции называют так, чтобы это было понятно.

Ссылкой удобно возвращать **несколько результатов**:

```cpp
#include <iostream>
#include <string>

bool split_time(const std::string &text, int &hours, int &minutes) {
    if (text.size() != 5 || text[2] != ':') {
        return false;
    }
    hours = (text[0] - '0') * 10 + (text[1] - '0');
    minutes = (text[3] - '0') * 10 + (text[4] - '0');
    return true;
}

int main() {
    int h, m;
    if (split_time("09:45", h, m)) {
        std::cout << h << " ч " << m << " мин\n";
    }
    std::cout << split_time("945", h, m) << '\n';
    return 0;
}
```

Вывод:

```text
9 ч 45 мин
0
```

`const std::string &` — константная ссылка: функция получает строку без копирования и обещает её не менять. Это тема следующего урока.

## Ссылки на элементы контейнеров

Ссылка может указывать на элемент массива или строки — это удобно, чтобы не писать длинное выражение несколько раз:

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> scores = {70, 85, 90};
    int &last = scores[scores.size() - 1];
    last += 5;
    std::cout << scores[2] << '\n';
    for (int &s : scores) {           // ссылка на каждый элемент по очереди
        s += 1;
    }
    std::cout << scores[0] << ' ' << scores[1] << ' ' << scores[2] << '\n';
    return 0;
}
```

Вывод:

```text
95
71 86 96
```

Цикл `for (int &s : scores)` проходит по элементам, и `s` на каждом шаге — ссылка на очередной элемент, поэтому изменения попадают в вектор. Без `&` переменная `s` была бы копией. Подробно этот цикл разобран в отдельном уроке.

## Висячие ссылки

Ссылка не продлевает жизнь объекту. Если объект перестал существовать, ссылка на него становится **висячей**, и обращение к ней — неопределённое поведение. Самая частая ситуация — ссылка на элемент вектора, который потом вырос:

```cpp
#include <iostream>
#include <vector>

int main() {
    std::vector<int> values = {1, 2};
    int &first = values[0];
    values.push_back(3);                // может перенести элементы в новый блок
    values.push_back(4);
    std::cout << first << '\n';         // Ошибка памяти
    return 0;
}
```

AddressSanitizer сообщает `heap-use-after-free`: при росте вектор выделил новый блок, перенёс элементы и освободил старый, а `first` по-прежнему ссылается в старый. Это ровно та же ошибка, что с указателем на элемент динамического массива после `realloc`. Правило то же: не держите ссылки и указатели на элементы вектора, пока в него добавляют элементы, — храните индекс.

Вторая классическая ошибка — вернуть ссылку на локальную переменную:

```cpp
int &bad() {
    int local = 42;
    return local;            // local исчезнет при выходе из функции
}
```

GCC предупреждает: `reference to local variable 'local' returned`. Возвращать ссылку можно только на то, что переживёт функцию: на элемент переданного по ссылке контейнера, на глобальный или статический объект.

## Ссылка или указатель

|                     | Ссылка           | Указатель        |
| ------------------- | ---------------- | ---------------- |
| может быть пустой   | нет              | да, `nullptr`    |
| можно перенаправить | нет              | да               |
| синтаксис доступа   | как к переменной | `*p`, `p->field` |
| арифметика          | нет              | да               |

Используйте ссылку, когда объект обязательно есть и не меняется; указатель — когда объекта может не быть или его нужно менять по ходу работы (например, при обходе списка).

<Concept title="Ссылка">

Ссылка `T &r = x` — второе имя объекта `x`: тот же адрес, та же память. Она инициализируется при объявлении, не перенаправляется и не бывает пустой. Параметр-ссылка позволяет функции менять аргумент без указателей и возвращать несколько результатов. Ссылка не продлевает жизнь объекта: ссылка на элемент вектора после роста и на локальную переменную после возврата — висячие.

</Concept>

## Частые ошибки

<CommonMistake title="«Перенаправление» ссылки">

`r = y;` не делает `r` ссылкой на `y`, а копирует значение `y` в объект, на который `r` ссылается. Если нужна переменная, которая указывает то на одно, то на другое, — это указатель.

</CommonMistake>

<CommonMistake title="Ссылка на элемент растущего вектора">

`int &x = v[0]; v.push_back(…);` — после роста `x` висит. AddressSanitizer поймает это как `heap-use-after-free`. Храните индекс и обращайтесь `v[i]` после каждой вставки.

</CommonMistake>

<CommonMistake title="Ссылка на временное значение">

`int &r = 5;` не компилируется: неконстантную ссылку нельзя связать с временным значением. (С константной — можно, об этом в следующем уроке.)

</CommonMistake>

## Практика

1. **Три числа по порядку** — функция, меняющая аргументы.
2. **Время из строки** — несколько результатов через ссылки.
3. **Найди ошибку: ссылка на первый элемент** — висячая ссылка.
4. **Таблица по ссылке** — функция, возвращающая ссылку на ячейку.

## Итоги

- Ссылка — второе имя объекта; объявляется `T &r = x` и всегда инициализируется.
- Ссылку нельзя перенаправить, и она не бывает пустой.
- Параметр-ссылка позволяет функции менять аргумент: `void swap_values(int &a, int &b)`.
- Ссылками удобно возвращать несколько результатов.
- `for (T &x : v)` изменяет элементы контейнера.
- Ссылка не продлевает жизнь объекту: после роста вектора ссылки на его элементы висят.
