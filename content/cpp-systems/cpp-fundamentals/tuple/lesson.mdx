## Больше двух значений

`std::pair` хранит ровно два значения. `std::tuple` из `<tuple>` — **кортеж** — хранит сколько угодно значений любых типов:

```cpp
#include <iostream>
#include <string>
#include <tuple>

int main() {
    std::tuple<std::string, int, double> record{"Ада", 36, 1.65};
    std::cout << std::get<0>(record) << ' ' << std::get<1>(record) << ' ' << std::get<2>(record) << '\n';
    std::get<1>(record) += 1;
    auto point = std::make_tuple(1, 2, 3);           // std::tuple<int, int, int>
    std::cout << std::get<1>(record) << ' ' << std::get<0>(point) + std::get<2>(point) << '\n';
    std::cout << std::get<std::string>(record) << '\n';
    return 0;
}
```

Вывод:

```text
Ада 36 1.65
37 4
Ада
```

У кортежа нет полей с именами — элементы достают функцией `std::get<N>(t)`, где `N` — номер элемента, известный при компиляции. Если тип в кортеже встречается один раз, можно достать и по типу: `std::get<std::string>(record)`.

## Структурные привязки и std::tie

`std::get<2>(t)` читается плохо. Как и с парой, кортеж удобно разложить структурной привязкой:

```cpp
#include <iostream>
#include <tuple>
#include <vector>

std::tuple<int, int, long long> stats(const std::vector<int> &v) {
    int lo = v[0], hi = v[0];
    long long sum = 0;
    for (int x : v) {
        lo = x < lo ? x : lo;
        hi = x > hi ? x : hi;
        sum += x;
    }
    return {lo, hi, sum};
}

int main() {
    std::vector<int> v = {4, -2, 9, 1};
    auto [lo, hi, sum] = stats(v);
    std::cout << lo << ' ' << hi << ' ' << sum << '\n';

    int a, b;
    long long c;
    std::tie(a, b, c) = stats({5, 5});         // разложить в уже существующие переменные
    std::cout << a << ' ' << b << ' ' << c << '\n';
    int only_max;
    std::tie(std::ignore, only_max, std::ignore) = stats(v);
    std::cout << only_max << '\n';
    return 0;
}
```

Вывод:

```text
-2 9 12
5 5 10
9
```

- Структурная привязка `auto [lo, hi, sum]` создаёт **новые** переменные.
- `std::tie(a, b, c) = …` присваивает элементы кортежа **уже существующим** переменным: `std::tie` собирает из них кортеж ссылок.
- `std::ignore` пропускает ненужный элемент.

Имена при распаковке связываются с элементами **по порядку**, а не по смыслу. Если функция возвращает `(min, max, sum)`, а распаковать как `auto [lo, sum, hi]`, переменная `sum` получит максимум — и компилятор не заметит: типы совпадают.

## Сравнение по нескольким ключам

Кортежи сравниваются лексикографически, как пары: по первому элементу, при равенстве — по второму и так далее. Это главный практический приём с кортежами — **функция сравнения по нескольким ключам в одну строку**:

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <tuple>
#include <vector>

struct Player {
    std::string name;
    int score;
    int time;
};

int main() {
    std::vector<Player> players = {{"Cid", 10, 50}, {"Ann", 12, 70}, {"Bob", 10, 40}, {"Dan", 10, 40}};
    std::sort(players.begin(), players.end(), [](const Player &a, const Player &b) {
        return std::make_tuple(-a.score, a.time, a.name) < std::make_tuple(-b.score, b.time, b.name);
    });
    for (const auto &p : players) {
        std::cout << p.name << ' ' << p.score << ' ' << p.time << '\n';
    }
    return 0;
}
```

Вывод:

```text
Ann 12 70
Bob 10 40
Dan 10 40
Cid 10 50
```

Порядок: больше очков (минус превращает возрастание в убывание), затем меньше время, затем имя по алфавиту. Сравните с цепочкой `if` из урока о лямбдах: смысл тот же, но правило читается сразу. Для полей, которые нельзя «перевернуть» минусом (строки), меняют местами `a` и `b` у этого поля: `std::make_tuple(a.score, b.name) < std::make_tuple(b.score, a.name)`.

`std::tie(a.x, a.y) < std::tie(b.x, b.y)` делает то же, что `make_tuple`, но без копирования полей — кортеж из ссылок. Минус к `std::tie` применить нельзя: он связывает только существующие переменные.

## tuple или struct

Кортеж удобен, когда группа значений живёт недолго: функция вернула несколько результатов, и их сразу распаковали; ключ сортировки собран на одну строку. Для данных, которые хранятся и передаются по программе, лучше **структура**: `player.score` понятнее, чем `std::get<1>(player)`, а добавление поля не сдвигает номера остальных.

<Concept title="std::tuple">

Кортеж хранит фиксированное число значений разных типов; элементы достают `std::get<N>` или структурной привязкой по порядку. `std::tie` собирает кортеж ссылок — для распаковки в существующие переменные и для сравнения без копий; `std::ignore` пропускает элемент. Кортежи сравниваются лексикографически, что даёт короткие функции сравнения по нескольким ключам. Для долгоживущих данных с именованными полями лучше структура.

</Concept>

## Частые ошибки

<CommonMistake title="Распаковка не в том порядке">

`auto [lo, sum, hi] = stats(v);` при возврате `(min, max, sum)` молча кладёт максимум в `sum`. Порядок распаковки должен совпадать с порядком элементов; если элементов много и их легко перепутать — верните структуру с именами.

</CommonMistake>

<CommonMistake title="Номер элемента в переменной">

`std::get<i>(t)` с переменной `i` не компилируется: номер должен быть известен при компиляции. Кортеж — не массив; перебирать его элементы циклом нельзя.

</CommonMistake>

<CommonMistake title="Минус в std::tie">

`std::tie(-a.score, a.name)` не компилируется: `std::tie` принимает только переменные. Для выражений используйте `std::make_tuple`.

</CommonMistake>

## Практика

1. **Дата в ISO** — функция возвращает кортеж.
2. **Сортировка по ключам** — `std::make_tuple` в функции сравнения.
3. **Найди ошибку: статистика** — распаковка не в том порядке.
4. **Расписание** — сортировка событий и поиск пересечений.

## Итоги

- `std::tuple` хранит фиксированное число значений разных типов.
- Элементы — `std::get<N>(t)`, по типу — `std::get<T>(t)`, удобнее — структурной привязкой.
- `std::tie` распаковывает в существующие переменные и сравнивает без копий; `std::ignore` пропускает элемент.
- Кортежи сравниваются лексикографически: функция сравнения по нескольким ключам пишется в одну строку.
- Порядок распаковки должен совпадать с порядком элементов.
- Для долгоживущих данных лучше структура с именами полей.
