## Цена передачи по значению

Параметр функции по умолчанию — **копия** аргумента. Для `int` это ничего не стоит, а для `std::string` или `std::vector` — копирование всех символов или элементов, с выделением памяти. Функция, которая просто считает символы в строке из мегабайта, при каждом вызове скопирует мегабайт.

```cpp
#include <iostream>
#include <string>

void by_value(std::string s, const char *original) {
    std::cout << "по значению: тот же буфер? " << (s.data() == original) << '\n';
}

void by_reference(const std::string &s, const char *original) {
    std::cout << "по ссылке: тот же буфер? " << (s.data() == original) << '\n';
}

int main() {
    std::string text(1000000, 'x');            // миллион символов
    by_value(text, text.data());
    by_reference(text, text.data());
    return 0;
}
```

Вывод:

```text
по значению: тот же буфер? 0
по ссылке: тот же буфер? 1
```

При вызове `by_value` создаётся новая строка-копия со своим буфером на миллион байт; при вызове `by_reference` — ничего: `s` — второе имя для `text`.

## const T& — посмотреть, но не трогать

Обычная ссылка `std::string &` позволила бы функции изменить строку вызывающего — а функции, которая только читает, это право не нужно. Поэтому для входных параметров используют **константную ссылку** `const std::string &`: передача без копирования и обещание не изменять.

```cpp
#include <iostream>
#include <string>

int count_char(const std::string &text, char c) {
    int count = 0;
    for (char x : text) {
        if (x == c) {
            count++;
        }
    }
    // text[0] = '!';          // ошибка компиляции: text — константа
    return count;
}

int main() {
    std::string s = "banana";
    std::cout << count_char(s, 'a') << ' ' << count_char("abracadabra", 'a') << '\n';
    return 0;
}
```

Вывод:

```text
3 5
```

Компилятор следит за обещанием: попытка изменить `text` внутри функции — ошибка компиляции. А по сигнатуре `int count_char(const std::string &, char)` сразу видно, что функция строку не меняет.

## Константная ссылка принимает временные значения

Обратите внимание на второй вызов: `count_char("abracadabra", 'a')`. Аргумент — строковый литерал, а не `std::string`. Компилятор создаёт **временную** строку и связывает с ней параметр. С обычной ссылкой так нельзя:

```cpp
#include <string>

int length(std::string &s) {
    return static_cast<int>(s.size());
}

int main() {
    std::string a = "hello";
    return length(a + " world");     // Ошибка компиляции
}
```

Компилятор: `cannot bind non-const lvalue reference of type 'std::string&' to an rvalue of type 'std::string'`. Логика простая: если функция может изменить аргумент, а аргумент — временное значение, которое исчезнет после вызова, то изменение бессмысленно и скорее всего означает ошибку. Константная ссылка с временными значениями связывается: результат `a + " world"`, литерал, возвращённая функцией строка — всё подходит.

## Константы вообще

`const` работает не только в параметрах. Константная переменная должна быть инициализирована и не меняется:

```cpp
#include <iostream>
#include <vector>

int main() {
    const int limit = 3;
    const std::vector<int> primes = {2, 3, 5, 7};
    // limit = 4;                // ошибка компиляции
    // primes.push_back(11);     // ошибка компиляции: вектор константный
    std::cout << limit * primes[1] << ' ' << primes.size() << '\n';
    return 0;
}
```

Вывод:

```text
9 4
```

У константного вектора можно читать элементы и вызывать «читающие» методы — `size()`, `[]` для чтения, — но нельзя ничего изменить. Компилятор знает, какие методы меняют объект, а какие нет.

Помечать константой всё, что не должно меняться, — хорошая привычка: компилятор поймает случайную запись, а читатель кода сразу видит, какие значения постоянны.

## Как передавать параметры

| Параметр                           | Как передать | Пример                                            |
| ---------------------------------- | ------------ | ------------------------------------------------- |
| маленький, только читается         | по значению  | `int`, `double`, `char`, `bool`, указатель        |
| большой, только читается           | `const T &`  | `const std::string &`, `const std::vector<int> &` |
| функция должна изменить аргумент   | `T &`        | `void sort3(int &a, int &b, int &c)`              |
| функции всё равно нужна своя копия | по значению  | функция меняет строку для себя и возвращает       |

Почему маленькие типы — по значению: ссылка внутри реализована как адрес, и обращение через неё — лишний шаг. Скопировать `int` дешевле, чем передать его адрес.

## Обход контейнера без копий

Цикл по элементам тоже копирует, если не попросить иначе. Для вектора строк `for (std::string s : words)` копирует каждую строку; `for (const std::string &s : words)` — нет:

```cpp
#include <iostream>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> words = {"const", "ссылки", "экономят", "копии"};
    std::size_t total = 0;
    for (const std::string &w : words) {
        total += w.size();
    }
    std::cout << "слов: " << words.size() << ", байт: " << total << '\n';
    return 0;
}
```

Вывод:

```text
слов: 4, байт: 43
```

## Возврат константной ссылки

Функция может вернуть `const T &` на то, что переживёт вызов, — например, на элемент контейнера, переданного по ссылке. Так поиск самой длинной строки не копирует ответ:

```cpp
#include <iostream>
#include <string>
#include <vector>

const std::string &longest(const std::vector<std::string> &words) {
    std::size_t best = 0;
    for (std::size_t i = 1; i < words.size(); i++) {
        if (words[i].size() > words[best].size()) {
            best = i;
        }
    }
    return words[best];
}

int main() {
    std::vector<std::string> words = {"ab", "abcde", "abc"};
    const std::string &w = longest(words);
    std::cout << w << '\n';
    return 0;
}
```

Вывод:

```text
abcde
```

Ссылка `w` действительна, пока жив вектор `words` и пока он не меняется. Вызывать `longest` для пустого вектора нельзя: `words[0]` не существует — проверку оставили вызывающему.

<Concept title="Константная ссылка">

`const T &` передаёт объект без копирования и запрещает его изменять — стандартный способ передать большой объект «на чтение». Константная ссылка связывается и с временными значениями, обычная — нет. Маленькие типы передают по значению, изменяемые аргументы — по `T &`. Цикл `for (const T &x : c)` обходит контейнер без копий.

</Concept>

## Частые ошибки

<CommonMistake title="Большой объект по значению">

`void print(std::vector<std::string> words)` копирует весь вектор и все строки при каждом вызове. Если функция только читает — `const std::vector<std::string> &`.

</CommonMistake>

<CommonMistake title="Неконстантная ссылка там, где хватает константной">

`int length(std::string &s)` нельзя вызвать с литералом или выражением, а читателю кажется, что функция меняет строку. Если не меняет — объявите `const`.

</CommonMistake>

<CommonMistake title="int по константной ссылке">

`void f(const int &x)` работает, но бесполезен: копирование `int` дешевле ссылки. Маленькие типы передают по значению.

</CommonMistake>

1. **Самая длинная строка** — возврат `const` ссылки на элемент.

3. **Найди ошибку: подсчёт символов** — неконстантная ссылка и временное значение.
4. **Сводка по группам** — вектор структур на чтение.

## Итоги

- Передача по значению копирует объект; для строк и контейнеров это дорого.
- `const T &` передаёт без копирования и запрещает изменение — так передают большие входные параметры.
- Константная ссылка связывается с временными значениями, обычная — нет.
- Маленькие типы — по значению, изменяемые аргументы — по `T &`.
- `for (const T &x : c)` обходит контейнер без копий.
- Возвращать `const T &` можно на то, что переживёт вызов.
