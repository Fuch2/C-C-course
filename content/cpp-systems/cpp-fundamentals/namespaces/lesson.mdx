## Проблема одинаковых имён

В большой программе на C все функции живут в одном общем пространстве имён. Если две библиотеки объявят функцию `init` или `parse`, программа не соберётся — линковщик сообщит о повторном определении. Поэтому библиотеки C добавляют к именам префиксы: `sqlite3_open`, `png_read_info`, `SDL_CreateWindow`. Это работает, но имена становятся длинными, а соглашение никто не проверяет.

В C++ для этого есть **пространства имён** (namespaces) — именованные области, внутри которых имена не конфликтуют с именами снаружи.

## Объявление и полные имена

```cpp
#include <iostream>

namespace geometry {
double area(double width, double height) {
    return width * height;
}
}

namespace finance {
double area(double price, double square_meters) {      // то же имя — другой смысл
    return price * square_meters;
}
}

int main() {
    std::cout << geometry::area(3, 4) << '\n';
    std::cout << finance::area(1500, 4) << '\n';
    return 0;
}
```

Вывод:

```text
12
6000
```

Две функции `area` не мешают друг другу: их **полные имена** — `geometry::area` и `finance::area`. Оператор `::` (оператор разрешения области видимости) читается «имя из»: `geometry::area` — «`area` из `geometry`». Код внутри пространства имён обращается к своим именам без префикса.

Пространство имён можно открывать несколько раз, в том числе в разных файлах, — объявления просто добавляются к нему. Так стандартная библиотека раскладывает тысячи имён по десяткам заголовков, и все они оказываются в одном пространстве `std`.

## Пространство std

Всё из стандартной библиотеки C++ лежит в пространстве имён `std`: `std::cout`, `std::string`, `std::vector`, `std::sort`. Поэтому в C++-программах так много `std::`. Это не многословие ради многословия: по префиксу сразу видно, что имя взято из стандартной библиотеки, а не написано в проекте.

## using: короче, но осторожно

Если имя нужно часто, префикс можно опустить двумя способами.

**`using`-объявление** вводит одно имя:

```cpp
#include <iostream>
#include <string>

using std::cout;
using std::string;

int main() {
    string name = "Грейс";
    cout << "Привет, " << name << "!\n";
    return 0;
}
```

Вывод:

```text
Привет, Грейс!
```

**`using`-директива** вводит **все** имена пространства: `using namespace std;`. Это удобно в учебных программах, но опасно: в `std` сотни имён — `count`, `distance`, `size`, `data`, `min`, `max`, `swap`, — и любое из них может столкнуться с вашим. Тогда компилятор сообщит о неоднозначности, а иногда хуже — молча выберет не ту функцию.

```cpp
#include <algorithm>
#include <iostream>
using namespace std;

int count = 0;                           // своя глобальная переменная

int main() {
    count++;                             // Ошибка компиляции
    cout << count << '\n';
    return 0;
}
```

Компилятор: `reference to 'count' is ambiguous` — `count` может означать и переменную, и функцию `std::count` из `<algorithm>`.

Правила, которых придерживаются в профессиональном коде:

- **никогда** не пишите `using namespace` в заголовочных файлах — директива попадёт во все файлы, которые этот заголовок подключат;
- в `.cpp`-файле предпочитайте полные имена или `using`-объявления для отдельных имён;
- `using namespace std;` допустим разве что внутри маленькой функции или в коротком учебном примере.

В этом модуле мы пишем `std::` явно.

## Вложенные пространства и псевдонимы

Пространства имён можно вкладывать друг в друга. С C++17 вложенное пространство объявляют одной строкой:

```cpp
#include <iostream>

namespace company::graphics::colors {
const int red = 0xFF0000;
}

namespace colors = company::graphics::colors;      // псевдоним

int main() {
    std::cout << std::hex << company::graphics::colors::red << ' ' << colors::red << '\n';
    return 0;
}
```

Вывод:

```text
ff0000 ff0000
```

Псевдоним `namespace colors = …` сокращает длинное имя, не открывая всё пространство целиком.

## Безымянное пространство вместо static

В C, чтобы функция была видна только в своём файле, её объявляют `static` (урок о связывании в модуле «Углублённый C»). В C++ для этого принято **безымянное пространство имён**:

```cpp
#include <iostream>

namespace {
int clamp_percent(int value) {           // видна только в этом файле
    return value < 0 ? 0 : value > 100 ? 100 : value;
}
}

int main() {
    std::cout << clamp_percent(-5) << ' ' << clamp_percent(42) << ' ' << clamp_percent(130) << '\n';
    return 0;
}
```

Вывод:

```text
0 42 100
```

Имена из безымянного пространства доступны в своём файле без префикса и имеют внутреннее связывание, как `static`. Удобство в том, что в него можно положить сразу и функции, и переменные, и типы.

Ещё одна мелочь: `::name` с пустой левой частью означает имя из **глобального** пространства. Это пригодится, если локальное имя заслонило глобальное.

<Concept title="Пространство имён">

Именованная область для имён: `geometry::area` и `finance::area` — разные функции. Всё из стандартной библиотеки лежит в `std`. `using`-объявление вводит одно имя, `using`-директива — все и рискует столкновениями; в заголовках её не пишут никогда. Вложенные пространства пишут через `::`, длинные сокращают псевдонимами, а безымянное пространство заменяет `static` для внутренних функций файла.

</Concept>

## Частые ошибки

<CommonMistake title="using namespace std в заголовке">

Директива в заголовке «протекает» во все файлы, которые его подключают, — и их собственные имена начинают конфликтовать с `std`. Автор этих файлов даже не узнает, откуда взялась ошибка.

</CommonMistake>

<CommonMistake title="Своё имя совпало с именем из std">

При `using namespace std;` глобальные имена `count`, `distance`, `size`, `data` становятся неоднозначными. Пишите `std::` явно или давайте своим именам более конкретные названия.

</CommonMistake>

<CommonMistake title="Забытый префикс">

`cout << x;` без `std::` и без `using` даёт ошибку `'cout' was not declared in this scope`. Компилятор обычно сам подсказывает: `suggested alternative: 'std::cout'`.

</CommonMistake>

## Практика

1. **Единицы длины** — функции с одним именем в разных пространствах.
2. **Статистика** — своё пространство имён и безымянные помощники.
3. **Найди ошибку: count** — столкновение с `std`.
4. **Текстовые команды** — вложенные пространства имён.

## Итоги

- Пространства имён защищают имена от столкновений; полное имя — `пространство::имя`.
- Стандартная библиотека C++ целиком лежит в `std`.
- `using std::cout;` вводит одно имя; `using namespace std;` вводит все и рискует столкновениями — в заголовках никогда.
- Вложенные пространства: `a::b::c`; длинные имена сокращают псевдонимами.
- Безымянное пространство делает имена видимыми только в своём файле — замена `static` из C.
