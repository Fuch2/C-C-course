## Теория

vector — плотный растущий массив с отличной locality. Он быстрее списка для обхода, но вставка в середину сдвигает элементы.

## Зачем инструмент нужен

vector — плотный растущий массив с отличной locality. Он быстрее списка для обхода, но вставка в середину сдвигает элементы.

## Пример C++20

```cpp
#include <iostream>
#include <vector>
#include <algorithm>


int main() {
    std::vector<int> v{3,-1,0}; std::erase_if(v,[](int x){return x<0;}); for(int x:v)std::cout<<x<<' '; std::cout<<'\n';
}

```

Ожидаемый вывод:

```text
3 0

```

## Стоимость и ограничения

| Аспект     | Разбор                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Время      | Стоимость определяется размером данных и выбранной операцией; фиксированные операции O(1), обходы O(n), дерево map/set O(log n) в среднем по высоте. |
| Память     | Объекты хранят состояние явно; контейнеры могут выделять память и инвалидировать ссылки при росте.                                                   |
| Компромисс | Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.                       |

## Сравнение с C

Используйте std::vector как стандартный компонент, когда его контракт совпадает с задачей. Проверяйте invalidation, порядок и исключения. Аналог C может дать больше ручного контроля, но требует самостоятельно поддерживать размеры, ошибки и время жизни. В C++ используйте абстракцию по её контракту, а не копируйте C-код в новом синтаксисе.

<CommonMistake title="Типичная ошибка">

Не переносите привычный C-подход автоматически: сначала определите владение, инвариант и стоимость операции.

</CommonMistake>

## Краткое резюме

Инструмент std::vector выражает намерение программы через типы и границы владения. Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.
