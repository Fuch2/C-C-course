## От пар итераторов к диапазонам

Алгоритмы из `<algorithm>` принимают **пару итераторов**: `std::sort(v.begin(), v.end())`. Это гибко — можно отсортировать часть вектора, — но в обычном случае приходится дважды писать имя контейнера, и легко ошибиться: `std::sort(a.begin(), b.end())` компилируется и ломает программу.

C++20 добавил в пространство имён `std::ranges` версии почти всех алгоритмов, которые принимают **диапазон целиком** — любой объект, у которого есть `begin` и `end`: контейнер, массив, `std::span`, `std::string_view`. А C++20 и C++23 добавили **представления** (`std::views`) — ленивые конвейеры обработки данных. Вместе они позволяют писать обработку коллекций короче и с меньшим числом ошибок.

## Алгоритмы `std::ranges`

```cpp
#include <algorithm>
#include <print>
#include <vector>

int main() {
    std::vector<int> v = {5, 3, 8, 1, 9, 2};
    std::ranges::sort(v);
    auto it = std::ranges::find(v, 8);
    std::println("{} {}", v.front(), it - v.begin());
    std::println("{} {}", std::ranges::count_if(v, [](int x) { return x > 4; }),
                 std::ranges::contains(v, 7));
    auto [low, high] = std::ranges::minmax(v);
    std::println("{} {} {}", low, high, std::ranges::fold_left(v, 0, std::plus{}));
    return 0;
}
```

Вывод:

```text
1 4
3 false
1 9 28
```

Имена знакомые — `sort`, `find`, `count_if`, — но аргумент один. Кое-что появилось впервые: `contains` (C++23) отвечает на вопрос «есть ли элемент» без сравнения итераторов, `minmax` возвращает пару значений, а `fold_left` (C++23) — свёртка: начинает с `0` и применяет `std::plus` к каждому элементу, то есть считает сумму. Это современная замена `std::accumulate`.

Ещё одно преимущество — сообщения об ошибках. Алгоритмы `std::ranges` описаны через **концепты** — проверяемые требования к типам. Если передать то, что сортировать нельзя (например, `std::list`, у которого нет произвольного доступа), компилятор скажет, какое требование не выполнено, вместо сотни строк про внутренности шаблонов.

## Проекции: сортировка по полю

Последний необязательный аргумент алгоритмов `std::ranges` — **проекция**: что взять у элемента перед сравнением. Это убирает самую частую причину писать лямбду-компаратор:

```cpp
#include <algorithm>
#include <print>
#include <string>
#include <vector>

struct Student {
    std::string name;
    int score;
};

int main() {
    std::vector<Student> group = {{"Ада", 90}, {"Алан", 75}, {"Грейс", 95}, {"Деннис", 75}};
    std::ranges::sort(group, {}, &Student::score);
    for (const Student &s : group) {
        std::print("{} ", s.name);
    }
    std::println();
    std::ranges::stable_sort(group, std::ranges::greater{}, &Student::score);
    std::println("{} {}", group.front().name, group.back().name);
    auto found = std::ranges::find(group, "Алан", &Student::name);
    std::println("{}", found->score);
    return 0;
}
```

Вывод:

```text
Алан Деннис Ада Грейс
Грейс Деннис
75
```

`&Student::score` — указатель на поле: «бери у каждого студента поле `score`». Второй аргумент — способ сравнения; `{}` означает «по умолчанию», то есть по возрастанию, а `std::ranges::greater{}` — по убыванию. `find` с проекцией ищет студента, **имя** которого равно `"Алан"`. `stable_sort` сохраняет порядок равных элементов: Алан и Деннис с одинаковым баллом остались в прежнем порядке.

Порядок Алана и Денниса после первой, нестабильной `sort` стандарт не гарантирует. Если порядок равных важен — используйте `stable_sort`.

## Представления: ленивые конвейеры

**Представление** (view) — объект, который описывает последовательность, но не хранит её элементы: они вычисляются по одному, когда до них дойдёт цикл. Представления соединяют оператором `|` в конвейер, похожий на конвейеры командной строки:

```cpp
#include <print>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3, 4, 5, 6, 7, 8};
    auto pipeline = v | std::views::filter([](int x) { return x % 2 == 0; })
                      | std::views::transform([](int x) { return x * x; })
                      | std::views::reverse;
    for (int x : pipeline) {
        std::print("{} ", x);
    }
    std::println();
    for (int x : v | std::views::drop(2) | std::views::take(3)) {
        std::print("{} ", x);
    }
    std::println();
    return 0;
}
```

Вывод:

```text
64 36 16 4
3 4 5
```

| Представление                | Что даёт                                       |
| ---------------------------- | ---------------------------------------------- |
| `views::filter(условие)`     | только элементы, для которых условие истинно   |
| `views::transform(функция)`  | результат функции для каждого элемента         |
| `views::take(n)`, `drop(n)`  | первые `n` элементов / всё, кроме первых `n`   |
| `views::reverse`             | элементы в обратном порядке                    |
| `views::iota(a, b)`          | числа от `a` до `b − 1` без всякого контейнера |
| `views::enumerate` (C++23)   | пары «номер, элемент»                          |
| `views::zip(a, b)` (C++23)   | пары элементов двух диапазонов                 |
| `views::adjacent<2>` (C++23) | пары соседних элементов                        |
| `views::chunk(n)` (C++23)    | куски по `n` элементов                         |
| `views::split(разделитель)`  | части строки или последовательности            |

Строка `auto pipeline = …` ничего не вычисляет и ничего не копирует: она лишь описывает, **как** получать элементы. Работа происходит в цикле — элемент за элементом. Поэтому конвейер из пяти шагов не создаёт пяти промежуточных векторов.

## Номера, пары и бесконечные последовательности

```cpp
#include <print>
#include <ranges>
#include <string>
#include <vector>

int main() {
    std::vector<std::string> names = {"Ада", "Алан", "Грейс"};
    std::vector<int> years = {1815, 1912, 1906};
    for (auto [i, name] : std::views::enumerate(names)) {
        std::print("{}.{} ", i + 1, name);
    }
    std::println();
    for (auto [name, year] : std::views::zip(names, years)) {
        std::print("{}:{} ", name, year);
    }
    std::println();
    auto squares = std::views::iota(1)
                 | std::views::transform([](int x) { return x * x; })
                 | std::views::take_while([](int x) { return x < 50; });
    for (int x : squares) {
        std::print("{} ", x);
    }
    std::println();
    return 0;
}
```

Вывод:

```text
1.Ада 2.Алан 3.Грейс
Ада:1815 Алан:1912 Грейс:1906
1 4 9 16 25 36 49
```

`enumerate` избавляет от отдельного счётчика в цикле, `zip` — от индексов при обходе двух векторов сразу (он останавливается на коротком). `views::iota(1)` без второго аргумента — **бесконечная** последовательность 1, 2, 3, … Она работает, потому что представления ленивы: `take_while` прекращает обход, как только квадрат достиг 50, и до остальных чисел дело не доходит.

## Собрать результат: `std::ranges::to`

Представление нельзя индексировать как вектор (у `filter` нет `[]`) и опасно хранить долго. Когда результат нужен как контейнер, его собирают функцией `std::ranges::to` (C++23):

```cpp
#include <print>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> scores = {72, 95, 61, 88, 99, 45};
    auto passed = scores | std::views::filter([](int s) { return s >= 70; })
                         | std::ranges::to<std::vector>();
    std::println("{} {} {}", passed.size(), passed[0], passed.back());
    auto squares = std::views::iota(1, 6) | std::views::transform([](int i) { return i * i; })
                 | std::ranges::to<std::vector<int>>();
    std::println("{} {}", squares.size(), squares[4]);
    return 0;
}
```

Вывод:

```text
4 72 99
5 25
```

`std::ranges::to<std::vector>()` сам выводит тип элементов; можно указать его явно — `to<std::vector<int>>()`. До C++23 то же писали циклом с `push_back`.

## Представление не владеет данными

Представление над контейнером хранит ссылку на него, а итераторы представления — это обёртки над итераторами контейнера. Если контейнер изменил размер или уничтожен, они устаревают. Классическая ошибка — менять вектор, пока обходишь представление над ним:

```cpp
#include <print>
#include <ranges>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3};
    for (int x : v | std::views::filter([](int x) { return x % 2 != 0; })) {
        v.push_back(x * 10); // Ошибка памяти
    }
    std::println("{}", v.size());
    return 0;
}
```

AddressSanitizer сообщает `heap-use-after-free`: первый `push_back` переносит элементы вектора в новый блок памяти, а итератор цикла продолжает читать старый, уже освобождённый.

Есть ловушка и тоньше. `filter` при первом обходе **запоминает**, где нашёлся первый подходящий элемент, чтобы не искать его снова. Если после этого изменить элементы так, что подходящим станет более ранний, повторный обход того же представления его пропустит — без всякой диагностики.

Правило: представление — это **шаг вычисления**, а не хранилище. Создавайте его рядом с местом использования, после последнего изменения контейнера; если результат нужен надолго — соберите его в вектор через `std::ranges::to`.

<Concept title="Диапазоны и представления">

Алгоритмы `std::ranges::…` принимают контейнер целиком, поддерживают проекции (`&Тип::поле`) и описаны концептами. Представления `std::views::…` соединяются через `|`, ничего не копируют и вычисляют элементы лениво, по мере обхода. `std::ranges::to` собирает результат в контейнер. Представление ссылается на исходные данные и устаревает, если они изменились.

</Concept>

## Частые ошибки

<CommonMistake title="Индекс у отфильтрованного представления">

`auto f = v | std::views::filter(…); f[0]` — ошибка компиляции: чтобы найти пятый подходящий элемент, `filter` должен пройти все предыдущие, поэтому `[]` у него нет. Нужен произвольный доступ — соберите вектор через `std::ranges::to`.

</CommonMistake>

<CommonMistake title="Представление, пережившее изменение контейнера">

`push_back`, `erase`, `clear` после создания представления делают его недействительным. Пересоздайте представление после изменений.

</CommonMistake>

<CommonMistake title="Побочные эффекты в transform">

Функция в `transform` вызывается при каждом обращении к элементу — при двух обходах дважды. Не печатайте и не меняйте внешние переменные внутри неё: представление может вызвать её не тогда и не столько раз, сколько вы ожидаете.

</CommonMistake>

<CommonMistake title="sort вместо stable_sort при сортировке по полю">

`std::ranges::sort(group, {}, &Student::score)` может переставить студентов с одинаковым баллом в любом порядке. Если важен исходный порядок равных — `stable_sort`.

</CommonMistake>

## Практика

1. **Лучшие студенты** — `stable_sort` с проекцией и `views::take`.
2. **Чётные квадраты** — конвейер `filter`, `transform`, `reverse` и `fold_left`.
3. **Найди ошибку: запомненное начало** — повторный обход `filter` после изменения элементов.
4. **Изменения цены** — `views::adjacent` и `views::enumerate`.

## Итоги

- `std::ranges::sort`, `find`, `count_if`, `minmax`, `contains` (C++23), `fold_left` (C++23) принимают диапазон целиком; ошибки описываются концептами.
- Проекция — последний аргумент: `std::ranges::sort(v, {}, &Student::score)`; `std::ranges::greater{}` сортирует по убыванию, `stable_sort` сохраняет порядок равных.
- Представления `filter`, `transform`, `take`, `drop`, `reverse`, `iota`, `enumerate`, `zip`, `adjacent` соединяются через `|` и вычисляются лениво, без промежуточных контейнеров.
- `std::ranges::to<std::vector>()` (C++23) собирает результат в контейнер.
- Представление ссылается на исходные данные: после изменения контейнера его нужно создать заново.
