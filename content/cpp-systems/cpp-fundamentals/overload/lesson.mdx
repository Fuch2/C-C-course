## Одно имя — разные типы

В C у каждой функции уникальное имя, поэтому модуль числа называется по-разному для разных типов: `abs` для `int`, `labs` для `long`, `llabs` для `long long`, `fabs` для `double`. Перепутать легко: `abs(-2.7)` молча превратит число в `int` и вернёт 2.

В C++ функции могут называться **одинаково**, если различаются параметрами. Это **перегрузка** (overloading). Компилятор выбирает подходящую версию по типам аргументов:

```cpp
#include <iostream>
#include <string>

int twice(int x) {
    return x * 2;
}

double twice(double x) {
    return x * 2;
}

std::string twice(const std::string &s) {
    return s + s;
}

int main() {
    std::cout << twice(21) << ' ' << twice(1.25) << ' ' << twice(std::string("ab")) << '\n';
    return 0;
}
```

Вывод:

```text
42 2.5 abab
```

Три разные функции с одним именем. Для `21` подходит `twice(int)`, для `1.25` — `twice(double)`, для строки — третья. Стандартная библиотека C++ так и устроена: `std::abs` перегружена для всех числовых типов, поэтому одно имя правильно работает и с `int`, и с `double`.

## Что различает перегрузки

Перегрузки должны различаться **количеством или типами параметров**. Тип возвращаемого значения не учитывается: две функции `int f(int)` и `double f(int)` — ошибка, потому что по вызову `f(5)` их не различить.

```cpp
#include <iostream>

double area(double radius) {
    return 3.14159265358979 * radius * radius;
}

double area(double width, double height) {
    return width * height;
}

int main() {
    std::cout << area(1.0) << ' ' << area(2.0, 3.5) << '\n';
    return 0;
}
```

Вывод:

```text
3.14159 7
```

## Как компилятор выбирает

Когда типы аргументов не совпадают с параметрами точно, компилятор ранжирует варианты: **точное совпадение** лучше **продвижения** (`char`, `short` → `int`, `float` → `double`), а продвижение лучше **преобразования** (`int` → `double`, `int` → `long`). Если лучший вариант один — он и вызывается. Если два варианта одинаково хороши — ошибка компиляции «вызов неоднозначен»:

```cpp
#include <iostream>

void show(long x) {
    std::cout << "long " << x << '\n';
}

void show(double x) {
    std::cout << "double " << x << '\n';
}

int main() {
    show(5L);
    show(2.5);
    show(5);                 // Ошибка компиляции
    return 0;
}
```

Компилятор: `call of overloaded 'show(int)' is ambiguous`. Для `int` и превращение в `long`, и превращение в `double` — преобразования одного ранга, и выбрать нельзя. Исправления: добавить перегрузку для `int` или явно привести аргумент.

## nullptr и перегрузка

Перегрузка объясняет, зачем в C++ появился `nullptr`:

```cpp
#include <iostream>

void check(int value) {
    std::cout << "число " << value << '\n';
}

void check(const int *pointer) {
    std::cout << "указатель " << (pointer == nullptr ? "пустой" : "непустой") << '\n';
}

int main() {
    int x = 5;
    check(0);
    check(&x);
    check(nullptr);
    return 0;
}
```

Вывод:

```text
число 0
указатель непустой
указатель пустой
```

`0` — целое число, поэтому вызывается `check(int)`, хотя программист мог иметь в виду пустой указатель. `NULL` в C++ обычно определён как `0`, и с ним та же история. `nullptr` имеет собственный тип и подходит только к указателям.

## Шаблоны функций

Часто перегрузки отличаются только типом, а тело у них одинаковое. Писать его заново для каждого типа не нужно — есть **шаблоны функций**:

```cpp
#include <iostream>
#include <string>

template <typename T>
T largest(T a, T b) {
    return a < b ? b : a;
}

int main() {
    std::cout << largest(3, 7) << ' ' << largest(2.5, -1.0) << ' '
              << largest(std::string("pear"), std::string("apple")) << '\n';
    std::cout << largest<double>(3, 7.5) << '\n';
    return 0;
}
```

Вывод:

```text
7 2.5 pear
7.5
```

`template <typename T>` объявляет **параметр-тип** `T`. При вызове `largest(3, 7)` компилятор выводит `T = int` и сам создаёт функцию `int largest(int, int)`; для строк — версию со строками. Это похоже на макрос, но без его опасностей: проверяются типы, аргументы вычисляются один раз, ошибки сообщаются в терминах функции.

Если типы аргументов разные — `largest(3, 7.5)` — компилятор не может вывести единый `T`, и тип указывают явно: `largest<double>(3, 7.5)`.

Шаблон работает с любым типом, для которого корректно его тело: здесь нужен оператор `<`. Многие функции стандартной библиотеки — шаблоны: `std::max`, `std::min`, `std::swap`, `std::sort`. Подробно шаблоны изучают отдельно, а пока достаточно уметь пользоваться ими и писать простые шаблоны функций.

<Concept title="Перегрузка и шаблоны">

Перегрузка — несколько функций с одним именем и разными параметрами; компилятор выбирает версию по типам аргументов, предпочитая точное совпадение, затем продвижение, затем преобразование. Возвращаемый тип в выборе не участвует; одинаково хорошие варианты дают ошибку неоднозначности. Шаблон функции `template <typename T>` — одно тело для многих типов: компилятор выводит `T` из аргументов и создаёт нужную версию.

</Concept>

## Частые ошибки

<CommonMistake title="Перегрузка по возвращаемому типу">

`int parse(const std::string &)` и `double parse(const std::string &)` не могут существовать вместе: вызов `parse(s)` их не различает. Дайте функциям разные имена или разные параметры.

</CommonMistake>

<CommonMistake title="Неоднозначный вызов">

Перегрузки для `long` и `double` без перегрузки для `int` делают неоднозначным любой вызов с `int` — включая литерал `5`. Перегружайте для того типа, которым функцию реально будут вызывать, или используйте шаблон.

</CommonMistake>

<CommonMistake title="Разные типы в шаблоне">

`std::max(3, 2.5)` не компилируется: у шаблона один параметр-тип, а аргументы — `int` и `double`. Пишите `std::max(3.0, 2.5)` или `std::max<double>(3, 2.5)`.

</CommonMistake>

## Практика

1. **Площади фигур** — перегрузка по количеству параметров.
2. **Описание значения** — перегрузка по типу.
3. **Найди ошибку: ограничение диапазона** — неоднозначный вызов.
4. **Обобщённая статистика** — шаблоны функций для чисел и строк.

## Итоги

- Перегрузка — функции с одним именем и разными параметрами.
- Выбор: точное совпадение, затем продвижение, затем преобразование; равные варианты — ошибка неоднозначности.
- Возвращаемый тип не различает перегрузки.
- `0` и `NULL` — целые числа; для пустого указателя — `nullptr`.
- Шаблон `template <typename T>` — одно тело для разных типов; `T` выводится из аргументов или указывается явно.
