## Двусторонняя очередь

`std::vector` быстро добавляет и удаляет в **конце**, а в начале — за `O(n)`: все элементы приходится сдвигать. Когда нужны оба конца — очередь заданий, история с ограниченной длиной, окно по потоку данных, — подходит `std::deque` из `<deque>` (double-ended queue, «дек»). В модуле «Алгоритмы» вы строили дек на двусвязном списке и на кольцевом буфере; `std::deque` — готовая реализация.

```cpp
#include <deque>
#include <iostream>

int main() {
    std::deque<int> d = {2, 3};
    d.push_front(1);
    d.push_back(4);
    d.push_front(0);
    std::cout << d.front() << ' ' << d.back() << ' ' << d[2] << ' ' << d.size() << '\n';
    d.pop_front();
    d.pop_back();
    for (int x : d) {
        std::cout << x << ' ';
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
0 4 2 5
1 2 3
```

| Операция                  | `std::vector`                    | `std::deque`           |
| ------------------------- | -------------------------------- | ---------------------- |
| `push_back`, `pop_back`   | амортизированное `O(1)`          | `O(1)`                 |
| `push_front`, `pop_front` | нет (`insert` в начало — `O(n)`) | `O(1)`                 |
| доступ `d[i]`             | `O(1)`                           | `O(1)`, чуть медленнее |
| вставка в середину        | `O(n)`                           | `O(n)`                 |
| элементы лежат подряд     | да                               | нет                    |

## Как устроен deque

Дек хранит элементы не одним блоком, а **несколькими блоками фиксированного размера** и маленьким массивом указателей на эти блоки. Добавление в начало или конец заполняет крайний блок, а когда он полон, выделяется новый — существующие элементы **не переносятся**. Поэтому доступ по индексу — две операции (найти блок, затем элемент), а ссылки на элементы остаются действительными при добавлении в начало и конец.

Цена — элементы лежат не подряд: дек нельзя передать функции C как массив, а последовательный обход немного медленнее, чем у вектора.

## Индексы сдвигаются

`push_front` добавляет элемент с индексом 0 — и все прежние элементы получают индекс на единицу больше. Если программа запомнила **номер** элемента, после вставки в начало номер нужно пересчитать:

```cpp
#include <deque>
#include <iostream>
#include <string>

int main() {
    std::deque<std::string> playlist = {"b", "c"};
    std::size_t current = 1;                       // играет "c"
    playlist.push_front("a");
    std::cout << playlist[current] << ' ';         // уже "b"!
    current++;                                     // поправка
    std::cout << playlist[current] << '\n';
    return 0;
}
```

Вывод:

```text
b c
```

## Стек и очередь стандартной библиотеки

Стек и очередь — абстрактные типы данных из модуля «Алгоритмы». В стандартной библиотеке они называются **адаптерами**: `std::stack` и `std::queue` берут готовый контейнер (по умолчанию — `std::deque`) и оставляют от его интерфейса только операции стека или очереди.

```cpp
#include <iostream>
#include <queue>
#include <stack>

int main() {
    std::stack<int> s;
    std::queue<int> q;
    for (int i = 1; i <= 3; i++) {
        s.push(i);
        q.push(i);
    }
    std::cout << "стек:";
    while (!s.empty()) {
        std::cout << ' ' << s.top();
        s.pop();
    }
    std::cout << "\nочередь:";
    while (!q.empty()) {
        std::cout << ' ' << q.front();
        q.pop();
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
стек: 3 2 1
очередь: 1 2 3
```

Обратите внимание: `pop()` **ничего не возвращает** — он только удаляет элемент. Сначала читают `top()` или `front()`, потом вызывают `pop()`. И ни `top()`, ни `pop()` не проверяют пустоту: для пустого стека это неопределённое поведение, поэтому перед ними проверяют `empty()`.

Зачем адаптер, если есть `std::deque`? Он ограничивает интерфейс: у `std::stack` нет доступа к середине и к «чужому» концу, и случайно нарушить порядок LIFO невозможно. Тип переменной сразу сообщает читателю, как она используется.

## Дек в алгоритмах

Дек — естественная структура для алгоритмов, которым нужны оба конца. Скользящий максимум из модуля «Алгоритмы» с `std::deque` записывается короче, чем с самодельным кольцевым буфером:

```cpp
#include <deque>
#include <iostream>
#include <vector>

int main() {
    std::vector<int> v = {1, 3, -1, -3, 5, 3, 6, 7};
    std::size_t k = 3;
    std::deque<std::size_t> window;                    // индексы, значения убывают
    for (std::size_t i = 0; i < v.size(); i++) {
        if (!window.empty() && window.front() + k <= i) {
            window.pop_front();                        // вышел из окна
        }
        while (!window.empty() && v[window.back()] <= v[i]) {
            window.pop_back();                         // больше не станет максимумом
        }
        window.push_back(i);
        if (i + 1 >= k) {
            std::cout << v[window.front()] << ' ';
        }
    }
    std::cout << '\n';
    return 0;
}
```

Вывод:

```text
3 3 5 5 6 7
```

<Concept title="std::deque, std::stack, std::queue">

`std::deque` — последовательность с быстрыми операциями на обоих концах (`push_front`, `push_back`, `pop_front`, `pop_back` за `O(1)`) и доступом по индексу. Элементы хранятся блоками, поэтому не лежат подряд, а ссылки на них переживают добавления на концах. `push_front` сдвигает индексы всех элементов. `std::stack` и `std::queue` — адаптеры над `std::deque`, оставляющие только операции стека и очереди; `pop()` ничего не возвращает и не проверяет пустоту.

</Concept>

## Частые ошибки

<CommonMistake title="Значение из pop()">

`int x = s.pop();` не компилируется: `pop()` возвращает `void`. Пишите `int x = s.top(); s.pop();`.

</CommonMistake>

<CommonMistake title="top() пустого стека">

`std::stack::top()` и `std::queue::front()` для пустого адаптера — неопределённое поведение без всякого сообщения. Проверяйте `empty()` перед обращением.

</CommonMistake>

<CommonMistake title="Сохранённый индекс после push_front">

Индекс элемента в деке после `push_front` увеличивается на единицу. Храните индексы осторожно или пересчитывайте их при вставке в начало.

</CommonMistake>

## Итоги

- `std::deque` — быстрые вставка и удаление на обоих концах и доступ по индексу.
- Элементы хранятся блоками: не подряд, но без переноса при росте на концах.
- `push_front` сдвигает индексы всех элементов.
- `std::stack` и `std::queue` — адаптеры над `std::deque`; `pop()` не возвращает значение и не проверяет пустоту.
- Дек — основа алгоритмов «скользящего окна» и поиска в ширину 0-1.
