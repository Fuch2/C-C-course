## Ошибки в C и в C++

В модуле «Углублённый C» ошибки обрабатывались кодами возврата, `errno` и `goto cleanup`. У этого подхода известные слабости: код ошибки легко проигнорировать, каждая функция в цепочке вызовов должна передавать его наверх вручную, а возвращаемое значение занято признаком ошибки и не может нести сам результат.

В C++ есть второй механизм — **исключения**. Функция, обнаружившая ошибку, **бросает** исключение (`throw`), и управление сразу переходит к ближайшему подходящему **обработчику** (`catch`) выше по цепочке вызовов — сколько бы функций между ними ни было.

```cpp
#include <iostream>
#include <stdexcept>

double divide(double a, double b) {
    if (b == 0) {
        throw std::invalid_argument("деление на ноль");
    }
    return a / b;
}

int main() {
    try {
        std::cout << divide(10, 4) << '\n';
        std::cout << divide(1, 0) << '\n';
        std::cout << "эта строка не выполнится\n";
    } catch (const std::invalid_argument &e) {
        std::cout << "ошибка: " << e.what() << '\n';
    }
    std::cout << "программа продолжается\n";
    return 0;
}
```

Вывод:

```text
2.5
ошибка: деление на ноль
программа продолжается
```

- `throw выражение;` создаёт объект-исключение и прекращает выполнение функции.
- `try { … }` — блок, исключения из которого будут перехвачены.
- `catch (const тип &e) { … }` — обработчик для исключений этого типа; `e.what()` возвращает текст сообщения.

После обработки выполнение продолжается **после** всего блока `try`/`catch` — оставшиеся строки внутри `try` пропускаются.

## Стандартные исключения

Стандартная библиотека бросает исключения сама, и вы уже встречали их в этом модуле:

```cpp
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

int main() {
    std::vector<int> v = {1, 2, 3};
    try {
        std::cout << v.at(10) << '\n';
    } catch (const std::out_of_range &e) {
        std::cout << "at: индекс вне диапазона\n";
    }
    try {
        std::cout << std::stoi("сорок два") << '\n';
    } catch (const std::invalid_argument &e) {
        std::cout << "stoi: не число\n";
    }
    try {
        std::cout << std::stoi("99999999999") << '\n';
    } catch (const std::out_of_range &e) {
        std::cout << "stoi: не помещается в int\n";
    }
    return 0;
}
```

Вывод:

```text
at: индекс вне диапазона
stoi: не число
stoi: не помещается в int
```

Все стандартные исключения — потомки класса `std::exception` (из `<exception>`), основные объявлены в `<stdexcept>`:

| Исключение              | Когда бросается                                               |
| ----------------------- | ------------------------------------------------------------- |
| `std::out_of_range`     | `at()` с неверным индексом, `stoi` для слишком большого числа |
| `std::invalid_argument` | `stoi`, `stod` для строки, которая не начинается с числа      |
| `std::length_error`     | попытка сделать контейнер больше максимального размера        |
| `std::bad_alloc`        | `new` или контейнер не смогли выделить память                 |
| `std::runtime_error`    | общая ошибка времени выполнения — удобна для своих ошибок     |

## Порядок обработчиков

После `try` может идти несколько `catch` — они проверяются **по порядку**, и срабатывает первый подходящий. Обработчик для `std::exception` ловит любое стандартное исключение, поэтому его ставят **последним**: если поставить его первым, до более точных обработчиков дело не дойдёт.

```cpp
#include <iostream>
#include <stdexcept>
#include <string>

void check(const std::string &text) {
    try {
        std::size_t pos;
        int value = std::stoi(text, &pos);
        if (pos != text.size()) {
            throw std::runtime_error("лишние символы после числа");
        }
        std::cout << text << " -> " << value << '\n';
    } catch (const std::invalid_argument &) {
        std::cout << text << ": не число\n";
    } catch (const std::out_of_range &) {
        std::cout << text << ": слишком большое\n";
    } catch (const std::exception &e) {
        std::cout << text << ": " << e.what() << '\n';
    }
}

int main() {
    check("42");
    check("abc");
    check("12abc");
    check("1e100000");
    return 0;
}
```

Вывод:

```text
42 -> 42
abc: не число
12abc: лишние символы после числа
1e100000: лишние символы после числа
```

`std::stoi(text, &pos)` записывает в `pos`, сколько символов разобрано. Если разобрана не вся строка, мы сами бросаем `std::runtime_error`, и его ловит последний обработчик. Имя параметра в `catch` можно не писать, если объект не нужен.

Ловят исключения **по константной ссылке** — `catch (const std::exception &e)`. Ловля по значению копирует объект и, если исключение — потомок указанного класса, обрезает его до базовой части (об этом — в модуле об ООП).

## Раскрутка стека

Когда исключение летит из глубины вызовов, все функции между `throw` и `catch` завершаются, и их **локальные переменные уничтожаются**, как при обычном выходе. Строки, векторы и другие объекты стандартной библиотеки при уничтожении освобождают свою память — поэтому исключение не приводит к утечке:

```cpp
#include <iostream>
#include <stdexcept>
#include <string>
#include <vector>

int parse_all(const std::vector<std::string> &items) {
    std::vector<int> numbers;                       // будет освобождён при исключении
    for (const auto &s : items) {
        numbers.push_back(std::stoi(s));
    }
    int sum = 0;
    for (int x : numbers) {
        sum += x;
    }
    return sum;
}

int main() {
    try {
        std::cout << parse_all({"1", "2", "3"}) << '\n';
        std::cout << parse_all({"4", "пять", "6"}) << '\n';
    } catch (const std::exception &e) {
        std::cout << "не удалось разобрать список\n";
    }
    return 0;
}
```

Вывод:

```text
6
не удалось разобрать список
```

Это главная причина, почему в C++ ресурсы держат в объектах, которые освобождают их сами: тогда и при обычном возврате, и при исключении всё освобождается автоматически, без `goto cleanup`. Этот принцип называется RAII — ему посвящён модуль «Время жизни объектов».

## Неперехваченное исключение

Если исключение не перехватил ни один обработчик, программа аварийно завершается вызовом `std::terminate`:

```cpp
#include <stdexcept>
#include <vector>

int main() {
    std::vector<int> v(3);
    return v.at(5);          // Ошибка выполнения: исключение не перехвачено
}
```

Программа печатает в поток ошибок `terminate called after throwing an instance of 'std::out_of_range'` и завершается сигналом `SIGABRT`. Поэтому исключения, которые могут вылететь, перехватывают там, где на ошибку можно осмысленно отреагировать, — часто в `main`.

## Когда бросать исключения

Исключения — для **исключительных** ситуаций: неверных данных, которые функция не может обработать сама, нехватки памяти, недоступного файла. Не стоит заменять ими обычные ветвления: «элемент не найден» в поиске — нормальный результат, для него лучше вернуть `end()` или признак. Исключение дорогое, когда брошено, но почти ничего не стоит, пока его нет.

Для ошибок, которые случаются часто и обрабатываются рядом с местом вызова — неверный ввод, неправильный формат строки, — в C++23 есть альтернатива: тип `std::expected`, который возвращает либо результат, либо описание ошибки. Ему посвящён следующий урок.

<Concept title="Исключения">

`throw` прерывает выполнение и передаёт объект-исключение ближайшему подходящему `catch` выше по цепочке вызовов; локальные объекты по пути уничтожаются, освобождая ресурсы. Обработчики проверяются по порядку — общий `std::exception` ставят последним; ловят по `const &`. Стандартная библиотека бросает `std::out_of_range`, `std::invalid_argument`, `std::bad_alloc`; свои ошибки удобно бросать как `std::runtime_error`. Неперехваченное исключение завершает программу.

</Concept>

## Частые ошибки

<CommonMistake title="Общий обработчик первым">

```cpp
catch (const std::exception &e) { … }       // ловит всё
catch (const std::out_of_range &e) { … }    // никогда не сработает
```

Обработчики проверяются по порядку. GCC предупреждает: `exception of type 'std::out_of_range' will be caught by earlier handler`. Ставьте точные типы раньше общих.

</CommonMistake>

<CommonMistake title="Ловля по значению">

`catch (std::exception e)` копирует исключение и теряет информацию о его настоящем типе. Ловите по константной ссылке.

</CommonMistake>

<CommonMistake title="Исключение вместо ветвления">

Бросать исключение, чтобы выйти из цикла или сообщить «не найдено», — медленно и запутанно. Исключения — для ошибок, а не для обычного хода программы.

</CommonMistake>

## Итоги

- `throw` бросает исключение, `try`/`catch` перехватывает; управление переходит к первому подходящему обработчику выше по стеку.
- Стандартные исключения: `std::out_of_range`, `std::invalid_argument`, `std::runtime_error`, `std::bad_alloc` — потомки `std::exception`.
- Обработчики проверяются по порядку: точные типы — раньше, `std::exception` — последним; ловят по `const &`.
- При раскрутке стека локальные объекты уничтожаются и освобождают ресурсы — это основа RAII.
- Неперехваченное исключение завершает программу через `std::terminate`.
- Исключения — для ошибок, а не для обычного хода программы.
