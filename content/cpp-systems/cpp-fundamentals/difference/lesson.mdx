## Зачем ещё один язык

C++ вырос из C: в 1979 году Бьёрн Страуструп начал добавлять к C классы, и язык назывался «C с классами». Почти весь C, который вы знаете, — циклы, функции, указатели, массивы, структуры — остаётся в C++. Но C++ — **другой язык**, со своими правилами и своим стилем.

Оба языка живы и развиваются параллельно: у C последний стандарт — C23, у C++ — C++23, а следующий, C++26, уже утверждён комитетом и постепенно появляется в компиляторах. Этот модуль использует C++23.

Главное, что даёт C++, — возможность поручить рутину компилятору и библиотеке. В C вы сами следите за длиной строки, вызываете `free` для каждого `malloc` и пишете динамический массив заново в каждой программе. В C++ строка, массив переменной длины и таблица «ключ → значение» — готовые типы стандартной библиотеки, которые сами выделяют и освобождают память. Этот модуль — о том, как пользоваться этими инструментами и где проходит граница между C и C++.

## Первая программа

```cpp
#include <iostream>

int main() {
    std::cout << "Привет, C++!\n";
    return 0;
}
```

Вывод:

```text
Привет, C++!
```

Что изменилось по сравнению с C:

- файл называется `main.cpp`, а компилируют его `g++` или `clang++` (а не `gcc`/`clang`): `g++ -std=c++23 -Wall -Wextra main.cpp -o main`;
- заголовок `<iostream>` без `.h` — это часть стандартной библиотеки C++;
- `std::cout << …` печатает значение — подробно в уроке о выводе;
- `int main()` без `void`: в C++ пустые скобки и так означают «без параметров».

## Сравним с C

Вот одна и та же задача — склеить имя и фамилию — на C и на C++:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void) {
    const char *first = "Ада", *last = "Лавлейс";
    char *full = malloc(strlen(first) + 1 + strlen(last) + 1);
    if (full == NULL) {
        return 1;
    }
    strcpy(full, first);
    strcat(full, " ");
    strcat(full, last);
    printf("%s (%zu байт)\n", full, strlen(full));
    free(full);
    return 0;
}
```

```cpp
#include <iostream>
#include <string>

int main() {
    std::string first = "Ада", last = "Лавлейс";
    std::string full = first + " " + last;
    std::cout << full << " (" << full.size() << " байт)\n";
    return 0;
}
```

Вывод обеих программ:

```text
Ада Лавлейс (21 байт)
```

В версии на C нужно вручную посчитать размер буфера (не забыв байт под `'\0'`), проверить результат `malloc`, склеить части и освободить память. В C++ `std::string` сам выделяет нужный объём, `+` склеивает строки, а память освобождается автоматически, когда переменная выходит из области видимости. Ошибиться на единицу в размере буфера или забыть `free` здесь просто негде.

Кириллические буквы занимают в UTF-8 по два байта, поэтому `size()` — 21 байт, а не 11 символов. И `strlen`, и `size()` считают байты.

## Что из C работает иначе

Большая часть кода на C компилируется как C++, но есть отличия, на которые вы наткнётесь в первые же дни.

**`void *` не превращается в другой указатель сам.** В C результат `malloc` можно присвоить любому указателю. В C++ — нет:

```cpp
#include <cstdlib>

int main() {
    int *values = malloc(10 * sizeof *values);   // Ошибка компиляции
    free(values);
    return 0;
}
```

Компилятор сообщает `invalid conversion from 'void*' to 'int*'`. В C++ так почти не пишут: для массива переменной длины есть `std::vector`, а если без `malloc` не обойтись — нужно явное приведение `static_cast<int *>(…)`.

**`bool`, `true` и `false` — встроенные.** В C++ так было всегда; в C они стали ключевыми словами только в C23, а до этого требовали `<stdbool.h>`.

**`nullptr` вместо `NULL`.** У `nullptr` свой тип — «пустой указатель», и он не путается с целым числом `0`, когда функция перегружена для `int` и для указателя (о перегрузке — в отдельном уроке). C23 позаимствовал `nullptr` у C++, но в C++ разница важнее: `NULL` здесь почти всегда просто `0`. Многие нововведения C23 — `constexpr`, `auto`, атрибуты `[[…]]`, `static_assert` без подключения заголовка — тоже пришли из C++, и языки снова сближаются.

**Имя структуры — уже тип.** После `struct Point { int x, y; };` можно писать просто `Point p;` без `struct` и без `typedef`.

**Символьный литерал — `char`.** В C `sizeof('a')` равен `sizeof(int)`, в C++ — 1.

```cpp
#include <iostream>

struct Point {
    int x, y;
};

int main() {
    Point p{3, 4};                       // без слова struct
    bool far = p.x * p.x + p.y * p.y > 20;
    int *nothing = nullptr;
    std::cout << sizeof('a') << ' ' << far << ' ' << (nothing == nullptr) << '\n';
    return 0;
}
```

Вывод:

```text
1 1 1
```

`bool` печатается как `1` или `0`; печатать `true`/`false` научимся в уроке о выводе.

## Библиотека C остаётся

Все функции стандартной библиотеки C доступны и в C++. Заголовки называются по-новому: `<stdio.h>` → `<cstdio>`, `<math.h>` → `<cmath>`, `<string.h>` → `<cstring>`: буква `c` в начале и без `.h`. В них те же функции, но объявленные в пространстве имён `std` — например, `std::sqrt`.

```cpp
#include <cmath>
#include <cstdio>

int main() {
    std::printf("%.3f\n", std::sqrt(2.0));
    return 0;
}
```

Вывод:

```text
1.414
```

Пользоваться `printf` в C++ можно, но в этом модуле мы будем писать в стиле C++: потоки `std::cout` и `std::cin`, форматированный вывод `std::print` из C++23, строки `std::string`, контейнеры вместо ручного `malloc`. Код в стиле «C, скомпилированный компилятором C++» работает, но теряет главные преимущества языка.

<Concept title="C++ — не надстройка, а другой язык">

C++ сохранил почти весь C, но добавил типы, которые сами управляют своими ресурсами, ссылки, перегрузку функций, пространства имён, исключения и большую стандартную библиотеку. Отличия в правилах (`void *`, `bool`, `nullptr`, имена структур) мелкие, отличие в стиле — большое: в C++ работу с памятью поручают типам, а не пишут вручную.

</Concept>

## Частые ошибки

<CommonMistake title="Файл .c, компилятор C">

Если назвать файл `main.c` или скомпилировать его `gcc`, он будет собран как программа на C — и `#include <iostream>` даст ошибку «нет такого файла». Файлы C++ называют `.cpp`, а компилируют `g++` или `clang++`.

</CommonMistake>

<CommonMistake title="Привычка к malloc">

`int *p = (int *)malloc(n * sizeof(int));` компилируется, но в C++ это почти всегда лишнее: память придётся освобождать вручную, а при ошибке легко получить утечку. Для массива переменной длины используйте `std::vector<int> p(n);` — урок о `std::vector` впереди.

</CommonMistake>

<CommonMistake title="NULL вместо nullptr">

`NULL` в C++ — это обычно просто `0`, целое число. При перегрузке `f(int)` и `f(int *)` вызов `f(NULL)` выберет версию для `int`. `nullptr` всегда означает указатель.

</CommonMistake>

## Практика

1. **Сумма двух чисел** — первая программа с вводом.
2. **Счётчик и максимум** — `bool` вместо флага-числа.
3. **Найди ошибку: код из C** — `malloc` в C++.
4. **Самое длинное слово** — строки без ручных буферов.

## Итоги

- C++ вырос из C и сохранил почти всё, но это отдельный язык: файлы `.cpp`, компилятор `g++` или `clang++`.
- Стандартная библиотека C++ берёт на себя рутину: `std::string` и контейнеры сами управляют памятью.
- `void *` не преобразуется в другие указатели неявно; `bool` и `nullptr` встроены; имя структуры — уже тип.
- Библиотека C доступна через заголовки `<cstdio>`, `<cmath>`, `<cstring>`.
- Стиль C++ — поручать управление ресурсами типам, а не писать его вручную.
