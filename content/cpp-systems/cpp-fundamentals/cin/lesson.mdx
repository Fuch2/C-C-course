## Ввод по типу переменной

В C ввод — `scanf` со строкой формата и адресами переменных: `scanf("%d %lf", &n, &x)`. Забытый `&` или неверный спецификатор — неопределённое поведение. В C++ ввод — поток `std::cin` и оператор `>>`, который сам выбирает способ чтения по типу переменной:

```cpp
#include <iostream>
#include <string>

int main() {
    int age;
    double height;
    std::string name;
    std::cin >> name >> age >> height;
    std::cout << name << ", " << age << " лет, рост " << height << " м\n";
    return 0;
}
```

Ввод:

```text
Ада 36
1.65
```

Вывод:

```text
Ада, 36 лет, рост 1.65 м
```

`>>` пропускает пробельные символы — пробелы, табуляции, переводы строк — и читает очередное **слово** (для строки) или число. Поэтому неважно, на одной строке значения или на разных. Адресов и спецификаторов нет: `>>` получает переменную по ссылке и знает её тип.

## Чтение до конца ввода

Выражение `std::cin >> x` возвращает сам поток, а поток в условии ведёт себя как `true`, пока чтение удаётся. Отсюда главная идиома:

```cpp
#include <iostream>

int main() {
    long long sum = 0;
    int count = 0, x;
    while (std::cin >> x) {
        sum += x;
        count++;
    }
    std::cout << count << " чисел, сумма " << sum << '\n';
    return 0;
}
```

Ввод:

```text
3 1 4
1 5
```

Вывод:

```text
5 чисел, сумма 14
```

Цикл останавливается, когда ввод закончился **или** очередное значение не удалось прочитать как число. Это аналог `while (scanf("%d", &x) == 1)`.

## Когда ввод некорректен

Если вместо числа встретилось слово, чтение не удаётся, и поток переходит в **состояние ошибки** (`failbit`). Переменная при этом получает 0, а все следующие операции чтения сразу завершаются неудачей — пока ошибку не сбросить:

```cpp
#include <iostream>
#include <limits>
#include <string>

int main() {
    int x;
    std::cin >> x;
    std::cout << "прочитано: " << x << ", поток в порядке: " << std::boolalpha << bool(std::cin) << '\n';
    std::cin.clear();                                   // сбросить состояние ошибки
    std::string bad;
    std::cin >> bad;                                    // забрать мешающее слово
    std::cin >> x;
    std::cout << "пропущено «" << bad << "», затем " << x << '\n';
    return 0;
}
```

Ввод:

```text
abc 42
```

Вывод:

```text
прочитано: 0, поток в порядке: false
пропущено «abc», затем 42
```

Схема восстановления всегда одна: `std::cin.clear()` сбрасывает ошибку, затем нужно убрать из потока то, что мешало, — прочитать слово в строку или пропустить остаток строки `std::cin.ignore(std::numeric_limits<std::streamsize>::max(), '\n')`.

## Целые строки: std::getline

`>>` для строки читает одно слово. Чтобы прочитать строку целиком, с пробелами, есть `std::getline(std::cin, line)`: он читает всё до перевода строки и сам перевод строки выбрасывает.

```cpp
#include <iostream>
#include <string>

int main() {
    std::string line;
    int number = 0;
    while (std::getline(std::cin, line)) {
        number++;
        std::cout << number << ": [" << line << "] " << line.size() << '\n';
    }
    return 0;
}
```

Ввод:

```text
Привет, мир
  с пробелами
```

Вывод:

```text
1: [Привет, мир] 20
2: [  с пробелами] 23
```

Пробелы в начале строки сохраняются, длина — в байтах (кириллица — по два байта на букву).

## Ловушка: >> и getline вместе

Самая частая ошибка с вводом в C++. Пусть первая строка — число, а дальше идут строки текста:

```cpp
#include <iostream>
#include <string>

int main() {
    int n;
    std::cin >> n;
    std::string first;
    std::getline(std::cin, first);
    std::cout << "n = " << n << ", первая строка: [" << first << "]\n";
    return 0;
}
```

Ввод:

```text
2
Анна Петрова
```

Вывод:

```text
n = 2, первая строка: []
```

`>>` прочитал `2` и остановился **перед** переводом строки. `getline` увидел этот перевод строки сразу и вернул пустую строку. Исправление — пропустить пробельные символы перед `getline`: `std::getline(std::cin >> std::ws, first)`. Манипулятор `std::ws` съедает все пробелы и переводы строк до первого значимого символа. (Если пустые строки во входе важны, вместо него пропускают ровно остаток строки через `std::cin.ignore`.)

## Разбор строки: std::istringstream

Иногда нужно сначала прочитать строку, а потом разобрать её на значения — например, чтобы обработать каждую строку отдельно. Для этого есть **строковый поток** `std::istringstream` из `<sstream>`: он работает как `std::cin`, но читает из строки.

```cpp
#include <iostream>
#include <sstream>
#include <string>

int main() {
    std::string line;
    while (std::getline(std::cin, line)) {
        std::istringstream in(line);
        long long sum = 0, x;
        int count = 0;
        while (in >> x) {
            sum += x;
            count++;
        }
        std::cout << count << " шт., сумма " << sum << '\n';
    }
    return 0;
}
```

Ввод:

```text
1 2 3
10

-5 5
```

Вывод:

```text
3 шт., сумма 6
1 шт., сумма 10
0 шт., сумма 0
2 шт., сумма 0
```

Пустая строка дала свою строку вывода — с одним `std::cin >> x` границы строк были бы потеряны.

## Скорость

По умолчанию `std::cin` синхронизирован с `scanf` и связан с `std::cout` (перед каждым чтением сбрасывается вывод). Для входа из сотен тысяч чисел это заметно. Две строки в начале `main` отключают и то и другое:

```cpp
std::ios::sync_with_stdio(false);
std::cin.tie(nullptr);
```

После этого нельзя смешивать `std::cin` с `scanf` и `getchar` в одной программе.

<Concept title="Поток ввода">

`std::cin >> x` читает значение по типу `x`, пропуская пробельные символы; в условии поток истинен, пока чтение удаётся, — так читают до конца ввода. Неудачное чтение переводит поток в состояние ошибки: `clear()` сбрасывает его, а мешающие символы нужно убрать. `std::getline` читает строку целиком; после `>>` перед ним пропускают перевод строки (`std::ws`). `std::istringstream` разбирает прочитанную строку тем же оператором `>>`.

</Concept>

## Частые ошибки

<CommonMistake title="getline после >>">

После `std::cin >> n` в потоке остаётся перевод строки, и следующий `getline` возвращает пустую строку. Пишите `std::getline(std::cin >> std::ws, line)` или пропускайте остаток строки через `ignore`.

</CommonMistake>

<CommonMistake title="Поток в ошибке «молчит»">

После неудачного чтения все следующие `>>` ничего не делают, а программа продолжает работать с нулями. Проверяйте результат чтения: `if (!(std::cin >> x)) { … }`.

</CommonMistake>

<CommonMistake title="Слово вместо строки">

`std::cin >> name` прочитает из «Анна Петрова» только «Анна». Для значений с пробелами нужен `getline`.

</CommonMistake>

## Практика

1. **Анкета** — `getline` после `>>`.
2. **Суммы по строкам** — `getline` и `istringstream`.
3. **Найди ошибку: нумерация строк** — пустая первая строка.
4. **Проверка ввода** — восстановление после ошибки.

## Итоги

- `std::cin >> x` читает значение по типу переменной и пропускает пробельные символы.
- `while (std::cin >> x)` — чтение до конца ввода или до первого некорректного значения.
- После неудачного чтения поток в ошибке: `clear()` и удаление мешающих символов.
- `std::getline` читает строку целиком; после `>>` перед ним нужен `std::ws` или `ignore`.
- `std::istringstream` разбирает строку как поток.
- Для большого ввода — `std::ios::sync_with_stdio(false)` и `std::cin.tie(nullptr)`.
