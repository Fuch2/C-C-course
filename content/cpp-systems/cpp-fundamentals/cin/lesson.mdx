## Зачем инструмент нужен

Потоковый ввод сообщает об ошибках через состояние потока. Это позволяет строить проверяемый конвейер, но требует явно проверять fail и eof.

## Пример C++20

```cpp
#include <iostream>
#include <sstream>

void summarize(std::istream& input) {
    int count = 0;
    long long sum = 0;
    while (true) {
        input >> std::ws;
        if (input.eof()) break;
        int value{};
        if (!(input >> value) || value < -1000 || value > 1000 || count == 100) {
            std::cout << "ОШИБКА\n";
            return;
        }
        ++count;
        sum += value;
    }
    std::cout << count << ' ' << sum << '\n';
}
int main() {
    std::istringstream input{"10 -2 4"};
    summarize(input);
}

```

Ожидаемый вывод:

```text
3 12

```

## Стоимость и ограничения

| Аспект     | Разбор                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Время      | Стоимость определяется размером данных и выбранной операцией; фиксированные операции O(1), обходы O(n), дерево map/set O(log n) в среднем по высоте. |
| Память     | Объекты хранят состояние явно; контейнеры могут выделять память и инвалидировать ссылки при росте.                                                   |
| Компромисс | Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.                       |

## Сравнение с C

Используйте std::cin как стандартный компонент, когда его контракт совпадает с задачей. Проверяйте invalidation, порядок и исключения. Аналог C может дать больше ручного контроля, но требует самостоятельно поддерживать размеры, ошибки и время жизни. В C++ используйте абстракцию по её контракту, а не копируйте C-код в новом синтаксисе.

<CommonMistake title="Типичная ошибка">

Не переносите привычный C-подход автоматически: сначала определите владение, инвариант и стоимость операции.

</CommonMistake>

## Практика

В stdin от 0 до 100 целых измерений −1000…1000, разделённых пробелами. Если есть некорректный токен, переполнение int или нарушение диапазона/количества, выведите ОШИБКА. Иначе — количество и сумму через пробел. 12x тоже ошибка. Допускается пустой ввод.

## Краткое резюме

Инструмент std::cin выражает намерение программы через типы и границы владения. Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.
