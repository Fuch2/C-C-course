## Хеш-таблица стандартной библиотеки

`std::map` хранит ключи упорядоченными и платит за это `O(log n)` на операцию. Если порядок не нужен, быстрее хеш-таблица — та самая, что вы писали в модуле «Алгоритмы» с цепочками и коэффициентом заполнения. В стандартной библиотеке она называется `std::unordered_map<Key, Value>` и живёт в `<unordered_map>`:

```cpp
#include <iostream>
#include <string>
#include <unordered_map>

int main() {
    std::unordered_map<std::string, int> price = {{"apple", 50}, {"pear", 70}};
    price["kiwi"] = 30;
    price["apple"] += 5;
    std::cout << price["apple"] << ' ' << price.size() << ' ' << price.contains("plum") << '\n';
    auto it = price.find("pear");
    if (it != price.end()) {
        std::cout << it->first << " = " << it->second << '\n';
    }
    price.erase("kiwi");
    std::cout << price.count("kiwi") << '\n';
    return 0;
}
```

Вывод:

```text
55 3 0
pear = 70
0
```

Интерфейс почти совпадает с `std::map`: `operator[]` (с той же ловушкой — он создаёт отсутствующий ключ), `find`, `contains`, `count`, `at`, `insert`, `erase`, обход со структурными привязками. Код можно переключать между ними, поменяв тип.

## Порядок обхода не определён

Главное отличие для программиста — **порядок**. `std::unordered_map` обходит элементы в порядке корзин, а он зависит от хеш-функции, числа корзин и истории вставок. Стандарт этот порядок не определяет: он может отличаться между компиляторами и даже меняться после добавления элемента, вызвавшего перестройку таблицы.

Поэтому если вывод должен быть упорядоченным, ключи собирают и сортируют:

```cpp
#include <algorithm>
#include <iostream>
#include <string>
#include <unordered_map>
#include <utility>
#include <vector>

int main() {
    std::unordered_map<std::string, int> count = {{"to", 2}, {"be", 2}, {"or", 1}, {"not", 1}};
    std::vector<std::pair<std::string, int>> sorted(count.begin(), count.end());
    std::sort(sorted.begin(), sorted.end());
    for (const auto &[word, c] : sorted) {
        std::cout << word << ' ' << c << '\n';
    }
    return 0;
}
```

Вывод:

```text
be 2
not 1
or 1
to 2
```

Вектор создаётся сразу из диапазона итераторов словаря — `sorted(count.begin(), count.end())` — и сортируется как вектор пар.

## Сложность и устройство

|                          | `std::map`                     | `std::unordered_map`              |
| ------------------------ | ------------------------------ | --------------------------------- |
| устройство               | сбалансированное дерево поиска | хеш-таблица с цепочками           |
| поиск, вставка, удаление | `O(log n)`                     | `O(1)` в среднем, `O(n)` в худшем |
| порядок обхода           | по возрастанию ключей          | не определён                      |
| `lower_bound`, диапазоны | есть                           | нет                               |
| требования к ключу       | оператор `<`                   | `std::hash` и `==`                |

Хеш-таблица растёт сама: когда коэффициент заполнения (`load_factor()` — элементов на корзину) превышает `max_load_factor()` (по умолчанию 1), число корзин увеличивается и все элементы перераспределяются. Если число элементов известно заранее, `reserve(n)` выделит корзины сразу и избавит от перестроек.

```cpp
#include <iostream>
#include <unordered_map>

int main() {
    std::unordered_map<int, int> squares;
    squares.reserve(1000);
    for (int i = 0; i < 1000; i++) {
        squares[i] = i * i;
    }
    std::cout << squares[31] << ' ' << (squares.load_factor() <= squares.max_load_factor()) << '\n';
    return 0;
}
```

Вывод:

```text
961 1
```

Худший случай `O(n)` наступает, если много ключей попало в одну корзину. Со стандартной хеш-функцией на обычных данных это маловероятно, но злоумышленник, знающий хеш-функцию, может подобрать такие ключи специально.

## Какие ключи подходят

Для ключа нужна хеш-функция `std::hash<Key>` и сравнение `==`. Они уже есть для чисел, указателей, `std::string`, `char` и перечислений. А вот для `std::pair` и своих структур стандартной хеш-функции нет — `std::unordered_map<std::pair<int, int>, int>` не скомпилируется без дополнительного кода. В таких случаях проще взять `std::map` (пара умеет `<`) или собрать ключ из чисел в одно: `x * 1'000'000'007LL + y`.

## Выбор между map и unordered_map

- Нужен порядок ключей или запросы «от … до» — `std::map`.
- Нужен только поиск по ключу и данных много — `std::unordered_map`: обычно в несколько раз быстрее.
- Ключ — пара или структура без хеш-функции — проще `std::map`.
- Важна гарантия худшего случая — `std::map`.

<Concept title="std::unordered_map">

Хеш-таблица «ключ → значение»: поиск, вставка и удаление за `O(1)` в среднем. Интерфейс как у `std::map`, включая ловушку `operator[]`, но порядок обхода не определён — для упорядоченного вывода ключи сортируют. Таблица растёт сама, `reserve` выделяет корзины заранее. Ключу нужны `std::hash` и `==`: для чисел и строк они есть, для пар и своих структур — нет.

</Concept>

## Частые ошибки

<CommonMistake title="Надежда на порядок обхода">

Программа, печатающая `unordered_map` обходом, может выдавать разный порядок на разных компиляторах и после небольшого изменения данных. Если порядок важен — сортируйте или используйте `std::map`.

</CommonMistake>

<CommonMistake title="Пара как ключ">

`std::unordered_map<std::pair<int, int>, int>` не компилируется: нет `std::hash` для пары. Используйте `std::map` или закодируйте пару одним числом.

</CommonMistake>

<CommonMistake title="Итераторы после вставки">

Вставка, вызвавшая перестройку таблицы, делает недействительными все итераторы (но не ссылки на элементы). Не держите итераторы `unordered_map`, пока добавляете элементы.

</CommonMistake>

## Итоги

- `std::unordered_map` — хеш-таблица: операции `O(1)` в среднем, `O(n)` в худшем случае.
- Интерфейс как у `std::map`; `operator[]` так же создаёт отсутствующий ключ.
- Порядок обхода не определён — для упорядоченного вывода сортируйте.
- `reserve` избавляет от перестроек; `load_factor` — элементов на корзину.
- Ключ требует `std::hash` и `==`: числа и строки — да, пары и структуры — нет.
- Порядок и диапазоны — `std::map`, быстрый поиск без порядка — `std::unordered_map`.
