## Зачем инструмент нужен

unordered_map использует хеширование и даёт ожидаемое O(1). Порядок не определён, а плохие хеши дают O(n).

## Пример C++20

```cpp
#include <iostream>
#include <unordered_map>
#include <string>


int main() {
    std::unordered_map<std::string,int> m{{"a",2}}; std::cout<<m.at("a")<<'\n';
}

```

Ожидаемый вывод:

```text
2

```

## Стоимость и ограничения

| Аспект     | Разбор                                                                                                                                               |
| ---------- | ---------------------------------------------------------------------------------------------------------------------------------------------------- |
| Время      | Стоимость определяется размером данных и выбранной операцией; фиксированные операции O(1), обходы O(n), дерево map/set O(log n) в среднем по высоте. |
| Память     | Объекты хранят состояние явно; контейнеры могут выделять память и инвалидировать ссылки при росте.                                                   |
| Компромисс | Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.                       |

## Сравнение с C

Используйте std::unordered_map как стандартный компонент, когда его контракт совпадает с задачей. Проверяйте invalidation, порядок и исключения. Аналог C может дать больше ручного контроля, но требует самостоятельно поддерживать размеры, ошибки и время жизни. В C++ используйте абстракцию по её контракту, а не копируйте C-код в новом синтаксисе.

<CommonMistake title="Типичная ошибка">

Не переносите привычный C-подход автоматически: сначала определите владение, инвариант и стоимость операции.

</CommonMistake>

## Краткое резюме

Инструмент std::unordered_map выражает намерение программы через типы и границы владения. Безопасность и выразительность типов уменьшают ручную работу, но добавляют правила времени жизни и иногда стоимость аллокаций.
