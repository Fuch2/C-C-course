## Три вида ошибок

Прежде чем обрабатывать ошибку, полезно понять, откуда она:

- **ошибка программиста** — функцию вызвали с `NULL`, индекс вышел за массив, нарушен инвариант структуры. Такие ошибки не «обрабатывают», а находят и исправляют; помогают проверки `assert` из следующего урока;
- **отказ окружения** — файла нет, диск заполнен, память кончилась, сеть недоступна. Программа не виновата, но обязана отреагировать: сообщить, освободить ресурсы, завершиться или повторить;
- **неверные данные** — пользователь ввёл `12px`, в файле испорченная строка. Это ожидаемая ситуация: данные проверяют и сообщают, что именно не так.

В C нет исключений: о двух последних видах ошибок функции сообщают явно, а вызывающий код явно проверяет. Этот урок — о том, как сделать это аккуратно.

## Как функция сообщает об ошибке

**Код возврата и выходной параметр** — основной способ в C. Функция возвращает статус, а результат записывает по указателю:

```c
int parse_port(const char *text, int *port);    // 1 — успех, 0 — ошибка
```

**Особое значение результата** — `NULL`, `-1`, `EOF` — подходит, только если оно не может быть законным результатом. У функции, возвращающей температуру, такого значения нет.

**Перечисление кодов** — когда причин несколько и вызывающему коду важно их различать. К нему добавляют функцию, которая превращает код в сообщение, — как `strerror` для `errno`:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef enum {
    PORT_OK,
    PORT_EMPTY,
    PORT_NOT_NUMBER,
    PORT_RANGE,
} PortError;

static const char *port_message(PortError e) {
    static const char *const MESSAGES[] = {
        [PORT_OK] = "успех",
        [PORT_EMPTY] = "пустая строка",
        [PORT_NOT_NUMBER] = "не число",
        [PORT_RANGE] = "порт должен быть от 1 до 65535",
    };
    return MESSAGES[e];
}

static PortError parse_port(const char *text, int *port) {
    if (*text == '\0') {
        return PORT_EMPTY;
    }
    char *end;
    long value = strtol(text, &end, 10);
    if (*end != '\0') {
        return PORT_NOT_NUMBER;
    }
    if (value < 1 || value > 65535) {
        return PORT_RANGE;
    }
    *port = (int)value;              // результат записывается только при успехе
    return PORT_OK;
}

int main(void) {
    const char *inputs[] = {"8080", "", "80a", "70000"};
    for (int i = 0; i < 4; i++) {
        int port = 0;
        PortError e = parse_port(inputs[i], &port);
        if (e == PORT_OK) {
            printf("\"%s\": порт %d\n", inputs[i], port);
        } else {
            printf("\"%s\": %s\n", inputs[i], port_message(e));
        }
    }
    return 0;
}
```

Вывод:

```text
"8080": порт 8080
"": пустая строка
"80a": не число
"70000": порт должен быть от 1 до 65535
```

Обратите внимание: `*port` меняется только при успехе. Вызывающий код может рассчитывать, что при ошибке его переменная осталась прежней, — это часть договора функции.

## Распространение ошибки

Ошибка, обнаруженная глубоко внизу, должна дойти до того уровня, который знает, что с ней делать: повторить, пропустить строку, завершить программу. Каждый уровень проверяет результат вызова и, если не может исправить ситуацию, возвращает ошибку выше — по возможности добавив контекст (имя файла, номер строки).

Самая частая ошибка здесь — **проигнорированный результат**. Компилятор умеет предупреждать о нём, если функцию пометить атрибутом C23 `[[nodiscard]]` («не отбрасывай»):

```c
#include <stdio.h>

[[nodiscard]] static int save_settings(const char *path) {
    return path[0] == '\0' ? -1 : 0;
}

int main(void) {
    save_settings("");              // Предупреждение: результат проигнорирован
    if (save_settings("cfg.ini") != 0) {
        puts("не удалось сохранить");
        return 1;
    }
    puts("сохранено");
    return 0;
}
```

Вывод:

```text
сохранено
```

Для первого вызова компилятор сообщит `ignoring return value of 'save_settings', declared with attribute 'nodiscard'`. Атрибут можно снабдить пояснением — оно попадёт в предупреждение: `[[nodiscard("проверьте, сохранились ли настройки")]]`. Если результат действительно не нужен, это показывают явным приведением: `(void)save_settings(path);`.

Помечайте `[[nodiscard]]` функции, которые сообщают об ошибке через возвращаемое значение, и функции, результат которых бессмысленно отбрасывать (например, возвращающие выделенную память). До C23 в GCC и Clang для этого был нестандартный `__attribute__((warn_unused_result))` — так помечены, например, многие функции glibc.

## Освобождение ресурсов: один выход

Функция, которая захватывает несколько ресурсов — открывает файлы, выделяет память, — на каждом пути ошибки обязана освободить то, что уже захватила. Если писать `return` после каждой проверки, код освобождения приходится повторять, и рано или поздно одну копию забудут обновить. Если вкладывать проверки друг в друга, код уходит вправо лесенкой.

Устоявшийся в C приём — **единая точка выхода** с `goto`. Указатели на ресурсы инициализируются `NULL`, при любой ошибке выполняется переход на метку `cleanup`, где всё освобождается в обратном порядке:

```c
#include <stdio.h>
#include <stdlib.h>

// Копирует файл, переводя буквы в верхний регистр. 0 — успех, −1 — ошибка.
static int copy_upper(const char *from, const char *to) {
    int status = -1;
    FILE *in = NULL;
    FILE *out = NULL;
    char *buffer = NULL;

    in = fopen(from, "r");
    if (in == NULL) {
        perror(from);
        goto cleanup;
    }
    out = fopen(to, "w");
    if (out == NULL) {
        perror(to);
        goto cleanup;
    }
    buffer = malloc(4096);
    if (buffer == NULL) {
        goto cleanup;
    }
    size_t n;
    while ((n = fread(buffer, 1, 4096, in)) > 0) {
        for (size_t i = 0; i < n; i++) {
            if (buffer[i] >= 'a' && buffer[i] <= 'z') {
                buffer[i] = (char)(buffer[i] - 'a' + 'A');
            }
        }
        if (fwrite(buffer, 1, n, out) != n) {
            goto cleanup;
        }
    }
    if (ferror(in)) {
        goto cleanup;
    }
    status = 0;                       // дошли до конца — успех

cleanup:                              // освобождение в обратном порядке
    free(buffer);
    if (out != NULL && fclose(out) != 0) {
        status = -1;
    }
    if (in != NULL) {
        fclose(in);
    }
    return status;
}

int main(void) {
    FILE *f = fopen("note.txt", "w");
    if (f == NULL) {
        return 1;
    }
    fputs("hello, errors\n", f);
    fclose(f);

    printf("первая копия: %d\n", copy_upper("note.txt", "upper.txt"));
    printf("вторая копия: %d\n", copy_upper("missing.txt", "upper2.txt"));

    char line[64];
    f = fopen("upper.txt", "r");
    if (f != NULL && fgets(line, sizeof line, f) != NULL) {
        printf("%s", line);
    }
    if (f != NULL) {
        fclose(f);
    }
    return 0;
}
```

Вывод:

```text
первая копия: 0
вторая копия: -1
HELLO, ERRORS
```

Почему это работает: `free(NULL)` ничего не делает, а для `fclose` проверка на `NULL` написана явно. Поэтому код после метки корректен, на каком бы шаге ни случилась ошибка. `goto` здесь не запутывает программу, а наоборот — даёт ей один понятный путь выхода. Так оформлены функции в ядре Linux, в Git, в CPython. Правило одно: переходы только **вперёд**, к меткам очистки в конце функции.

## Частично созданный объект

Функция-конструктор, которая выделяет структуру и её внутренние буферы, при ошибке на середине должна вернуть `NULL` **и** освободить то, что успела выделить. Пользователь не должен получать наполовину готовый объект:

```c
typedef struct {
    char *title;
    int *values;
    size_t count;
} Series;

Series *series_create(const char *title, size_t count) {
    Series *s = calloc(1, sizeof *s);     // все указатели сразу NULL
    if (s == NULL) {
        return NULL;
    }
    s->title = malloc(strlen(title) + 1);
    s->values = calloc(count, sizeof *s->values);
    if (s->title == NULL || s->values == NULL) {
        series_destroy(s);                 // освобождает то, что успели выделить
        return NULL;
    }
    strcpy(s->title, title);
    s->count = count;
    return s;
}
```

Функция уничтожения пишется так, чтобы принимать и частично заполненный объект: `free(NULL)` безопасен, поэтому `series_destroy` просто освобождает все поля и саму структуру.

## Сообщения и коды завершения

- Сообщения об ошибках — в `stderr`, результаты — в `stdout`. Тогда вывод программы можно передать дальше (`prog > result.txt`), а ошибки останутся на экране.
- Сообщение должно содержать **контекст**: что делали и с каким объектом — `config.ini:12: неизвестный ключ «colr»`, — и причину из `strerror`, если она есть.
- Код завершения сообщает результат вызывающей программе: `return EXIT_SUCCESS;` (0) при успехе, `EXIT_FAILURE` или свой ненулевой код при ошибке. Скрипты и системы сборки проверяют именно его.

<Concept title="Ошибка — тоже результат">

В C ошибка — обычное значение, которое функция возвращает, а вызывающий проверяет. Хороший договор функции описывает оба исхода: что будет при успехе, какие ошибки возможны, в каком состоянии останутся аргументы и ресурсы при ошибке. Тогда ошибку можно передать выше, обработать или сообщить — и ни один ресурс не потеряется по дороге.

</Concept>

## Частые ошибки

<CommonMistake title="Проигнорированный результат">

`fclose(out);`, `scanf("%d", &n);`, `malloc(size)` без проверки. Ошибка проявится позже и в другом месте. Проверяйте результат каждой функции, которая может не сработать.

</CommonMistake>

<CommonMistake title="Утечка на пути ошибки">

`if (bad) return -1;` после `malloc` или `fopen` теряет ресурс. Используйте единую точку выхода с освобождением в обратном порядке.

</CommonMistake>

<CommonMistake title="Сообщение без контекста">

«Ошибка!» не помогает ни пользователю, ни вам. Пишите, что и где не получилось, и почему: имя файла, номер строки, `strerror(code)`.

</CommonMistake>

<CommonMistake title="Изменённый результат при ошибке">

Функция, которая при ошибке успела частично изменить выходные данные, оставляет вызывающего с испорченным состоянием. Записывайте результат только после всех проверок.

</CommonMistake>

## Итоги

- Ошибки программиста ищут и исправляют, отказы окружения и неверные данные — обрабатывают.
- Основной способ сообщить об ошибке в C — код возврата и результат через выходной параметр; при нескольких причинах — перечисление кодов и функция-описание.
- Ошибку проверяют на каждом уровне и передают выше с контекстом; атрибут `warn_unused_result` помогает не забыть проверку.
- Несколько ресурсов освобождают через единую точку выхода: указатели инициализированы `NULL`, при ошибке — `goto cleanup`, освобождение в обратном порядке.
- Конструктор при ошибке освобождает частично созданный объект и возвращает `NULL`; выходные параметры меняются только при успехе.
- Сообщения об ошибках — в `stderr` с контекстом, код завершения — `EXIT_SUCCESS` или ненулевой.
