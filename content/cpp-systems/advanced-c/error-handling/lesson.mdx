## Теория

В C ошибки обычно представлены статусом возврата и отдельным выходным параметром. Успешное значение не должно пересекаться с кодом ошибки. Хороший контракт определяет, изменяется ли выходной параметр при отказе и кто освобождает ресурсы. Это позволяет вызывающему коду безопасно повторить операцию или откатиться.

Сосредоточьте освобождение ресурсов в понятных ветвях или одном блоке cleanup. goto cleanup может упростить проверку нескольких ресурсов, если переходы направлены только к освобождению. Не заменяйте проверку ввода assert: пользовательская ошибка — штатный сценарий. В анализаторе строка с неверными данными учитывается как ошибка данных, а отказ чтения файла прекращает обработку; это разные уровни отказа.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
static int read_value(int valid,int *out){if(!valid)return 0;*out=42;return 1;}
int main(void) {
    int value=7;int ok=read_value(0,&value);printf("%d %d\n",ok,value);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
0 7
```

Функция возвращает два канала: статус операции и данные, действительные только при успехе. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Ноль бывает корректным результатом; его нельзя одновременно использовать как единственный признак ошибки.

## Проект: Анализатор журнала измерений

Прочитайте файл с показаниями датчиков и вычислите min, max, average, число измерений и число ошибочных строк. Формат каждой строки: timestamp,value. timestamp — десятичное целое 0…1000000; value — конечное число −1000…1000, распознаваемое strtod в стандартной C locale. Допускаются пробелы вокруг чисел и в конце строки. После значения других символов быть не должно. Дубликаты timestamp допустимы. Пустая строка, неверный разделитель, NaN/Inf, переполнение и строка длиннее 127 байтов считаются одной ошибкой каждая. Вход содержит не более 200 строк. Последняя строка может не иметь перевода строки.

При наличии измерений выведите: count min max average errors; числа с двумя знаками после точки. Без корректных измерений выведите НЕТ ДАННЫХ errors. Нулевой результат форматируйте без минуса. Ошибка чтения/создания файла завершает программу ненулевым кодом, а не увеличивает errors.

Адаптер копирует stdin в tmpfile и перемещается к началу; функция analyze(FILE\*) читает именно этот файл. Файл в браузерном тесте передаётся своим текстовым содержимым. Не загружайте весь журнал в массив измерений: достаточно текущей строки и накопителей.
