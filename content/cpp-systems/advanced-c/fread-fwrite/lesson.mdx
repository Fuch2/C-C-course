## Цели обучения

- Разобраться в теме «fread/fwrite» и её границах применимости.
- Объяснить типичную ошибку, а не только запомнить правильную запись.
- Проверить решение на нормальных и граничных входах.

## Теория

fread и fwrite возвращают число полных элементов, а не всегда число байтов. Вызов fread(buf, 1, n, file) удобен для форматов: результат прямо показывает прочитанные байты. Короткое чтение требует проверки ferror и feof; частичный элемент не следует трактовать как полноценную запись.

Выделите функцию чтения точного количества байтов, которая возвращает статус и не выдаёт частичные данные за успех. После полного разбора проверьте политику лишнего хвоста: запрещён он или содержит следующий пакет. Для записи необходимо проверять и количество элементов, и завершение буферизованного вывода. В проекте бинарного парсера эти проверки отделяют корректный пустой файл формата от обрезанного заголовка.

<Concept title="Ментальная модель">

Чтение — запрос на порцию, а возвращаемое число — подтверждение реально полученного объёма.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>

int main(void) {
    FILE *f=tmpfile();if(!f)return 1;unsigned char data[2]={3,4},copy[2];if(fwrite(data,1,2,f)!=2 || fseek(f,0,SEEK_SET)!=0 || fread(copy,1,2,f)!=2){fclose(f);return 1;}if(fclose(f)!=0)return 1;printf("%u %u\n",(unsigned)copy[0],(unsigned)copy[1]);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
3 4
```

Чтение — запрос на порцию, а возвращаемое число — подтверждение реально полученного объёма. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Успешное чтение одного байта заголовка не означает, что весь заголовок доступен.

## Проект: Парсер бинарного файла

Разберите формат SENS/1 из настоящего бинарного потока FILE*. Заголовок: октет 0 = 83 (S), октет 1 = 78 (N), октет 2 = версия 1, октет 3 = количество записей 0…64. Каждая запись — unsigned 16-bit little-endian измерение. Файл должен содержать ровно 4+2*count байтов. При неверной сигнатуре, версии, количестве, усечении или лишнем хвосте выведите ОШИБКА. При успехе — count и сумму измерений.

Транспорт браузерного теста: stdin содержит n (0…256) и n десятичных байтов 0…255. Адаптер записывает их через fwrite в tmpfile и перемещается к началу. Сам парсер принимает FILE\*, читает fread/fgetc и не использует исходный массив. Это позволяет передать нулевые байты и некорректные файлы через текстовое поле. Реальный файловый формат не содержит транспортного n. Ошибки ввода/вывода также считаются ошибкой. Формат рассчитан на CHAR_BIT=8.

## Краткое резюме

Чтение — запрос на порцию, а возвращаемое число — подтверждение реально полученного объёма. Для применения темы «fread/fwrite» фиксируйте контракт до написания кода. Успешное чтение одного байта заголовка не означает, что весь заголовок доступен. Успешный пример дополняйте граничными тестами; правильный stdout не отменяет требований языка к типам, времени жизни и ресурсам.
