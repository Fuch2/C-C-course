## Байты блоками

`fgets` и `fprintf` работают с текстом: строками, числами в десятичной записи. Но многие данные — изображения, архивы, базы, сохранения игр — это просто байты, и записывать их удобнее блоками, без перевода в текст. Для этого есть две функции:

```c
size_t fread(void *buffer, size_t size, size_t count, FILE *stream);
size_t fwrite(const void *buffer, size_t size, size_t count, FILE *stream);
```

Они читают или пишут до `count` элементов по `size` байтов. Возвращается **число полностью прочитанных или записанных элементов**, а не байтов. Если результат меньше `count`, значит, файл кончился или произошла ошибка — какая именно, скажут `feof` и `ferror`.

Двоичные файлы открывают с буквой `b`: `"rb"`, `"wb"`, `"r+b"`. В Linux и macOS она ни на что не влияет, а в Windows текстовый режим превращает `\r\n` в `\n` при чтении и обратно при записи — и двоичные данные испортятся. Поэтому для байтов `b` пишут всегда.

## Записать и прочитать массив

```c
#include <stdio.h>

int main(void) {
    int scores[] = {120, -7, 4500, 0, 33};
    FILE *f = fopen("scores.bin", "wb");
    if (f == NULL) {
        return 1;
    }
    size_t written = fwrite(scores, sizeof scores[0], 5, f);
    fclose(f);
    printf("записано элементов: %zu\n", written);

    int loaded[10];
    f = fopen("scores.bin", "rb");
    if (f == NULL) {
        return 1;
    }
    size_t got = fread(loaded, sizeof loaded[0], 10, f);   // просим больше, чем есть
    printf("прочитано элементов: %zu, конец файла: %s\n", got, feof(f) ? "да" : "нет");
    fclose(f);
    for (size_t i = 0; i < got; i++) {
        printf("%d ", loaded[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
записано элементов: 5
прочитано элементов: 5, конец файла: да
120 -7 4500 0 33
```

Файл занимает 20 байтов — пять `int` по 4 байта, ровно как они лежали в памяти. Такой «снимок памяти» удобен для временных файлов своей же программы, но не годится для обмена: размер `int`, порядок байтов и выравнивание структур на другой машине могут отличаться. Как описывать переносимые двоичные форматы — в следующем уроке.

## Копирование блоками

Файл копируют кусками фиксированного размера. Важно записывать столько байтов, сколько **прочитано**, а не размер буфера: последний кусок обычно короче.

```c
#include <stdio.h>

int main(void) {
    FILE *src = fopen("source.bin", "wb");
    if (src == NULL) {
        return 1;
    }
    for (int i = 0; i < 300; i++) {
        fputc(i % 256, src);
    }
    fclose(src);

    FILE *in = fopen("source.bin", "rb");
    FILE *out = fopen("copy.bin", "wb");
    if (in == NULL || out == NULL) {
        return 1;
    }
    unsigned char buffer[128];
    size_t n, total = 0;
    int blocks = 0;
    while ((n = fread(buffer, 1, sizeof buffer, in)) > 0) {
        fwrite(buffer, 1, n, out);        // n, а не sizeof buffer
        total += n;
        blocks++;
    }
    fclose(in);
    fclose(out);
    printf("блоков %d, байтов %zu\n", blocks, total);
    return 0;
}
```

Вывод:

```text
блоков 3, байтов 300
```

Здесь `size = 1`, поэтому «элементы» — это байты, и результат `fread` — число байтов. Блоки 128 + 128 + 44: последний неполный. Размер буфера — компромисс: слишком маленький означает много вызовов, слишком большой — лишнюю память; обычно берут от 4 до 64 КБ.

## Позиция в файле: `fseek`, `ftell`, `rewind`

У каждого потока есть **текущая позиция** — номер байта, с которого начнётся следующее чтение или запись. Её можно узнать и изменить:

```c
int fseek(FILE *stream, long offset, int whence);   // 0 — успех
long ftell(FILE *stream);                            // текущая позиция или −1
void rewind(FILE *stream);                           // в начало
```

`whence` задаёт, от чего отсчитывать `offset`: `SEEK_SET` — от начала файла, `SEEK_CUR` — от текущей позиции, `SEEK_END` — от конца. Классический способ узнать размер файла — перейти в конец и спросить позицию:

```c
#include <stdio.h>

int main(void) {
    FILE *f = fopen("data.bin", "wb+");          // запись и чтение
    if (f == NULL) {
        return 1;
    }
    fputs("ABCDEFGHIJ", f);
    fseek(f, 0, SEEK_END);
    printf("размер %ld\n", ftell(f));
    fseek(f, -3, SEEK_END);                        // три байта до конца
    printf("%c", fgetc(f));
    fseek(f, 2, SEEK_SET);                         // третий байт от начала
    printf("%c", fgetc(f));
    fseek(f, 1, SEEK_CUR);                         // пропустить один
    printf("%c\n", fgetc(f));
    rewind(f);
    printf("снова с начала: %c\n", fgetc(f));
    fclose(f);
    return 0;
}
```

Вывод:

```text
размер 10
HCE
снова с начала: A
```

Для текстовых потоков значение `ftell` по стандарту — непрозрачный «маркер», а не номер байта (в Windows из-за `\r\n` они расходятся). Считать размеры и смещения надёжно только в двоичных потоках. И `long` в 32-битных системах ограничивает файл двумя гигабайтами — для больших файлов есть `fseeko`/`ftello` (POSIX) и `fgetpos`/`fsetpos`.

## Файл записей: произвольный доступ

Если все записи одного размера, файл работает как массив на диске: запись номер `i` начинается со смещения `i * sizeof(Record)`. Чтобы прочитать или изменить её, не нужно читать файл целиком — достаточно перейти на нужное место:

```c
#include <stdio.h>

typedef struct {
    int id;
    long long balance;
} Account;

int main(void) {
    FILE *db = fopen("accounts.dat", "w+b");
    if (db == NULL) {
        return 1;
    }
    for (int i = 0; i < 4; i++) {
        Account a = {i + 1, 1000 * (i + 1)};
        fwrite(&a, sizeof a, 1, db);
    }

    Account a;
    fseek(db, 2 * (long)sizeof(Account), SEEK_SET);   // запись номер 2 (третья)
    fread(&a, sizeof a, 1, db);
    a.balance += 500;
    fseek(db, -(long)sizeof(Account), SEEK_CUR);      // назад к началу записи
    fwrite(&a, sizeof a, 1, db);

    rewind(db);
    while (fread(&a, sizeof a, 1, db) == 1) {
        printf("счёт %d: %lld\n", a.id, a.balance);
    }
    fclose(db);
    return 0;
}
```

Вывод:

```text
счёт 1: 1000
счёт 2: 2000
счёт 3: 3500
счёт 4: 4000
```

Между `fread` и `fwrite` в одном потоке стоит `fseek` — без перехода позиции (или `fflush`) переключение между чтением и записью не определено. Так устроены простейшие базы данных: индекс записи превращается в смещение, и любая запись доступна за одно перемещение.

## Временный файл

`tmpfile()` создаёт временный двоичный файл, открытый на запись и чтение (`"wb+"`). Он удаляется сам при закрытии или завершении программы — не нужно придумывать имя и убирать за собой:

```c
#include <stdio.h>

int main(void) {
    FILE *tmp = tmpfile();
    if (tmp == NULL) {
        perror("tmpfile");
        return 1;
    }
    double values[] = {1.5, 2.25, 3.125};
    fwrite(values, sizeof values[0], 3, tmp);
    rewind(tmp);
    double sum = 0, v;
    while (fread(&v, sizeof v, 1, tmp) == 1) {
        sum += v;
    }
    printf("сумма %.3f\n", sum);
    fclose(tmp);                      // файл исчезнет
    return 0;
}
```

Вывод:

```text
сумма 6.875
```

<Concept title="Файл — массив байтов с курсором">

Двоичный поток — это массив байтов на диске и курсор-позиция. `fread` и `fwrite` копируют байты между памятью и файлом и сдвигают курсор, `fseek` двигает его без копирования. Всё остальное — записи фиксированной длины, копирование, размер файла — комбинации этих трёх действий.

</Concept>

## Частые ошибки

<CommonMistake title="Результат fread — элементы, а не байты">

`fread(records, sizeof(Record), 10, f)` вернёт число записей, например 3. Сравнение результата с `10 * sizeof(Record)` никогда не выполнится.

</CommonMistake>

<CommonMistake title="Запись размера буфера вместо прочитанного">

`fwrite(buffer, 1, sizeof buffer, out)` после короткого последнего `fread` допишет в копию мусор из прошлых блоков. Записывайте ровно `n` байтов.

</CommonMistake>

<CommonMistake title="Двоичные данные в текстовом режиме">

`fopen(name, "r")` для изображения работает в Linux, но портит файл в Windows. Для двоичных данных — `"rb"`, `"wb"`.

</CommonMistake>

<CommonMistake title="Структура с указателем в файле">

`fwrite` структуры с полем `char *name` запишет **адрес** строки, а не её символы. При чтении в другой программе этот адрес бессмыслен. В файл пишут сами данные — массивы фиксированного размера или строки с длиной.

</CommonMistake>

## Итоги

- `fread` и `fwrite` копируют `count` элементов по `size` байтов и возвращают число **полных элементов**; меньшее число означает конец файла или ошибку.
- Двоичные файлы открывают с буквой `b`: в Windows текстовый режим меняет байты `\r\n`.
- Массив, записанный `fwrite`, — снимок памяти: годится для своих временных файлов, но не для обмена между системами.
- При копировании блоками записывают столько байтов, сколько прочитано.
- `fseek` с `SEEK_SET`, `SEEK_CUR`, `SEEK_END` меняет позицию, `ftell` сообщает её; размер файла — `fseek` в конец и `ftell` (для двоичных потоков).
- Записи фиксированного размера дают произвольный доступ: запись `i` — по смещению `i * sizeof(Record)`. Между чтением и записью — `fseek` или `fflush`.
- `tmpfile()` создаёт временный двоичный файл, который удаляется сам.
