## Цели обучения

- Разобраться в теме «volatile» и её границах применимости.
- Объяснить типичную ошибку, а не только запомнить правильную запись.
- Проверить решение на нормальных и граничных входах.

## Теория

volatile сообщает реализации, что доступы к объекту имеют наблюдаемое значение, например при работе с отображённым аппаратным регистром. Конкретные гарантии ширины и порядка доступа определяются компилятором и платформой. Этот квалификатор не заменяет атомики и не обеспечивает межпоточную синхронизацию.

При чтении регистра значение может измениться между двумя доступами. Снимок в обычную переменную полезен, если дальнейший расчёт должен использовать одно наблюдение. Но чтение некоторых регистров само имеет побочный эффект, поэтому нельзя добавлять его «для удобства отладки» без документации устройства. В учебной программе volatile-объект находится в обычной памяти: это демонстрирует синтаксис, а не эмулирует реальное оборудование.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>

int main(void) {
    volatile unsigned status=2;unsigned snapshot=status;status=4;printf("%u %u\n",snapshot,status);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
2 4
```

Каждое чтение — отдельное наблюдение прибора; снимок хранит результат одного наблюдения. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. volatile не устраняет data race и не превращает read-modify-write в атомарную операцию.

## Краткое резюме

Каждое чтение — отдельное наблюдение прибора; снимок хранит результат одного наблюдения. Для применения темы «volatile» фиксируйте контракт до написания кода. volatile не устраняет data race и не превращает read-modify-write в атомарную операцию. Успешный пример дополняйте граничными тестами; правильный stdout не отменяет требований языка к типам, времени жизни и ресурсам.
