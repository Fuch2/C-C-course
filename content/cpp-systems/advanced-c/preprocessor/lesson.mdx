## Программа до компилятора

Строки `#include` и `#define` вы пишете с первого урока, а в этом разделе встретили `#ifndef` и `#endif`. Все они — команды **препроцессора**: программы, которая обрабатывает текст `.c` файла до того, как его увидит компилятор. Препроцессор:

- склеивает строки, разорванные обратной косой чертой;
- заменяет комментарии пробелами;
- выполняет **директивы** — строки, начинающиеся с `#`: вставляет заголовки, запоминает и раскрывает макросы, выбрасывает части текста.

Результат — единица трансляции: чистый текст на C без директив, макросов и комментариев. Посмотреть его можно командой `gcc -E main.c` (подробнее — в модуле «Инструменты разработчика»).

Главное, что нужно понять про препроцессор: **он не знает языка C**. Для него нет типов, функций, областей видимости и выражений — только строки и **токены** (лексемы). Отсюда и сила препроцессора, и почти все его ловушки, которым посвящены следующие уроки.

## Этапы обработки текста

Стандарт описывает обработку исходного текста как последовательность фаз. Для препроцессора важны три, и именно в таком порядке:

1. **Склейка строк.** Обратная косая черта `\` в самом конце строки удаляется вместе с переводом строки — две физические строки становятся одной логической.
2. **Токены и комментарии.** Текст разбивается на токены, а каждый комментарий заменяется **одним пробелом**.
3. **Директивы и макросы.** Выполняются директивы, раскрываются макросы, вставляются заголовки.

```c
#include <stdio.h>

#define GREETING "Привет, " \
                 "мир"

int main(void) {
    int/* комментарий */value = 4;
    printf("%s: %d\n", GREETING, value);
    return 0;
}
```

Вывод:

```text
Привет, мир: 4
```

Определение `GREETING` занимает две физические строки, но после склейки это одна директива. Комментарий между `int` и `value` превратился в пробел, поэтому получилось `int value`, а не `intvalue`. Две строки `"Привет, " "мир"` подряд склеивает уже компилятор — это следующая фаза: соседние строковые литералы объединяются в один.

Порядок фаз объясняет неприятный сюрприз. Склейка строк выполняется **раньше** удаления комментариев, поэтому обратная косая черта в конце однострочного комментария продолжает комментарий на следующую строку:

```c
#include <stdio.h>

int main(void) {
    int total = 10;
    // Предупреждение: multi-line comment — путь к файлу C:\temp\
    total = 20;
    printf("%d\n", total);
    return 0;
}
```

Вывод:

```text
10
```

Строка `total = 20;` стала частью комментария и не выполнилась. GCC предупреждает об этом (`-Wcomment` входит в `-Wall`), но предупреждение легко пропустить.

## Директивы

Директива — строка, первый непробельный символ которой `#`. Пробелы допустимы и до `#`, и после него: `  #  define N 10` — тоже директива. Директива занимает одну логическую строку и заканчивается переводом строки, а не точкой с запятой.

| Директива                                                                       | Что делает                                    |
| ------------------------------------------------------------------------------- | --------------------------------------------- |
| `#include`                                                                      | вставляет текст файла                         |
| `#embed` (C23)                                                                  | вставляет байты файла как список чисел        |
| `#define`, `#undef`                                                             | определяет и удаляет макрос                   |
| `#if`, `#ifdef`, `#ifndef`, `#elif`, `#elifdef`, `#elifndef`, `#else`, `#endif` | оставляет или выбрасывает часть текста        |
| `#error`, `#warning` (C23)                                                      | останавливает компиляцию или предупреждает    |
| `#line`                                                                         | меняет номер строки и имя файла для сообщений |
| `#pragma`                                                                       | особая команда конкретного компилятора        |
| `#` на пустой строке                                                            | ничего не делает                              |

Директивы должны начинать строку: в записи `x = 5; #define N 10` символ `#` — обычный токен, и компилятор сообщит синтаксическую ошибку.

## Токены, а не текст

Препроцессор работает с токенами: идентификаторами, числами, строковыми и символьными литералами, знаками операций. Макрос заменяется, только если его имя — **целый идентификатор**. Внутри строкового литерала или как часть другого имени — нет:

```c
#include <stdio.h>

#define LIMIT 10

int main(void) {
    int LIMITED = 3;                          // другой идентификатор
    printf("LIMIT = %d\n", LIMIT);            // в строке замены нет
    printf("LIMITED = %d\n", LIMITED);
    return 0;
}
```

Вывод:

```text
LIMIT = 10
LIMITED = 3
```

Токены выделяются **жадно**: из оставшегося текста берётся самый длинный токен, какой возможно. Поэтому `a+++b` — это `a ++ + b`, а не `a + ++b`. И поэтому опасна запись

```text
average = total/*count;        // «total, делённое на *count»?
```

Здесь `/*` — начало комментария, который поглотит всё до ближайшего `*/`. Ставьте пробелы вокруг операций: `total / *count`.

## Предопределённые макросы

Некоторые макросы определены всегда. Их значения подставляет сам препроцессор:

| Макрос                 | Значение                                                       |
| ---------------------- | -------------------------------------------------------------- |
| `__FILE__`             | имя текущего файла — строковый литерал                         |
| `__LINE__`             | номер текущей строки — целое число                             |
| `__DATE__`, `__TIME__` | дата и время компиляции — строки `"Oct 17 2026"`, `"14:05:31"` |
| `__STDC__`             | `1`, если компилятор соответствует стандарту                   |
| `__STDC_VERSION__`     | версия стандарта: `202311L` для C23, `201710L` для C17         |

```c
#include <stdio.h>

int main(void) {
    printf("файл %s, строка %d\n", __FILE__, __LINE__);
    printf("функция %s\n", __func__);
    printf("новее C17: %s\n", __STDC_VERSION__ > 201710L ? "да" : "нет");
    return 0;
}
```

Вывод:

```text
файл main.c, строка 4
функция main
новее C17: да
```

Само значение `__STDC_VERSION__` здесь не печатается намеренно: для C23 Clang 19 выдаёт окончательное `202311`, а GCC 14 — промежуточное `202000`. Поэтому версию сравнивают, а не проверяют на равенство.

`__func__` похож на макрос, но им не является. Препроцессор не знает, что такое функция, — поэтому имя текущей функции подставляет компилятор: `__func__` ведёт себя как локальный массив `static const char __func__[] = "main";`.

Чаще всего эти имена используют в диагностике: сообщение `main.c:42: не удалось открыть файл` сразу показывает, где искать. В уроке о макросах с параметрами вы напишете макрос, который подставляет файл и строку автоматически.

## `#line`

Директива `#line` меняет номер следующей строки, а с необязательным вторым аргументом — и имя файла:

```c
#include <stdio.h>

int main(void) {
#line 100 "grammar.y"
    printf("%s:%d\n", __FILE__, __LINE__);
    printf("%s:%d\n", __FILE__, __LINE__);
    return 0;
}
```

Вывод:

```text
grammar.y:100
grammar.y:101
```

Вручную её почти не пишут. Ею пользуются генераторы кода — например, генераторы синтаксических анализаторов bison и flex создают `.c` файл из описания грамматики и расставляют `#line` так, чтобы ошибки компиляции указывали на строку исходной грамматики, а не сгенерированного кода.

## `#error` и `#pragma`

`#error` прекращает компиляцию и печатает сообщение. Сама по себе она бесполезна, но вместе с условной компиляцией проверяет настройки сборки: «эта программа требует C11», «не задан размер буфера».

```c
#include <stdio.h>

#error "Модуль ещё не перенесён на эту платформу"  // Ошибка компиляции

int main(void) {
    return 0;
}
```

`#warning` (стандартная с C23, а раньше — расширение GCC и Clang) делает то же, но не останавливает сборку: `#warning "устаревший режим, будет удалён"`.

`#pragma` передаёт компилятору особую команду. Стандарт определяет лишь несколько прагм, остальные — расширения конкретных компиляторов: `#pragma once`, `#pragma pack`, `#pragma GCC diagnostic`. Незнакомую прагму компилятор обязан проигнорировать, но с `-Wall` предупредит о ней.

## `#embed`: файл внутри программы

Иногда данные нужно встроить прямо в программу: иконку, шрифт, таблицу, сертификат. Раньше файл превращали в C-код внешней утилитой (`xxd -i logo.png > logo.h`), и такой «код» из миллионов чисел медленно компилировался. C23 добавил директиву `#embed`: препроцессор сам читает файл и подставляет его байты как числа через запятую:

```c resources.c
#include <stddef.h>

static const unsigned char LOGO[] = {
#embed "logo.png"
};
static const size_t LOGO_SIZE = sizeof LOGO;
```

У директивы есть параметры: `limit(64)` — взять не больше 64 байт, `if_empty(0)` — что подставить для пустого файла. `#embed` поддерживают Clang 19 и GCC 15; GCC 14 из песочницы курса её ещё не знает, поэтому пример здесь только для чтения. Проверить поддержку можно выражением `__has_embed("logo.png")` внутри `#if`.

## Как увидеть результат

Команда `gcc -E main.c` печатает единицу трансляции. В ней будут строки вида

```text
# 1 "main.c"
# 1 "/usr/include/stdio.h" 1 3 4
```

— это **маркеры строк**: так препроцессор сообщает компилятору, из какого файла и с какой строки пришёл следующий текст, чтобы сообщения об ошибках указывали на настоящие места. Флаг `-P` убирает маркеры, и вывод становится похож на обычную программу.

<Concept title="Препроцессор — текстовый процессор">

Препроцессор не проверяет, что результат — правильная программа на C. Он режет текст на токены и выполняет команды: вставить, заменить, выбросить. Ошибки, которые он допустил «по вашей просьбе», компилятор найдёт уже в получившемся тексте — и сообщение будет ссылаться на место, где макрос использован, а не на место, где он определён.

</Concept>

## Частые ошибки

<CommonMistake title="Обратная косая черта в конце комментария">

`// каталог C:\data\` склеит комментарий со следующей строкой, и она исчезнет. Не заканчивайте комментарии символом `\`.

</CommonMistake>

<CommonMistake title="Пробел после обратной косой черты">

Склейка работает, только если `\` — **последний** символ строки. Пробел после неё ломает многострочный макрос; GCC предупреждает: `backslash and newline separated by space`.

</CommonMistake>

<CommonMistake title="Точка с запятой после директивы">

`#include <stdio.h>;` и `#define SIZE 10;` — частая привычка из обычного кода. В первом случае GCC предупредит о лишних токенах, во втором точка с запятой станет частью макроса и всплывёт в каждом месте использования.

</CommonMistake>

<CommonMistake title="/* внутри выражения">

`x = y/*p;` открывает комментарий. Пробелы вокруг операций: `x = y / *p;`.

</CommonMistake>

3. **Токенизатор** — жадное разбиение строки C на токены.

## Итоги

- Препроцессор обрабатывает текст до компилятора: склеивает строки, заменяет комментарии пробелами, выполняет директивы и раскрывает макросы. Языка C он не знает.
- Склейка строк выполняется раньше удаления комментариев: `\` в конце `//`-комментария продолжает его на следующую строку.
- Директива — строка, начинающаяся с `#` (пробелы допустимы); она заканчивается переводом строки.
- Макросы заменяются только целыми идентификаторами, не внутри строк и не внутри других имён. Токены выделяются жадно: `a+++b` — это `a ++ + b`.
- `__FILE__`, `__LINE__`, `__DATE__`, `__TIME__`, `__STDC_VERSION__` — предопределённые макросы; `__func__` подставляет компилятор.
- `#line` меняет номер строки и имя файла, `#error` останавливает компиляцию, `#warning` (C23) предупреждает, `#pragma` — команда конкретного компилятора.
- `#embed` (C23) встраивает байты файла в массив без внешних утилит.
