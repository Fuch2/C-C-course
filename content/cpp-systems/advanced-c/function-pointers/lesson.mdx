## Функция как значение

Переменная может хранить число, адрес массива или структуру. А может — **адрес функции**. Тогда «какую функцию вызвать» становится данными: его можно передать в другую функцию, вернуть, положить в массив или структуру. Вы уже пользовались этим, когда передавали функцию сравнения в `qsort`. Теперь разберём механизм полностью.

Код функции лежит в памяти, и у него есть адрес. Имя функции в выражении (кроме операндов `&` и `sizeof`) превращается в **указатель на функцию** — так же, как имя массива превращается в указатель на первый элемент:

```c
#include <stdio.h>

int add(int a, int b) {
    return a + b;
}

int multiply(int a, int b) {
    return a * b;
}

int main(void) {
    int (*op)(int, int);       // указатель на функцию (int, int) -> int
    op = add;
    printf("%d\n", op(6, 7));
    op = multiply;             // тот же вызов — другая функция
    printf("%d\n", op(6, 7));
    return 0;
}
```

Вывод:

```text
13
42
```

Строка `op(6, 7)` встречается дважды и вызывает разные функции: выбор сделан не при компиляции, а во время работы — в момент присваивания.

## Синтаксис объявления

```c
int (*op)(int, int);
```

Читается от имени: `op` — указатель (`*op` в скобках) на функцию, принимающую `(int, int)` и возвращающую `int`. Скобки вокруг `*op` обязательны. Без них

```c
int *op(int, int);
```

— это прототип **функции** `op`, возвращающей `int *`. Правило чтения сложных объявлений: начинайте с имени, идите вправо, пока не встретите закрывающую скобку, затем влево, затем выходите из скобок и повторяйте.

Присваивать и вызывать можно двумя равнозначными способами:

| Запись      | Равнозначная запись | Смысл                        |
| ----------- | ------------------- | ---------------------------- |
| `op = add;` | `op = &add;`        | запомнить адрес функции      |
| `op(6, 7)`  | `(*op)(6, 7)`       | вызвать функцию по указателю |

Короткие формы встречаются чаще. Длинные подчёркивают, что `op` — указатель, а не имя функции.

Тип указателя должен **точно** совпадать с типом функции. Присваивание функции другого типа — предупреждение `incompatible pointer type`, а вызов через указатель неподходящего типа — неопределённое поведение, даже если «похоже». Функция `double half(double)` не вызывается правильно через `int (*)(int)`: аргумент передаётся не в том регистре.

## `typedef` делает объявления читаемыми

Указатели на функции быстро становятся нечитаемыми. Вот настоящий прототип стандартной функции `signal`, которая устанавливает обработчик сигнала и возвращает предыдущий:

```c
void (*signal(int sig, void (*handler)(int)))(int);
```

С `typedef` для **типа функции** то же объявление читается с первого взгляда:

```c
typedef void SignalHandler(int);          // тип: функция (int) -> void

SignalHandler *signal(int sig, SignalHandler *handler);
```

`signal` принимает номер сигнала и указатель на обработчик и возвращает указатель на обработчик. Встречается и другой стиль — синоним сразу для указателя: `typedef void (*SignalHandlerPtr)(int);`. Первый вариант удобнее: звёздочка остаётся видна в каждом объявлении, и читатель не забудет, что имеет дело с указателем.

## Таблица функций

Указатели на функции можно положить в массив — и выбирать действие по индексу или по ключу вместо длинного `switch`:

```c
#include <stdio.h>

typedef int Operation(int a, int b);

static int op_add(int a, int b) { return a + b; }
static int op_sub(int a, int b) { return a - b; }
static int op_mul(int a, int b) { return a * b; }
static int op_max(int a, int b) { return a > b ? a : b; }

static const struct {
    char symbol;
    Operation *apply;
} OPERATIONS[] = {
    {'+', op_add},
    {'-', op_sub},
    {'*', op_mul},
    {'M', op_max},
};

static Operation *find_operation(char symbol) {
    for (size_t i = 0; i < sizeof OPERATIONS / sizeof OPERATIONS[0]; i++) {
        if (OPERATIONS[i].symbol == symbol) {
            return OPERATIONS[i].apply;
        }
    }
    return NULL;
}

int main(void) {
    const char *program = "+-*M/";
    for (const char *p = program; *p != '\0'; p++) {
        Operation *op = find_operation(*p);
        if (op == NULL) {
            printf("%c: нет такой операции\n", *p);
        } else {
            printf("%c: %d\n", *p, op(12, 5));
        }
    }
    return 0;
}
```

Вывод:

```text
+: 17
-: 7
*: 60
M: 12
/: нет такой операции
```

Новая операция — одна строка в таблице, а код поиска и вызова не меняется. Так устроены интерпретаторы команд, разборщики аргументов командной строки и обработчики сетевых сообщений. Обратите внимание на `NULL`: указатель на функцию может быть нулевым, и это удобный способ сказать «функции нет». Вызов нулевого указателя — аварийное завершение, поэтому его проверяют перед вызовом.

## Функция как параметр

Функция, которая принимает другую функцию, отделяет «как обойти данные» от «что с ними сделать»:

```c
#include <stdio.h>

typedef int Transform(int x);

static void apply_all(int *values, int count, Transform *f) {
    for (int i = 0; i < count; i++) {
        values[i] = f(values[i]);
    }
}

static int square(int x) { return x * x; }
static int negate(int x) { return -x; }

int main(void) {
    int data[] = {1, 2, 3, 4};
    apply_all(data, 4, square);
    apply_all(data, 4, negate);
    for (int i = 0; i < 4; i++) {
        printf("%d ", data[i]);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
-1 -4 -9 -16
```

Переданную так функцию называют **функцией обратного вызова** (callback): `apply_all` сама вызывает её для каждого элемента. Этой идее — и тому, как передать в callback дополнительные данные, — посвящён следующий урок.

## Функция, возвращающая функцию

Функция может вернуть указатель на функцию. Без `typedef` объявление пугает, с ним — обычное:

```c
#include <stdio.h>

typedef double Formula(double x);

static double to_fahrenheit(double c) { return c * 9 / 5 + 32; }
static double to_kelvin(double c) { return c + 273.15; }

// Без typedef: double (*choose_formula(char unit))(double)
static Formula *choose_formula(char unit) {
    switch (unit) {
    case 'F':
        return to_fahrenheit;
    case 'K':
        return to_kelvin;
    default:
        return NULL;
    }
}

int main(void) {
    const char units[] = {'F', 'K', 'R'};
    for (int i = 0; i < 3; i++) {
        Formula *f = choose_formula(units[i]);
        if (f != NULL) {
            printf("100 C = %.2f %c\n", f(100), units[i]);
        } else {
            printf("шкала %c неизвестна\n", units[i]);
        }
    }
    return 0;
}
```

Вывод:

```text
100 C = 212.00 F
100 C = 373.15 K
шкала R неизвестна
```

## Структура с функциями: интерфейс в стиле C

Поле структуры тоже может быть указателем на функцию. Тогда структура описывает не только данные, но и **поведение** — разные экземпляры ведут себя по-разному, а код, который ими пользуется, одинаков:

```c
#include <stdio.h>

struct Logger {
    const char *name;
    void (*write)(const char *message);
};

static void write_plain(const char *message) {
    printf("%s\n", message);
}

static void write_framed(const char *message) {
    printf("[ %s ]\n", message);
}

static void report(const struct Logger *log, const char *message) {
    printf("%s> ", log->name);
    log->write(message);
}

int main(void) {
    const struct Logger loggers[] = {
        {"консоль", write_plain},
        {"рамка", write_framed},
    };
    for (int i = 0; i < 2; i++) {
        report(&loggers[i], "сервер запущен");
    }
    return 0;
}
```

Вывод:

```text
консоль> сервер запущен
рамка> [ сервер запущен ]
```

Функция `report` ничего не знает о конкретных способах записи — она вызывает то, что лежит в поле `write`. Так устроены драйверы в ядре Linux (структура `file_operations` с указателями `read`, `write`, `open`), потоки ввода-вывода в стандартной библиотеке и виртуальные функции в C++: компилятор C++ строит для каждого класса похожую таблицу указателей.

<Concept title="Выбор функции — тоже данные">

Без указателей на функции выбор поведения записывается в коде: `if`, `switch`. С ними выбор хранится в переменной, таблице или поле структуры и может меняться во время работы. Код, который вызывает функцию по указателю, не зависит от того, какие функции существуют, — новые варианты добавляются без его изменения.

</Concept>

## Частые ошибки

<CommonMistake title="Звёздочка без скобок">

`int *compare(int, int);` — функция, возвращающая указатель. Указатель на функцию: `int (*compare)(int, int);`. Если путаетесь, заведите `typedef` типа функции.

</CommonMistake>

<CommonMistake title="Имя функции без вызова">

`if (is_ready)` вместо `if (is_ready())` проверяет адрес функции, который никогда не равен нулю, — условие всегда истинно. GCC предупреждает: `the address of 'is_ready' will always evaluate as 'true'`.

</CommonMistake>

<CommonMistake title="Приведение функции к чужому типу">

Функция сравнения для `qsort` с сигнатурой `int cmp(const int *, const int *)`, приведённая к `int (*)(const void *, const void *)`, «работает», но формально это неопределённое поведение. Пишите функцию ровно того типа, который ожидается, и приводите указатели уже внутри неё.

</CommonMistake>

<CommonMistake title="Вызов нулевого указателя">

Необязательный обработчик хранится как `NULL`. Перед вызовом проверяйте: `if (handler != NULL) handler(event);`.

</CommonMistake>

## Итоги

- Имя функции в выражении превращается в указатель на неё. Указатель на функцию можно хранить, передавать, возвращать и класть в массивы и структуры.
- Объявление: `тип (*имя)(параметры);` — скобки вокруг `*имя` обязательны. `f(x)` и `(*f)(x)`, `p = f` и `p = &f` равнозначны.
- Тип указателя должен точно совпадать с типом функции; вызов через чужой тип — неопределённое поведение.
- `typedef` типа функции (`typedef int Operation(int, int);`) делает объявления читаемыми.
- Таблица функций заменяет длинные `switch`: новое действие — новая строка таблицы.
- Структура с указателями на функции задаёт поведение объекта — так устроены драйверы, потоки и виртуальные функции.
- Нулевой указатель на функцию означает «функции нет»; перед вызовом его проверяют.
