- Разобраться в теме «const» и её границах применимости.

- Проверить решение на нормальных и граничных входах.

## Теория

const ограничивает изменение через квалифицированное выражение. const int *p запрещает запись в int через p, но разрешает менять сам указатель; int *const p фиксирует указатель. Интерфейс чтения массива должен принимать const int \*, чтобы компилятор обнаруживал случайную запись.

Квалификатор не делает память физически защищённой и не гарантирует константное выражение C17. Изменение объекта, определённого как const, через снявший квалификатор cast имеет неопределённое поведение. Если исходный объект изменяемый, другой допустимый указатель может его менять: const-view не означает, что значение никогда не меняется. Для дизайна API полезнее явно сформулировать, кто имеет право записи и как долго действителен указатель.

<Concept title="Ментальная модель">

const — разрешение на конкретном пути доступа, а не универсальная заморозка всех путей.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>

int main(void) {
    int sample=5;const int *view=&sample;sample=6;printf("%d\n",*view);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
6
```

## Краткое резюме

const — разрешение на конкретном пути доступа, а не универсальная заморозка всех путей. Для применения темы «const» фиксируйте контракт до написания кода. Приведение типа не делает законной запись в объект, который был определён const. Успешный пример дополняйте граничными тестами; правильный stdout не отменяет требований языка к типам, времени жизни и ресурсам.
