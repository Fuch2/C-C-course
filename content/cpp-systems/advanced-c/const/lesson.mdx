## Что уже известно

Слово `const` встречалось вам дважды. В «Основах C» — как способ дать имя числу: `const int MAX_USERS = 100;`. В модуле о памяти — как обещание в интерфейсе функции: `size_t strlen(const char *s)` не изменит строку, а `const char *const NAMES[]` — таблица, в которой нельзя заменить ни указатель, ни символы.

Этот урок — о том, что осталось за кадром: почему в C `const`-переменная — не настоящая константа, что даёт `constexpr` из C23, как константы живут в программе из нескольких файлов, чем опасен `typedef` указателя и что означает второй квалификатор указателей — `restrict`.

## Константный объект — ещё не константа

В C `const int LIMIT = 2;` — это **переменная, которую нельзя менять**, а не константа в смысле языка. Там, где стандарт требует **константного выражения** — значения, известного при компиляции, — `const`-переменная не подходит:

```c
#include <stdio.h>

int main(void) {
    const int LIMIT = 2;
    int command = 2;
    switch (command) {
    case LIMIT:                  // Ошибка компиляции: case label does not reduce to an integer constant
        puts("предел");
        break;
    default:
        puts("другое");
    }
    return 0;
}
```

Так поступает GCC. Clang такой код принимает — как расширение GNU, с предупреждением `expression is not an integer constant expression; folding it to a constant is a GNU extension`. Но по стандарту это не константное выражение, и переносимая программа на это не полагается.

То же с размером массива вне функций:

```c
#include <stdio.h>

const int SIZE = 4;
int table[SIZE];                 // Ошибка компиляции: variably modified 'table' at file scope

int main(void) {
    printf("%zu\n", sizeof table);
    return 0;
}
```

Внутри функции запись `int buffer[SIZE];` компилируется — но создаёт **массив переменной длины** (VLA): компилятор считает, что размер может стать известен только во время работы. Отсюда странная ошибка при попытке его инициализировать:

```c
#include <stdio.h>

int main(void) {
    const int n = 4;
    int counts[n] = {0};         // Ошибка компиляции: variable-sized object may not be initialized except with an empty initializer
    printf("%d\n", counts[0]);
    return 0;
}
```

Константные выражения нужны в метках `case`, в размерах массивов вне функций и в структурах, в ширине битовых полей, в директивах `#if` и в `static_assert`. В C++ `const int` с инициализатором-константой считается константным выражением — это одно из заметных различий языков. Сорок лет у C не было «настоящих» именованных констант, кроме `enum` и `#define`; C23 наконец добавил `constexpr`.

## `constexpr` — константа, известная при компиляции

Объект `constexpr` вычисляется при компиляции и годится везде, где нужно константное выражение — и при этом остаётся обычным объектом с типом и областью видимости:

```c
#include <stdio.h>

constexpr int SIZE = 4;
constexpr double TAX_RATE = 0.2;
constexpr int PRIMES[] = {2, 3, 5, 7};

static int table[SIZE];                  // размер массива вне функций — можно

int main(void) {
    int counts[SIZE] = {0};              // обычный массив, инициализация разрешена
    int command = 2;
    switch (command) {
    case SIZE / 2:                       // метка case — можно
        counts[1]++;
        break;
    default:
        break;
    }
    printf("%zu %d %.1f %d\n", sizeof table, counts[1], 100 * TAX_RATE, PRIMES[3]);
    return 0;
}
```

Вывод:

```text
16 1 20.0 7
```

`constexpr` в C намеренно проще, чем одноимённое слово в C++. Правил четыре, и все проверяет компилятор:

1. **Инициализатор — константное выражение.** `constexpr int N = read_count();` — ошибка: `initializer element is not constant`.
2. **Значение должно быть представимо точно.** `constexpr float F = 0.1;` — ошибка: `double` 0.1 нельзя без потерь записать во `float`. `constexpr unsigned char B = 300;` — тоже ошибка. Неявное округление, которое `const` молча допускает, здесь запрещено. По той же причине на платформах со знаковым `char` (x86-64) Clang не принимает `constexpr char S[] = "привет";`: байты UTF-8 больше 127 не помещаются в знаковый `char`. На ARM `char` беззнаковый, и та же строка компилируется, — для переносимого кода такие массивы объявляют `constexpr unsigned char`.
3. **Указатель может быть только нулевым**: `constexpr int *P = nullptr;` — можно, адрес переменной — нельзя.
4. **Только объекты.** Функций `constexpr` в C нет — в отличие от C++.

## `enum` — целая константа до C23

До C23 настоящие целые константы давал только `enum`, и в существующем коде вы встретите этот приём постоянно. Перечисление не обязано описывать «варианты»: безымянный `enum` — стандартный (и до C23 единственный) способ завести типизированную целую константу:

```c
#include <stdio.h>

enum { BUFFER_SIZE = 8, LIMIT = 2 };

static int history[BUFFER_SIZE];        // размер массива вне функций — можно

int main(void) {
    int counts[BUFFER_SIZE] = {0};      // обычный массив, инициализация разрешена
    int command = 2;
    switch (command) {
    case LIMIT:                         // метка case — можно
        counts[LIMIT]++;
        break;
    default:
        break;
    }
    printf("%d %zu %zu\n", counts[LIMIT], sizeof counts, sizeof history);
    return 0;
}
```

Вывод:

```text
1 32 32
```

У констант `enum` есть область видимости (их можно объявить внутри функции), они видны в отладчике и не требуют памяти. Ограничения: тип по умолчанию `int`, поэтому для дробных чисел, строк и больших значений `enum` не подходит; и препроцессор их не знает, так что в `#if` нужен `#define`. Ни `constexpr`, ни `enum` препроцессор не видит: он работает до компиляции.

| Нужно                                         | C23                    | Код для C17 и старше  |
| --------------------------------------------- | ---------------------- | --------------------- |
| целая константа: размер массива, `case`, флаг | `constexpr` или `enum` | `enum`                |
| дробное число, небольшой массив чисел         | `constexpr`            | `static const` объект |
| строка, таблица указателей, структура         | `static const` объект  | `static const` объект |
| значение для `#if` или флага сборки `-D`      | `#define`              | `#define`             |

`enum` остаётся лучшим выбором для набора связанных значений (состояния, коды команд), а `constexpr` — для отдельной константы любого арифметического типа.

## Константы и несколько файлов

`const`-переменная вне функций в C имеет **внешнее** связывание, как любая глобальная переменная. Поэтому определение в заголовке

```c config.h
const double TAX_RATE = 0.2;
```

даст `multiple definition of 'TAX_RATE'`, как только заголовок подключат два файла. (В C++ `const` на уровне файла подразумевает внутреннее связывание, и там такой заголовок работает — ещё одна ловушка для тех, кто переходит между языками.)

Правильных вариантов два:

```c config.h
static const double TAX_RATE = 0.2;           // своя копия в каждом файле
extern const char *const MONTH_NAMES[12];     // объявление общей таблицы
```

```c config.c
#include "config.h"

const char *const MONTH_NAMES[12] = {
    "январь", "февраль", "март", "апрель", "май", "июнь",
    "июль", "август", "сентябрь", "октябрь", "ноябрь", "декабрь",
};
```

`static const` подходит для отдельных чисел: копия занимает несколько байтов, а чаще компилятор вообще подставляет значение прямо в код. Большую таблицу так размножать не стоит — её объявляют `extern const` и определяют один раз.

В C23 есть и третий вариант: `constexpr` на уровне файла имеет **внутреннее** связывание, как `static`. Строку `constexpr double TAX_RATE = 0.2;` можно положить в заголовок и подключать в любое число файлов — каждый получит свою константу, и линковщик не пожалуется.

## Таблицы вместо вычислений

`static const` массивы — удобный способ заменить ветвления и вычисления поиском по таблице. Компилятор помещает их в память только для чтения вместе со строковыми литералами:

```c
#include <stdio.h>

static const int DAYS_IN_MONTH[12] = {31, 28, 31, 30, 31, 30, 31, 31, 30, 31, 30, 31};

static int is_leap(int year) {
    return (year % 4 == 0 && year % 100 != 0) || year % 400 == 0;
}

static int day_of_year(int day, int month, int year) {
    int result = day;
    for (int m = 0; m < month - 1; m++) {
        result += DAYS_IN_MONTH[m];
    }
    if (month > 2 && is_leap(year)) {
        result++;
    }
    return result;
}

int main(void) {
    printf("%d %d %d\n", day_of_year(1, 3, 2023), day_of_year(1, 3, 2024), day_of_year(31, 12, 2024));
    return 0;
}
```

Вывод:

```text
60 61 366
```

Таблица описывает данные один раз и наглядно, а `const` гарантирует, что никакая функция случайно не «исправит» февраль на 29 дней.

## `const` и `typedef`

`typedef` указателя и `const` вместе дают неожиданный результат. `const` относится к **типу целиком**, а целый тип здесь — указатель:

```c
#include <stdio.h>

typedef char *String;

int main(void) {
    char word[] = "кот";
    char other[] = "пёс";
    const String s = word;     // это char *const s, а не const char *s
    s[0] = 'K';                // можно: меняются символы
    s = other;                 // Ошибка компиляции: assignment of read-only variable 's'
    printf("%s\n", s);
    return 0;
}
```

Хотели запретить изменение строки, а получили запрет на перестановку указателя. Чтобы описать «указатель на константные символы», нужен отдельный тип: `typedef const char *ConstString;`. Отсюда общее правило: **не прячьте указатели за `typedef`**, кроме непрозрачных типов вроде `FILE *`, где пользователь и так не заглядывает внутрь.

## Где `const` бессмыслен

У параметра, который передаётся **по значению**, `const` ничего не обещает вызывающему коду: функция и так получает копию. В объявлении `void print_row(const int width);` его можно не писать — такой прототип совместим с определением без `const`. В определении он иногда полезен как защита от случайного изменения параметра внутри функции.

У возвращаемого значения скалярного типа `const` бессмыслен совсем, и `-Wextra` об этом предупреждает:

```c
#include <stdio.h>

// Предупреждение: type qualifiers ignored on function return type
const int answer(void) {
    return 42;
}

int main(void) {
    int x = answer();
    x++;                       // копия — обычная переменная
    printf("%d\n", x);
    return 0;
}
```

Вывод:

```text
43
```

## `const` в полях структуры

Поле можно объявить `const`: тогда его значение задаётся только при инициализации. Это удобно для идентификаторов, которые не должны меняться:

```c
#include <stdio.h>

struct Account {
    const int id;
    double balance;
};

int main(void) {
    struct Account a = {17, 100.0};
    a.balance += 50.0;           // можно
    a.id = 18;                   // Ошибка компиляции: assignment of read-only member 'id'
    printf("%d %.1f\n", a.id, a.balance);
    return 0;
}
```

Но у такого поля есть цена: структуру целиком больше нельзя присвоить (`a = b;` — тоже ошибка), а значит, нельзя переставлять элементы массива таких структур обычным обменом. Поэтому поля `const` используют редко — чаще защищают структуру целиком через `const struct Account *` в интерфейсе.

## `restrict`: обещание об отсутствии пересечений

Кроме `const` и `volatile` (ему посвящён отдельный урок), в C99 появился третий квалификатор — `restrict`. Он применяется только к указателям и означает: **пока жив этот указатель, к объекту обращаются только через него**. Посмотрите на настоящие объявления из `<string.h>`:

```c
void *memcpy(void *restrict dest, const void *restrict src, size_t n);
void *memmove(void *dest, const void *src, size_t n);
```

`memcpy` обещает компилятору, что области `dest` и `src` не пересекаются, — поэтому для пересекающихся областей она даёт неопределённое поведение, а `memmove` без этого обещания работает всегда. Зная, что записи в `dest` не меняют `src`, компилятор может читать и писать большими блоками и в любом порядке.

```c
#include <stdio.h>

void add_arrays(int *restrict out, const int *restrict a, const int *restrict b, int n) {
    for (int i = 0; i < n; i++) {
        out[i] = a[i] + b[i];
    }
}

int main(void) {
    int a[] = {1, 2, 3}, b[] = {10, 20, 30}, sum[3];
    add_arrays(sum, a, b, 3);
    printf("%d %d %d\n", sum[0], sum[1], sum[2]);
    return 0;
}
```

Вывод:

```text
11 22 33
```

Компилятор **не проверяет** обещание `restrict`: вызов `add_arrays(a, a, b, 3)` скомпилируется, но нарушит контракт. Поэтому `restrict` пишут в функциях, где пересечение действительно не имеет смысла, и упоминают это в документации.

<Concept title="Квалификаторы — обещания">

`const` обещает, что объект не будут менять через это имя. `restrict` — что к объекту не будут обращаться в обход этого указателя. `volatile` — что каждое обращение важно и его нельзя убрать. Компилятор проверяет только первое обещание, и то не до конца; остальные он принимает на веру и использует для оптимизации.

</Concept>

## Частые ошибки

<CommonMistake title="const int как размер массива или метка case">

В C `const`-переменная — не константное выражение. В C23 используйте `constexpr`, в коде для старых стандартов — `enum` для целых констант и `#define` для значений препроцессора.

</CommonMistake>

<CommonMistake title="const-переменная в заголовке">

`const int MAX = 10;` в заголовке — определение с внешним связыванием в каждом файле. Пишите `constexpr` (C23) или `static const` для скаляров, `extern const` и одно определение — для таблиц, или `enum`.

</CommonMistake>

<CommonMistake title="const String при typedef char *String">

`const` прилипает к указателю, а не к символам. Заведите отдельный тип `typedef const char *ConstString;` или не прячьте указатель за синонимом.

</CommonMistake>

<CommonMistake title="memcpy для пересекающихся областей">

`restrict` в прототипе `memcpy` — формальный запрет на пересечение. Сдвиг части массива на месте делают через `memmove`.

</CommonMistake>

## Итоги

- В C `const`-переменная — объект только для чтения, но не константное выражение: её нельзя использовать в `case`, в размерах массивов вне функций, в `#if`. Внутри функции `int a[n]` с `const int n` — массив переменной длины.
- `constexpr` (C23) — константа, известная при компиляции: годится для `case` и размеров массивов, требует точного значения, указатель — только нулевой, функций `constexpr` в C нет.
- Безымянный `enum` — классический способ задать целую константу; `#define` — для препроцессора, `static const` — для строк и таблиц.
- `const` на уровне файла в C имеет внешнее связывание: в заголовке — `constexpr`, `static const` или `extern const` с одним определением.
- `static const` таблицы заменяют ветвления поиском и защищены от изменения.
- `const` при `typedef` указателя относится к указателю: `const String` — это `char *const`.
- `const` у возвращаемого скалярного значения бессмыслен; у параметра-значения важен только внутри определения.
- `restrict` обещает, что к объекту обращаются только через этот указатель; компилятор не проверяет обещание и использует его для оптимизации.
