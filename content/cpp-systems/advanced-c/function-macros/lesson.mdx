## Макрос, похожий на функцию

У макроса могут быть параметры. Такой макрос записывается и вызывается как функция, но работает по-прежнему подстановкой текста: аргументы вставляются на место параметров, и только потом компилятор видит результат.

```c
#include <stdio.h>

#define SQUARE(x) ((x) * (x))
#define MAX(a, b) ((a) > (b) ? (a) : (b))

int main(void) {
    int side = 7;
    printf("%d\n", SQUARE(side));          // ((side) * (side))
    printf("%d\n", SQUARE(side + 1));      // ((side + 1) * (side + 1))
    printf("%d\n", MAX(side, 10));         // ((side) > (10) ? (side) : (10))
    printf("%.2f\n", MAX(2.5, 1.0));       // работает и с double
    return 0;
}
```

Вывод:

```text
49
64
10
2.50
```

Препроцессор не знает типов, поэтому один `MAX` работает и с `int`, и с `double` — это главное, чем макросы с параметрами привлекательны в C.

В определении открывающая скобка должна стоять **сразу** после имени. С пробелом получится макрос без параметров, замена которого начинается со скобки:

```c
#include <stdio.h>

#define TWICE (x) ((x) * 2)       // TWICE — это «(x) ((x) * 2)»

int main(void) {
    printf("%d\n", TWICE(5));     // Ошибка компиляции: 'x' undeclared
    return 0;
}
```

При **вызове** пробел перед скобкой допустим: `SQUARE (side)` — тоже вызов.

## Скобки вокруг каждого параметра и всего выражения

Скобки в `((x) * (x))` — не перестраховка. Аргумент подставляется как есть и смешивается с окружающими операциями:

```c
#include <stdio.h>

#define DOUBLE_BAD(x) x * 2
#define SUM_BAD(a, b) (a) + (b)

#define DOUBLE(x) ((x) * 2)
#define SUM(a, b) ((a) + (b))

int main(void) {
    printf("%d %d\n", DOUBLE_BAD(1 + 2), DOUBLE(1 + 2));     // 1 + 2 * 2
    printf("%d %d\n", 10 * SUM_BAD(1, 2), 10 * SUM(1, 2));   // 10 * (1) + (2)
    return 0;
}
```

Вывод:

```text
5 6
12 30
```

Правило: **каждый параметр в замене — в скобках, и вся замена — в скобках**. Первое защищает от аргумента-выражения, второе — от операций вокруг вызова.

Аргументы разделяются запятыми **верхнего уровня**: запятая внутри круглых скобок аргумент не делит. `MAX(f(1, 2), 3)` — два аргумента: `f(1, 2)` и `3`.

## `#`: аргумент как строка

Оператор `#` перед параметром превращает аргумент в строковый литерал — ровно в том виде, в каком его написали:

```c
#include <stdio.h>

#define SHOW(expr) printf("%s = %d\n", #expr, (expr))

int main(void) {
    int width = 6, height = 4;
    SHOW(width * height);
    SHOW(width   -   height);      // пробелы сожмутся до одного
    SHOW((width + height) / 2);
    SHOW(width % 4);
    return 0;
}
```

Вывод:

```text
width * height = 24
width - height = 2
(width + height) / 2 = 5
width % 4 = 2
```

`#expr` даёт строку `"width * height"`, которая печатается через `%s`. Функция так не сможет: она получает только значение аргумента, а не текст выражения. Отладочная печать и сообщения проверок — главное применение `#`.

Соблазнительно приклеить текст выражения прямо к формату: `printf(#expr " = %d\n", (expr))` — соседние литералы склеятся в одну строку. Это работает, пока в выражении нет знака `%`. Вызов `SHOW(width % 4)` превратит формат в `"width % 4 = %d\n"`, и `printf` прочтёт `% 4` как начало спецификатора — неопределённое поведение. Clang предупреждает: `invalid conversion specifier`. Текст, пришедший извне, передают отдельным аргументом через `%s`, а не вставляют в формат.

## `##`: склейка токенов

Оператор `##` склеивает два токена в один. Так макрос может **создавать имена**:

```c
#include <stdio.h>

#define DEFINE_MAX(type)                       \
    static type max_##type(type a, type b) {   \
        return a > b ? a : b;                  \
    }

DEFINE_MAX(int)          // создаёт функцию max_int
DEFINE_MAX(double)       // создаёт функцию max_double

int main(void) {
    printf("%d %.1f\n", max_int(3, 9), max_double(2.5, -1.0));
    return 0;
}
```

Вывод:

```text
9 2.5
```

Одно определение порождает семейство функций для разных типов — с проверкой типов, в отличие от `MAX`. Обратная косая черта в конце строк склеивает многострочное определение в одну директиву.

У `#` и `##` есть тонкость: аргумент рядом с ними **не раскрывается** заранее. `STR(__LINE__)` с `#define STR(x) #x` даст строку `"__LINE__"`, а не номер. Если нужно сначала раскрыть аргумент, добавляют промежуточный макрос:

```c
#include <stdio.h>

#define STR(x) #x
#define XSTR(x) STR(x)          // аргумент раскрывается до передачи в STR
#define VERSION 3

int main(void) {
    puts(STR(VERSION));
    puts(XSTR(VERSION));
    puts("строка " XSTR(__LINE__));
    return 0;
}
```

Вывод:

```text
VERSION
3
строка 10
```

## Переменное число аргументов

Многоточие в списке параметров принимает любое число аргументов, а в замене они доступны как `__VA_ARGS__`. Вместе с `__FILE__` и `__LINE__` это даёт макрос трассировки, который сам подставляет место вызова:

```c
#include <stdio.h>

#define TRACE(...) (printf("%s:%d: ", __FILE__, __LINE__), printf(__VA_ARGS__))

int main(void) {
    int items = 3;
    TRACE("старт\n");
    TRACE("товаров: %d\n", items);
    return 0;
}
```

Вывод:

```text
main.c:7: старт
main.c:8: товаров: 3
```

`__LINE__` раскрывается в строке **вызова** `TRACE`, а не в строке определения: подстановка происходит там, где макрос использован. Функция `trace` знала бы только свою собственную строку.

Формат здесь — часть `__VA_ARGS__`, а не отдельный параметр. Хочется написать `#define TRACE(fmt, ...) printf(fmt, __VA_ARGS__)`, но тогда вызов `TRACE("старт\n")` превратится в `printf("старт\n", )` — лишняя запятая. До C23 у этой проблемы не было стандартного решения (GCC и Clang предлагали расширение `, ##__VA_ARGS__`). C23 добавил `__VA_OPT__(…)`: его содержимое подставляется, только если переменные аргументы есть:

```c
#include <stdio.h>

#define LOG(level, fmt, ...) printf("[" level "] " fmt "\n" __VA_OPT__(,) __VA_ARGS__)

int main(void) {
    LOG("INFO", "сервер запущен");
    LOG("WARN", "диск заполнен на %d%%", 91);
    return 0;
}
```

Вывод:

```text
[INFO] сервер запущен
[WARN] диск заполнен на 91%
```

В первом вызове `__VA_OPT__(,)` исчезает вместе с запятой, во втором — подставляет её перед `91`. Заодно обратите внимание на склейку строк: соседние строковые литералы `"[" "INFO" "] "` компилятор объединяет в один.

## Несколько инструкций: `do { … } while (0)`

Макрос из нескольких инструкций приходится заключать в фигурные скобки. Но и этого мало:

```c
#include <stdio.h>

#define SWAP_INT(a, b) { int tmp_ = (a); (a) = (b); (b) = tmp_; }

int main(void) {
    int x = 5, y = 3;
    if (x > y)
        SWAP_INT(x, y);       // Ошибка компиляции: «{ … };» перед else
    else
        printf("уже по порядку\n");
    printf("%d %d\n", x, y);
    return 0;
}
```

После подстановки получается `{ … };` — блок и пустая инструкция, а `else` после них ни к чему не относится. Стандартный приём — обернуть тело в `do { … } while (0)`: это одна инструкция, которая требует точки с запятой после себя и выполняется ровно один раз:

```c
#include <stdio.h>

#define SWAP_INT(a, b)       \
    do {                     \
        int tmp_ = (a);      \
        (a) = (b);           \
        (b) = tmp_;          \
    } while (0)

int main(void) {
    int x = 5, y = 3;
    if (x > y)
        SWAP_INT(x, y);
    else
        printf("уже по порядку\n");
    printf("%d %d\n", x, y);
    return 0;
}
```

Вывод:

```text
3 5
```

Так оформляют любой макрос, который выглядит как вызов функции, но содержит несколько инструкций.

У `SWAP_INT` осталось ограничение: тип `int` зашит в макрос, и для `double` нужен второй макрос. В C23 тип можно взять у аргумента — оператором `typeof`, который возвращает тип выражения:

```c
#include <stdio.h>

#define SWAP(a, b)              \
    do {                        \
        typeof(a) tmp_ = (a);   \
        (a) = (b);              \
        (b) = tmp_;             \
    } while (0)

int main(void) {
    int x = 5, y = 3;
    double p = 1.5, q = -2.25;
    SWAP(x, y);
    SWAP(p, q);
    printf("%d %d %.2f %.2f\n", x, y, p, q);
    return 0;
}
```

Вывод:

```text
3 5 -2.25 1.50
```

`typeof(a)` вычисляется при компиляции и сам аргумент не выполняет, поэтому повторного вычисления здесь нет. Есть и вариант `typeof_unqual`, который отбрасывает `const` и `volatile`. До C23 `typeof` был расширением GCC и Clang — его используют, например, макросы ядра Linux.

## X-макросы: одна таблица — много мест

Частая задача: перечисление и таблица названий должны совпадать. Добавили цвет в `enum`, забыли в массив строк — и названия «съехали». X-макрос хранит данные **один раз** и разворачивает их в нужные формы:

```c
#include <stdio.h>

#define COLOR_LIST(X)          \
    X(RED, "красный")          \
    X(GREEN, "зелёный")        \
    X(BLUE, "синий")

#define AS_ENUM(name, text) COLOR_##name,
#define AS_TEXT(name, text) text,

enum Color { COLOR_LIST(AS_ENUM) COLOR_COUNT };

static const char *const color_names[] = { COLOR_LIST(AS_TEXT) };

int main(void) {
    for (int c = 0; c < COLOR_COUNT; c++) {
        printf("%d %s\n", c, color_names[c]);
    }
    printf("всего %d\n", COLOR_COUNT);
    return 0;
}
```

Вывод:

```text
0 красный
1 зелёный
2 синий
всего 3
```

`COLOR_LIST` принимает имя другого макроса и применяет его к каждой строке таблицы. С `AS_ENUM` получается `COLOR_RED, COLOR_GREEN, COLOR_BLUE,`, с `AS_TEXT` — `"красный", "зелёный", "синий",`. Новый цвет добавляется одной строкой в `COLOR_LIST` — и попадает во все места сразу. Последний элемент `COLOR_COUNT` автоматически равен числу цветов.

## Макрос или функция

| Только макрос может                             | Только функция может                                  |
| ----------------------------------------------- | ----------------------------------------------------- |
| получить текст аргумента (`#`)                  | проверить типы аргументов                             |
| создать имя (`##`)                              | вычислить каждый аргумент ровно один раз              |
| подставить `__FILE__` и `__LINE__` места вызова | иметь собственные локальные переменные без конфликтов |
| работать с любым типом без копий кода           | появиться в отладчике и стеке вызовов                 |

Если задачу решает функция `static inline`, выбирайте её. Макрос оправдан, когда нужно то, что в левом столбце. Классический пример — размер массива:

```c
#define ARRAY_SIZE(a) (sizeof(a) / sizeof((a)[0]))
```

Функция так не сможет: массив, переданный в функцию, превращается в указатель, и `sizeof` внутри неё даст размер указателя. Но и макрос надо применять только к настоящим массивам: `ARRAY_SIZE(p)` для указателя `p` молча вернёт бессмыслицу. Об этих и других опасностях — следующий урок.

<Concept title="Подстановка до компиляции">

Вызов макроса не существует во время работы программы: препроцессор заменил его текстом ещё до компиляции. Поэтому макрос не может ничего «вернуть» или «принять по значению» — он может только вставить выражение, которое компилятор потом вычислит в контексте вызова.

</Concept>

## Частые ошибки

<CommonMistake title="Пробел между именем и скобкой в определении">

`#define AREA (w, h) ((w) * (h))` — макрос без параметров. Ошибка проявится в месте вызова, где появятся непонятные `w` и `h`.

</CommonMistake>

<CommonMistake title="Параметры без скобок">

`#define HALF(x) x / 2` превратит `HALF(a + b)` в `a + b / 2`. Каждый параметр — в скобки, вся замена — тоже.

</CommonMistake>

<CommonMistake title="Точка с запятой в конце определения">

`#define SQUARE(x) ((x) * (x));` даст две точки с запятой после `SQUARE(n);` и сломает выражения вроде `SQUARE(n) + 1`. Точку с запятой ставит тот, кто вызывает макрос.

</CommonMistake>

<CommonMistake title="Несколько инструкций без do-while">

Без обёртки `do { … } while (0)` макрос ломается в `if` без фигурных скобок: под условие попадает только первая инструкция или `else` теряет пару.

</CommonMistake>

## Практика

1. **Отладочная печать** — макрос `SHOW` с оператором `#`.
2. **Найди ошибку: макрос обмена** — макрос из нескольких инструкций под `if`.
3. **Коды ошибок** — X-макрос для перечисления и таблиц.
4. **Стек для любого типа** — генерация структуры и функций через `##`.

## Итоги

- Макрос с параметрами подставляет аргументы на место параметров до компиляции. Скобка в определении стоит сразу после имени.
- Каждый параметр в замене и всю замену заключают в скобки.
- `#параметр` превращает аргумент в строку, `a##b` склеивает токены. Аргументы рядом с ними не раскрываются заранее — для этого нужен промежуточный макрос.
- `...` и `__VA_ARGS__` принимают любое число аргументов; `__FILE__` и `__LINE__` в макросе дают место вызова.
- Макрос из нескольких инструкций оборачивают в `do { … } while (0)`.
- X-макросы хранят таблицу данных в одном месте и разворачивают её в перечисления, массивы и функции.
- Если задачу решает функция `static inline`, выбирайте её; макрос нужен для текста аргументов, создания имён, места вызова и обобщённости по типам.
