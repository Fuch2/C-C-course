## Цели обучения

- Разобраться в теме «Assertions» и её границах применимости.
- Объяснить типичную ошибку, а не только запомнить правильную запись.
- Проверить решение на нормальных и граничных входах.

## Теория

assert проверяет внутреннее утверждение программы и аварийно завершает её при нарушении в сборке с активными проверками. При определённом NDEBUG выражение не вычисляется. Поэтому обязательные операции, ввод и изменение состояния нельзя прятать в assert.

Проверки внешнего ввода остаются обычным кодом во всех конфигурациях. Утверждения документируют уже установленные инварианты, например size &lt;= capacity после успешного reserve. Если их нарушение возможно из-за обычного пользовательского ввода, это признак неверно выбранного уровня проверки. \_Static_assert выполняется при трансляции и полезен для предположений о целевой платформе, а не для runtime-данных.

<Concept title="Ментальная модель">

assert — сигнал о нарушении доказанного внутреннего правила; проверка ввода — часть нормального поведения.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
#include <assert.h>
int main(void) {
    int count=3;assert(count>=0);printf("%d\n",count);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
3
```

assert — сигнал о нарушении доказанного внутреннего правила; проверка ввода — часть нормального поведения. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. assert(scanf(...) == 1) удалит чтение ввода при NDEBUG.

<CommonMistake title="Типичная ошибка">

assert(scanf(...) == 1) удалит чтение ввода при NDEBUG.

</CommonMistake>

## Практическое задание

Прочитайте n. При n вне 0…20 выведите ОШИБКА обычной проверкой; иначе assert подтвердит инвариант, затем выведите n\*n.

Вкладка «Практика» содержит стартовый код, примеры и публичные тесты. После самостоятельной попытки откройте подсказку; эталонное решение и разбор доступны по подтверждённому запросу.

## Краткое резюме

assert — сигнал о нарушении доказанного внутреннего правила; проверка ввода — часть нормального поведения. Для применения темы «Assertions» фиксируйте контракт до написания кода. assert(scanf(...) == 1) удалит чтение ввода при NDEBUG. Успешный пример дополняйте граничными тестами; правильный stdout не отменяет требований языка к типам, времени жизни и ресурсам.
