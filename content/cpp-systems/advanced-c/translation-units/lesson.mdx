## Теория

Единица трансляции — исходный файл после обработки директив препроцессора и включения заголовков. Компилятор проверяет её независимо от соседних .c. Поэтому объявление функции должно быть доступно в месте вызова: наличие реализации в другом файле не сообщает компилятору её тип. Объявление описывает интерфейс, определение предоставляет тело. Затем линкер связывает внешние ссылки объектных файлов.

Разделение позволяет пересобирать только затронутые части. Но граница файла не является границей безопасности типов всей программы: несовместимые объявления в разных единицах трансляции могут не вызвать понятной ошибки линкера. Один общий заголовок, включённый и клиентом, и реализацией, уменьшает этот риск. Не включайте .c вместо заголовка: это копирует определения и разрушает независимую сборку.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
int adjust(int);
int main(void) {
    printf("%d\n",adjust(10));
    return 0;
}
int adjust(int value){return value+1;}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
11
```

Представьте отдельные цеха: каждый выпускает объектный файл по известным интерфейсам; линкер соединяет их внешние имена. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Вызов без прототипа недопустим в современном C. Подключение реализации через #include может дать несколько определений.

Создайте три файла в отдельной доверенной среде сборки. Браузерная практика принимает один исходник; следующие команды описывают отдельную многофайловую сборку.

```text
/* sensor.h */
#ifndef SENSOR_H
#define SENSOR_H
int adjust(int value);
#endif

/* sensor.c */
#include "sensor.h"
int adjust(int value) { return value + 1; }

/* main.c */
#include <stdio.h>
#include "sensor.h"
int main(void) { printf("%d\n", adjust(10)); return 0; }
```

```sh
gcc -std=c17 -Wall -Wextra -c sensor.c -o sensor.o
gcc -std=c17 -Wall -Wextra -c main.c -o main.o
gcc main.o sensor.o -o sensor-demo
```

Уберите sensor.o из последней команды и объясните undefined reference; верните его. Объявление позволило скомпилировать вызов, но не заменило определение.
