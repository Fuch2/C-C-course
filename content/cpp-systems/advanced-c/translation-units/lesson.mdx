## Зачем делить программу на файлы

До сих пор каждая ваша программа помещалась в один файл `main.c`. Настоящие программы так не пишут: редактор текста, игра или драйвер — это сотни и тысячи файлов. Разделение решает сразу несколько задач:

- **навигация** — функции разбора команд лежат в `parser.c`, работа с файлами — в `storage.c`, и нужное место легко найти;
- **скорость сборки** — после правки одного файла перекомпилируется только он, а не весь проект;
- **повторное использование** — модуль статистики из одной программы можно подключить к другой;
- **командная работа** — два человека правят разные файлы и не мешают друг другу.

Этот раздел курса — о том, как язык C позволяет собирать программу из частей: что компилятор знает о соседних файлах (ничего), как файлы договариваются о функциях и переменных и какие ошибки возникают на стыках.

## Единица трансляции

Компилятор C обрабатывает **один `.c` файл за раз**. Он берёт файл, подставляет вместо каждой строки `#include` текст заголовка и компилирует получившийся текст. Этот текст — файл вместе со всем, что в него вставлено, — называется **единицей трансляции** (translation unit).

Каждая единица трансляции превращается в отдельный **объектный файл** `.o` с машинным кодом её функций. Затем **линковщик** соединяет объектные файлы в одну программу и подставляет адреса функций, которые вызываются из других файлов:

```text
main.c  + stdio.h  →  компилятор  →  main.o  ┐
                                             ├→  линковщик  →  app
stats.c + stdio.h  →  компилятор  →  stats.o ┘
```

На своём компьютере такую программу собирают одной командой — компилятор сам обработает оба файла и вызовет линковщик:

```text
$ gcc main.c stats.c -o app
```

Или по шагам: сначала каждый файл отдельно с флагом `-c` («только компилировать»), затем линковка. Так поступают системы сборки — подробнее в модуле «Инструменты разработчика»:

```text
$ gcc -c main.c          # создаёт main.o
$ gcc -c stats.c         # создаёт stats.o
$ gcc main.o stats.o -o app
```

Главное следствие: **компилируя `main.c`, компилятор не заглядывает в `stats.c`**. Всё, что `main.c` использует из другого файла, должно быть описано в самом `main.c` (или в заголовке, который он подключает).

## Объявление и определение

Чтобы скомпилировать вызов функции, компилятору не нужно её тело. Ему достаточно знать **тип**: сколько параметров, каких типов и что функция возвращает. Отсюда два разных понятия:

- **определение** (definition) — функция вместе с телом. Оно создаёт функцию: из него получается машинный код;
- **объявление** (declaration), или **прототип**, — заголовок функции с точкой с запятой. Это обещание: «функция с таким типом где-то существует».

```c
#include <stdio.h>

int square(int x);                 // объявление: тело будет ниже
double average(int a, int b);      // ещё одно объявление

int main(void) {
    printf("%d\n", square(7));
    printf("%.1f\n", average(3, 4));
    return 0;
}

int square(int x) {                // определение
    return x * x;
}

double average(int a, int b) {     // определение
    return (a + b) / 2.0;
}
```

Вывод:

```text
49
3.5
```

Когда компилятор доходит до вызова `square(7)` в `main`, тела функции он ещё не видел. Но прототип выше уже сообщил тип, поэтому вызов компилируется: аргумент `7` передаётся как `int`, результат читается как `int`. Встретив определение ниже, компилятор сверяет его с прототипом.

В прототипе имена параметров необязательны: `int square(int);` значит то же самое. Но имена служат документацией — `double average(int a, int b)` понятнее, чем `double average(int, int)`.

Объявлений одной функции может быть сколько угодно, а **определение — ровно одно во всей программе**. Это правило одного определения:

```c
#include <stdio.h>

int cube(int x);
int cube(int x);         // повторное объявление — допустимо
int cube(int value);     // имена параметров могут отличаться, важен только тип

int main(void) {
    printf("%d\n", cube(3));
    return 0;
}

int cube(int x) {
    return x * x * x;
}
```

Вывод:

```text
27
```

Если определить функцию дважды в одном файле, компилятор сообщит `redefinition of 'cube'`. Если в двух разных файлах — каждый файл по отдельности скомпилируется, а ошибку найдёт линковщик: `multiple definition of 'cube'`.

## Без объявления: что сделает компилятор

В старом C (до стандарта C99) функцию можно было вызвать без объявления: компилятор считал, что она возвращает `int` и принимает что угодно. Стандарт C99 это запретил, но компиляторы ещё двадцать лет сохраняли старое поведение ради старого кода — выдавали предупреждение и продолжали сборку. С GCC 14 (2024) и Clang 16 это **ошибка**, а в C23 понятия «неявное объявление» просто нет:

```c
#include <stdio.h>

int main(void) {
    printf("%.1f\n", ratio(1, 4));      // Ошибка компиляции: ratio ещё не объявлена
    return 0;
}

double ratio(int a, int b) {
    return (double)a / b;
}
```

```text
main.c:4:22: error: implicit declaration of function 'ratio' [-Wimplicit-function-declaration]
main.c:8:8: error: conflicting types for 'ratio'; have 'double(int,  int)'
```

Первая ошибка — главная: в строке 4 компилятор ещё ничего не знает о `ratio`. Вторая — её следствие: старые правила «угадали» тип `int ratio()`, а определение говорит о `double`. Исправление одно: прототип `double ratio(int a, int b);` перед `main` или определение функции выше места вызова.

Зачем знать историю, если компилятор всё равно не пропустит? В интернете и в старых проектах полно советов «это всего лишь предупреждение». В старой сборке с `-std=c89` или старым компилятором такая программа соберётся, а если определение лежит в **другом файле**, будет печатать мусор: `main` прочитает результат как `int`, хотя функция вернула `double`. Если вы видите `implicit declaration` в чужом проекте — это настоящая ошибка, а не шум.

## Пустые скобки: до C23 и сейчас

Прототип `int count(void);` говорит: «параметров нет». А что значит объявление с пустыми скобками `int count();`? Ответ зависит от стандарта — и это одно из самых заметных изменений C23:

- **до C23** (C89–C17) пустые скобки означали «параметры **неизвестны**». Компилятор переставал проверять аргументы и даже не преобразовывал их к нужному типу;
- **в C23** пустые скобки означают ровно то же, что `(void)`, — как в C++.

Возьмём программу, написанную по старым правилам:

```c
#include <stdio.h>

double half();          // Ошибка компиляции в C23: это half(void)

int main(void) {
    printf("%.1f\n", half(3));
    return 0;
}

double half(double x) {
    return x / 2;
}
```

Компилятор курса работает по C23 и не собирает её:

```text
main.c:6:22: error: too many arguments to function 'half'
main.c:10:8: error: conflicting types for 'half'; have 'double(double)'
```

Если собрать тот же файл с `-std=c17`, GCC не выдаст ни одного предупреждения, а программа напечатает `0.0` вместо `1.5`. Функция ждёт `double`, а получает `int`, который передаётся в другом регистре процессора, — неопределённое поведение. Clang по C17 хотя бы предупредит: `a function declaration without a prototype is deprecated in all versions of C`.

С полным прототипом `double half(double x);` компилятор сам превращает `3` в `3.0`, и программа печатает `1.5` по любому стандарту.

Правило: функция без параметров объявляется как `(void)`, функция с параметрами — с полным списком типов. В C23 `int count();` уже безопасно, но `(void)` работает во всех стандартах, а библиотечный код часто собирают и старыми компиляторами — поэтому в заголовках по-прежнему пишут `(void)`.

## Типы в объявлении и определении должны совпадать

Внутри одного файла компилятор сверяет прототип с определением и не пропустит противоречие:

```c
#include <stdio.h>

int area(int w, int h);

int main(void) {
    printf("%d\n", area(3, 4));
    return 0;
}

double area(double w, double h) {      // Ошибка компиляции: conflicting types for 'area'
    return w * h;
}
```

Но если определение и неверное объявление живут в **разных** файлах, их никто не сравнит. Компилятор видит каждый файл отдельно, а линковщик C сопоставляет функции только по **имени**:

```c geometry.c
double area(double w, double h) {
    return w * h;
}
```

```c main.c
#include <stdio.h>

int area(int w, int h);            // объявление не совпадает с определением

int main(void) {
    printf("%d\n", area(3, 4));    // собирается без ошибок, печатает мусор
    return 0;
}
```

Команда `gcc main.c geometry.c -o app` пройдёт без единой ошибки, а программа будет передавать целые числа туда, где ждут дробные, — снова неопределённое поведение. Защита от этого — **заголовочный файл**: одно объявление, которое подключают и `geometry.c`, и все его пользователи. Тогда противоречие увидит компилятор при сборке `geometry.c`. Заголовкам посвящён следующий урок.

## Взаимная рекурсия: без прототипа не обойтись

Часто прототипов можно избежать, если определить функции **до** места вызова, а `main` поставить в конец файла. Но бывает, что две функции вызывают друг друга: `a` вызывает `b`, а `b` — `a`. Какую бы ни поставить первой, вторая окажется ниже места вызова. Такая **взаимная рекурсия** требует хотя бы одного прототипа:

```c
#include <stdio.h>

bool is_odd(unsigned n);           // без этой строки is_even не скомпилируется

bool is_even(unsigned n) {
    return n == 0 ? true : is_odd(n - 1);
}

bool is_odd(unsigned n) {
    return n == 0 ? false : is_even(n - 1);
}

int main(void) {
    for (unsigned n = 0; n <= 5; n++) {
        printf("%u: %s\n", n, is_even(n) ? "чётное" : "нечётное");
    }
    return 0;
}
```

Вывод:

```text
0: чётное
1: нечётное
2: чётное
3: нечётное
4: чётное
5: нечётное
```

Пример игрушечный — чётность проще проверить через `n % 2`. Но тот же приём нужен в серьёзных задачах: разбор вложенных выражений, где «выражение» состоит из «слагаемых», а слагаемое может быть «выражением в скобках». Вы напишете такой разбор в практике.

<Concept title="Объявление — это договор">

Объявление обещает компилятору: «функция с таким типом существует». Компилятор верит на слово и генерирует вызов. Проверить обещание он может только тогда, когда видит определение в той же единице трансляции. Найти само определение — задача линковщика, но и он проверяет лишь имя. Поэтому договоры между файлами записывают **один раз** — в заголовке, — а не переписывают вручную в каждом файле.

</Concept>

## Частые ошибки

<CommonMistake title="Отключать ошибку implicit declaration">

Сообщение `implicit declaration of function` означает, что компилятор не знает типа функции. Причины: забыт прототип, опечатка в имени или не подключён заголовок (например, `string.h` для `strlen`). Старый код иногда «чинят» флагом `-Wno-implicit-function-declaration` или `-std=gnu89` — так ошибка не исчезает, а прячется до запуска. Добавьте объявление.

</CommonMistake>

<CommonMistake title="Пустые скобки в коде для разных стандартов">

В C23 `int read_value();` — то же, что `int read_value(void);`, но в C17 и раньше такое объявление отключает проверку аргументов, и GCC не предупредит даже с `-Wall -Wextra` (нужен отдельный флаг `-Wstrict-prototypes`). Заголовок, который подключают проекты на разных стандартах, пишите с `(void)`.

</CommonMistake>

<CommonMistake title="Объявление переписано вручную">

Прототип, скопированный в несколько файлов, легко рассогласовать: изменили параметр в определении, а одну из копий забыли. Компилятор этого не заметит. Объявление должно жить в одном месте — в заголовке.

</CommonMistake>

<CommonMistake title="Определение в двух файлах">

Две функции с одинаковым именем в разных файлах — ошибка линковки `multiple definition`, даже если тела одинаковые. Как скрыть вспомогательную функцию внутри файла, вы узнаете в уроке о `static`.

</CommonMistake>

## Итоги

- Единица трансляции — `.c` файл вместе с подставленными заголовками. Компилятор обрабатывает каждую отдельно и ничего не знает о других файлах.
- Объектные файлы соединяет линковщик; он ищет определения по имени и не проверяет типы.
- Определение создаёт функцию (с телом), объявление (прототип) сообщает только её тип. Объявлений может быть много, определение — одно на всю программу.
- Перед вызовом функция должна быть объявлена. `implicit declaration` в GCC 14+ и Clang — ошибка; в старых компиляторах это было предупреждение, которое нельзя игнорировать.
- В C23 пустые скобки в объявлении означают `(void)`, в C17 и раньше — «параметры неизвестны» без проверки аргументов. В заголовках пишите `(void)`.
- Взаимно рекурсивным функциям нужен прототип хотя бы одной из них.
