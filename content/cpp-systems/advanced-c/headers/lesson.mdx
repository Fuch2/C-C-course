## Теория

Заголовок — текстовый контракт модуля. В нём размещают прототипы, типы и необходимые константы; определения общих объектов обычно остаются в .c. Заголовок должен быть самодостаточным: если интерфейс использует size_t, он сам включает stddef.h. Тогда порядок чужих include не меняет работоспособность клиента.

Реализация тоже включает свой заголовок. Это заставляет компилятор сопоставить объявление с определением. Минимизируйте зависимости: каждый лишний include увеличивает объём повторной обработки и связывает клиентов с деталями. Публичный struct раскрывает представление; непрозрачный тип скрывает поля, но требует отдельного API создания и уничтожения. Выбор определяется тем, кто управляет временем жизни объекта.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
typedef struct { int raw; } Reading;
int main(void) {
    Reading r={12}; printf("%d\n",r.raw);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
12
```

Заголовок похож на разъём: клиенту нужны форма контактов и правила использования, а не внутренние провода. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Определение int counter = 0 в заголовке создаёт отдельное внешнее определение в каждом клиенте.
