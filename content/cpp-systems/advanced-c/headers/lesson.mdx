## Договор в одном месте

В прошлом уроке прототипы приходилось переписывать в каждый файл, который вызывает функцию, — и рассогласованная копия превращалась в неопределённое поведение без единого предупреждения. Решение — **заголовочный файл** (header): файл с расширением `.h`, в котором объявления записаны один раз. Каждый, кому они нужны, подключает его директивой `#include`.

Модуль статистики из двух файлов — заголовка и реализации — и программа, которая им пользуется:

```c stats.h
int stats_min(const int *values, int count);
int stats_max(const int *values, int count);
double stats_mean(const int *values, int count);
```

```c stats.c
#include "stats.h"

int stats_min(const int *values, int count) {
    int best = values[0];
    for (int i = 1; i < count; i++) {
        if (values[i] < best) {
            best = values[i];
        }
    }
    return best;
}

int stats_max(const int *values, int count) {
    int best = values[0];
    for (int i = 1; i < count; i++) {
        if (values[i] > best) {
            best = values[i];
        }
    }
    return best;
}

double stats_mean(const int *values, int count) {
    long long sum = 0;
    for (int i = 0; i < count; i++) {
        sum += values[i];
    }
    return (double)sum / count;
}
```

```c main.c
#include <stdio.h>
#include "stats.h"

int main(void) {
    int t[] = {12, -3, 7, 25, 4};
    printf("min=%d max=%d mean=%.1f\n", stats_min(t, 5), stats_max(t, 5), stats_mean(t, 5));
    return 0;
}
```

Сборка: `gcc main.c stats.c -o app`. Заголовок в команду не передают — его подключают сами `.c` файлы.

Заголовок — это **интерфейс** модуля: что модуль умеет и как к нему обращаться. `.c` файл — **реализация**: как именно это сделано. Пользователю модуля достаточно прочитать заголовок.

## Как работает `#include`

`#include` — самая простая директива препроцессора: она **вставляет текст** файла на своё место. Никакой магии: после препроцессора `main.c` превращается в единицу трансляции, где вместо строки `#include "stats.h"` стоят три прототипа (а вместо `#include <stdio.h>` — несколько сотен строк объявлений стандартной библиотеки):

```text
...объявления из stdio.h, в том числе int printf(const char *, ...);...
int stats_min(const int *values, int count);
int stats_max(const int *values, int count);
double stats_mean(const int *values, int count);

int main(void) {
    ...
}
```

Две формы записи отличаются тем, где искать файл:

| Запись               | Где ищется                                              | Для чего                           |
| -------------------- | ------------------------------------------------------- | ---------------------------------- |
| `#include "stats.h"` | сначала в каталоге текущего файла, затем в системных    | заголовки вашего проекта           |
| `#include <stdio.h>` | только в системных каталогах и каталогах из флагов `-I` | стандартная и сторонние библиотеки |

Подключать можно любой файл, но по соглашению подключают только `.h`. Строка `#include "stats.c"` вставит в `main.c` определения функций — и как только `stats.c` попадёт в команду сборки сам, линковщик найдёт каждую функцию дважды.

## Модуль в одном файле

Браузерная песочница курса принимает один файл. Поэтому в примерах и задачах этого раздела модуль собран в одном файле, а части отмечены комментариями — так, как если бы вы вручную подставили заголовок через `#include`:

```c
#include <stdio.h>

// ---- counter.h ----
void counter_add(int amount);
int counter_total(void);

// ---- main.c ----
int main(void) {
    counter_add(5);
    counter_add(-2);
    counter_add(10);
    printf("%d\n", counter_total());
    return 0;
}

// ---- counter.c ----
int total = 0;

void counter_add(int amount) {
    total += amount;
}

int counter_total(void) {
    return total;
}
```

Вывод:

```text
13
```

Порядок частей повторяет то, что видит компилятор: сначала интерфейс, потом код, который им пользуется. Функция `main` стоит **выше** реализации и знает о модуле только то, что написано в разделе `counter.h`.

## Что кладут в заголовок

| В заголовке                                    | Почему                                                                              |
| ---------------------------------------------- | ----------------------------------------------------------------------------------- |
| прототипы функций модуля                       | чтобы вызовы в других файлах компилировались с проверкой типов                      |
| определения типов: `struct`, `enum`, `typedef` | компилятору нужен тип в каждом файле, где создают переменные или обращаются к полям |
| макросы-константы: `#define STATS_MAX 100`     | пользователям нужны те же константы, что и реализации                               |
| объявления общих переменных с `extern`         | об этом — в уроке об `extern`                                                       |

А вот **определения** функций и переменных в заголовок не кладут. Заголовок подключают многие `.c` файлы, и каждое определение окажется в каждом из них — линковщик сообщит `multiple definition`.

Типы — исключение из этого правила, и не случайно. Определение `struct` не создаёт ни кода, ни памяти: это описание для компилятора. Повторять его в разных единицах трансляции можно и нужно — иначе файл, который создаёт переменную `struct Point`, не будет знать её размер.

## Реализация подключает свой заголовок

Первая строка `stats.c` — `#include "stats.h"`. Это не формальность. Подключив собственный заголовок, реализация даёт компилятору сверить каждое определение с объявлением. Если кто-то изменит тип в одном месте и забудет другое, ошибка обнаружится при сборке `stats.c`:

```c
#include <stdio.h>

// ---- stats.h ----
double stats_mean(const int *values, int count);

// ---- stats.c ----
int stats_mean(const int *values, int count) {  // Ошибка компиляции: conflicting types
    int sum = 0;
    for (int i = 0; i < count; i++) {
        sum += values[i];
    }
    return sum / count;
}

int main(void) {
    int t[] = {1, 2};
    printf("%d\n", stats_mean(t, 2));
    return 0;
}
```

Именно этой проверки не хватало в прошлом уроке, когда объявление `area` в `main.c` разошлось с определением в `geometry.c`: теперь объявление одно, и его видят обе стороны.

## Самодостаточный заголовок

Заголовок должен компилироваться сам по себе — то есть сам подключать всё, что использует. Если в прототипе встречается `size_t`, заголовку нужен `<stddef.h>`, для `FILE` — `<stdio.h>`, для `uint32_t` — `<stdint.h>`. Для `bool` в C23 ничего не нужно, но заголовок, который должен собираться и по C17, подключает `<stdbool.h>`:

```c buffer.h
#include <stddef.h>

size_t buffer_used(void);
```

Если забыть `#include <stddef.h>`, заголовок будет работать только в тех файлах, которые случайно подключили `<stdio.h>` или `<stdlib.h>` раньше него, — а в остальных сборка упадёт:

```c
size_t buffer_used(void);     // Ошибка компиляции: unknown type name 'size_t'

int main(void) {
    return 0;
}
```

Простой способ проверить самодостаточность — подключать в `.c` файле модуля его собственный заголовок **первым**, до стандартных. Тогда забытый `#include` сразу даст ошибку.

## Непрозрачные типы

Если положить определение структуры в заголовок, пользователи модуля получат доступ к её полям. Иногда это удобно (точка с полями `x` и `y`), но часто опасно: пользователь стека может написать `s->size = 100` и сломать модуль. Кроме того, любое изменение полей заставит пересобрать все файлы, которые подключают заголовок.

C позволяет объявить структуру, не раскрывая её устройства:

```c stack.h
typedef struct Stack Stack;        // структура существует, но её поля секретны

Stack *stack_create(void);
void stack_destroy(Stack *s);
int stack_push(Stack *s, int value);
int stack_pop(Stack *s, int *out);
```

`struct Stack` здесь — **неполный тип**: компилятор знает, что такая структура есть, но не знает её полей и размера. С неполным типом можно:

- объявлять указатели `Stack *s` и передавать их в функции;
- сравнивать указатели и присваивать их.

Нельзя:

- создать переменную `Stack s;` — неизвестен размер;
- вычислить `sizeof(Stack)`;
- обратиться к полю `s->size`.

Полное определение `struct Stack { ... };` лежит только в `stack.c`, поэтому только функции модуля видят поля. Пользователь получает указатель из `stack_create` и передаёт его остальным функциям. Такой тип называют **непрозрачным** (opaque). Вы давно пользуетесь им: `FILE *` из `<stdio.h>` устроен именно так.

```c
#include <stdio.h>
#include <stdlib.h>

// ---- counter.h ----
typedef struct Counter Counter;
Counter *counter_create(int start);
void counter_step(Counter *c);
int counter_value(const Counter *c);
void counter_destroy(Counter *c);

// ---- main.c ----
int main(void) {
    Counter *c = counter_create(10);
    if (c == NULL) {
        return 1;
    }
    counter_step(c);
    counter_step(c);
    printf("%d\n", counter_value(c));
    counter_destroy(c);
    return 0;
}

// ---- counter.c ----
struct Counter {
    int value;
    int steps;
};

Counter *counter_create(int start) {
    Counter *c = malloc(sizeof *c);
    if (c != NULL) {
        c->value = start;
        c->steps = 0;
    }
    return c;
}

void counter_step(Counter *c) {
    c->value++;
    c->steps++;
}

int counter_value(const Counter *c) {
    return c->value;
}

void counter_destroy(Counter *c) {
    free(c);
}
```

Вывод:

```text
12
```

В `main` тип `Counter` неполный: структура определена ниже. Попытка обратиться к полю не скомпилируется:

```c
#include <stdio.h>

typedef struct Counter Counter;
Counter *counter_create(int start);

int main(void) {
    Counter *c = counter_create(10);
    printf("%d\n", c->value);      // Ошибка компиляции: invalid use of incomplete typedef
    return 0;
}
```

За непрозрачность платят тем, что объект всегда создаётся в куче функцией модуля, а доступ к любому полю — вызов функции. Поэтому маленькие простые типы (точка, дробь, цвет) обычно оставляют открытыми, а скрывают те, у которых есть **инвариант** — условие, которое функции модуля поддерживают и которое пользователь не должен нарушить.

## Имена: префикс модуля

В C нет пространств имён: все внешние функции программы и всех её библиотек живут в одном общем списке имён. Если два модуля определят функцию `init`, линковщик сообщит `multiple definition`. Поэтому к именам добавляют префикс модуля: `stats_mean`, `stack_push`, `board_add`, а к макросам — его заглавную форму: `STATS_MAX`. Стандартная библиотека следует тому же правилу: `str*` для строк, `f*` для файлов, `mem*` для памяти.

<Concept title="Интерфейс и реализация">

Заголовок — обещание модуля остальной программе: «эти функции и типы существуют и ведут себя так». Всё, чего нет в заголовке, — внутреннее дело модуля, которое можно свободно менять. Чем меньше заголовок, тем меньше обещаний приходится выполнять и тем легче развивать код.

</Concept>

## Частые ошибки

<CommonMistake title="Определение в заголовке">

```c log.h
void log_line(const char *text) {          // тело функции в заголовке
    printf("[log] %s\n", text);
}
```

Каждый `.c` файл, подключивший `log.h`, получит свою копию функции, и линковка упадёт с `multiple definition of 'log_line'`. В заголовке — только прототип `void log_line(const char *text);`.

</CommonMistake>

<CommonMistake title="Подключение .c файла">

`#include "stats.c"` копирует реализацию в другой файл. Пока `stats.c` не участвует в сборке сам, это даже работает — но правило одного определения нарушено, раздельная компиляция потеряна, а при росте проекта появится `multiple definition`.

</CommonMistake>

<CommonMistake title="Заголовок зависит от порядка подключения">

Если заголовок использует `size_t`, `bool` или `FILE`, но сам не подключает нужный стандартный заголовок, он работает «через раз» — в зависимости от того, что подключено выше. Подключайте собственный заголовок первым в его `.c` файле.

</CommonMistake>

<CommonMistake title="Поля структуры, которые пользователь может испортить">

Открытая структура с инвариантом (`size <= capacity`) позволяет пользователю записать в поля что угодно. Если модуль следит за инвариантом, сделайте тип непрозрачным.

</CommonMistake>

## Итоги

- Заголовок `.h` содержит интерфейс модуля: прототипы, типы, макросы. Реализация — в `.c`. `#include` просто вставляет текст заголовка.
- Свои заголовки подключают в кавычках, стандартные — в угловых скобках. `.c` файлы не подключают.
- Определения функций и переменных в заголовок не кладут — иначе `multiple definition`. Типы — можно: они не создают кода.
- Реализация подключает свой заголовок (лучше первым): так компилятор сверит объявления с определениями, а заодно проверит самодостаточность заголовка.
- Неполный тип `typedef struct Stack Stack;` скрывает поля: пользователь работает только через указатель и функции модуля.
- Внешние имена модуля начинаются с общего префикса: в C нет пространств имён.
