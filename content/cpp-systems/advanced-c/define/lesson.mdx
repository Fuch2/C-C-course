## Что вы уже знаете

В «Основах C» `#define` задавал имена константам: `#define MAX_SCORE 100`. Вы знаете, что это текстовая замена без типа, что после директивы не ставят точку с запятой и что выражение в макросе нужно брать в скобки: `#define BORDER (10 + 2)`. В этом уроке разберём, как именно препроцессор раскрывает макросы, сколько они живут, почему игнорируют области видимости и когда `#define` действительно нужен.

## Как раскрывается макрос

Определение `#define ИМЯ замена` запоминает **последовательность токенов** замены. Встретив в тексте идентификатор `ИМЯ`, препроцессор подставляет эти токены, а затем **снова просматривает** результат: если в подстановке есть другие макросы, раскрываются и они.

Отсюда следствие: порядок определений не важен — важно, что известно в **момент использования**:

```c
#include <stdio.h>

#define AREA (WIDTH * HEIGHT)      // WIDTH и HEIGHT пока не определены — это не ошибка
#define WIDTH 8
#define HEIGHT 5

int main(void) {
    printf("%d\n", AREA);          // AREA → (WIDTH * HEIGHT) → (8 * 5)
    return 0;
}
```

Вывод:

```text
40
```

При определении `AREA` препроцессор ничего не проверяет и не раскрывает — он просто запоминает токены `( WIDTH * HEIGHT )`. Раскрытие происходит в строке с `printf`, а к этому моменту известны все три макроса.

Повторный просмотр мог бы зациклиться: что будет, если макрос ссылается на себя? Правило защищает от бесконечности: **внутри собственной подстановки макрос не раскрывается**. Получившийся идентификатор остаётся как есть — и дальше это обычное имя C:

```c
#include <stdio.h>

int limit = 5;
#define limit (limit * 2)        // внутреннее limit — уже переменная

int main(void) {
    printf("%d\n", limit);       // limit → (limit * 2) → значение 10
    return 0;
}
```

Вывод:

```text
10
```

Этим приёмом пользуется и стандартная библиотека: `errno` в glibc — макрос, который раскрывается в обращение к функции, возвращающей адрес переменной текущего потока. Для пользователя же `errno` выглядит как обычная переменная. Но в своём коде называть макрос так же, как переменную, не стоит: такой код трудно читать.

## Сколько живёт макрос

Макрос действует от строки `#define` до конца единицы трансляции — или до директивы `#undef`, которая его удаляет. После `#undef` имя можно определить заново:

```c
#include <stdio.h>

#define UNIT "см"
void show_length(int value) {
    printf("%d %s\n", value, UNIT);
}
#undef UNIT

#define UNIT "кг"
void show_weight(int value) {
    printf("%d %s\n", value, UNIT);
}
#undef UNIT

int main(void) {
    show_length(180);
    show_weight(75);
    return 0;
}
```

Вывод:

```text
180 см
75 кг
```

`#undef` полезен и для вспомогательных макросов, которые нужны только в одном месте файла: удалив макрос сразу после использования, вы не дадите ему случайно сработать ниже.

Повторное определение **с другой заменой** без `#undef` — нарушение правил. GCC выдаёт предупреждение и использует новое значение:

```c
#include <stdio.h>

#define LIMIT 10
// Предупреждение: "LIMIT" redefined
#define LIMIT 20

int main(void) {
    printf("%d\n", LIMIT);
    return 0;
}
```

Вывод:

```text
20
```

Если такое происходит в большом проекте, это почти всегда ошибка: два заголовка определяют один макрос по-разному, и значение зависит от порядка включения. Совпадающее определение повторять можно — это вы видели в уроке о защите заголовков.

## Макрос не знает областей видимости

Макрос, определённый внутри функции, продолжает действовать и после неё — до конца файла. Препроцессор не знает о фигурных скобках, функциях и структурах. Поэтому имя макроса заменяется **везде**, в том числе там, где вы имели в виду совсем другое:

```c
#include <stdio.h>

#define size 16

struct Buffer {
    char data[size];
    int size;            // Ошибка компиляции: превращается в int 16;
};

int main(void) {
    struct Buffer b;
    b.size = 0;
    printf("%d\n", b.size);
    return 0;
}
```

Компилятор видит `int 16;` и сообщает `expected identifier or '(' before numeric constant` — сообщение указывает на поле, а виноват макрос несколькими строками выше. В большом проекте такой макрос может прийти из заголовка, которого вы даже не открывали.

Защита одна — **соглашение об именах**: макросы пишут ЗАГЛАВНЫМИ буквами (`BUFFER_SIZE`), а для переменных, полей и функций заглавные имена не используют. Тогда пересечься имена не могут. Нарушители этого правила известны: заголовок `windows.h` определяет макросы `min` и `max`, которые ломают любой код со своими функциями `min` и `max`.

## Пустые макросы

Замена может быть пустой: `#define DEBUG`. Такой макрос раскрывается в ничто — имя просто исчезает из текста. Пустые макросы используют в двух ролях.

**Флаги** для условной компиляции: важно не значение, а сам факт определения. Защита заголовков `#define POINT_H` — тоже флаг.

**Пометки** в объявлениях, которые на разных платформах означают разное. В переносимой библиотеке пометка `API` в Linux пустая, а в Windows раскрывается в особое слово для экспорта функций из DLL:

```c
#include <stdio.h>

#define API

API int twice(int x) {
    return 2 * x;
}

int main(void) {
    API int value = twice(21);
    printf("%d\n", value);
    return 0;
}
```

Вывод:

```text
42
```

## Макросы из командной строки

Макрос можно определить, не трогая исходник: флаг `-D` компилятора работает как `#define` в самом начале файла.

| Флаг                 | Равносильно                |
| -------------------- | -------------------------- |
| `-DBUFFER_SIZE=4096` | `#define BUFFER_SIZE 4096` |
| `-DDEBUG`            | `#define DEBUG 1`          |
| `-UDEBUG`            | `#undef DEBUG`             |

Чтобы программа собиралась и без флага, значение по умолчанию задают так:

```c
#include <stdio.h>

#ifndef BUFFER_SIZE
#define BUFFER_SIZE 256         // значение по умолчанию
#endif

int main(void) {
    char buffer[BUFFER_SIZE];
    printf("буфер %zu байт\n", sizeof buffer);
    return 0;
}
```

Вывод:

```text
буфер 256 байт
```

Команда `gcc -DBUFFER_SIZE=4096 main.c` соберёт ту же программу с буфером 4096 байт. Директивы `#ifndef` и `#endif` разберём подробно в уроке об условной компиляции.

## Строки из макросов

Соседние строковые литералы компилятор склеивает в один, поэтому макросы-строки удобно собирать в сообщения прямо при компиляции:

```c
#include <stdio.h>

#define APP_NAME "notes"
#define APP_VERSION "2.1"

int main(void) {
    puts(APP_NAME " версии " APP_VERSION);
    puts("Использование: " APP_NAME " [файл]");
    return 0;
}
```

Вывод:

```text
notes версии 2.1
Использование: notes [файл]
```

С переменной `const char *` так не получится: склеиваются только литералы, известные при компиляции.

## Когда нужен `#define`

У макроса нет типа и области видимости, его не видно в отладчике. Поэтому для обычных констант лучше подходят `enum` и `const` (у `const` в C есть свои ограничения — им посвящён отдельный урок). Но есть задачи, которые решает только препроцессор:

- значение нужно в директивах `#if` — препроцессор не знает ни `const`, ни `enum`;
- значение задаётся при сборке флагом `-D`;
- нужна строковая константа, которую склеивают с другими литералами;
- константа в заголовке, общем для C и C++, или для размера массива в структуре.

<Concept title="Макрос — это подстановка токенов">

Препроцессор не вычисляет `#define BORDER 10 + 2` — он запоминает четыре токена и вставляет их в каждое место использования, где они смешиваются с окружающим текстом. Все свойства макросов следуют из этого: нет типа, нет области видимости, есть повторный просмотр и защита от самоподстановки.

</Concept>

## Частые ошибки

<CommonMistake title="Макрос с именем обычного идентификатора">

`#define size 16` или `#define count 0` ломают поля, параметры и функции с этими именами во всём файле. Имена макросов — только заглавными буквами.

</CommonMistake>

<CommonMistake title="Разные определения одного макроса">

Предупреждение `redefined` нельзя игнорировать: значение макроса теперь зависит от того, какой заголовок подключён последним. Найдите оба определения и оставьте одно или переименуйте.

</CommonMistake>

<CommonMistake title="Макрос определён ниже места использования">

```c
int buffer[SIZE];        // SIZE ещё не определён: ошибка 'SIZE' undeclared
#define SIZE 64
```

Определение `AREA` может ссылаться на ещё не определённые макросы, но **использовать** макрос можно только после его определения.

</CommonMistake>

## Итоги

- Препроцессор запоминает замену как последовательность токенов и после подстановки просматривает результат снова. Макрос раскрывается в момент использования, поэтому порядок определений не важен.
- Внутри собственной подстановки макрос не раскрывается — это защищает от бесконечной рекурсии.
- Макрос живёт до конца единицы трансляции или до `#undef`. Переопределение с другой заменой — предупреждение и почти всегда ошибка.
- Макросы игнорируют области видимости и заменяют имя везде. Поэтому их имена пишут заглавными буквами.
- Пустые макросы служат флагами и пометками; флаг `-D` определяет макрос при сборке, а `#ifndef` задаёт значение по умолчанию.
- `#define` незаменим для значений в `#if`, настроек сборки и строковых литералов; для остальных констант лучше `enum` и `const`.
