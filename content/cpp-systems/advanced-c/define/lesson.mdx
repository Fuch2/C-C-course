- Проверить решение на нормальных и граничных входах.

## Теория

Объектоподобный макрос заменяет имя последовательностью токенов. Типизированного объекта и адреса у него нет. Скобки вокруг выражения сохраняют ожидаемый приоритет при подстановке. Не ставьте точку с запятой в значение: это внедряет лишнюю границу оператора в чужое выражение.

Для значения, которому нужен адрес или контроль типа, предпочтителен const-объект. Для целочисленной константы времени компиляции часто подходит enum. Макрос оправдан для препроцессорной конфигурации и условной компиляции. Например размер таблицы может зависеть от фиксированного числа каналов, но проверка диапазона пользовательского индекса всё равно выполняется во время работы.

<Concept title="Ментальная модель">

Макрос — текстовая подстановка, а не ячейка памяти с постоянным значением.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
#define STEP (1 + 2)
int main(void) {
    printf("%d\n",2*STEP);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
6
```

Макрос — текстовая подстановка, а не ячейка памяти с постоянным значением. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. #define SCALE 2 + 3 превращает x _ SCALE в x _ 2 + 3.

<CommonMistake title="Типичная ошибка">

#define SCALE 2 + 3 превращает x _ SCALE в x _ 2 + 3.

</CommonMistake>
