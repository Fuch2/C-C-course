## Одно слово — два смысла

Слово `static` вы уже встречали в уроке об области видимости: локальная переменная со `static` живёт всё время работы программы и сохраняет значение между вызовами функции. Там же было сказано, что у `static` перед **глобальным** именем другой смысл. Теперь, когда программа состоит из нескольких файлов, он становится главным:

| Где стоит `static`                       | Что меняет                                                            |
| ---------------------------------------- | --------------------------------------------------------------------- |
| перед функцией или глобальной переменной | имя видно **только в своём файле** — линковщик его не знает           |
| перед локальной переменной               | переменная живёт **всё время работы программы**, а не до конца вызова |

Начнём с первого.

## Вспомогательная функция видна всем

В модуле рациональных чисел из прошлого урока была вспомогательная функция `gcd`. В заголовке её нет, но линковщик о ней знает: любая функция, определённая без `static`, доступна из любого файла программы. Если в соседнем модуле статистики тоже окажется своя `gcd`, сборка упадёт:

```c rational.c
#include "rational.h"

long long gcd(long long a, long long b) {
    // ...
}
```

```c stats.c
#include "stats.h"

long long gcd(long long a, long long b) {     // другой модуль, то же имя
    // ...
}
```

```text
$ gcc main.c rational.c stats.c -o app
/usr/bin/ld: stats.o: in function `gcd':
stats.c:(.text+0x0): multiple definition of `gcd'; rational.o:rational.c:(.text+0x0): first defined here
```

Авторы модулей ничего не знали друг о друге, а программа не собирается. Исправление — слово `static`:

```c rational.c
#include "rational.h"

static long long gcd(long long a, long long b) {
    // ...
}
```

Функция со `static` имеет **внутреннее связывание**: её имя существует только внутри своей единицы трансляции. Линковщик её не видит, поэтому в каждом файле может быть своя `static long long gcd` — конфликта нет. Обычные функции имеют **внешнее связывание**: их имя общее для всей программы. Подробнее о видах связывания — в уроке «Связывание».

Внутри файла `static`-функцией пользуются как обычной:

```c
#include <stdio.h>

static int digit_sum(int n) {          // видна только в этом файле
    int sum = 0;
    while (n > 0) {
        sum += n % 10;
        n /= 10;
    }
    return sum;
}

int is_lucky(int ticket) {             // часть интерфейса модуля
    return digit_sum(ticket / 1000) == digit_sum(ticket % 1000);
}

int main(void) {
    printf("%d %d\n", is_lucky(123321), is_lucky(123456));
    return 0;
}
```

Вывод:

```text
1 0
```

Правило для модулей простое: **всё, чего нет в заголовке, объявляйте `static`**. Тогда вспомогательные функции не столкнутся с чужими, а читатель сразу видит, что функция — внутреннее дело файла и её можно менять, не оглядываясь на другие модули.

## Скрытое состояние модуля

Тем же словом `static` скрывают глобальные переменные модуля. Модуль журнала хранит уровень подробности и число записанных сообщений — это его внутреннее состояние:

```c
#include <stdio.h>

// ---- log.h ----
void log_set_level(int level);
void log_message(int level, const char *text);
int log_count(void);

// ---- main.c ----
int main(void) {
    log_message(1, "старт");
    log_set_level(2);
    log_message(1, "подробности");      // ниже порога — не печатается
    log_message(3, "ошибка диска");
    printf("записано: %d\n", log_count());
    return 0;
}

// ---- log.c ----
static int min_level = 0;
static int written = 0;

void log_set_level(int level) {
    min_level = level;
}

void log_message(int level, const char *text) {
    if (level >= min_level) {
        printf("[%d] %s\n", level, text);
        written++;
    }
}

int log_count(void) {
    return written;
}
```

Вывод:

```text
[1] старт
[3] ошибка диска
записано: 2
```

Переменные `min_level` и `written` живут всё время работы программы, как любые глобальные, но доступны только функциям из `log.c`. Другой файл не может их изменить — даже объявив `extern int written;`, он получит ошибку линковки `undefined reference`. Изменить состояние можно только через функции модуля, а значит, модуль сам отвечает за его правильность.

У такого приёма есть цена: состояние **одно на всю программу**. Если понадобятся два независимых журнала, придётся переходить к структуре, которую создают функцией модуля, — как непрозрачный тип из урока о заголовках.

## `static` у локальной переменной

Вспомним второй смысл. Локальная `static` переменная:

- создаётся **один раз** — до начала работы `main` — и живёт до конца программы;
- инициализируется тоже один раз, а при следующих вызовах функции сохраняет последнее значение;
- видна, как обычная локальная, только внутри своего блока.

Классическое применение — счётчик, который нужен только одной функции. Глобальная переменная для этого слишком доступна, а обычная локальная обнуляется при каждом вызове:

```c
#include <stdio.h>

int next_ticket(void) {
    static int last = 100;     // инициализируется один раз
    last++;
    return last;
}

int main(void) {
    for (int i = 0; i < 3; i++) {
        printf("талон %d\n", next_ticket());
    }
    return 0;
}
```

Вывод:

```text
талон 101
талон 102
талон 103
```

Второе применение — **кэш**: функция запоминает уже вычисленные результаты в `static` массиве и при повторном запросе не считает заново. Например, числа Фибоначчи с запоминанием:

```c
#include <stdio.h>

static long long calls = 0;

long long fib(int n) {
    static long long memo[91];     // нули: static обнуляется до начала программы
    calls++;
    if (n < 2) {
        return n;
    }
    if (memo[n] == 0) {
        memo[n] = fib(n - 1) + fib(n - 2);
    }
    return memo[n];
}

int main(void) {
    long long first = fib(40);
    printf("fib(40) = %lld, вызовов: %lld\n", first, calls);
    long long again = fib(40);
    printf("ещё раз: %lld, вызовов всего: %lld\n", again, calls);
    return 0;
}
```

Вывод:

```text
fib(40) = 102334155, вызовов: 79
ещё раз: 102334155, вызовов всего: 80
```

Первый вызов `fib(40)` прошёл рекурсией до низа и на обратном пути заполнил кэш — 79 вызовов. Без кэша понадобилось бы 331 160 281 вызов: каждое значение пересчитывалось бы заново. Второй вызов сразу нашёл готовое значение в `memo[40]`: кэш живёт между вызовами, потому что массив `static`.

Значение и счётчик сохранены в переменные до `printf` не случайно: порядок вычисления аргументов функции в C не определён, и в записи `printf("%lld %lld", fib(40), calls)` компилятор вправе прочитать `calls` раньше, чем вызовет `fib`.

Важная подробность: `static` переменные (локальные и глобальные) без инициализатора заполняются **нулями**, а инициализатор обязан быть **константным выражением** — значение должно быть известно до запуска программы:

```c
#include <stdio.h>

int start_value(void) {
    return 5;
}

int next(void) {
    static int value = start_value();   // Ошибка компиляции: initializer element is not constant
    return value++;
}

int main(void) {
    printf("%d\n", next());
    return 0;
}
```

## Указатель на `static` буфер

Функция может вернуть указатель на свою `static` переменную: в отличие от обычной локальной, она не исчезнет после возврата. Так устроены некоторые стандартные функции, например `asctime` и `strerror`. Но буфер **один на все вызовы**, и каждый следующий вызов затирает результат предыдущего:

```c
#include <stdio.h>

const char *format_time(int seconds) {
    static char buffer[16];
    snprintf(buffer, sizeof buffer, "%02d:%02d:%02d",
             seconds / 3600, seconds / 60 % 60, seconds % 60);
    return buffer;
}

int main(void) {
    const char *start = format_time(3600);
    const char *end = format_time(7322);
    printf("%s - %s\n", start, end);
    return 0;
}
```

Вывод:

```text
02:02:02 - 02:02:02
```

Оба указателя `start` и `end` указывают на один и тот же массив, в котором после второго вызова лежит `02:02:02`. Ещё коварнее запись `printf("%s - %s\n", format_time(3600), format_time(7322));`: из-за неопределённого порядка вычисления аргументов GCC и Clang напечатают разные, но одинаково неправильные строки.

Надёжный интерфейс — буфер передаёт вызывающий код: `void format_time(int seconds, char *out, size_t size)`. Тогда у каждого вызова своя память.

## `static` в заголовке

`static` в заголовке почти всегда ошибка. Заголовок вставляется в каждый `.c` файл, поэтому строка

```c counter.h
static int counter = 0;
```

создаёт в **каждом** файле свою отдельную переменную `counter`. Сборка пройдёт без ошибок, но если `main.c` увеличит счётчик, `report.c` по-прежнему увидит ноль — это два разных объекта. Для общей переменной нужен `extern` (следующий урок), для скрытой — `static` в `.c` файле.

Исключение — короткие функции `static inline`. Их кладут в заголовок намеренно: каждый файл получает свою копию, конфликта имён нет, а компилятор может встроить тело функции прямо в место вызова:

```c minmax.h
static inline int max_int(int a, int b) {
    return a > b ? a : b;
}
```

## Компилятор находит мёртвый код

У `static`-функции есть ещё одно достоинство: компилятор знает **всех** её пользователей — они в том же файле. Если функцию никто не вызывает, GCC и Clang предупредят:

```c
#include <stdio.h>

// Предупреждение: 'old_format' defined but not used
static int old_format(int x) {
    return x * 100;
}

int main(void) {
    printf("готово\n");
    return 0;
}
```

Вывод:

```text
готово
```

```text
main.c:4:12: warning: 'old_format' defined but not used [-Wunused-function]
```

Для функции без `static` такого предупреждения не бывает: компилятор не знает, не вызывают ли её из другого файла.

<Concept title="Видимость по умолчанию — слишком широкая">

В C функции и глобальные переменные по умолчанию видны всей программе. Это исторический выбор, а не хорошая практика. Пишите `static` везде, где имя не нужно другим файлам, — и интерфейс модуля сведётся к тому, что объявлено в заголовке.

</Concept>

## Частые ошибки

<CommonMistake title="Вспомогательная функция без static">

Функция `trim`, `gcd` или `swap` без `static` попадает в общий список имён программы и рано или поздно столкнётся с одноимённой функцией другого модуля или библиотеки.

</CommonMistake>

<CommonMistake title="Ожидание, что static локальная обнулится">

`static int count = 0;` внутри функции выполняет присваивание нуля **один раз**. При втором вызове `count` хранит старое значение. Если нужен свежий счётчик на каждый вызов, `static` не нужен.

</CommonMistake>

<CommonMistake title="Два вызова функции со static буфером в одном выражении">

`printf("%s %s", f(a), f(b))` с функцией, возвращающей указатель на `static` буфер, печатает одну строку дважды. Сохраните результат первого вызова в свой массив или передавайте буфер параметром.

</CommonMistake>

<CommonMistake title="static переменная в заголовке">

Каждый файл получает свою копию, и «общий» счётчик на деле оказывается несколькими независимыми. Компилятор и линковщик молчат.

</CommonMistake>

2. В примере с `fib` уберите `static` у массива `memo`, допишите `= {0}` и замените 40 на 30. Сколько вызовов понадобится теперь и почему?

## Практика

1. **Генератор идентификаторов** — внутреннее состояние модуля в `static` переменных.
2. **Биномиальные коэффициенты с кэшем** — `static` таблица внутри функции.
3. **Найди ошибку: общий буфер** — функция форматирования возвращает `static` буфер.
4. **Модуль случайных чисел** — скрытое состояние генератора.

## Итоги

- `static` перед функцией или глобальной переменной даёт **внутреннее связывание**: имя видно только в своём `.c` файле, линковщик о нём не знает.
- Всё, чего нет в заголовке модуля, объявляют `static`: вспомогательные функции и внутреннее состояние.
- `static` локальная переменная создаётся один раз, живёт до конца программы и хранит значение между вызовами. Применения — счётчики и кэши.
- `static` переменные без инициализатора равны нулю, инициализатор должен быть константным выражением.
- Указатель на `static` буфер переживает вызов, но буфер общий: следующий вызов затирает результат.
- `static` переменная в заголовке создаёт отдельную копию в каждом файле. В заголовке уместны только функции `static inline`.
