## Поток и `FILE *`

До сих пор программа получала данные из `stdin` и печатала в `stdout`. Настоящие программы читают конфигурации, журналы, таблицы и сохраняют результаты в файлы. В стандартной библиотеке C файл открывается как **поток** — объект типа `FILE`, с которым работают через указатель `FILE *`.

`FILE` — непрозрачный тип, как в уроке о заголовках: внутри лежат буфер, текущая позиция в файле, признаки конца файла и ошибки, но поля структуры программе не нужны — всё делают функции `<stdio.h>`. Три потока открыты всегда:

| Поток    | Что это                       | Связанные функции               |
| -------- | ----------------------------- | ------------------------------- |
| `stdin`  | стандартный ввод              | `scanf` = `fscanf(stdin, …)`    |
| `stdout` | стандартный вывод             | `printf` = `fprintf(stdout, …)` |
| `stderr` | вывод ошибок, без буферизации | `fprintf(stderr, …)`, `perror`  |

Функции с буквой `f` — `fprintf`, `fscanf`, `fgets`, `fputs` — принимают поток первым или последним аргументом и работают одинаково с файлами и стандартными потоками.

## Открыть и закрыть

```c
FILE *fopen(const char *path, const char *mode);
int fclose(FILE *stream);
```

`fopen` открывает файл и возвращает поток или `NULL`, если открыть не удалось: файла нет, нет прав, путь указывает на каталог. Проверять результат нужно **всегда**. `fclose` записывает остаток буфера, закрывает файл и освобождает поток; для файла, в который писали, её результат тоже стоит проверить — ошибка записи может обнаружиться только здесь.

Режим открытия — строка:

| Режим  | Если файла нет | Если файл есть           | Чтение | Запись         |
| ------ | -------------- | ------------------------ | ------ | -------------- |
| `"r"`  | ошибка         | читать с начала          | да     | нет            |
| `"w"`  | создать        | **стереть** содержимое   | нет    | да             |
| `"a"`  | создать        | дописывать в конец       | нет    | только в конец |
| `"r+"` | ошибка         | читать и писать с начала | да     | да             |
| `"w+"` | создать        | стереть                  | да     | да             |
| `"a+"` | создать        | читать, писать в конец   | да     | только в конец |

С C11 к `"w"` можно добавить `x`: `"wx"` не сотрёт существующий файл, а вернёт ошибку. Буква `b` — двоичный режим, о нём в следующих уроках.

Программа в песочнице курса работает во временном каталоге, поэтому может создавать файлы. После завершения программы они исчезают:

```c
#include <stdio.h>

int main(void) {
    FILE *out = fopen("notes.txt", "w");
    if (out == NULL) {
        perror("notes.txt");
        return 1;
    }
    fprintf(out, "купить хлеб\n");
    fputs("позвонить маме\n", out);
    fputc('!', out);
    fputc('\n', out);
    if (fclose(out) != 0) {
        perror("запись notes.txt");
        return 1;
    }

    FILE *in = fopen("notes.txt", "r");
    if (in == NULL) {
        perror("notes.txt");
        return 1;
    }
    char line[100];
    int number = 0;
    while (fgets(line, sizeof line, in) != NULL) {
        printf("%d: %s", ++number, line);
    }
    fclose(in);
    return 0;
}
```

Вывод:

```text
1: купить хлеб
2: позвонить маме
3: !
```

`perror` печатает в `stderr` переданный текст и описание последней ошибки системы, например `notes.txt: No such file or directory`. Подробнее о том, откуда берётся это описание, — в уроке об `errno`.

## Чтение строк: `fgets`

```c
char *fgets(char *buffer, int size, FILE *stream);
```

`fgets` читает до перевода строки включительно, но не больше `size − 1` символов, и дописывает `'\0'`. Возвращает `buffer` или `NULL`, если ничего не прочитано (конец файла или ошибка). Две особенности:

- перевод строки **остаётся** в буфере — его удаляют выражением `line[strcspn(line, "\n")] = '\0';`;
- если строка длиннее буфера, `fgets` вернёт её начало без `'\n'`, а следующий вызов продолжит с того же места.

```c
#include <stdio.h>
#include <string.h>

int main(void) {
    FILE *f = fopen("data.txt", "w");
    if (f == NULL) {
        return 1;
    }
    fputs("short\na rather long line\n", f);
    fclose(f);

    f = fopen("data.txt", "r");
    if (f == NULL) {
        return 1;
    }
    char part[8];                        // нарочно маленький буфер
    while (fgets(part, sizeof part, f) != NULL) {
        int whole = strchr(part, '\n') != NULL;
        part[strcspn(part, "\n")] = '\0';
        printf("[%s]%s\n", part, whole ? "" : " ...продолжение следует");
    }
    fclose(f);
    return 0;
}
```

Вывод:

```text
[short]
[a rathe] ...продолжение следует
[r long ] ...продолжение следует
[line]
```

Буфер на 8 байтов вмещает 7 символов строки и завершающий ноль. Строка `short` с переводом строки поместилась целиком, а длинная пришла тремя кусками, и только в последнем есть `'\n'`. Размер буфера считается в **байтах**: русская буква в UTF-8 занимает два байта, и маленький буфер может разрезать букву пополам. Поэтому буфер берут с запасом и проверяют, дочитана ли строка до `'\n'`.

## Чтение символов: `fgetc` и `EOF`

`fgetc` возвращает следующий байт как `unsigned char`, преобразованный в `int`, или `EOF` (обычно −1) в конце файла. Результат нужно хранить в `int`: в `char` нельзя отличить `EOF` от байта `0xFF`.

```c
#include <stdio.h>

int main(void) {
    FILE *f = fopen("letters.txt", "w");
    if (f == NULL) {
        return 1;
    }
    fputs("abc\nde\n", f);
    fclose(f);

    f = fopen("letters.txt", "r");
    if (f == NULL) {
        return 1;
    }
    int c;                                // int, а не char
    int bytes = 0, lines = 0;
    while ((c = fgetc(f)) != EOF) {
        bytes++;
        if (c == '\n') {
            lines++;
        }
    }
    printf("байтов %d, строк %d\n", bytes, lines);
    fclose(f);
    return 0;
}
```

Вывод:

```text
байтов 7, строк 2
```

## Конец файла или ошибка: `feof` и `ferror`

У потока есть два признака: **конец файла** и **ошибка**. Они устанавливаются, только когда операция чтения **уже не удалась**. Отсюда частая ошибка — проверять `feof` до чтения:

```c
#include <stdio.h>

int main(void) {
    FILE *f = fopen("nums.txt", "w");
    if (f == NULL) {
        return 1;
    }
    fputs("10\n20\n30\n", f);
    fclose(f);

    f = fopen("nums.txt", "r");
    if (f == NULL) {
        return 1;
    }
    int value = 0, sum = 0;
    while (!feof(f)) {                    // неправильно
        fscanf(f, "%d", &value);
        sum += value;
    }
    printf("сумма %d\n", sum);            // ожидали 60
    fclose(f);
    return 0;
}
```

Вывод:

```text
сумма 90
```

После чтения числа 30 конец файла ещё не достигнут: в файле остался перевод строки. Цикл делает ещё одну итерацию, `fscanf` ничего не читает, `value` остаётся равным 30 — и оно прибавляется второй раз. Правильная схема: условием цикла служит **результат чтения**, а `feof` и `ferror` используют после цикла, чтобы узнать, почему чтение закончилось:

```c
while (fscanf(f, "%d", &value) == 1) {
    sum += value;
}
if (ferror(f)) {
    perror("чтение nums.txt");
} else if (!feof(f)) {
    fprintf(stderr, "в файле не число\n");
}
```

## Буферизация

Поток не обращается к диску при каждом `fputc`: он копит данные в буфере и записывает их блоком. Это во много раз быстрее, но меняет привычную картину:

- данные попадают в файл при заполнении буфера, при `fflush(f)` и при `fclose(f)`. Если программа упадёт раньше, хвост буфера пропадёт;
- `stdout` буферизуется построчно, если вывод идёт в терминал, и блоками — если в файл или программу. `stderr` не буферизуется совсем. Поэтому при перенаправлении вывода сообщения об ошибках и обычный вывод могут перемешаться не в том порядке, в каком их печатали;
- в потоке, открытом на чтение и запись (`"r+"`, `"w+"`), между записью и чтением обязателен `fflush` или переход позиции (`fseek`, `rewind`). Без них поведение не определено.

## Функция для любого потока

Раз стандартные потоки — тоже `FILE *`, функцию обработки удобно писать для потока, а не для имени файла. Тогда она одинаково работает с файлом, `stdin` и временным файлом:

```c
#include <stdio.h>

static long count_words(FILE *in) {
    long words = 0;
    int c, inside = 0;
    while ((c = fgetc(in)) != EOF) {
        if (c == ' ' || c == '\n' || c == '\t') {
            inside = 0;
        } else if (!inside) {
            inside = 1;
            words++;
        }
    }
    return words;
}

int main(void) {
    FILE *f = fopen("text.txt", "w");
    if (f == NULL) {
        return 1;
    }
    fputs("раз два  три\nчетыре\n", f);
    fclose(f);
    f = fopen("text.txt", "r");
    if (f == NULL) {
        return 1;
    }
    printf("в файле %ld слов\n", count_words(f));
    fclose(f);
    printf("в stdin %ld слов\n", count_words(stdin));
    return 0;
}
```

Ввод:

```text
ещё три слова
```

Вывод:

```text
в файле 4 слов
в stdin 3 слов
```

<Concept title="Поток — посредник между программой и файлом">

Программа никогда не пишет на диск напрямую: она передаёт данные потоку, а поток решает, когда отдать их операционной системе. У потока есть позиция, буфер и два признака — конца файла и ошибки. Почти все ошибки с файлами — непроверенный `fopen`, лишняя итерация с `feof`, потерянный хвост без `fclose` — следуют из того, что об этом посреднике забыли.

</Concept>

## Частые ошибки

<CommonMistake title="Непроверенный fopen">

`FILE *f = fopen(name, "r"); fgets(line, 100, f);` при отсутствии файла передаст `NULL` в `fgets` — программа упадёт. Проверяйте результат и сообщайте об ошибке через `perror`.

</CommonMistake>

<CommonMistake title="while (!feof(f))">

`feof` становится истинным только после неудачного чтения, поэтому последняя итерация обрабатывает старые данные. Условие цикла — результат функции чтения.

</CommonMistake>

<CommonMistake title="char для результата fgetc">

`char c = fgetc(f);` смешивает `EOF` с байтом `0xFF`: цикл закончится раньше времени (или никогда, если `char` беззнаковый). Храните результат в `int`.

</CommonMistake>

<CommonMistake title="Забытый fclose">

Незакрытый поток держит открытый файл: процессу позволено открыть ограниченное число файлов (в песочнице — 64). Кроме того, хвост буфера записи без `fclose` может не попасть в файл.

</CommonMistake>

## Итоги

- Файл открывается как поток `FILE *`; `stdin`, `stdout`, `stderr` — тоже потоки, и функции с буквой `f` работают со всеми одинаково.
- `fopen` возвращает `NULL` при ошибке — проверяйте всегда; режим `"w"` стирает файл, `"a"` дописывает в конец.
- `fclose` записывает остаток буфера; для записанных файлов проверяйте её результат.
- `fgets` читает строку вместе с `'\n'`, но не больше размера буфера в байтах; `fgetc` возвращает `int`, чтобы отличать `EOF`.
- Признаки конца файла и ошибки устанавливаются после неудачного чтения: условие цикла — результат чтения, `feof` и `ferror` — после цикла.
- Потоки буферизуются: данные попадают в файл при `fflush`, `fclose` или заполнении буфера; между записью и чтением в потоке `"r+"` нужен `fflush` или `fseek`.
