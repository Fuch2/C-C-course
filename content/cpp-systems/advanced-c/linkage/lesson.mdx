## Три вопроса к каждому имени

В прошлых уроках слова `static` и `extern` меняли то видимость имени, то время жизни переменной. Чтобы перестать путаться, разложим всё по полочкам. У каждого объявления в C есть три **независимых** свойства:

1. **Область видимости** (scope) — в какой части текста программы имя можно использовать.
2. **Связывание** (linkage) — обозначают ли одинаковые имена в разных объявлениях один и тот же объект.
3. **Время хранения** (storage duration) — когда объект создаётся и когда исчезает. Это свойство есть только у переменных.

Первое — про текст, второе — про сборку из файлов, третье — про работу программы. Слова `static` и `extern` меняют разные из этих свойств в зависимости от того, где стоят, — отсюда и путаница.

## Область видимости

Видов области видимости в C четыре:

- **блок** — от объявления до закрывающей `}` блока. Локальные переменные и параметры функций (их блок — тело функции);
- **файл** — от объявления до конца единицы трансляции. Всё, что объявлено вне функций;
- **прототип функции** — имена параметров в объявлении `int area(int w, int h);` видны только внутри скобок, поэтому их можно не писать или назвать иначе, чем в определении;
- **функция** — только у меток `goto`: метка видна во всей функции, даже выше места, где она поставлена.

Внутренний блок может объявить имя, уже видимое снаружи, — тогда внешнее **скрыто** до конца блока. Это вы уже видели в «Основах C».

## Связывание: одно имя — один объект?

Если имя `count` объявлено в двух местах, это одна переменная или две? Ответ даёт связывание:

- **внешнее** — все объявления с этим именем во всей программе обозначают **один** объект или функцию. Так по умолчанию у функций и у переменных вне функций;
- **внутреннее** — одно имя обозначает один объект в пределах **своей единицы трансляции**, в другом файле то же имя — другой объект. Его даёт `static` вне функций;
- **нет связывания** — каждое объявление создаёт **отдельный** объект. Так у локальных переменных и параметров, в том числе у локальных `static`.

```c
#include <stdio.h>

static int count = 100;      // область — файл, связывание внутреннее

void tick(void) {
    static int count = 0;    // область — блок, связывания нет: другая переменная
    count++;
    printf("tick: %d\n", count);
}

int main(void) {
    tick();
    tick();
    printf("файловая: %d\n", count);
    return 0;
}
```

Вывод:

```text
tick: 1
tick: 2
файловая: 100
```

В программе две переменные `count`. Локальная `static` скрывает файловую внутри `tick` и, несмотря на `static`, не имеет связывания: никакое другое объявление на неё сослаться не может.

## Время хранения

- **автоматическое** — объект создаётся при входе в блок и исчезает при выходе. Обычные локальные переменные и параметры;
- **статическое** — объект существует всё время работы программы, инициализируется до `main` и по умолчанию равен нулю. Переменные вне функций и локальные `static`;
- **выделенное** — объект создаёт `malloc` и уничтожает `free`. У него нет имени — только адрес;
- **потоковое** — `_Thread_local` (C11): у каждого потока своя копия. Понадобится в многопоточных программах.

## Сводная таблица

| Объявление                  | Область   | Связывание | Время хранения |
| --------------------------- | --------- | ---------- | -------------- |
| `int x;` вне функций        | файл      | внешнее    | статическое    |
| `static int x;` вне функций | файл      | внутреннее | статическое    |
| `extern int x;` вне функций | файл      | внешнее¹   | статическое    |
| `int x;` в блоке, параметр  | блок      | нет        | автоматическое |
| `static int x;` в блоке     | блок      | нет        | статическое    |
| `extern int x;` в блоке     | блок      | внешнее¹   | статическое    |
| `int f(void);` где угодно   | файл/блок | внешнее¹   | —              |
| `static int f(void) { … }`  | файл      | внутреннее | —              |

¹ Если раньше в файле видно объявление того же имени со `static`, связывание будет внутренним: `extern` повторяет связывание предыдущего объявления, а не задаёт его заново.

Таблица объясняет, почему у `static` два смысла. Вне функций время хранения и так статическое, и `static` меняет **связывание**. В блоке связывания и так нет, и `static` меняет **время хранения**. Слово одно, а меняет каждый раз то единственное свойство, которое там вообще можно поменять.

## Имена, занятые стандартной библиотекой

Внешнее связывание означает, что ваши имена делят одно пространство не только с другими модулями, но и с библиотекой C. Все имена её функций зарезервированы: собственная функция `log`, `index`, `time` или `remove` формально даёт неопределённое поведение, а на практике — предупреждения или конфликты:

```c
#include <stdio.h>

// Предупреждение: conflicting types for built-in function 'log'
void log(const char *text) {
    printf("[log] %s\n", text);
}

int main(void) {
    log("старт");
    return 0;
}
```

Вывод:

```text
[log] старт
```

Программа запустилась, но компилятор предупредил: `log` — встроенная функция из `<math.h>` с типом `double(double)`. Стоит кому-нибудь подключить `<math.h>`, и предупреждение превратится в ошибку `conflicting types for 'log'`.

Кроме имён стандартных функций, зарезервированы:

- идентификаторы, начинающиеся с подчёркивания и заглавной буквы или с двух подчёркиваний (`_Value`, `__count`);
- имена вне функций, начинающиеся с подчёркивания (`_buffer`);
- внешние имена, которые начинаются с `str`, `mem`, `is` или `to` и строчной буквы: стандарт оставил их для будущих функций библиотеки. Под правило попадают `strip`, `memory_used`, `isvalid` и даже `total`. Нарушают его повсюду, и обычно это сходит с рук, но это ещё один довод за префикс проекта.

Самое надёжное правило — то же, что для модулей: внешние имена с префиксом проекта (`app_log`), внутренние — `static`.

## `inline` и связывание

Ключевое слово `inline` (C99) подсказывает компилятору встроить тело функции в место вызова. Но у него есть ловушка, связанная со связыванием. Функция с `inline` и без `static` **не создаёт** внешнего определения — компилятор вправе встроить её, а если не встроил, ищет обычное определение в другом файле. Без оптимизации (`-O0`) встраивания нет, и сборка падает:

```c
#include <stdio.h>

inline int twice(int x) {        // Ошибка компиляции: undefined reference to `twice'
    return 2 * x;
}

int main(void) {
    printf("%d\n", twice(4));
    return 0;
}
```

Правила для «чистого» `inline` с внешним связыванием запутанные: нужно ещё одно объявление с `extern` ровно в одном `.c` файле. Поэтому на практике пишут `static inline`: каждая единица трансляции получает свою копию, связывание внутреннее, конфликтов нет, а компилятор встраивает функцию, когда это выгодно. Именно так оформляют короткие функции в заголовках:

```c
#include <stdio.h>

static inline int clamp(int value, int low, int high) {
    return value < low ? low : value > high ? high : value;
}

int main(void) {
    printf("%d %d %d\n", clamp(-5, 0, 10), clamp(5, 0, 10), clamp(50, 0, 10));
    return 0;
}
```

Вывод:

```text
0 5 10
```

## Как спроектировать связывание модуля

| Что                                     | Где объявить                                          | Связывание |
| --------------------------------------- | ----------------------------------------------------- | ---------- |
| функции интерфейса                      | прототип в `.h`, определение в `.c`                   | внешнее    |
| вспомогательные функции                 | только в `.c`, со `static`                            | внутреннее |
| состояние модуля                        | `static` переменные в `.c`                            | внутреннее |
| действительно общая переменная          | `extern` в `.h`, одно определение в `.c`              | внешнее    |
| короткие функции для всех пользователей | `static inline` в `.h`                                | внутреннее |
| константы                               | `enum` или `#define` в `.h`; таблицы — `extern const` | —          |

<Concept title="Связывание — договор с линковщиком">

Область видимости решает компилятор, глядя на текст одного файла. Связывание решает, что увидит линковщик: только имена с внешним связыванием попадают в общий список имён программы. Чем меньше в этом списке имён от вашего модуля, тем меньше шансов на конфликт и тем свободнее можно менять внутренности модуля.

</Concept>

## Частые ошибки

<CommonMistake title="Путать видимость и время жизни">

`static int calls;` внутри функции живёт всю программу, но видна только в своём блоке. Из другой функции к ней не обратиться — для этого нужна переменная файла.

</CommonMistake>

<CommonMistake title="Локальная переменная с именем глобальной">

Объявили внутри функции `int total = 0;`, а хотели обновлять глобальную `total`. Компилятор молчит (предупреждает только флаг `-Wshadow`), а глобальная переменная так и остаётся нулём.

</CommonMistake>

<CommonMistake title="Своя функция с библиотечным именем">

`log`, `abs`, `exit`, `time`, `index`, `remove` уже заняты. Даже если программа собирается, она полагается на неопределённое поведение.

</CommonMistake>

<CommonMistake title="inline без static">

`inline int f(...)` в заголовке без отдельного внешнего определения даёт `undefined reference` при сборке без оптимизации. Пишите `static inline`.

</CommonMistake>

## Итоги

- У имени три независимых свойства: область видимости (где видно в тексте), связывание (одно ли это имя для разных объявлений) и время хранения (сколько живёт объект).
- Связывание бывает внешним (одно имя — один объект во всей программе), внутренним (в пределах файла) и отсутствует у локальных имён.
- Время хранения: автоматическое, статическое, выделенное (`malloc`) и потоковое.
- `static` вне функций меняет связывание, внутри блока — время хранения.
- `extern` повторяет связывание ранее видимого объявления, а если его нет — даёт внешнее.
- Имена функций стандартной библиотеки и идентификаторы с `_` + заглавной буквой или `__` зарезервированы.
- Короткие функции в заголовках объявляют `static inline`; «чистое» `inline` требует отдельного внешнего определения.
