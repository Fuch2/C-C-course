## Сдвиг влево и вправо

Вы уже пользовались сдвигами, не разбирая их подробно: `1u << n` строил маску, `x >> 24` доставал старший байт. Пора разобраться, как они работают и где их ловушки — а ловушек у сдвигов больше, чем у остальных побитовых операций.

`x << n` сдвигает биты влево на `n` позиций: старшие биты уходят за край, справа приходят нули. Для беззнакового числа это умножение на 2ⁿ (с отбрасыванием того, что не поместилось). `x >> n` сдвигает вправо: младшие биты пропадают, слева у беззнаковых чисел приходят нули — это деление на 2ⁿ с отбрасыванием остатка.

```c
#include <stdio.h>

static void print_bits(unsigned value) {
    for (int i = 7; i >= 0; i--) {
        putchar((value >> i) & 1u ? '1' : '0');
    }
}

int main(void) {
    unsigned x = 0x2Du;                          // 0010 1101 = 45
    print_bits(x);
    printf(" = %u\n", x);
    print_bits((x << 2) & 0xFFu);
    printf(" = %u\n", (x << 2) & 0xFFu);         // 45 * 4 = 180
    print_bits(x >> 3);
    printf(" = %u\n", x >> 3);                   // 45 / 8 = 5
    return 0;
}
```

Вывод:

```text
00101101 = 45
10110100 = 180
00000101 = 5
```

Компиляторы сами заменяют умножение и деление на степень двойки сдвигами, поэтому `x * 8` в программе так же быстр, как `x << 3`. Пишите то, что выражает смысл: арифметику — арифметикой, работу с битами — сдвигами.

## Тип результата: продвижение левого операнда

Результат сдвига имеет тип **левого операнда после продвижения**. Значения меньше `int` — `char`, `uint8_t`, `uint16_t` — перед сдвигом превращаются в `int`, поэтому «вытолкнутые» биты никуда не пропадают:

```c
#include <stdint.h>
#include <stdio.h>

int main(void) {
    uint8_t b = 0xF0;
    printf("%d\n", b << 4);                  // int: 0xF00 = 3840
    uint8_t kept = (uint8_t)(b << 4);        // явно обрезать до 8 бит
    printf("%u\n", (unsigned)kept);
    return 0;
}
```

Вывод:

```text
3840
0
```

Чтобы получить результат нужной ширины, его присваивают переменной этого типа или приводят явно.

## Когда сдвиг не определён

Стандарт C перечисляет случаи, в которых сдвиг — неопределённое поведение. Их три, и каждый встречается в реальном коде:

1. **Величина сдвига отрицательна или не меньше ширины типа**: `x << 32` для 32-битного `x`. Процессор x86 берёт от величины сдвига только младшие 5 битов, поэтому `1u << 32` на нём даёт `1`, а не `0`.
2. **Сдвиг влево знакового числа, результат которого не помещается в тип**: `1 << 31` для 32-битного `int` — единица попадает в знаковый бит.
3. **Сдвиг влево отрицательного числа**: `-1 << 3`.

Литерал `1` имеет тип `int`, поэтому самая частая ошибка — маска старшего бита:

```c
#include <stdio.h>

int main(void) {
    int bit = 31;
    unsigned mask = 1 << bit;     // Ошибка выполнения: left shift of 1 by 31 places cannot be represented in type 'int'
    printf("%08X\n", mask);
    return 0;
}
```

Без санитайзера программа, скорее всего, напечатает `80000000` — и ошибка останется незамеченной до смены компилятора или уровня оптимизации. UBSan останавливает её с сообщением, приведённым в комментарии. Правильная запись — `1u << bit`: беззнаковая единица, и бит 31 законен. Для 64-битных масок нужна 64-битная единица: `UINT64_C(1) << 40` или `1ull << 40`; `1u << 40` — снова сдвиг на величину больше ширины типа.

## Сдвиг вправо отрицательных чисел

Для отрицательного знакового числа результат `>>` определяется **реализацией**. GCC и Clang выполняют арифметический сдвиг: слева приходят копии знакового бита, и число остаётся отрицательным. Но это не деление: деление в C округляет к нулю, а арифметический сдвиг — вниз.

```c
#include <stdio.h>

int main(void) {
    int x = -7;
    printf("%d %d\n", x >> 1, x / 2);
    printf("%d %d\n", 7 >> 1, 7 / 2);
    return 0;
}
```

Вывод:

```text
-4 -3
3 3
```

Ещё один довод держать битовые операции в беззнаковых типах.

## Приоритет: сдвиг слабее арифметики

`<<` и `>>` выполняются **после** `+` и `-`. Запись `1 << n - 1` — это `1 << (n - 1)`, а `x << 2 + 1` — сдвиг на 3. Если вы имели в виду другое, это ошибка, о которой GCC предупреждает (`suggest parentheses around '+' inside '<<'`). При сочетании сдвигов с арифметикой всегда ставьте скобки.

## Байты и поля: сдвинь и наложи маску

Сдвиг вправо переносит нужную группу битов к нулевой позиции, маска отрезает лишнее. Сдвиг влево и `|` собирают число обратно. Так упаковывают цвет `0xRRGGBB`:

```c
#include <stdint.h>
#include <stdio.h>

static uint32_t pack_rgb(unsigned r, unsigned g, unsigned b) {
    return (uint32_t)r << 16 | (uint32_t)g << 8 | (uint32_t)b;
}

int main(void) {
    uint32_t color = pack_rgb(255, 128, 16);
    printf("#%06X\n", (unsigned)color);
    unsigned r = (color >> 16) & 0xFFu;
    unsigned g = (color >> 8) & 0xFFu;
    unsigned b = color & 0xFFu;
    printf("%u %u %u\n", r, g, b);
    return 0;
}
```

Вывод:

```text
#FF8010
255 128 16
```

Приведение `(uint32_t)r` перед сдвигом здесь не украшение. Если сдвигать байт без приведения, он продвинется до `int`, и для байтов от 128 сдвиг на 24 позиции переполнит `int` — снова неопределённое поведение:

```c
#include <stdint.h>
#include <stdio.h>

int main(void) {
    unsigned char bytes[4] = {0xFF, 0x00, 0x00, 0x01};
    uint32_t value = bytes[0] << 24 | bytes[3];    // Ошибка выполнения: left shift of 255 by 24 places cannot be represented in type 'int'
    printf("%08X\n", (unsigned)value);
    return 0;
}
```

Правильно — `(uint32_t)bytes[0] << 24`, как в уроке о порядке байтов.

## Циклический сдвиг

У процессоров есть инструкция **циклического сдвига** (rotate): биты, ушедшие за один край, возвращаются с другого. В C отдельной операции нет, её собирают из двух сдвигов:

```c
#include <stdint.h>
#include <stdio.h>

static uint32_t rotl32(uint32_t x, unsigned n) {
    n &= 31;                                        // сдвиг на 32 и больше — по кругу
    return (x << n) | (x >> ((32 - n) & 31));
}

int main(void) {
    uint32_t x = 0x12345678u;
    printf("%08X\n", (unsigned)rotl32(x, 8));
    printf("%08X\n", (unsigned)rotl32(x, 0));
    printf("%08X\n", (unsigned)rotl32(x, 36));
    return 0;
}
```

Вывод:

```text
34567812
12345678
23456781
```

Маска `& 31` во втором сдвиге важна: при `n = 0` без неё получилось бы `x >> 32` — неопределённое поведение. GCC и Clang узнают эту запись и превращают её в одну инструкцию `rol`. Циклические сдвиги — основа многих хеш-функций и шифров: они перемешивают биты, ничего не теряя.

<Concept title="Сдвиг — это перенос битов, а не арифметика">

Для беззнаковых чисел сдвиг совпадает с умножением и делением на степень двойки — пока биты не уходят за край. Для знаковых чисел совпадение ломается: отрицательные значения и переполнение знакового бита дают неопределённое или зависящее от реализации поведение. Думайте о сдвиге как о переносе битов и выполняйте его в беззнаковых типах подходящей ширины.

</Concept>

## Частые ошибки

<CommonMistake title="1 << 31 и 1u << 40">

`1` — это `int`: сдвиг в знаковый бит не определён. `1u` — 32 бита: сдвиг на 40 не определён. Маски: `1u << n` для `n < 32`, `UINT64_C(1) << n` для 64 бит.

</CommonMistake>

<CommonMistake title="Сдвиг байта без приведения">

`b << 24` для `unsigned char b` выполняется в `int` и переполняется при `b ≥ 128`. Приводите к `uint32_t` до сдвига.

</CommonMistake>

<CommonMistake title="Величина сдвига из данных">

Если `n` пришло из ввода или вычислений, проверьте `0 ≤ n < ширина` или наложите маску `n & 31`. Иначе программа может работать на одной платформе и ломаться на другой.

</CommonMistake>

<CommonMistake title="Сдвиг вместо деления отрицательного числа">

`-7 >> 1` равно `-4`, а `-7 / 2` — `-3`. Для деления используйте `/`; компилятор сам подберёт быструю последовательность команд.

</CommonMistake>

## Практика

1. **Циклический сдвиг** — `rol` и `ror` для 32-битных чисел.
2. **Цвета RGB и RGB565** — упаковка и распаковка полей цвета.
3. **Найди ошибку: старший канал** — маска `1 << 31`.
4. **Base64** — кодирование и декодирование по шесть битов.

## Итоги

- `x << n` сдвигает биты влево (для беззнаковых — умножение на 2ⁿ), `x >> n` — вправо (деление на 2ⁿ).
- Тип результата — продвинутый тип левого операнда: `uint8_t` и `uint16_t` сдвигаются как `int`.
- Неопределённое поведение: величина сдвига < 0 или ≥ ширины типа, переполнение знакового числа при сдвиге влево, сдвиг влево отрицательного числа. `1 << 31` — ошибка, `1u << 31` — нет.
- Сдвиг вправо отрицательного числа зависит от реализации и не равен делению.
- Сдвиги слабее `+` и `-` — ставьте скобки.
- Поля извлекают сдвигом и маской, собирают сдвигами и `|`, приводя части к нужному беззнаковому типу до сдвига.
- Циклический сдвиг: `(x << n) | (x >> ((32 - n) & 31))` при `n & 31`.
