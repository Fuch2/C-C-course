## Теория

Бинарный формат задаёт байты, их порядок и смысл независимо от представления структур компилятора. Запись struct целиком переносит padding, размер типов и порядок байтов машины; такой файл не становится переносимым протоколом. Задайте сигнатуру, версию, длины и способ кодирования чисел явно.

Парсер проверяет доступность байтов до обращения и ограничивает количество записей до выделения памяти. Для little-endian значения из двух октетов формула b0 | (b1 &lt;&lt; 8) работает после преобразования к достаточно широкому unsigned. В C байт не обязан быть восьмибитным; формат октетов требует CHAR_BIT == 8 или отдельной адаптации. Сначала проверяйте заголовок и длину, затем данные: частично разобранное сообщение не должно считаться успешным.

<Concept title="Ментальная модель">

Файл — договор о последовательности байтов, а не фотография struct в памяти.

</Concept>

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>

int main(void) {
    unsigned value=258;printf("%u %u\n",value & 255u,(value >> 8) & 255u);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
2 1
```

Файл — договор о последовательности байтов, а не фотография struct в памяти. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. fwrite(&record, sizeof record, 1, file) не определяет переносимый формат.

<CommonMistake title="Типичная ошибка">

fwrite(&record, sizeof record, 1, file) не определяет переносимый формат.

</CommonMistake>
