## От обобщённой функции к обобщённой структуре данных

В модуле о памяти вы писали функции, которые работают с любым типом: `swap_any` и разворот массива получали адрес, количество и **размер элемента** и работали с байтами, а `qsort` вызывала вашу функцию сравнения. В прошлом уроке появился контекст `void *ctx` — данные любого типа для callback'а.

Теперь соберём это вместе и построим **обобщённый контейнер** — динамический массив, который хранит элементы любого типа: `int`, `double`, структуры, указатели. Код контейнера будет один, а тип элементов определится при создании. Так устроены контейнеры в библиотеках на C: GLib (`GArray`), ядро Linux, интерпретаторы языков.

## Устройство: байты и размер элемента

Контейнер не знает типа элементов — только их размер. Данные хранятся в одном блоке памяти как последовательность элементов по `elem_size` байтов:

```c
typedef struct {
    void *data;          // блок памяти с элементами
    size_t size;         // сколько элементов сейчас
    size_t capacity;     // на сколько элементов хватает памяти
    size_t elem_size;    // размер одного элемента в байтах
} Vector;
```

Адрес элемента номер `i` вычисляется в байтах — через `char *`, потому что арифметика с `void *` в стандартном C запрещена:

```c
static void *vector_at(const Vector *v, size_t i) {
    return (char *)v->data + i * v->elem_size;
}
```

Значение кладут и достают **по адресу**: `push` получает указатель на значение и копирует `elem_size` байтов через `memcpy`. Тип исчез из интерфейса — остались адреса и размеры:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    void *data;
    size_t size, capacity, elem_size;
} Vector;

static void vector_init(Vector *v, size_t elem_size) {
    v->data = NULL;
    v->size = v->capacity = 0;
    v->elem_size = elem_size;
}

static void *vector_at(const Vector *v, size_t i) {
    return (char *)v->data + i * v->elem_size;
}

static int vector_push(Vector *v, const void *elem) {
    if (v->size == v->capacity) {
        size_t bigger = v->capacity ? v->capacity * 2 : 4;
        void *grown = realloc(v->data, bigger * v->elem_size);
        if (grown == NULL) {
            return 0;
        }
        v->data = grown;
        v->capacity = bigger;
    }
    memcpy(vector_at(v, v->size), elem, v->elem_size);
    v->size++;
    return 1;
}

static void vector_free(Vector *v) {
    free(v->data);
    vector_init(v, v->elem_size);
}

struct Point {
    int x, y;
};

int main(void) {
    Vector numbers, points;
    vector_init(&numbers, sizeof(int));
    vector_init(&points, sizeof(struct Point));

    for (int i = 1; i <= 5; i++) {
        int square = i * i;
        vector_push(&numbers, &square);          // передаём адрес значения
        struct Point p = {i, -i};
        vector_push(&points, &p);
    }
    for (size_t i = 0; i < numbers.size; i++) {
        printf("%d ", *(int *)vector_at(&numbers, i));
    }
    printf("\n");
    const struct Point *last = vector_at(&points, points.size - 1);
    printf("точек %zu, последняя (%d, %d), вместимость %zu\n", points.size, last->x, last->y,
           points.capacity);
    vector_free(&numbers);
    vector_free(&points);
    return 0;
}
```

Вывод:

```text
1 4 9 16 25
точек 5, последняя (5, -5), вместимость 8
```

Одни и те же функции работают с `int` и со структурой. Цена — ответственность программиста: приведение `*(int *)vector_at(...)` компилятор не проверяет, и если перепутать векторы, программа прочитает байты точки как число.

## Значения или указатели

Контейнер может хранить сами значения (как выше) или **указатели** на объекты. Вектор строк — это вектор элементов типа `char *`: `elem_size = sizeof(char *)`, а `push` получает адрес указателя.

Тогда встаёт вопрос **владения**: кто освободит сами строки? Если вектор ими владеет, ему нужна функция уничтожения элемента — ещё один callback:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef void Destroy(void *elem);

typedef struct {
    void *data;
    size_t size, capacity, elem_size;
    Destroy *destroy;               // как уничтожить элемент; NULL — ничего не делать
} Vector;

static int vector_push(Vector *v, const void *elem) {
    if (v->size == v->capacity) {
        size_t bigger = v->capacity ? v->capacity * 2 : 4;
        void *grown = realloc(v->data, bigger * v->elem_size);
        if (grown == NULL) {
            return 0;
        }
        v->data = grown;
        v->capacity = bigger;
    }
    memcpy((char *)v->data + v->size * v->elem_size, elem, v->elem_size);
    v->size++;
    return 1;
}

static void vector_free(Vector *v) {
    if (v->destroy != NULL) {
        for (size_t i = 0; i < v->size; i++) {
            v->destroy((char *)v->data + i * v->elem_size);
        }
    }
    free(v->data);
}

static void free_string(void *elem) {
    free(*(char **)elem);           // элемент — указатель на строку
}

static char *copy_string(const char *text) {
    size_t len = strlen(text) + 1;
    char *copy = malloc(len);
    if (copy != NULL) {
        memcpy(copy, text, len);
    }
    return copy;
}

int main(void) {
    Vector words = {NULL, 0, 0, sizeof(char *), free_string};
    const char *source[] = {"альфа", "бета", "гамма"};
    for (int i = 0; i < 3; i++) {
        char *copy = copy_string(source[i]);
        if (copy == NULL || !vector_push(&words, &copy)) {
            free(copy);
            break;
        }
    }
    for (size_t i = 0; i < words.size; i++) {
        printf("%s\n", ((char **)words.data)[i]);
    }
    vector_free(&words);            // освободит и строки, и массив указателей
    return 0;
}
```

Вывод:

```text
альфа
бета
гамма
```

Функция уничтожения получает **адрес элемента** — здесь это `char **`, а не `char *`. Тот же уровень косвенности вы встречали в функции сравнения строк для `qsort`.

## Указатель на элемент живёт до изменения вектора

`vector_at` возвращает адрес внутри блока `data`. Когда вектор растёт, `realloc` может переместить блок — и все ранее полученные указатели на элементы становятся висячими:

```c
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct {
    void *data;
    size_t size, capacity, elem_size;
} Vector;

static int vector_push(Vector *v, const void *elem) {
    if (v->size == v->capacity) {
        size_t bigger = v->capacity ? v->capacity * 2 : 4;
        void *grown = realloc(v->data, bigger * v->elem_size);
        if (grown == NULL) {
            return 0;
        }
        v->data = grown;
        v->capacity = bigger;
    }
    memcpy((char *)v->data + v->size * v->elem_size, elem, v->elem_size);
    v->size++;
    return 1;
}

int main(void) {
    Vector v = {NULL, 0, 0, sizeof(int)};
    int value = 10;
    vector_push(&v, &value);
    int *first = v.data;                    // указатель на первый элемент
    for (int i = 0; i < 10; i++) {
        vector_push(&v, &i);                // вектор растёт, блок переезжает
    }
    printf("%d\n", *first);                 // Ошибка памяти: heap-use-after-free
    free(v.data);
    return 0;
}
```

AddressSanitizer сообщает `heap-use-after-free`: `first` указывает в старый блок, который `realloc` уже освободил. Правило: **указатель на элемент контейнера действителен только до следующего изменения контейнера**. Если элемент нужно запомнить надолго, храните его индекс.

## Обобщённые алгоритмы

Раз элементы лежат подряд, к контейнеру применимы стандартные `qsort` и `bsearch` — им нужны ровно те же сведения: начало, количество и размер элемента:

```c
#include <stdio.h>
#include <stdlib.h>

struct Point {
    int x, y;
};

static int by_x_then_y(const void *pa, const void *pb) {
    const struct Point *a = pa;
    const struct Point *b = pb;
    if (a->x != b->x) {
        return (a->x > b->x) - (a->x < b->x);
    }
    return (a->y > b->y) - (a->y < b->y);
}

int main(void) {
    struct Point points[] = {{3, 1}, {1, 2}, {3, 0}, {2, 5}};
    void *data = points;                    // так данные видит обобщённый вектор
    size_t size = 4, elem_size = sizeof points[0];
    qsort(data, size, elem_size, by_x_then_y);
    for (size_t i = 0; i < size; i++) {
        printf("(%d, %d) ", points[i].x, points[i].y);
    }
    printf("\n");
    return 0;
}
```

Вывод:

```text
(1, 2) (2, 5) (3, 0) (3, 1)
```

## Типобезопасная обёртка

Чтобы не писать приведения в каждом месте использования, вокруг обобщённого контейнера делают тонкие функции для конкретного типа:

```c
static inline int ints_push(Vector *v, int value) {
    return vector_push(v, &value);
}

static inline int ints_get(const Vector *v, size_t i) {
    return *(const int *)vector_at(v, i);
}
```

Код контейнера по-прежнему один, а пользователь работает с `int` и получает проверку типов. Сравните с макросом `DEFINE_STACK` из урока о макросах: там для каждого типа генерировалась своя копия кода — быстрее (размер известен при компиляции, нет вызовов через указатель), но код дублируется и хуже отлаживается. Подход с `void *` — один экземпляр кода ценой проверок типов и косвенных вызовов. В C используют оба.

## `void *` или неполный тип

Для непрозрачных дескрипторов `void *` подходит плохо. Если `typedef void *Stack;` и `typedef void *Queue;`, компилятор позволит передать очередь в функцию стека — оба типа на деле `void *`. С неполными типами `typedef struct Stack Stack;` и `typedef struct Queue Queue;` такая путаница — ошибка компиляции. Поэтому `void *` оставляют для данных, тип которых действительно произволен, — элементов контейнера и контекстов callback'ов.

<Concept title="Тип стёрт — ответственность перешла к программисту">

Обобщённый контейнер на `void *` знает о данных только их размер. Всё, что раньше проверял компилятор, — какой тип лежит в векторе, тот ли размер передан, на что указывает элемент, кто владеет памятью, — теперь держится на договорённостях. Пишите их в комментариях к функциям и прячьте приведения в типизированных обёртках.

</Concept>

## Частые ошибки

<CommonMistake title="Арифметика с void *">

`v->data + i * v->elem_size` — расширение GCC: оно считает размер `void` равным 1. Стандарт запрещает такую арифметику; с `-Wpedantic` будет предупреждение. Приводите к `char *`.

</CommonMistake>

<CommonMistake title="Значение вместо адреса">

`vector_push(&v, 42)` передаёт число туда, где ждут адрес, — компилятор предупредит о превращении целого в указатель. Нужно `int x = 42; vector_push(&v, &x);`.

</CommonMistake>

<CommonMistake title="Не тот размер элемента">

Вектор строк, созданный с `elem_size = sizeof(char)` вместо `sizeof(char *)`, будет копировать по одному байту указателя. Размер берите из выражения того же вида, что и элементы: `sizeof(char *)`, `sizeof(struct Point)`.

</CommonMistake>

<CommonMistake title="Указатель на элемент после push">

Любое добавление может переместить данные. Не храните указатели на элементы между изменениями контейнера — храните индексы.

</CommonMistake>

## Итоги

- Обобщённый контейнер хранит `void *data`, количество, вместимость и `elem_size`. Тип элементов знают только пользователи контейнера.
- Адрес элемента вычисляют в байтах через `char *`: `(char *)data + i * elem_size`. Значения кладут и достают по адресу через `memcpy`.
- Контейнер может хранить значения или указатели; во втором случае нужно решить, кто владеет объектами, — например, передать функцию уничтожения элемента.
- Указатель на элемент действителен только до следующего изменения контейнера: `realloc` может переместить данные.
- Элементы лежат подряд, поэтому к контейнеру применимы `qsort` и `bsearch`.
- Типизированные обёртки `static inline` прячут приведения; для непрозрачных дескрипторов лучше неполные типы, чем `void *`.
