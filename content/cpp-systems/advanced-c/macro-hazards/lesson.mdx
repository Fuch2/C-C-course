## Скобки — это ещё не всё

В прошлом уроке скобки вокруг параметров и всей замены спасали от ошибок приоритета. Но есть ловушки, от которых скобки не защищают: они следуют из того, что макрос — подстановка текста, а не вызов функции. В этом уроке — главные из них и безопасные замены макросам.

## Аргумент вычисляется несколько раз

Функция вычисляет каждый аргумент ровно один раз — до вызова. Макрос вставляет текст аргумента столько раз, сколько параметр встречается в замене. Если у аргумента есть **побочный эффект** — изменение переменной, ввод, вывод, — он повторится:

```c
#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

static int calls = 0;

int next_reading(void) {
    calls++;
    return calls * 10;
}

int main(void) {
    int best = MAX(next_reading(), 5);
    printf("best = %d, вызовов: %d\n", best, calls);

    int x = 5, y = 3;
    int m = MAX(x++, y++);
    printf("m = %d, x = %d, y = %d\n", m, x, y);
    return 0;
}
```

Вывод:

```text
best = 20, вызовов: 2
m = 6, x = 7, y = 4
```

`MAX(next_reading(), 5)` превратилось в `((next_reading()) > (5) ? (next_reading()) : (5))`: функция вызвана в сравнении и ещё раз в результате. Поэтому `best` равно не 10, а 20. Во втором случае `x++` выполнился дважды: при сравнении (5 > 3) и при выборе результата — `m` стало 6, а `x` — 7.

Если бы аргументом был `scanf`, программа прочитала бы два числа вместо одного. Если тяжёлый расчёт — посчитала бы его дважды. Отсюда правило для тех, кто **пользуется** макросами: не передавайте в них выражения с побочными эффектами. А для тех, кто **пишет**: используйте каждый параметр в замене ровно один раз — или замените макрос функцией.

## Захват имён

Макрос с собственными переменными подставляет их имена в чужой код. Если они совпадут с именами у вызывающего, макрос «захватит» их:

```c
#include <stdio.h>

#define REPEAT(n, action)              \
    for (int i = 0; i < (n); i++) {    \
        action;                        \
    }

int main(void) {
    int i = 7;
    REPEAT(3, printf("i = %d\n", i));   // ожидали трижды «i = 7»
    printf("после: i = %d\n", i);
    return 0;
}
```

Вывод:

```text
i = 0
i = 1
i = 2
после: i = 7
```

Аргумент `printf("i = %d\n", i)` подставился **внутрь** цикла макроса, где имя `i` уже означает счётчик цикла, а не переменную из `main`. Компилятор не предупреждает: затенение законно, а с точки зрения компилятора макроса не существует — есть только получившийся текст.

Защититься можно непохожими именами внутри макросов: `i_`, `repeat_i_`, `tmp_swap_`. Это снижает риск, но не исключает его. Полностью проблема решается только функцией: у функции свои локальные переменные, и чужие имена до них не дотянутся.

## Типы не проверяются

Макрос примет аргументы любых типов, и обычные преобразования сработают внутри подставленного выражения — иногда неожиданно:

```c
#include <stdio.h>

#define MAX(a, b) ((a) > (b) ? (a) : (b))

static inline int max_int(int a, int b) {
    return a > b ? a : b;
}

int main(void) {
    unsigned int limit = 1;
    int delta = -1;
    // Предупреждение: comparison of integer expressions of different signedness
    printf("%lld\n", (long long)MAX(delta, limit));
    printf("%d\n", max_int(delta, (int)limit));
    return 0;
}
```

Вывод:

```text
4294967295
1
```

При сравнении `int` с `unsigned int` число `-1` превращается в беззнаковое `4294967295` — оно «больше» единицы, и макрос возвращает его. Функция `max_int` с параметрами `int` такого не допустит: тип аргументов виден в её объявлении, и компилятор приведёт их или предупредит.

## Запятые в аргументах

Препроцессор делит аргументы по запятым верхнего уровня и знает только о **круглых** скобках. Фигурные и квадратные он не учитывает:

```c
#include <stdio.h>

#define DECLARE_TABLE(name, values) static const int name[] = values

DECLARE_TABLE(primes, {2, 3, 5, 7});    // Ошибка компиляции: macro "DECLARE_TABLE" passed 5 arguments, but takes just 2

int main(void) {
    printf("%d\n", primes[0]);
    return 0;
}
```

Список `{2, 3, 5, 7}` разбился на четыре аргумента. Обходной путь — принять «хвост» через многоточие: `#define DECLARE_TABLE(name, ...) static const int name[] = __VA_ARGS__`. Но само существование такой ловушки — повод задуматься, нужен ли здесь макрос.

## Ошибки указывают не туда

Компилятор видит текст **после** подстановки. Ошибка внутри макроса выглядит так:

```text
main.c:12:15: error: invalid operands to binary > (have 'struct Point' and 'struct Point')
   12 |     int m = MAX(p, q);
      |             ^~~
main.c:3:23: note: in definition of macro 'MAX'
    3 | #define MAX(a, b) ((a) > (b) ? (a) : (b))
      |                       ^
```

GCC и Clang стараются помочь пометками `in expansion of macro`, но в цепочке из нескольких макросов сообщение быстро становится нечитаемым. Отладчик тоже не может «зайти» в макрос: в программе нет никакого `MAX`, есть только подставленный код.

## Безопасные замены

**`static inline` функции.** Вычисляют аргументы один раз, проверяют типы, имеют свои локальные переменные и видны в отладчике. Компилятор встраивает их так же эффективно, как подставил бы макрос, поэтому довод «макрос быстрее» давно устарел.

**`constexpr` и `enum` для констант.** Подчиняются областям видимости, имеют тип и видны в отладчике. `constexpr` (C23) подходит для чисел любого арифметического типа, `enum` — для целых.

**`_Generic` для обобщённых интерфейсов.** В C11 появилось выражение, которое выбирает вариант по **типу** выражения во время компиляции. Вместе с функциями оно даёт «перегрузку» без недостатков макросов:

```c
#include <stdio.h>

static inline int max_int(int a, int b) {
    return a > b ? a : b;
}

static inline double max_double(double a, double b) {
    return a > b ? a : b;
}

static void print_int(int x) {
    printf("int: %d\n", x);
}

static void print_double(double x) {
    printf("double: %.2f\n", x);
}

#define MAX(a, b) _Generic((a), int: max_int, double: max_double)((a), (b))
#define PRINT(x) _Generic((x), int: print_int, double: print_double)(x)

int main(void) {
    int calls = 0;
    PRINT(MAX(3, 9));
    PRINT(MAX(2.5, -1.0));
    PRINT(MAX(++calls, 0));       // аргумент вычисляется один раз
    PRINT(calls);
    return 0;
}
```

Вывод:

```text
int: 9
double: 2.50
int: 1
int: 1
```

`_Generic((a), int: max_int, double: max_double)` — выражение выбора: по типу `a` оно превращается в имя одной из функций, а затем следует обычный вызов `(...)((a), (b))`. Управляющее выражение `(a)` в `_Generic` **не вычисляется** — от него берётся только тип, поэтому `++calls` выполнился ровно один раз, внутри вызова функции. Так устроен стандартный заголовок `<tgmath.h>`: `sqrt(x)` там выбирает `sqrtf`, `sqrt` или `sqrtl` по типу аргумента.

Иногда встречаются **выражения-инструкции** GCC — `({ int t = (a); t * t; })`. Это расширение компилятора, а не стандарт C: с `-Wpedantic` компилятор предупредит, а другой компилятор может его не понять.

## Если макрос всё-таки нужен

Иногда без макроса не обойтись: нужен текст аргумента, место вызова, создание имён или значение для `#if`. Тогда соблюдайте правила:

1. Имя — ЗАГЛАВНЫМИ буквами: читатель должен видеть, что это не функция.
2. Каждый параметр и вся замена — в скобках.
3. Каждый параметр используется один раз; если нет — напишите это в комментарии к макросу.
4. Несколько инструкций — в `do { … } while (0)`, без точки с запятой в конце.
5. Локальные переменные макроса — с необычными именами.

<Concept title="Макрос не знает, где он окажется">

Функция живёт в своём мире: свои переменные, свои вычисленные аргументы, проверенные типы. Макрос растворяется в месте вызова и взаимодействует со всем, что вокруг: приоритетами операций, именами переменных, побочными эффектами. Все опасности этого урока — следствия одного факта.

</Concept>

## Частые ошибки

<CommonMistake title="Побочный эффект в аргументе">

`MAX(i++, limit)`, `SQUARE(read_int())`, `ABS(rand())` — аргумент вычисляется дважды. Сохраните значение в переменную до вызова макроса или используйте функцию.

</CommonMistake>

<CommonMistake title="Имя внутри макроса совпало с вашим">

Макрос с `tmp` или `i` внутри захватит одноимённую переменную вызывающего кода. Ошибка проявится как неправильный результат без предупреждений.

</CommonMistake>

<CommonMistake title="Смешанные типы">

`MAX(-1, 1u)` сравнивает в беззнаковой арифметике и возвращает огромное число. Флаг `-Wextra` предупредит о сравнении знакового с беззнаковым — не игнорируйте это предупреждение.

</CommonMistake>

<CommonMistake title="Фигурные скобки в аргументе">

`MACRO({1, 2, 3})` — это три аргумента. Препроцессор считает только круглые скобки.

</CommonMistake>

## Практика

1. **Найди ошибку: двойное чтение** — макрос `MAX` с вводом в аргументе.
2. **Найди ошибку: захват имени** — переменная цикла макроса скрывает переменную вызывающего.
3. **Обобщённые функции** — `MAX` и `PRINT` через `_Generic` для чисел и строк.

## Итоги

- Аргумент макроса вычисляется столько раз, сколько параметр встречается в замене. Побочные эффекты повторяются.
- Переменные внутри макроса могут захватить одноимённые переменные вызывающего кода.
- Макрос не проверяет типы: смешение знаковых и беззнаковых приводит к неожиданным результатам.
- Препроцессор делит аргументы по запятым и учитывает только круглые скобки.
- Ошибки в макросах указывают на место подстановки, а отладчик макросов не видит.
- Безопасные замены: `static inline` функции, `constexpr` и `enum` для констант, `_Generic` для выбора функции по типу аргумента. Если макрос всё же нужен, `typeof` (C23) позволяет не зашивать в него тип.
- Если макрос нужен, пишите его по правилам: заглавное имя, скобки, один раз каждый параметр, `do { … } while (0)`, необычные локальные имена.
