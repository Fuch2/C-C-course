## Цели обучения

- Разобраться в теме «Опасности макросов» и её границах применимости.
- Объяснить типичную ошибку, а не только запомнить правильную запись.
- Проверить решение на нормальных и граничных входах.

## Теория

У макроса нет обычной области видимости локальных переменных функции. Он может захватить имя вызывающего кода, повторить аргумент или изменить структуру if/else. Многооператорный макрос оборачивают в do &#123; ... &#125; while (0), чтобы снаружи он выглядел как один оператор. Это не устраняет опасности повторного использования аргумента.

Сначала раскройте подозрительный вызов на бумаге, затем проверьте последовательность чтений и изменений. Не пытайтесь угадывать результат неопределённого поведения. Если операция вычисляет число, замена на inline-функцию обычно проще доказательства безопасности макроса. Инкремент лучше вынести в отдельный оператор: намерение становится проверяемым без знания реализации вспомогательной операции.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
static int twice(int value){return value+value;}
int main(void) {
    int i=3;int value=twice(i);++i;printf("%d %d\n",value,i);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
6 4
```

Проверяйте результат копирования целиком, как будто вставили его руками в место вызова. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Выражения MIN(next(), limit) и SQUARE(i++) могут вызвать вычисление больше одного раза.
