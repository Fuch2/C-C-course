## Цели обучения

- Разобраться в теме «Header guards» и её границах применимости.
- Объяснить типичную ошибку, а не только запомнить правильную запись.
- Проверить решение на нормальных и граничных входах.

## Теория

Повторное текстовое включение заголовка может повторно определить struct или enum. Guard использует уникальный макрос: при первом включении #ifndef пропускает тело и #define отмечает его; следующие включения в той же единице трансляции пропускают тело. Между разными компиляциями состояние макроса не сохраняется.

Имя guard должно различаться у разных заголовков. Используйте префикс проекта и путь, например SENSOR_SAMPLE_H. Зарезервированные имена с двойным подчёркиванием оставьте реализации. Guard предотвращает повтор внутри единицы трансляции, но не исправляет внешнее определение переменной, попавшее в несколько .c. Для такой переменной нужен extern в заголовке и одно определение в реализации.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
#ifndef SENSOR_READING_H
#define SENSOR_READING_H
typedef struct { int raw; } Reading;
#endif
int main(void) {
    Reading r={7};printf("%d\n",r.raw);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
7
```

На каждой сборочной площадке стоит свой штамп «уже прочитано»; штамп не является общим для всего проекта. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. Скопированный guard с тем же именем может молча скрыть другой заголовок.
