## Как библиотека сообщает об ошибке

Функции стандартной библиотеки сообщают об ошибке в два шага. Сначала — **особым возвращаемым значением**: `fopen` возвращает `NULL`, `fgetc` — `EOF`, `remove` — ненулевое число. А **причину** функция записывает в переменную `errno` из `<errno.h>`: целое число — код ошибки. Коды обозначены макросами:

| Макрос   | Значение в Linux | Причина                                  |
| -------- | ---------------- | ---------------------------------------- |
| `ENOENT` | 2                | нет такого файла или каталога            |
| `EACCES` | 13               | нет прав доступа                         |
| `EEXIST` | 17               | файл уже существует                      |
| `EISDIR` | 21               | это каталог                              |
| `EINVAL` | 22               | недопустимый аргумент                    |
| `EDOM`   | 33               | аргумент вне области определения функции |
| `ERANGE` | 34               | результат не помещается в тип            |

Стандарт C определяет только `EDOM`, `ERANGE` и `EILSEQ`; остальные коды добавляет POSIX, и их числовые значения в разных системах разные. Поэтому в программе сравнивают с макросом — `errno == ENOENT`, — а не с числом 2.

## `perror` и `strerror`

Текстовое описание кода дают две функции: `perror(текст)` печатает в `stderr` строку «текст: описание текущей ошибки», а `strerror(код)` возвращает описание как строку:

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    FILE *f = fopen("missing.txt", "r");
    if (f == NULL) {
        int code = errno;                          // сохранить сразу
        printf("код %d: %s\n", code, strerror(code));
        printf("это ENOENT? %s\n", code == ENOENT ? "да" : "нет");
        perror("missing.txt");                     // то же — в stderr
    }
    return 0;
}
```

Вывод:

```text
код 2: No such file or directory
это ENOENT? да
```

Строка от `perror` ушла в `stderr` и в выводе программы не видна, — так и задумано: сообщения об ошибках не смешиваются с результатами. Описания на английском, потому что программа работает в стандартной локали «C».

## Правила работы с `errno`

`errno` — не флаг ошибки, а **последняя записанная причина**. Отсюда три правила.

**1. Смотреть на `errno` только после того, как функция сообщила о неудаче.** Успешная функция не обязана обнулять `errno` — и вправе изменить её как угодно. Даже успешный `printf` иногда записывает туда код промежуточной неудачи. Поэтому `if (errno != 0)` вместо проверки результата — ошибка.

**2. Сохранять `errno` сразу.** Любой следующий вызов библиотеки может её перезаписать. Вот как это выглядит в одной строке:

```c
#include <errno.h>
#include <stdio.h>
#include <string.h>

int main(void) {
    int result = remove("nothing.txt");
    int code = errno;                                  // правильно: сразу после вызова
    printf("%d: %s\n", result, strerror(code));
    errno = 0;
    printf("%d: %s\n", remove("nothing.txt"), strerror(errno));   // неправильно
    return 0;
}
```

Во второй строке порядок вычисления аргументов не определён. GCC сначала вызывает `strerror(errno)` — когда `remove` ещё не выполнилась — и печатает `Success`; Clang вызывает `remove` первой и печатает правильное описание. Сохранённый в переменную код такой проблемы не имеет.

**3. Обнулять `errno` перед функциями, у которых нет особого значения ошибки.** `strtol`, `strtod` и математические функции на любой результат могут ответить законным числом, поэтому единственный способ узнать о переполнении — записать `errno = 0` перед вызовом и проверить её после. Сама библиотека `errno` никогда не обнуляет.

## `strtol`: правильный разбор числа

`atoi("12x")` возвращает 12, `atoi("abc")` — 0, а `atoi("99999999999")` — что угодно: об ошибках `atoi` не сообщает вовсе. `strtol` сообщает обо всех трёх, если правильно её спросить:

```c
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>

static void parse(const char *text) {
    char *end;
    errno = 0;                                  // правило 3
    long value = strtol(text, &end, 10);
    if (end == text) {
        printf("\"%s\": не число\n", text);
    } else if (errno == ERANGE) {
        printf("\"%s\": вне диапазона long, получено %ld\n", text, value);
    } else if (*end != '\0') {
        printf("\"%s\": лишние символы \"%s\"\n", text, end);
    } else {
        printf("\"%s\": %ld\n", text, value);
    }
}

int main(void) {
    parse("42");
    parse("  -17");
    parse("12px");
    parse("abc");
    parse("99999999999999999999");
    return 0;
}
```

Вывод:

```text
"42": 42
"  -17": -17
"12px": лишние символы "px"
"abc": не число
"99999999999999999999": вне диапазона long, получено 9223372036854775807
```

Указатель `end` показывает, где закончилось число: если он не сдвинулся — цифр не было, если указывает не на конец строки — после числа остались символы. При переполнении `strtol` возвращает `LONG_MAX` или `LONG_MIN` и записывает `ERANGE`. Ведущие пробелы и знак `strtol` пропускает сама. Тот же приём работает для `strtoul`, `strtoll` и `strtod`.

## Математические функции

`<math.h>` сообщает о двух видах ошибок:

- **ошибка области** (`EDOM`): аргумент вне области определения — `sqrt(-1)`, `log(-1)`; результат — NaN;
- **ошибка диапазона** (`ERANGE`): результат слишком велик или мал — `exp(1000)`, полюс `log(0)`; результат — бесконечность или 0.

```c
#include <errno.h>
#include <math.h>
#include <stdio.h>

static void report(const char *name, double result) {
    int code = errno;
    printf("%s = %g, %s\n", name, result,
           code == EDOM ? "ошибка области" : code == ERANGE ? "ошибка диапазона" : "без ошибок");
    errno = 0;
}

int main(void) {
    volatile double minus_one = -1.0, zero = 0.0, big = 1000.0;   // не дать вычислить при компиляции
    errno = 0;
    report("sqrt(-1)", sqrt(minus_one));
    report("log(0)", log(zero));
    report("exp(1000)", exp(big));
    report("sqrt(2)", sqrt(2.0));
    return 0;
}
```

Вывод:

```text
sqrt(-1) = nan, ошибка области
log(0) = -inf, ошибка диапазона
exp(1000) = inf, ошибка диапазона
sqrt(2) = 1.41421, без ошибок
```

`volatile` у аргументов здесь не случаен: с константами компилятор вправе вычислить функцию сам ещё при компиляции — и тогда `errno` никто не запишет. Стандарт разрешает реализации сообщать об ошибках математики через `errno`, через флаги исключений плавающей точки или обоими способами — это показывает макрос `math_errhandling`. glibc поддерживает оба, но флаг компилятора `-ffast-math` отключает запись в `errno`.

## `errno` в многопоточной программе

Если бы `errno` была обычной глобальной переменной, потоки затирали бы коды друг друга. Поэтому с C11 `errno` у каждого потока своя (это макрос, который раскрывается в обращение к переменной текущего потока). Ошибка в одном потоке не влияет на `errno` другого.

<Concept title="Возвращаемое значение говорит «что», errno — «почему»">

Результат функции отвечает на вопрос, была ли ошибка. `errno` отвечает на вопрос, почему она случилась, — и только если ошибка действительно была. Поэтому порядок всегда один: проверить результат, сразу сохранить `errno`, затем решать, что делать, и сообщить об ошибке с описанием `strerror`.

</Concept>

## Частые ошибки

<CommonMistake title="errno без проверки результата">

`fopen(...); if (errno) …` сработает от «старой» ошибки или от успешного вызова, который изменил `errno`. Сначала результат функции, потом `errno`.

</CommonMistake>

<CommonMistake title="errno не обнулена перед strtol">

Если предыдущее число вызвало `ERANGE`, а `errno` не обнулили, следующее правильное число тоже покажется переполненным. `errno = 0;` — перед каждым вызовом.

</CommonMistake>

<CommonMistake title="Печать до сохранения">

`printf("ошибка: "); perror(name);` — `printf` мог изменить `errno`. Сохраните код сразу после неудачного вызова и печатайте `strerror(code)`.

</CommonMistake>

<CommonMistake title="atoi и atof">

Они не различают «0», «не число» и переполнение. Для чисел из ввода используйте `strtol`, `strtoll`, `strtod` с проверкой `end` и `errno`.

</CommonMistake>

## Практика

1. **Разбор целых** — `strtol` с полной проверкой.
2. **Операции с файлами** — диагностика `fopen` и `remove` по `errno`.
3. **Найди ошибку: ложное переполнение** — `errno` не обнулена перед `strtol`.
4. **Математика без сюрпризов** — ошибки области и диапазона.

## Итоги

- Функция сообщает о неудаче возвращаемым значением, а причину записывает в `errno`; коды — макросы `ENOENT`, `ERANGE`, `EDOM` и другие.
- `strerror(код)` даёт описание, `perror(текст)` печатает его в `stderr`.
- Смотрите на `errno` только после неудачи, сохраняйте её сразу, а перед `strtol`, `strtod` и математическими функциями обнуляйте.
- Разбор числа: `strtol` с указателем `end` различает «не число», «лишние символы» и `ERANGE`. `atoi` ошибок не сообщает.
- Математические функции сообщают `EDOM` (аргумент вне области) и `ERANGE` (результат вне диапазона), если `math_errhandling` включает `MATH_ERRNO`.
- В C11 у каждого потока своя `errno`.
