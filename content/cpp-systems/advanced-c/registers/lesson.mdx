## Регистры устройства

В микроконтроллере нет драйверов операционной системы между программой и железом. Светодиод, последовательный порт или таймер управляются **регистрами**: 32-битными словами по фиксированным адресам памяти. Запись в слово по адресу `0x48000014` меняет напряжение на ножках порта A, чтение слова по адресу `0x40013800` возвращает состояние последовательного порта. Такую схему называют **отображением устройств на память** (memory-mapped I/O).

Документация микроконтроллера описывает каждый регистр таблицей: смещение от базового адреса устройства, назначение битов, тип доступа. Например, упрощённый регистр управления последовательным портом:

| Биты  | Поле  | Доступ | Назначение                          |
| ----- | ----- | ------ | ----------------------------------- |
| 0     | `UE`  | R/W    | включить порт                       |
| 2     | `RE`  | R/W    | включить приёмник                   |
| 3     | `TE`  | R/W    | включить передатчик                 |
| 9     | `PS`  | R/W    | чётность: 0 — чётная, 1 — нечётная  |
| 10    | `PCE` | R/W    | контроль чётности включён           |
| 31–11 | —     | —      | зарезервировано: сохранять значение |

Всё, что вы изучили в этом разделе, сходится здесь: поля и маски, `volatile`, побитовые операции, указатели.

## Доступ к регистрам из C

Регистр — это `volatile`-объект по известному адресу. В программе для микроконтроллера его описывают так:

```c
#define GPIOA_ODR (*(volatile uint32_t *)0x48000014u)

GPIOA_ODR |= 1u << 5;          // включить светодиод на ножке 5
```

Чаще регистры одного устройства описывают структурой, поля которой идут в порядке смещений, и «накладывают» её на базовый адрес:

```c
typedef struct {
    volatile uint32_t SR;      // смещение 0x00: состояние
    volatile uint32_t DR;      // смещение 0x04: данные
    volatile uint32_t BRR;     // смещение 0x08: делитель скорости
    volatile uint32_t CR1;     // смещение 0x0C: управление
} UartRegs;

#define UART1 ((UartRegs *)0x40013800u)

UART1->BRR = 139;              // запись в регистр по адресу 0x40013808
```

Так устроены заголовки производителей (стандарт CMSIS для ARM Cortex-M). На обычном компьютере по этим адресам нет устройств — программа упадёт. Поэтому в примерах и задачах урока регистры **моделируются** структурой в обычной памяти, а поведение железа — функциями модели. Код драйвера при этом пишется так же, как для настоящего микроконтроллера.

## Поля регистра: позиция и маска

Для каждого поля заводят макросы позиции и маски — так пишут и в заголовках производителей:

```c
#include <stdint.h>
#include <stdio.h>

typedef struct {
    volatile uint32_t SR;
    volatile uint32_t DR;
    volatile uint32_t BRR;
    volatile uint32_t CR1;
} UartRegs;

#define UART_CR1_UE (1u << 0)
#define UART_CR1_RE (1u << 2)
#define UART_CR1_TE (1u << 3)
#define UART_CR1_PS (1u << 9)
#define UART_CR1_PCE (1u << 10)

static UartRegs uart_model;               // вместо настоящего адреса
#define UART1 (&uart_model)

static void uart_init(uint32_t clock, uint32_t baud) {
    UART1->CR1 = 0;                                   // выключить на время настройки
    UART1->BRR = (clock + baud / 2) / baud;           // делитель с округлением
    UART1->CR1 = UART_CR1_TE | UART_CR1_RE | UART_CR1_PCE | UART_CR1_UE;
}

int main(void) {
    uart_init(16000000, 115200);
    printf("BRR = %u, CR1 = 0x%04X\n", (unsigned)UART1->BRR, (unsigned)UART1->CR1);
    printf("реальная скорость %u бод\n", (unsigned)(16000000 / UART1->BRR));
    return 0;
}
```

Вывод:

```text
BRR = 139, CR1 = 0x040D
реальная скорость 115107 бод
```

Делитель — целое число, поэтому скорость получается приблизительной: 115 107 вместо 115 200, ошибка 0,08 %. Последовательный порт допускает расхождение до 2–3 %, а при большей ошибке приёмник начнёт путать биты — поэтому делитель всегда проверяют на точность.

## Чтение — изменение — запись

Записать в регистр всё слово целиком можно, только когда известно значение всех полей. Чтобы изменить **одно** поле, нужно прочитать регистр, поменять биты и записать обратно:

```c
UART1->CR1 = (UART1->CR1 & ~UART_CR1_PS) | UART_CR1_PS;   // нечётная чётность
UART1->CR1 |= UART_CR1_TE;                                 // то же, короче
```

Такую последовательность называют **чтение — изменение — запись** (read-modify-write). Она сохраняет остальные биты, в том числе зарезервированные, которые документация требует не трогать.

Но она **не атомарна**: между чтением и записью может сработать прерывание, которое изменит тот же регистр. Его изменение затрётся записью основной программы. В драйверах на время такой последовательности запрещают прерывания или используют регистры, специально созданные для атомарных изменений.

## Регистры установки и сброса

У порта ввода-вывода есть регистр выхода `ODR` (бит `n` — уровень на ножке `n`) и регистр `BSRR` для атомарных изменений. Запись в `BSRR` единицы в бит `n` (0–15) **устанавливает** ножку `n`, единицы в бит `n + 16` — **сбрасывает**, а нули ничего не меняют. Одна запись — без чтения — меняет нужные ножки, и прерывание не может вклиниться.

```c
#include <stdint.h>
#include <stdio.h>

static uint32_t odr;                            // модель регистра выхода

// Модель железа: так устройство реагирует на запись в BSRR.
static void bsrr_write(uint32_t value) {
    uint32_t set = value & 0xFFFFu;
    uint32_t reset = value >> 16;
    odr = (odr & ~reset) | set;                 // при конфликте побеждает установка
}

int main(void) {
    odr = 0x00F0u;
    bsrr_write(1u << 3);                        // установить ножку 3
    printf("%04X\n", (unsigned)odr);
    bsrr_write(1u << (4 + 16));                 // сбросить ножку 4
    printf("%04X\n", (unsigned)odr);
    bsrr_write(1u << 0 | 1u << (7 + 16));       // установить 0 и сбросить 7 — одной записью
    printf("%04X\n", (unsigned)odr);
    return 0;
}
```

Вывод:

```text
00F8
00E8
0069
```

В программе для микроконтроллера `bsrr_write(x)` — это просто `GPIOA->BSRR = x;`, а всё, что делает функция модели, выполняет железо.

## Сброс записью единицы

Регистры состояния содержат **флаги событий**: «пришёл байт», «передача завершена», «ошибка кадра». Флаги устанавливает устройство, а программа сбрасывает их, когда обработала событие. Во многих устройствах флаг сбрасывается **записью единицы** в его бит, а запись нуля ничего не меняет (write-1-to-clear, W1C). Так можно сбросить один флаг, не трогая остальные, — но только если записать единицу **только** в его бит.

Привычная запись `SR |= FLAG` здесь — ошибка: она читает регистр, где установлены **все** текущие флаги, добавляет нужный и записывает всё обратно — единицами. Устройство сбрасывает все флаги разом, и события, которые программа ещё не обработала, теряются:

```c
#include <stdint.h>
#include <stdio.h>

#define FLAG_RX (1u << 0)                  // пришёл байт
#define FLAG_TX (1u << 1)                  // передача завершена
#define FLAG_ERR (1u << 2)                 // ошибка кадра

static uint32_t sr;                        // модель регистра состояния

static void sr_write(uint32_t value) {     // модель железа: W1C
    sr &= ~value;
}

int main(void) {
    sr = FLAG_RX | FLAG_TX | FLAG_ERR;     // устройство сообщило о трёх событиях
    sr_write(sr | FLAG_RX);                // как SR |= FLAG_RX — неправильно
    printf("после |=: %X\n", (unsigned)sr);

    sr = FLAG_RX | FLAG_TX | FLAG_ERR;
    sr_write(FLAG_RX);                     // как SR = FLAG_RX — правильно
    printf("после =:  %X\n", (unsigned)sr);
    return 0;
}
```

Вывод:

```text
после |=: 0
после =:  6
```

Бывают и другие типы доступа: **только чтение** (запись игнорируется), **сброс чтением** (флаг сбрасывается при чтении регистра — поэтому такие регистры нельзя «просто посмотреть» в отладчике), регистры данных, где каждое чтение забирает следующий байт из очереди приёмника. Тип доступа каждого бита написан в документации, и код драйвера должен ему следовать.

<Concept title="Регистр — не переменная">

Обычная переменная хранит то, что в неё записали. Регистр — интерфейс устройства: чтение может вернуть не то, что записано, а запись — означать команду, а не сохранение значения. Поэтому с регистром работают по документации: какой бит что делает, как его менять, что произойдёт при чтении. `volatile` гарантирует, что каждое обращение дойдёт до устройства, — а правильность обращений остаётся за программистом.

</Concept>

## Частые ошибки

<CommonMistake title="Регистр без volatile">

Без `volatile` компилятор вправе прочитать регистр один раз и не повторять «лишние» записи. Цикл ожидания флага зависнет, а последовательность команд устройству сократится.

</CommonMistake>

<CommonMistake title="|= для регистра W1C">

`SR |= FLAG` сбрасывает все установленные флаги. Для сброса одного флага записывайте только его бит: `SR = FLAG`.

</CommonMistake>

<CommonMistake title="Неатомарное чтение — изменение — запись">

Если регистр меняет и прерывание, последовательность чтение — изменение — запись может потерять его изменение. Используйте регистры установки и сброса или запрещайте прерывания на время изменения.

</CommonMistake>

<CommonMistake title="Двойное чтение регистра данных">

`if (UART->DR != '\r') buf[n++] = UART->DR;` читает регистр дважды и забирает из очереди два байта. Прочитайте значение один раз в переменную.

</CommonMistake>

## Практика

1. **Настройка последовательного порта** — значения регистров по параметрам связи.
2. **Порт ввода-вывода** — модель регистра `BSRR` и вычисление нужной записи.
3. **Найди ошибку: потерянные события** — сброс флагов W1C через `|=`.
4. **Найди ошибку: пропавшие байты** — двойное чтение регистра данных.

## Итоги

- Регистры устройств — `volatile`-объекты по фиксированным адресам; их описывают макросами или структурой, наложенной на базовый адрес.
- Поля регистра описывают макросами позиции и маски; одно поле меняют последовательностью чтение — изменение — запись, сохраняя остальные и зарезервированные биты.
- Чтение — изменение — запись не атомарна: прерывание между чтением и записью может потерять изменение.
- Регистры установки и сброса (`BSRR`) меняют отдельные биты одной записью без чтения.
- Флаги W1C сбрасываются записью единицы только в нужный бит; `|=` сбросит все флаги.
- Тип доступа каждого бита — только чтение, сброс чтением, W1C — берут из документации: регистр — интерфейс устройства, а не переменная.
