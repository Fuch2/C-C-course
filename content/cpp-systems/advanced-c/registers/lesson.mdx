## Теория

Регистр устройства — интерфейс с аппаратной семантикой, а не просто unsigned по адресу. Документация определяет ширину доступа, зарезервированные биты, эффекты чтения и записи. У read-write регистра read-modify-write может быть допустим, но у write-one-to-clear запись единицы очищает флаг. Универсальное reg |= mask для такого регистра способно случайно сбросить другие события.

В учебной задаче моделируем W1C обычным числом, чтобы проверить логику без доступа к оборудованию. Реальный драйвер дополнительно зависит от ABI, memory barriers, платформенных функций MMIO и конкуренции с прерываниями. volatile само по себе не решает эти вопросы. Никогда не разыменовывайте придуманный аппаратный адрес в обычном приложении.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>

int main(void) {
    unsigned pending=7;unsigned acknowledge=1;printf("%u\n",pending & ~acknowledge);
    return 0;
}
```

## Практическое задание

Модель W1C: ввод status и clear 0…255. Выведите status после очистки единиц маски clear: остальные флаги сохраняются.
