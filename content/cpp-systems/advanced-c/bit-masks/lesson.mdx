## Поле — маска и позиция

В прошлых уроках маска выделяла один бит или целый байт. Но часто в числе хранятся **поля** произвольной ширины: три бита на режим, пять — на день месяца, двенадцать — на делитель частоты. Поле описывают двумя числами — **позицией** младшего бита `p` и **шириной** `w`:

```text
16-битное слово:  1011 0110 1100 0101
поле p = 6, w = 4:      ^^ ^^           биты 6..9 = 1011 = 11
маска поля:       0000 0011 1100 0000 = 0x03C0 = ((1u << 4) - 1) << 6
```

Два действия с полем:

- **прочитать**: сдвинуть поле вниз и отрезать лишнее — `(x >> p) & ((1u << w) - 1)`;
- **записать**: очистить место и положить новое значение — `(x & ~mask) | ((value << p) & mask)`.

```c
#include <stdio.h>

static unsigned field_mask(unsigned pos, unsigned width) {
    return ((1u << width) - 1u) << pos;
}

static unsigned field_get(unsigned x, unsigned pos, unsigned width) {
    return (x >> pos) & ((1u << width) - 1u);
}

static unsigned field_set(unsigned x, unsigned pos, unsigned width, unsigned value) {
    unsigned mask = field_mask(pos, width);
    return (x & ~mask) | ((value << pos) & mask);
}

int main(void) {
    unsigned word = 0xB6C5u;
    printf("%u\n", field_get(word, 6, 4));          // 1011 = 11
    word = field_set(word, 6, 4, 3);                // записать 0011
    printf("%04X %u\n", word, field_get(word, 6, 4));
    word = field_set(word, 6, 4, 0x1F);             // 5 битов в 4-битное поле
    printf("%04X %u\n", word, field_get(word, 6, 4));
    return 0;
}
```

Вывод:

```text
11
B4C5 3
B7C5 15
```

Обе части записи важны. Без `x & ~mask` новые единицы смешаются со старыми. Без `& mask` у значения слишком большое число залезет в соседние поля — в последней строке «лишний» пятый бит значения `0x1F` отрезан, и соседние биты не пострадали.

Ширина 32 — особый случай: `1u << 32` не определено. Если поле может занимать всё слово, маску считают отдельно: `width == 32 ? 0xFFFFFFFFu : …`.

## Пример: дата и время в FAT

Файловая система FAT — та, что на флешках и картах памяти, — и формат ZIP хранят дату изменения файла в 16 битах, а время — в других 16:

```text
дата:  гггг ггг м ммм д дддд     год − 1980 (биты 9–15), месяц (5–8), день (0–4)
время: чччч ч мм мммм с сссс     часы (11–15), минуты (5–10), секунды / 2 (0–4)
```

```c
#include <stdio.h>

static unsigned pack_date(unsigned year, unsigned month, unsigned day) {
    return (year - 1980) << 9 | month << 5 | day;
}

static unsigned pack_time(unsigned hours, unsigned minutes, unsigned seconds) {
    return hours << 11 | minutes << 5 | seconds / 2;
}

int main(void) {
    unsigned date = pack_date(2024, 3, 15);
    unsigned time = pack_time(14, 30, 45);
    printf("дата 0x%04X, время 0x%04X\n", date, time);
    printf("%u-%02u-%02u %02u:%02u:%02u\n", (date >> 9) + 1980, (date >> 5) & 0xFu, date & 0x1Fu,
           time >> 11, (time >> 5) & 0x3Fu, (time & 0x1Fu) * 2);
    return 0;
}
```

Вывод:

```text
дата 0x586F, время 0x73D6
2024-03-15 14:30:44
```

Секунды хранятся с точностью до двух — в пяти битах помещается только 0…31. Поэтому 45 секунд превратились в 44: экономия трёх байтов на файл в 1980-х стоила точности. Год занимает 7 битов и закончится в 2107 году.

## Множества на битах

Множество небольших чисел — например, от 0 до 63 — удобно хранить в одном `uint64_t`: бит `k` установлен, если число `k` входит в множество. Операции над множествами превращаются в одну инструкцию:

| Множества               | Биты            |
| ----------------------- | --------------- |
| добавить `k`            | `s \| (1 << k)` |
| удалить `k`             | `s & ~(1 << k)` |
| `k` принадлежит         | `(s >> k) & 1`  |
| объединение A ∪ B       | `a \| b`        |
| пересечение A ∩ B       | `a & b`         |
| разность A \ B          | `a & ~b`        |
| симметрическая разность | `a ^ b`         |
| размер                  | число единиц    |

```c
#include <stdint.h>
#include <stdio.h>

static void print_set(const char *name, uint64_t set) {
    printf("%s:", name);
    for (int k = 0; k < 64; k++) {
        if ((set >> k) & 1u) {
            printf(" %d", k);
        }
    }
    printf("\n");
}

int main(void) {
    enum { MON, TUE, WED, THU, FRI, SAT, SUN };
    uint64_t anna = (UINT64_C(1) << MON) | (UINT64_C(1) << WED) | (UINT64_C(1) << FRI);
    uint64_t boris = (UINT64_C(1) << WED) | (UINT64_C(1) << THU) | (UINT64_C(1) << FRI);
    print_set("оба свободны", anna & boris);
    print_set("хотя бы один", anna | boris);
    print_set("только Анна", anna & ~boris);
    return 0;
}
```

Вывод:

```text
оба свободны: 2 4
хотя бы один: 0 2 3 4
только Анна: 0
```

## Битовый массив

Если чисел больше 64, множество хранят в массиве слов. Элемент `i` лежит в слове `i / 32` на позиции `i % 32`; для степени двойки это записывают сдвигом и маской — `i >> 5` и `i & 31`. Битовый массив в 8 раз компактнее массива `bool`, и в кэш процессора помещается больше данных.

Классический пример — **решето Эратосфена**: отмечаем составные числа, вычёркивая кратные каждого простого.

```c
#include <stdint.h>
#include <stdio.h>

enum { LIMIT = 100 };
static uint32_t composite[LIMIT / 32 + 1];       // бит i — число i составное

static void mark(unsigned i) {
    composite[i >> 5] |= 1u << (i & 31);
}

static int is_marked(unsigned i) {
    return (composite[i >> 5] >> (i & 31)) & 1u;
}

int main(void) {
    for (unsigned p = 2; p * p <= LIMIT; p++) {
        if (!is_marked(p)) {
            for (unsigned m = p * p; m <= LIMIT; m += p) {
                mark(m);
            }
        }
    }
    int count = 0;
    for (unsigned i = 2; i <= LIMIT; i++) {
        if (!is_marked(i)) {
            count++;
        }
    }
    printf("простых до %d: %d, массив %zu байт\n", LIMIT, count, sizeof composite);
    return 0;
}
```

Вывод:

```text
простых до 100: 25, массив 16 байт
```

Сто флагов уместились в 16 байтах. Тот же приём — `std::bitset` и `std::vector<bool>` в C++, битовые карты свободных блоков в файловых системах, фильтры Блума.

## Битовые поля структур

C позволяет объявить поля структуры заданной ширины — **битовые поля**:

```c
#include <stdio.h>

struct FatDate {
    unsigned day : 5;
    unsigned month : 4;
    unsigned year : 7;          // год − 1980
};

int main(void) {
    struct FatDate d = {15, 3, 44};
    unsigned input_day = 40;
    d.month = 12;                          // компилятор сам сдвигает и маскирует
    d.day = input_day;                     // не помещается в 5 битов: остаётся 40 % 32
    printf("%u.%u.%u, размер %zu байт\n", (unsigned)d.day, (unsigned)d.month,
           d.year + 1980u, sizeof d);
    return 0;
}
```

Вывод:

```text
8.12.2024, размер 4 байт
```

Запись удобная: компилятор сам генерирует сдвиги и маски. Но **расположение** битовых полей — порядок полей в слове, выравнивание, размер всей структуры — определяет реализация. Один компилятор положит `day` в младшие биты, другой — в старшие, и `sizeof` тоже может отличаться. Поэтому битовые поля структур хороши для компактного хранения **внутри** программы, но не для форматов файлов, сетевых протоколов и регистров устройств, где расположение битов задано извне, — там нужны явные сдвиги и маски, как в начале урока.

Ещё ограничения: у битового поля нельзя взять адрес (`&d.month` — ошибка), а переносимые типы полей — только `unsigned int`, `signed int` и `_Bool`. Знаковое поле `int level : 3` хранит значения от −4 до 3.

<Concept title="Поле = позиция + ширина">

Любая операция с полем — это две маленькие формулы: прочитать — сдвинуть вниз и наложить маску ширины; записать — очистить место маской поля и положить сдвинутое и обрезанное значение. Всё остальное — даты FAT, цвета, заголовки пакетов, регистры — частные случаи.

</Concept>

## Частые ошибки

<CommonMistake title="Забыли сдвинуть при чтении">

`x & 0x0F0` выделяет поле, но оставляет его на месте: значение получается в 16 раз больше. Сначала сдвиг, потом маска: `(x >> 4) & 0xF`.

</CommonMistake>

<CommonMistake title="Запись без очистки">

`x |= value << pos` складывает биты нового значения со старыми. Повторная запись меньшего числа ничего не изменит. Сначала `x &= ~mask`.

</CommonMistake>

<CommonMistake title="Значение шире поля">

`(value << pos)` без `& mask` для слишком большого значения испортит соседние поля. Обрезайте значение маской поля.

</CommonMistake>

<CommonMistake title="Битовые поля структур в формате файла">

Запись структуры с битовыми полями в файл через `fwrite` на другом компиляторе прочитается иначе. Для внешних форматов — явные сдвиги и маски.

</CommonMistake>

## Итоги

- Поле задаётся позицией `p` и шириной `w`; маска поля — `((1u << w) - 1) << p` (ширину 32 обрабатывают отдельно).
- Прочитать: `(x >> p) & ((1u << w) - 1)`. Записать: `(x & ~mask) | ((value << p) & mask)`.
- Даты FAT, цвета RGB565, заголовки пакетов и регистры — наборы полей в одном числе.
- Множество чисел от 0 до 63 — `uint64_t`; объединение, пересечение и разность — `|`, `&`, `& ~`.
- Битовый массив: элемент `i` — бит `i & 31` в слове `i >> 5`; в 8 раз компактнее массива `bool`.
- Битовые поля структур удобны внутри программы, но их расположение определяет реализация — для внешних форматов нужны явные сдвиги и маски.
