## Не звоните нам — мы вам позвоним

**Функция обратного вызова** (callback) — функция, которую вы передаёте другой функции, чтобы та вызвала её в нужный момент. Роли распределяются так: библиотечная функция знает **как** — как отсортировать массив, обойти дерево, дождаться события, — а ваша функция знает **что** — как сравнить два элемента, что сделать с узлом, как отреагировать на событие.

Вы уже встречали такие пары: `qsort` и функция сравнения, `bsearch`. В стандартной библиотеке есть и другие: `atexit` вызывает ваши функции при завершении программы, `signal` — при получении сигнала, `thrd_create` (C11) — в новом потоке. В этом уроке вы научитесь писать такие функции сами и решите главную проблему обратных вызовов — как передать в них дополнительные данные.

## Функции высшего порядка

Функцию, которая принимает другую функцию, называют **функцией высшего порядка**. Простейшая — обход массива:

```c
#include <stdio.h>

typedef void Visitor(int value);

static void for_each(const int *values, size_t count, Visitor *visit) {
    for (size_t i = 0; i < count; i++) {
        visit(values[i]);
    }
}

static void print_square(int value) {
    printf("%d ", value * value);
}

int main(void) {
    int data[] = {3, 1, 4, 1, 5};
    for_each(data, 5, print_square);
    printf("\n");
    return 0;
}
```

Вывод:

```text
9 1 16 1 25
```

Пока callback'у хватает элемента, всё просто. Но попробуйте посчитать числа **больше порога**, где порог вводит пользователь. Функции `is_big(int value)` негде взять порог: сигнатура фиксирована, а `for_each` о пороге ничего не знает.

Первое, что приходит в голову, — глобальная переменная `threshold`. Это работает, но плохо: функция зависит от скрытого состояния, два вызова с разными порогами нельзя вложить друг в друга, а в многопоточной программе такой код ломается.

## Контекст: указатель на ваши данные

Стандартное решение в C — **контекст**: дополнительный параметр `void *ctx`, который функция высшего порядка ничего не делая передаёт в каждый вызов callback'а. Что лежит по этому адресу, знают только тот, кто вызывает, и сам callback:

```c
#include <stdio.h>

typedef int Predicate(int value, void *ctx);

static size_t count_if(const int *values, size_t count, Predicate *pred, void *ctx) {
    size_t found = 0;
    for (size_t i = 0; i < count; i++) {
        if (pred(values[i], ctx)) {
            found++;
        }
    }
    return found;
}

static int greater_than(int value, void *ctx) {
    const int *limit = ctx;              // мы знаем, что передали int
    return value > *limit;
}

struct Range {
    int low, high;
};

static int in_range(int value, void *ctx) {
    const struct Range *r = ctx;         // а здесь — структуру
    return value >= r->low && value <= r->high;
}

int main(void) {
    int data[] = {12, 5, 40, 7, 25, 3, 18};
    int limit = 10;
    struct Range teens = {13, 19};
    printf("больше %d: %zu\n", limit, count_if(data, 7, greater_than, &limit));
    printf("от %d до %d: %zu\n", teens.low, teens.high, count_if(data, 7, in_range, &teens));
    return 0;
}
```

Вывод:

```text
больше 10: 4
от 13 до 19: 1
```

`count_if` одна для всех условий, а каждое условие получает свои данные. Внутри callback'а `void *` превращается обратно в указатель нужного типа — компилятор этого не проверяет, поэтому тип контекста — часть договора между вызывающим и callback'ом.

Контекст может быть и **изменяемым**: через него callback накапливает результат.

```c
#include <stdio.h>

typedef void Step(int value, void *ctx);

static void for_each(const int *values, size_t count, Step *step, void *ctx) {
    for (size_t i = 0; i < count; i++) {
        step(values[i], ctx);
    }
}

struct Stats {
    long long sum;
    int count;
    int max;
};

static void collect(int value, void *ctx) {
    struct Stats *s = ctx;
    s->sum += value;
    if (s->count == 0 || value > s->max) {
        s->max = value;
    }
    s->count++;
}

int main(void) {
    int data[] = {4, -2, 9, 7};
    struct Stats stats = {0, 0, 0};
    for_each(data, 4, collect, &stats);
    printf("сумма %lld, чисел %d, максимум %d\n", stats.sum, stats.count, stats.max);
    return 0;
}
```

Вывод:

```text
сумма 18, чисел 4, максимум 9
```

Такой контекст — ручной аналог **замыкания** из других языков: функция плюс данные, которые она «помнит».

## Досрочная остановка обхода

Часто callback должен уметь сказать «хватит». Распространённое соглашение — возвращать 0, чтобы продолжить, и не ноль, чтобы остановить обход; функция высшего порядка возвращает это значение наружу. Так устроены функции обхода каталогов `nftw` и обратные вызовы SQLite:

```c
#include <stdio.h>

typedef int Visit(int index, int value, void *ctx);

static int walk(const int *values, int count, Visit *visit, void *ctx) {
    for (int i = 0; i < count; i++) {
        int stop = visit(i, values[i], ctx);
        if (stop != 0) {
            return stop;
        }
    }
    return 0;
}

static int find_negative(int index, int value, void *ctx) {
    if (value < 0) {
        *(int *)ctx = index;
        return 1;                       // нашли — останавливаемся
    }
    return 0;
}

int main(void) {
    int data[] = {8, 3, -1, 6, -4};
    int position = -1;
    if (walk(data, 5, find_negative, &position)) {
        printf("первое отрицательное на позиции %d\n", position);
    }
    return 0;
}
```

Вывод:

```text
первое отрицательное на позиции 2
```

## Регистрация обработчиков

Callback можно не вызывать сразу, а **запомнить** и вызвать позже — когда произойдёт событие. Так устроены графические интерфейсы, сетевые библиотеки и игровые движки: код регистрирует обработчики, а цикл событий вызывает их.

```c
#include <stdio.h>

typedef void Handler(const char *event, void *ctx);

static struct {
    Handler *handler;
    void *ctx;
} subscribers[8];
static int subscriber_count = 0;

static void subscribe(Handler *handler, void *ctx) {
    if (subscriber_count < 8) {
        subscribers[subscriber_count].handler = handler;
        subscribers[subscriber_count].ctx = ctx;
        subscriber_count++;
    }
}

static void emit(const char *event) {
    for (int i = 0; i < subscriber_count; i++) {
        subscribers[i].handler(event, subscribers[i].ctx);
    }
}

static void print_event(const char *event, void *ctx) {
    printf("%s: %s\n", (const char *)ctx, event);
}

static void count_event(const char *event, void *ctx) {
    (void)event;
    (*(int *)ctx)++;
}

int main(void) {
    static int clicks = 0;               // должна жить, пока подписка активна
    subscribe(print_event, "журнал");
    subscribe(count_event, &clicks);
    emit("нажатие");
    emit("нажатие");
    printf("нажатий: %d\n", clicks);
    return 0;
}
```

Вывод:

```text
журнал: нажатие
журнал: нажатие
нажатий: 2
```

Зарегистрированный контекст используется **после** возврата из функции, которая подписалась. Поэтому он должен жить достаточно долго: строковый литерал и `static` переменная подходят, а адрес обычной локальной переменной функции, которая уже вернулась, — нет. Это висячий указатель, знакомый по модулю о памяти.

## `atexit`: обратный вызов при выходе

Стандартная `atexit` регистрирует функцию, которую нужно вызвать при нормальном завершении программы — возврате из `main` или вызове `exit`. Функции вызываются в порядке, **обратном** регистрации: последний зарегистрированный ресурс освобождается первым.

```c
#include <stdio.h>
#include <stdlib.h>

static void close_log(void) {
    puts("журнал закрыт");
}

static void close_database(void) {
    puts("база закрыта");
}

int main(void) {
    atexit(close_log);          // открыли журнал первым
    atexit(close_database);     // базу — вторым
    puts("работаем");
    return 0;                   // после main вызовутся обработчики
}
```

Вывод:

```text
работаем
база закрыта
журнал закрыт
```

При аварийном завершении — `abort`, необработанный сигнал, `_Exit` — обработчики `atexit` не вызываются.

## Чего не хватает `qsort`

Функция сравнения `qsort` не получает контекста. Чтобы отсортировать по полю, выбранному во время работы (по возрасту или по имени — как скажет пользователь), приходится либо писать несколько функций сравнения, либо прятать выбор в глобальную переменную. Некоторые системы предлагают `qsort_r` с контекстом, но у glibc и BSD у неё разный порядок параметров, а `qsort_s` из необязательного приложения стандарта почти нигде не реализована. Поэтому в переносимом коде, когда нужен контекст, сортировку пишут сами — вы сделаете это в практике.

<Concept title="Договор обратного вызова">

У функции, принимающей callback, должен быть ясный договор: когда и сколько раз вызывается callback, в каком порядке, что означает его результат, какого типа контекст и сколько он должен жить, можно ли из callback'а менять обходимую структуру. Без этого пользователь будет угадывать — а ошибки в обратных вызовах трудно отлаживать.

</Concept>

## Частые ошибки

<CommonMistake title="Глобальная переменная вместо контекста">

Порог, счётчик или направление сортировки в глобальной переменной делают функцию нереентерабельной: её нельзя вызвать вложенно или из двух потоков. Передавайте данные через `void *ctx`.

</CommonMistake>

<CommonMistake title="Контекст не того типа">

Передали `&count` типа `long`, а callback приводит `ctx` к `int *`. Компилятор не заметит: `void *` превращается во что угодно. Держите тип контекста в документации функции и в имени параметра.

</CommonMistake>

<CommonMistake title="Контекст умер раньше подписки">

Подписка с адресом локальной переменной, которая вызывается после возврата из функции, обращается к уже несуществующему объекту. Контекст должен жить столько же, сколько регистрация.

</CommonMistake>

<CommonMistake title="Изменение коллекции во время обхода">

Callback, который удаляет элементы из обходимого списка или добавляет новые подписки во время рассылки, может сломать цикл обхода. Договор должен явно разрешать или запрещать такие действия.

</CommonMistake>

## Практика

1. **Фильтр с контекстом** — одна функция фильтрации для разных условий.
2. **Свёртка** — накопление результата через изменяемый контекст.
3. **Сортировка с контекстом** — своя устойчивая сортировка с выбором ключа и направления.
4. **Шина событий** — подписки, отписки и рассылка событий.

## Итоги

- Callback — функция, которую передают другой функции, чтобы та вызвала её. Функция высшего порядка знает, как обойти данные, callback — что с ними сделать.
- Дополнительные данные передают через контекст `void *ctx`: функция высшего порядка передаёт его в каждый вызов, callback приводит его к нужному типу.
- Контекст может быть изменяемым — так callback накапливает результат. Это ручной аналог замыкания.
- Соглашение «0 — продолжить, не ноль — остановиться» позволяет прервать обход досрочно.
- Зарегистрированный callback вызывается позже, поэтому его контекст должен жить достаточно долго.
- `atexit` вызывает обработчики при нормальном завершении в обратном порядке регистрации.
- У `qsort` нет контекста; когда он нужен, переносимый код пишет свою сортировку с параметром `void *ctx`.
