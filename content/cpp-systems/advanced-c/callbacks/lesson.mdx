## Теория

Callback передаёт выбор действия вызывающему коду, а алгоритм сохраняет контроль над обходом. Контекст void \* позволяет передать состояние без глобальных переменных. Контракт должен описывать, сколько раз вызывается обработчик, может ли он остановить обход и сохраняет ли алгоритм указатель на контекст после возврата.

Синхронный обход может использовать адрес локального контекста, пока вызов не завершился. Асинхронное хранение того же адреса требует более долгого времени жизни. Разделите данные и поведение: функция знает, что делать с одним элементом, структура контекста хранит сумму или порог. Это делает независимые экземпляры обработки возможными без скрытого static-состояния.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
static void visit(int value,void *context){int *sum=context;*sum+=value;}
int main(void) {
    int sum=0;visit(4,&sum);visit(6,&sum);printf("%d\n",sum);
    return 0;
}
```

## Проект: Динамический массив на C

Реализуйте vector-подобный контейнер int: структуру Vector с data, size, capacity и функции reserve, push, pop, at, clear, destroy. Инвариант: size &lt;= capacity; только элементы [0,size) инициализированы. reserve сохраняет данные и состояние при отказе; push при заполнении удваивает вместимость, начиная с 1. clear сохраняет выделенную память. destroy освобождает её и обнуляет структуру.

Протокол: первая строка q (0…200), далее q команд: + x добавляет int −1000…1000 без вывода; - удаляет и печатает последний элемент либо ПУСТО; ? i печатает элемент индекса i (0…1000) либо ОШИБКА; r n резервирует не менее n (0…1000) без вывода; c очищает без освобождения; s печатает size и capacity. reserve увеличивает capacity ровно до запрошенной величины, если она больше текущей. Некорректные команды не подаются. После последней команды уничтожьте контейнер. Ошибка выделения завершает программу с ненулевым кодом.

Тесты проверяют наблюдаемое поведение и диагностику памяти. На разборе отдельно проверьте инварианты и гарантию сохранения состояния при отказе allocator.
