## Теория

#if, #ifdef и #elif выбирают код при сборке. defined(NAME) отвечает, определён ли макрос, а #if NAME проверяет его числовое значение. Макрос, определённый как 0, всё ещё проходит #ifdef. Это различие особенно важно для флагов возможностей.

Задавайте значения по умолчанию через #ifndef, чтобы -D мог их переопределить. Неподдерживаемую комбинацию остановите через #error. Каждая поддерживаемая конфигурация — отдельная программа, которую нужно собрать и проверить: тесты только debug-ветки ничего не говорят о release-ветке. Избыточное число независимых флагов быстро увеличивает число комбинаций.

## Запускаемый пример

Пример не требует stdin. Выполните его кнопкой «Запустить», затем измените одно значение и предскажите новый результат до повторного запуска.

```c
#include <stdio.h>
#define TRACE 0
#if TRACE
#define LABEL "Отладка"
#else
#define LABEL "Работа"
#endif
int main(void) {
    puts(LABEL);
    return 0;
}
```

## Разбор выполнения

Сначала создаются объекты и выбирается операция, затем вычисляется аргумент вывода. Ожидаемый stdout:

```text
Работа
```

Конфигурация сборки выбирает один чертёж; runtime if выбирает действие уже собранного устройства. Проверьте, какая часть примера задаётся при трансляции, а какая выполняется в main. #ifdef FEATURE включает ветвь даже при -DFEATURE=0.
