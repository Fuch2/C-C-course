## Один исходник — разные программы

Одна и та же программа часто нужна в нескольких вариантах: отладочная сборка печатает подробности, а финальная — нет; под Linux файлы открываются одними функциями, под Windows — другими; необязательная возможность включается флагом при сборке. Держать несколько копий исходника — значит исправлять каждую ошибку в нескольких местах.

**Условная компиляция** решает это иначе: препроцессор оставляет или выбрасывает части текста ещё до компилятора. Выброшенный код не компилируется вовсе, поэтому в нём могут быть вызовы функций, которых на этой платформе нет. Вы уже пользовались этим механизмом в защите заголовков; теперь разберём его полностью.

## `#if`, `#elif`, `#else`, `#endif`

```c
#include <stdio.h>

#define LOG_LEVEL 2            // 0 — тихо, 1 — ошибки, 2 — предупреждения, 3 — всё

int main(void) {
#if LOG_LEVEL >= 3
    puts("режим: подробный");
#elif LOG_LEVEL == 2
    puts("режим: предупреждения и ошибки");
#elif LOG_LEVEL == 1
    puts("режим: только ошибки");
#else
    puts("режим: тихий");
#endif
    return 0;
}
```

Вывод:

```text
режим: предупреждения и ошибки
```

Препроцессор вычисляет условия по порядку и оставляет **первую** ветку с ненулевым условием (или `#else`, если ни одна не подошла). Остальные ветки исчезают из текста. Каждый `#if` закрывается своим `#endif`, блоки можно вкладывать друг в друга.

Условие `#if` — целочисленное константное выражение, которое вычисляет **препроцессор**. В нём можно использовать:

- целые числа и символьные константы (`'A'`);
- макросы — они раскрываются до вычисления;
- арифметику, сравнения, логические `!`, `&&`, `||`, а также `?:` и побитовые операции;
- оператор `defined(ИМЯ)` — 1, если макрос определён, иначе 0.

Нельзя: переменные, `sizeof`, приведения типов, константы `enum`. Препроцессор работает до компилятора и ничего о них не знает.

## Неопределённое имя равно нулю

Есть правило, которое делает `#if` коварным: после раскрытия макросов каждый оставшийся идентификатор **заменяется нулём**. Ошибки нет:

```c
#include <stdio.h>

#define DEBUG_LEVEL 2

int main(void) {
#if DEBUG_LEVL >= 2                  // опечатка: DEBUG_LEVL — это 0
    puts("подробная отладка");
#endif
    puts("готово");
    return 0;
}
```

Вывод:

```text
готово
```

Опечатка в имени молча выключила отладочный код. Ровно так же ведут себя константы `enum` и переменные: `#if MAX_USERS > 10` для `enum { MAX_USERS = 64 };` всегда ложно. GCC и Clang умеют предупреждать о неопределённых именах в `#if` флагом `-Wundef` — его стоит включать в проектах с большим количеством условной компиляции.

`sizeof` в условии даже не разбирается — препроцессор видит неизвестное имя `sizeof` (то есть 0) и за ним непонятную скобку:

```c
#include <stdio.h>

#if sizeof(int) == 4                 // Ошибка компиляции: missing binary operator before token "("
#define INT_BITS 32
#endif

int main(void) {
    printf("%d\n", INT_BITS);
    return 0;
}
```

Для таких проверок есть макросы из `<limits.h>` и `<stdint.h>` (`#if INT_MAX == 2147483647`) и `static_assert`, о котором пойдёт речь в последнем уроке модуля.

## `#ifdef`, `#ifndef` и `defined`

`#ifdef ИМЯ` — то же, что `#if defined(ИМЯ)`, а `#ifndef ИМЯ` — `#if !defined(ИМЯ)`. Сокращённые формы проверяют одно имя, а `defined` можно комбинировать:

```c
#if defined(USE_COLOR) && !defined(NO_TERMINAL)
    /* цветной вывод */
#endif
```

`#ifdef` проверяет только **факт определения**, а не значение. Это частая ловушка:

```c
#include <stdio.h>

#define DEBUG 0                      // «выключили» отладку

int main(void) {
#ifdef DEBUG
    puts("отладка включена");        // всё равно печатается
#endif
#if DEBUG
    puts("отладка включена (по значению)");
#endif
    puts("работа");
    return 0;
}
```

Вывод:

```text
отладка включена
работа
```

Договоритесь в проекте об одном стиле. Либо флаг — это **наличие** макроса (`-DDEBUG` включает, отсутствие выключает, проверка `#ifdef`). Либо флаг — это **значение** (`#define DEBUG 0` или `1`, проверка `#if DEBUG`). Смешивать нельзя.

## Типичные применения

**Отладочный код.** Макрос печати, который в финальной сборке превращается в ничто:

```c
#include <stdio.h>

#define DEBUG

#ifdef DEBUG
#define DEBUG_PRINT(...) printf(__VA_ARGS__)
#else
#define DEBUG_PRINT(...) ((void)0)
#endif

int main(void) {
    int total = 0;
    for (int i = 1; i <= 3; i++) {
        total += i * i;
        DEBUG_PRINT("i=%d total=%d\n", i, total);
    }
    printf("сумма квадратов: %d\n", total);
    return 0;
}
```

Вывод:

```text
i=1 total=1
i=2 total=5
i=3 total=14
сумма квадратов: 14
```

Без строки `#define DEBUG` (или при сборке без флага `-DDEBUG`) вызовы `DEBUG_PRINT` превратятся в `((void)0);` — пустое выражение, которое ничего не делает, но оставляет синтаксис корректным.

**Платформа и компилятор.** Компиляторы определяют макросы, по которым можно узнать систему и сам компилятор:

| Макрос      | Когда определён                                            |
| ----------- | ---------------------------------------------------------- |
| `__linux__` | Linux                                                      |
| `_WIN32`    | Windows, в том числе 64-битная                             |
| `__APPLE__` | macOS и iOS                                                |
| `__unix__`  | Unix-подобные системы (Linux, BSD; на macOS — нет)         |
| `__GNUC__`  | GCC **и** Clang: Clang притворяется GCC ради совместимости |
| `__clang__` | только Clang                                               |
| `_MSC_VER`  | компилятор Microsoft Visual C++                            |

```c
#include <stdio.h>

int main(void) {
#if defined(_WIN32)
    puts("Windows");
#elif defined(__APPLE__)
    puts("macOS");
#elif defined(__linux__)
    puts("Linux");
#else
#error "Неизвестная платформа"
#endif
    return 0;
}
```

Вывод:

```text
Linux
```

Песочница курса работает в Linux, поэтому выбрана третья ветка. Ветка `#else` с `#error` — хорошая привычка: на незнакомой платформе программа не соберётся с понятным сообщением, вместо того чтобы молча остаться без нужного кода. Чтобы отличить Clang от GCC, `__clang__` проверяют **первым**: `__GNUC__` определён в обоих.

**Версия стандарта.** Библиотеку часто собирают разными компиляторами и по разным стандартам. Новые возможности используют, только если компилятор их поддерживает, а для старых стандартов оставляют запасной вариант:

```c
#include <stdio.h>

#if __STDC_VERSION__ > 201710L
#define NODISCARD [[nodiscard]]
#else
#define NODISCARD
#endif

NODISCARD static int parse_digit(char c) {
    return c >= '0' && c <= '9' ? c - '0' : -1;
}

int main(void) {
#if __STDC_VERSION__ > 201710L
    puts("C23: есть constexpr, nullptr и атрибуты [[...]]");
#elif __STDC_VERSION__ >= 201112L
    puts("C11 или C17");
#else
    puts("старый стандарт");
#endif
    printf("%d\n", parse_digit('7'));
    return 0;
}
```

Вывод:

```text
C23: есть constexpr, nullptr и атрибуты [[...]]
7
```

Обратите внимание на сравнение `> 201710L`, а не `== 202311L`. Окончательное значение для C23 — `202311L`, его выдаёт Clang 19, а GCC 14 в режиме `-std=c23` пока сообщает промежуточное `202000L`. Проверка «новее C17» работает в обоих.

C23 добавил и директивы, которые делают такие проверки короче:

- `#elifdef ИМЯ` и `#elifndef ИМЯ` — сокращения для `#elif defined(ИМЯ)` и `#elif !defined(ИМЯ)`;
- `__has_include(<заголовок>)` — есть ли заголовок: `#if __has_include(<stdckdint.h>)`;
- `__has_c_attribute(nodiscard)` — поддерживает ли компилятор атрибут.

Ими пользуются для постепенного перехода: новый код работает с возможностями C23 там, где они есть, и не ломает сборку на старых компиляторах.

**Проверка настроек.** `#error` внутри `#if` останавливает сборку с неправильными параметрами:

```c
#include <stdio.h>

#define BUFFER_SIZE 8

#if BUFFER_SIZE < 16
#error "BUFFER_SIZE должен быть не меньше 16"   // Ошибка компиляции
#endif

int main(void) {
    char buffer[BUFFER_SIZE];
    printf("%zu\n", sizeof buffer);
    return 0;
}
```

**Временно выключить код.** `#if 0 … #endif` надёжнее, чем закомментировать блок: внутри может быть код со своими комментариями `/* */`, которые сломали бы внешний комментарий.

## Цена условной компиляции

Выброшенный код **не компилируется**. Если в отладочную ветку вкралась опечатка, финальная сборка этого не заметит — ошибку найдут, только когда кто-нибудь включит отладку. Каждый флаг удваивает число вариантов программы, и проверить их все трудно.

Поэтому условные блоки делают маленькими, а платформенный код выносят в отдельные функции или файлы. А там, где это возможно, вместо `#if` используют обычный `if` с константой: компилятор проверит обе ветки, а оптимизатор выбросит ненужную:

```c
#include <stdio.h>

#ifndef VERBOSE
#define VERBOSE 0
#endif

int main(void) {
    int items = 3;
    if (VERBOSE) {
        printf("обрабатываем %d элементов\n", items);
    }
    printf("обработано: %d\n", items);
    return 0;
}
```

Вывод:

```text
обработано: 3
```

Код внутри `if (VERBOSE)` компилируется всегда, поэтому опечатка в нём сразу даст ошибку — даже в сборке без подробного вывода.

<Concept title="Препроцессор выбирает текст, а не поведение">

`#if` решает до компиляции, какие строки вообще станут частью программы. Обычный `if` решает во время работы, какие строки выполнить. Если вариант зависит от платформы или настроек сборки — нужен `#if`. Если от данных — `if`. А когда подходят оба, `if` с константой безопаснее.

</Concept>

## Частые ошибки

<CommonMistake title="#ifdef для флага со значением">

`#define FEATURE 0` не выключает код под `#ifdef FEATURE`: макрос определён. Проверяйте значения через `#if FEATURE`, а наличие — через `#ifdef`.

</CommonMistake>

<CommonMistake title="Опечатка в имени внутри #if">

Неопределённое имя в `#if` молча равно нулю. Включайте `-Wundef`, чтобы компилятор предупреждал о таких именах.

</CommonMistake>

<CommonMistake title="sizeof и enum в #if">

Препроцессор не знает типов и перечислений. `sizeof` в `#if` — синтаксическая ошибка, константа `enum` — ноль. Используйте `<limits.h>` или `static_assert`.

</CommonMistake>

<CommonMistake title="Платформенные ветки без #else">

Если ни одна ветка не подошла, код просто исчезает, и ошибка проявится далеко от места причины. Добавляйте `#else` с `#error`.

</CommonMistake>

## Практика

1. **Найди ошибку: молчаливая отладка** — опечатка в имени макроса внутри `#if`.
2. **Какие строки попадут в программу** — смоделировать `#ifdef`, `#ifndef`, `#else`, `#endif`, `#define` и `#undef`.
3. **Вычисление условий #if** — выражения с `defined`, макросами и неопределёнными именами.

## Итоги

- Условная компиляция оставляет или выбрасывает части текста до компилятора: выброшенный код не компилируется.
- `#if` вычисляет целочисленное выражение из чисел, макросов, операций и `defined(ИМЯ)`; оставляется первая ветка с ненулевым условием.
- Неопределённое имя в `#if` равно нулю — без ошибки. `sizeof`, переменные и `enum` в `#if` не работают.
- `#ifdef` и `#ifndef` проверяют факт определения, а не значение: `#define DEBUG 0` всё равно включает `#ifdef DEBUG`.
- Типичные применения: отладочный код, платформа и компилятор (`__linux__`, `_WIN32`, `__clang__`), версия стандарта, проверка настроек через `#error`, `#if 0`.
- Выброшенный код не проверяется компилятором; где возможно, используйте `if` с константой.
