## Где видно имя

**Область видимости** — часть текста программы, где имя можно использовать. Для локальной переменной это участок от объявления до закрывающей скобки её блока. Внутренний блок может объявить своё имя, совпадающее с внешним, — оно **затеняет** внешнее до конца блока:

```cpp
#include <print>

int value = 1;

int main() {
    std::println("{}", value);
    int value = 2;
    {
        std::println("{}", value);
        int value = 3;
        std::println("{} {}", value, ::value);
    }
    std::println("{}", value);
    return 0;
}
```

Вывод:

```text
1
2
3 1
2
```

Внутренняя `value` живёт и видна только внутри фигурных скобок. До глобальной переменной можно добраться через `::value`, а до затенённой локальной из внешнего блока — уже никак. Затенение законно, но почти всегда сбивает с толку; флаг `-Wshadow` предупреждает о нём.

## Чем меньше область, тем лучше

Объявляйте переменную как можно ближе к месту использования и в самом узком блоке. Тогда её нельзя случайно использовать раньше времени или после того, как она потеряла смысл, а объект и его ресурсы освобождаются сразу, как только не нужны.

Для этого в C++17 у `if` и `switch` появился **инициализатор**: переменная объявляется прямо в условии и видна во всех ветках, но не после `if`:

```cpp
#include <map>
#include <print>
#include <string>

int main() {
    const std::map<std::string, int> stock{{"яблоки", 12}, {"груши", 0}};
    for (const char *name : {"яблоки", "груши", "сливы"}) {
        if (auto it = stock.find(name); it == stock.end()) {
            std::println("{}: нет в каталоге", name);
        } else if (it->second == 0) {
            std::println("{}: закончились", name);
        } else {
            std::println("{}: {} шт.", name, it->second);
        }
    }
    return 0;
}
```

Вывод:

```text
яблоки: 12 шт.
груши: закончились
сливы: нет в каталоге
```

Итератор `it` нужен только для проверки — и существует только в ней. С C++20 инициализатор есть и у цикла по диапазону: `for (auto list = load(); const auto &x : list)`.

## Каждая итерация — новый объект

Переменная, объявленная в теле цикла, создаётся и уничтожается **на каждой итерации**:

```cpp
#include <print>

struct Tracer {
    int n;
    explicit Tracer(int n) : n(n) {
        std::print("+{} ", n);
    }
    ~Tracer() {
        std::print("-{} ", n);
    }
};

int main() {
    for (int i = 1; i <= 3; i++) {
        Tracer t(i);
    }
    std::println();
    return 0;
}
```

Вывод:

```text
+1 -1 +2 -2 +3 -3
```

Если объект дорого создавать (например, буфер), а он нужен в каждой итерации, его объявляют до цикла и переиспользуют. Если же объект должен начинать каждую итерацию «с чистого листа» — объявляйте внутри.

## Лямбда переживает свою область

Лямбда — объект, и у неё тоже есть время жизни. Её можно вернуть из функции, сохранить в `std::function` или в контейнер — и она переживёт область, где была создана. Тогда важно, **как** она захватила переменные:

- захват **по значению** (`[x]`, `[=]`, `[x = выражение]`) копирует значение внутрь лямбды — копия живёт вместе с ней;
- захват **по ссылке** (`[&x]`, `[&]`) хранит ссылку на исходную переменную — она действительна, только пока переменная жива.

```cpp
#include <functional>
#include <print>

std::function<int()> make_counter(int start, int step) {
    return [value = start, step]() mutable {
        value += step;
        return value;
    };
}

int main() {
    auto a = make_counter(10, 5);
    auto b = make_counter(0, 1);
    const int first = a();
    const int second = a();
    std::println("{} {} {}", first, second, b());
    return 0;
}
```

Вывод:

```text
15 20 1
```

Каждый счётчик хранит своё `value` внутри себя; `mutable` разрешает его менять. А вот так — ошибка:

```cpp
#include <functional>
#include <print>

std::function<int()> make_counter(int start, int step) {
    int value = start;
    return [&]() {
        value += step;
        return value;
    };
}

int main() {
    auto c = make_counter(10, 5);
    std::println("{}", c()); // Ошибка памяти
    return 0;
}
```

`[&]` захватил ссылки на `value` и `step` — локальные переменные `make_counter`. Функция вернулась, её кадр стека освобождён, и лямбда обращается к мёртвым переменным. AddressSanitizer сообщает `stack-use-after-return`.


<Important title="Правило для лямбд">

Если лямбда может пережить текущую функцию — её возвращают, сохраняют в поле или контейнер, передают в другой поток, — захватывайте **по значению**. Захват по ссылке `[&]` безопасен, только когда лямбда используется немедленно, например в `std::ranges::sort` или `std::ranges::count_if`.

</Important>

<Concept title="Область видимости и время жизни">

Область видимости локального имени — от объявления до конца блока; внутреннее имя затеняет внешнее. Локальный объект умирает, когда выполнение покидает его блок, а объект в теле цикла — в конце каждой итерации. Инициализаторы в `if`, `switch` и `for` сужают область переменной до одного оператора. Лямбда — объект, способный пережить свою область: захват по значению копирует данные внутрь неё, захват по ссылке оставляет ссылки на чужие переменные, которые повиснут после выхода из их блока.

</Concept>

## Частые ошибки

<CommonMistake title="[&] в лямбде, которая выходит из функции">

Возвращаемая или сохраняемая лямбда с захватом по ссылке ссылается на мёртвые локальные переменные. Захватывайте по значению: `[x]`, `[x = std::move(x)]`.

</CommonMistake>

<CommonMistake title="Затенение переменной">

`int count = 0; if (…) { int count = 5; … }` — внешний `count` не меняется. Включите `-Wshadow` и давайте разным переменным разные имена.

</CommonMistake>

<CommonMistake title="Переменная шире, чем нужно">

Итератор или временный буфер, объявленный в начале функции, легко использовать по ошибке ниже. Объявляйте переменные в самом узком блоке, используйте инициализаторы в `if`.

</CommonMistake>

## Практика

1. **Словарь** — `if` с инициализатором.
2. **Счётчики** — лямбды с собственным состоянием в контейнере.
3. **Найди ошибку: забытый счётчик** — захват по ссылке в возвращаемой лямбде.
4. **Отмена действий** — объекты, срабатывающие при выходе из области.

## Итоги

- Область видимости — где можно написать имя; время жизни — когда существует объект.
- Внутренние имена затеняют внешние; `-Wshadow` об этом предупреждает.
- Объявляйте переменные в самом узком блоке; для этого есть инициализаторы в `if`, `switch` и `for`.
- Объект в теле цикла создаётся и уничтожается на каждой итерации.
- Лямбда, переживающая свою область, должна захватывать по значению.
