## Цели обучения

- Различать scope имени и lifetime объекта на примерах затенения и static.
- Проследить на MemoryDiagram независимость двух объектов с одним именем.
- Диагностировать висячую ссылку при возврате и исправить функцию на возврат по значению.

## Модель и назначение

Scope отвечает на вопрос, где в исходном тексте разрешено употреблять имя. Lifetime отвечает на вопрос, существует ли объект в данный момент исполнения. Для простой локальной переменной эти интервалы совпадают, и совпадение порождает путаницу. Затенение имени во вложенном блоке не уничтожает внешний объект. Локальная static-переменная хранит объект между вызовами функции, хотя имя доступно только внутри неё. Динамический объект переживает блок создания, если владение вынесено наружу, а ссылка на локальный объект не переживает возврат из функции.

## Механика и гарантии

Ссылка — дополнительное имя существующего объекта, а не владелец. Локальная const-ссылка, напрямую привязанная к временному объекту, продлевает его жизнь до конца своей области: const std::string&amp; s = std::string&#123;"ok"&#125; законно. Но продление не передаётся через возвраты: если функция приняла const T&amp; и вернула её же, временный объект вызывающего умрёт в конце полного выражения. std::string_view и std::span не продлевают жизнь данным никогда. В C++20 временные объекты разрушаются в конце полного выражения; для результата вычисления надёжнее всего возвращать владеющее значение — NRVO и устранение копий делают это бесплатным.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { int value = 4; { int value = 9; std::cout << value << " "; } std::cout << value << "\n"; }
```

Ожидаемый вывод:

```text
9 4
```

## Разбор и эксперимент

Постройте две временные шкалы: для const auto&amp; s = std::string&#123;"abc"&#125; и для std::string_view v = std::string&#123;"abc"&#125;. В первом случае строка живёт вместе со ссылкой; во втором умирает в конце выражения инициализации, а view остаётся указывать на освобождённый буфер.

### Имя и объект живут по разным часам

Scope — свойство исходного текста: где компилятор разрешает употреблять имя. Lifetime — свойство исполнения: когда объект существует. Они совпадают у простой локальной переменной, и это совпадение порождает три устойчивых заблуждения.

Первое: «выход из scope уничтожает объект». Нет — объект, созданный в new, переживает блок; копия значения, вынесенная наружу, тоже. Уничтожаются только автоматические объекты блока. Второе: «затенение имени убивает внешний объект». Тоже нет — внутренний value скрывает имя, внешний объект жив и снова виден после закрывающей скобки. Третье: «const&amp; сохраняет объект». const запрещает изменение через ссылку, но не управляет временем жизни; продление жизни временного объекта — отдельное специальное правило, которое не передаётся через возвраты функций.

Практический вывод для C++20: возвращайте значения. NRVO и гарантированное устранение копий prvalue делают возврат std::string или vector таким же дешёвым, как ссылка, но без класса ошибок «висячий результат».

<CommonMistake title="Граница корректности">

Не возвращайте const int&amp; на локальную переменную: const запрещает изменение через ссылку, но не хранит объект. Тот же дефект встречается у string_view на временную строку, у span на временный vector и у ссылок на элементы возвращённого по значению контейнера.
