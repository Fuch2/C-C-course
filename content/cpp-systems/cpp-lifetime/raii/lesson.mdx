## Ресурс нужно вернуть

**Ресурс** — всё, что программа берёт на время и обязана вернуть: память из кучи, открытый файл, сетевое соединение, блокировку мьютекса, поток. Каждое «взять» требует ровно одного «вернуть». Вернуть забыли — утечка; вернули дважды — разрушение чужих данных.

Вручную это сделать трудно. Функция может выйти раньше через `return`, а исключение покидает её из **любой** строки:

```cpp
#include <print>
#include <stdexcept>

int open_handles = 0;

int acquire() {
    ++open_handles;
    return 42;
}

void release(int) {
    --open_handles;
}

void process(bool fail) {
    const int h = acquire();
    if (fail) {
        throw std::runtime_error("сбой");
    }
    release(h);
}

int main() {
    try {
        process(false);
        process(true);
    } catch (const std::exception &e) {
        std::println("ошибка: {}", e.what());
    }
    std::println("открыто: {}", open_handles);
    return 0;
}
```

Вывод:

```text
ошибка: сбой
открыто: 1
```

Исключение пролетело мимо `release` — дескриптор утёк. Можно дописать `try`/`catch` в каждую такую функцию, но каждый новый ресурс и каждый новый путь выхода умножают проверки.

## Захват ресурса — это инициализация

Идиома **RAII** (Resource Acquisition Is Initialization) связывает ресурс со временем жизни объекта: конструктор захватывает ресурс, деструктор освобождает. Деструктор локального объекта вызывается при **любом** выходе из блока — обычном, через `return`, `break` или исключение. Значит, освобождение невозможно забыть.

```cpp
#include <print>
#include <stdexcept>

int open_handles = 0;

int acquire() {
    ++open_handles;
    return 42;
}

void release(int) {
    --open_handles;
}

class Handle {
public:
    Handle() : id_(acquire()) {}
    ~Handle() {
        release(id_);
    }
    Handle(const Handle &) = delete;
    Handle &operator=(const Handle &) = delete;

    int id() const {
        return id_;
    }

private:
    int id_;
};

void process(bool fail) {
    const Handle h;
    if (fail) {
        throw std::runtime_error("сбой");
    }
}

int main() {
    try {
        process(false);
        process(true);
    } catch (const std::exception &e) {
        std::println("ошибка: {}", e.what());
    }
    std::println("открыто: {}", open_handles);
    return 0;
}
```

Вывод:

```text
ошибка: сбой
открыто: 0
```

В `process` больше нет кода освобождения вовсе. Копирование `Handle` запрещено: две копии освободили бы один дескриптор дважды. Как правильно копировать и перемещать владельцев, разберём в следующих уроках.

## RAII в стандартной библиотеке

Вы пользуетесь RAII с первых уроков:

| Тип                                      | Ресурс              | Освобождение в деструкторе       |
| ---------------------------------------- | ------------------- | -------------------------------- |
| `std::string`, `std::vector`, `std::map` | память              | освобождает буфер                |
| `std::unique_ptr`, `std::shared_ptr`     | объект в куче       | удаляет объект                   |
| `std::ifstream`, `std::ofstream`         | открытый файл       | закрывает файл                   |
| `std::lock_guard`, `std::scoped_lock`    | блокировка мьютекса | снимает блокировку               |
| `std::jthread` (C++20)                   | поток               | просит остановиться и дожидается |

Блокировка — классический пример. С `std::scoped_lock` мьютекс снимается на любом пути выхода:

```cpp
#include <mutex>
#include <print>

std::mutex m;
int balance = 100;

bool withdraw(int amount) {
    const std::scoped_lock lock(m);
    if (amount > balance) {
        return false;
    }
    balance -= amount;
    return true;
}

int main() {
    const bool a = withdraw(30);
    const bool b = withdraw(500);
    const bool c = withdraw(70);
    std::println("{} {} {} остаток {}", a, b, c, balance);
    return 0;
}
```

Вывод:

```text
true false true остаток 0
```

Ранний `return false` снимает блокировку так же надёжно, как обычный выход. Забытый `m.unlock()` в ручном варианте навсегда заблокировал бы все остальные потоки.

<Important title="Деструктор не бросает исключений">

Деструкторы по умолчанию `noexcept`: исключение из деструктора завершает программу через `std::terminate`. Освобождение ресурса не должно падать; если ошибку закрытия важно сообщить (например, при сбросе файла на диск), дайте классу отдельный метод `close()`, а деструктор пусть лишь подстраховывает.

</Important>

<Concept title="RAII">

RAII связывает ресурс со временем жизни объекта: конструктор захватывает, деструктор освобождает. Так как деструктор локального объекта вызывается при любом выходе из блока — включая исключения, — освобождение нельзя забыть или пропустить. Владельца ресурса обычно делают некопируемым. Стандартные контейнеры, умные указатели, файловые потоки, блокировки и `std::jthread` — RAII-классы. Деструкторы не бросают исключений.

</Concept>

## Частые ошибки

<CommonMistake title="Ручное освобождение после кода, который может бросить">

`p = new T; work(); delete p;` — если `work` бросит, `delete` не выполнится. Владелец-объект освобождает ресурс сам.

</CommonMistake>

<CommonMistake title="Безымянный RAII-объект">

`std::scoped_lock(m);` или `std::lock_guard<std::mutex>{m};` без имени создают временный объект, который умирает на точке с запятой, — блокировка снимается сразу. Всегда давайте имя: `const std::scoped_lock lock(m);`.

</CommonMistake>

<CommonMistake title="Копируемый владелец">

Если у класса-владельца нет запрета копирования, копия освободит ресурс второй раз. Запретите копирование (`= delete`) или реализуйте его осмысленно.

</CommonMistake>

## Практика

1. **Соединения** — освобождение при обычном выходе, раннем выходе и исключении.
2. **Отступы** — объект, восстанавливающий состояние при выходе из области.
3. **Найди ошибку: утечка при ошибке разбора** — ручной `delete[]`, до которого не дошли.
4. **Стек состояний рисования** — сохранение и восстановление состояния при исключениях.

## Итоги

- Ресурс — всё, что нужно вернуть: память, файлы, соединения, блокировки, потоки.
- RAII: конструктор захватывает ресурс, деструктор освобождает; освобождение происходит при любом выходе из блока.
- Код с RAII не содержит ручной очистки и остаётся корректным при исключениях.
- Владельцев ресурса делают некопируемыми; деструкторы не бросают исключений.
- Контейнеры, умные указатели, файловые потоки, блокировки и `std::jthread` — готовые RAII-классы.
