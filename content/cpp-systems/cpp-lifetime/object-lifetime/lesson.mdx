## Цели обучения

- Различать память, объект и значение и называть границы времени жизни объекта.
- Проследить на MemoryDiagram создание и завершение объекта во вложенном блоке.
- Вернуть результат вычисления по значению, не создавая висячих адресов.

## Модель и назначение

Объект в C++ — это не участок памяти, а участок памяти с типом, состоянием и интервалом существования. Время жизни начинается, когда инициализация завершена, и заканчивается, когда начинается вызов деструктора. Память при этом может существовать дольше объекта: байты стекового кадра никуда не исчезают в момент выхода из блока, но объекта в них уже нет. Обращение к памяти, где объект уже не жив, — undefined behavior, даже если старые байты ещё хранят прежнее значение и чтение «выдаёт правильный ответ».

## Механика и гарантии

Различайте три сущности: переменную-указатель, объект по её адресу и владельца, отвечающего за освобождение. Указатель может пережить объект: delete не ищет и не обнуляет все копии адреса, поэтому ненулевой указатель не доказывает существование объекта. Напротив, копия значения int полностью независима от источника и может безопасно пережить его — именно поэтому результат вычислений возвращают по значению. Отдельный тонкий случай: после освобождения аллокатор может выдать тот же адрес новому объекту. Совпадение адреса не даёт старому заёмщику права доступа: разрешение связано с объектом, а не с числом.

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { int total = 0; { int reading = 42; total = reading; } std::cout << total << "\n"; }
```

Ожидаемый вывод:

```text
42
```

## Разбор и эксперимент

Замените копирование значения сохранением адреса &amp;reading и прочитайте его после блока. Отметьте точную границу — закрывающую скобку, после которой разыменование становится недопустимым. Не запускайте дефектный вариант вне sandbox.

### Три уровня: память, объект, значение

Адрес, объект и значение — разные вещи. Аллокатор выдаёт участок памяти; объект возникает на нём после инициализации и существует до начала деструктора; значение можно скопировать и унести с собой. Ошибка «использование после освобождения» — это попытка работать с объектом, которого больше нет, через память, которая физически ещё доступна.

Проверьте себя на любом участке кода: для каждого ресурса назовите три точки — создание, последнее допустимое использование и завершение жизни. Если третью точку назвать нельзя, у ресурса нет владельца. Если вторая точка лежит после третьей, это дефект независимо от того, «повезло» ли при запуске.

Отдельный тонкий случай — повторное использование адреса. После delete новый объект может получить тот же адрес, и старый указатель будет «указывать» уже на другой объект. Значение адреса совпало, но право доступа — нет: прежний заёмщик не получал разрешения читать нового жильца.

<CommonMistake title="Граница корректности">

Случайно правильное значение из освобождённой памяти не делает чтение законным. Undefined behavior не обязано приводить к падению: программа может работать на отладочной сборке и ломаться на релизной. Корректность исходника нельзя оценивать по ожидаемому stdout.

</CommonMistake>

## Практика

В solve(a,b) создайте во вложенном блоке локальное измерение a+b и скопируйте его значение во внешнюю переменную. Верните значение после завершения блока. Не возвращайте адрес или ссылку на локальную переменную.
