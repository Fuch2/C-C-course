## Когда объект существует

У каждого объекта есть **время жизни** — отрезок выполнения программы, когда объект существует: от конца работы конструктора до начала работы деструктора. Вне этого отрезка память может ещё быть на месте, но объекта в ней уже (или ещё) нет, и обращение к нему — неопределённое поведение.

Не путайте время жизни с **областью видимости**. Область видимости — свойство **имени** в тексте программы: где компилятор разрешает его написать. Время жизни — свойство **объекта** во время работы. Они часто совпадают, но не всегда: статическая переменная функции невидима снаружи, но живёт до конца программы; объект в куче живёт, хотя указатель на него давно вышел из области видимости.

## Четыре вида хранения

Как долго живёт объект, определяет его **вид хранения** (storage duration):

| Вид            | Как создаётся                                          | Когда умирает                                |
| -------------- | ------------------------------------------------------ | -------------------------------------------- |
| автоматический | локальная переменная, параметр                         | в конце своего блока `{ … }`                 |
| статический    | глобальная переменная, `static` внутри функции         | после завершения `main`                      |
| динамический   | `new`, а чаще — внутри контейнера или умного указателя | при `delete` (или когда владелец его удалит) |
| потоковый      | `thread_local`                                         | при завершении потока                        |

Проследим за объектами, которые сообщают о своём рождении и смерти:

```cpp
#include <print>
#include <string>
#include <utility>

struct Tracer {
    std::string name;
    explicit Tracer(std::string n) : name(std::move(n)) {
        std::println("+{}", name);
    }
    ~Tracer() {
        std::println("-{}", name);
    }
};

Tracer global("глобальный");

void visit() {
    static Tracer counter("статический");
    Tracer local("локальный");
}

int main() {
    std::println("начало main");
    Tracer a("a");
    {
        Tracer b("b");
    }
    visit();
    visit();
    Tracer *p = new Tracer("в куче");
    delete p;
    std::println("конец main");
    return 0;
}
```

Вывод:

```text
+глобальный
начало main
+a
+b
-b
+статический
+локальный
-локальный
+локальный
-локальный
+в куче
-в куче
конец main
-a
-статический
-глобальный
```

Прочитайте вывод сверху вниз:

- глобальный объект создаётся **до** `main`;
- `b` умирает на закрывающей скобке своего блока, `a` — в конце `main`;
- статический объект функции создаётся при **первом** вызове `visit`, и только один раз, а локальный — при каждом вызове;
- объект в куче живёт ровно от `new` до `delete`;
- статические объекты уничтожаются после `main` в порядке, **обратном** созданию.

## Временные объекты

Выражение может создать **временный объект** — значение без имени: результат функции, возвращающей объект, или `std::string("…")`. Временный объект умирает в конце **полного выражения** — на точке с запятой:

```cpp
#include <print>
#include <string>
#include <utility>

struct Tracer {
    std::string name;
    explicit Tracer(std::string n) : name(std::move(n)) {
        std::println("+{}", name);
    }
    ~Tracer() {
        std::println("-{}", name);
    }
};

Tracer make(const char *name) {
    return Tracer(name);
}

int main() {
    make("t1");
    std::println("после t1");
    const Tracer &kept = make("t2");
    std::println("после t2: {}", kept.name);
    return 0;
}
```

Вывод:

```text
+t1
-t1
после t1
+t2
после t2: t2
-t2
```

Временный `t1` умер сразу. А `t2` привязан к локальной константной ссылке, и это **продлевает** его жизнь до конца области видимости ссылки. Обратите внимание: каждый объект создан один раз, хотя `make` «возвращает копию». С C++17 возврат временного объекта гарантированно не копирует его: объект сразу строится там, куда возвращается.

## Висячая ссылка

Продление жизни работает только при **прямой** привязке временного объекта к ссылке. Если ссылка получена через функцию или метод, временный объект умирает как обычно, а ссылка остаётся — **висячая**:

```cpp
#include <print>
#include <sstream>
#include <string>
#include <vector>

std::vector<std::string> split(const std::string &line) {
    std::istringstream in(line);
    std::vector<std::string> words;
    std::string w;
    while (in >> w) {
        words.push_back(w);
    }
    return words;
}

int main() {
    const std::string &first = split("первое слово и остальные").front();
    std::println("{}", first); // Ошибка памяти
    return 0;
}
```

`front()` возвращает ссылку на элемент временного вектора. На точке с запятой вектор уничтожается вместе со строками, и `first` ссылается на освобождённую память. AddressSanitizer сообщает `heap-use-after-free`. Исправление — хранить значение, а не ссылку: `const std::string first = split(…).front();` или сначала сохранить вектор.

<Tip title="C++23: временные объекты в цикле for">

До C++23 та же ловушка была в цикле `for (const auto &x : make().items())`: временный объект `make()` умирал до начала цикла, а `items()` возвращал ссылку внутрь него. В C++23 временные объекты в заголовке цикла живут до конца цикла. Clang 19 уже следует новому правилу, GCC — начиная с 15-й версии; в GCC 14 из песочницы курса такой цикл всё ещё читает освобождённую память. Пока поддержка неполная, не полагайтесь на неё.

</Tip>

<Concept title="Время жизни объекта">

Время жизни — от завершения конструктора до начала деструктора. Вид хранения задаёт его длину: автоматические объекты живут до конца блока, статические — до завершения программы (статические переменные функций создаются при первом вызове), динамические — от `new` до `delete`, потоковые — до конца потока. Статические и автоматические объекты уничтожаются в порядке, обратном созданию. Временный объект умирает в конце полного выражения; прямая привязка к константной ссылке продлевает его жизнь, ссылка, полученная через функцию, — нет.

</Concept>

## Частые ошибки

<CommonMistake title="Ссылка на часть временного объекта">

`const auto &x = make().field_ref();` — объект умирает на точке с запятой, ссылка повисает. Если результат нужен дальше, сохраните **значение** или сначала сам объект.

</CommonMistake>

<CommonMistake title="Возврат ссылки на локальную переменную">

`const std::string &f() { std::string s = "…"; return s; }` — `s` умирает при выходе из функции. Компилятор предупреждает; возвращайте значение — копирования не будет.

</CommonMistake>

<CommonMistake title="«Объект вышел из видимости — значит, удалён»">

Указатель на объект из кучи может выйти из области видимости, а объект останется жить — это утечка. Время жизни динамического объекта не связано с именами, пока им не управляет владелец.

</CommonMistake>

## Итоги

- Время жизни — свойство объекта во время работы, область видимости — свойство имени в тексте программы.
- Автоматические объекты умирают в конце блока, статические — после `main`, динамические — при `delete`.
- Статическая переменная функции создаётся при первом вызове и живёт до конца программы.
- Объекты одного вида уничтожаются в порядке, обратном созданию.
- Временный объект живёт до конца полного выражения; продлить его жизнь может только прямая привязка к ссылке.
