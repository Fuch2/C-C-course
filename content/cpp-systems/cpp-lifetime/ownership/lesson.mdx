## Кто отвечает за ресурс

У каждого ресурса должен быть **владелец** — объект, который отвечает за его освобождение. Все остальные, кто пользуется ресурсом, — **заёмщики**: они читают или меняют его, но не освобождают и не решают, сколько он живёт. Почти все ошибки управления памятью — это путаница в этих ролях: два владельца (двойное освобождение), ни одного владельца (утечка), заёмщик пережил владельца (висячая ссылка).

В C++ роли выражаются **типами**. Глядя на объявление, читатель должен понимать, кто владеет:

| Владеют                                    | Заимствуют                                     |
| ------------------------------------------ | ---------------------------------------------- |
| значения: `std::string`, `Book`            | ссылки: `const Book &`, `Book &`               |
| контейнеры: `std::vector<Book>`            | сырые указатели: `const Book *`, `Book *`      |
| `std::unique_ptr<T>`, `std::shared_ptr<T>` | представления: `std::string_view`, `std::span` |

Современное правило (C++ Core Guidelines, R.3): **сырой указатель никогда не владеет**. Если функция получила `T *`, она не вызывает `delete`. Указатель — заёмщик, который может быть пустым; ссылка — заёмщик, который пустым быть не может.

## Владелец и заёмщики

```cpp
#include <print>
#include <span>
#include <string>
#include <string_view>
#include <vector>

struct Book {
    std::string title;
    int year;
};

// Заимствует весь набор книг на время вызова, возвращает заимствованный указатель.
const Book *oldest(std::span<const Book> books) {
    const Book *best = nullptr;
    for (const Book &b : books) {
        if (best == nullptr || b.year < best->year) {
            best = &b;
        }
    }
    return best;
}

// Заимствует строку на время вызова.
bool mentions(const Book &book, std::string_view word) {
    return book.title.contains(word);
}

int main() {
    const std::vector<Book> shelf{{"Дюна", 1965}, {"Солярис", 1961}, {"Пикник на обочине", 1972}};
    if (const Book *b = oldest(shelf)) {
        std::println("старейшая: {} ({})", b->title, b->year);
    }
    std::println("{}", mentions(shelf[2], "обочин"));
    return 0;
}
```

Вывод:

```text
старейшая: Солярис (1961)
true
```

Владелец книг — вектор `shelf` в `main`. `oldest` и `mentions` только заимствуют: принимают `std::span` и ссылку, не копируют книги и ничего не освобождают. Указатель, который вернула `oldest`, тоже заёмщик: он действителен, пока жив `shelf` и пока вектор не перевыделил память.

## Как функция объявляет свои намерения

| Параметр                                              | Смысл                                                    |
| ----------------------------------------------------- | -------------------------------------------------------- |
| `const T &`, `std::string_view`, `std::span<const T>` | читаю на время вызова                                    |
| `T &`, `std::span<T>`                                 | меняю на время вызова                                    |
| `const T *`, `T *`                                    | заимствую, но объекта может не быть (`nullptr`)          |
| `T` (по значению)                                     | беру свою копию или забираю владение (через `std::move`) |
| `std::unique_ptr<T>` по значению                      | забираю единоличное владение объектом в куче             |

Возврат подчиняется тем же правилам: функция, возвращающая ссылку, `string_view` или указатель, **одалживает** то, что принадлежит кому-то другому, — и этот кто-то должен пережить результат.

## Заёмщик пережил владельца

Самая частая ошибка с заёмщиками — представление на временную строку:

```cpp
#include <print>
#include <string>
#include <string_view>

std::string make_title(int n) {
    return "Глава номер " + std::to_string(n) + ": начало пути";
}

int main() {
    const std::string_view title = make_title(1);
    std::println("{}", title); // Ошибка памяти
    return 0;
}
```

`make_title` вернула временную строку — владельца символов. `string_view` лишь указывает на них, а не продлевает жизнь временного объекта. На точке с запятой строка уничтожена, и `title` смотрит в освобождённую память: `heap-use-after-free`. Правило: в переменной храните **владельца** (`std::string`), а `string_view` используйте для параметров и коротких локальных вычислений над строкой, которая точно жива.

<Concept title="Владение и заимствование">

У ресурса один владелец, который его освобождает; заёмщики пользуются ресурсом, не управляя временем его жизни. Владеют значения, контейнеры и умные указатели; заимствуют ссылки, сырые указатели, `std::string_view` и `std::span`. Сырой указатель не владеет. Параметр по константной ссылке или представлению — чтение на время вызова, по значению — своя копия или передача владения. Заёмщик не должен пережить владельца.

</Concept>

## Частые ошибки

<CommonMistake title="string_view или span на временный объект">

`std::string_view v = make_string();` и `std::span<const int> s = make_vector();` повисают сразу. Сохраняйте владельца, а представление создавайте из него.

</CommonMistake>

<CommonMistake title="delete для полученного указателя">

Функция, получившая `T *`, не знает, как и кем создан объект, — он может лежать на стеке или в векторе. Освобождает только владелец.

</CommonMistake>

<CommonMistake title="Указатель на элемент растущего вектора">

`const Book *b = &shelf[0]; shelf.push_back(…);` — вектор переехал, указатель висит. Заимствуйте элементы, только пока контейнер не меняется.

</CommonMistake>

## Практика

1. **Библиотека** — владелец и функции-заёмщики.
2. **Разбор без копий** — `string_view` на части строки-владельца.
3. **Найди ошибку: реестр имён** — представления на временные строки.
4. **Дерево владения** — моделирование владельцев и висячих ссылок.

## Итоги

- У каждого ресурса один владелец; заёмщики пользуются им, не управляя временем жизни.
- Владеют значения, контейнеры и умные указатели; заимствуют ссылки, сырые указатели, `string_view` и `span`.
- Сырой указатель не владеет и не освобождается заёмщиком.
- Параметры и возвращаемые типы сообщают намерения: читать, менять, забрать владение.
- Заёмщик не может пережить владельца — иначе висячая ссылка.
