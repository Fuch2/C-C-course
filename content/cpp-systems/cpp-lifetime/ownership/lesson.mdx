## Цели обучения

- Называть владельца и заёмщика для каждого адреса в программе.
- Проследить на MemoryDiagram, что заимствование не меняет владельца.
- Диагностировать нарушение договора заимствования и исправить интерфейс на const T&amp;.

## Модель и назначение

Владелец отвечает за прекращение использования и освобождение ресурса; заёмщик получает временный доступ и не освобождает ничего. Один адрес может находиться у многих наблюдателей, но количество копий адреса не определяет количество владельцев: владелец ровно тот, кто обязан освободить ресурс. Современный C++ выражает роли типами параметров: const T&amp; — чтение заимствованного объекта, T&amp; — изменяемое заимствование, unique_ptr&lt;T> по значению — передача исключительного владения, shared_ptr&lt;T> по значению — вступление в совместное владение.

## Механика и гарантии

Сырой T\* не сообщает, кто вызывает delete: для чужого API это нужно выяснять по контракту — получен указатель из new, malloc, библиотечной create-функции или это адрес поля. Функция inspect не должна удалять переданный объект только потому, что получила указатель; функция, сохраняющая адрес «на потом», обязана согласовать срок заимствования с временем жизни владельца. Не принимайте shared_ptr только для синхронного чтения: это навязывает клиенту способ хранения и атомарную работу со счётчиком там, где достаточно const T&amp;.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int describe(const std::string& s) { return static_cast<int>(s.size()); }
int main() { auto name = std::make_unique<std::string>("sensor"); std::cout << describe(*name) << " " << *name << "\n"; }
```

Ожидаемый вывод:

```text
6 sensor
```

## Разбор и эксперимент

Сравните inspect(const int&amp;) и consume(std::unique_ptr&lt;int>): в первом случае объект остаётся у владельца, во втором исходный unique_ptr после вызова пуст. Вызов consume(std::move(owner)) делает передачу видимой в коде клиента.

### Четыре вопроса к каждому интерфейсу

Для любой функции, принимающей указатель или ссылку, ответьте: (1) может ли она изменить объект; (2) может ли сохранить доступ после возврата; (3) принимает ли ответственность за освобождение; (4) допустимо ли отсутствие объекта (null). Ответы и есть договор владения.

Современный C++ позволяет выразить три из четырёх ответов типами. const T&amp; — «читаю, не сохраняю, не освобождаю». T&amp; — «изменяю, не сохраняю, не освобождаю». unique_ptr&lt;T> по значению — «принимаю исключительное владение; клиент обязан написать std::move». shared_ptr&lt;T> по значению — «становлюсь совладельцем». Остаётся лишь вопрос про null, который решается документированием или std::optional.

Сырой T\* в новом коде должен означать ровно одно: заимствование без передачи владения и без обязательства освобождать. Как только функция начинает хранить указатель «на потом», сырой тип теряет смысл — нужен владелец с явным сроком жизни.

<CommonMistake title="Граница корректности">

Договор «удалит кто-нибудь из вызывающих» допускает и утечку, и повторное удаление. Передача сырого адреса сама по себе владение не передаёт.

</CommonMistake>
