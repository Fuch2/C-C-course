## Цели обучения

- Отличать сборку по достижимости от подсчёта ссылок на примере цикла.
- Проследить на MemoryDiagram, почему счётчики цикла никогда не обнуляются.
- Диагностировать цикл сильного владения и разорвать его слабым обратным ребром.

## Модель и назначение

Подсчёт ссылок не является сборщиком мусора по достижимости: он удаляет объект при обнулении счётчика, а не при потере доступности из корней. Если A сильно владеет B, а B сильно владеет A, после исчезновения внешних владельцев оба счётчика остаются положительными. Объекты недостижимы для программы, но их деструкторы не запускаются. Разорвать цикл в деструкторе нельзя — до деструктора не доходит исполнение.

## Механика и гарантии

Нарисуйте ориентированный граф владения отдельно от графа доступа. В дереве родитель владеет детьми через shared_ptr, а ребёнок наблюдает родителя через weak_ptr. Для общего графа выберите внешний реестр владельцев с невладеющими рёбрами или явный протокол teardown. Циклы прячутся и в замыканиях: объект хранит std::function, а лямбда захватила shared_ptr на этот же объект — граф владения объект → callback → объект. Не заменяйте все рёбра на weak без модели владения: узлы начнут исчезать слишком рано.

<MemoryDiagram title="Время жизни и связи владения">

```text

сильных у каждого: 1 → деструкторы не выполняются → утечка
```

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Node { std::shared_ptr<Node> child; std::weak_ptr<Node> parent; };
int main() { std::weak_ptr<Node> observer; { auto root = std::make_shared<Node>(); auto leaf = std::make_shared<Node>(); root->child = leaf; leaf->parent = root; observer = root; } std::cout << (observer.expired() ? 1 : 0) << "\n"; }
```

Ожидаемый вывод:

```text
1
```

## Разбор и эксперимент

В практике счётчик живых узлов должен вернуться к нулю после блока. Внешние weak-наблюдатели помогают проверить это, не удерживая узлы сами. Добавьте третий узел и определите, какие рёбра должны быть слабыми.

### Подсчёт ссылок не находит недостижимое

Сборщик по достижимости удаляет объекты, до которых нельзя дойти из корней. Подсчёт ссылок удаляет объект, когда его счётчик обнулился. Цикл A → B → A держит оба счётчика положительными после исчезновения внешних владельцев: объекты недостижимы из программы, но «живы» для счётчиков. Деструкторы не выполняются, память не возвращается. Разорвать цикл в деструкторе невозможно — до деструктора не доходит исполнение.

Лечение — асимметрия рёбер. Выберите направление владения (родитель владеет потомком, владелец владеет зависимым) и сделайте его сильным; обратное ребро объявите наблюдением через weak_ptr. Альтернативы: внешний реестр владельцев с невладеющими рёбрами или явный протокол teardown, вызываемый до выхода из области.

Циклы прячутся не только в полях parent/child. std::function с захваченным shared_ptr на владельца, observer-списки, кеш «объект → свой же обработчик» — рисуйте граф владения для замыканий так же, как для полей. Замена всех рёбер на weak без модели владения — другая крайность: узлы начнут умирать слишком рано.

<CommonMistake title="Граница корректности">

Успешный stdout не доказывает отсутствие удержания: цикл проявляется только исчезновением деструкторов. Тест на утечку обязан завершить все внешние области владения, а наблюдатели в нём должны быть слабыми.

</CommonMistake>
