## Когда счётчик никогда не обнулится

Подсчёт ссылок удаляет объект, когда исчезает последний владелец. Но если два объекта владеют **друг другом**, каждый из них — владелец другого, и счётчики никогда не дойдут до нуля, даже когда снаружи на них никто не ссылается. Это **цикл владения** — утечка, которую `shared_ptr` не может обнаружить.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Person {
    std::string name;
    std::shared_ptr<Person> partner;
    explicit Person(std::string n) : name(std::move(n)) {}
    ~Person() {
        std::println("удалён {}", name);
    }
};

int main() {
    auto ada = std::make_shared<Person>("Ада");
    auto alan = std::make_shared<Person>("Алан");
    ada->partner = alan;
    alan->partner = ada;
    std::println("владельцев Ады: {}", ada.use_count());
    return 0; // Ошибка памяти
}
```

При выходе из `main` локальные `ada` и `alan` уничтожаются, счётчики падают с 2 до 1 — и останавливаются: Аду держит поле `alan->partner`, Алана — поле `ada->partner`. Деструкторы не вызываются, «удалён» не печатается, а LeakSanitizer при завершении сообщает об утечке двух объектов.

<MemoryDiagram title="Цикл владения">

```text
ada (локальная) ──▶ [Ада]  partner ──────▶ [Алан] ◀── alan (локальная)
                      ▲                       │
                      └──────── partner ──────┘
после выхода из main: локальных указателей нет,
но каждый объект держит другого: счётчики 1 и 1 — навсегда
```

</MemoryDiagram>

## Разорвать цикл

В любом цикле должна быть хотя бы одна **невладеющая** связь. Какую выбрать, подсказывает предметная область: кто кого на самом деле должен держать в живых?

| Структура                   | Владеющая связь           | Невладеющая связь                                  |
| --------------------------- | ------------------------- | -------------------------------------------------- |
| пара равноправных партнёров | внешний владелец (реестр) | `weak_ptr` друг на друга                           |
| дерево                      | родитель → дети           | ребёнок → родитель: `weak_ptr` или сырой указатель |
| двусвязный список           | `next`                    | `prev`: `weak_ptr` или сырой указатель             |
| граф с циклами              | граф владеет всеми узлами | рёбра: сырые указатели или индексы                 |
| объект и его колбэк         | объект владеет колбэком   | колбэк захватывает `weak_ptr` на объект            |

С `weak_ptr` партнёры больше не продлевают друг другу жизнь:

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Person {
    std::string name;
    std::weak_ptr<Person> partner;
    explicit Person(std::string n) : name(std::move(n)) {}
    ~Person() {
        std::println("удалён {}", name);
    }
};

int main() {
    auto ada = std::make_shared<Person>("Ада");
    auto alan = std::make_shared<Person>("Алан");
    ada->partner = alan;
    alan->partner = ada;
    if (auto p = ada->partner.lock()) {
        std::println("партнёр Ады: {}", p->name);
    }
    std::println("владельцев Ады: {}", ada.use_count());
    return 0;
}
```

Вывод:

```text
партнёр Ады: Алан
владельцев Ады: 1
удалён Алан
удалён Ада
```

## Цикл через лямбду

Современный и коварный вариант цикла — объект хранит колбэк, а колбэк захватывает `shared_ptr` на тот же объект. Так часто пишут обработчики событий и асинхронный код: `[self = shared_from_this()] { … }`. Если колбэк хранится в самом объекте (или в том, чем объект владеет), объект держит лямбду, а лямбда держит объект.

Лечение — захватить слабую ссылку и заблокировать её при вызове:

```cpp
#include <functional>
#include <memory>
#include <print>
#include <string>
#include <utility>

class Button : public std::enable_shared_from_this<Button> {
public:
    explicit Button(std::string label) : label_(std::move(label)) {}
    ~Button() {
        std::println("удалена кнопка {}", label_);
    }

    void wire() {
        on_click_ = [weak = weak_from_this()] {
            if (auto self = weak.lock()) {
                std::println("нажата {}", self->label_);
            }
        };
    }

    void click() const {
        on_click_();
    }

private:
    std::string label_;
    std::function<void()> on_click_;
};

int main() {
    auto ok = std::make_shared<Button>("OK");
    ok->wire();
    ok->click();
    return 0;
}
```

Вывод:

```text
нажата OK
удалена кнопка OK
```

С захватом `[self = shared_from_this()]` кнопка никогда бы не удалилась.

<Concept title="Циклические ссылки">

Цикл из владеющих `shared_ptr` никогда не освобождается: каждый объект держит следующего, и счётчики не доходят до нуля. В каждом цикле одна связь должна быть невладеющей — `weak_ptr`, сырой указатель или индекс, — и выбирают её по смыслу: дети не владеют родителем, `prev` не владеет списком, колбэк не владеет объектом. Колбэки, хранящиеся в объекте, захватывают `weak_from_this()`, а не `shared_from_this()`. LeakSanitizer находит такие утечки при завершении программы.

</Concept>

## Частые ошибки

<CommonMistake title="shared_ptr в обе стороны">

Родитель ↔ ребёнок, `next` ↔ `prev`, партнёр ↔ партнёр через `shared_ptr` — гарантированная утечка. Одно направление — `weak_ptr` или сырой указатель.

</CommonMistake>

<CommonMistake title="[self = shared_from_this()] в хранимом колбэке">

Объект держит колбэк, колбэк держит объект. Захватывайте `weak_from_this()` и проверяйте `lock()` внутри.

</CommonMistake>

<CommonMistake title="«Разрыв» цикла вручную перед выходом">

`ada->partner.reset()` перед `return` спасает только этот путь выполнения. Исключение или ранний выход вернут утечку. Чините структуру связей, а не отдельные места.

</CommonMistake>

## Практика

1. **Партнёры** — равноправная связь через `weak_ptr`.
2. **Двусвязный список** — `next` владеет, `prev` наблюдает.
3. **Найди ошибку: вечная сессия** — колбэк захватывает `shared_from_this()`.
4. **Сборщик циклов** — почему подсчёт ссылок не видит циклы и как их находит обход от корней.

## Итоги

- Объекты, владеющие друг другом через `shared_ptr`, никогда не освобождаются.
- В каждом цикле одна связь должна быть невладеющей: `weak_ptr`, сырой указатель или индекс.
- Направление владения подсказывает предметная область: родитель → дети, `next` → следующий, объект → колбэк.
- Хранимые колбэки захватывают `weak_from_this()`.
- LeakSanitizer показывает утечки из-за циклов при завершении программы.
