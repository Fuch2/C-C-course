## Зачем копировать то, что сейчас умрёт

Копия владельца ресурса стоит дорого: глубокая копия вектора из миллиона чисел — миллион чисел, скопированных в новый буфер. Но часто источник после копирования **никому не нужен**: это временный объект, который умрёт на точке с запятой, или локальная переменная, которую возвращают из функции. Копировать её данные, чтобы сразу же уничтожить оригинал, — пустая работа.

**Перемещение** (C++11) решает это: новый объект **забирает** ресурсы источника вместо того, чтобы их копировать. Для вектора это значит забрать указатель на буфер, размер и ёмкость — три числа вместо миллиона. Источник остаётся пустым, но **корректным** объектом: его можно уничтожить или присвоить ему новое значение.

```cpp
#include <print>
#include <utility>
#include <vector>

int main() {
    std::vector<int> big(1'000'000, 7);
    const int *buffer = big.data();
    std::vector<int> owner = std::move(big);
    std::println("{} {}", owner.data() == buffer, owner.size());
    big = {1, 2, 3};
    std::println("{}", big.size());
    return 0;
}
```

Вывод:

```text
true 1000000
3
```

`owner` получил **тот же самый** буфер, что был у `big`: ни один элемент не скопирован. После перемещения `big` можно снова использовать, присвоив ему новое значение.

<MemoryDiagram title="Копирование и перемещение вектора">

```text
копирование:   big   ──▶ [7 7 7 … 7]          owner ──▶ [7 7 7 … 7]   новый буфер, n копий
перемещение:   big   ──▶ ∅ (пусто)            owner ──▶ [7 7 7 … 7]   тот же буфер, O(1)
```

</MemoryDiagram>

## Когда объект перемещается

Перемещение выбирается для значений, которые больше не понадобятся:

| Источник                           | Пример                                                   |
| ---------------------------------- | -------------------------------------------------------- |
| временный объект                   | `v.push_back(std::string("текст"));`                     |
| локальная переменная в `return`    | `return result;` — перемещается или вообще не копируется |
| явное разрешение через `std::move` | `v.push_back(std::move(name));`                          |

Проследим за объектом, который сообщает о копиях и перемещениях:

```cpp
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Tracker {
    std::string name;

    explicit Tracker(std::string n) : name(std::move(n)) {}
    Tracker(const Tracker &other) : name(other.name) {
        std::println("копия {}", name);
    }
    Tracker(Tracker &&other) noexcept : name(std::move(other.name)) {
        std::println("перемещение {}", name);
    }
};

Tracker make(std::string n) {
    Tracker local(std::move(n));
    return local;
}

int main() {
    Tracker a("a");
    const Tracker b = a;
    const Tracker c = std::move(a);
    std::vector<Tracker> v;
    v.reserve(3);
    v.push_back(b);
    v.push_back(Tracker("t"));
    const Tracker d = make("m");
    std::println("готово: {} {}", c.name, d.name);
    return 0;
}
```

Вывод при сборке GCC и Clang:

```text
копия a
перемещение a
копия a
перемещение t
готово: a m
```

`b` — копия, потому что `a` ещё нужна. `c` забирает содержимое `a` — разрешение дал `std::move`. Временный `Tracker("t")` перемещается в вектор автоматически. А `make` не вызывает ни копирования, ни перемещения: компиляторы строят `local` прямо на месте `d` (это необязательная оптимизация NRVO; если её нет, `return local` всё равно **перемещает**, а не копирует).

## Перемещаемые, но не копируемые

Некоторые ресурсы нельзя копировать, но можно передавать: `std::unique_ptr` (единственный владелец объекта), `std::jthread` (поток), `std::ifstream` (открытый файл). Для них перемещение — единственный способ отдать владение: из функции, в контейнер, в поле другого объекта.

```cpp
#include <memory>
#include <print>
#include <utility>
#include <vector>

std::unique_ptr<int> make_value(int v) {
    return std::make_unique<int>(v);
}

int main() {
    std::vector<std::unique_ptr<int>> owners;
    owners.push_back(make_value(1));
    auto two = make_value(2);
    owners.push_back(std::move(two));
    std::println("{} {} {}", owners.size(), *owners[1], two == nullptr);
    return 0;
}
```

Вывод:

```text
2 2 true
```

`owners.push_back(two)` без `std::move` не скомпилируется: копировать `unique_ptr` нельзя. После перемещения `two` пуст — для `unique_ptr` это гарантировано стандартом.

<Important title="Состояние после перемещения">

Объект, из которого переместили, находится в **корректном, но неопределённом** состоянии: его можно уничтожить, присвоить ему новое значение или вызвать методы без предусловий (`clear()`, `empty()`). Полагаться на его содержимое нельзя — кроме типов, которые явно это гарантируют, как `std::unique_ptr` (становится пустым).

</Important>

<Concept title="Семантика перемещения">

Перемещение передаёт ресурсы от объекта, который больше не нужен, вместо копирования: новый владелец забирает указатель, источник остаётся корректным, но пустым или неопределённым. Перемещаются временные объекты, локальные переменные в `return` и всё, что передано через `std::move`. Для владельцев памяти перемещение стоит O(1) вместо O(n). Некопируемые ресурсы — `unique_ptr`, потоки, файлы — передаются только перемещением.

</Concept>

## Частые ошибки

<CommonMistake title="Использование объекта после перемещения">

`names.push_back(std::move(name)); std::println("{}", name);` — содержимое `name` больше не определено. Используйте значение до перемещения или не перемещайте.

</CommonMistake>

<CommonMistake title="std::move в return локальной переменной">

`return std::move(local);` мешает компилятору построить объект на месте результата (NRVO) и не даёт выигрыша. Пишите просто `return local;`.

</CommonMistake>

<CommonMistake title="Перемещение из const">

`std::move` от константного объекта даёт константную rvalue-ссылку, и выбирается **копирование**: из константы ничего забрать нельзя. Компилятор не предупреждает.

</CommonMistake>

## Практика

1. **Склад коробок** — когда объект копируется, а когда перемещается.
2. **Очередь задач** — передача задач без копирования.
3. **Найди ошибку: пропавшее имя** — использование объекта после перемещения.
4. **Обмен без копий** — алгоритмы, которые только перемещают.

## Итоги

- Перемещение забирает ресурсы у объекта, который больше не нужен, вместо копирования.
- Временные объекты и локальные переменные в `return` перемещаются автоматически; остальное — через `std::move`.
- Для вектора и строки перемещение — O(1): передаётся указатель на буфер.
- Некопируемые ресурсы (`unique_ptr`, потоки, файлы) передаются только перемещением.
- После перемещения объект корректен, но его содержимое не определено.
