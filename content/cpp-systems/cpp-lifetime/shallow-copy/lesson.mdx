## Копируется адрес, а не объект

Неявное копирование копирует поля по очереди. Для поля-указателя «скопировать» значит скопировать **адрес**: обе копии будут указывать на один и тот же объект. Такое копирование называют **поверхностным** (shallow copy).

Само по себе это не ошибка. Если указатель — заёмщик, поверхностная копия — именно то, что нужно: два наблюдателя одного счёта должны видеть одни и те же деньги.

```cpp
#include <print>

struct Account {
    long long balance = 0;
};

struct View {
    const Account *account;
    long long shown() const {
        return account->balance;
    }
};

int main() {
    Account acc;
    const View a{&acc};
    const View b = a;
    acc.balance = 500;
    std::println("{} {}", a.shown(), b.shown());
    return 0;
}
```

Вывод:

```text
500 500
```

Обе копии `View` смотрят на один `Account`, которым владеет `main`. Копия наблюдателя — ещё один наблюдатель.

## Когда поверхностная копия — катастрофа

Всё меняется, если указатель **владеет**: класс сам выделил объект и удаляет его в деструкторе. После поверхностной копии у одного блока памяти два владельца, и каждый уверен, что должен его освободить:

```cpp
#include <print>

class Box {
public:
    explicit Box(int value) : value_(new int(value)) {}
    ~Box() {
        delete value_;
    }

    int get() const {
        return *value_;
    }

private:
    int *value_;
};

void show(Box box) {
    std::println("{}", box.get());
}

int main() {
    const Box a(7);
    show(a); // Ошибка памяти
    return 0;
}
```

Передача по значению создала копию `box` — с тем же адресом. При выходе из `show` деструктор копии удалил `int`. В конце `main` деструктор `a` удаляет его **второй раз**: AddressSanitizer сообщает `attempting double-free`. А если между этими моментами обратиться к `a.get()`, получится `heap-use-after-free`.

<MemoryDiagram title="Два владельца одного блока">

```text
до копии:            a.value_ ──▶ [ 7 ]
после копии:         a.value_ ──▶ [ 7 ] ◀── box.value_     одно new, два delete
выход из show:       ~box: delete         a.value_ ──▶ [ ✗ ]  висит
конец main:          ~a:   delete ещё раз → double free
```

</MemoryDiagram>

Опаснее всего то, что программа **компилируется без предупреждений**, а иногда и «работает»: двойное освобождение — неопределённое поведение, оно может проявиться через тысячи строк в совсем другом месте.

## Диагноз и лечение

Правило диагностики: посчитайте, сколько раз выполняется `new` и сколько объектов считают себя вправе сделать `delete`. Одно выделение и два права на освобождение — ошибка. Лечение зависит от того, что должен означать тип:

| Смысл типа                    | Решение                                                         |
| ----------------------------- | --------------------------------------------------------------- |
| наблюдатель, не владеет       | не удалять в деструкторе; поверхностная копия правильна         |
| самостоятельное значение      | **глубокая копия**: копия выделяет свой объект (следующий урок) |
| единственный владелец ресурса | запретить копирование (`= delete`), разрешить перемещение       |
| владение по-настоящему общее  | `std::shared_ptr` со счётчиком владельцев                       |

А лучше всего — не держать владеющий сырой указатель вовсе. Поле `int value_` или `std::vector<int>` копируется правильно само. Поле `std::unique_ptr<int>` запрещает неявное копирование — и ошибка выше превращается в **ошибку компиляции** в строке `show(a)`.

<Concept title="Поверхностное копирование">

Неявное копирование указателя копирует адрес: копии ссылаются на один объект. Для указателя-заёмщика это правильно. Для указателя-владельца это создаёт двух владельцев одного блока: первый деструктор освобождает его, второй — ещё раз (double free), а между ними оригинал висит (use-after-free). Лечение: глубокая копия, запрет копирования, общее владение через `std::shared_ptr` — или поле, которое само умеет копироваться либо запрещает копирование.

</Concept>

## Частые ошибки

<CommonMistake title="Владеющий сырой указатель без своего копирования">

Класс с `new` в конструкторе и `delete` в деструкторе, но без конструктора копирования и присваивания — бомба замедленного действия. Первая же передача по значению создаст двух владельцев.

</CommonMistake>

<CommonMistake title="Лечение симптома">

Обнулить указатель в одной копии или убрать `delete` из деструктора — значит превратить двойное освобождение в утечку. Нужно решить, что означает копирование типа, а не прятать последствия.

</CommonMistake>

<CommonMistake title="Ожидание независимой копии от поверхностной">

Копия объекта с указателем на общие данные меняет оригинал: `b.style->font = 20` меняет и стиль `a`. Если копии должны быть независимы, нужна глубокая копия.

</CommonMistake>

2. Добавьте в `Box` строки `Box(const Box &) = delete;` и `Box &operator=(const Box &) = delete;`. Что скажет компилятор о `show(a)`?
3. Замените поле `int *value_` на `int value_`. Какие строки класса стали лишними?

## Практика

1. **Наблюдатели счёта** — поверхностная копия как задумано.
2. **Документы и стили** — часть полей копируется глубоко, часть поверхностно.
3. **Найди ошибку: изображение по значению** — двойное освобождение после копии.
4. **Аудит указателей** — моделирование владельцев, двойных освобождений и утечек.

## Итоги

- Неявное копирование поля-указателя копирует адрес — копии ссылаются на один объект.
- Для заёмщиков это правильно, для владельцев — двойное освобождение и висячие указатели.
- Одно `new` и два права на `delete` — главный признак ошибки.
- Лечение: глубокая копия, запрет копирования, `std::shared_ptr` — или поле, которое само копируется правильно.
- `std::unique_ptr` вместо сырого указателя превращает такую ошибку в ошибку компиляции.
