## Цели обучения

- Связать неявное копирование адреса с появлением второго права на освобождение.
- Проследить на MemoryDiagram порядок разрушения двух владельцев одного блока.
- Диагностировать double delete по фрагментам и исправить Box глубокой копией.

## Модель и назначение

Поверхностная копия переносит непосредственные поля: для указателя копируется адрес, а не объект по адресу. Для невладеющего представления это нормально — два View намеренно наблюдают один int. Для класса, чей деструктор удаляет этот int, это катастрофа: после неявного копирования два экземпляра считают один ресурс своим. Первый деструктор освобождает блок, второй пытается освободить его ещё раз — double delete.

## Механика и гарантии

Сначала определите смысл типа, затем способ копирования. Представление — уберите удаление и гарантируйте внешнего владельца. Самостоятельное значение — создавайте глубокую копию. Исключительный владелец — запретите копирование и разрешите перемещение. Обнуление p только в одном экземпляре не лечит вторую копию; удаление одного delete вручную в main оставляет класс ошибочным при другом порядке разрушения. Диагностическая таблица: один new и два права на освобождение — красный флаг; два new и два владельца — корректная глубокая копия; один new, один владелец и несколько заёмщиков — тоже корректно.

<MemoryDiagram title="Время жизни и связи владения">

```text

После неявной копии: a.p → A(7) ← b.p; два права на один блок
~b освобождает A
```

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct View { int* p; };
int main() { int x = 3; View a{&x}; View b = a; x = 11; std::cout << *a.p << " " << *b.p << "\n"; }
```

Ожидаемый вывод:

```text
11 11
```

## Разбор и эксперимент

Для View безопасно изменить объект через владельца и увидеть изменение через обе копии представления. Для владеющего Box ожидается противоположный тест: изменение копии не затрагивает оригинал.

### Копирование байтов копирует адреса

Неявный копирующий конструктор копирует каждое поле его собственной операцией копирования. Для int это число; для сырого указателя — адрес, а не объект по адресу. Один new и два экземпляра, каждый из которых считает ресурс своим, — классический рецепт double delete: первый деструктор освобождает блок, второй пытается освободить его ещё раз.

Диагностическая таблица: посчитайте количество new и количество прав на освобождение. Один new, одно право — корректно (любым из перечисленных способов достигнуто). Один new, два права — double delete. Один new, ноль прав — утечка. Два new, два права — глубокая копия, корректно.

ASan покажет место второго освобождения, но первопричина почти всегда раньше — в строке копирования. Чинить только строку, на которую указал sanitizer, значит лечить симптом: восстановите историю появления второго права на один блок. И помните: удаление деструктора «исправляет» падение ценой утечки — это не исправление, а подмена одного дефекта другим.

<CommonMistake title="Граница корректности">

Нельзя лечить double delete удалением всех деструкторов: вместе с падением исчезает и освобождение ресурса. Исправление должно объяснять единственного владельца либо независимость копий.

</CommonMistake>

## Сначала диагноз, затем исправление

В переключателе практики два обязательных задания. Первое проверяет классификацию четырёх фрагментов. Зафиксируйте причину и границу времени жизни до изменения кода. Второе содержит дефектный исходник: исправьте владение, сохранив требуемое поведение. Код диагноза проверяется автоматически; пояснение в комментарии служит самопроверке. Оба задания нужны для завершения практики.

### Фрагмент 0

```cpp
struct Buf { int* p; explicit Buf(int n):p(new int[n]){} ~Buf(){delete[] p;} };
Buf a(4); Buf b = a;
```

### Фрагмент 1

```cpp
struct Buf { std::vector<int> p; };
Buf a; Buf b = a;
```

### Фрагмент 2

```cpp
struct Pair { int* a; int* b; ~Pair(){delete a; delete b;} };
int* shared = new int(1); Pair p{shared, shared};
```

### Фрагмент 3

```cpp
int* p = new int(3); int* q = p; p = nullptr; delete p; delete q;
```

Исправьте Box с сырым int\* и деструктором: копия должна владеть отдельным int. Добавьте глубокий копирующий конструктор и запретите копирующее присваивание. solve создаёт first(a), во вложенном блоке копию second, меняет её значение на b и сохраняет его; после уничтожения second возвращает сохранённое.
