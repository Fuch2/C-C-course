## Когда объект копируется

**Конструктор копирования** создаёт новый объект как копию существующего того же типа. Он вызывается чаще, чем кажется:

| Ситуация                      | Пример                                             |
| ----------------------------- | -------------------------------------------------- |
| инициализация другим объектом | `Tracker b = a;`, `Tracker b(a);`, `Tracker b{a};` |
| передача по значению          | `void f(Tracker t); f(a);`                         |
| добавление в контейнер        | `v.push_back(a);`                                  |
| захват по значению в лямбду   | `[a] { … }`                                        |

Проверим, подсчитав копии:

```cpp
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Tracker {
    static inline int copies = 0;
    std::string name;

    explicit Tracker(std::string n) : name(std::move(n)) {}
    Tracker(const Tracker &other) : name(other.name + "'") {
        ++copies;
        std::println("копия {}", name);
    }
};

void by_value(Tracker) {}
void by_ref(const Tracker &) {}

Tracker make() {
    return Tracker("m");
}

int main() {
    const Tracker a("a");
    const Tracker b = a;
    by_value(a);
    by_ref(a);
    const Tracker c = make();
    std::vector<Tracker> v;
    v.reserve(1);
    v.push_back(a);
    std::println("копий: {}, у c имя {}", Tracker::copies, c.name);
    return 0;
}
```

Вывод:

```text
копия a'
копия a'
копия a'
копий: 3, у c имя m
```

Три копии: `b`, параметр `by_value` и элемент вектора. `by_ref` копий не делает — ради этого и передают по константной ссылке. А `make()` вернула временный объект, который с C++17 гарантированно строится сразу на месте `c`: это **устранение копии** (copy elision), и конструктор копирования не вызывается вовсе.

## Неявный конструктор копирования

Если вы не объявили конструктор копирования, компилятор создаёт его сам: он копирует базы и поля по очереди, каждое — его собственным конструктором копирования. Для класса из строк, чисел и контейнеров это ровно то, что нужно: копия `std::string` — новая строка, копия `std::vector` — новый вектор с копиями элементов.

```cpp
#include <print>
#include <string>
#include <vector>

struct Playlist {
    std::string title;
    std::vector<std::string> songs;
};

int main() {
    Playlist mine{"Утро", {"Песня 1", "Песня 2"}};
    Playlist yours = mine;
    yours.title = "Вечер";
    yours.songs.push_back("Песня 3");
    std::println("{}: {} | {}: {}", mine.title, mine.songs.size(), yours.title, yours.songs.size());
    return 0;
}
```

Вывод:

```text
Утро: 2 | Вечер: 3
```

Копия независима: изменения `yours` не задевают `mine`. Так ведут себя **типы-значения**, и к этому стоит стремиться: если все поля копируются правильно, писать конструктор копирования не нужно.

<MemoryDiagram title="Независимые копии">

```text
mine                       yours = mine
┌──────────────────┐       ┌──────────────────┐
│ title ─▶ "Утро"  │       │ title ─▶ "Вечер" │   свой буфер
│ songs ─▶ [1][2]  │       │ songs ─▶ [1][2][3]│  свой буфер
└──────────────────┘       └──────────────────┘
каждое поле скопировано своим конструктором копирования — общих данных нет
```

</MemoryDiagram>

## Свой конструктор копирования

Свой конструктор пишут, когда копия должна отличаться от «поле в поле»: получить новый уникальный номер, не копировать кэш, вести журнал. Сигнатура — `T(const T &other)`:

- параметр — **ссылка**: передача по значению сама потребовала бы копии, то есть бесконечной рекурсии;
- **константная**: копирование не меняет оригинал и работает для константных объектов и временных значений.

```cpp
#include <print>
#include <string>
#include <utility>

class Ticket {
public:
    explicit Ticket(std::string event) : id_(next_id_++), event_(std::move(event)) {}
    Ticket(const Ticket &other) : id_(next_id_++), event_(other.event_) {}

    void print() const {
        std::println("билет №{} на «{}»", id_, event_);
    }

private:
    static inline int next_id_ = 1;
    int id_;
    std::string event_;
};

int main() {
    const Ticket a("Концерт");
    const Ticket b = a;
    a.print();
    b.print();
    return 0;
}
```

Вывод:

```text
билет №1 на «Концерт»
билет №2 на «Концерт»
```

Копия билета — билет на то же событие, но с **новым** номером. Обратите внимание: в своём конструкторе копирования нужно явно скопировать **все** поля, которые должны совпадать. Забытое поле получит значение по умолчанию — и компилятор не предупредит.

Явно выбрать поведение компилятора можно и без тела: `Ticket(const Ticket &) = default;` — неявное копирование, `= delete` — копирование запрещено (как у RAII-владельцев из прошлого урока).

<Concept title="Конструктор копирования">

Конструктор копирования `T(const T &)` создаёт новый объект как копию существующего: при инициализации, передаче по значению, добавлении в контейнер, захвате в лямбду. Неявный конструктор копирует базы и поля по очереди — для типов-значений этого достаточно. Свой пишут, когда копия должна отличаться; в нём нужно явно скопировать все нужные поля. `= default` и `= delete` выбирают неявное поведение или запрет. С C++17 инициализация временным значением того же типа не вызывает копирования вовсе.

</Concept>

## Частые ошибки

<CommonMistake title="Забытое поле в своём конструкторе копирования">

Добавили поле в класс — не забудьте конструктор копирования. Если особой логики нет, удалите свой конструктор и положитесь на неявный или `= default`.

</CommonMistake>

<CommonMistake title="Передача тяжёлых объектов по значению без нужды">

`void print(std::vector<std::string> v)` копирует весь вектор на каждый вызов. Если функция только читает — `const std::vector<std::string> &` или `std::span<const std::string>`.

</CommonMistake>

<CommonMistake title="Параметр конструктора копирования по значению">

`T(T other)` — ошибка компиляции: передача по значению сама требует копирования. Только `T(const T &)`.

</CommonMistake>

## Практика

1. **Счётчик копий** — где копирование происходит, а где нет.
2. **Билеты** — копия с новым номером.
3. **Найди ошибку: потерянная тема** — забытое поле в конструкторе копирования.
4. **Родословная копий** — копия, которая помнит, от кого произошла.

## Итоги

- Конструктор копирования вызывается при инициализации объектом того же типа, передаче по значению, вставке в контейнер.
- Передача по константной ссылке копий не делает; инициализация временным значением с C++17 — тоже.
- Неявный конструктор копирует поля по очереди; для типов-значений его достаточно.
- Свой конструктор копирования — `T(const T &)`; в нём копируют все нужные поля явно.
- `= default` и `= delete` явно выбирают поведение копирования.
