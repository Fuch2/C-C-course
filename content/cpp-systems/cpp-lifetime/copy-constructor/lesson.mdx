## Цели обучения

- Отличать инициализацию копированием от присваивания по наличию объекта назначения.
- Проследить на MemoryDiagram создание независимого блока при глубокой копии.
- Реализовать глубоко копирующий конструктор и обосновать запрет присваивания.

## Модель и назначение

Конструктор копирования создаёт новый объект из существующего; стандартная сигнатура — T(const T&amp; other). Запись T b = a является инициализацией: объекта b ещё не было, оператор присваивания не участвует. Для класса без пользовательских правил компилятор копирует базы и поля их собственными операциями: int копирует число, vector — элементы, сырой указатель — только адрес. Поэтому смысл копии определяет не компилятор, а контракт типа.

## Механика и гарантии

У значения (измерение, строка) изменение копии не должно менять оригинал — нужна глубокая копия. У дескриптора общего объекта копия может намеренно разделять состояние. У исключительного владельца копирование запрещают через = delete. В примере Measurement владеет одним int: её копирующий конструктор выделяет новый int и копирует значение. Если выделение бросит, новый объект не создан, а источник не изменён — это сильная гарантия. Присваивание здесь запрещено: хороший конструктор копирования не исправляет автоматически опасный operator=, это отдельная операция.

<MemoryDiagram title="Время жизни и связи владения">

```text
a.value ──> блок A: 10
Measurement b = a: выделить блок B; скопировать 10 в B
b.value ──> блок B: 10
*b.value = 25: блок B хранит 25; блок A остаётся 10
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Measurement { std::unique_ptr<int> value; explicit Measurement(int v): value(std::make_unique<int>(v)) {} Measurement(const Measurement& other): value(std::make_unique<int>(*other.value)) {} Measurement& operator=(const Measurement&) = delete; };
int main() { Measurement a{10}; Measurement b = a; *b.value = 25; std::cout << *a.value << " " << *b.value << "\n"; }
```

Ожидаемый вывод:

```text
10 25
```

## Разбор и эксперимент

После создания копии b измените её значение, затем уничтожьте b во вложенном блоке и прочитайте a. Проверка наблюдает одновременно независимость значений и освобождение разных блоков.

### Инициализация и присваивание — разные операции

T b = a — это инициализация: объекта b ещё не было, работает конструктор копирования. b = a, где b уже существует, — присваивание: работает operator=. Смешение этих двух путей — частый источник ошибок: у класса может быть корректный конструктор копирования и опасное присваивание, и наоборот.

Копирующий конструктор не может иметь сигнатуру T(T other): такой параметр сам требовал бы копирования для передачи, и рекурсия не terminating. Поэтому всегда const T&amp; (или T&amp;, но const покрывает оба случая).

Что должна делать копия — решает семантика типа, а не компилятор. Значение (измерение, строка) — allocate новое содержимое. Дескриптор общего ресурса (shared_ptr) — разделить владение. Исключительный владелец (unique_ptr, файловый Guard) — запретить копирование через = delete. Третий вариант — не «отсутствие функциональности», а честное сообщение типа: «меня нельзя продублировать, можно только переместить».

<CommonMistake title="Граница корректности">

Сигнатура T(T other) невозможна как конструктор копирования: передача параметра сама потребовала бы копирования. Передачу больших объектов только для чтения выполняйте через const T&amp;.

</CommonMistake>
