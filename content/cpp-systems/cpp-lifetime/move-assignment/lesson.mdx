## Цели обучения

- Перечислить три обязательства move-присваивания: очистить, принять, обнулить источник.
- Проследить на MemoryDiagram освобождение прежнего блока назначения.
- Реализовать самоперемещение как безопасный no-op с проверкой адресов.

## Модель и назначение

В target = std::move(source) целевой объект уже существует и может владеть другим ресурсом. Перемещающее присваивание обязано освободить прежнее состояние target, принять состояние source и оставить оба объекта допустимыми. Если просто переписать target.p, старый ресурс утечёт; если не обнулить source, появятся два владельца одного адреса. Это конструктор копирования работает на пустом месте — присваивание всегда имеет дело с живым назначением.

## Механика и гарантии

Для нашего Cell самоперемещение сохраняет значение: проверка this != &amp;other делает операцию безопасным no-op. Это выбранная гарантия класса, а не универсальное обещание всех типов — публикуйте и тестируйте именно свой контракт. Для разных объектов delete p освобождает прежний ресурс, затем exchange забирает адрес источника. Здесь нет выделения и исключений, поэтому noexcept обоснован. Если владелец хранит ещё размер или deleter, переносить нужно согласованное состояние целиком.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Cell { std::unique_ptr<int> p; explicit Cell(int x): p(std::make_unique<int>(x)) {} Cell& operator=(Cell&& x) noexcept { if (this != &x) p = std::move(x.p); return *this; } };
int main() { Cell a{1}, b{6}; a = std::move(b); std::cout << *a.p << " " << (b.p ? 1 : 0) << "\n"; }
```

Ожидаемый вывод:

```text
6 0
```

## Разбор и эксперимент

Проверьте четыре случая: непустой в непустой, непустой в пустой, пустой в непустой и самоперемещение через ссылку-алиас. В последнем случае значение должно сохраниться.

### Назначение уже существует

В target = std::move(source) целевой объект уже жив и, возможно, владеет ресурсом. Перемещающее присваивание обязано: освободить прежнее состояние target, принять состояние source, оставить source допустимым (обычно пустым). Пропуск первого шага — утечка; пропуск третьего — два владельца одного блока.

Самоперемещение x = std::move(x) возможно через ссылку-алиас и должно оставлять объект допустимым. Проверка this != &amp;other превращает его в безопасный no-op; без неё наивная реализация «delete p; p = exchange(other.p, null)» удалит собственный ресурс и запишет null. Другие классы могут выбрать более слабый контракт — «допустимое, но неопределённое состояние»; публикуйте тот, который тестируете.

Исключения: простая передача указателя не бросает, noexcept обоснован. Если же присваивание переносит deleter, размер или вложенные объекты, проверьте каждый шаг. noexcept, нарушенный в середине переноса, оставит оба объекта в разошедшемся состоянии и завершит процесс.

<CommonMistake title="Граница корректности">

Не пишите p = other.p без очистки прежнего ресурса. Проверка только значений не обнаруживает утечку: нужны сценарий непустого назначения и диагностика памяти.
