## Цели обучения

- Объяснить блок управления как источник совместного владения.
- Проследить на MemoryDiagram счётчик сильных владельцев через копии и reset.
- Разделить владение копированием и объяснить, почему конструирование из get() запрещено.

## Модель и назначение

shared_ptr применяют, когда несколько независимых участников должны продлевать жизнь одного объекта и момент последнего использования заранее неизвестен. Копия указателя не копирует объект: участники разделяют владение через блок управления. Когда последний сильный владелец исчезает, управляемый объект уничтожается. Это дороже и сложнее исключительного владения — shared_ptr не является универсальным лекарством от непонятных сроков жизни.

## Механика и гарантии

Новую долю владения получают только копированием существующего shared_ptr. Конструирование двух shared_ptr из одного сырого адреса создаёт независимые блоки управления: каждый удалит объект — double delete. shared_ptr(this) внутри метода — та же ошибка изнутри; для законной выдачи совладения существует enable_shared_from_this. make_shared совмещает выделение объекта и блока управления. const shared_ptr&lt;T> запрещает менять указатель, но не объект; shared_ptr&lt;const T> ограничивает изменение объекта. Атомарен счётчик, а не сам T: доступ к объекту из нескольких потоков требует отдельной синхронизации.

<MemoryDiagram title="Время жизни и связи владения">

second ──> тот же блок

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { auto first = std::make_shared<int>(4); auto second = first; *second += 3; first.reset(); std::cout << *second << " " << second.use_count() << "\n"; }
```

Ожидаемый вывод:

```text
7 1
```

## Разбор и эксперимент

Скопируйте shared_ptr, измените int через второго владельца и прочитайте через первого: это намеренно общее состояние. Сравните с глубокой копией из предыдущих уроков, где значения независимы.

### Совладение — явное архитектурное решение

shared_ptr нужен, когда несколько независимых участников обязаны продлевать жизнь объекта и момент последнего использования заранее неизвестен: кеш с живыми подписчиками, граф с несколькими путями доступа, объект, захваченный несколькими отложенными задачами. Если владелец один — unique_ptr дешевле, проще и строже.

Критическая механика: блок управления. Копирование shared_ptr увеличивает счётчик существующего блока. Конструирование двух shared_ptr из одного сырого адреса создаёт два независимых блока — каждый считает себя единственным владельцем и удалит объект: double delete. Поэтому второе владение получают только копированием первого, а в коде не должно быть записи shared_ptr&lt;T> second(first.get()).

shared_ptr(this) внутри методов — та же ошибка изнутри объекта; для законной выдачи совладения из this существует enable_shared_from_this. И помните про потоки: атомарен счётчик, а не объект. Два потока с одним shared_ptr не дают права менять T без отдельной синхронизации.

<CommonMistake title="Граница корректности">

Нельзя писать shared_ptr&lt;T> second(first.get()) для получения совладельца — копируйте first. И не создавайте shared_ptr(this) для подключения к уже существующему владению.

</CommonMistake>
