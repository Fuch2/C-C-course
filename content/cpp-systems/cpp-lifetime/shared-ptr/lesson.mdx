## Несколько владельцев

Иногда у объекта нет одного естественного владельца: настройки нужны нескольким сервисам, картинка из кэша — нескольким окнам, и неизвестно, кто закончит работу последним. `std::shared_ptr<T>` реализует **совместное владение**: каждая копия указателя — владелец, а объект удаляется, когда уничтожается **последний** из них.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Config {
    std::string name;
    explicit Config(std::string n) : name(std::move(n)) {
        std::println("загружен {}", name);
    }
    ~Config() {
        std::println("выгружен {}", name);
    }
};

int main() {
    auto a = std::make_shared<Config>("prod");
    std::println("владельцев: {}", a.use_count());
    {
        auto b = a;
        std::println("владельцев: {}", a.use_count());
        auto c = std::move(b);
        std::println("владельцев: {}", a.use_count());
    }
    std::println("владельцев: {}", a.use_count());
    a.reset();
    std::println("конец main");
    return 0;
}
```

Вывод:

```text
загружен prod
владельцев: 1
владельцев: 2
владельцев: 2
владельцев: 1
выгружен prod
конец main
```

Копирование `shared_ptr` увеличивает счётчик владельцев, уничтожение и `reset` — уменьшают. Перемещение счётчик не меняет: владелец просто сменил имя. Когда счётчик дошёл до нуля, объект удалён.

## Блок управления

Счётчик хранится не в объекте и не в указателе, а в отдельном **блоке управления** в куче. Каждый `shared_ptr` — это два указателя: на объект и на блок.

<MemoryDiagram title="shared_ptr и блок управления">

```text
a ──┬──────────────────────────▶ [ Config "prod" ]
    └──▶ [ блок управления: владельцев 2, наблюдателей 0, удалитель ]
b ──┬──────────────────────────▶ (тот же объект)
    └──▶ (тот же блок)
make_shared: объект и блок — одно выделение памяти
```

</MemoryDiagram>

Отсюда практические следствия:

- `shared_ptr` вдвое больше сырого указателя, а копирование стоит **атомарного** увеличения счётчика — это заметно в горячих циклах. Передавайте `shared_ptr` по значению, только когда функция действительно становится совладельцем; если она лишь пользуется объектом — `const T &`.
- `std::make_shared` выделяет объект и блок **одним** вызовом — быстрее и компактнее, чем `std::shared_ptr<T>(new T)`.
- Счётчик потокобезопасен, а сам объект — нет: одновременно менять его из разных потоков без синхронизации нельзя. Для атомарной замены самого указателя есть `std::atomic<std::shared_ptr<T>>` (C++20).

## Когда выбирать shared_ptr

По умолчанию — `unique_ptr`. `shared_ptr` нужен, когда время жизни **действительно** определяется несколькими независимыми владельцами. Если «на всякий случай» сделать всё `shared_ptr`, становится непонятно, кто и когда освобождает ресурсы, а циклические ссылки приводят к утечкам (урок о циклах). `unique_ptr` легко превратить в `shared_ptr` позже — присваиванием `std::shared_ptr<T> s = std::move(u);`.

Хороший приём — **общие неизменяемые данные**: `std::shared_ptr<const T>`. Владельцев много, но изменить объект не может никто, поэтому и гонок данных нет.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

class Widget {
public:
    explicit Widget(std::shared_ptr<const std::vector<std::string>> palette) : palette_(std::move(palette)) {}
    const std::string &color(std::size_t i) const {
        return (*palette_)[i % palette_->size()];
    }

private:
    std::shared_ptr<const std::vector<std::string>> palette_;
};

int main() {
    const std::shared_ptr<const std::vector<std::string>> palette =
        std::make_shared<std::vector<std::string>>(std::vector<std::string>{"красный", "синий"});
    const Widget a(palette), b(palette);
    std::println("{} {} владельцев {}", a.color(0), b.color(3), palette.use_count());
    return 0;
}
```

Вывод:

```text
красный синий владельцев 3
```

## Два блока управления — двойное удаление

Блок управления создаётся, когда `shared_ptr` впервые получает сырой указатель. Если сделать это дважды для одного объекта, появятся два независимых счётчика, и каждый в конце удалит объект:

```cpp
#include <memory>

int main() {
    int *raw = new int(5);
    std::shared_ptr<int> a(raw);
    std::shared_ptr<int> b(raw);
    return 0; // Ошибка памяти
}
```

Копируйте существующий `shared_ptr`, а не создавайте новый из сырого указателя. Особый случай — объект, которому нужен `shared_ptr` на **самого себя**: `std::shared_ptr<T>(this)` создаёт второй блок. Для этого класс наследует `std::enable_shared_from_this<T>` и вызывает `shared_from_this()`.

<Concept title="std::shared_ptr">

`std::shared_ptr<T>` — совместное владение: копии увеличивают счётчик в блоке управления, уничтожение уменьшает, объект удаляется вместе с последним владельцем. Создают через `std::make_shared` (одно выделение). Копирование стоит атомарной операции; передавайте `shared_ptr` по значению только новым совладельцам. Счётчик потокобезопасен, объект — нет; `shared_ptr<const T>` даёт безопасные общие данные. Новый `shared_ptr` из сырого указателя, которым уже кто-то владеет, — двойное удаление; на себя — через `enable_shared_from_this`.

</Concept>

## Частые ошибки

<CommonMistake title="shared_ptr по умолчанию">

Совместное владение размывает ответственность и стоит дороже. Начинайте с `unique_ptr` и переходите к `shared_ptr`, когда владельцев действительно несколько.

</CommonMistake>

<CommonMistake title="shared_ptr из get() или this">

`std::shared_ptr<T>(p.get())` и `std::shared_ptr<T>(this)` создают второй блок управления — двойное удаление. Копируйте существующий указатель, для себя — `shared_from_this()`.

</CommonMistake>

<CommonMistake title="const std::shared_ptr<T> & в каждой функции">

Если функции не нужно владение, ей не нужен и `shared_ptr` — достаточно `const T &`. Такая функция работает с любым объектом, а не только с объектами в `shared_ptr`.

</CommonMistake>

## Практика

1. **Общий документ** — несколько редакторов владеют одним документом.
2. **Кэш картинок** — объект живёт, пока им пользуются, даже после удаления из кэша.
3. **Найди ошибку: сессия сама себе владелец** — `shared_ptr(this)` вместо `shared_from_this`.
4. **Копирование при записи** — общие данные до первого изменения.

## Итоги

- `shared_ptr` — совместное владение; объект удаляется вместе с последним владельцем.
- Счётчик живёт в блоке управления; `make_shared` создаёт объект и блок одним выделением.
- Копирование увеличивает счётчик атомарно, перемещение его не меняет.
- По умолчанию выбирайте `unique_ptr`; `shared_ptr<const T>` — для общих неизменяемых данных.
- Не создавайте `shared_ptr` из сырого указателя, которым уже владеют; для `this` — `enable_shared_from_this`.
