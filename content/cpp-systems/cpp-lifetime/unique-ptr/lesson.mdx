## Единственный владелец

`std::unique_ptr<T>` — умный указатель, который **единолично владеет** объектом в куче: удаляет его в своём деструкторе и не позволяет себя копировать. Это RAII для динамической памяти и замена почти каждой паре `new`/`delete` в современном коде.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Doc {
    std::string name;
    explicit Doc(std::string n) : name(std::move(n)) {
        std::println("открыт {}", name);
    }
    ~Doc() {
        std::println("закрыт {}", name);
    }
};

int main() {
    auto a = std::make_unique<Doc>("отчёт");
    std::println("имя: {}", a->name);
    {
        auto b = std::make_unique<Doc>("черновик");
    }
    std::unique_ptr<Doc> c = std::move(a);
    std::println("a пуст: {}", a == nullptr);
    c.reset();
    std::println("конец main");
    return 0;
}
```

Вывод:

```text
открыт отчёт
имя: отчёт
открыт черновик
закрыт черновик
a пуст: true
закрыт отчёт
конец main
```

`b` удалил свой документ на закрывающей скобке. `std::move(a)` передал владение `c`, и `a` стал пустым. `c.reset()` удалил документ раньше конца области. Ни одного `delete` — и ни одной утечки при любом пути выхода.

С функцией удаления по умолчанию `unique_ptr` занимает столько же памяти, сколько обычный указатель, а разыменование стоит столько же. Это абстракция без накладных расходов.

## Основные операции

| Операция                  | Что делает                                                            |
| ------------------------- | --------------------------------------------------------------------- |
| `*p`, `p->x`              | доступ к объекту                                                      |
| `if (p)`, `p == nullptr`  | есть ли объект                                                        |
| `p.get()`                 | сырой указатель для **заимствования** — владение остаётся у `p`       |
| `p.reset()`, `p.reset(q)` | удалить текущий объект (и взять новый)                                |
| `p.release()`             | отказаться от владения и вернуть сырой указатель — удалять теперь вам |
| `std::move(p)`            | передать владение другому `unique_ptr`                                |

`release()` нужен редко — в основном при передаче объекта в старый C-код, который сам его удалит. В обычном коде владение передают перемещением.

## Владение в сигнатурах

Тип параметра сообщает, что функция делает с владением:

| Сигнатура                                 | Смысл                                           |
| ----------------------------------------- | ----------------------------------------------- |
| `void use(const Widget &)` или `Widget *` | пользуюсь объектом, владение не трогаю          |
| `void take(std::unique_ptr<Widget>)`      | забираю владение — вызывающий пишет `std::move` |
| `std::unique_ptr<Widget> make()`          | отдаю владение новым объектом                   |
| `void reseat(std::unique_ptr<Widget> &)`  | могу заменить объект внутри вашего указателя    |

Частая ошибка — принимать `const std::unique_ptr<Widget> &`, когда функции нужен только сам объект. Такая функция не работает с объектами на стеке или в векторе. Передавайте `Widget &` или `Widget *`.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

struct Shape {
    virtual ~Shape() = default;
    virtual double area() const = 0;
};

struct Square final : Shape {
    double side;
    explicit Square(double s) : side(s) {}
    double area() const override {
        return side * side;
    }
};

std::unique_ptr<Shape> make_square(double side) {
    return std::make_unique<Square>(side);
}

void describe(const Shape &s) {
    std::println("площадь {}", s.area());
}

class Canvas {
public:
    void adopt(std::unique_ptr<Shape> shape) {
        shapes_.push_back(std::move(shape));
    }
    std::size_t size() const {
        return shapes_.size();
    }

private:
    std::vector<std::unique_ptr<Shape>> shapes_;
};

int main() {
    Canvas canvas;
    auto sq = make_square(3);
    describe(*sq);
    canvas.adopt(std::move(sq));
    canvas.adopt(make_square(2));
    std::println("на холсте {}, sq пуст: {}", canvas.size(), sq == nullptr);
    return 0;
}
```

Вывод:

```text
площадь 9
на холсте 2, sq пуст: true
```

Фабрика возвращает владение, `describe` только заимствует объект, `adopt` забирает владение — и всё это видно из сигнатур. Вызов `canvas.adopt(sq)` без `std::move` не скомпилируется.

<MemoryDiagram title="Передача владения">

```text
sq ─────────────▶ [Square 3]        main владеет
canvas.adopt(std::move(sq))
sq = nullptr
canvas.shapes_[0] ─▶ [Square 3]      владеет холст; удалит в своём деструкторе
```

</MemoryDiagram>

## Два владельца — ошибка

`unique_ptr` гарантирует единоличное владение, только если объект с самого начала попал к нему один раз. Создать двух «единственных» владельцев из одного сырого указателя — двойное удаление:

```cpp
#include <memory>

int main() {
    int *raw = new int(5);
    std::unique_ptr<int> a(raw);
    std::unique_ptr<int> b(raw);
    return 0; // Ошибка памяти
}
```

Поэтому объекты создают через `std::make_unique` — сырой указатель тогда вообще не появляется в коде, и подобную ошибку не из чего сделать.

<Concept title="std::unique_ptr">

`std::unique_ptr<T>` единолично владеет объектом в куче и удаляет его в деструкторе; копировать его нельзя, перемещать — можно. Создают его через `std::make_unique`. `get()` даёт заимствованный сырой указатель, `reset()` удаляет объект, `release()` отказывается от владения. Функции принимают `unique_ptr` по значению, чтобы забрать владение, и `T &`/`T *`, чтобы только пользоваться объектом. Накладных расходов по сравнению с сырым указателем нет.

</Concept>

## Частые ошибки

<CommonMistake title="Два unique_ptr из одного указателя">

`std::unique_ptr<T> b(a.get());` или два указателя из одного `raw` — двойное удаление. Владение передают только через `std::move`.

</CommonMistake>

<CommonMistake title="release() без delete">

`p.release();` ради «обнуления» — утечка: объект больше никому не принадлежит. Для удаления — `reset()`.

</CommonMistake>

<CommonMistake title="Висячий результат get()">

`Shape *s = p.get(); p.reset();` — `s` указывает на удалённый объект. Заимствованный указатель живёт не дольше владельца.

</CommonMistake>

## Итоги

- `std::unique_ptr` единолично владеет объектом и удаляет его; копировать нельзя, перемещать можно.
- Создавайте объекты через `std::make_unique`; сырой указатель тогда не появляется.
- `get()` — заимствование, `reset()` — удаление, `release()` — отказ от владения.
- Сигнатуры сообщают о владении: `unique_ptr` по значению забирает, `T &` и `T *` только пользуются.
- Два `unique_ptr` для одного объекта — двойное удаление.
