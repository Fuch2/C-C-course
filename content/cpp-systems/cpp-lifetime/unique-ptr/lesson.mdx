## Цели обучения

- Различать get, reset и release по последствию для владения.
- Проследить на MemoryDiagram момент, когда сохранённый адрес становится висячим.
- Диагностировать use-after-free после reset и исправить порядок операций.

## Модель и назначение

unique_ptr&lt;T> хранит исключительное владение объектом и вызывает deleter при разрушении или reset. Копирование запрещено — типом; перемещение передаёт владение. get возвращает заимствованный адрес без передачи права удаления; operator\* и operator-> требуют живого ненулевого объекта; bool проверяет пустоту. Сырой адрес, сохранённый заранее, после reset может стать висячим — unique_ptr не делает безопасными все выданные им указатели.

## Механика и гарантии

release отдаёт адрес и прекращает владение без удаления: если никто не примет ответственность, будет утечка. reset удаляет прежний объект и принимает новый адрес; никогда не вызывайте reset(p.get()) на самом владельце — сначала удалится тот самый объект. Для массивов существует unique_ptr&lt;T[]> с парным delete[]; обычный unique_ptr&lt;T> несовместим с new T[n]. Удаление наследника через unique_ptr&lt;Base> требует виртуального деструктора в Base: стандартный deleter вызывает delete через статический тип указателя.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { auto owner = std::make_unique<int>(9); int saved = *owner; owner.reset(); std::cout << saved << " " << (owner ? 1 : 0) << "\n"; }
```

Ожидаемый вывод:

```text
9 0
```

## Разбор и эксперимент

Сравните reset и release по двум вопросам: кто удалил объект и кто обязан удалить его теперь. В практике значение нужно получить до reset и хранить независимо от адреса.

### get, reset, release — три разные операции

get() выдаёт заимствованный адрес: владение остаётся у unique_ptr, жизнь объекта не продлевается. reset() уничтожает прежний объект и принимает новый адрес (или nullptr). release() прекращает владение без удаления и возвращает адрес — ответственность переходит тому, кто принял указатель; если никто не примет, будет утечка. Путаница между тремя порождает три разных класса дефектов: use-after-free (get сохранили, reset вызвали), двойное удаление (release, а владелец всё равно удалён — уже не будет, но типичная ошибка: release + уникальный владелец в другом месте) и утечку (release без принимающей стороны).

reset(p.get()) на самом указателе — гарантированная катастрофа: сначала удалится объект, затем владелец запишет висячий адрес. Никогда не вызывайте reset с адресом, который владелец уже хранит.

Удаление наследника через unique_ptr&lt;Base> требует виртуального деструктора в Base: стандартный deleter вызывает delete через статический тип указателя. Для массивов существует отдельная специализация unique_ptr&lt;T[]>, применяющая delete[]. Обычный unique_ptr&lt;T> с new T[n] — несовместимые пары освобождения.

<CommonMistake title="Граница корректности">

get не создаёт второго владельца и не продлевает жизнь объекта. Сохранённый ранее сырой адрес переживает reset владельца и становится висячим.

</CommonMistake>

## Сначала диагноз, затем исправление

В переключателе практики два обязательных задания. Первое проверяет классификацию четырёх фрагментов. Зафиксируйте причину и границу времени жизни до изменения кода. Второе содержит дефектный исходник: исправьте владение, сохранив требуемое поведение. Код диагноза проверяется автоматически; пояснение в комментарии служит самопроверке. Оба задания нужны для завершения практики.

### Фрагмент 0

```cpp
auto p = std::make_unique<int>(5); int* raw = p.get(); p.reset(); int v = *raw;
```

### Фрагмент 1

```cpp
auto p = std::make_unique<int>(5); int v = *p; p.reset();
```

### Фрагмент 2

```cpp
auto p = std::make_unique<int>(5); auto q = std::move(p); int v = *q;
```

### Фрагмент 3

```cpp
auto p = std::make_unique<int>(5); std::unique_ptr<int> q(p.get());
```

Исправьте use-after-free: solve создаёт owner(a), сохраняет значение до reset, вызывает reset и возвращает сохранённое + b. Не разыменовывайте сырой адрес после reset и не удаляйте его вручную.
