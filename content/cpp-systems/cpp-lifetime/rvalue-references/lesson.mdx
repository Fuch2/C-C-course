## Цели обучения

- Классифицировать выражения по категориям lvalue, prvalue и xvalue.
- Проследить на MemoryDiagram, почему именованная rvalue-ссылка сама является lvalue.
- Реализовать перегрузки route и предсказать выбор компилятора для каждого вызова.

## Модель и назначение

Категория значения принадлежит выражению, а не переменной навсегда. lvalue обозначает объект с устойчивой идентичностью — у него можно взять адрес. prvalue вычисляет значение и инициализирует объект. xvalue обозначает объект, ресурсы которого разрешено переиспользовать; rvalue объединяет prvalue и xvalue. Ссылка T&amp;&amp; связывается с rvalue и даёт перегрузкам способ отличать заимствование для чтения от разрешения потребить состояние.

## Механика и гарантии

Именованный параметр T&amp;&amp; внутри функции — lvalue-выражение: у него есть имя, и его можно использовать несколько раз. Чтобы передать разрешение на перемещение дальше, нужен явный std::move; само связывание ссылки ничего не переносит. const T&amp; принимает и lvalue, и rvalue для чтения. Не смешивайте rvalue-ссылку конкретного типа с forwarding reference T&amp;&amp; в шаблоне с выводимым T: там действуют вывод типа и схлопывание ссылок — это отдельная тема perfect forwarding.

<MemoryDiagram title="Время жизни и связи владения">

```text
int value = 9           → выражение value: lvalue
std::move(value)         → xvalue; объект тот же
int&& ref = ...          → ref обозначает value
Выражение ref            → lvalue, несмотря на тип int&&
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int route(const int&) { return 1; } int route(int&&) { return 2; }
int main() { int value = 9; int&& ref = std::move(value); std::cout << route(ref) << " " << route(std::move(ref)) << " " << route(5) << "\n"; }
```

Ожидаемый вывод:

```text
1 2 2
```

## Разбор и эксперимент

Замените route(std::move(ref)) на route(ref) и предскажите выбранную перегрузку. Затем добавьте const int и объясните, почему int&amp;&amp; не связывается с const xvalue.

### Категория принадлежит выражению, а не переменной

lvalue — выражение с устойчивой идентичностью (у него можно взять адрес). prvalue — выражение, инициализирующее объект (литерал, результат функции, возвращающей значение). xvalue — объект, ресурсы которого разрешено забрать. rvalue = prvalue + xvalue. Ссылка T&amp;&amp; связывается с rvalue и позволяет перегрузкам различать «прочитать» и «потребить».

Главная ловушка: параметр int&amp;&amp; value внутри функции — именованная переменная, и любое выражение с её именем является lvalue. Тип «rvalue-ссылка» не делает каждое использование перемещением — иначе второй cout молча читал бы опустошённый объект. Чтобы передать разрешение на потребление дальше, нужен явный std::move(value).

Не путайте T&amp;&amp; конкретного типа с forwarding reference T&amp;&amp; в шаблоне с выводимым T: там включаются правила вывода и схлопывания ссылок, и параметр может оказаться lvalue-ссылкой. Это тема perfect forwarding; в рамках урока достаточно запомнить: если T выводится — правила другие. И никогда не возвращайте T&amp;&amp; на локальную переменную: категория выражения не продлевает жизнь объекта.

<CommonMistake title="Граница корректности">

Тип int&amp;&amp; не делает каждое использование имени перемещением: иначе повторное чтение параметра молча опустошало бы объект. Категорию задаёт форма выражения, а не объявленный тип.

</CommonMistake>
