## Категории значений

Чтобы решить, можно ли забрать ресурсы объекта, компилятору нужно знать, **нужен ли объект после этого выражения**. Для этого у каждого выражения есть **категория значения**:

| Категория   | Что это                                        | Примеры                                     |
| ----------- | ---------------------------------------------- | ------------------------------------------- |
| **lvalue**  | объект с именем или адресом, будет жить дальше | `x`, `v[0]`, `*p`, `name`                   |
| **prvalue** | «чистое» временное значение                    | `42`, `x + 1`, `std::string("a")`, `make()` |
| **xvalue**  | объект, который разрешили забрать              | `std::move(x)`, `static_cast<T &&>(x)`      |

prvalue и xvalue вместе называются **rvalue** — значения, ресурсы которых можно забрать. Грубое правило: если у выражения есть имя и можно взять его адрес — это lvalue.

## Ссылки разных видов

C++11 добавил **rvalue-ссылку** `T &&`. Она привязывается только к rvalue — к тем значениям, которые больше никому не нужны. Вместе с обычными ссылками получается три варианта:

| Параметр    | Принимает lvalue | Принимает rvalue | Смысл                          |
| ----------- | ---------------- | ---------------- | ------------------------------ |
| `T &`       | да               | нет              | изменю ваш объект              |
| `const T &` | да               | да               | прочитаю                       |
| `T &&`      | нет              | да               | заберу, вам он больше не нужен |

Перегрузка по виду ссылки позволяет функции **копировать** то, что ещё нужно, и **забирать** то, что не нужно:

```cpp
#include <print>
#include <string>
#include <utility>

void take(const std::string &s) {
    std::println("копирую «{}»", s);
}

void take(std::string &&s) {
    std::println("забираю «{}»", s);
}

int main() {
    std::string name = "Ада";
    take(name);
    take(std::string("Алан"));
    take(name + "!");
    take("литерал");
    take(std::move(name));
    return 0;
}
```

Вывод:

```text
копирую «Ада»
забираю «Алан»
забираю «Ада!»
забираю «литерал»
забираю «Ада»
```

`name` — lvalue, и выбрана перегрузка для чтения. Временная строка, результат `+` и строка, созданная из литерала, — rvalue. `std::move(name)` превращает lvalue в xvalue: `std::move` ничего не перемещает сам, это лишь **приведение типа** к `std::string &&`, разрешение забрать.

Именно так устроены `push_back(const T &)` и `push_back(T &&)` у вектора, а также пары конструкторов копирования и перемещения.

## Именованная rvalue-ссылка — это lvalue

Самая важная тонкость: внутри функции параметр `std::string &&s` — **имя**, а значит, lvalue. Чтобы передать его дальше с перемещением, нужен ещё один `std::move`:

```cpp
#include <print>
#include <string>
#include <utility>

struct Tracker {
    std::string v;
    Tracker() = default;
    explicit Tracker(std::string s) : v(std::move(s)) {}
    Tracker(const Tracker &o) : v(o.v) {
        std::println("копия");
    }
    Tracker(Tracker &&o) noexcept : v(std::move(o.v)) {
        std::println("перемещение");
    }
    Tracker &operator=(const Tracker &o) {
        v = o.v;
        std::println("копирующее присваивание");
        return *this;
    }
    Tracker &operator=(Tracker &&o) noexcept {
        v = std::move(o.v);
        std::println("перемещающее присваивание");
        return *this;
    }
};

struct Holder {
    Tracker value;
    void set_slow(Tracker &&t) {
        value = t;
    }
    void set_fast(Tracker &&t) {
        value = std::move(t);
    }
};

int main() {
    Holder h;
    h.set_slow(Tracker("a"));
    h.set_fast(Tracker("b"));
    return 0;
}
```

Вывод:

```text
копирующее присваивание
перемещающее присваивание
```

`set_slow` получила разрешение забрать объект, но не воспользовалась им: `value = t` копирует, потому что `t` — имя. Компилятор поступает так намеренно: имя можно использовать несколько раз, и забирать данные молча при первом же обращении было бы опасно.

```text
std::move(name)    xvalue          ✓          ✓  ← разрешение забрать
name + "!"         prvalue         ✓          ✓  ← временный объект
внутри take(T &&s): s — снова lvalue → дальше передавать через std::move(s)
```

## Пробрасывающие ссылки

В шаблоне запись `T &&` с выводимым `T` означает другое — **пробрасывающую** (forwarding) ссылку: она принимает и lvalue, и rvalue, а `T` запоминает, что именно пришло. `std::forward<T>(x)` передаёт значение дальше в той же категории:

```cpp
#include <print>
#include <string>
#include <utility>

void take(const std::string &s) {
    std::println("копирую «{}»", s);
}

void take(std::string &&s) {
    std::println("забираю «{}»", s);
}

template <typename T>
void relay(T &&x) {
    take(std::forward<T>(x));
}

int main() {
    std::string name = "Ада";
    relay(name);
    relay(std::string("Алан"));
    return 0;
}
```

Вывод:

```text
копирую «Ада»
забираю «Алан»
```

Так устроены `emplace_back`, `std::make_unique` и другие функции, которые передают аргументы конструктору без лишних копий. То же значит `auto &&` в объявлении переменной.

<Concept title="Rvalue-ссылки">

lvalue — выражение с именем или адресом, rvalue (prvalue и xvalue) — значение, которое больше не нужно. `const T &` принимает всё, `T &&` — только rvalue; перегрузка по ним разделяет «прочитать» и «забрать». `std::move` — приведение к `T &&`, а не перемещение. Именованная rvalue-ссылка — lvalue: чтобы передать её дальше с перемещением, снова нужен `std::move`. В шаблоне `T &&` — пробрасывающая ссылка, а `std::forward<T>` сохраняет категорию аргумента.

</Concept>

## Частые ошибки

<CommonMistake title="Забытый std::move для параметра T &&">

`void set(Tracker &&t) { value = t; }` — копия. Параметр с именем — lvalue: `value = std::move(t);`.

</CommonMistake>

<CommonMistake title="std::move «на всякий случай»">

`std::move` от переменной, которая понадобится ниже, оставляет её в неопределённом состоянии. Перемещайте только то, что больше не используете.

</CommonMistake>

<CommonMistake title="std::move вместо std::forward в шаблоне">

`template <class T> void relay(T &&x) { take(std::move(x)); }` заберёт и у тех, кто передал lvalue и ждёт, что его объект останется прежним. В шаблоне с пробрасывающей ссылкой — только `std::forward<T>(x)`.

</CommonMistake>

## Итоги

- lvalue — объект с именем, который будет жить дальше; rvalue — значение, которое можно забрать.
- `T &&` привязывается только к rvalue; перегрузки `const T &` и `T &&` разделяют копирование и перемещение.
- `std::move` — приведение к rvalue, а не операция перемещения.
- Именованная rvalue-ссылка — lvalue; для передачи дальше нужен `std::move`.
- В шаблонах `T &&` — пробрасывающая ссылка, и передают её через `std::forward<T>`.
