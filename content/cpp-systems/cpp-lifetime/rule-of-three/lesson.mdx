## Цели обучения

- Сформулировать инвариант владельца до написания трёх специальных операций.
- Проследить на MemoryDiagram transitions блоков при копии, присваивании и разрушении.
- Реализовать Cell по правилу трёх, переживающий самоприсваивание и bad_alloc.

## Модель и назначение

Если тип вручную управляет ресурсом и ему нужен собственный деструктор, вместе с ним необходимо рассмотреть конструктор копирования и копирующее присваивание. Это правило проектирования, а не требование написать три тела любой ценой: для исключительного ресурса обе копии законно удалить, для значения они должны создавать независимое содержимое. Ошибка возникает, когда написан только ~Buffer, а неявные копии продолжают дублировать адрес.

## Механика и гарантии

Инвариант учебного Cell прост: p всегда указывает на один собственный int. Деструктор удаляет его; копирующий конструктор выделяет другой int; присваивание сначала выделяет новый блок, затем удаляет старый. Такой порядок переживает самоприсваивание и сохраняет сильную гарантию при bad_alloc. Ручной new показан для понимания механики: в прикладном коде такой Cell лучше выразить готовым владеющим членом. Не добавляйте специальные операции классу, у которого нет соответствующей ответственности.

<MemoryDiagram title="Время жизни и связи владения">

```text
Конструирование: один Cell → один блок
Копия: два Cell → два разных блока
Присваивание: подготовить новый блок → заменить → удалить старый
Разрушение: каждый Cell удаляет только свой блок
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Cell { int* p; explicit Cell(int x): p(new int(x)) {} ~Cell() { delete p; } Cell(const Cell& x): p(new int(*x.p)) {} Cell& operator=(const Cell& x) { int* next = new int(*x.p); delete p; p = next; return *this; } };
int main() { Cell a{4}; Cell b = a; b = a; *a.p = 6; std::cout << *b.p << "\n"; }
```

Ожидаемый вывод:

```text
4
```

## Разбор и эксперимент

Постройте цепочку y = x; z = y; затем измените x. Значения y и z должны остаться прежними. Отдельно оцените цену хранения одного int динамически: это учебный способ увидеть владение, а не рекомендация.

### Инвариант первичен, функции вторичны

Правило трёх читается не как «напиши три функции», а как «если ты управляешь ресурсом вручную, все три специальные операции должны поддерживать один инвариант». Сформулируйте инвариант до кода: например, «p либо null, либо указывает на единственный int, за освобождение которого отвечает этот объект». Затем проверьте каждую операцию как переход между допустимыми состояниями.

Конструктор: создаёт состояние из аргументов. Копия: из состояния источника строит новое независимое состояние, не трогая источник. Присваивание: корректно освобождает старое, принимает новое, переживает self-assignment и исключение. Деструктор: освобождает ровно свой ресурс, не бросает.

Если ресурс исключительный, законное решение — = delete на обе копии. Правило трёх разрешает запретить копирование; оно запрещает лишь одно: оставить неявную поверхностную копию владеющего указателя. Современный C++ расширяет список до пяти операций (правило пяти), и рассуждение остаётся тем же — просто переходов становится больше.

Одна корректная операция не компенсирует другую опасную. Проверяйте все пути: copy construction, copy assignment после неё и самоприсваивание через алиас.

## Практика

Реализуйте Cell по правилу трёх: деструктор, глубокий копирующий конструктор, присваивание с подготовкой замены до удаления старого блока. solve создаёт x(a), копию y, объект z(b), выполняет z = y и самоприсваивание z через алиас, меняет y на b и возвращает *z.p + *y.p.
