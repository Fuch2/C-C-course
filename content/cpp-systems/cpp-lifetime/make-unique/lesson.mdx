## Создание владельца одной строкой

`std::make_unique<T>(аргументы…)` создаёт объект `T` в куче, передаёт аргументы его конструктору и сразу возвращает `std::unique_ptr<T>`, который этим объектом владеет. Сырой указатель при этом ни на мгновение не появляется в вашем коде:

```cpp
#include <memory>
#include <print>
#include <string>
#include <vector>

struct Point {
    int x;
    int y;
};

int main() {
    auto p = std::make_unique<Point>(3, 4);
    auto stars = std::make_unique<std::string>(5, '*');
    auto zeros = std::make_unique<int[]>(4);
    auto list = std::make_unique<std::vector<int>>(3, 7);
    std::println("точка ({}, {})", p->x, p->y);
    std::println("строка {}", *stars);
    std::println("массив {} {} {} {}", zeros[0], zeros[1], zeros[2], zeros[3]);
    std::println("вектор: размер {}, первый {}", list->size(), list->front());
    return 0;
}
```

Вывод:

```text
точка (3, 4)
строка *****
массив 0 0 0 0
вектор: размер 3, первый 7
```

Разберём строки по очереди:

- `make_unique<Point>(3, 4)` — у `Point` нет конструктора, но с C++20 агрегат можно инициализировать круглыми скобками, поэтому `make_unique` работает и для простых структур;
- `make_unique<std::string>(5, '*')` — аргументы уходят конструктору `std::string(5, '*')`;
- `make_unique<int[]>(4)` — массив из четырёх `int`, **заполненный нулями**; у такого указателя есть `operator[]`;
- `make_unique<std::vector<int>>(3, 7)` — вызывает `vector(3, 7)`: три семёрки, а не вектор `{3, 7}`.

Тип объекта написан один раз, переменная объявлена через `auto` — и при этом сразу видно, что это владелец.

## Почему не new

Ту же работу можно сделать вручную: `std::unique_ptr<Point> p(new Point(3, 4));`. Но у `make_unique` три преимущества:

1. **Нет сырого `new`.** Правило современного C++ — не писать в коде голые `new` и `delete`. Если `new` не встречается, неоткуда взяться и ошибке с двумя владельцами одного указателя или с забытым `delete`.
2. **Тип пишется один раз.** В `std::unique_ptr<Point> p(new Point(...))` он повторяется дважды, и при правке легко изменить только одно место.
3. **Безопасность при исключениях.** До C++17 вызов `f(std::unique_ptr<A>(new A), g())` мог выполнить `new A`, потом `g()`, и если `g()` бросала исключение — объект `A` терялся. В C++17 порядок вычисления аргументов уточнили, и эта утечка больше невозможна, но `make_unique` защищал от неё всегда.

`new` в современном коде остаётся только там, где объект нельзя создать иначе: например, когда конструктор закрыт, а владелец получает объект из чужого кода.

## Массивы: нули или мусор

Для динамических массивов есть две формы:

| Вызов                                      | Что получается                                     |
| ------------------------------------------ | -------------------------------------------------- |
| `std::make_unique<int[]>(n)`               | `n` элементов, инициализированных значением (нули) |
| `std::make_unique_for_overwrite<int[]>(n)` | `n` элементов **без** инициализации (C++20)        |
| `std::make_unique<int>(n)`                 | **один** `int` со значением `n` — не массив!       |

`make_unique_for_overwrite` нужен, когда буфер всё равно сейчас целиком перезапишут — например, прочитают в него файл. Обнуление тогда — лишняя работа. Читать элементы до записи нельзя: в них мусор.

В обычном коде вместо `unique_ptr<int[]>` чаще берут `std::vector<int>`: он знает свой размер и умеет расти. Массив в `unique_ptr` уместен, когда размер задан один раз и не меняется, а лишние 16 байт на ёмкость и размер вектора не нужны.

## Фабрики возвращают владение

Функция, которая создаёт объект и отдаёт его вызывающему, возвращает `std::unique_ptr`. Это **фабрика**: по описанию она решает, объект какого класса создать, а вызывающий получает владельца базового типа:

```cpp
#include <memory>
#include <numbers>
#include <print>
#include <string>
#include <string_view>

struct Shape {
    virtual ~Shape() = default;
    virtual std::string name() const = 0;
    virtual double area() const = 0;
};

struct Circle final : Shape {
    double r;
    explicit Circle(double r) : r(r) {}
    std::string name() const override {
        return "круг";
    }
    double area() const override {
        return std::numbers::pi * r * r;
    }
};

struct Rect final : Shape {
    double w;
    double h;
    Rect(double w, double h) : w(w), h(h) {}
    std::string name() const override {
        return "прямоугольник";
    }
    double area() const override {
        return w * h;
    }
};

std::unique_ptr<Shape> make_shape(std::string_view kind, double a, double b) {
    if (kind == "circle") {
        return std::make_unique<Circle>(a);
    }
    if (kind == "rect") {
        return std::make_unique<Rect>(a, b);
    }
    return nullptr;
}

int main() {
    for (std::string_view kind : {"circle", "rect", "star"}) {
        if (auto shape = make_shape(kind, 2, 3)) {
            std::println("{}: {:.2f}", shape->name(), shape->area());
        } else {
            std::println("{}: неизвестная фигура", kind);
        }
    }
    std::shared_ptr<Shape> shared = make_shape("rect", 1, 5);
    std::println("общая фигура: {}, владельцев {}", shared->name(), shared.use_count());
    return 0;
}
```

Вывод:

```text
круг: 12.57
прямоугольник: 6.00
star: неизвестная фигура
общая фигура: прямоугольник, владельцев 1
```

Здесь работают два преобразования:

- `unique_ptr<Circle>` неявно превращается в `unique_ptr<Shape>` — так же, как `Circle *` в `Shape *`. Удалять объект через базовый указатель можно, потому что деструктор `Shape` виртуальный;
- `unique_ptr` можно превратить в `std::shared_ptr` — владение переходит к общему указателю (о нём следующий урок). Поэтому фабрики возвращают именно `unique_ptr`: вызывающий сам решит, нужен ли ему общий владелец.

Пустой `unique_ptr` (`nullptr`) — естественный ответ «объект не создан». Если вызывающему нужна причина отказа, фабрика может вернуть `std::expected<std::unique_ptr<Shape>, std::string>`.

## Закрытый конструктор и ключ доступа

Иногда объекты класса должен создавать только один «хозяин» — например, пул соединений. Если сделать конструктор закрытым, а пул — другом, `make_unique` перестанет компилироваться: конструктор вызывает не пул, а код внутри стандартной библиотеки.

Решение — **ключ доступа** (passkey): конструктор открыт, но требует аргумент типа, который может создать только хозяин:

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>
#include <vector>

class Pool;

class Connection {
public:
    class Key {
        friend class Pool;
        Key() = default;
    };

    Connection(Key, std::string host) : host_(std::move(host)) {}
    const std::string &host() const {
        return host_;
    }

private:
    std::string host_;
};

class Pool {
public:
    Connection &open(std::string host) {
        connections_.push_back(std::make_unique<Connection>(Connection::Key{}, std::move(host)));
        return *connections_.back();
    }
    std::size_t size() const {
        return connections_.size();
    }

private:
    std::vector<std::unique_ptr<Connection>> connections_;
};

int main() {
    Pool pool;
    Connection &db = pool.open("db.local");
    pool.open("cache.local");
    std::println("{} соединения, первое: {}", pool.size(), db.host());
    return 0;
}
```

Вывод:

```text
2 соединения, первое: db.local
```

Конструктор `Key` закрыт, и создать ключ может только друг — `Pool`. Сам ключ можно копировать и перемещать, поэтому `make_unique` спокойно передаёт его конструктору `Connection`. Код вне пула не может написать `Connection::Key{}` — и не может создать соединение.

<Concept title="std::make_unique">

`std::make_unique<T>(args…)` создаёт `T` в куче с аргументами `args` и возвращает владеющий `std::unique_ptr<T>`. Для массивов: `make_unique<T[]>(n)` — `n` элементов, инициализированных нулями, `make_unique_for_overwrite<T[]>(n)` — без инициализации. Фабрики возвращают `unique_ptr<Base>`; его можно превратить в `shared_ptr`. Голые `new` и `delete` в коде не нужны.

</Concept>

<Tip title="Когда make_unique не подходит">

- Нужна своя функция удаления (`fclose`, `free`, функция библиотеки) — `make_unique` её не принимает; об этом урок о пользовательских функциях освобождения.
- Объект создаёт чужой код и отдаёт вам указатель — тогда владельца строят из готового указателя: `std::unique_ptr<T> p(raw);`.
- Нужен список инициализации: `make_unique<std::vector<int>>(3, 7)` вызывает `vector(3, 7)`. Для вектора `{3, 7}` пишут `std::make_unique<std::vector<int>>(std::initializer_list<int>{3, 7})`.

</Tip>

## Частые ошибки

<CommonMistake title="make_unique<int>(n) вместо make_unique<int[]>(n)">

`std::make_unique<int>(10)` создаёт **один** `int` со значением 10. Запись в `p.get()[5]` выходит за границу выделенной памяти. Массив — `std::make_unique<int[]>(10)`.

</CommonMistake>

<CommonMistake title="new внутри make_unique">

`std::make_unique<Widget>(new Widget)` не компилируется или создаёт не то, что задумано: аргументы уходят **конструктору** `Widget`, а не указателю. `make_unique` сам вызывает `new`.

</CommonMistake>

<CommonMistake title="Чтение буфера make_unique_for_overwrite">

Элементы, созданные через `make_unique_for_overwrite<int[]>(n)`, не инициализированы. Сумма или вывод до записи дают мусор. Если буфер не будет сразу целиком перезаписан, берите `make_unique<int[]>(n)`.

</CommonMistake>

## Итоги

- `std::make_unique<T>(args…)` создаёт объект и владельца сразу; сырой `new` не нужен.
- С C++20 `make_unique` работает и для агрегатов: `make_unique<Point>(3, 4)`.
- `make_unique<T[]>(n)` — массив нулей, `make_unique_for_overwrite<T[]>(n)` — без инициализации, `make_unique<T>(n)` — один объект.
- Фабрики возвращают `unique_ptr<Base>`; его можно передать в `shared_ptr`.
- Ключ доступа позволяет создавать объекты через `make_unique`, оставляя создание одному хозяину.
