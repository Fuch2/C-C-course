## Модель и назначение

make_unique&lt;T>(args...) создаёт объект T с переданными аргументами и сразу возвращает unique_ptr&lt;T>. Приобретение ресурса и назначение владельца становятся одной операцией: промежуточного сырого адреса, который мог бы утечь между new и конструированием владельца, просто не существует. Если конструктор T бросит, память new-выражения освобождается.

## Механика и гарантии

make_unique&lt;int[]>(n) создаёт владеющий массив из n элементов с инициализацией нулями и гарантирует парный delete[]. Размер в unique_ptr не хранится — его нужно вести отдельно; для последовательности переменной длины чаще подходит vector. make_unique не принимает пользовательский deleter: для FILE и библиотечных ресурсов конструируйте unique_ptr&lt;T, D> явно. Не оправдывайте фабрику примерами про порядок вычисления аргументов до C++17 — в C++20 они неактуальны; настоящая причина — отсутствие окна утечки и единая точка владения.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { auto buf = std::make_unique<int[]>(4); buf[3] = 8; std::cout << buf[0] << " " << buf[3] << "\n"; }
```

Ожидаемый вывод:

```text
0 8
```

## Разбор и эксперимент

Замените массив на vector&lt;int>(4) и перечислите дополнительные возможности: size, итераторы, изменение длины. Объясните, когда фиксированное отдельное владение массивом всё же уместнее.

### Один шаг вместо двух

Без фабрики создание владельца выглядит как T\* raw = new T(args); std::unique_ptr&lt;T> p(raw); — между двумя шагами может пройти бросающий код, и raw утечёт. make_unique&lt;T>(args) соединяет выделение и назначение владельца в одну операцию: промежуточного сырого адреса просто не существует.

make_unique&lt;T[]>(n) создаёт массив с инициализацией нулями и гарантирует парный delete[]. Размер при этом не хранится — для последовательности переменной длины или с проверкой границ нужен vector. make_unique не принимает пользовательский deleter: для FILE и библиотечных ресурсов конструируйте unique_ptr&lt;T, D> явно.

Не оправдывайте фабрику примерами про порядок вычисления аргументов до C++17 — в C++20 эти примеры неактуальны. Настоящие причины две: отсутствие висячего окна между new и владельцем и единая точка, где код ревью проверяет «кто владеет». В коде, где новый объект сразу становится уникальным владельцем, new не должен встречаться вообще.

<CommonMistake title="Граница корректности">

Не используйте unique_ptr&lt;int[]> как контейнер с проверкой границ: operator[] не проверяет индекс, а длину нужно знать отдельно.

</CommonMistake>
