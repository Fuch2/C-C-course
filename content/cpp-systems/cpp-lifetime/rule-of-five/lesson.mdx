## Пять специальных функций

С появлением перемещения к правилу трёх добавились две функции. **Правило пяти**: если вы объявили хотя бы одну из пяти —

- деструктор,
- конструктор копирования, копирующее присваивание,
- перемещающий конструктор, перемещающее присваивание, —

объявите все пять: реализуйте, `= default` или `= delete`. Причина та же, что у правила трёх, плюс одна новая: объявление любой из них **меняет то, что компилятор создаст сам**, и последствия неочевидны.

## Что компилятор создаёт сам

| Вы объявили…          | копирование                 | перемещение           |
| --------------------- | --------------------------- | --------------------- |
| ничего                | создаётся                   | создаётся             |
| деструктор            | создаётся (устарело)        | **не объявляется**    |
| копирующую операцию   | вторая создаётся (устарело) | **не объявляется**    |
| перемещающую операцию | **удаляется**               | вторая не объявляется |

«Не объявляется» коварнее, чем кажется: ошибки компиляции нет, rvalue просто привязываются к конструктору копирования, и каждое «перемещение» молча становится копией. Проверим на поле, которое сообщает, что с ним сделали:

```cpp
#include <print>
#include <utility>

struct Probe {
    Probe() = default;
    Probe(const Probe &) {
        std::println("  поле скопировано");
    }
    Probe(Probe &&) noexcept {
        std::println("  поле перемещено");
    }
    Probe &operator=(const Probe &) = default;
    Probe &operator=(Probe &&) noexcept = default;
};

struct Plain {
    Probe p;
};

struct WithDestructor {
    Probe p;
    ~WithDestructor() {}
};

struct WithDefaults {
    Probe p;
    ~WithDefaults() {}
    WithDefaults() = default;
    WithDefaults(const WithDefaults &) = default;
    WithDefaults &operator=(const WithDefaults &) = default;
    WithDefaults(WithDefaults &&) noexcept = default;
    WithDefaults &operator=(WithDefaults &&) noexcept = default;
};

int main() {
    std::println("Plain:");
    Plain a;
    [[maybe_unused]] Plain b = std::move(a); // переменные нужны только ради перемещения
    std::println("WithDestructor:");
    WithDestructor c;
    [[maybe_unused]] WithDestructor d = std::move(c);
    std::println("WithDefaults:");
    WithDefaults e;
    [[maybe_unused]] WithDefaults f = std::move(e);
    return 0;
}
```

Вывод:

```text
Plain:
  поле перемещено
WithDestructor:
  поле скопировано
WithDefaults:
  поле перемещено
```

Пустой деструктор `~WithDestructor() {}` отключил перемещение класса — `std::move` превратился в копирование всех полей. Явные `= default` всех пяти функций возвращают привычное поведение и заодно документируют намерения.

Особенно часто так теряют перемещение у **полиморфной базы**: `virtual ~Base() = default;` — тоже объявленный деструктор. Если такой класс должен перемещаться, допишите остальные четыре функции как `= default`.

## Полный набор для класса-владельца

```cpp
#include <algorithm>
#include <cstddef>
#include <print>
#include <utility>

class Buffer {
public:
    Buffer(std::size_t size, int fill) : size_(size), data_(new int[size]) {
        std::fill_n(data_, size_, fill);
    }
    ~Buffer() {
        delete[] data_;
    }
    Buffer(const Buffer &other) : size_(other.size_), data_(new int[other.size_]) {
        std::copy_n(other.data_, size_, data_);
    }
    Buffer &operator=(const Buffer &other) {
        Buffer copy(other);
        swap(copy);
        return *this;
    }
    Buffer(Buffer &&other) noexcept
        : size_(std::exchange(other.size_, 0)), data_(std::exchange(other.data_, nullptr)) {}
    Buffer &operator=(Buffer &&other) noexcept {
        Buffer moved(std::move(other));
        swap(moved);
        return *this;
    }

    void swap(Buffer &other) noexcept {
        std::swap(size_, other.size_);
        std::swap(data_, other.data_);
    }

    std::size_t size() const {
        return size_;
    }

private:
    std::size_t size_;
    int *data_;
};

int main() {
    Buffer a(3, 1), b(5, 2);
    Buffer c = a;
    c = b;
    Buffer d = std::move(c);
    a = std::move(d);
    Buffer &alias = a;
    a = std::move(alias);
    std::println("{} {} {} {}", a.size(), b.size(), c.size(), d.size());
    return 0;
}
```

Вывод:

```text
5 5 0 0
```

Все присваивания выражены через конструкторы и обмен: копирующее строит копию, перемещающее — перемещённый временный объект. Старое содержимое `*this` уходит с временным объектом, самоприсваивание и самоперемещение безопасны без проверок. Логика владения написана ровно в трёх местах: конструктор копирования, перемещающий конструктор и деструктор.

<MemoryDiagram title="Пять функций одного владельца">

```text

Buffer(const Buffer &)     создать свой ресурс — копию чужого
operator=(const Buffer &)  копия + обмен        (старое уходит с копией)
Buffer(Buffer &&)          забрать чужой ресурс, источник — пуст
operator=(Buffer &&)       перемещённый временный + обмен
```

## Только перемещение

Для ресурсов, копия которых не имеет смысла, копирующие операции удаляют, а перемещающие реализуют:

```cpp
class Socket {
public:
    ~Socket();
    Socket(const Socket &) = delete;
    Socket &operator=(const Socket &) = delete;
    Socket(Socket &&other) noexcept;
    Socket &operator=(Socket &&other) noexcept;
};
```

Это тоже все пять функций — правило выполнено. Так устроены `std::unique_ptr`, `std::jthread` и файловые потоки.

<Concept title="Правило пяти">

Деструктор, две копирующие и две перемещающие операции объявляют вместе: реализуют, `= default` или `= delete`. Объявленный деструктор или копирующая операция отключает неявное перемещение — rvalue начинают копироваться без всякой диагностики; объявленная перемещающая операция удаляет неявное копирование. Для владельца ресурса логику пишут в двух конструкторах и деструкторе, а присваивания выражают через них и обмен. Некопируемые владельцы удаляют копирование и реализуют перемещение.

</Concept>

## Частые ошибки

<CommonMistake title="virtual ~Base() = default и потерянное перемещение">

Полиморфная база с одним виртуальным деструктором копирует там, где могла бы перемещать. Если базу перемещают, объявите остальные четыре функции `= default` (или запретите копирование, если она не должна копироваться).

</CommonMistake>

<CommonMistake title="Пустой деструктор «для порядка»">

`~T() {}` в классе, которому деструктор не нужен, тихо отключает перемещение. Не объявляйте деструктор без причины.

</CommonMistake>

<CommonMistake title="Перемещение реализовано, копирование забыто">

Объявили только перемещающий конструктор — копирование стало удалённым. Если тип должен копироваться, напишите или `= default` копирующие операции.

</CommonMistake>

## Практика

1. **Свой вектор** — класс с полным набором из пяти функций.
2. **Что создаст компилятор** — эксперимент с объявлениями специальных функций.
3. **Найди ошибку: документы копируются** — виртуальный деструктор отключил перемещение.
4. **Строка с малым буфером** — пять функций для двух режимов хранения.

## Итоги

- Пять специальных функций объявляют вместе: реализуют, `= default` или `= delete`.
- Объявленный деструктор или копирование отключает неявное перемещение — без предупреждений.
- Объявленное перемещение удаляет неявное копирование.
- Присваивания удобно выражать через конструкторы и обмен.
- Некопируемый владелец: копирование `= delete`, перемещение реализовано.
