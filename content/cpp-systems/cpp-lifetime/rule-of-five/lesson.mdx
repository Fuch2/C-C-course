## Модель и назначение

К трём копирующим операциям управления ресурсом C++11 добавил move-конструктор и move-присваивание. Все пять операций должны поддерживать один инвариант. Механика генерации критична: объявление деструктора или любой копирующей операции подавляет неявную генерацию перемещений — добавили ~T() для логирования, и std::move начал тихо копировать. Компиляция проходит, производительность исчезает.

## Механика и гарантии

Для нашего Cell null означает пустое состояние после перемещения. Копия непустого Cell создаёт независимый int; копия пустого остаётся пустой — без проверки other.p выражение new int(\*other.p) разыменует null. Copy-присваивание использует временную копию и swap; move-конструктор забирает указатель; move-присваивание очищает старое и забирает новое. Все пять не обязаны быть доступны: владелец файла может удалить копии, сохранив перемещения. = default и = delete — такие же решения правила пяти.

<MemoryDiagram title="Время жизни и связи владения">

```text
Состояния: пустой | владеет одним int
copy: пустой→пустой; владелец→новый независимый владелец
move: источник→пустой; назначение→прежний ресурс источника
destruct: пустой→ничего; владелец→ровно одно освобождение
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Value { std::vector<int> data; Value(): data{5} {} ~Value() = default; Value(const Value&) = default; Value& operator=(const Value&) = default; Value(Value&&) noexcept = default; Value& operator=(Value&&) noexcept = default; };
int main() { Value a; Value b = a; Value c = std::move(b); std::cout << c.data[0] << " " << a.data[0] << "\n"; }
```

Ожидаемый вывод:

```text
5 5
```

## Разбор и эксперимент

В практике последовательно используются все пять операций, включая копию пустого объекта. Составьте таблицу владельцев после каждой строки: ни один блок не должен остаться без владельца и ни один — с двумя.

### Пять операций — один инвариант

Правило пяти расширяет правило трёх: деструктор, copy ctor, copy assign, move ctor, move assign должны согласованно поддерживать одно описание допустимых состояний. Удобный формат — таблица переходов: из какого состояния операция ведёт и в какое приводит, для источника и для назначения.

Важная механика генерации: объявление деструктора или любой копирующей операции подавляет неявную генерацию move-операций. Добавили ~T() для логирования — std::move начал тихо копировать. Компиляция проходит, производительность исчезла; без тестов это не заметить. Поэтому «= default» и «= delete» — тоже полноценные решения правила пяти: владелец файла может удалить копии и оставить перемещения.

defaulted move для сырого указателя лишь копирует адрес — тип int\* не знает, что он «исключительный». Если специальная функция не может быть = default без нарушения инварианта, пишите её вручную либо замените поле на владеющий тип и перейдите к правилу нуля.

<CommonMistake title="Граница корректности">

Не забывайте копирование moved-from объекта, если контракт его разрешает: без проверки null копирующий конструктор разыменует пустой указатель.

</CommonMistake>
