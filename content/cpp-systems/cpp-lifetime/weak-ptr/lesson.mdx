## Наблюдать, не владея

Иногда объекту нужен доступ к другому объекту, но он не должен продлевать ему жизнь: кэш не должен держать в памяти картинки, которые никто не показывает; подписчик события может исчезнуть раньше издателя; ребёнок в дереве знает о родителе, но не владеет им. Сырой указатель для этого опасен — по нему не узнать, жив ли ещё объект.

`std::weak_ptr<T>` — **наблюдатель** объекта, которым владеют `shared_ptr`. Он не увеличивает счётчик владельцев, а значит, не мешает удалению. Зато через блок управления он всегда может узнать, жив ли объект, и временно получить к нему доступ.

```cpp
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Doc {
    std::string name;
    explicit Doc(std::string n) : name(std::move(n)) {}
    ~Doc() {
        std::println("удалён {}", name);
    }
};

void peek(const std::weak_ptr<Doc> &w) {
    if (auto doc = w.lock()) {
        std::println("жив: {}, владельцев {}", doc->name, doc.use_count());
    } else {
        std::println("объекта больше нет");
    }
}

int main() {
    auto owner = std::make_shared<Doc>("отчёт");
    std::weak_ptr<Doc> watcher = owner;
    std::println("владельцев {}", owner.use_count());
    peek(watcher);
    owner.reset();
    std::println("истёк: {}", watcher.expired());
    peek(watcher);
    return 0;
}
```

Вывод:

```text
владельцев 1
жив: отчёт, владельцев 2
удалён отчёт
истёк: true
объекта больше нет
```

`weak_ptr` не учитывается в `use_count`. Пока `peek` работает с объектом, `lock()` создаёт временного владельца — поэтому внутри видно двух владельцев, и объект не может исчезнуть посреди работы. После `owner.reset()` объект удалён, а `lock()` возвращает пустой `shared_ptr`.

<MemoryDiagram title="weak_ptr смотрит в блок управления">

```text
owner ──┬──────────────▶ [Doc "отчёт"]
        └──▶ [блок: владельцев 1, наблюдателей 1]
watcher ────▶ (тот же блок)        объект не держит
owner.reset() → владельцев 0 → ~Doc()        блок жив, пока есть watcher
watcher.lock() → владельцев 0 → пустой shared_ptr
```

</MemoryDiagram>

## Правильный способ доступа

У `weak_ptr` нет `*` и `->`: напрямую к объекту обратиться нельзя, только через `lock()`. Это сделано намеренно. Проверка «сначала `expired()`, потом обращение» ненадёжна: между проверкой и обращением другой поток может отпустить последнего владельца. `lock()` проверяет и захватывает владение **атомарно**, поэтому единственный правильный шаблон:

```cpp
if (auto sp = weak.lock()) {
    // объект жив и не исчезнет, пока жив sp
}
```

`expired()` годится только для вопросов «можно ли уже выбросить эту запись», где ответ не используется для доступа к объекту.

## Где нужен weak_ptr

| Задача                                | Почему не `shared_ptr` и не сырой указатель                               |
| ------------------------------------- | ------------------------------------------------------------------------- |
| кэш объектов                          | `shared_ptr` держал бы в памяти всё, что когда-то загружалось             |
| список подписчиков                    | издатель не должен продлевать жизнь подписчикам; сырой указатель повиснет |
| ссылка ребёнка на родителя            | двусторонний `shared_ptr` образует цикл и утечку (следующий урок)         |
| объект отдаёт ссылку на себя в колбэк | колбэк может сработать после удаления объекта                             |

Кэш со слабыми ссылками отдаёт уже загруженный объект, если он ещё кому-то нужен, и загружает заново, если нет:

```cpp
#include <map>
#include <memory>
#include <print>
#include <string>
#include <utility>

struct Image {
    std::string name;
    explicit Image(std::string n) : name(std::move(n)) {
        std::println("загружено {}", name);
    }
};

class Cache {
public:
    std::shared_ptr<Image> get(const std::string &name) {
        if (auto alive = slots_[name].lock()) {
            return alive;
        }
        auto fresh = std::make_shared<Image>(name);
        slots_[name] = fresh;
        return fresh;
    }

private:
    std::map<std::string, std::weak_ptr<Image>> slots_;
};

int main() {
    Cache cache;
    auto a = cache.get("кот");
    auto b = cache.get("кот");
    std::println("один объект: {}", a == b);
    a.reset();
    b.reset();
    auto c = cache.get("кот");
    return 0;
}
```

Вывод:

```text
загружено кот
один объект: true
загружено кот
```

Пока картинку держат `a` или `b`, кэш отдаёт тот же объект. Когда владельцев не осталось, картинка удалена, хотя запись в кэше осталась, — и следующий запрос загружает её снова.

## Ссылка на себя

Объект, которым владеет `shared_ptr`, может выдать слабую ссылку на самого себя: класс наследует `std::enable_shared_from_this<T>`, и метод `weak_from_this()` (C++17) возвращает `weak_ptr` из его собственного блока управления. Так объект подписывается на события, не продлевая себе жизнь: если его удалят, издатель просто не сможет его заблокировать.

<Concept title="std::weak_ptr">

`std::weak_ptr<T>` наблюдает за объектом, которым владеют `shared_ptr`, не увеличивая счётчик владельцев. Доступ — только через `lock()`, который атомарно возвращает `shared_ptr` на живой объект или пустой; `expired()` — лишь подсказка. Блок управления живёт, пока есть наблюдатели. `weak_ptr` нужен кэшам, спискам подписчиков, обратным ссылкам на родителя и колбэкам; ссылку на себя даёт `weak_from_this()`.

</Concept>

## Частые ошибки

<CommonMistake title="Проверка expired(), затем lock()">

`if (!w.expired()) { auto sp = w.lock(); sp->…; }` — между проверкой и захватом объект может исчезнуть, и `sp` окажется пустым. Только `if (auto sp = w.lock())`.

</CommonMistake>

<CommonMistake title="Сырой указатель вместо weak_ptr у наблюдателя">

Издатель с `Listener *` не узнает, что подписчик удалён, и вызовет метод мёртвого объекта. `weak_ptr` отвечает на вопрос «жив ли?».

</CommonMistake>

<CommonMistake title="Мёртвые записи навсегда">

`weak_ptr` не удаляет себя из контейнера. Кэш или список подписчиков нужно периодически чистить от истёкших записей (`std::erase_if` с `expired()`).

</CommonMistake>

## Практика

1. **Наблюдение за документом** — владельцы и наблюдатель.
2. **Слабый кэш** — объекты живут, пока нужны кому-то кроме кэша.
3. **Найди ошибку: мёртвый подписчик** — сырой указатель в списке подписчиков.
4. **Шина событий** — подписка через `weak_from_this` и очистка мёртвых подписок.

## Итоги

- `weak_ptr` наблюдает за объектом, не продлевая ему жизнь.
- Доступ — только через `lock()`; `expired()` — подсказка, а не разрешение.
- Блок управления живёт, пока есть наблюдатели, даже после удаления объекта.
- Кэши, подписчики, ссылки на родителя и колбэки — типичные места для `weak_ptr`.
- `enable_shared_from_this` и `weak_from_this()` дают слабую ссылку на себя.
