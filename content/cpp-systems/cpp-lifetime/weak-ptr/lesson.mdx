## Цели обучения

- Объяснить, почему lock(), а не expired(), является безопасным способом доступа.
- Проследить на MemoryDiagram, как held продлевает жизнь объекта после reset владельца.
- Построить наблюдателя, который честно переживает смерть объекта и сообщает о ней.

## Модель и назначение

weak_ptr хранит возможность попытаться получить совместное владение, не продлевая жизнь объекта. Прямого доступа у него нет — operator\* отсутствует намеренно. Единственный безопасный путь: lock() возвращает shared_ptr, который либо пуст (объект мёртв), либо удерживает живой объект на всё время своего существования. Сохраните результат в локальную переменную — так наблюдение превращается в ограниченный интервал владения.

## Механика и гарантии

expired() сообщает, осталось ли сильное владение, но схема if (!weak.expired()) с последующим действием не закрепляет объект: между проверкой и доступом состояние может измениться даже в однопоточном коде с вложенными областями. lock объединяет проверку и получение владения атомарно относительно счётчика. Классические применения: обратное ребро child → parent, кеш с исчезающими объектами, подписки, где смерть получателя означает «пропустить уведомление». Заранее решите, что делать при отсутствии объекта: пропустить, вернуть fallback или сообщить об ошибке.

weak - - наблюдает -> блок; жизнь A не продлевает

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { auto owner = std::make_shared<int>(6); std::weak_ptr<int> weak = owner; auto held = weak.lock(); owner.reset(); std::cout << *held << " "; held.reset(); std::cout << (weak.expired() ? 1 : 0) << "\n"; }
```

Ожидаемый вывод:

```text
6 1
```

## Разбор и эксперимент

Удерживайте результат lock, сбросьте первоначального владельца и проверьте доступ через удержанный shared_ptr. Только после его reset наблюдатель становится expired.

### lock() превращает наблюдение в короткое владение

weak_ptr не продлевает жизнь объекта и не даёт прямого доступа — у него намеренно нет operator\*. Единственный безопасный путь — lock(): он возвращает shared_ptr, который либо пуст (объект уже умер), либо удерживает живой объект на всё время своего существования. Результат lock нужно сохранить в локальную переменную и работать через неё.

Паттерн if (!w.expired()) &#123; ... сделать что-то ... &#125; — гонка даже в однопоточном коде с вложенными областями: между проверкой и действием объект может уничтожить любой промежуточный reset. expired() годится для диагностики и статистики, не для управления доступом.

Классические применения: обратное ребро child → parent в дереве владения; кеш, который переиспользует живые объекты и не удерживает мёртвые; подписки, где исчезновение получателя означает «пропустить уведомление». Везде weak_ptr отвечает на вопрос «если объект ещё жив, дай мне им воспользоваться» — и заранее определённый fallback на «не жив».

<CommonMistake title="Граница корректности">

Не сохраняйте сырой адрес из временного weak.lock().get(): временный shared_ptr может быть последним владельцем и исчезнет в конце полного выражения.

</CommonMistake>
