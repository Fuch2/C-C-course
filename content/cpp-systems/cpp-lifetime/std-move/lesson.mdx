## Цели обучения

- Объяснить std::move как приведение категории, а не как операцию переноса.
- Проследить на MemoryDiagram, почему move от const выбирает копирующую перегрузку.
- Реализовать Probe, фиксирующий выбор перегрузки значением поля kind.

## Модель и назначение

std::move — это приведение категории выражения к xvalue с сохранением cv-квалификаторов. Он не выделяет память, не вызывает деструктор и сам ничего не переносит: работу выполняет выбранная перегрузка конструктора или оператора присваивания. Инструкция std::move(x); как отдельный оператор не опустошит x. Имя функции правильнее читать как «этот объект разрешено использовать как источник перемещения».

## Механика и гарантии

Если x — const T, результат имеет тип const T&amp;&amp;: типичный move-конструктор T(T&amp;&amp;) не может принять его, потому что изменение источника запрещено, — и доступный T(const T&amp;) молча выполнит копирование. У unique_ptr копирование удалено, поэтому move от const даст честную ошибку компиляции. Для возврата локального значения пишите return result: применяются правила elision; return std::move(result) способно помешать NRVO. Не разбрасывайте move ради скорости — сначала установите, где прежнее состояние больше не нужно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Probe { Probe() = default; Probe(const Probe&) { std::cout << "copy "; } Probe(Probe&&) noexcept { std::cout << "move "; } };
int main() { Probe a; Probe b(std::move(a)); const Probe c; Probe d(std::move(c)); std::cout << "\n"; }
```

Ожидаемый вывод:

```text
move copy
```

## Разбор и эксперимент

Probe в примере печатает выбранную перегрузку. Сначала предскажите обе строки без запуска, затем удалите move-конструктор: оба случая будут копировать через const&amp;.

### std::move ничего не перемещает

std::move — это static_cast к xvalue. Он не выделяет память, не вызывает деструктор, не обнуляет источник. Инструкция std::move(x); сама по себе не делает ничего, кроме изменения категории выражения. Работу выполняет выбранная перегрузка конструктора или оператора присваивания — если она есть.

Следствие номер один: move от const не работает. std::move(constObj) даёт const T&amp;&amp;, а типичный move-конструктор T(T&amp;&amp;) не может принять const — изменение источника запрещено. Перегрузка T(const T&amp;) молча скопирует. У unique_ptr копирование удалено, поэтому будет честная ошибка компиляции. Следствие номер два: return std::move(local) мешает NRVO и чаще всего вредит — пишите return local.

Практическое правило применения: найдите последнее место, где нужно прежнее состояние объекта, и перемещайте после него. Переместили строку в контейнер до логирования её содержимого — журнал уже не увидит текст. Порядок операций важнее количества move.

<CommonMistake title="Граница корректности">

Не объявляйте объект const, если собираетесь передать изменяемое владение. Наличие std::move в вызове не является доказательством, что выбрана move-перегрузка.

</CommonMistake>
