## Не всё освобождается через delete

Умные указатели по умолчанию освобождают объект через `delete`. Но многие ресурсы приходят из C-библиотек и освобождаются своими функциями: память из `malloc` — через `free`, файл из `fopen` — через `fclose`, объекты библиотек — через `xxx_destroy`. Вызвать для них `delete` — неопределённое поведение.

Поэтому у умных указателей есть **пользовательская функция освобождения** (deleter): вызываемый объект, который получает указатель и освобождает ресурс так, как нужно.

```cpp
#include <cstdlib>
#include <cstring>
#include <memory>
#include <print>

struct FreeDeleter {
    void operator()(void *p) const noexcept {
        std::free(p);
    }
};

using CString = std::unique_ptr<char, FreeDeleter>;

CString duplicate(const char *s) {
    return CString(strdup(s));
}

int main() {
    CString copy = duplicate("привет");
    std::println("{} ({} байт)", copy.get(), std::strlen(copy.get()));
    std::println("{} {}", sizeof(CString) == sizeof(char *), sizeof(std::unique_ptr<char, void (*)(void *)>));
    return 0;
}
```

Вывод:

```text
привет (12 байт)
true 16
```

`strdup` выделяет копию строки через `malloc`, и `CString` освободит её через `free` — при любом выходе из области. Функция освобождения — часть **типа** `unique_ptr`: `std::unique_ptr<char, FreeDeleter>` и `std::unique_ptr<char>` — разные типы.

## Какой тип выбрать для функции освобождения

| Вариант                                                | Размер `unique_ptr`   | Замечания                                      |
| ------------------------------------------------------ | --------------------- | ---------------------------------------------- |
| пустая структура с `operator()`                        | как у указателя       | лучший вариант: ноль накладных расходов        |
| лямбда без захвата: `decltype([](T *p) { … })` (C++20) | как у указателя       | удобно, но тип лямбды есть в каждом объявлении |
| указатель на функцию `void (*)(T *)`                   | два указателя         | функцию нужно передавать в каждый конструктор  |
| структура с состоянием                                 | указатель + состояние | когда освобождение зависит от данных (пул)     |

Пустая структура не хранит данных, и компилятор не тратит на неё место. Указатель на функцию — это данные: его нужно хранить в каждом объекте. Брать адреса функций стандартной библиотеки (`&std::fclose`, `&std::free`) стандарт не разрешает — они могут быть реализованы иначе, чем обычные функции, — поэтому оборачивайте их в свою структуру.

## C-интерфейсы с выходным параметром

Многие C-функции возвращают ресурс через параметр-указатель на указатель: `int create(…, Widget **out)`. Раньше приходилось заводить временный сырой указатель и потом отдавать его владельцу. C++23 добавил адаптеры `std::out_ptr` и `std::inout_ptr`: они передают в функцию адрес временного указателя и после вызова кладут результат в умный указатель.

```cpp
#include <cstdlib>
#include <memory>
#include <print>

// Условная C-библиотека.
extern "C" int make_numbers(int count, int **out) {
    if (count <= 0) {
        return -1;
    }
    *out = static_cast<int *>(std::malloc(sizeof(int) * count));
    for (int i = 0; i < count; ++i) {
        (*out)[i] = i * i;
    }
    return 0;
}

struct FreeDeleter {
    void operator()(void *p) const noexcept {
        std::free(p);
    }
};

int main() {
    std::unique_ptr<int, FreeDeleter> numbers;
    if (make_numbers(5, std::out_ptr(numbers)) == 0) {
        std::println("{} {}", numbers.get()[2], numbers.get()[4]);
    }
    return 0;
}
```

Вывод:

```text
4 16
```

Ни одного сырого указателя-владельца в пользовательском коде: функция записала результат, и `numbers` сразу стал его владельцем.

## Функция освобождения у shared_ptr

У `shared_ptr` функция освобождения **не** входит в тип: её передают в конструктор, и она хранится в блоке управления. Поэтому `std::shared_ptr<Device>` с любыми функциями освобождения — один тип, и их можно складывать в один контейнер. Цена — `make_shared` с ней использовать нельзя, а блок управления выделяется отдельно.

```cpp
#include <memory>
#include <print>

struct Device {
    int id;
};

int main() {
    std::shared_ptr<Device> a(new Device{1}, [](Device *d) {
        std::println("закрыто устройство {}", d->id);
        delete d;
    });
    std::shared_ptr<Device> b = a;
    a.reset();
    std::println("ещё открыто: {}", b->id);
    return 0;
}
```

Вывод:

```text
ещё открыто: 1
закрыто устройство 1
```


</MemoryDiagram>

<Concept title="Пользовательские функции освобождения">

Функция освобождения — вызываемый объект, которым умный указатель освобождает ресурс вместо `delete`. У `unique_ptr` она часть типа: пустая структура с `operator()` не добавляет накладных расходов, указатель на функцию удваивает размер, структура с состоянием хранит своё состояние. У `shared_ptr` она хранится в блоке управления и не влияет на тип. Для C-функций с выходным параметром C++23 предлагает `std::out_ptr` и `std::inout_ptr`. Так любой C-ресурс получает RAII-владельца.

</Concept>

## Частые ошибки

<CommonMistake title="delete для памяти из malloc">

`std::unique_ptr<char> s(strdup("…"));` освободит строку через `delete` — несовпадение способов выделения и освобождения. AddressSanitizer сообщает `alloc-dealloc-mismatch`.

</CommonMistake>

<CommonMistake title="unique_ptr<int> для new int[n]">

Для массива нужен `std::unique_ptr<int[]>` — он вызовет `delete[]`. Обычный `unique_ptr<int>` вызовет `delete` — снова несовпадение.

</CommonMistake>

<CommonMistake title="Функция освобождения, которая бросает исключения">

Она вызывается из деструктора. Объявляйте её `noexcept` и сообщайте об ошибках закрытия иначе.

</CommonMistake>

## Практика

1. **Устройства C-библиотеки** — RAII-обёртка для функций open/close.
2. **Строки из malloc** — `free` как функция освобождения и `std::out_ptr`.
3. **Найди ошибку: не тот способ освобождения** — `delete` для памяти из `malloc`.
4. **Пул соединений** — функция освобождения с состоянием, возвращающая объект в пул.

## Итоги

- Ресурсы C-библиотек освобождают их собственными функциями, а не `delete`.
- Функция освобождения `unique_ptr` — часть типа; пустая структура не добавляет накладных расходов.
- Функции стандартной библиотеки оборачивают в структуру, а не берут их адрес.
- `std::out_ptr` (C++23) связывает выходной параметр C-функции с умным указателем.
- У `shared_ptr` функция освобождения хранится в блоке управления и не меняет тип.
