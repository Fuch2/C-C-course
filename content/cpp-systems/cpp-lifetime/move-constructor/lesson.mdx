## Цели обучения

- Сформулировать инвариант «один блок — один владелец» для перемещающего конструктора.
- Проследить на MemoryDiagram обнуление источника через std::exchange.
- Диагностировать move-конструктор с двумя владельцами и исправить его обменом указателя.

## Модель и назначение

Перемещающий конструктор T(T&amp;&amp; other) создаёт нового владельца из источника, ресурсы которого разрешено забрать. Для сырого указателя недостаточно скопировать адрес: нужно лишить источник права освобождения, иначе оба деструктора удалят один блок. Инвариант владельца: p либо null, либо указывает на единственный принадлежащий объекту int. std::exchange(other.p, nullptr) возвращает старый адрес и одновременно переводит источник в пустое состояние одной операцией; delete nullptr в деструкторе безопасен.

## Механика и гарантии

Пустое состояние становится частью публичного договора: метод get не может безусловно разыменовывать p. В учебном Cell get возвращает 0 для пустого объекта; другая допустимая политика — предусловие has_value, но его нужно явно проверять. noexcept важен: vector при росте перемещает элементы только если перемещение noexcept или копия недоступна. Но noexcept обязан быть правдой — исключение из noexcept-функции завершает программу через terminate; передача указателя не бросает, поэтому здесь он обоснован.

<MemoryDiagram title="Время жизни и связи владения">

```text
До: source.p → A; target не существует
Ошибочно: target.p = source.p → два владельца A → double delete
Правильно: target.p = exchange(source.p, null)
После: source.p = null; target.p → A; оба объекта живы
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Cell { int* p; explicit Cell(int n): p(new int(n)) {} ~Cell() { delete p; } Cell(const Cell&) = delete; Cell& operator=(const Cell&) = delete; Cell(Cell&& x) noexcept : p(std::exchange(x.p, nullptr)) {} int get() const { return p ? *p : 0; } };
int main() { Cell a{20}; Cell b(std::move(a)); std::cout << a.get() << " " << b.get() << "\n"; }
```

Ожидаемый вывод:

```text
0 20
```

## Разбор и эксперимент

Поместите перемещённый объект во внутренний блок и выйдите из него: источник должен остаться допустимым пустым объектом. Затем переместите уже пустой источник ещё раз и проверьте, что ничего не падает.

### Источник обязан потерять право освобождения

Перемещающий конструктор T(T&amp;&amp; other) создаёт нового владельца из обречённого источника. Для владеющего указателя недостаточно скопировать адрес: other.p должен стать null, иначе два деструктора удалят один блок. std::exchange(other.p, nullptr) делает обе половины одной операцией — возвращает старое значение и записывает новое.

Переносите инвариант целиком. Если у объекта поля data и size, передача только data оставит у источника size прежним: его empty() будет лгать, а деструктор — освобождать по неверной длине. Тот же принцип для deleter с состоянием: указатель, выделенный аллокатором A, нельзя отдать владельцу с deleter от аллокатора B.

noexcept на move-конструкторе — не украшение. std::vector при росте перемещает элементы только если перемещение noexcept или копия недоступна; бросающий move заставит контейнер копировать. Но noexcept обязан быть правдой: исключение из noexcept-функции — это std::terminate. Передача указателя с обнулением не бросает, поэтому здесь noexcept обоснован; new внутри — уже нет.

<CommonMistake title="Граница корректности">

Неправильный move-конструктор часто компилируется и выдаёт верные значения до выхода из области: ошибка проявляется во втором delete при разрушении. Проверяйте разрушение обоих объектов, а не только напечатанные значения.

</CommonMistake>

Второе содержит дефектный исходник: исправьте владение, сохранив требуемое поведение. Код диагноза проверяется автоматически; пояснение в комментарии служит самопроверке. Оба задания нужны для завершения практики.

### Фрагмент 0

```cpp
// ~Cell вызывает delete p.
Cell(Cell&& other) noexcept : p(other.p) {}
```

### Фрагмент 1

```cpp
Cell(Cell&& other) noexcept : p(other.p) { other.p = nullptr; }
```

### Фрагмент 2

```cpp
Cell(Cell&& other) : p(std::exchange(other.p, nullptr)) {}
```

```cpp
auto src = std::make_unique<int>(2); int* raw = src.get(); src.reset(); int v = *raw;
```
