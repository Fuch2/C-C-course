## Как забрать ресурс

**Перемещающий конструктор** `T(T &&other)` создаёт объект, забирая ресурсы у `other`. Для класса, который владеет памятью через указатель, это значит: взять указатель себе, а у источника оставить пустое, но корректное состояние — чтобы его деструктор ничего не освободил повторно.

Удобнее всего это делать функцией `std::exchange` (C++14): она присваивает переменной новое значение и возвращает старое.

```cpp
#include <algorithm>
#include <cstddef>
#include <print>
#include <utility>

class Buffer {
public:
    Buffer(std::size_t size, int fill) : size_(size), data_(new int[size]) {
        std::fill_n(data_, size_, fill);
    }
    Buffer(const Buffer &other) : size_(other.size_), data_(new int[other.size_]) {
        std::copy_n(other.data_, size_, data_);
        std::println("копия: новый буфер");
    }
    Buffer(Buffer &&other) noexcept
        : size_(std::exchange(other.size_, 0)), data_(std::exchange(other.data_, nullptr)) {
        std::println("перемещение: тот же буфер");
    }
    Buffer &operator=(const Buffer &) = delete;
    ~Buffer() {
        delete[] data_;
    }

    std::size_t size() const {
        return size_;
    }

private:
    std::size_t size_;
    int *data_;
};

int main() {
    Buffer a(1000, 7);
    Buffer b = a;
    Buffer c = std::move(a);
    std::println("{} {} {}", a.size(), b.size(), c.size());
    return 0;
}
```

Вывод:

```text
копия: новый буфер
перемещение: тот же буфер
0 1000 1000
```

После перемещения `a` пуст: размер 0, указатель `nullptr`. Его деструктор выполнит `delete[] nullptr` — это законно и ничего не делает. Тысяча чисел не копировалась ни разу.

<MemoryDiagram title="Перемещающий конструктор">

```text
до:      a.data_ ──▶ [7 7 … 7]          c ещё не создан
после:   a.data_ = nullptr, a.size_ = 0
         c.data_ ──▶ [7 7 … 7]          тот же блок, без копирования
конец:   ~c: delete[] блок    ~a: delete[] nullptr — ничего
```

</MemoryDiagram>

## Почему noexcept так важен

Когда `std::vector` растёт, он переносит элементы в новый буфер. Если перенос сломается на середине из-за исключения, вектор обязан остаться прежним (строгая гарантия). Копирование это позволяет — оригиналы целы. Перемещение — нет: часть элементов уже «выпотрошена». Поэтому вектор перемещает элементы при росте, **только если перемещающий конструктор объявлен `noexcept`**, иначе копирует (функция `std::move_if_noexcept`).

```cpp
#include <print>
#include <vector>

struct Fast {
    Fast() = default;
    Fast(const Fast &) {
        ++copies;
    }
    Fast(Fast &&) noexcept {
        ++moves;
    }
    static inline int copies = 0;
    static inline int moves = 0;
};

struct Slow {
    Slow() = default;
    Slow(const Slow &) {
        ++copies;
    }
    Slow(Slow &&) {
        ++moves;
    }
    static inline int copies = 0;
    static inline int moves = 0;
};

int main() {
    std::vector<Fast> fast;
    std::vector<Slow> slow;
    for (int i = 0; i < 5; ++i) {
        fast.emplace_back();
        slow.emplace_back();
    }
    std::println("Fast: копий {}, перемещений {}", Fast::copies, Fast::moves);
    std::println("Slow: копий {}, перемещений {}", Slow::copies, Slow::moves);
    return 0;
}
```

Вывод (libstdc++):

```text
Fast: копий 0, перемещений 7
Slow: копий 7, перемещений 0
```

В libstdc++ ёмкость растёт как 1, 2, 4, 8, поэтому при росте было семь переносов: один элемент, затем два, затем четыре. Без `noexcept` все они — копии. Для вектора строк или буферов это разница между переносом указателей и полным копированием всех данных. Перемещение, которое только переставляет указатели, не может бросить исключение — объявляйте его `noexcept`.

## Неявный перемещающий конструктор

Компилятор создаёт перемещающий конструктор сам — поэлементное перемещение баз и полей, — если в классе **не объявлены** копирующие операции, перемещающее присваивание и деструктор. Для класса из строк, векторов и умных указателей он правильный и `noexcept`, когда таковы перемещения полей.

Если объявить хотя бы деструктор или конструктор копирования, неявного перемещения **не будет**: вместо него молча используется копирование. Вернуть его можно явно: `T(T &&) noexcept = default;`.

<Concept title="Перемещающий конструктор">

`T(T &&other) noexcept` создаёт объект, забирая ресурсы `other`, и оставляет `other` пустым, но разрушаемым и присваиваемым; для указателей это удобно делать через `std::exchange`. Перемещающий конструктор должен быть `noexcept`, иначе `std::vector` при росте будет копировать. Неявный перемещающий конструктор создаётся, только если в классе нет пользовательских копирующих операций, перемещающего присваивания и деструктора; `= default` возвращает его явно.

</Concept>

## Частые ошибки

<CommonMistake title="Источник не обнулён">

`Buffer(Buffer &&o) : data_(o.data_) {}` — теперь блоком владеют оба, и два деструктора освободят его дважды. Указатель источника обязательно обнулить: `std::exchange(o.data_, nullptr)`.

</CommonMistake>

<CommonMistake title="Перемещение без noexcept">

Вектор при росте будет копировать элементы, и выгоды от перемещения не будет там, где она нужнее всего. Компилятор не предупреждает.

</CommonMistake>

<CommonMistake title="Деструктор «для отладки» отключил перемещение">

Добавили в класс пустой `~T() {}` — и неявное перемещение исчезло, все перемещения стали копиями. Не объявляйте деструктор без необходимости или добавьте `= default` для перемещения.

</CommonMistake>

## Практика

1. **Перемещаемый буфер** — сколько выделений памяти стоит работа с вектором буферов.
2. **noexcept и рост вектора** — копии и перемещения при росте.
3. **Найди ошибку: два владельца после перемещения** — источник не обнулён.
4. **Связный список** — глубокое копирование и перемещение за O(1).

## Итоги

- Перемещающий конструктор забирает ресурсы и оставляет источник пустым и разрушаемым.
- Указатели источника обнуляют — удобно через `std::exchange`.
- Перемещение объявляют `noexcept`, иначе вектор при росте копирует.
- Неявный перемещающий конструктор пропадает, если объявлены копирование или деструктор; `= default` возвращает его.
