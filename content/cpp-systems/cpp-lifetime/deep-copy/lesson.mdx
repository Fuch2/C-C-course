## Цели обучения

- Определять, какие поля требуют дублирования, по семантике владения типа.
- Проследить на MemoryDiagram независимость двух буферов после копирования.
- Реализовать Buffer с независимой копией и объяснить стоимость глубокого копирования.

## Модель и назначение

Глубокая копия создаёт независимые ресурсы там, где этого требует семантика значения: для буфера это новый массив и поэлементное копирование. «Глубокая» не означает «рекурсивно скопировать каждый указатель»: часть указателей может быть невладеющей ссылкой на общий сервис, кеш или родителя. Сначала решите, какие поля выражают владение, — только они требуют дублирования.

## Механика и гарантии

Копирование буфера из n элементов стоит O(n) времени и O(n) памяти — при необходимой независимости это неизбежно. При неуспехе на середине частично заполненный буфер должен очищаться: vector гарантирует это сам. Если элементы vector — shared_ptr, копируется участие в владении, а объекты за указателями остаются общими: vector не гарантирует независимость всего графа. Для графов с общими подграфами и циклами нужен словарь соответствия старых узлов новым; для полиморфных объектов — виртуальный clone.

<MemoryDiagram title="Время жизни и связи владения">

```text
original → буфер A: 1 2 3
copy → буфер B: 1 2 3; адреса A и B различаются
copy[0] = 99 → B: 99 2 3
A остаётся 1 2 3 — значения независимы
```

</MemoryDiagram>

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { std::vector<int> original{1, 2, 3}; auto copy = original; copy[0] = 99; std::cout << original[0] << " " << copy[0] << " " << original.size() << "\n"; }
```

Ожидаемый вывод:

```text
1 99 3
```

## Разбор и эксперимент

Замените vector&lt;int> на vector&lt;shared_ptr&lt;int>> и предскажите, изменится ли объект через копию. Объясните, какой уровень структуры стал независимым, а какой остался общим.

### Глубина определяется договором, а не рекурсией

«Глубокая копия» не значит «рекурсивно скопировать всё, до чего дотянулись указатели». Часть указателей может быть намеренно невладеющей: ссылка на общий сервис, кеш, родительский узел. Скопировав их, вы сломаете архитектуру разделения. Сначала решите, какие поля выражают владение, — только они требуют дублирования ресурсов.

Для буфера из n элементов глубокая копия стоит O(n) времени и O(n) памяти — это неизбежно, если нужна независимость. При неудаче на середине копирования частично заполненный буфер обязан очиститься: либо используйте vector (он гарантирует это сам), либо ловите исключение и удаляйте за собой.

Отдельный случай — графы с общими подграфами и циклами. Независимое клонирование каждого поля удвоит общие узлы и зациклится на кольцах. Нужен словарь «старый узел → новый», который сохраняет топологию и прерывает циклы. Для полиморфных типов эту задачу решает виртуальный clone().

<CommonMistake title="Граница корректности">

Побайтовый memcpy класса с vector или string разрушает инварианты владельца: копируются внутренние адреса представления. Копируйте объекты их операциями, а не сырыми байтами.

</CommonMistake>

## Практика

Создайте Buffer с vector&lt;int>. solve заполняет original значениями &#123;a, b&#125;, копирует Buffer, заменяет первый элемент копии на b и возвращает original[0] + copy[0]. Не используйте общий динамический массив для двух Buffer.
