## Копия со своими данными

**Глубокая копия** создаёт не только новый объект, но и новые копии всего, чем он владеет. После неё у оригинала и копии нет общих данных: каждый освобождает своё, и изменения одного не видны другому. Так копируются `std::string`, `std::vector` и остальные контейнеры — поэтому типы из них ведут себя как значения.

Если класс сам владеет памятью через сырой указатель, глубокое копирование нужно написать вручную — в конструкторе копирования и в операторе присваивания:

```cpp
#include <print>
#include <utility>

class Box {
public:
    explicit Box(int value) : value_(new int(value)) {}
    Box(const Box &other) : value_(new int(*other.value_)) {}
    Box &operator=(const Box &other) {
        Box copy(other);
        std::swap(value_, copy.value_);
        return *this;
    }
    ~Box() {
        delete value_;
    }

    int get() const {
        return *value_;
    }
    void set(int v) {
        *value_ = v;
    }

private:
    int *value_;
};

void show(Box box) {
    box.set(box.get() * 10);
    std::println("в функции {}", box.get());
}

int main() {
    Box a(7);
    show(a);
    Box b(1);
    b = a;
    a.set(8);
    std::println("{} {}", a.get(), b.get());
    return 0;
}
```

Вывод:

```text
в функции 70
8 7
```

Копия в `show` получила свой `int`, изменила его и удалила при выходе — оригинал не пострадал. После `b = a` у `b` тоже свой `int`: изменение `a` его не задело. Каждое `new` теперь имеет ровно одного владельца.

```text
поверхностная:  a.value_ ──▶ [ 7 ] ◀── b.value_      один блок, два владельца ✗

глубокая:       a.value_ ──▶ [ 7 ]                    у каждого свой блок ✓
                b.value_ ──▶ [ 7 ]
```

## Глубокая копия структуры

Если объект владеет не одним значением, а целой структурой — списком, деревом, графом, — глубокая копия должна обойти её всю. Для дерева это естественно делать рекурсией: скопировать узел, затем его поддеревья.

```cpp
#include <print>
#include <utility>

struct Node {
    int value;
    Node *left = nullptr;
    Node *right = nullptr;
};

Node *clone(const Node *n) {
    if (n == nullptr) {
        return nullptr;
    }
    return new Node{n->value, clone(n->left), clone(n->right)};
}

void destroy(Node *n) {
    if (n != nullptr) {
        destroy(n->left);
        destroy(n->right);
        delete n;
    }
}

class Tree {
public:
    Tree() = default;
    Tree(const Tree &other) : root_(clone(other.root_)) {}
    Tree &operator=(const Tree &other) {
        Tree copy(other);
        std::swap(root_, copy.root_);
        return *this;
    }
    ~Tree() {
        destroy(root_);
    }

    void insert(int v) {
        Node **slot = &root_;
        while (*slot != nullptr) {
            slot = v < (*slot)->value ? &(*slot)->left : &(*slot)->right;
        }
        *slot = new Node{v};
    }

    int count() const {
        return count(root_);
    }

private:
    static int count(const Node *n) {
        return n == nullptr ? 0 : 1 + count(n->left) + count(n->right);
    }

    Node *root_ = nullptr;
};

int main() {
    Tree a;
    for (int v : {5, 3, 8, 1}) {
        a.insert(v);
    }
    Tree b = a;
    b.insert(9);
    std::println("{} {}", a.count(), b.count());
    return 0;
}
```

Вывод:

```text
4 5
```

`clone` создаёт новый узел для каждого узла оригинала. Копия `b` — отдельное дерево, и вставка в неё не меняет `a`. Деструкторы двух деревьев освобождают каждый свои узлы.

## Цена и альтернативы

Глубокая копия стоит пропорционально размеру данных: скопировать дерево из миллиона узлов — миллион выделений памяти. Поэтому:

- тяжёлые объекты передают по константной ссылке, а не по значению;
- когда объект больше не нужен оригиналу, его **перемещают**, а не копируют (уроки о семантике перемещения);
- если копий много, а меняют их редко, данные делают общими и неизменяемыми через `std::shared_ptr<const T>` и копируют только при изменении (copy-on-write).

Копия полиморфного объекта, известного по указателю на базу, делается виртуальной функцией `clone()` — вы встречали её в уроке о срезке.

<Concept title="Глубокое копирование">

Глубокая копия копирует всё, чем владеет объект, и не оставляет общих данных: у каждой копии свои ресурсы и свой деструктор их освобождает. Для класса с владеющим сырым указателем её пишут в конструкторе копирования (выделить и скопировать) и в операторе присваивания (copy-and-swap). Структуры — списки, деревья, графы — копируют обходом всей структуры. Глубокая копия дорога: тяжёлые объекты передают по ссылке или перемещают.

</Concept>

## Частые ошибки

<CommonMistake title="Глубокий конструктор, поверхностное присваивание">

Написали конструктор копирования, а оператор `=` оставили неявным — он скопирует указатель. Глубокое копирование нужно в обеих операциях, и деструктор — третья часть того же набора (урок «Правило трёх»).

</CommonMistake>

<CommonMistake title="Копирование только верхнего уровня структуры">

Скопировать корень дерева, но оставить старые указатели на детей — получить смесь глубокой и поверхностной копии с двойным освобождением поддеревьев.

</CommonMistake>

<CommonMistake title="Глубокая копия там, где нужна ссылка">

`void print(Tree t)` копирует всё дерево ради чтения. Передавайте `const Tree &`.

</CommonMistake>

## Практика

1. **Матрица** — класс с массивом в куче и глубоким копированием.
2. **Копия дерева** — рекурсивная глубокая копия.
3. **Найди ошибку: забытое присваивание** — глубокий конструктор и поверхностный `operator=`.
4. **Копия графа** — глубокая копия структуры с общими узлами и циклами.

## Итоги

- Глубокая копия создаёт собственные копии всех ресурсов; общих данных не остаётся.
- Для владеющего сырого указателя её пишут в конструкторе копирования и в операторе присваивания.
- Структуры копируют обходом: узел и все его потомки.
- Глубокая копия дорога: передавайте тяжёлые объекты по ссылке, перемещайте ненужные.
- Контейнеры стандартной библиотеки копируются глубоко сами — лучший способ получить глубокую копию бесплатно.
