## Цели обучения

- Перечислить операции, меняющие сильный счётчик, и операции, которые его не меняют.
- Проследить на MemoryDiagram счётчик через копию, ссылку, перемещение и выход из блока.
- Вычислить use_count в каждой точке трассировки и объяснить расхождение объекта и блока управления.

## Модель и назначение

Счётчик сильных владельцев меняется при копировании, разрушении, reset и присваивании shared_ptr. Ссылка shared_ptr&lt;T>&amp; нового владельца не создаёт и счётчик не увеличивает; перемещение передаёт существующую долю, оставляя источник пустым. use_count удобен для учебной трассировки в одном потоке, но не является протоколом блокировки: в многопоточной программе значение устаревает в момент возврата.

## Механика и гарантии

Объект и блок управления живут по разным часам. При исчезновении последнего сильного владельца объект уничтожается; слабые наблюдатели могут удерживать блок управления, чтобы узнавать о смерти объекта. При make_shared объект и блок часто размещены в одном выделении, поэтому память возвращается аллокатору только после исчезновения слабых ссылок, хотя деструктор T уже выполнен. Проверка if (use_count() == 1) «можно менять безопасно» — ложное право: состояние может измениться между чтением и использованием.

Схема показывает логические объекты и отношения, а не реальную раскладку ABI. Сплошная стрелка означает владение, пунктирная — заимствование. Исчезновение имени и уничтожение объекта проверяйте отдельно.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

int main() { auto p = std::make_shared<int>(1); { auto q = p; auto& ref = q; (void)ref; auto r = std::move(q); std::cout << p.use_count() << " "; } std::cout << p.use_count() << "\n"; }
```

Ожидаемый вывод:

```text
2 1
```

## Разбор и эксперимент

Добавьте функцию read(shared_ptr&lt;int> p) и сравните счётчик внутри неё с read(const shared_ptr&lt;int>&amp; p). Если функция только читает int, рассмотрите ещё более простой const int&amp;.

### Счётчик — не протокол блокировки

Сильный счётчик меняется при копировании, разрушении, reset и присваивании shared_ptr. Ссылка shared_ptr&lt;T>&amp; нового владельца не создаёт и счётчик не увеличивает. Перемещение передаёт существующую долю, оставляя источник пустым: суммарно сильных не прибавилось.

use_count() полезен в учебной трассировке однопоточного кода, но в многопоточной программе он устаревает в момент возврата: между чтением и использованием другой поток может уничтожить последнего владельца. Проверка if (use_count() == 1) «можно менять безопасно» — ложная: это не право, а снимок прошлого.

Объект и блок управления живут по разным часам. При make_shared они часто размещены в одном выделении: объект разрушается при нуле сильных, но память возвращается аллокатору только после исчезновения слабых наблюдателей. Формулировка «объект уничтожен, когда счётчик ноль» верна; «вся память освобождена, когда счётчик ноль» — уже нет.

<CommonMistake title="Граница корректности">

use_count() == 1 не даёт права менять объект без синхронизации в многопоточном коде. Счётчик — снимок прошлого, а не гарантия будущего.

</CommonMistake>
