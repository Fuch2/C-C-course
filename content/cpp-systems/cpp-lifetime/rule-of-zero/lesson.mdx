## Цели обучения

- Объяснить, как компилятор составляет операции класса из операций его членов.
- Проследить на MemoryDiagram независимость копий, обеспеченную одним vector.
- Реализовать Report без специальных операций и найти границу применимости правила.

## Модель и назначение

Предметный класс обычно не должен вручную управлять освобождением: поля string, vector и unique_ptr уже реализуют все необходимые операции. Правило нуля предлагает не объявлять собственные деструктор и специальные операции, когда готовые члены выражают нужное владение, — компилятор составит операции класса из операций его членов. Каждый не написанный вручную деструктор — это не написанная потенциальная ошибка.

## Механика и гарантии

У Report с vector&lt;int> копирование даёт независимые элементы, а перемещение может передать буфер. У Report с unique_ptr копирование недоступно, а перемещение обычно генерируется — это не недостаток: тип сообщает, что ресурс исключительный. Правило нуля не доказывает инварианты автоматически: если объект хранит сырой указатель внутрь своего vector, неявная копия скопирует старый адрес, а реаллокация при перемещении его обесценит. Храните индекс или вычисляйте представление по запросу.

## Запускаемый пример

```cpp
#include <iostream>
#include <memory>
#include <vector>
#include <utility>
#include <string>

struct Report { std::vector<int> samples; };
int main() { Report a{{8, 2}}; auto b = a; b.samples[0] = 4; std::cout << a.samples[0] << " " << b.samples[0] << "\n"; }
```

Ожидаемый вывод:

```text
8 4
```

## Разбор и эксперимент

Добавьте поле std::string title и проверьте независимость копии. Затем добавьте сырой указатель на элемент vector и объясните, почему правило нуля перестало обеспечивать нужный смысл копии.

### Лучшая специальная функция — ненаписанная

Правило нуля: предметный класс не объявляет деструктор и специальные операции вовсе, если его поля уже владеют ресурсами через string, vector, unique_ptr. Компилятор составляет операции класса из операций членов — и эти операции уже проверены миллионами запусков. Каждый не написанный вручную деструктор — это не написанная потенциальная ошибка.

Граница ответственности: Report с vector&lt;int> samples следует правилу нуля; низкоуровневый FileHandle, оборачивающий FILE\*, — правилу пяти. Оба живут в одной программе на разных этажах. Правило нуля не отменяет правило пяти — оно переносит его в один переиспользуемый слой.

Осторожность с правилом нуля нужна в одном случае: связанные поля. Если объект хранит vector и сырой указатель внутрь его буфера, неявная копия скопирует старый адрес, а перемещение с реаллокацией его обесценит. Такой кеш — кандидат на удаление: храните индекс или вычисляйте представление по запросу. Инвариант, который нельзя выразить типами полей, придётся выражать пятью функциями.
