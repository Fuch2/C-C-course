## Инициализация или присваивание

Знак `=` в C++ означает две разные операции:

- `Tracer c = a;` — **инициализация**: объекта `c` ещё нет, его создаёт конструктор копирования;
- `b = a;` — **присваивание**: объект `b` уже существует, у него есть своё состояние и, возможно, свои ресурсы. Работает **оператор копирующего присваивания** `operator=`.

```cpp
#include <print>
#include <string>
#include <utility>

struct Tracer {
    std::string name;

    explicit Tracer(std::string n) : name(std::move(n)) {}
    Tracer(const Tracer &other) : name(other.name) {
        std::println("конструктор копирования: {}", name);
    }
    Tracer &operator=(const Tracer &other) {
        std::println("присваивание: {} ← {}", name, other.name);
        name = other.name;
        return *this;
    }
};

int main() {
    const Tracer a("a");
    Tracer b("b");
    const Tracer c = a;
    b = a;
    std::println("{} {} {}", a.name, b.name, c.name);
    return 0;
}
```

Вывод:

```text
конструктор копирования: a
присваивание: b ← a
a a a
```

Главное отличие: присваивание должно сначала **избавиться от старого** состояния. Для строки это значит освободить старый буфер (или переиспользовать его), для владельца файла — закрыть старый файл.

## Неявное присваивание и правила оператора

Если оператор не объявлен, компилятор создаёт его сам: он присваивает базы и поля по очереди их собственными операторами `=`. Для типов-значений этого достаточно — `std::string` и `std::vector` сами правильно обращаются со старыми данными.

Свой оператор пишут по устоявшимся правилам:

- сигнатура `T &operator=(const T &other)`;
- возвращает `*this` по ссылке — чтобы работали цепочки `a = b = c` и выражения вроде `(a = b).method()`;
- корректно работает при **самоприсваивании** `a = a` — оно редко пишется явно, но легко получается через ссылки: `items[i] = items[j]` при `i == j`;
- при исключении оставляет объект в прежнем, целом состоянии.

## Присваивание владельца ресурса

Сложнее всего — классу, который сам владеет памятью. Наивная версия выглядит естественно, но ломается при самоприсваивании:

```cpp
Buffer &operator=(const Buffer &other) {
    delete[] data_;                          // освободили своё…
    size_ = other.size_;
    data_ = new int[size_];
    std::copy_n(other.data_, size_, data_);  // …а при b = b other — это сам объект:
    return *this;                            // копируем новый пустой буфер в себя, данные потеряны
}
```

И при исключении тоже: если `new` бросит `std::bad_alloc`, старые данные уже удалены, а `data_` указывает на освобождённую память — объект испорчен.

Надёжный способ — идиома **copy-and-swap**: сначала сделать полную копию (если что-то бросит, `*this` ещё не тронут), затем обменяться с ней содержимым. Старые данные уйдут вместе с копией в её деструкторе:

```cpp
#include <algorithm>
#include <cstddef>
#include <print>
#include <utility>

class Buffer {
public:
    Buffer(std::size_t size, int fill) : size_(size), data_(new int[size]) {
        std::fill_n(data_, size_, fill);
    }
    Buffer(const Buffer &other) : size_(other.size_), data_(new int[other.size_]) {
        std::copy_n(other.data_, size_, data_);
    }
    Buffer &operator=(const Buffer &other) {
        Buffer copy(other);
        std::swap(size_, copy.size_);
        std::swap(data_, copy.data_);
        return *this;
    }
    ~Buffer() {
        delete[] data_;
    }

    void set(std::size_t i, int value) {
        data_[i] = value;
    }

    void print() const {
        for (std::size_t i = 0; i < size_; ++i) {
            std::print("{} ", data_[i]);
        }
        std::println("({} шт.)", size_);
    }

private:
    std::size_t size_;
    int *data_;
};

int main() {
    Buffer a(3, 7);
    Buffer b(5, 1);
    b = a;
    Buffer &same = b;  // самоприсваивание через ссылку
    b = same;
    a.set(0, 9);
    a.print();
    b.print();
    return 0;
}
```

Вывод:

```text
9 7 7 (3 шт.)
7 7 7 (3 шт.)
```

Самоприсваивание безопасно: копия делается **до** того, как что-либо удалено. (Буквальное `b = b;` Clang отметил бы предупреждением `-Wself-assign-overloaded`, поэтому в примере оно сделано через ссылку — так самоприсваивание и возникает в настоящем коде.) Изменение `a` не задело `b` — у каждого свой буфер. И ни одного `delete[]` в операторе: старый буфер `b` освободил деструктор `copy`.

<MemoryDiagram title="copy-and-swap: b = a">

```text
1. Buffer copy(a)       copy.data_ ─▶ [7 7 7]   (новый буфер; если бросит — b не тронут)
2. swap                 b.data_    ─▶ [7 7 7]
                        copy.data_ ─▶ [1 1 1 1 1]   (старый буфер b)
3. выход из operator=   ~copy() освобождает [1 1 1 1 1]
```

</MemoryDiagram>

<Tip title="Лучше всего — не писать оператор вовсе">

Буфер здесь написан вручную, чтобы показать механику. В реальном коде поле `std::vector<int>` даёт правильные копирование, присваивание и освобождение бесплатно — неявные операции класса просто вызовут операции вектора. Об этом урок «Правило нуля».

</Tip>

<Concept title="Копирующее присваивание">

`b = a` для существующего `b` вызывает `T &operator=(const T &)`: он заменяет старое состояние новым и возвращает `*this`. Неявный оператор присваивает поля по очереди — для типов-значений этого достаточно. Свой оператор обязан работать при самоприсваивании и при исключениях; идиома copy-and-swap решает обе задачи: сначала полная копия, затем обмен, старое освобождает деструктор копии. Если класс копируется особым образом, конструктор копирования и присваивание должны быть согласованы.

</Concept>

## Частые ошибки

<CommonMistake title="Сначала удалить, потом копировать">

`delete[] data_; … copy(other.data_ …)` теряет данные при `a = a` и оставляет испорченный объект, если выделение памяти бросит. Сначала копия, потом обмен.

</CommonMistake>

<CommonMistake title="Утечка старого ресурса">

`data_ = new int[n]; copy(…);` без освобождения прежнего буфера — утечка при каждом присваивании. В copy-and-swap старое освобождает деструктор временной копии.

</CommonMistake>

<CommonMistake title="operator= без return *this">

Выход из не-void функции без `return` — неопределённое поведение, а цепочки `a = b = c` перестают работать. Всегда `return *this;`.

</CommonMistake>

## Практика

1. **Места в зале** — присваивание, которое сохраняет номер билета.
2. **Буфер** — copy-and-swap для класса, владеющего памятью.
3. **Найди ошибку: строка присвоила сама себя** — наивное присваивание и самоприсваивание.
4. **Склад со строгой гарантией** — присваивание, которое при ошибке ничего не меняет.

## Итоги

- Инициализация создаёт объект (конструктор копирования), присваивание меняет существующий (`operator=`).
- Оператор присваивания возвращает `*this` и заменяет старое состояние новым.
- Самоприсваивание и исключения — главные ловушки своего оператора.
- copy-and-swap: полная копия, обмен, старое освобождает деструктор копии.
- Лучший оператор присваивания — неявный, когда поля сами умеют копироваться.
