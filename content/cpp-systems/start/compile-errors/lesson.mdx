## Компилятор — ваш первый помощник

Ошибки компиляции пугают новичков: на экране появляется стена текста на английском. На самом деле это лучшие ошибки из возможных. Компилятор нашёл проблему **до запуска**, указал файл, строку и позицию, а часто ещё и подсказал исправление. Ошибки, которые проявляются только во время работы программы, искать гораздо труднее.

В этом уроке вы научитесь читать сообщения компилятора и исправлять самые частые ошибки. Все сообщения ниже — настоящие: их выдаёт GCC, которым проверяются задачи курса. Каждый пример можно запустить и увидеть сообщение целиком.

## Анатомия сообщения об ошибке

Возьмём программу с забытой точкой с запятой:

```c
#include <stdio.h>

int main(void) {
    printf("Привет\n")    // Ошибка компиляции
    return 0;
}
```

GCC сообщит:

```text
main.c: In function 'main':
main.c:4:23: error: expected ';' before 'return'
    4 |     printf("Привет\n")
      |                       ^
      |                       ;
    5 |     return 0;
      |     ~~~~~~
```

Разберём по частям:

| Фрагмент                       | Значение                                                          |
| ------------------------------ | ----------------------------------------------------------------- |
| `In function 'main'`           | Ошибка внутри функции `main`                                      |
| `main.c:4:23`                  | Файл `main.c`, строка 4, позиция 23 в строке                      |
| `error`                        | Это ошибка: программа не будет собрана                            |
| `expected ';' before 'return'` | «Ожидалась `;` перед `return`»                                    |
| Строки с `^` и `;`             | Компилятор показывает место и предлагает вставить точку с запятой |

Обратите внимание: компилятор заметил проблему, только дойдя до слова `return` на строке 5, но указал на конец строки 4 — туда, где должна была стоять точка с запятой. Однако так бывает не всегда.

<Important title="Ошибка бывает выше, чем указано">

Компилятор сообщает о месте, где он **понял**, что что-то не так. Сама ошибка может находиться раньше — в конце предыдущей строки или даже несколькими строками выше. Если на указанной строке всё в порядке, посмотрите на строки над ней.

</Important>

## Три правила чтения ошибок

1. **Исправляйте первую ошибку.** Одна опечатка может породить десяток сообщений: компилятор «сбивается» и дальше видит ошибки там, где их нет. Исправьте первую, скомпилируйте снова — часто остальные исчезнут.
2. **Найдите ключевые слова.** Сообщения строятся из небольшого набора английских слов. Словарик ниже покрывает большинство случаев в этом модуле.
3. **Читайте подсказки.** Фраза `did you mean` («возможно, вы имели в виду») и строки с предложенным исправлением часто содержат готовый ответ.

| Слово в сообщении      | Перевод                                   |
| ---------------------- | ----------------------------------------- |
| `error`                | ошибка                                    |
| `warning`              | предупреждение                            |
| `expected`             | ожидалось                                 |
| `before`               | перед                                     |
| `undeclared`           | не объявлено                              |
| `did you mean`         | возможно, вы имели в виду                 |
| `missing terminating`  | нет закрывающего (символа)                |
| `implicit declaration` | неявное объявление — функция не объявлена |
| `undefined reference`  | ссылка на то, чего не существует          |
| `at end of input`      | в конце файла                             |
| `token`                | элемент кода: слово, число, знак          |

## Ошибка 1: нет закрывающей кавычки

```c
#include <stdio.h>

int main(void) {
    printf("Привет\n);    // Ошибка компиляции
    return 0;
}
```

```text
main.c:4:12: error: missing terminating " character
    4 |     printf("Привет\n);
      |            ^~~~~~~~~~~
main.c:5:5: error: expected expression before 'return'
```

Первое сообщение точно описывает проблему: у строки нет закрывающей кавычки. Компилятор считает, что строка тянется до конца строки кода, вместе со скобкой и точкой с запятой. Второе и следующие сообщения — следствия первого. Добавьте кавычку перед `)` — исчезнут все.

## Ошибка 2: опечатка в имени переменной

```c
#include <stdio.h>

int main(void) {
    int sum = 2 + 3;
    printf("%d\n", summ);    // Ошибка компиляции
    return 0;
}
```

```text
main.c:5:20: error: 'summ' undeclared (first use in this function); did you mean 'sum'?
    5 |     printf("%d\n", summ);
      |                    ^~~~
      |                    sum
```

`undeclared` — имя `summ` нигде не объявлено. Компилятор даже нашёл похожее имя и предложил `sum`. Заодно он предупредит, что переменная `sum` не используется: пока в программе опечатка, это действительно так.

## Ошибка 3: опечатка в имени функции

```c
#include <stdio.h>

int main(void) {
    prinft("Привет\n");    // Ошибка компиляции
    return 0;
}
```

```text
main.c:4:5: error: implicit declaration of function 'prinft'; did you mean 'printf'? [-Wimplicit-function-declaration]
    4 |     prinft("Привет\n");
      |     ^~~~~~
      |     printf
```

`implicit declaration` — «неявное объявление»: компилятор встретил вызов функции `prinft`, о которой ничего не знает, и сразу предложил похожее имя `printf`. В квадратных скобках — название проверки, которая сработала.

В старых книгах и на форумах можно прочитать, что это лишь предупреждение и программа всё равно соберётся. Так было до GCC 14 (2024 год): компилятор «додумывал» объявление функции и надеялся на лучшее. Стандарт C запрещает вызывать необъявленные функции ещё с 1999 года, а современные GCC и Clang считают это ошибкой.

## Ошибка 4: забыт `#include`

```c
int main(void) {
    printf("Привет\n");    // Ошибка компиляции: нет #include <stdio.h>
    return 0;
}
```

```text
main.c:2:5: error: implicit declaration of function 'printf' [-Wimplicit-function-declaration]
main.c:1:1: note: include '<stdio.h>' or provide a declaration of 'printf'
  +++ |+#include <stdio.h>
```

То же сообщение `implicit declaration`, но имя написано верно. Значит, компилятор не знает функцию, потому что её объявление не подключено. Строка `note` («заметка») прямо говорит, что делать: добавить `#include <stdio.h>`, а строка с `+++` показывает, куда именно.

## Ошибка 5: имя `main` с ошибкой

```c
#include <stdio.h>

int Main(void) {    // Ошибка компоновки: нужна функция main
    printf("Привет\n");
    return 0;
}
```

```text
/usr/bin/ld: Scrt1.o: in function `_start':
(.text+0x1c): undefined reference to `main'
collect2: error: ld returned 1 exit status
```

Компилятор перевёл эту программу без единого замечания: функция `Main` с большой буквы — законное имя. Сообщение пришло от другой программы — **компоновщика** (линковщика, `ld`). Он собирает готовую программу из частей и не нашёл функцию `main`, с которой программа должна начинаться: в C большие и маленькие буквы различаются. `undefined reference to` — «ссылка на несуществующее»: что-то используется, но нигде не определено. О компоновщике подробно поговорим в модуле «Инструменты разработчика». Пока запомните: сообщение `undefined reference to` почти всегда означает опечатку в имени функции или её отсутствие.

## Ошибка 6: потерялась фигурная скобка

```c
#include <stdio.h>

int main(void) {
    printf("Привет\n");
    return 0;
    // Ошибка компиляции: нет закрывающей }
```

```text
main.c:5:5: error: expected declaration or statement at end of input
```

`at end of input` — «в конце файла». Компилятор дошёл до конца файла, а функция так и не закрылась. Такую ошибку легко найти, если код аккуратно выровнен: каждая `}` стоит строго под началом строки, где открылась соответствующая `{`.

## Как действовать, когда сборка не прошла

1. Найдите **первую** строку со словом `error`.
2. Прочитайте номер строки и посмотрите на неё **и на строку выше**.
3. Переведите ключевые слова сообщения по словарику.
4. Исправьте одну проблему и скомпилируйте снова.
5. Если сообщение непонятно, переключите компилятор на Clang: его формулировки иногда яснее.

<Tip title="Компилируйте почаще">

Чем меньше кода вы написали с последней успешной компиляции, тем проще найти ошибку. Опытные программисты компилируют после каждых нескольких строк.

</Tip>

## Частые ошибки при исправлении ошибок

<CommonMistake title="Исправлять все сообщения сразу">

Двадцать сообщений не означают двадцать ошибок. Часто это одна пропущенная кавычка или скобка. Исправьте первое — и посмотрите, что осталось.

</CommonMistake>

<CommonMistake title="Искать ошибку только на указанной строке">

Пропущенная точка с запятой или скобка обнаруживается на следующей строке. Если строка из сообщения выглядит правильной, смотрите выше.

</CommonMistake>

<CommonMistake title="Править наугад">

Если не понимаете сообщение, не меняйте код случайным образом: так появляются новые ошибки. Переведите сообщение и найдите похожий пример в этом уроке.

</CommonMistake>

## Практика

Во всех задачах этого урока заготовка содержит **ошибки**. Нажмите «Запустить», прочитайте сообщения компилятора, исправьте программу и отправьте на проверку. Логику программ менять не нужно — только ошибки.

1. **Сломанное приветствие** — пропущенные символы.
2. **Опечатки** — неверные имена.
3. **Скобки и заголовки** — структура программы.
4. **Прямоугольник** — несколько разных ошибок в одной программе.

## Итоги

- Сообщение компилятора содержит файл, строку, позицию, тип (`error` или `warning`) и описание.
- Исправляйте первую ошибку и компилируйте снова: остальные сообщения часто оказываются её следствиями.
- Настоящая ошибка может находиться выше указанной строки.
- `undeclared` — опечатка в имени переменной, `expected` — пропущенный символ, `implicit declaration` — опечатка в имени функции или забытый `#include`, `undefined reference` — функция объявлена или вызвана, но нигде не определена (например, `Main` вместо `main`).
- Подсказки `did you mean` и `note` часто содержат готовое исправление.
