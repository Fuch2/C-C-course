## Собралась — ещё не значит работает

Компилятор проверяет, что программа написана по правилам языка. Но он не знает, **что** вы хотели посчитать. Программа может собраться без единого предупреждения и всё равно:

- **аварийно завершиться** во время работы — это ошибка времени выполнения (runtime error);
- **выдать неверный ответ** — это логическая ошибка.

Логические ошибки самые коварные: программа ведёт себя спокойно, просто считает не то. В этом уроке вы научитесь находить оба вида ошибок тремя приёмами: ручной трассировкой, отладочной печатью и продуманными тестами.

## Аварийное завершение

Самый простой пример аварии — целочисленное деление на ноль:

```c
#include <stdio.h>

int main(void) {
    int total, people;
    scanf("%d %d", &total, &people);
    printf("%d\n", total / people);
    return 0;
}
```

Ввод:

```text
100 4
```

Вывод:

```text
25
```

Запустите пример, затем замените ввод на `100 0`. Программа не напечатает ничего: процессор не умеет делить целые числа на ноль, и операционная система принудительно остановит программу. В результатах запуска вы увидите «Ошибка выполнения» и **ненулевой код завершения** (в Linux — 136).

Компилятор не мог предупредить об этой ошибке: на этапе компиляции неизвестно, какое число введёт пользователь. Защищаться от таких случаев вы научитесь в уроке «if и else». В модуле о памяти вы встретите и другие причины аварий — например, обращение к памяти, которая программе не принадлежит.

<Important title="Как отличить аварию от логической ошибки">

Авария — программа остановилась с ненулевым кодом завершения, часто ничего не напечатав. Логическая ошибка — программа завершилась с кодом `0`, но ответ не совпал с ожидаемым.

</Important>

## Логическая ошибка: приоритет операций

Задача: напечатать среднее арифметическое двух чисел. Вот первая попытка:

```c
#include <stdio.h>

int main(void) {
    int a = 4, b = 8;
    printf("%d\n", a + b / 2);
    return 0;
}
```

Вывод:

```text
8
```

Среднее чисел 4 и 8 — это 6, а программа напечатала 8. Причина та же, что в школьной математике: деление выполняется **раньше** сложения. Компьютер посчитал `4 + (8 / 2) = 4 + 4 = 8`. Нужны скобки: `(a + b) / 2`.

Это и есть логическая ошибка: код правильный с точки зрения языка, но выражает не ту формулу.

## Приём 1: ручная трассировка

**Трассировка** — это выполнение программы «на бумаге»: вы идёте по строкам сверху вниз и после каждой записываете значения переменных. Звучит медленно, но для коротких программ это самый надёжный способ понять, что происходит.

```c
#include <stdio.h>

int main(void) {
    int x = 5;
    x = x * 2;
    x = x - 3;
    int y = x / 2;
    printf("%d %d\n", x, y);
    return 0;
}
```

<MemoryDiagram title="Трассировка: значения после каждой строки">

| Строка           | `x` | `y` | Пояснение                                  |
| ---------------- | --- | --- | ------------------------------------------ |
| `int x = 5;`     | 5   | —   | `x` создана со значением 5                 |
| `x = x * 2;`     | 10  | —   | Берём старое `x` (5), умножаем, записываем |
| `x = x - 3;`     | 7   | —   | 10 − 3                                     |
| `int y = x / 2;` | 7   | 3   | 7 / 2 = 3: дробная часть отбрасывается     |

</MemoryDiagram>

Вывод:

```text
7 3
```

Если ваш прогноз совпал с реальным выводом — вы понимаете программу. Если нет — найдите **первую** строку, где значение в таблице разошлось с вашими ожиданиями. Ошибка там.

## Приём 2: отладочная печать

Когда программа длиннее, удобнее, чтобы она сама сообщала о промежуточных значениях. Для этого временно добавляют печать в важных местах. Но обычный `printf` испортит вывод, и тесты перестанут проходить. Решение — печатать отладочные сообщения в **отдельный поток ошибок** `stderr`:

```c
#include <stdio.h>

int main(void) {
    int price = 120, count = 3, discount = 20;
    int total = price * count;
    fprintf(stderr, "отладка: total до скидки = %d\n", total);
    total = total - discount;
    printf("%d\n", total);
    return 0;
}
```

Вывод:

```text
340
```

У каждой программы два канала вывода: **stdout** (стандартный вывод) — для результата, и **stderr** (стандартный поток ошибок) — для диагностики. `printf` пишет в stdout, а `fprintf(stderr, ...)` — в stderr. Проверяющая система сравнивает только stdout, поэтому отладочная печать в stderr не мешает тестам. В результатах запуска её видно отдельно.

<Tip title="Убирайте отладку после исправления">

Отладочная печать — временные «леса». Когда ошибка найдена, удалите её: в готовой программе она только мешает читать код.

</Tip>

## Приём 3: тесты, которые ищут ошибки

Если программа прошла один пример, это ещё не доказательство. Хорошие тесты специально проверяют места, где программы обычно ломаются:

| Вид теста           | Пример для «среднего двух чисел» | Что проверяет                     |
| ------------------- | -------------------------------- | --------------------------------- |
| Обычный случай      | `4 8` → `6`                      | Основная формула                  |
| Одинаковые значения | `5 5` → `5`                      | Простейший случай                 |
| Ноль                | `0 0` → `0`, `0 9` → `4`         | Деление и сложение с нулём        |
| Нечётная сумма      | `3 4` → `3`                      | Отбрасывание дробной части        |
| Большие числа       | `1000000 1000000` → `1000000`    | Не выходит ли результат за предел |

Перед отправкой решения придумайте 3–4 собственных теста и проверьте программу кнопкой «Запустить» с вашим вводом. Скрытые тесты курса построены по тем же принципам.

## Как читать результат проверки

После отправки решения вы увидите таблицу тестов:

- **Открытые тесты** показывают ввод, ожидаемый и фактический вывод. Сравните их построчно — разница подскажет, где ошибка.
- **Скрытые тесты** показывают только «пройден» или «не пройден». Если открытые тесты прошли, а скрытые — нет, подумайте, какие особые случаи из таблицы выше программа обрабатывает неправильно.
- **Ошибка выполнения** в тесте означает аварию: ищите деление на ноль или другие недопустимые операции.

## Частые ошибки

<CommonMistake title="Подгонять программу под пример">

Если в примере ввод `4 8` и ответ `6`, программа `printf("6\n");` пройдёт пример, но провалит скрытые тесты. Решение должно вычислять ответ для любых допустимых данных.

</CommonMistake>

<CommonMistake title="Оставлять отладочный printf">

Лишняя строка в stdout делает вывод неверным. Отладку печатайте в stderr и удаляйте после исправления.

</CommonMistake>

<CommonMistake title="Менять код наугад">

Если тест не проходит, не переставляйте строки в надежде на удачу. Выполните трассировку, найдите первую строку, где значения расходятся с ожиданием, и исправьте именно её.

</CommonMistake>

## Практика

В каждой заготовке есть **логическая ошибка**: программа собирается, но печатает неверный ответ. Запустите её на примере, сравните с ожидаемым выводом, найдите ошибку трассировкой или отладочной печатью и исправьте.

1. **Среднее двух чисел** — приоритет операций.
2. **Минуты в часы** — неверная константа.
3. **Скидка** — порядок действий.
4. **Градусы Фаренгейта** — неожиданное целочисленное деление.

## Итоги

- Компилятор ловит нарушения правил языка, но не ошибки в смысле программы.
- Авария — ненулевой код завершения; логическая ошибка — код `0`, но неверный ответ.
- Трассировка: выполните программу на бумаге и найдите первую строку, где значения расходятся с ожиданием.
- Отладочную печать выводите в `stderr` через `fprintf(stderr, ...)`: тесты сравнивают только `stdout`.
- Проверяйте решение на своих тестах: одинаковые значения, ноль, граничные и большие числа.
