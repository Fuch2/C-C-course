## Зачем нужен компилятор

В прошлом уроке мы выяснили, что процессор понимает только машинный код, а люди пишут программы на языках вроде C. Между ними стоит **компилятор** — программа-переводчик. В этом уроке разберём, что именно происходит между моментом, когда вы набрали код, и моментом, когда на экране появился результат.

Понимать этот путь важно с первого дня: сообщения об ошибках будут приходить из разных его этапов, и чтобы исправить ошибку, нужно знать, кто и почему на неё пожаловался.

## Три участника: исходный код, компилятор, исполняемый файл

**Исходный код** (source code) — обычный текстовый файл с программой на C. Его можно открыть в любом текстовом редакторе. Файлы с кодом на C принято называть с окончанием `.c`, например `main.c`. Файлы на C++ — `.cpp`.

**Компилятор** читает исходный код, проверяет, что он написан по правилам языка, и переводит его в машинный код. Самые известные компиляторы C и C++ — **GCC** и **Clang**. Они бесплатные и работают в Linux, macOS и Windows.

**Исполняемый файл** (executable) — результат работы компилятора. В нём лежит машинный код, готовый к запуску. В Windows такие файлы обычно имеют окончание `.exe`, в Linux и macOS окончания часто нет вовсе.

<MemoryDiagram title="Путь программы">

| Шаг | Что есть              | Кто работает         | Результат                      |
| --- | --------------------- | -------------------- | ------------------------------ |
| 1   | `main.c` — текст на C | Вы, в редакторе      | Исходный код                   |
| 2   | `main.c`              | Компилятор GCC/Clang | Исполняемый файл `main`        |
| 3   | Исполняемый файл      | Операционная система | Запущенная программа — процесс |
| 4   | Работающая программа  | Процессор            | Вывод на экран, код завершения |

</MemoryDiagram>

Важное следствие: **компиляция и запуск — разные действия**. Скомпилировать программу нужно один раз, а запускать готовый файл можно сколько угодно. Но если вы изменили исходный код, исполняемый файл сам не обновится — компилировать нужно заново.

## Как это выглядит на собственном компьютере

Когда вы установите компилятор у себя (этому посвящён модуль «Инструменты разработчика»), работа будет выглядеть так. Это команды для **терминала** — окна, где команды вводятся текстом:

```bash
gcc main.c -o hello
./hello
```

Первая команда просит GCC скомпилировать файл `main.c` и сохранить результат (`-o` — от слова output) в файл `hello`. Вторая запускает получившийся файл. Точка и косая черта `./` означают «файл из текущей папки».

Если в коде есть ошибка, первая команда напечатает сообщение об ошибке и исполняемый файл **не появится** — запускать будет нечего.

## Что происходит, когда вы нажимаете «Запустить»

В этом курсе устанавливать ничего не нужно. Когда вы нажимаете «Запустить» или «Проверить», происходит то же самое, только на сервере:

1. Ваш код отправляется в изолированную среду — **песочницу**. Она отрезана от сети и от остального компьютера, поэтому даже ошибочная программа ничего не сломает.
2. Компилятор GCC (или Clang — его можно выбрать в редакторе задачи) собирает программу по стандарту **C23** — это текущая версия языка C, опубликованная в 2024 году. Для C++ используется стандарт **C++23**. Языки развиваются: раз в несколько лет комитет по стандартизации выпускает новую версию, и в старых книгах вы встретите C89, C99, C11 и C17. Почти всё, что вы изучите, работает во всех этих версиях; где C23 что-то изменил, мы скажем об этом отдельно.
3. Если компиляция прошла успешно, программа запускается, а вы видите её вывод.
4. Если компилятор нашёл ошибку, программа не запускается, и вы видите сообщение компилятора.

Компилятор в курсе включён в строгом режиме: он сообщает не только об ошибках, но и о подозрительных местах — **предупреждениях**.

## Ошибки и предупреждения компилятора

**Ошибка** (error) означает, что код нарушает правила языка. Компилятор отказывается создавать исполняемый файл. Пример — забытая точка с запятой:

```c
#include <stdio.h>

int main(void) {
    printf("Привет\n")    // Ошибка компиляции: нет точки с запятой
    return 0;
}
```

Нажмите «Запустить» — программа не выполнится, а компилятор напишет примерно следующее:

```text
main.c:4:23: error: expected ';' before 'return'
```

Разбор этого сообщения — в уроке «Ошибки компиляции». Пока заметьте главное: компилятор указывает файл (`main.c`), строку (`4`) и позицию в строке (`23`).

**Предупреждение** (warning) означает, что код формально правильный, но выглядит подозрительно. Программа соберётся и запустится, но компилятор советует обратить внимание:

```c
#include <stdio.h>

int main(void) {
    int unused = 5;   // Предупреждение: переменная нигде не используется
    printf("Готово\n");
    return 0;
}
```

Вывод:

```text
Готово
```

Перед выводом программы компилятор сообщит:

```text
main.c:4:9: warning: unused variable 'unused' [-Wunused-variable]
```

Переменную создали, но ни разу не использовали — возможно, программист забыл дописать код. Опытные разработчики добиваются, чтобы программа собиралась **без единого предупреждения**: за предупреждениями часто прячутся настоящие ошибки.

<Important title="Правило курса">

Относитесь к предупреждениям как к ошибкам. Если компилятор что-то сообщил — прочитайте и исправьте, даже если программа работает.

</Important>

## Ошибки во время выполнения

Бывает, что компилятор доволен, но программа всё равно работает неправильно. Такие ошибки называют **ошибками времени выполнения** (runtime errors). Компилятор не может их найти, потому что они зависят от данных, которые появятся только при запуске.

Классический пример — деление на ноль:

```c
#include <stdio.h>

int main(void) {
    int a, b;
    scanf("%d %d", &a, &b);
    printf("%d\n", a / b);
    return 0;
}
```

Ввод:

```text
7 2
```

Вывод:

```text
3
```

С вводом `7 2` программа печатает `3` (дробная часть при делении целых чисел отбрасывается — об этом урок «Арифметика»). А теперь впишите в поле ввода `7 0` и запустите снова. Программа аварийно завершится, и вместо вывода вы увидите ошибку выполнения с ненулевым кодом завершения.

## Код завершения

Каждая программа, заканчивая работу, сообщает операционной системе число — **код завершения**. По соглашению `0` означает «всё прошло успешно», любое другое число — «что-то пошло не так». Строка `return 0;` в конце `main` как раз и возвращает этот ноль.

Под результатом каждого запуска в курсе показан код завершения. Если программа упала из-за ошибки, код будет отличен от нуля. Подробнее об этом поговорим в уроке «Функция main и код завершения».

## GCC и Clang

Мы будем пользоваться двумя компиляторами. Оба реализуют один и тот же стандарт языка, поэтому правильная программа даёт одинаковый результат с любым из них. Отличаются они формулировками сообщений: иногда одно и то же сообщение понятнее у Clang, иногда у GCC. Если сообщение об ошибке непонятно, переключите компилятор в редакторе задачи и прочитайте вариант второго.

## Частые ошибки

<CommonMistake title="Изменили код, но запускаете старый файл">

На собственном компьютере после правки `main.c` нужно снова выполнить `gcc`. Иначе `./hello` запустит старую версию, и будет казаться, что ваши изменения «не работают». В курсе компиляция выполняется автоматически при каждом запуске.

</CommonMistake>

<CommonMistake title="Игнорировать предупреждения">

«Работает же!» — работает на этих данных. Предупреждение о неиспользуемой переменной часто означает, что результат вычисления потерян, а предупреждение о неявном объявлении функции — что забыт `#include`.

</CommonMistake>

<CommonMistake title="Читать только последнюю строку сообщения">

Одна ошибка может вызвать цепочку сообщений. Читайте сообщения сверху вниз и исправляйте **первую** ошибку — остальные часто исчезают сами.

</CommonMistake>

## Итоги

- Исходный код — текст программы, исполняемый файл — машинный код, компилятор переводит одно в другое.
- Компиляция и запуск — разные шаги. После изменения кода программу нужно скомпилировать заново.
- Ошибка компиляции не даёт создать программу; предупреждение указывает на подозрительное место — исправляйте и то, и другое.
- Ошибки времени выполнения проявляются только при запуске и зависят от входных данных.
- Код завершения `0` означает успех, ненулевой — ошибку.
