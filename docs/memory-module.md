# Память и указатели в C

Модуль C17 из 28 последовательных уроков для ученика, прошедшего «Основы языка C». Переработан по стандарту урока из [аудита контента](content-audit.md): в каждом уроке теория маленькими шагами с запускаемыми примерами и точным выводом, частые ошибки, 7 вопросов (включая «что выведет программа»), 3–4 задачи с 8–12 тестами, конкретными подсказками и разбором решения.

Итого: 28 уроков (в среднем около 1200 слов текста), 196 вопросов, 110 задач и 1101 тест, 107 запускаемых примеров, из них 16 — намеренно ошибочных с меткой `// Ошибка памяти`. 41 задача «Найди ошибку» даёт дефектную заготовку; 4 задачи урока «Valgrind» и одна задача урока о заполнителях проверяются Valgrind, остальные — ASan/UBSan.

## Программа

| Блок                 | Уроки                                                                                                                            |
| -------------------- | -------------------------------------------------------------------------------------------------------------------------------- |
| Модель памяти        | карта памяти процесса, байты объекта и `sizeof`, стек вызовов, куча, время жизни объектов                                        |
| Указатели глубже     | указатели на массивы и таблицы, `memcpy`/`memmove`/`memset`, указатель на указатель, `const` в интерфейсах, `void *` и `qsort`   |
| Динамическая память  | `malloc`, `calloc`, `realloc`, `free` и владение, динамический массив                                                            |
| Ошибки памяти        | утечки, висячие указатели, use-after-free, двойное освобождение, переполнение буфера, выход за границы, неопределённое поведение |
| Представление данных | выравнивание, заполнители в структурах, порядок байтов                                                                           |
| Инструменты          | AddressSanitizer и UBSan, Valgrind, итоговый практикум по отладке                                                                |

ID уроков прежней версии сохранены, поэтому прогресс учеников не теряется; ID задач теперь формируются как `<урок>-task-N`. Темы, уже изученные в «Основах C» (базовые указатели, `NULL`, арифметика указателей, `const`-указатели), не повторяются, а углубляются. Отчёты ASan, LSan, UBSan и Valgrind в тексте уроков — настоящие, полученные запуском примеров в sandbox.

## Авторинг

Каждый урок — `lesson.src.mjs` (metadata, вопросы, задачи) и `lesson.mdx` (текст). Сборка и проверка — `node --import tsx scripts/lessons/build.ts memory-pointers/<урок>`:

- поле `diagnostics` урока задаёт доверенный режим проверки всех его задач (у задачи можно переопределить);
- эталон каждой задачи выполняется на GCC и на Clang с ASan/UBSan, выводы скрытых тестов вычисляются эталоном;
- для задач с `bug: true` дефектная заготовка запускается в режиме диагностики задачи и обязана провалить проверку (отрицательный контроль, `bugDetected` в `docs/verification/lessons.json`);
- примеры MDX в уроках с диагностикой дополнительно выполняются под ASan/UBSan; пример с меткой `// Ошибка памяти` обязан дать отчёт санитайзера, его вывод без инструментов не проверяется.

Разбор примеров вынесен в `scripts/lessons/examples.ts`. Вспомогательные скрипты для подготовки текста: `scripts/lessons/memory-examples.ts` сохраняет ошибочные примеры урока в файлы, `scripts/lessons/diagnose.ts` запускает исходник в sandbox с ASan/UBSan или Valgrind и печатает отчёт.

## Что проверяет платформа

Метаданные упражнения задают `diagnostics: "sanitizers" | "valgrind"`. При нажатии «Проверить» сервер добавляет режим во внутренний запрос runner. Публичные `submit` и `execute` не принимают этот параметр; кнопка «Запустить» работает в обычном режиме.

Sanitizers: фиксированные `-fsanitize=address,undefined`, `-fno-sanitize-recover=all`, `-fno-omit-frame-pointer`, `-g`; `ASAN_OPTIONS=detect_leaks=1:halt_on_error=1`. Valgrind: `--leak-check=full`, `--track-origins=yes`, `--error-exitcode=99`. Правильный stdout при диагностической ошибке не засчитывается. В образ sandbox добавлен `llvm-symbolizer` (пакет `llvm`), поэтому отчёты санитайзеров содержат имена функций, файлы и строки (`/work/main.c:7:16`), а не только адреса.

Режимы не меняют ограничения sandbox: network=none, 256 МБ RAM, CPU, pids, non-root, read-only root, no-new-privileges, ограниченные tmpfs, внешний timeout и очистку. Бюджет диагностического теста — 10 секунд, задания — 90 секунд.

## Проверка модуля

`npm run test:memory` (`scripts/verify-memory.ts`, параллелизм `MEMORY_JOBS`, по умолчанию 2):

1. каждое эталонное решение проходит все тесты под Clang ASan/UBSan/LSan и под GCC Valgrind;
2. дефектная заготовка каждого задания «Найди ошибку» отклоняется в режиме диагностики этого задания;
3. обычные примеры MDX выполняются под ASan/UBSan без отчётов и с записанным выводом, примеры `// Ошибка памяти` дают отчёт.

Отчёт — `docs/verification/memory.json`. Структурный тест — `tests/unit/memory-content.test.ts`.

Динамическая диагностика проверяет выполненные пути и не доказывает отсутствия всех UB; отказ `malloc` на каждом пути тестами не моделируется — ветви ошибок разобраны в объяснениях решений.

Технические факты о средствах диагностики сверялись с руководствами [AddressSanitizer](https://clang.llvm.org/docs/AddressSanitizer.html), [UBSan](https://clang.llvm.org/docs/UndefinedBehaviorSanitizer.html) и [Valgrind Memcheck](https://valgrind.org/docs/manual/mc-manual.html). Материал уроков написан самостоятельно.
