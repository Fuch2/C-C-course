# Алгоритмы и структуры данных

Модуль на C23 из 28 последовательных уроков после «Инструментов разработчика». Переработан по стандарту урока из [аудита контента](content-audit.md): теория маленькими шагами с запускаемыми примерами и точным выводом, трассировки, инварианты и оценки сложности, частые ошибки, 8 вопросов (включая «что выведет программа»), 4–5 задач с 8–12 тестами, конкретными подсказками и разбором решения.

Итого: 28 уроков, 224 вопроса, 113 задач, из них 28 «Найди ошибку» с отрицательным контролем и 3 benchmark-задачи. Все задачи проверяются в доверенном режиме ASan/UBSan.

## Программа

| Раздел             | Уроки                                                                                                    |
| ------------------ | -------------------------------------------------------------------------------------------------------- |
| Анализ алгоритмов  | что такое алгоритм (инвариант и вариант цикла), подсчёт операций, O-нотация, O(1), O(n), O(log n), O(n²) |
| Поиск              | линейный поиск, двоичный поиск и поиск по ответу                                                         |
| Сортировки         | пузырёк, выбор, вставки, рекурсия, слияние, быстрая сортировка                                           |
| Линейные структуры | динамический массив и амортизация, односвязный и двусвязный списки, стек, очередь, кольцевой буфер       |
| Хеширование        | хеш-таблица: цепочки, открытая адресация, надгробия                                                      |
| Деревья            | бинарное дерево и обходы, дерево поиска, куча и очередь с приоритетом                                    |
| Графы              | представления, поиск в ширину, поиск в глубину, циклы и топологическая сортировка                        |

ID уроков прежней версии сохранены, порядок изменён в одном месте: рекурсия стоит перед сортировкой слиянием, потому что на ней построены слияние и быстрая сортировка. ID задач — `<урок>-task-N`, у benchmark-задач — `algo-binary-search-benchmark`, `algo-insertion-benchmark`, `algo-vector-benchmark`.

Без повторов с предыдущими модулями: реализация динамического массива разобрана в «Памяти» и в проекте «Углублённого C», здесь — амортизированный анализ, коэффициент роста и уменьшение ёмкости; `qsort`, указатели на функции и `memmove` используются как готовые инструменты. Связь со стандартной библиотекой C++ показана короткими запускаемыми примерами C++23 (`std::lower_bound`, `std::stable_sort`, `std::list`, `std::unordered_map`, `std::priority_queue`) — как предпросмотр «Основ C++».

## Практика

- Задачи нарастают по сложности внутри урока: разминка, основная задача, «Найди ошибку», задача повышенной сложности.
- «Найди ошибку» — классические дефекты алгоритмов: неверное начальное значение, переполнение счётчика и хеша, потерянный кандидат двоичного поиска, выход за массив при сравнении соседей, порядок условий во вставках, потерянный хвост слияния, опорный в рекурсии, висячий указатель после `realloc`, использование после `free` в списках, деревьях и очереди, переполнение очереди BFS, отметка после рекурсии в заливке. Дефекты выбраны так, чтобы заготовка быстро проваливала тесты или давала отчёт санитайзера, а не зависала: бесконечный цикл превысил бы общий лимит проверки (10 тестов × 10 с с санитайзерами больше 90 с).
- Графовые задачи используют сжатые списки смежности (подсчёт степеней и префиксные суммы); вершины во вводе нумеруются с 1.
- Размер тестов ограничен лимитом stdin (16 КБ), поэтому скрытые тесты проверяют корректность и граничные случаи, а не асимптотику. Ограничения в условиях описывают задачу честно — решение должно укладываться в них по сложности.

## Benchmark-практика

Три задачи измеряют определённые в условиях события — воспроизводимую модель стоимости, а не время:

- сравнения линейного поиска и нижней границы двоичного поиска на одних и тех же запросах;
- сравнения и сдвиги сортировки вставками на разных порядках данных;
- копирования при росте динамического массива для стратегий `+1`, `+100`, `×2`, `×1,5`.

Каждая включает пустой вход (`n = 0`). Решения не используют `clock()` и `time()`.

## Эксперимент со временем и cache locality

Время работы — дополнительный эксперимент, который автопроверка намеренно не требует. Если вы проводите его в том же Docker runner, сохраняйте ограничения:

1. Сравните последовательное суммирование массива из 65 536 чисел с обходом цепочки индексов с шагом 8191 по модулю 65 536 (взаимная простота гарантирует обход всех элементов); обе контрольные суммы должны совпасть.
2. Ставьте `clock()` непосредственно вокруг измеряемого участка, проверяйте `(clock_t)-1`, делите на `CLOCKS_PER_SEC` в `double`; увеличивайте число повторов, если длительность меньше разрешения часов.
3. Делайте прогрев и несколько замеров в разном порядке; записывайте медиану, разброс, компилятор и фактические флаги доверенного runner. Произвольные флаги из браузера не передаются.
4. Измерения с ASan/UBSan — для диагностики, сравнение времени — отдельным обычным запуском. `clock()` измеряет процессорное время; Docker quota, архитектура и фоновые задачи влияют на результат.

## Авторинг

Каждый урок — `lesson.src.mjs` и `lesson.mdx`; сборка — `node --import tsx scripts/lessons/build.ts algorithms-structures/<урок>`. Скрипт проверяет эталоны на GCC и Clang с ASan/UBSan, вычисляет выводы скрытых тестов, сверяет примеры MDX (C23 и C++23) и ответы вопросов с запуском, а для задач с `bug: true` убеждается, что дефектная заготовка не проходит тесты. На медленном Docker уменьшайте параллелизм: `LESSON_JOBS=2`.

## Проверки

- `npm test` — `tests/unit/algorithms-content.test.ts`: порядок и цепочка уроков, стандарт урока, отчёт GCC/Clang, отрицательные контроли, benchmark-задачи без измерения времени, индекс поиска и скрытие решений.
- `npm run test:algorithms` — `scripts/verify-algorithms.ts`: эталоны на GCC и Clang с ASan/UBSan, отрицательные контроли, все примеры MDX (C23 и C++23, `// Ошибка памяти` — с обязательным отчётом санитайзера). Отчёт — `docs/verification/algorithms.json`, параллелизм — `ALGORITHMS_JOBS`; аргументы — подстроки ID уроков для частичной проверки без записи отчёта.

Гарантии стандартной библиотеки C++ сверены с рабочим текстом стандарта: [vector](https://eel.is/c++draft/vector.overview), [сортировка](https://eel.is/c++draft/alg.sorting), [unordered-контейнеры](https://eel.is/c++draft/unord.req.general), [priority_queue](https://eel.is/c++draft/priority.queue). C++ не требует от `vector` конкретного коэффициента роста, от `map` определённого вида сбалансированного дерева, а от `unordered_map` — постоянного времени в худшем случае. Материал авторский.
