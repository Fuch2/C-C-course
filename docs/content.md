# Движок учебного курса

Весь учебный текст и задания находятся в `content/cpp-systems/`. React-компоненты отвечают за отображение и взаимодействия. Схемы — `packages/shared/src/content.ts`, загрузчик и парсер — `packages/course-engine/src/`, расчёты прогресса — `packages/shared/src/progress.ts`.

## Файлы и публикация

```text
content/cpp-systems/
  course.json
  first-program/
    lesson.json
    lesson.mdx
    scheme.png           # необязательное изображение
  another-directory/
    lesson.json
    lesson.md
  projects/first-build/
    project.json
  playground.json        # исходник и описание свободной песочницы
```

Загрузчик рекурсивно сканирует каталог. Имя директории не задаёт ID и порядок; урок может находиться на любой глубине. Рядом с каждым `lesson.json` нужен ровно один `lesson.md` или `lesson.mdx`. Символические ссылки запрещены. `course.json` содержит описания модулей; списки уроков вычисляются автоматически из `moduleId`.

`published: false` явно помечает черновик. Его файлы тоже проходят валидацию, но он исключён из навигации, поиска, процентов и публичного API. Опубликованный урок/проект не может зависеть от черновика. Сейчас опубликованы 115 уроков в пяти модулях; 36 уроков «Основы языка C» содержат по две самостоятельные практические задачи, 28 уроков памяти — пошаговые схемы и диагностику решений.

## Модели и metadata

Все объекты Zod строгие: неизвестные поля вызывают ошибку, а не молча отбрасываются.

| Модель         | Поля                                                                                                                                                                                    |
| -------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Course         | id, title, description, subtitle, modules                                                                                                                                               |
| Module         | id, title, description, order, level, icon, prerequisites                                                                                                                               |
| Lesson         | id, title, description, moduleId, order, difficulty, estimatedMinutes, prerequisites, objectives, tags, published, standard, completion, quiz, exercise, additionalExercises            |
| LessonSection  | id, title, depth, line — содержание из заголовков AST                                                                                                                                   |
| Quiz           | id, title, questions                                                                                                                                                                    |
| QuizQuestion   | id, question, options, correct, explanation                                                                                                                                             |
| CodingExercise | id, title, description, difficulty, starterCode, language, standard, compiler, examples, constraints, hints, publicTests, hiddenTests, referenceSolution, solutionExplanation, checking |
| TestCase       | id, name, expected и ровно одно из stdin/arguments                                                                                                                                      |
| Hint           | id, text, order                                                                                                                                                                         |
| Project        | id, title, description, moduleId, order, difficulty, estimatedMinutes, prerequisites, objectives, tags, lessonIds, deliverables, published                                              |

`id`: латинские строчные буквы, цифры и дефис, до 80 символов. ID курса, модулей, уроков, quiz, упражнений и проектов уникальны в курсе. ID вопросов уникальны внутри quiz; ID тестов и подсказок — внутри упражнения. Повтор prerequisites запрещён.

`difficulty`: `beginner`, `intermediate`, `advanced`; интерфейс отображает «Начальный», «Средний», «Продвинутый». `estimatedMinutes` — положительное целое число. `order` — неотрицательное целое. Модули сортируются по `(order, id)`, затем уроки внутри каждого модуля по `(order, id)`. При равном order результат детерминирован. Подсказки сортируются аналогично. `level` модуля остаётся русской строкой для совместимости интерфейса.

`publicTests` и `hiddenTests` физически разделены в metadata. Публичный DTO содержит только `publicTests`, число скрытых тестов и идентификаторы подсказок; тексты подсказок выдаются отдельным запросом с записью статистики. `referenceSolution`, `solutionExplanation`, входы, ожидаемые ответы и имена скрытых тестов не сериализуются в `/content` и не входят в поисковый индекс.

Режим `checking` задаёт способ grading:

- `stdout/exact` сравнивает stdout посимвольно;
- `stdout/trimmed` нормализует CRLF, пробелы справа и завершающие пустые строки;
- `function` описывает имя, тип результата и параметры. Сервер автоматически добавляет test harness к коду ученика, преобразует `arguments` теста в stdin и компилирует объединённый исходник внутри Docker;
- `custom/unordered-lines` сравнивает мультимножество строк без требования к порядку;
- `custom/floating-point` сравнивает одно конечное число с заданным `tolerance`.

Custom checker является фиксированным декларативным алгоритмом в доверенном приложении. Контент не содержит исполняемого checker-кода, поэтому он не создаёт новый путь запуска кода на host.

Пример metadata: `content/cpp-systems/first-program/lesson.json`. Поля `summary` и `minutes` больше не записываются в metadata; загрузчик вычисляет эти совместимые псевдонимы из `description` и `estimatedMinutes`. `number` модуля также вычисляется после сортировки.

## Зависимости и навигация

`prerequisites` модуля содержит ID модулей, урока и проекта — ID уроков. Проверяется существование каждой ссылки. DFS обходит весь граф, включая несвязанные части, и показывает цепочку цикла, например `a → b → c → a`.

Урок наследует все уроки модулей, перечисленных в prerequisites его модуля, включая транзитивные зависимости. После объединения снова проверяется отсутствие циклов. `effectivePrerequisites` содержит полное транзитивное множество зависимостей; интерфейс показывает ещё не завершённые подготовительные уроки. Это рекомендация порядка обучения, а не запрет открывать материал.

Ссылки вперёд разрешены, если нет цикла. Граф зависимостей и визуальный порядок — разные свойства. `previousLessonId` и `nextLessonId` определяются по отсортированной опубликованной программе, включая переход между модулями. На границах возвращается `null`. Функция `lessonNavigation` предоставляет соответствующие объекты.

Проект хранит список учебных шагов `lessonIds` и ожидаемых результатов `deliverables`; все ссылки проверяются загрузчиком. Страница `/projects` читает дескрипторы из файлов.

## Markdown и декларативный MDX

Используются [remark-mdx](https://mdxjs.com/packages/remark-mdx/) и [remark-rehype](https://unifiedjs.com/explore/package/remark-rehype/). Сервер строит синтаксическое дерево без компиляции MDX в исполняемый JavaScript. Браузер получает готовое дерево отображения, которое React выводит через разрешённые компоненты.

Поддерживаются заголовки 1–6, абзацы, выделение, таблицы GFM, маркированные и нумерованные списки, inline code, fenced code blocks с подсветкой, ссылки и изображения. Содержание и якоря строятся из того же AST: учитываются inline-форматирование, повторные заголовки и коллизии slug. Заголовок внутри блока кода не попадает в содержание.

MDX допускает **учебные компоненты и строковые параметры**. JavaScript-выражения, import/export, spread props, HTML и произвольные компоненты отклоняются с именем файла и номером строки. В блоках кода скобки и JSX остаются обычным учебным текстом. Компоненты пишутся отдельными блоками; между тегом и Markdown оставляется пустая строка.

```mdx
<Concept title="Время жизни объекта">

Объект существует от создания до окончания своего времени жизни.

</Concept>

<MemoryDiagram title="Области процесса">

| Область | Содержимое             |
| ------- | ---------------------- |
| Код     | Инструкции             |
| Стек    | Данные текущих вызовов |

</MemoryDiagram>

<Quiz />

<CodingExercise />
```

У всех компонентов необязательный строковый `title`. Учебное содержание передаётся как вложенный Markdown.

| Компонент      | Поведение                                                                    |
| -------------- | ---------------------------------------------------------------------------- |
| Concept        | Выделенное объяснение понятия                                                |
| Important      | Важное условие или правило                                                   |
| Warning        | Предупреждение                                                               |
| Tip            | Практический совет                                                           |
| MemoryDiagram  | Подписанная схема, таблица или текстовый блок с горизонтальной прокруткой    |
| TryIt          | Пояснение и переход к настоящему редактору текущего урока                    |
| Quiz           | Встроенные вопросы из metadata, проверка через API и сохранение результата   |
| CodingExercise | Открытие встроенного Monaco и настоящая проверка задания из metadata         |
| Checkpoint     | Раскрываемое пояснение для самопроверки; не подменяет сохранённое завершение |
| CommonMistake  | Разбор типичной ошибки                                                       |
| UnderTheHood   | Раскрываемые подробности устройства механизма                                |

В одном документе допускается не более одного Quiz и CodingExercise. Quiz встраивает проверку знаний. CodingExercise в уроке с несколькими задачами открывает вкладку практики с переключателем всех заданий, а в уроке с одной задачей открывает встроенный редактор. Они используют те же сохранённые результаты, что и вкладки урока. При переключении вкладки встроенный редактор размонтируется с сохранением черновика; два редактора одного задания одновременно не работают.

Изображения: `![Описание](./scheme.png)` с файлом внутри content либо внешний HTTP(S) URL. Локальные PNG/JPEG/GIF/WebP/AVIF выдаются через `/api/content-assets/...`; traversal, symlink за пределы content и чтение JSON через этот маршрут запрещены. Ссылки задаются как `/lesson/ID`, `#якорь` или полный URL. Опасные схемы URL отклоняются.

## Поиск и прогресс

Поисковый индекс строится один раз при загрузке из названия, description, objectives, tags и видимого Markdown/MDX, включая подписи компонентов. Решения, скрытые проверки и пояснения правильных ответов не индексируются. Нормализация: NFKC, нижний регистр, ё → е. Все слова запроса должны встретиться; совпадения в названии имеют приоритет. Все выбранные теги должны точно совпасть после нормализации. Без запроса, но с тегами работает фильтр; совсем пустой запрос возвращает пустой список.

`GET /api/search?q=память&tag=C&tag=указатели` возвращает `results` и доступные `tags`. Интерфейс `/search` и ссылки тегов урока используют этот API.

Режимы завершения:

- `reading`: 100% после чтения; quiz и практика не добавляют проценты вместо чтения.
- `practice`: чтение 20%, успешный quiz 30%, успешная проверка всех упражнений урока 50%; завершение после всех трёх частей.

Сохранённый `completedAt` сохраняет уже достигнутое завершение. `calculateProgress` вычисляет среднее по урокам с равными весами, округляет до целого, игнорирует посторонние записи и повторные ID уроков. Пустой модуль имеет 0% и не считается завершённым. Модуль и курс, интерфейс и Prisma-агрегат используют одну функцию; проценты модулей не усредняются между собой.

## Проверка и обновление

```sh
npm run content:check
npm run check
npm run test:runner
npm run test:solutions
```

Ошибка показывает путь и нарушенное поле/связь. В разработке контент перечитывается при загрузке; в production кешируется по абсолютному каталогу. `clearCourseCache()` предназначен для тестов и контролируемой перезагрузки. После изменения опубликованного контента пересоберите приложение: статические страницы и список маршрутов формируются на этапе build.

`scripts/author-course.py` — прежний генератор стартовых материалов, адаптированный к новой схеме. Он перезаписывает JSON и Markdown, но сохраняет уже существующий MDX. Для обычного авторинга редактируйте файлы напрямую; генератор не требуется для добавления нового урока.

## Полный модуль C17

`c-fundamentals/` содержит 45 уроков, включая шесть практикумов. Каждый урок — каталог с авторским исходником `lesson.src.mjs` (metadata, вопросы, задачи и эталоны) и текстом `lesson.mdx`; `lesson.json` генерируется командой `node --import tsx scripts/lessons/build.ts [фильтр]`. Скрипт компилирует эталоны в Docker sandbox на GCC и Clang (ASan/UBSan), вычисляет ожидаемые выводы скрытых тестов, сверяет блоки «Вывод:» примеров MDX и ответы вопросов «что выведет программа» с реальным запуском и записывает отчёт `docs/verification/lessons.json`. Не редактируйте `lesson.json` этих уроков вручную.

Необязательное `additionalExercises` — массив дополнительных `CodingExercise` (до 8); отсутствие означает пустой массив. IDs упражнений уникальны во всём курсе. У каждой задачи собственные public/hidden tests, hints, starterCode и referenceSolution. Стандарт каждой задачи совпадает со стандартом урока. Публичное представление одинаково очищает основную и дополнительные задачи.

`npm run test:solutions` проверяет все задачи на GCC и Clang через Docker runner; результаты сохраняются в `docs/verification/`.

Материал написан для C17. Для сверки базовых правил использовался публичный [проект WG14 N1570](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n1570.pdf) (это проект C11, а не текст C17) и [документация GCC о поддержке стандартов](https://gcc.gnu.org/onlinedocs/gcc/Standards.html). Примеры не используют расширения GNU; размеры типов не объявляются универсальными свойствами языка.

«Инструменты разработчика»: `content/cpp-systems/developer-tools`, 12 уроков из `lesson.src.mjs` (терминал → стадии сборки → препроцессор и объектные файлы → флаги компилятора → линковка → структура проекта → Make → CMake → GDB → LLDB → санитайзеры → Git), 107 вопросов, 40 задач на C, моделирующих работу инструментов; сборка — `node --import tsx scripts/lessons/build.ts developer-tools`.

«Углублённый C»: `content/cpp-systems/advanced-c`, 28 уроков и три проекта. Проекты в `projects/advanced-*` ссылаются на уроки; их условия и тесты хранятся в дополнительных упражнениях. Генератор: `python3 scripts/author-advanced.py`, затем форматирование и `npm run content:check`.
