# Углублённый C

Модуль на C23 из 28 последовательных уроков после «Памяти и указателей в C». Переработан по стандарту урока из [аудита контента](content-audit.md): теория маленькими шагами с запускаемыми примерами и точным выводом, частые ошибки, 8–9 вопросов (включая «что выведет программа»), 3–4 задачи с 8–12 тестами, конкретными подсказками и разбором решения.

Итого: 28 уроков (в среднем около 1550 слов текста), 225 вопросов, 100 задач, из них 26 «Найди ошибку» с отрицательным контролем, и три проекта. Все задачи проверяются в доверенном режиме ASan/UBSan.

## Программа

| Раздел                     | Уроки                                                                                         |
| -------------------------- | --------------------------------------------------------------------------------------------- |
| Программа из многих файлов | единицы трансляции, заголовки, защита от повторного включения, `static`, `extern`, связывание |
| Препроцессор               | обзор и фазы, `#define`, макросы с параметрами, опасности макросов, условная компиляция       |
| Константы                  | `const`, константные выражения, `enum`, `restrict`                                            |
| Функции как данные         | указатели на функции, callbacks и контекст `void *ctx`, обобщённые контейнеры на `void *`     |
| Биты                       | `&`, `\|` и `~`, `^`, сдвиги, поля и маски, `volatile`, регистры устройств                    |
| Файлы                      | `FILE *` и текстовый ввод-вывод, `fread`/`fwrite`/`fseek`, двоичные форматы                   |
| Ошибки                     | `errno`, обработка ошибок и `goto cleanup`, `assert` и `static_assert`                        |

ID уроков прежней версии сохранены, порядок перестроен по разделам; ID задач — `<урок>-task-N`. Темы, разобранные в «Основах C» и «Памяти» (`const` в интерфейсах, `void *` и `qsort`, порядок байтов, выравнивание), не повторяются, а углубляются. Командная строка компилятора, `-I`, `-D`, `nm`, Make и отладчики — в модуле «Инструменты разработчика», который идёт следом.

Многофайловые программы показаны блоками с именем файла (` ```c geometry.h `): такой блок подписан именем файла и не запускается. Для запуска модули собраны в одном файле с разделами-комментариями `// ---- counter.h ----`.

## Проекты

| Проект                         | Урок                      | Проверяемые сценарии                                                                                     |
| ------------------------------ | ------------------------- | -------------------------------------------------------------------------------------------------------- |
| Обобщённый динамический массив | `advanced-void-pointer`   | один контейнер для `int` и точек, рост и `reserve`, вставка и удаление через `memmove`, `qsort`, границы |
| Парсер бинарного файла         | `advanced-binary-files`   | little-endian, пустой набор, неверные сигнатура/версия/число записей, усечение, лишний хвост             |
| Анализатор журнала измерений   | `advanced-error-handling` | min/max/average/count/errors, пустой файл, NaN/Inf, переполнение, длинная строка, EOF без перевода       |

Проекты — дополнительные упражнения уроков с фиксированными ID (`advanced-project-*`), карточки — `content/cpp-systems/projects/advanced-*`. Файловый транспорт: данные из stdin записываются в настоящий `tmpfile()` внутри sandbox.

## Авторинг

Каждый урок — `lesson.src.mjs` и `lesson.mdx`; сборка — `node --import tsx scripts/lessons/build.ts advanced-c/<урок>`. Скрипт проверяет эталоны на GCC и Clang с ASan/UBSan, вычисляет выводы скрытых тестов, сверяет примеры MDX и ответы вопросов с запуском, а для задач с `bug: true` убеждается, что дефектная заготовка не проходит тесты. На медленном Docker уменьшайте параллелизм: `LESSON_JOBS=2`.

## Проверки

- `npm test` — `tests/unit/advanced-content.test.ts`: порядок и цепочка уроков, стандарт урока, отчёт GCC/Clang, отрицательные контроли, блоки с именами файлов, проекты и скрытие решений.
- `npm run test:advanced` — `scripts/verify-advanced.ts`: эталоны на GCC и Clang с ASan/UBSan, отрицательные контроли, примеры MDX (обычные — с записанным выводом; `// Ошибка компиляции` — не собираются; `// Ошибка выполнения` и `// Ошибка памяти` — завершаются ошибкой или отчётом санитайзера). Отчёт — `docs/verification/advanced.json`, параллелизм — `ADVANCED_JOBS`.
- `npm run test:advanced-projects` — контракты проектов в Docker: отказ `realloc` у обобщённого вектора и отклонение смысловых ошибок тестами парсера и анализатора.

Технические факты сверялись с рабочим проектом стандарта C23 [WG14 N3220](https://www.open-std.org/jtc1/sc22/wg14/www/docs/n3220.pdf), документацией [GCC](https://gcc.gnu.org/onlinedocs/) и [glibc](https://www.gnu.org/software/libc/manual/). Особенности, найденные при проверке примеров на GCC 14 и Clang 19, описаны в уроках: `const int` в `case` у Clang, потеря буфера `stdout` при `abort`, беззнаковый `char` на arm64, `__STDC_VERSION__` = `202000L` у GCC 14 в режиме `-std=c23`, повтор идентичного определения структуры (C23 разрешил, GCC 14 принимает, Clang 19 — нет). Материал авторский.
