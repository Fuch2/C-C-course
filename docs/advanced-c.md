# Углублённый C

33 авторских урока C17, 33 запускаемых примера, 99 вопросов, 33 упражнения и три проектных упражнения. Материал проходит от единиц трансляции и контрактов заголовков к макросам, linkage, callbacks, битовым полям, файловым потокам, обработке ошибок, сборке и отладке.

Контент хранится в `content/cpp-systems/advanced-c/`, метаданные проектов — в `content/cpp-systems/projects/advanced-*`. Авторский источник `scripts/author-advanced.py` создаёт только текст. Изменения в сгенерированных уроках нужно переносить в него перед регенерацией. После генерации выполните форматирование и parser.

## Проекты

| Проект                       | Практика                                                          | Проверяемые сценарии                                                                                                                       |
| ---------------------------- | ----------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| Динамический массив на C     | `advanced-callbacks`, задание «Динамический массив на C»          | рост, reserve, сохранение данных, pop пустого массива, границы индекса, clear и повторное использование                                    |
| Парсер бинарного файла       | `advanced-fread-fwrite`, задание «Парсер бинарного файла»         | little-endian, пустой набор записей, неверная сигнатура/версия, усечённый заголовок/запись, лишний хвост, неверное количество              |
| Анализатор журнала измерений | `advanced-error-handling`, задание «Анализатор журнала измерений» | min/max/average/count/errors, пустой файл, отрицательные данные, NaN/Inf, переполнение, мусор после числа, длинная строка, EOF без newline |

Проекты показаны карточками на `/course/cpp-systems` и `/projects`. Ссылка открывает нужное упражнение; черновики, подсказки, просмотр решения и попытки сохраняются штатной системой. Завершение практики урока требует решения обеих задач. Проектная карточка использует существующую модель Project; отдельная сущность прогресса проекта не вводится.

Файловый транспорт: данные из текстового stdin записываются в настоящий `tmpfile()` внутри sandbox. Бинарный проект принимает десятичные октеты, затем парсер читает бинарный FILE*. Анализатор копирует текстовый журнал в файл и обрабатывает поток с постоянной памятью. Доступ к файловой системе хоста не нужен. Скрытые сценарии и эталонные исходники остаются на сервере.

Браузерный runner компилирует один исходник. Многофайловые сборки, Make/CMake и интерактивные сеансы GDB/LLDB описаны отдельно и не выдаются за возможности браузерного редактора. Команды предназначены для отдельной доверенной учебной среды. Функциональные тесты не доказывают архитектуру решения в произвольном ученическом исходнике. Для эталонного vector отдельный Docker-тест внедряет отказ realloc и проверяет сохранение владельца, размера и данных.

## Проверки

- `npm run content:check` — схема, MDX, уникальность ID, граф prerequisites.
- `npm test` — структура модуля, навигация, поиск проектов, скрытие решений и тестов.
- `npm run test:advanced` — 36 решений на GCC/Clang и 33 примера на Clang, все с ASan/UBSan в Docker.
- `npm run test:advanced-projects` — отказ realloc, инварианты vector и проверка, что тесты отвергают намеренные ошибки endian и максимума.
- `npm run typecheck`, `npm run lint`, `npm run test:integration`, `npm run build` — проверки платформы.

Отчёт `docs/verification/advanced.json` обновляется после каждого прогона. `complete: true` означает, что выполнены все 105 проверок; дополнительно все `ok` должны быть `true`. Каждая запись содержит fingerprint исходника и тестов. Каждый stdin запускается в отдельном ограниченном контейнере. Настройки безопасности runner не меняются.
