# Время жизни объектов и управление ресурсами

Модуль `cpp-lifetime` продолжает ООП: 24 последовательных урока C++20, 24 MemoryDiagram, 24 безопасных запускаемых примера, 72 вопроса и 30 упражнений. Каноническая точка входа: `/lesson/lifetime-object-lifetime`; модуль доступен в `/course/cpp-systems` и поиске.

## Методика

Маршрут движется от различия памяти, имени и объекта к RAII, контрактам владельца и заёмщика, независимости копий, передаче ресурсов и графам совместного владения. Каждый урок содержит модель, механизм, гарантии, схему, предсказуемый пример, эксперимент, дополнительный углублённый разбор, типичную ошибку, самопроверку и практику. Формальная граница lifetime класса объясняется отдельно от специальных правил работы конструктора и деструктора. Материалы не обещают пустоту любого moved-from объекта или бесплатность любого move.

Учебные raw-pointer владельцы нужны для понимания правил трёх и пяти. Прикладной выбор показан через правило нуля и готовые владельцы. Материал охватывает самоприсваивание, самоперемещение, отказ при подготовке копии, частично созданный объект, время жизни блока управления, `lock`, `get/reset/release`, пары освобождения и контекст deleter.

## Диагностика перед исправлением

| Урок              | Дефект                   | Исправление                             |
| ----------------- | ------------------------ | --------------------------------------- |
| Scope и lifetime  | dangling reference       | Возврат независимого значения           |
| Ownership         | Неоднозначное владение   | Читающий заёмщик и явный владелец       |
| Shallow copy      | double delete            | Независимая копия ресурса               |
| Move constructor  | Два владельца после move | Передача с допустимым пустым источником |
| unique_ptr        | use-after-free           | Сохранение значения до reset            |
| Cyclic references | Цикл shared_ptr          | Слабая обратная связь                   |

В этих уроках сначала предлагается отдельное задание с четырьмя фрагментами: ученик классифицирует первичный дефект и записывает обоснование в комментарии. Затем исправляет реальный дефектный starterCode. Код диагноза проверяется автоматически; свободное текстовое обоснование предназначено для самопроверки. Оба упражнения обязательны для зачёта практики, их черновики и история независимы. Существующий интерфейс позволяет переключаться между заданиями; технической блокировки открытия второго до первого нет. Порядок задан педагогически, а не новым API-состоянием.

Function grading проверяет результаты и диагностику выполнения. Он не доказывает структуру произвольного решения ученика: ручное ревью дополнительно проверяет требуемые типы, специальные операции и отсутствие обхода задачи прямой арифметикой. Скрытые тесты, решения, разборы и правильные ответы quiz не выдаются публичным API до соответствующего явного запроса.

## Воспроизведение

Авторские источники: `scripts/lifetime-lessons.mjs`, `scripts/lifetime-notes.mjs`, `scripts/lifetime-bugs.mjs`. Генерация: `node scripts/author-lifetime.mjs`. Генератор обновляет только содержимое нового модуля и его запись в программе курса. Исходники примеров в `examples.json` сверяются с первым блоком C++ в MDX unit-тестом.

`npm run test:lifetime` проверяет 30 эталонов GCC и Clang, 24 примера Clang и шесть отрицательных исходников. Компиляция и исполнение происходят только через `apps/runner` в прежнем ограниченном Docker sandbox с ASan/UBSan; каждый тест получает отдельный контейнер. Отрицательный контроль обязан скомпилироваться и завершиться диагностикой соответствующей категории — ошибка компиляции или просто неверное число не считается обнаружением дефекта. `runnerReady()` проверяется после каждого задания. Отчёт с SHA-256 проверяемых исходников и тестов: `docs/verification/lifetime.json`.

`npm run test:lifetime -- --retry-failed` повторяет неуспешные или изменённые проверки. Успешный результат используется повторно только при полном совпадении SHA-256 исходника, компилятора и тестов; прошлые неуспешные попытки сохраняются в отчёте. Лимиты sandbox при повторе не меняются.

Проверки платформы: `npm run content:check`, `npm run typecheck`, `npm run lint`, `npm test`, `npm run test:integration`, `npm run build`.

Технические правила сверены с первичными разделами проекта стандарта: [время жизни](https://eel.is/c++draft/basic.life), [специальные конструкторы](https://eel.is/c++draft/class.copy.ctor), [unique_ptr](https://eel.is/c++draft/unique.ptr), [shared_ptr](https://eel.is/c++draft/util.smartptr.shared). Используются возможности и правила C++20; тексты, диаграммы и задания авторские.
