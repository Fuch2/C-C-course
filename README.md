# Код / Система

Локальная интерактивная платформа **«C/C++: от основ до системного программирования»**. Весь интерфейс и авторский учебный контент — на русском языке. Сейчас опубликовано 9 модулей и 212 уроков, включая «Основы C++» и «Объектно-ориентированное программирование в C++» на C++20.

Реализованы **Этап 1: архитектура и базовое приложение**, **файловый движок учебного курса**, безопасный Docker runner и полноценная система практических задач. Движок сканирует контент, проверяет строгие Zod-схемы и граф prerequisites, строит навигацию, содержание и поисковый индекс. Поддерживаются Markdown/MDX, 11 учебных компонентов и фильтры по тегам. Формат и примеры: [авторинг контента](docs/content.md). Опубликованы девять модулей и 215 уроков: «Старт: первая программа» (5 уроков), «Основы языка C» (45 уроков, включая шесть практикумов), «Память и указатели в C» (28 уроков, 110 задач, 41 задание «Найди ошибку» с проверкой ASan/UBSan и Valgrind), «Углублённый C» (28 уроков, 3 проекта), «Инструменты разработчика» (12 уроков, 40 задач: терминал, сборка, линковка, Make, CMake, GDB, LLDB, санитайзеры, Git), «Алгоритмы и структуры данных» (28 уроков, 31 задание), «Основы C++» (21 урок), «Объектно-ориентированное программирование в C++» (24 урока, проект из трёх этапов) и «Время жизни объектов и управление ресурсами» (24 урока, 30 заданий, 24 MemoryDiagram). Задачи урока имеют отдельные черновики и историю; практическая часть завершается после решения всех задач. Задания используют exact/trimmed stdout, function harness, custom checker и доверенную диагностику памяти. Подробнее: [время жизни и ресурсы](docs/lifetime-module.md), [ООП и проект датчиков](docs/oop-module.md), [модуль памяти](docs/memory-module.md), [алгоритмы, структуры и benchmark-практика](docs/algorithms-module.md).

## Запуск через Docker

Нужны Docker Engine/Desktop и Docker Compose v2. Выполните из корня проекта:

```sh
docker compose up --build -d
```

Откройте **http://localhost:3000**. Инициализатор сам создаст SQLite, применит миграции и подготовит секретный ключ runner. Node.js на хосте для этого способа не нужен. Первая сборка скачивает компиляторы и зависимости; следующие используют кэш.

```sh
docker compose ps
docker compose logs --tail=100 web runner init
docker compose down
```

`docker compose down` сохраняет данные в именованных томах. Не добавляйте `-v`, если хотите сохранить прогресс. Порт привязан только к `127.0.0.1`. Для другого порта задайте **обе** переменные:

```sh
WEB_PORT=3100 APP_ORIGIN=http://localhost:3100 docker compose up -d
```

Если используется rootless Docker с другим путём socket, задайте `DOCKER_SOCKET_PATH`. В обычном Docker Desktop оставьте значение по умолчанию.

### Автообновление после изменений

```sh
docker compose watch
```

Команда поднимает сервисы и остаётся работать: при изменении уроков, кода сайта, общих пакетов или runner соответствующий образ пересобирается и контейнер перезапускается. Если сборка падает, продолжает работать прежняя версия. Открытые вкладки раз в 10 секунд сверяют метку сборки через `/api/version` и перезагружаются сами; пока фокус в редакторе или поле ввода, перезагрузка ждёт. Черновики кода сохраняются перед перезагрузкой. Изменение `package.json` или `package-lock.json` заново устанавливает зависимости, такая сборка заметно дольше.

## Локальная разработка

Нужен Node.js 22.12+ и npm 10 или новее.

```sh
npm ci
npm run setup
npm run dev
```

`setup` создаёт `.env` с отдельным ключом runner, генерирует Prisma Client и применяет миграции. Главная, курс, уроки, поиск, завершение урока, прогресс, закладки и настройки работают без запущенного runner.

Для компиляции и выполнения кода дополнительно запустите Docker, соберите sandbox и откройте второй терминал:

```sh
docker build -f docker/sandbox/Dockerfile -t code-systems-sandbox:local .
npm run dev:runner
```

Production-сборка и запуск без Compose:

```sh
npm run build
npm start
```

Не запускайте `npm start` и `npm run dev` одновременно на одном порту. Инструменты проекта запускаются через `scripts/tool.mjs`, поэтому пробелы и двоеточие в пути рабочей папки не мешают npm-скриптам.

## Что работает

- Один автоматически создаваемый **локальный пользователь**. Регистрация, пароль и cookie не нужны; разные браузеры открывают общий локальный прогресс.
- Каталог и страница курса с количеством уроков, временем, модулями и прогрессом.
- Раскрывающееся дерево модулей и уроков слева, индикаторы прохождения, breadcrumbs и общий прогресс сверху.
- Markdown-урок: цели, sticky-оглавление, подсветка кода, копирование и настоящий запуск подходящих C/C++-примеров, ссылки на соседние уроки и сохранение завершения.
- Command palette по `Ctrl/Cmd + K` и расширенный поиск по модулям, урокам, заголовкам, терминам и заданиям; закладки, настройки и продолжение обучения.
- Тёмный графитовый интерфейс со спокойным оливковым акцентом, адаптивная навигация, клавиатурные вкладки, видимый фокус и ссылка перехода к содержимому.
- Сохранены уже разработанные Monaco, настоящая компиляция GCC/Clang, stdin/stdout/stderr, quiz, подсказки, разборы, скрытые проверки и история попыток.
- Песочница с независимым черновиком и историей запусков. Исходники и сообщения компилятора не имитируются.

Демонстрационный урок имеет режим `completion: "reading"`: кнопка **«Завершить урок»** сохраняет факт чтения. Дополнительные quiz и задача остаются самостоятельными результатами — они не отмечаются пройденными автоматически. Для будущих практических уроков предусмотрен режим `practice`, требующий чтения, успешного quiz и всех тестов задачи.

## Структура monorepo

```text
apps/
  web/                 Next.js App Router, React, интерфейс и API
  runner/              Доверенный сервис управления sandbox
packages/
  ui/                  Общие визуальные компоненты
  shared/              Zod-контракты, типы, оценивание
  course-engine/       Загрузка, валидация и поиск Markdown-контента
content/cpp-systems/   course.json, lesson.json и lesson.md
prisma/               Схема и последовательные миграции SQLite
docker/               Production-образы и sandbox компиляторов
tests/                Unit, SQLite/HTTP integration и Docker-тесты
docs/                 Архитектура, API, авторинг и безопасность
scripts/              Настройка, сборка и проверка решений
```

Данные хранятся через Prisma в `User`, `Settings`, `CourseProgress`, `LessonProgress`, `ExerciseAttempt`, `QuizAttempt`, `Bookmark`, `Draft` и `StudyDay`. Некоторые модели используют `@@map` для сохранения существующих таблиц без потери истории. См. [архитектуру](docs/architecture.md).

## Проверки

```sh
npm run typecheck
npm run lint
npm test
npm run test:integration
npm run build
```

Или одной командой: `npm run check`. HTTP integration самостоятельно поднимает временный Next.js и отдельную SQLite, затем удаляет только свои тестовые данные.

```sh
npm run test:runner
npm run test:solutions
npm run test:memory
npm run format:check
```

Docker-тесты проверяют реальные компиляторы и защитные лимиты. `test:solutions` прогоняет эталонные решения опубликованных уроков на GCC и Clang; отчёт содержит отпечаток исходника/тестов. `npm run format` применяет Prettier.

## Ограничения и эксплуатация

Это локальная установка для одного пользователя. Она **не предназначена для публикации в интернете** без отдельной системы аутентификации, авторизации и эксплуатационного усиления runner. Web не имеет доступа к Docker socket; доверенный runner имеет этот доступ и потому требует защиты. Пользовательские программы всегда запускаются в отдельном контейнере без внешней сети, от непривилегированного пользователя и с лимитами ресурсов.

Лимиты: исходник до 64 КБ UTF-8, stdin до 16 КБ; 15 секунд на компиляцию, 0,1–10 секунд на запуск (по умолчанию 2), 256 МБ RAM без swap, 64 PID, 1 CPU и 32 КБ суммарного stdout/stderr на фазу. Запись разрешена только в ограниченные tmpfs: `/work` 64 МБ, `/tmp` 16 МБ; один файл до 16 МБ. Очередь — 2 параллельные работы и до 8 ожидающих, ожидание до 20 секунд. Контроль находится вне sandbox; каждый тест получает новый контейнер. Подробности: [безопасность](docs/security.md), [API выполнения](docs/api.md).

Опубликованные девять модулей покрывают язык C, C++20, алгоритмы и системные темы, но не заменяют полный учебный материал по C/C++. Аппаратный Embedded и итоговый многофайловый проект в текущий состав не входят.

Модуль [«Углублённый C»](docs/advanced-c.md): `npm run test:advanced` проверяет 36 упражнений на GCC/Clang и 33 примера на Clang с ASan/UBSan. Проекты доступны в программе курса и как отдельные задачи в практике уроков.
