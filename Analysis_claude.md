# Анализ проекта «Код / Система»

Дата: 14 октября 2026 года.

Это локальная платформа для изучения C/C++. Устройство: monorepo на Next.js 16 (`apps/web`), отдельный доверенный runner (`apps/runner`), который управляет Docker, общие пакеты `shared`, `course-engine` и `ui`, и файловый курс. Сейчас в курсе 9 модулей, 215 уроков и 4 проекта, около 18 тыс. строк кода и 8 МБ контента.

Платформа в хорошем состоянии. Главные проблемы — незавершённый перенос уроков, неравное качество контента между модулями и тесты, которые отстали от переписанных уроков.

## Проблемы

### Высокий приоритет

#### 1. Перенос пяти уроков в «Инструменты разработчика» сделан наполовину

Каталоги `makefile`, `cmake`, `gdb`, `lldb` и `sanitizers` уже лежат в `content/cpp-systems/developer-tools/`, но в их `lesson.json` по-прежнему стоит `moduleId: "advanced-c"` (порядок 29–33). Последствия:

- на сайте в «Углублённом C» 33 урока;
- в «Инструментах разработчика» 7 уроков с порядком 3, 4, 5, 6, 7, 10, 12;
- падает unit-тест `tests/unit/advanced-content.test.ts:8`;
- обязательный по AGENTS.md `npm run test:advanced` падает сразу: `scripts/verify-advanced.ts:17` ожидает 28 уроков;
- у модуля developer-tools нет ни unit-теста, ни скрипта проверки.

#### 2. Задачи в модулях ООП и «Время жизни» можно сдать без понимания темы

Проверка вызывает функцию и сравнивает только её `int`-результат (`buildSubmissionSource`, `packages/shared/src/index.ts:146`), контракт класса она не видит. Сверка ожидаемых выводов тестов с простыми формулами показала:

- 20 из 30 задач «Времени жизни» и 13 из 26 задач ООП проходят решением `return a + b;` (или `return b;` / `return a - b;`);
- пример: `content/cpp-systems/cpp-lifetime/raii/lesson.json` засчитывается без класса `Restore`;
- в developer-tools 6 из 7 задач ожидают один и тот же вывод во всех тестах (например, вывести `status -> diff -> add -> commit`), тестов по 2.

#### 3. После первой же попытки quiz показывает правильные ответы

API возвращает `explanation` по каждому вопросу при любой отправке (`apps/web/app/api/lessons/[lessonId]/[action]/route.ts:167`). В новых уроках объяснение прямо содержит ответ, например «i = 2, 5, 8, 11…». Поэтому со второй попытки quiz засчитывается гарантированно. Это расходится с правилом AGENTS.md «без правильных ответов quiz до явного запроса разбора».

#### 4. Тесты отстали от переписанного контента, одна защитная проверка перестала работать

Все три падения в `tests/runner/journey.test.ts` — из-за старых предположений о контенте:

- тест ждёт 2 задачи в `c17-structure`, а их теперь 4;
- в `first-program` тоже теперь 4 задачи;
- отрицательный контроль «утечка с правильным stdout не принимается» (`journey.test.ts:170`) ищет `free(p);` в эталоне урока `memory-memory-leak`, а его там больше нет. Проверка того, что ASan отклоняет утечку, фактически ничего не проверяет.

### Средний приоритет

#### 5. Каждая страница весит около 1,1 МБ данных React (RSC payload)

Корневой `apps/web/app/layout.tsx:20-22` передаёт сводки всех 215 уроков дважды: в `LearningTools` и в `Shell`. Сводки занимают около 570 КБ JSON, из них 76% — массивы `effectivePrerequisites` (до ~190 ID на урок). Клиенту они нужны только на странице самого урока, где приходят вместе с `PublicLesson`. Если убрать их из сводок и передавать список один раз, страница станет примерно в 4 раза легче.

Замеры на запущенном экземпляре: `/lesson/first-program` — 1,24 МБ (102 КБ в gzip), `/playground` — 1,07 МБ, главная — 1,42 МБ.

#### 6. Нет git, а старые генераторы перезаписывают контент

Проект не находится под контролем версий. При этом:

- повторный запуск `scripts/author-advanced.py` создаст `makefile`, `cmake`, `gdb`, `lldb` в `advanced-c/` (строки 262–290). ID уроков задублируются, и курс перестанет загружаться; кроме того, скрипт перепишет `course.json` (строки 736–742);
- `scripts/author-course.py` тоже переписывает `course.json` и создаёт уроки в старой плоской структуре;
- `docs/content.md:156` прямо советует запускать `python3 scripts/author-advanced.py`.

Без истории версий такую ошибку не откатить.

#### 7. Пробелы в отчётах проверки

- Отчёта для «Основ C++» нет вообще. Раньше мешало отсутствие Docker с cgroup v2, сейчас он доступен.
- В `docs/verification/lifetime.json` 88 из 90 проверок успешны.
- В `docs/verification/solutions.json` всего 2 проверки — полного прогона нет.
- `test:solutions` запускает эталоны без режима диагностики задачи (`scripts/verify-solutions.ts:41`). Для 255 задач с ASan/UBSan он не воспроизводит то, как их проверяют ученику.

#### 8. Документация устарела

- README и AGENTS.md пишут о 212 уроках, 36 уроках «Основ C», 33 уроках «Углублённого C» и модуле «Практикум C/C++», которого уже нет; модуль «Старт» не упоминается.
- `docs/content.md` указывает «115 уроков в пяти модулях».
- AGENTS.md утверждает, что integration suite запускает собранный runner; на деле собранный runner запускает только `tests/runner/execute-api.test.ts`, а integration использует `next dev`.

#### 9. Качество контента заметно разное

«Старт», «Основы C» и «Память» переписаны по новому стандарту из `docs/content-audit.md`. Остальные шесть модулей (137 уроков) — нет:

| Показатель        | Переписанные модули | Остальные модули                                                                                         |
| ----------------- | ------------------- | -------------------------------------------------------------------------------------------------------- |
| Текст урока, слов | ~1000–1200          | ~350–650                                                                                                 |
| Вопросы quiz      | 6+ разных типов     | почти все из двух вариантов: 84 из 84 в алгоритмах, 63 из 63 в «Основах C++», 56 из 84 в «Углублённом C» |
| Тестов на задачу  | 8–12                | 3–6 (в developer-tools — 2)                                                                              |

Кроме того, у всех 60 примеров к задачам «Времени жизни» одно и то же шаблонное объяснение («Проследите операции и сопоставьте результат с контрактом задания»), а в «Основах C++» 21 вопрос повторяет одно и то же объяснение.

### Низкий приоритет

- **Проверка дробных чисел пропускает пустой вывод.** Если ожидается `0`, пустой stdout засчитывается, потому что `Number('') === 0` (`packages/shared/src/index.ts:134`). Подтверждено запуском `gradeResults`. Сейчас этот проверяльщик ни одна задача не использует.
- **Защита от подделки адреса неполная.** `assertOrigin` (`apps/web/lib/http.ts:16`) пропускает запрос, если Origin совпадает с заголовком Host. Это и есть сценарий DNS rebinding: запрос с подставленным Host вернул 200. Отдельного списка разрешённых хостов нет, заголовка Content-Security-Policy тоже нет.
- **Мёртвый код в runner.** `apps/runner/src/sandbox.ts:255-262` пишет исходник во временный каталог на хосте, но этот файл нигде не используется: исходник передаётся в контейнер через `tee`.
- **Возможная ложная пометка о превышении ресурсов.** `sandbox.ts:187` считает счётчик `max` из `memory.events`, а он срабатывает и без OOM. Компиляция и запуск идут в одном контейнере, поэтому тяжёлая компиляция может пометить фазу как `resource_limit`. Не воспроизводилось; стоит добавить регрессионный тест.
- **Автоперезагрузка вкладки стирает ответы quiz.** `UpdateWatcher` перезагружает страницу при уходе фокуса из поля; радиокнопки не считаются вводом, а ответы quiz не сохраняются. Проблема есть только в режиме `docker compose watch`.
- **Мелочи:**
  - импорты без `.js` в `packages/course-engine/src/graph.ts:1` и `packages/shared/src/progress.ts:1` (работают благодаря bundler/tsx, но расходятся с ESM-соглашением из AGENTS.md);
  - оставшийся `scripts/__pycache__` от удалённого скрипта;
  - Prisma 6 при уже вышедшей 7;
  - в `.claude/settings.local.json` разрешён `docker run *`: это фактически root-доступ к хосту для агента.

## Что сделано хорошо

- **Песочница спроектирована грамотно**, и Docker-тесты это подтвердили:
  - отдельный контейнер на каждый тест;
  - нет сети, все capabilities сброшены, read-only корень;
  - лимиты по процессам, памяти, размеру файлов и выводу;
  - запуск требует cgroup v2;
  - очистка по меткам и сравнение токена за постоянное время (`timingSafeEqual`).
- Публичный API действительно не отдаёт скрытые тесты, решения и подсказки до запроса.
- Zod проверяет данные на всех границах API, TypeScript в строгом режиме.
- В MDX запрещены HTML и JavaScript, у изображений есть защита от выхода за каталог курса.
- Курсорная пагинация и ограничение истории попыток (100 на задачу) исправлены по прошлому ревью и покрыты тестами.
- Конвейер авторинга `scripts/lessons/build.ts` проверяет эталоны в sandbox на GCC и Clang и сверяет выводы примеров с реальным запуском. Это правильная основа для переписывания остальных модулей.

## Рекомендуемый порядок работ

1. Сделать `git init` и первый коммит, до любых правок.
2. Довести перенос: `moduleId` и порядок пяти уроков, `verify-advanced.ts`, тесты для developer-tools.
3. Обновить `journey.test.ts` и вернуть рабочий отрицательный контроль утечки.
4. Удалить или пометить устаревшие генераторы, исправить `docs/content.md`, README и AGENTS.md.
5. Облегчить layout: убрать `effectivePrerequisites` из сводок и вторую копию списка уроков.
6. Определиться с политикой quiz: показывать объяснения только к верным ответам или после N попыток.
7. При переписывании ООП и «Времени жизни» заменить проверку через `int solve(a, b)` на stdout-сценарии или проверки контракта, как в проекте датчиков.
8. Запустить `npm run test:cpp-fundamentals` и полный `npm run test:solutions`, пока доступен Docker с cgroup v2.
